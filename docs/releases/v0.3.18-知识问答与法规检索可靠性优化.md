# v0.3.18 - 知识问答与法规检索可靠性优化

发布日期：2026-10-16

## 版本概述

本版本围绕知识库与法规库的实际问答链路进行可靠性加固，重点解决模型已配置但知识问答不可用、精确条文召回后仍被过早过滤、聊天回答因引用格式问题被整体拒绝，以及法规库未命中时无法给出可区分风险的参考答复等问题。

## 核心改动

### 1. 知识问答模型选择闭环

- “知识使用与治理 → 搜索问答”新增“回答模型”选择器，清晰显示当前用于生成有据回答的模型，并支持在页面内切换。
- 模型选择按当前账号隔离保存，不会影响聊天会话、法规问答或其他应用的模型选择。
- 回答请求显式携带所选模型；结果卡片展示服务端实际使用的模型名称，方便复核与审计。
- 未显式选择模型时，服务端按“个人默认模型 → 系统默认模型 → 当前账号可用授权模型”的顺序回退，避免已配置可用模型时仍错误提示找不到知识问答模型。
- 无可用模型或模型密钥异常时，返回可执行的中文提示；仅“检索证据”不依赖回答模型，仍可独立使用。

### 2. 知识召回与重排序可解释性优化

- 召回测试不再只显示已通过引用门槛的少量片段；诊断界面会展示前列候选，明确区分“已召回”“达到阈值”和“可引用”，便于定位向量、关键词或重排序问题。
- 对“盗窃”等精确词面命中的条文分块，允许其进入后续重排序与可信度判断，避免仅因向量分数偏低被提前丢弃。
- 引用可信度计算纳入短语命中和词项覆盖；外部重排序服务返回较低分时，为精确词面命中保留受控的本地相关性下限，降低跨模型分数标定差异造成的误拒绝。
- 仍保留专题库范围、标签、访问权限、可信度门槛及多样性去重约束；本次优化不绕过知识库权限或引用证据边界。

### 3. 聊天知识来源核验修复

- 聊天与知识工作台的回答在“缺少引用”“引用与来源不匹配”或“语义核验不通过”时，会基于本轮原始证据尝试一次受约束的引用修复。
- 修复后的正文必须再次通过原有来源核验，才会展示给用户；修复失败仍按原策略拒绝未经核验的结论。
- 审计结果保留引用修复标记，帮助后续分析模型引用质量与资料覆盖情况。

### 4. 法规问答检索与安全回退

- 法规问答查询规划会抽取“抢劫”“抢劫罪”等核心短词，与完整问题并行检索，减少长问题、量刑描述或口语化表达导致的词法召回落空。
- 法规结构化答案解析兼容 JSON 前后附带说明的模型输出；只要条文编号、原文短引和来源关系均可核验，仍可生成有据答复。
- 已召回候选但模型仅缺少引用格式时，保留“未核验的模型参考回答”，同时明确提示用户对照候选条文复核；不存在候选或候选与结论冲突时，仍不会把未经依据支持的法律结论伪装为条文回答。
- 当法规库没有候选时，页面显示候选池、检索异常数和条文数诊断；可区分资料为空、文档条文数为零、普通未命中和检索链路异常，便于生产排查。

## 验证与发布注意事项

- 覆盖知识模型回退、引用修复、精确词面召回、外部重排序保护、法规查询规划、法规依据核验与模型参考回答等 48 项针对性回归与契约测试。
- 前端模型选择器、静态资源与样式构建检查通过；开发规范和新增 SQL 门禁通过。
- 当前开发数据库与生产法规库规模不同，生产发布后应使用“盗窃”“抢劫罪最高可以判处多少年有期徒刑”等真实问题验证候选池数量、命中条文、外部重排序状态及最终引用展示。
