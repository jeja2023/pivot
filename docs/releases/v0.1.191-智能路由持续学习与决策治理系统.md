发布范围：智能路由决策运行时、多提供器策略融合、本地轻量模型、Laya 内网决策服务、冻结评测集治理、决策模型制品熔断与运维巡检、个人记忆自然语言交互弹窗、系统监控中心决策指标。

## 1. 版本概览与核心设计原则

v0.1.191 正式引入 Pivot 统一业务决策运行时（Unified Business Decision Runtime）与持续学习治理体系。该系统旨在将大模型聊天链路中的隐式调度决策（如知识库检索时机、工具调用规划、反问澄清或直接回答）转化为**可量化、可比较、可审计、受数据治理约束的持续学习闭环**。

在架构设计上严格贯彻以下五个核心原则：

1. **权限门禁严格收敛（Capability Gate Closedness）**：决策系统仅在已经通过 Pivot 权限校验的合规动作候选集内进行打分与优化，绝对禁止动态放大候选集或跨越租户/用户权限边界。
2. **隐私脱敏与数据安全（Zero-Raw-Prompt Exposure）**：所有决策提供器（包含外部 Laya 及 Qwen）仅接收规则脱敏后的任务状态特征和允许候选列表，任何原始用户提问原文均不得写入决策日志、训练样本导出或审计跟踪。
3. **影子模式先行（Shadow-First Verification）**：系统默认以影子模式（Shadow Mode）运行，学习型决策器并行打分并沉淀建议，但不改变实际执行路径；仅在通过冻结评测集且人工激活策略制品后才允许受控生效。
4. **制品门禁与不可变注册表（Immutable Artifact Registry）**：所有参与 Active 灰度的模型与策略必须具备冻结的代码版本、数据版本、权重哈希与校准阈值，缺少已激活制品时自动平滑回退至影子模式。
5. **实时熔断与自愈（Autonomous Circuit Breaker）**：线上运行时若出现提供器异常、版本漂移、调用超时或执行失败率超出冻结阈值，系统自动触发熔断降级并退役问题制品，确保核心聊天业务链路零中断。

## 2. 核心功能特性

### 2.1 统一业务决策运行时与多场景覆盖
- **决策运行时 (`server/services/decision-runtime.js`)**：收敛业务决策入口，统一管理 `chat.rag`（知识库检索 / 跳过）、`chat.tools`（推荐规划 / 仅候选 / 跳过）以及 `chat.next_step`（直接回答 / 反问澄清）等关键调度路径。
- **全生命周期执行闭环 (`server/services/chat-decision-outcomes.js`)**：在会话执行各阶段（意图确定、检索完成、工具规划、回复完成）自动记录决策结果（`success` / `failure` / `partial` / `skipped`）、耗时与原因码，形成完整的决策执行回执。

### 2.2 多提供器策略融合与校准
- **通用提供器契约 (`server/services/decision-provider.js`)**：
  - **既有启发式路由 (`existing-router`)**：保留既有高可靠性规则基线作为底层兜底。
  - **本地轻量线性决策器 (`decision-light-model`)**：毫秒级响应的轻量线性模型，完全本地运行，不消耗大模型算力。
  - **Qwen 结构化决策器 (`qwen`)**：利用 Qwen 输出严谨的 JSON 结构化打分，强制关闭思考模式，输出 Token 严格受限。
  - **内网 Laya 决策服务 (`laya`)**：通过 HTTP 接入企业内网自研 Laya 决策模型，支持单请求超时隔离与并发信号量控制。
- **策略注册与融合 (`server/services/decision-policy.js`)**：支持多提供器输出加权融合、概率校准（Platt scaling）与置信度阈值过滤；高风险或需审批动作严格禁止自动采纳。

### 2.3 冻结评测集治理与数据合规导出
- **基准评测用例集 (`docs/decision-evaluation-set.v1.json`, `docs/decision-evaluation-set.v2.json`)**：内置覆盖多语言、边界场景、负向用例、长上下文及高风险工具调用的标准冻结评测用例。
- **人工审核队列与治理状态机 (`server/services/decision-evaluation-reviews.js`)**：导入的评测用例进入 Review Queue，只有经人工复核确认的用例才可成为冻结基准，防止脏数据污染评测。
- **安全数据集导出 (`server/services/decision-dataset-exporter.js`)**：按时间窗口严格切分训练集、校准集与测试集，严防哈希泄漏；跨租户脱敏训练默认强制要求 CLI 显式参数与 `PIVOT_DECISION_ALLOW_GLOBAL_TRAINING` 环境变量双重批准。

### 2.4 模型制品熔断机制与运维巡检
- **自动熔断巡检 (`server/services/decision-artifact-breaker.js`)**：定期对已激活制品运行统计巡检，当统计窗口内失败率超过评测报告冻结的阈值时，自动将制品标记为 `retired` 并回退至既有路由。
- **定期维护巡检 (`server/services/decision-maintenance.js`)**：定时汇总样本分布与提供器运行状态，按配置周期（默认 180 天）自动清理超期历史决策明细，同时永久保留不可变模型制品与评测审计。

### 2.5 个人记忆自然语言交互弹窗重构
- **现代化视觉重构 (`client/chat/partials/workspaces/chat-shell.html`, `client/chat/styles/base/input.css`)**：
  - 全新卡片式设计，带有“自然语言感知”状态徽章与清晰操作说明。
  - 预置快捷指令芯片（“记住新偏好”、“忘记旧信息”、“更正偏好”），支持一键填充指令。
  - 实时意图解析与结果预览卡片（Preview Card），按动作类型（remember/forget/modify/warning）动态切换样式、状态徽章与候选记忆条目选择。
  - 键盘操作增强：支持 `Ctrl+Enter` 快速触发预览与确认修改，支持 `Esc` 键快捷退出。
  - 全面遵循全局 CSS 变量与设计规范，完美适配桌面与暗黑模式。

### 2.6 系统监控中心决策指标卡片
- **监控指标扩展 (`client/chat/stats-monitor.js`, `server/routes/admin-stats.js`)**：
  - 监控概览区新增“决策器（24h）”与“决策器 P95”卡片。
  - 直观透出 24 小时内智能决策器的调用总数、错误数以及毫秒级 P95 耗时。
  - 数据库迁移未完成时显示“待迁移”提示，保障平滑升级体验。

## 3. PostgreSQL 数据库迁移

本版本新增 2 个版本化数据库迁移（包含完整 SQLite 与 PostgreSQL `upPg` 支持）：

### 1. `202609280001_decision_learning_foundations`
创建智能决策核心存储底座：
- `decision_records`：记录脱敏任务状态、候选动作、提供器打分、策略裁决与选定动作；
- `decision_outcomes`：记录决策的执行结果、状态、人工验证结论及耗时；
- `decision_model_artifacts`：存储不可变模型制品元数据、代码/数据版本、权重哈希与校准参数；
- `decision_preferences`：存储用户和租户级别的显式路径偏好。

### 2. `202609280002_decision_evaluation_governance`
创建评测集与治理支持：
- `decision_evaluation_cases`：存储冻结评测集用例定义；
- `decision_evaluation_reviews`：记录评测用例的人工审核日志与预期动作裁决。

## 5. 运维操作与发布指引

### 5.1 常用 npm 命令
- 校验冻结评测集：`npm run check:decision-evaluation-set`
- 导入冻结评测集：`npm run import:decision-evaluation-set`
- 训练本地轻量模型：`npm run train:decision-light-model`
- 导出 Laya 训练数据集：`npm run export:laya-decision-dataset`
- 决策服务提供器压测：`npm run benchmark:decision-providers`
- 决策服务资源影响压测：`npm run benchmark:decision-resources`
- 生产发布前置检查（Preflight）：`npm run preflight:decision-release`
- 收集发布证据快照：`npm run report:decision-release-evidence`

### 5.2 Laya 容器部署
仓库根目录下提供两套 Docker Compose 编排模版：
- `docker-compose.laya.yml`：标准 CPU 运行环境；
- `docker-compose.laya.gpu.yml`：NVIDIA GPU 加速运行环境。

部署验收指引详见文档：[docs/Laya内网决策服务部署与验收.md](file:///e:/pivot/docs/Laya内网决策服务部署与验收.md)。
