# v0.7.56 长期记忆历史向量兼容修复

发布日期：2026-10-28

## 问题

部分生产库的 `memories.embedding` 仍是历史 text 表示，例如 `[0.1,0.2,...]`。长期记忆候选下推曾直接执行 `embedding <=> ?::vector`，PostgreSQL 会报 `operator does not exist: text <=> vector`，随后只能回退应用层排序并持续写警告。

## 修复

- 使用 `embedding::vector(查询维度)` 与 query vector 进行余弦距离计算，与已有 HNSW 表达式保持一致。
- 仅允许完整数值数组格式、`embedding_dimensions` 与查询维度一致的行进入 SQL 向量排序；非法或旧格式由现有应用层解析和安全回退处理。
- 真正的密钥和敏感字段脱敏不变；该修复只影响长期记忆向量候选的数据库类型兼容。

无需数据库迁移。部署服务并重启后生效；历史非法向量仍需通过现有恢复任务重新生成，不能从损坏文本恢复。
