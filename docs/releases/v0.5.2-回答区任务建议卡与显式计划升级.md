# v0.5.2 回答区任务建议卡与显式计划升级

发布日期：2026-10-19

## 版本摘要

任务建议不再出现在输入框或发送按钮旁。用户先按原方式发送消息并获得普通回答；如果该请求符合本地高置信任务规则，系统只在**最新助手回答的底部**展示一张紧凑、可关闭的任务建议卡。

```text
用户问题 → 普通回答
              └─ 可将此请求转为受控任务
                 先生成计划并审阅，不会立即执行。
                 [查看执行计划] [继续对话] [×]
```

这一交互沿用“先展示可审阅计划、再由用户显式开始实施”的公开 Plan 模式原则；例如 GitHub Copilot 的 Plan mode 在计划完成并审阅后才提供 Start Implementation，而不是把执行隐含在普通聊天中。[GitHub Copilot Plan mode](https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-plan-mode)

## 用户交互

- **普通问答、解释、翻译、润色和单次创作**：只显示回答，不显示卡片。
- **多步骤或有明确交付物的请求**：先显示回答，再在该回答中显示建议卡。
- **查看执行计划**：使用这一轮原始用户目标创建 v0.5.0 的草案；不使用用户随后输入但尚未发送的内容。
- **继续对话 / ×**：移除卡片；同一会话同类别任务不再重复显示建议。
- **新回答到来**：上一张临时建议卡自动消失，始终只保留最新建议。
- **`/task <目标>`**：熟练用户可在输入框中使用该命令后按 Enter，直接进入草案审阅；不会先发送普通聊天消息。

## 安全与数据边界

- 卡片的高置信分类在浏览器本地执行，不访问模型、RAG、记忆、工具目录或外部服务。
- 建议卡不持久化为聊天消息，刷新页面不会显示成模型曾经给出的结论。
- 点击“查看执行计划”后才会创建持久化草案；草案与 Run 的 revision、策略摘要、确认、过期、预算、`builtin_only` 和执行期审批边界保持不变。
- 管理员关闭聊天 Agent 执行能力时，已显示的卡片会移除，之后不再生成。

## 已执行验证

- `npm run test:e2e -- --grep "回答区任务建议只生成计划并等待用户确认"`
- `npm run check`

本版本不开放自动任务创建、自动执行或无监督外部工具调用。
