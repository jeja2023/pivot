# Pivot v0.1.121 发布记录：CI 无头环境受控登录测试适配与无显示服务降级

## 版本概览

- **版本号**：v0.1.121
- **发布日期**：2026-09-10
- **核心定位**：CI / 容器 / 无头 Linux 环境受控登录流程鲁棒性加固，解决 Playwright Chromium 在无 XServer / $DISPLAY 运行期崩溃问题。

---

## 变更背景与根因分析

在 Linux CI Runner（如 GitHub Actions `ubuntu-latest`）及无 GUI 桌面环境的容器环境中运行全量测试时，`tests/agent-browser.test.js` 中的测试用例 `controlled login flow waits for user readiness without exposing credentials` 出现单测失败：
```
browserType.launchPersistentContext: Target page, context or browser has been closed
Looks like you launched a headed browser without having a XServer running.
Set either 'headless: true' or use 'xvfb-run <your-playwright-app>' before running Playwright.
[ERROR:ui/ozone/platform/x11/ozone_platform_x11.cc:257] Missing X server or $DISPLAY
[ERROR:ui/aura/env.cc:246] The platform failed to initialize. Exiting.
```

### 根本原因

1. `server/services/agent-browser.js` 中 `createControlledLoginFlow` 原本硬编码了 `{ ...options, headless: false, networkPolicy: policy }`，不仅无法通过传入参数覆盖 `headless`，而且在无头 Linux/CI 环境中由于没有 XServer/DISPLAY 会触发 Chromium Ozone 底层初始化致命错误。
2. 单元测试用例在执行受控登录断言时未显式开启无头模式，导致在 CI 构建矩阵中遭遇窗口宿主崩溃。

---

## 核心改进与修复

### 1. 受控登录支持 Headless 参数与运行环境自适应识别
- 在 `server/services/agent-browser.js` 增加 `isHeadlessEnvironment()` 环境检测函数，统一识别 CI（`process.env.CI`）、明确开关（`process.env.HEADLESS === 'true'`）以及无图形桌面 Linux 会话（`process.platform === 'linux' && !process.env.DISPLAY && !process.env.WAYLAND_DISPLAY`）。
- `createControlledLoginFlow` 调整为支持外部显式指定 `options.headless`；在未显式指定时，环境为无头环境则安全回退至 `headless: true`，桌面环境则维持原有的 `headless: false` 以便用户交互。

### 2. 自动化测试隔离与无头执行
- 在 `tests/agent-browser.test.js` 中将受控登录测试显式配置为 `headless: true`，确保在任何构建机器（Windows、macOS、Linux CI）均稳定快速执行。
- 新增 `headless environment detector recognizes CI and explicit flags` 单测，覆盖环境变量与环境探测的断言。
