# v0.7.75 四阶段系统优化与验证

日期：2026-10-30。该版本将本轮优化按 W1–W4 分类记录；各阶段是同一版本中的工作包，并非四个已经分别发布的版本。以下只将已实施并经相应验证的工作列为完成，未完成的项目保留在文末。

## W1：安全边界与优先修复

- 桌面隐身认证头只注入当前服务同源请求，跨源残留头被清除；桌面状态 IPC 不返回密钥。服务端对隐身密钥加密存储，并以条件更新迁移历史明文。
- 隐身协议新增绑定 Host 的 v2 签名，桌面客户端同时发送旧版签名以兼容既有服务；新服务默认仍接受旧客户端。客户端全部升级后可设置 `PIVOT_STEALTH_ALLOW_LEGACY=false`，反向代理需保留原始 Host。旧协议兼容期仍存在重放窗口，时间窗口本身不是一次性防重放机制。
- 旧模板独立页面跳转到工作台，安全 HTML 扫描扩展至客户端 JS 和 HTML。健康详情仅管理员可访问，目录探针不返回物理路径，实时请求仅记录粗粒度路径。
- 产物评论和交互执行遵循既有产物访问规则；匿名分享验证实际公开分享及有效期，不支持的可见性默认拒绝。服务端内部错误不再向客户端回显原始异常。
- 出站地址限制补充 CGNAT、IPv4 兼容 IPv6 和 NAT64 特定前缀；DuckDB 限制外部访问，代码 Worker 在沙箱域内构造输入。外部 PostgreSQL 连接保留只读事务、增加语句超时，并与主库类型解析隔离。
- Windows 更新校验拒绝无效或无法验证的签名；自签名更新需客户端建立证书信任并固定证书 SHA-256 指纹，非回环 HTTP 更新源需显式允许不安全 HTTP。

## W2：检索、Agent 与运行可靠性

- Wiki 列表使用稳定游标分批读取，在空间及关联专题库权限过滤后继续补足结果。RAG 缓存范围的文档、图谱和反馈版本合并为一次读取，缓存命中前仍检查权限和版本；词法候选不再提前取向量，混合排序按原权限范围批量补取。
- 长期记忆 HNSW 索引在事务外并发创建，并防止重复构建；无法确认其他构建者状态时不会擅自删除无效索引。原报告认为二级排序必然导致全表扫描的结论已修正，生产计划和召回需另行测量。
- 工具治理及发布版本在单次目录构建中批量读取和复用；实际执行仍逐项重新核验。Agent 事件批量分配序号、写入和入队，outbox 批量领取及确认、失败回退和 24 小时保留；清理时保留幂等标记。
- 持久 Agent 事件使用大整数安全的 SSE 游标。同用户新事件通过事务锁保证 ID 分配和提交顺序；重连以固定上界分页、处理背压，并对补发期间缓存的事件排序去重。单连接每次最多补发 25 页，缓存达到上限时断开重连。跨节点广播、实时阶段乱序和旧版本混跑仍不具备完整保证。
- 流式审计增量按最多 16 条或 2 秒合并并在结束或失败时冲刷；批次失败逐条尝试，仍失败时记录数量。进程异常退出或写入失败可能丢失采样增量；最终结果继续按既有流程持久化。
- 修复上下文裁剪时工具调用与结果不配对；MCP 会话按用户、账号、凭据及目标隔离并设定上限。登录、改密哈希使用有界工作线程；聊天完成上下文准备后才占用模型并发槽。
- 收紧观测和 Host 缓存，回收一次性 HTTP 连接和已确认关闭的浏览器 Profile；qpdf 和 veraPDF 探测异步化并限制资源。修复 qpdf 11.3 的加密参数，解密、优化和输出保护密码经标准输入传递；重新保护已加密输入时仍使用受限临时密码文件。
- 语音网关兼容既有路径并要求配置密钥，相关离线部署文档同步更新。

## W3：前端、依赖与交付

- 应用中心恢复子应用按需加载并预取法规资源；演示文稿复用实时事件连接，隐藏工作区减少相关轮询。流式回复结束后恢复长会话虚拟列表；设置工作区保留实际字号，由宽表格自身滚动。
- 移除 `natural` 和无代码引用的 `typescript-language-server`；工具推荐改用轻量索引。生产工作区模板缓存并修复 Pyright 子进程及桌面打包配置。
- code 和 foreach Worker 默认使用 `node:22-bookworm-slim`，终端 Worker 继续使用包含 Python、Git 和 ripgrep 的底座。只读主容器增加 Chromium 用户目录临时挂载并移除 capabilities。离线部署时可指定已审计的本地底座镜像，正式发布仍需固定镜像摘要与签名。
- 为本机运行时附加到 npm 输出末尾的特定诊断增加窄范围兼容，避免桌面打包器陷入缓慢的 JSON 回退。测试用 Windows 目录包已构建，打包后 Electron 可加载 DuckDB 和 Sharp；包未签名且使用测试配置，不可用于发布。

## W4：部署一致性与工程治理

- 数据库结构、版本迁移和种子初始化按 schema 通过独立连接加锁，避免多实例并发初始化和单连接池自锁；业务路由限流器接入共享存储。
- 维护定时器、Outbox、GPU 和模型端点监控、部分 Agent 调度、知识库、记忆、数据分析及发布熔断执行器接入关闭流程；相关执行器停止调度并等待在途任务，服务关闭等待上限为 5 秒。其他后台任务仍需逐项收口。
- 多节点就绪状态保持未就绪，严格预检会阻止启动；共享队列、存储和锁就绪不代表跨节点 SSE 已可靠投递。
- CI 避免重复运行 Node 全量测试并拆分浏览器测试；安全 HTML 和同步 I/O 扫描扩展，新增 60 KiB 生产 JS 字节基线及部分核心模块渐进式类型检查。
- 多节点 token 指标使用数据库共享快照，过期后以事务锁协调重算；单节点保持原查询。该优化保留删除和修正语义，但仍需定期扫描历史记录，尚未完成增量汇总或生产负载验收。

## 验证与限制

- 隔离 PostgreSQL 18 / pgvector 0.8.6 的最新 Node 全量回归共 2512 项，2510 项通过、2 项因离线依赖未启用而跳过、零失败。两项跳过的 FastMCP 鉴权及真实 Mermaid/Graphviz 容器集成随后单独通过。
- 隔离数据库和假模型的完整浏览器 E2E 104 项通过；部分后台停机改动在浏览器测试启动后增加，另有隔离 PostgreSQL 和定向竞态回归。最新静态检查、Lint 和类型检查通过。
- 本机已有 Node 基础镜像用于构建并运行 code/foreach Worker，验证非 root、只读、无 capabilities、断网和执行协议。默认 slim 镜像因本机代理连接失败未拉取验证；已有离线主镜像内的真实 qpdf 测试通过。新主镜像未完成构建。
- 后续进展：个人 RAG 配置已迁移为异步有界缓存，token 累计与当日统计合并为同一快照读取；文档 ZIP 异步解压，部分后台队列和旧流式服务接入受管停机，简单单段长流文本支持增量追加。桌面目录包已排除三项 PDF 依赖的源码映射；持久 Agent 事件已有跨节点数据库补查。详细限制与验证范围见优化方案的最新记录。
- 未完成：暗色模式；所有实时事件的完整跨节点投递及故障验收；异常退出后的浏览器 Profile 和其他历史临时文件回收；代表性生产数据上的检索计划、延迟与召回测量及历史向量迁移；前端资源打包与复杂 Markdown 长流优化；多节点 token 持久增量汇总；正式安装器、签名更新和目标环境验收。

## 更新与部署

部署时先备份数据库和受管数据目录，按目标环境更新主服务及配套客户端，允许启动迁移完成后再开放流量；迁移包含 outbox 清理所需的事件退役标记。多节点环境保持严格预检阻断，直到广播、重放及故障恢复通过验收，且所有事件写入节点已升级到同一用户级顺序锁协议。旧版隐身客户端升级完成前保留兼容开关；关闭兼容前检查代理 Host 转发与客户端版本。上述目录包仅为本机验证产物，不是正式发布物。

完整方案的修订、测试范围及剩余验收条件见 [系统优化方案](../reports/pivot优化方案20261030.md)。
