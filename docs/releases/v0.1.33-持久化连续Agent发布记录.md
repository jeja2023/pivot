# v0.1.33 持久化连续 Agent 发布记录

发布日期：2026-08-23  
适用端：Web、Electron 客户端、服务端 PostgreSQL 部署  
版本来源：`CHANGELOG.md` 顶部版本标题；通过 `npm run version:sync` 同步到包和 README

## 1. 发布目标

本版本解决普通聊天离开会话后任务仍在后台执行、但回复记录不稳定或消失的问题。普通聊天现在自动获得与自主任务相同的持久化运行语义：聊天请求负责创建任务和显示接管状态，Agent Runtime 负责持续规划、工具调用、审批等待、恢复和最终结果沉淀。

用户无需改变聊天入口、模型选择、RAG/MCP 开关或附件操作方式。Web 和 Electron 共享同一服务端合同，客户端只负责展示状态、恢复连接和发出控制命令。

## 2. 运行链路

```text
普通聊天 / 重新生成
        |
        v
聊天预检 -> 保存用户消息或复用源消息 -> 组装 chatBridge metadata
        |
        v
创建持久化 agent_run -> SSE agent_handoff -> Agent Runtime 后台执行
        |
        +--> agent.streaming / agent.run 实时事件
        +--> 工具、审批、检查点、预算、网络策略和重试
        |
        v
终态回写 messages.agent_run_id -> 会话刷新/恢复 -> 长期记忆与标题后处理
```

## 3. 持久化合同

### 3.1 Agent metadata

`chatBridge` 保存以下受控字段：

- 会话 ID、原用户消息 ID、可见文本和当前用户消息。
- 最近 24 条 user/assistant 历史，单条内容有长度上限。
- 会话 system prompt。
- `mcpEnabled`、MCP 工具白名单、RAG 开关和 RAG scope。
- 长期记忆上下文和 RAG 检索上下文，均按字符预算截断。
- bridge 版本、创建时间和最终写回的 `messageId`。

内容不会直接信任客户端的任意结构；服务端会重新读取用户会话、校验用户归属并通过视觉输入安全路径处理图片附件。

### 3.2 结果幂等

终态写回遵循以下顺序：

1. 查询 Agent metadata 中已有的 `messageId`。
2. 查询 `messages.agent_run_id` 是否已经存在助手消息。
3. 不存在时写入一条助手消息，并更新耗时、Tokens/秒、会话时间和后处理任务。
4. 将生成的消息 ID 写回 Agent metadata。
5. 并发回调撞上唯一索引时，失败方重新读取获胜消息并返回同一 ID。

因此，重复 SSE、进程恢复、后台扫描和客户端重连不会重复生成助手结果。

## 4. 断线与恢复

- 服务启动恢复扫描查询已完成但未写回的聊天 Agent，并补写最终答案或错误摘要。
- 打开会话时，客户端调用 `/api/agents/runs/chat-active?sessionId=...`。
- 活跃运行显示“规划/工具调用/等待审批”等临时状态，完成运行会在恢复扫描或轮询后显示最终消息。
- SSE `agent.streaming` 提供低延迟状态；SSE 断线时现有 Agent 轮询作为兜底。
- 会话请求带选择序列保护，旧会话响应不能覆盖后选会话。

## 5. 重新生成语义

重新生成请求不再插入新的用户消息。服务端从当前用户自己的会话读取最近一条用户消息，复用其 ID、内容和历史，创建新的持久化 Agent 运行。以下错误均有明确行为：

- 无法读取源消息：返回 `REGENERATE_SOURCE_UNAVAILABLE`。
- 没有可重生成的用户消息：返回 `REGENERATE_SOURCE_NOT_FOUND`。
- Agent 创建失败：返回 `AGENT_HANDOFF_FAILED`，并在适用情况下持久化可见错误助手消息。

## 7. 客户端控制

普通聊天状态条复用 Agent 控制合同：

- 停止：取消 Agent 运行并中止当前前端请求。
- 批准：提交审批决定，运行继续推进。
- 拒绝：提交拒绝决定，运行进入终态并回写说明。
- 继续：对可恢复的失败/中断运行发出 resume 控制。
- 详情：跳转到完整 Agent 运行详情，查看步骤、工具、审计和最终结果。

## 9. 上线前冒烟

自动化测试没有替代真实部署环境中的模型和 Electron 验证。上线前应使用实际模型凭据执行：

1. Web 普通聊天发送一个需要工具或多轮规划的任务。
2. 关闭/刷新页面，确认任务仍在执行并最终回写原会话。
3. 在另一台 Electron 客户端打开同一会话，确认能看到状态和最终答案。
4. 验证审批、停止、拒绝和继续操作。
5. 验证重新生成不重复插入用户消息。
6. 检查服务日志、Agent 运行记录和 `messages.agent_run_id` 关联。

真实供应商凭据、生产浏览器账号和正式 Electron 安装包属于部署环境验证项，不在本地隔离测试中伪造通过。
