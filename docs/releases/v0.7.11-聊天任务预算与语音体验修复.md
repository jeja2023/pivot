# v0.7.11 聊天任务预算与语音体验修复

根因：聊天自动接管同时写入 maxTokenBudget=60000 和 budget_config.max_tokens_total=60000，覆盖任务通用默认值。多轮调用重复传入上下文，累计输入输出容易超过 60000；这与模型的单次上下文窗口不同。

新任务创建时使用统一模型预算策略：

- AGENT_TASK_MAX_TOKENS_TOTAL=0 或留空：按已配置模型窗口的 8 倍计算，最低 500000，自动最多 10000000。
- 正整数：使用部署方显式累计限额，最多 10000000。
- 显式 budgetConfig、已有运行和已审批草案：保持原预算，不在恢复时自动放宽。新草案的预算进入审批快照，启动时两层预算一致。
- 步骤、工具、时间、风险与审批约束继续有效；单次上下文裁剪继续由模型配置管理。

Qwen3.6-35B-A3B 官方标注原生窗口为 262144。部署实际按该容量启动时，在 Pivot 模型配置填写 context_window_tokens=262144，自动累计预算为 2097152；单次输入需扣除输出预算及安全余量。仅修改 .env.example 不会更新生产 .env，已有正数值需要管理员按实际目标调整，随后重启/重建服务并创建新任务。[官方模型说明](https://huggingface.co/Qwen/Qwen3.6-35B-A3B)

语音保留现有 Windows 系统识别、部署内识别、浏览器本地识别及本地朗读，没有替换引擎或启用外部服务。Windows 桌面原生识别不依赖页面麦克风接口；旧客户端缺少原生接口或 IPC 不匹配时明确提示更新客户端。普通浏览器录音继续遵守安全上下文要求，没有关闭浏览器安全设置。[麦克风安全上下文要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

实时语音开启后先聆听；完成识别后提交本次语音问题，模型回答按句朗读。新增输入区状态，区分聆听、识别、等待和朗读。修复流式文本恰在句号结束时未及时入队的问题，朗读语言跟随所选本地声音，保留当前播放对象引用，恢复暂停的朗读引擎；播放失败或未启动时提示系统音量、输出设备和中文语音组件，停止时清除状态、定时器与引用。

窄屏验收发现样式压缩器会把 calc 中的 --sidebar-width 变量名当成减法拆开，导致收起侧栏后仍占宽度。移除该错误重写，保留源 CSS 的合法运算空格；补充三项构建测试并重建样式包。任务创建表单也将“留空表示不限”修正为“留空自动分配”，避免与实际累计预算策略冲突。

用户已确认更新客户端后识别和实时语音正常，因此本次仅做状态与播放细节优化，不改为新的语音架构。本次不部署生产、不修改生产数据库或已有任务限额。

验收见 [报告](../reports/聊天任务预算与语音体验验收报告_2026-10-19.md)。
