# Pivot v0.7.193 发布说明

2026-11-21 · PPT Master 模板制作稳定性修复

## 模型上下文与逐轮诊断

- 进入制稿阶段时，如果当轮可见的宿主指引全文已覆盖先前的分页工具结果，则按路径、字符偏移和原文比对后收起重复的分页正文。尚未覆盖或文字不同的结果继续呈现，分页元数据与原检查点保留。
- 所选模板规范已随宿主消息发送时，收起已由它覆盖的任务副本或运行包读取结果。模型仍可按需要读取所选模板及项目文件。
- 完整制作每轮等待完整 JSON，采用现有的 `AGENT_MODEL_REQUEST_TIMEOUT_MS`，默认 600 秒。制作过程显示实际配置的本轮等待时限，已有配置继续生效。
- 逐轮诊断区分 Pivot 等待超时、连接或传输超时、上游 HTTP 504 和模型连接提前关闭。有记录时同时显示本轮排队和模型端点请求用时，方便定位等待发生在哪一段。

## 模板选择、恢复与交付

- 更换模板保留表单及已选素材。存在另选的 PPTX 原稿时，提交前提示移除冲突原稿，图片及音视频可以保留。
- 模板制作的补充素材上限为 20 个，前端在模型预检和上传前校验，服务端继续校验创建请求。
- 模型将任务内的 `selected-template/` 副本误用运行包读取时，宿主改用任务文件读取，并保留分页参数。
- 支持恢复的执行器先在临时目录准备并核对副本，再替换任务中的目标目录。完整副本可直接复用，同一运行身份内可修复上一次留下的残缺副本。
- 最终清单的模板引用须来自规范的设计规则正文，元数据不能充当规则。正式交付核对模板安装摘要、对应页码和可见文字，结果标明需人工复核的风格规则。

## 升级与兼容

- 更新 Pivot 主应用可使用表单、上下文、诊断、路径兼容和交付证据的改进。要启用模板副本恢复，需同时重建并更新 PPT Master v6.10.0 独立执行器，确认服务报告 `selectedTemplateRecovery: 1`。
- 相对 v0.7.192 无新增数据库迁移或必填配置。保留原服务连接配置、访问密钥和持久任务卷。旧检查点继续绑定原执行器运行身份，切换镜像前应在原环境完成仍需续跑的任务。[部署与复验步骤](../deployment/PPTMaster独立服务部署与更新.md#v07193-ppt-master-模板制作稳定性修复)

## 验证记录

- 升版后通过 `npm run check`，核对软件包、锁文件、README、设计基线和运行时版本。5 条发布文档链接通过检查，独立本机实例的 `/version.json` 返回 `v0.7.193`。
- 修复批次通过 `npm run check`、变更文件 ESLint 检查及 136 项定向回归。Python 部署与执行器测试运行 31 项，20 项通过，11 项在该 Windows 验证环境跳过。
- 用同一学术研究模板和分段读取记录做本地对照回放，制稿请求的预计输入从 71,636 降至 43,032 令牌，约减少 40%。这是 Pivot 对合成请求的输入估算，生产模型耗时和计费令牌留待现场复验。
- 「咨询决策」和「学术研究」通过浏览器端到端测试，使用模拟模型和包含修复的真实执行器，覆盖选模板、自动修页、PPTX 下载及交付证据。14 个内置模板在该执行器上均通过残缺副本恢复、安装与摘要核对。
- 本版启用源码版本号。正式制品构建、生产部署及用户自部署模型原任务复验待进行。
