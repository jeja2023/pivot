# v0.7.114 — BI 旧探索受控迁移与固定来源对照

落实建设方案第 14.1 节。旧关联探索保留原 ID、关系和查询行为；用户从模型列表明确创建一个新的个人正式草稿，不自动替换历史资产。

## 迁移与对照合同

盘点原关系、可见单数据集指标、本人来源视图及已登记数据版本；尚未登记历史版本的旧数据如实显示当前修订和行数。用户选择事实表与粒度，保留原关系方向、键及基数，不支持的多对多、反向关系和非事实指标保留为草稿待完善项。指标复制后独立维护，并记录原指标 ID 和修订；修改原指标不改变新草稿或历史发布版本。

迁移请求绑定盘点摘要、修订和幂等键，新草稿、不可改写来源记录及审计同事务提交。重复或并发提交同一请求只创建一个模型；盘点后来源或指标变化要求重新确认。

首次检查选择一至五个维度及一至十个旧探索可比指标，覆盖记录数、金额或其他数值汇总、原关联未匹配数和完整分组。新旧计算复用同一个不可变来源清单；旧值保留原始文本关联键及双精度数值规则，导入指标的旧值使用迁移时冻结的原配置。正式值使用当前声明的精确语义。去重和派生口径通过正式试算验证，不虚构旧探索不具备的聚合能力。

对照最多完整核验五千个分组，超过上限保持未完成并阻止首次发布。无法复现的原图、成员键歧义、丢失旧来源也不计为通过。修正图期间保留原来源和节点标识，以便共同固定快照；完成首次对照发布后，后续版本沿用正常差异与发布流程。数值或口径有差异时展示原因，发布者逐项填写接受原因，记录绑定检查和来源清单；服务端拒绝缺少完整对照的首次发布。

对照所需旧键和原指标字段在准入、执行、读取与提交时核验当前权限。对照合同保存在不可改写的检查记录中，任务记录被保留策略清理后仍不能绕过旧字段权限。正式任务的请求内容和已经固定的清单也不能改写。

发布并完成正式运行后，可在“保存为分析视图”中明确选择一个盘点中的旧视图；确认后才切换到该模型版本，并收窄为个人视图。其余视图、仪表盘和原探索不批量替换。视图变更再次核对本人所有权与修订，并写入原配置摘要。
