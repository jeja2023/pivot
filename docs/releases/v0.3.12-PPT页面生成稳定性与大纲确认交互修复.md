# v0.3.12 - PPT 页面生成稳定性与大纲确认交互修复

> **发布日期**：2026-10-16  
> **升级类型**：PPT AI 结构化输出可靠性、确认交互与生成预算治理修复  
> **兼容性**：向后兼容；不涉及数据库迁移，不改变既有演示文稿、模板、素材或导出文件

## 版本概述

本版本解决 PPT 制作应用在“确认演示大纲”后生成页面时，长时间等待后提示“AI 返回的页面数据格式不完整”的问题；同时将原先只能阅读、无法操作的“待确认”提示改为明确可执行的确认流程。

## 一、页面生成的结构化输出韧性

- 页面生成请求的输出预算调整为最多 7200 tokens，并限制每页至多 4 个元素、每段正文不超过 240 个字符、演讲备注不超过 160 个字符，降低多页文稿输出过长而截断 JSON 的风险。
- 服务端仍会先使用本地容错处理代码围栏、字符串内换行和尾随逗号等常见格式问题。
- 如果模型返回的页面 JSON 未闭合或无法解析，系统会从已经确认的大纲重新发起一次“紧凑输出模式”请求，而非尝试补齐已丢失页面的原始残片。
- 紧凑模式要求每页使用 2 至 3 个元素（含标题）、清空演讲备注，并避免在没有可核实数据时生成表格或图表；这样可在保留大纲事实约束的同时缩短响应。
- 两次请求仍无法形成有效页面数据时，界面会提示减少页数或补充材料后再试，不会创建不完整文稿。

## 二、待确认项的可执行交互

- AI 大纲中的 `assumptions` 现在逐条显示为可勾选的“待确认”项，而不是静态文字。
- 用户可逐条确认，也可使用“确认全部待确认项”一次完成；界面实时显示“已确认 X / Y 项”。
- 存在未确认项时，“生成页面”按钮被禁用，并提供明确原因；全部确认后才允许向页面生成接口提交大纲。
- 普通“提示”仍为只读风险说明，不会阻塞生成。若假设不成立，用户可选择“返回调整要求”，修改主题、材料或约束后重新生成大纲。

## 三、256K 上下文与输出预算策略

生产模型的 256K 上下文窗口主要用于承载较长的材料、模板信息和已确认大纲；它不表示页面生成应使用同等规模的输出 token。

- 本版本保留受控的 7200 output-token 上限，而不因 256K 窗口直接提升到 12K 或 16K。
- 较大的输出上限会显著增加响应时间、调用成本以及 JSON 在末尾截断或格式失效的概率。
- 若生产调用的 `usage.outputTokens` 长期接近 7200，且紧凑重试仍频繁发生，可将上限小幅评估至 8192；超过 12 页或含大量表格、图表的文稿应优先采用分批生成，而不是继续放大单次输出。

## 四、部署与验证

- 后端路由、前端交互脚本及合并后的应用样式包需要作为同一版本部署；浏览器刷新后即可使用新的确认交互。
- 本版本不包含数据库迁移；常规应用发布或桌面端打包流程即可交付。
- 已完成 PPT 专项 39 项自动化测试、相关 JavaScript 语法检查、ESLint 与前端静态资源检查。
