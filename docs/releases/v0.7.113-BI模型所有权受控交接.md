# v0.7.113 — BI 模型所有权受控交接

对应生产建设方案第 22.3 节的所有者离岗处理。该流程仅处理已有模型的维护责任交接，沿用现有账号、来源权限、共享复核及计划任务体系。

## 交接合同

所有者先选择接收人，系统核对接收人对当前草稿和全部保留发布版本的来源及字段权限，展示模型修订、共享影响和相关刷新/工作流计划。申请绑定影响摘要、接收人、新业务负责人、维护联系人和原因，七天有效；相同幂等键不能改为另一份申请。

接收人从模型列表的“模型交接”入口核对并逐项确认。接受时重新取得当前授权和模型写入栅栏，核验来源权限、当前所有者、修订、发布绑定和计划摘要。模型或计划变化须重新发起；活动任务或保留中的执行槽未结束时拒绝交接。并发接受两个请求只允许一个成功。

成功后仅改变模型所有者，草稿修订递增，模型转为个人，原共享证据失效，相关旧主体的刷新与工作流计划暂停。数据集、历史发布快照、原分析视图和凭据保留各自归属；计划重新启用须在原计划入口重新确认模型访问、执行主体和依赖绑定。重新共享须有新的业务复核。

接受、拒绝和撤回写入不可改写的终态及同事务审计。权限变化使申请不能接受时，仍允许双方处理拒绝或撤回。系统管理员仅可为已停用或删除的所有者发起，仍必须由具备全部来源权限的另一位接收人确认；管理员身份不增加来源读取权。

原生分析刷新在执行前重新加载账号，停用或删除后将计划暂停。草稿、发布、共享和交接统一先取得模型授权栅栏再取行锁，编辑直接取排他锁，避免共享锁升级与行锁交叉等待。
