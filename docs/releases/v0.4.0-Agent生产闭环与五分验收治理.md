# v0.4.0 - Agent 生产闭环与五分验收治理

发布日期：2026-10-18

## 发布定位

v0.4.0 是对 v0.3.20（验收治理与可恢复工作区）和 v0.3.21（SLO PostgreSQL 修复）的正式 minor 汇总发布。版本范围涵盖 Agent 运行时、控制面、安全执行、工作区恢复、协作编排、质量治理和可观测性，不是一次普通补丁更新。

本版本不将任何领域标注为生产 5 分。18 个领域的代码、测试和认定机制已显著完善，但 5 分仍须由受控环境中的灰度周期、跨平台演练、SLO、外部证据和委员会签署证明。

## 完整变更台账

### 1. 五分验收与委员会治理

- 落地 18 领域结构化验收台账、冻结指标策略、受控证据产物 SHA-256、独立核验和历史自由文本排除机制。
- 五类证据为实现审查、自动化、非功能、灰度、委员会；非功能/灰度要求最少 30 样本，灰度至少 24 小时且 P0/P1=0。
- 系统管理员配置四方委员会成员；每位成员以本人登录态签署，签署人与提交人均不能核验同一委员会记录。
- 新增质量面板台账、受控 JSON 模板、委员会成员配置、签署进度和独立核验入口。

### 2. 受控执行、授权和隔离

- 高风险动作使用短期一次性 Execution Grant，绑定调用主体、Run、工具、输入摘要、资源和策略快照。
- Capability Worker 仅使用 RSA-SHA256 签名清单中的 `image@sha256` 和固定命令，缺配置、签名、预置镜像或授权时 fail-closed。
- Docker Worker 固定非 root、只读根、无网络、Capabilities 清空、无在线拉取、PID/内存/CPU 约束及受限挂载。
- 新增 Worker 部署预检和 staging 隔离演练；演练复用真实 Worker 参数并验证非 root、根只读、Capabilities 清空、外网阻断。

### 3. 事务、恢复和受控工作区

- Task Transaction 对通知、HTTP 写和工作区效果进行暂存、验收、提交、补偿和资源租约治理；跨 Run 业务幂等键阻止重复副作用。
- 非幂等结果不确定时需任务所有者提交持久化结论与证据，系统不会自动重放。
- 影子工作树补丁后生成本机 gzip 内容寻址归档；排除 `.git`、`node_modules`、符号链接、`.env`、`.npmrc`、私钥、证书、密码库等敏感项，并限制 1,000 文件/20MB。
- 摘要与恢复句柄进入事务快照；恢复工具需要人工确认，重新校验句柄和摘要，只能写入新的 Pivot 管理目录。

### 4. 智能运行时、协作与扩展

- 渐进工具发现按 ACL、目录版本、TTL、契约和风险摘要失效；读批处理派发前重新核对当前目录。
- 模型质量路由、故障分类与单次兼容降级保持工具、审批、预算和网络约束不扩大。
- Hook 包组织级签名、输入输出 Schema、范围/超时/排序/审计、`run.started` fail-closed 和包导入/停用/吊销均实现。
- Agent Handoff 使用持久化状态机；Supervisor 只汇合已验证、非空且可靠交付的子任务，组织委派角色只能收紧权限和资源上限。

### 5. 数据治理、交互安全与质量运营

- Working Memory 不可变修订、三级上下文压缩、CAS 引用与硬字段保留指标；Prompt 稳定段审批/原子激活/缓存可观测；长期记忆来源复核、撤销和效用周期已连接。
- 浏览器写操作保存脱敏 Observe/Act/Observe 证据和恢复栅栏；下载/上传均受内容边界约束；语音控制只作用于当前会话关联 Run。
- JS/TS/Python 工作区语义导航基于 TypeScript Language Service 和受控 Pyright，索引不保存源码且拒绝目录越界。
- 评测分层、双裁判、人审、发布熔断与回滚；运行 SLO 低样本不通过、真正越界才告警。修复了 JSONB `?` 运算符被参数转换器错误改写为 `$1` 的 SLO 监视故障。

### 6. 文档、迁移与验证

- 新增 [18 领域五分验收运行手册](../agent-experience/five-point-acceptance-runbook.md)，给出每个领域的工程验证、外部证据和禁止误判条件。
- 新增验收、委员会、Hook、事务、浏览器、Prompt、记忆、协作等版本化 PostgreSQL 迁移；迁移覆盖门禁通过。
- 完整工程明细见 [v0.3.20 变更台账](v0.3.20-全域五分验收门禁与可恢复工作区闭环.md)，SLO 热修复见 [v0.3.21 记录](v0.3.21-Agent运行SLO监视PostgreSQL语法修复.md)。
- 最后完整验证：`npm run test:agent:quality` 152/152 通过，`npm run check` 全量通过。

## 仍未满足的生产验收条件

尚需由真实受控环境完成：Windows Docker 与 Linux Worker 隔离/恢复实机演练、签名镜像发布链、真实生产样本/容量/SLO、每领域完整灰度周期、P0/P1 记录、第三方副作用恢复演练，以及四方委员会实际签署与独立核验。未满足前不得把任何领域或本版本描述为“全域 5 分”。
