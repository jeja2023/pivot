# v0.1.62 发布记录：Skill 个人创作与组织共享流程简化

发布日期：2026-09-01

## 结果

Skill 使用方式收束为两条路径：个人创作保持轻量，组织共享保持集中治理。

| 场景 | 操作人 | 签名要求 | 发布条件 |
| --- | --- | --- | --- |
| 个人草稿与个人发布 | 技能作者 | 不需要 | 清单、声明式检查、沙箱与评测通过 |
| 团队或组织共享 | 租户管理员 | 需要组织签名 | 管理员批准、服务端组织签名和全部门禁通过 |
| 兼容技能包导入 | 导入者 | 需要有效签名 | 受信公钥验签与供应链检查通过 |

## 已完成

### 个人创作

- 单文件技能配方可直接创建个人草稿、预览校验、保存新版本和发布给本人使用。
- 个人用户无需持有组织私钥，也不会被未配置组织签名的环境阻断。

### 组织共享

- 技能治理窗口新增“批准共享版本”操作；只有当前租户管理员可以执行。
- 管理员批准后，服务端从部署环境读取组织私钥，生成不可变签名信封，并重新执行完整验证；未批准版本不能发布到团队或组织。
- 浏览器请求不接收私钥、私钥 Base64 或密钥标识。私钥不会保存到数据库、Skill 配方或客户端。
- 个人与组织目录投影按 owner key 分离，避免同一版本在不同范围发布时发生目录主键冲突。
- 分离式兼容包签名会同包摘要一起持久化为版本信封，后续验证复用同一签名载荷。

## 部署配置

部署端需要为组织共享配置一对匹配的 RSA 密钥：

```dotenv
# 公钥：用于复验共享版本和兼容技能包。
AGENT_SKILL_PUBLIC_KEY=
# 私钥的 Base64 PEM：仅在服务器的密钥管理/环境注入中保存。
AGENT_SKILL_ORGANIZATION_PRIVATE_KEY_BASE64=
# 可审计的固定密钥标识。
AGENT_SKILL_ORGANIZATION_KEY_ID=organization-default
```

未配置上述密钥时，个人 Skill 仍可正常使用；管理员尝试批准共享版本时会得到明确的配置提示，不会降级为无签名共享。

当前生产环境没有存量 Skill，因此 PEP 已直接运行在：

```dotenv
PIVOT_AGENT_PEP_MODE=enforce
```
