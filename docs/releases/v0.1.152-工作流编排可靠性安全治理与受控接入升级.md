# Pivot v0.1.152 发布记录：工作流编排可靠性、安全治理与受控接入升级

## 发布概要

v0.1.152 完成《[Pivot 工作流编排能力对标与升级方案](../../Pivot工作流编排能力对标与升级方案.md)》中当前代码库可闭环的 A～F 阶段工作项。改造坚持现有 `dag_spec`、PostgreSQL、CAS、MCP、凭据与工具治理底座，不新建并行工作流 IR 或第二套连接器平台。

本版本重点处理“定义可保存但运行语义不完整”“缓存可能脱离授权上下文”“嵌套执行难以恢复”“大输出不可安全复用”“多实例配额停留在内存”等问题。外部 Worker、消息代理、S3、通用补偿和实时协同仍按负载与场景门槛后置。

## 用户可见能力

### 1. 更可靠的编排与恢复

- 新增 `joinMode=any_active`：True/False 互斥分支汇聚时，只要存在已激活分支即可继续；未命中分支不会被误当作成功依赖。
- 指定节点重跑保留完整原图、路由边、Schema 和布局，不再通过裁剪子图改变原执行语义；复用节点记录来源运行 ID。
- 节点失败会生成结构化 `errorInfo`，包括分类、错误码、可否重试、建议处理方式、尝试次数与超时标记。
- 新增“使用契约化兜底输出”失败策略。兜底值必须通过该节点输出 Schema 校验；不合格时仍保留失败状态和校验原因。

### 2. 子工作流与数组批处理

- 子工作流拥有独立 invocation ID、调用路径和固定解析版本；同名子节点、审批键与操作键不会与主图或其他调用点混用。
- 新增“逐项调用子工作流”节点 `workflow.iteration`：支持数组来源、输入映射、最大项数、1～10 路并发、停止/保留失败/过滤失败三种策略。
- 每个结果保留输入索引、状态、输出或错误、调用实例和固定版本；迭代子流程首期限制为无副作用、无审批、无延时、无循环节点，避免将结果未知的外部动作并发放大。
- 运行详情新增子工作流调用列表，展示调用路径、版本、父调用与失败摘要。

### 3. 调试、变量与 AI 预设

- 节点测试结果只存在当前编辑会话，支持覆盖、恢复和 Mock；Mock 不调用工具、不改变定义、不进入正式运行或发布产物。
- Mock 与兜底输出均在编辑期校验输出契约，避免下游基于无效测试数据配置字段。
- 变量目录区分真实工具字段、测试样本、测试覆盖和模拟结果。
- 节点库新增“参数抽取”“内容分类”预设，均基于现有 `agent.llm` 的结构化 JSON 输出与可编辑输出 Schema，不引入独立模型执行器。

### 4. 受控 API 接入与可迁移包

- 工具库可导入受限的 OpenAPI 3 JSON 操作；导入不发送请求，仅生成受控工具定义。
- API 操作沿用既有凭据引用、安全 HTTP、网络策略、审批和工具目录。写方法强制副作用/审批契约，操作不参与 DAG 缓存。
- 工作流导出新增依赖清单：模型、工具、凭据引用、网络目标、子工作流版本和脱敏字段均可审查。
- 导出会清除 Header、URL 参数等敏感字面量；导入会拒绝未脱敏的敏感字段，目标环境需自行配置凭据。

## 安全与正确性

### 缓存与定义版本

- 缓存准入由 `cacheable` 工具契约决定，未知工具和具有副作用、审批或沙箱交互的工具默认不缓存。
- 缓存键包含调用用户、租户、工作流/版本、节点、工具版本、模型、绑定版本和绑定更新时间，不记录密钥正文。
- 工作流定义在编辑、保存、导出、导入、发布、Diff 和重跑之间完整保留输入/输出 Schema、`when`、重试、超时、失败策略、兜底输出、缓存、汇聚模式和路由边。

### 发布、评测与访问控制

- 发布历史、发布回滚和版本解析统一使用工作流资源访问控制；共享接收者仅能读取授权发布信息，不能借 ID 查看草稿或发布目标详情。
- 保存使用事务内锁定与版本 CAS；发布在预检通过后原子更新 release 与发布指针，避免半发布状态。
- 评测批次冻结用例输入、断言、目标工作流版本和相关快照；批次内不会重新解析动态 `current`/`published` 别名。

### 大输出与生命周期

- 超过节点内联阈值的完整输出写入已有 CAS，节点仅保存受控预览、引用、摘要和完整性信息。
- 完整输出读取复核租户/用户授权；未落盘或已失效的预览不具备自动重放资格。
- 节点覆盖、物理删除和保留期清理会更新 CAS 引用计数，避免活动节点引用的对象被提前回收。

## 多实例运行与观测

- 新增 `agent_run_concurrency_leases`，用 PostgreSQL 事务和 advisory lock 原子限制每用户跨实例并发；租约过期后可以回收。
- 队列续期同时续运行锁和用户并发租约；租约丢失、被其他实例接管或跨实例取消时，旧执行器停止提交结果。仍由当前实例持锁的任务安全回队等待重新认领。
- 新增以下低基数指标：
  - `pivot_workflow_dag_node_total`
  - `pivot_workflow_dag_cache_total`
  - `pivot_workflow_invocation_total`
  - `pivot_workflow_iteration_item_total`

- 拆分子工作流/迭代运行器、HTTP 工具、OpenAPI API 路由、OpenAPI 工作台、节点测试/Mock 和子工作流运行详情渲染，避免核心文件继续增长。

## 兼容性与边界

- 旧 DAG 保持既有 `dependsOn`、`condition` 与默认全量汇聚语义；`any_active` 是显式新字段。
- 已有节点输出形状不被统一包装为 Items；文本、对象、`rows`、`structuredContent` 和产物引用继续兼容。
- 发布版本一经某次运行/子工作流/评测解析即固定；之后的发布或回滚仅影响新的动态引用。
- 本版本不增加 Redis/RabbitMQ/Kafka、S3、独立 DAG Worker、通用 Saga 补偿、实时协同或任意嵌套循环。这些能力仍需满足方案中的业务与负载立项条件。
