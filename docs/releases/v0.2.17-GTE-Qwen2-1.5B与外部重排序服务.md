# v0.2.17：GTE-Qwen2-1.5B 与外部重排序服务

发布日期：2026-10-13

## 推荐生产组合

```text
Embedding：Alibaba-NLP/gte-Qwen2-1.5B-instruct
Reranker：BAAI/bge-reranker-v2-m3
```

`gte-Qwen2-1.5B-instruct` 输出 1536 维向量，可直接使用项目现有 pgvector HNSW 索引；法规与知识库共同使用该系统级模型。`bge-reranker-v2-m3` 是独立 Cross-Encoder，只接收“查询 + 已授权候选正文”并重新排序，不生成或存储向量。

## Windows GPU 服务建议

在独立的 Windows Server 上分别部署两个局域网服务，避免 Embedding 批量建库与在线精排争抢同一个模型进程：

```text
http://<gpu-server>:8080/v1/embeddings → Alibaba-NLP/gte-Qwen2-1.5B-instruct
http://<gpu-server>:8081/rerank        → BAAI/bge-reranker-v2-m3
```

推荐使用 Hugging Face Text Embeddings Inference（TEI）或提供同等 JSON 契约的内部网关。Embedding 服务必须兼容 OpenAI 的 `POST /v1/embeddings`；Reranker 服务必须接收：

```json
{"query":"问题","texts":["候选一","候选二"],"model":"BAAI/bge-reranker-v2-m3","raw_scores":false}
```

并返回带 `index` 与 `score` 的 `results` 数组。模型服务仅向 Pivot 应用服务器所在网段开放，并建议在反向代理处要求 Bearer Token。

## Pivot 系统配置

在 admin 的“知识库 → 检索配置”中填写：

```dotenv
EMBEDDING_API_URL=http://<gpu-server>:8080/v1
EMBEDDING_MODEL=Alibaba-NLP/gte-Qwen2-1.5B-instruct
RERANK_ENABLED=true
RERANK_API_URL=http://<gpu-server>:8081
RERANK_MODEL=BAAI/bge-reranker-v2-m3
RERANK_PROTOCOL=tei
RERANK_CANDIDATE_LIMIT=30
RERANK_TIMEOUT_MS=1800
```

`RERANK_CANDIDATE_LIMIT` 应保持在 20–40；它只影响最终精排窗口，不会扩大权限范围或数据库初始召回范围。连续 3 次失败后，重排序进入 30 秒熔断，自动使用原有 RRF、词法与轻量确定性排序。

如改用 llama.cpp 部署 Reranker，保持地址不变并将 `RERANK_PROTOCOL=llama_cpp`。项目会改用 llama.cpp 所需的 `documents` 请求字段；TEI 继续使用 `texts` 字段。

## Windows Server 上的 llama.cpp

从 llama.cpp 官方 Release 下载与 NVIDIA 驱动匹配的 Windows x64 CUDA 压缩包，解压后令 `llama-server.exe` 位于 `D:\llama.cpp`。以下 PowerShell 示例使用社区转换的 GGUF；部署前应以实际检索样本确认输出维度为 1536、并验证与原始模型的召回效果。

```powershell
$LlamaHome = 'D:\llama.cpp'
$ModelRoot = 'D:\pivot-models'
New-Item -ItemType Directory -Force -Path "$ModelRoot\embedding", "$ModelRoot\reranker" | Out-Null
py -m pip install --upgrade huggingface_hub
hf download tensorblock/gte-Qwen2-1.5B-instruct-GGUF gte-Qwen2-1.5B-instruct-Q5_K_M.gguf --local-dir "$ModelRoot\embedding"
hf download cstr/bge-reranker-v2-m3-GGUF bge-reranker-v2-m3-q8_0.gguf --local-dir "$ModelRoot\reranker"
```

分别启动两个进程：

```powershell
& "$LlamaHome\llama-server.exe" -m "$ModelRoot\embedding\gte-Qwen2-1.5B-instruct-Q5_K_M.gguf" --embedding --pooling last --embd-normalize 2 --ctx-size 8192 --parallel 4 --batch-size 2048 --ubatch-size 1024 --n-gpu-layers 99 --host 0.0.0.0 --port 8080 --alias 'Alibaba-NLP/gte-Qwen2-1.5B-instruct' --api-key '<embedding-key>' --no-webui --metrics

& "$LlamaHome\llama-server.exe" -m "$ModelRoot\reranker\bge-reranker-v2-m3-q8_0.gguf" --embedding --pooling rank --rerank --ctx-size 4096 --parallel 2 --n-gpu-layers 99 --host 0.0.0.0 --port 8081 --alias 'BAAI/bge-reranker-v2-m3' --api-key '<rerank-key>' --no-webui --metrics
```

只允许 Pivot 应用服务器访问端口，避免向公网暴露模型端点：

```powershell
New-NetFirewallRule -DisplayName 'Pivot embedding from application server' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8080 -RemoteAddress '<PIVOT_APPLICATION_SERVER_IP>'
New-NetFirewallRule -DisplayName 'Pivot reranker from application server' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8081 -RemoteAddress '<PIVOT_APPLICATION_SERVER_IP>'
```

检查服务：

```powershell
curl.exe http://127.0.0.1:8080/health
curl.exe http://127.0.0.1:8081/health
curl.exe http://127.0.0.1:8080/v1/embeddings -H "Authorization: Bearer <embedding-key>" -H 'Content-Type: application/json' -d '{"model":"Alibaba-NLP/gte-Qwen2-1.5B-instruct","input":"劳动合同试用期最长多久"}'
curl.exe http://127.0.0.1:8081/rerank -H "Authorization: Bearer <rerank-key>" -H 'Content-Type: application/json' -d '{"model":"BAAI/bge-reranker-v2-m3","query":"劳动合同试用期","documents":["劳动合同试用期最长不得超过六个月。","公司应按月支付工资。"]}'
```

在 Pivot 中填写 `EMBEDDING_API_URL=http://<gpu-server>:8080/v1`、`RERANK_API_URL=http://<gpu-server>:8081` 和 `RERANK_PROTOCOL=llama_cpp`。保留当前 BGE-M3 服务可以作为**冷备**；由于单条文/分块当前仅存一套向量，GTE 全量重建后无法即时用 BGE 向量接管语义检索。主服务故障时系统会安全回退到关键词检索；如需 BGE 热备语义检索，必须另行建设双向量存储与双索引。

## 模型切换步骤

1. 先在系统检索配置保存 GTE 与 Reranker 地址，使用 Embedding“测试连接”确认应返回 1536 维。
2. 法规查询进入“批量处理”，执行“重建全库向量”。
3. 知识库进入“批量治理”，以 admin 身份执行“全库重建向量”。
4. 等待两个后台队列清空；期间词法检索保持可用。
5. 使用已准备的法规、制度、问答样本对比开启和关闭 Reranker 的 Top-3 命中率、P95 延迟与错误率后，再正式启用。

## 安全边界

- 仅把已通过知识库 ACL 或法规可见性过滤的有限文本发送给 Reranker。
- Reranker 故障、超时或返回格式错误不会阻断检索，也不会降级权限边界。
- Embedding 模型、地址或维度改变后必须全量重建；不得混用历史向量。
