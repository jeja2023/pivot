# v0.1.41 版本发布记录

**发布日期**：2026-08-24  
**版本主题**：普通聊天双模式与 Agent 执行许可

---

## 一、产品行为

普通聊天现在明确区分两种模式：

- **普通回答**：默认模式，使用原有聊天模型流，不创建 `agent_runs`。
- **Agent 执行**：用户主动选择后，进入连续 Agent，支持多轮规划、工具调用、审批、检查点、后台执行、断线恢复和最终结果回写。

消息长度、关键词和“任务意图”不再决定是否自动创建 Agent。简单闲聊和复杂问题都遵循用户当前选择的模式。

## 二、实现内容

### 1. 聊天输入模式选择

- 输入区“添加”菜单新增回答模式单选项。
- 默认选择“普通回答”，选择会保存在当前浏览器，后续发送继续沿用。
- Agent 模式在管理员禁用时自动禁用并显示原因；普通回答仍可发送。
- 聊天请求新增 `chatMode: normal|agent` 字段。

### 2. 服务端强制执行许可

- 新增 `GET /api/chat/capabilities`，返回默认模式、可用模式和 Agent 执行许可状态。
- 服务端只在 `chatMode=agent` 时进入聊天 Agent handoff。
- Agent 执行许可关闭时返回 `AGENT_EXECUTION_DISABLED`，不能通过伪造前端请求绕过管理员设置。
- Agent 目标长度仍受 `MAX_CHAT_AGENT_GOAL_LENGTH` 保护；普通回答不受 Agent 目标校验影响。

### 3. 配置兼容与管理界面

```env
# 是否允许聊天选择 Agent 执行模式；普通回答始终可用
CHAT_AGENT_EXECUTION_ENABLED=1
```

历史配置 `CHAT_AUTO_AGENT_ENABLED` 和数据库键 `chat_auto_agent_enabled` 保留兼容读取，但语义已从“自动升级”变为“Agent 执行许可”。系统设置页面同步改为“允许聊天使用 Agent 执行模式”。

## 四、验证

- Agent SSE、聊天桥接、预算契约：通过。
- 聊天渲染、模式选择器和服务端模式路由静态契约：通过。
- ESLint、JavaScript 语法、文本完整性、架构边界、Raw SQL 基线：通过。
- PostgreSQL 集成测试需在配置 `TEST_DATABASE_URL` 或 `DATABASE_URL` 的环境补跑。

## 五、升级说明

本版本无需数据库迁移。升级后普通聊天默认使用普通回答；需要连续 Agent 时，在输入菜单选择“Agent 执行”。管理员可以在系统设置关闭该模式，关闭不影响普通回答、手工 Agent 或自动化工作流。
