# v0.1.184 PostgreSQL 长期记忆迁移兼容性修复

发布日期：2026-09-27

发布范围：PostgreSQL 版本化迁移 `202609260001_long_term_memory_productization` 的历史字段兼容性。

## 问题与影响

早期生产数据库中的 `memories.source_message_ids` 列可能保留为 `TEXT`，而当前 PostgreSQL Schema 快照使用 `JSONB`。长期记忆产品化迁移在回填 `memory_source_evidence` 时，将该列与 `'[]'::jsonb` 直接作为 `COALESCE` 参数使用。

PostgreSQL 不会在 `COALESCE(TEXT, JSONB)` 间隐式转换，因而迁移报出以下错误并使服务启动中止：

```text
COALESCE types text and jsonb cannot be matched
```

迁移运行器已使用事务包装单条迁移。因此失败时会回滚该迁移中的表、索引和回填操作，并且不会记录迁移 ID；升级代码后重新启动即可安全重试。

## 修复内容

- 来源消息列表统一先执行 `source_message_ids::text`，消除旧版 `TEXT` 和新版 `JSONB` 的 SQL 类型分歧。
- 新增仅在迁移会话内可见的临时解析函数：
  - 空值或空白值返回空 JSONB 数组；
  - 合法 JSON 数组原样用于来源证据回填；
  - JSON 对象、标量、非数组与非法历史文本返回空数组；
  - 单条历史脏数据不会阻断整库迁移。
- 回填完成后立即删除临时函数；`memories.source_message_ids` 的实际列类型和历史正文均不被改写。

## 升级步骤

1. 部署 `v0.1.184` 的服务端代码及 `package.json` / `package-lock.json`。
2. 重启 Pivot 服务。
3. 服务启动会重新执行尚未记录的 `202609260001_long_term_memory_productization` 迁移，然后继续后续长期记忆迁移。
4. 在启动日志确认出现 PostgreSQL 迁移完成记录，服务健康检查恢复正常。

不需要手工删除 `agent_schema_migrations` 中的记录：发生该错误时事务已回滚，因此该迁移不会被记录为已完成。若目标库已经成功记录了该迁移，则不需要重跑或手动修改字段。

## 验收证据

- 新增 `tests/long-term-memory-productization-migration.test.js`：验证 SQL 不再混用 `TEXT` / `JSONB` 的 `COALESCE`，并覆盖安全数组解析与临时函数清理。
- 真实 PostgreSQL 回归：在事务内将 `memories.source_message_ids` 临时改为 `TEXT`，插入历史 JSON 文本并执行迁移，确认 `memory_source_evidence` 正确回填，最后回滚测试事务。
- `node scripts/run_node_tests.js tests/long-term-memory-productization-migration.test.js` 通过。
- `npm run check:text`、全量 JavaScript 语法检查、`npm run check:standards:changed` 与 `git diff --check` 通过。

## 发布边界

- 本版本不新增数据库迁移 ID，也不需要手动变更生产表结构；它只修复既有未完成迁移的兼容执行路径。
- 无新增环境变量或配置项。
- 非数组或无法解析的历史来源消息列表不会被强制猜测或改写；它们不会生成来源证据，后续新的记忆写入仍按当前数据契约记录来源。
