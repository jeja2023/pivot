# v0.1.193 智能路由按需唤醒与决策治理加固

发布日期：2026-09-29

发布范围：聊天按需智能路由、`@` 显式选择优先级、MCP 授权续跑、统一业务决策运行时与模型制品治理、长期记忆来源撤销、PostgreSQL 兼容迁移、聊天交互细节。

---

## 1. 发布目标

本版本将聊天路由从“默认对每轮消息探测知识库和工具”调整为“仅在真正需要时唤醒”。目标是减少普通对话的额外延迟、无关检索和工具授权打断，同时保留对内部受控知识、实时业务数据、本机资源、指定网页和外部操作的准确识别。

同时，版本为学习型决策模型补齐训练范围、冻结评测与资源隔离门禁，并将消息删除、记忆来源撤销和待执行抽取任务统一为原子事务，确保交互体验、数据一致性和多租户治理同时成立。

---

## 2. 聊天路由与授权体验

### 2.1 知识库和工具改为按需唤醒

路由器先做轻量需求判定；未命中需求时不读取知识库目录或工具目录、不生成 Embedding、不调用知识库或工具决策器，也不展示工具授权提示。

| 请求类型 | 路由行为 |
| --- | --- |
| 普通问答、办公写作、报告提纲、静态图表、表格对比 | 直接回答 |
| SQL/API/MCP 概念解释、代码示例、教学演示 | 直接回答 |
| 公司制度、审批、报销等需要受控内部依据的问题 | 按需检索知识库 |
| 查询订单、库存、客户、销售等实时业务数据 | 发现受治理工具，未授权时请求授权 |
| 读取本机目录/文件、访问指定网址、导出文件、发送通知 | 发现受治理工具，按既有授权与审批策略执行 |

英文的内部知识库检索和业务数据查询也纳入相同的按需规则。

### 2.2 `@` 显式选择的优先级

`@知识库` 和 `@工具` 不是普通提示词，而是传入服务端的受控路由覆盖：

```text
@ 显式选择
  > 权限、工具白名单、首次授权、风险审批
  > 智能路由与学习型决策建议
  > 普通直接回答
```

- `@知识库` 固定检索用户选择的 Collection 范围；
- `@工具` 只允许在用户选择、且通过权限治理和白名单筛选的工具中规划；
- 主动决策策略不能将显式 `@工具` 选择改判为 `skip`；
- 显式选择不绕过首次 MCP 授权、会话确认或高风险审批；
- 删除输入框内的 `@` 引用后，对应覆盖自动失效，恢复按需智能判断。

### 2.3 MCP 续跑和聊天交互

- 工具首次授权仍复用同一原始用户消息，不重复保存用户输入；
- 续跑请求携带明确的 `mcp_authorized` 或 `mcp_skipped` 来源，审计日志不再误记为“重新生成回答”；
- 授权提示仅保留必要的“允许并继续/直接回答”操作，普通内容不显示冗余路由信息；
- 模型选择器旁的上下文窗口用量控件调整为紧凑的圆形指示器。

## 3. 决策模型与发布治理

### 3.1 决策制品训练范围

新增模型制品迁移 `202609290002_decision_artifact_governance`，为 `decision_model_artifacts` 增加：

- `training_tenant_id`：制品仅可用于对应租户；
- `global_training_approved`：仅经明确批准的全局训练制品可跨租户使用；
- 按提供器和训练范围维持独立的 active 制品唯一性与索引。

运行时优先使用当前租户制品，再使用已批准的全局制品；制品激活、退役、缓存和 Active 灰度就绪检查均按此范围工作。

### 3.2 冻结评测和发布门禁

- 训练候选注册要求绑定单租户或明确的全局训练批准；
- `--register` 训练流程必须提供已审核冻结评测报告；报告记录评测集版本、源摘要、案例数、提供器版本和指标；
- 激活、发布预检和部署就绪度同时校验模型版本、权重、训练范围和冻结评测证据；
- 基准报告优先写入实际已审核的评测集版本，避免环境变量与评测输入不一致。

### 3.3 运行时可靠性与资源保护

- 学习型提供器可在可用时独立参与策略融合；既有启发式路由仅在没有学习型输出时作为安全回退；
- Qwen 决策必须配置审核版本，新增独立硬超时和单进程并发上限；超时、排队取消或并发受限时保持既有路由；
- 全局模型信号量和端点信号量支持 AbortSignal，避免已取消的短时决策继续占用生成容量；
- Active 模式读取策略制品与模型制品时绕过进程内过期缓存，保证跨实例回滚可在下一轮决策生效；
- Laya、本地轻量模型和 Qwen 均在 Active 模式按当前租户范围校验已激活制品。

## 4. 消息删除、长期记忆与 PostgreSQL 兼容性

### 4.1 删除流程原子性

删除单条消息或整个会话时，服务端在同一数据库事务中完成：

1. 锁定仍可删除的消息或会话；
2. 撤销其关联的长期记忆来源证据；
3. 取消仍在排队的记忆抽取任务；
4. 软删除消息、附件或会话。

任何步骤失败都会整体回滚，避免出现“消息已删但记忆仍注入”或“接口报错但数据部分提交”的状态。

### 4.2 历史来源字段迁移

新增迁移 `202609290003_memory_source_ids_jsonb_compatibility`，将历史数据库中 `memories.source_message_ids` 与 `memory_suppressions.source_message_ids` 的 TEXT 列安全转换为 JSONB：

- 可解析的 JSON 数组保持原值；
- 空值、空字符串和非法/非数组 JSON 降级为 `[]`；
- 统一 JSONB 默认值，恢复需要的非空约束；
- 来源撤销写入使用参数化 JSON 文本，兼容迁移尚未执行的 TEXT 列和迁移完成后的 JSONB 列。

## 5. 配置与升级

新增决策运行时配置：

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PIVOT_QWEN_DECISION_TIMEOUT_MS` | `1200` | Qwen 结构化决策硬超时，超时后保留既有路由。 |
| `PIVOT_QWEN_DECISION_MAX_CONCURRENT` | `1` | 单进程 Qwen 决策最大并发，优先保障最终回答容量。 |

现有 `PIVOT_CHAT_AUTO_RAG_ENABLED` 与 `PIVOT_CHAT_AUTO_TOOL_DISCOVERY_ENABLED` 的含义更新为“按需自动路由”：开启并不代表每轮检索或发现工具。

升级时正常执行数据库迁移即可。生产环境若启用 Active 决策灰度，需要为每个灰度租户准备相匹配的 active 模型制品和已审核冻结评测证据；否则部署就绪检查会明确阻止发布。

## 6. 验证覆盖

本版本新增或更新自动化覆盖，包含：

- 普通回答不读取知识库/工具目录、不产生路由向量或工具授权；
- 中英文的内部资料检索与实时数据工具路由；
- 报告、图表、SQL/API/MCP 教学等反例的直接回答；
- 真实外部操作与工具首次授权路径；
- `@工具` 显式选择不能被主动策略改判为跳过；
- Qwen 决策硬超时与并发受限降级；
- 制品训练范围、冻结评测证据、租户 Active 读取和发布就绪检查；
- 消息删除、来源撤销、任务取消的事务边界；
- PostgreSQL 历史 TEXT 来源数组向 JSONB 的迁移与删除路径兼容性。
