# v0.3.11 - 知识库检索相关性与中文化修复

> **发布日期**：2026-10-16  
> **升级类型**：知识库检索精度、用户隔离可见性、中文界面与历史库启动兼容性修复  
> **兼容性**：向后兼容；不改变用户自有知识库、文档和已授权资料的访问边界

## 版本概述

本版本修复了知识使用与治理页面中“最终回答已拒答、但仍展示无关召回候选”的问题，并完成召回诊断、搜索问答、质量评测的用户可见界面中文化。

## 一、检索相关性与安全交付

- 对“抢劫罪判几年”“涉嫌故意伤害罪”等带明确罪名的问法，自动提取罪名及核心词作为相关性锚点，并把锚点加入受控多查询检索。
- 候选必须命中至少一个明确锚点，不能只因“犯罪、可以、判处”等泛词通过后续可信度门控。
- 搜索问答页仅显示已通过相关性和可信度校验、可作为回答依据的片段；未通过的初筛候选不会再被误呈现为检索结果。
- 未命中可靠证据时，会明确说明已拒绝泛化候选；最终回答继续遵循来源和语义核验的安全拒答规则。

## 二、界面全面中文化

- 召回测试诊断中的检索模式、排名来源、队列状态、入选状态和时间单位统一中文化，不再展示 `rank`、`fts`、`MMR selected`、`pending`、`hybrid_dual_rrf_mmr` 等内部英文。
- 搜索问答页将 `confidence_rejected` 等内部状态映射为中文业务说明。
- 质量评测页将运行状态、前 3 条召回率、平均倒数排名、前 5 条排序质量、引用综合得分、依据核验通过率等全部改为中文表达；详情、比较弹窗和输入提示同步处理。

## 三、权限可见性与启动稳定性

- 系统 `admin` 查看全库知识库文档时，列表显示上传用户昵称及账号提示；普通用户和非 `admin` 管理员既不能跨用户读取文档，也不会接收上传者资料。
- 历史 PostgreSQL 库不再因快照版本变更而被强制补建全部外键；遇到历史字段类型不兼容的外键时记录告警并延后处理，不阻断服务启动或删除既有数据。

## 四、验证

- 新增明确罪名锚点、无关条文拒绝、中文界面、上传用户可见性和历史外键恢复回归测试。
- 知识库专项自动化测试、ESLint、开发规范和差异检查已通过。
- 目标生产环境仍需在部署后以真实知识库数据复测典型业务问题，确认文档已索引、已启用，并执行知识库上线验收命令。
