# v0.1.195 原生知识库 LLM Wiki 融合上线

发布日期：2026-09-30

发布范围：知识库 LLM Wiki Space、原始来源映射、本地模型编译、审核发布、资料变更失效、融合检索、聊天显式范围、工作台、配置与回归。

---

## 1. 发布目标

Pivot 在既有专题库、文档版本、RAG、引用和知识图谱之上新增 LLM Wiki 派生综合层。Wiki 用于跨文档概览、主题导航和关系总结；原始资料仍是回答、合规和审计的唯一权威依据。

本版本不引入 Microsoft LLM Wiki 的 VS Code/Copilot 运行时，也不使用第三方 SaaS。编译由 Pivot 已配置且有权使用的本地模型执行，所有输入、来源、模型预算、审核和访问权限均经过现有治理链路。

---

## 2. 数据与来源治理

新增迁移 `202609300001_knowledge_llm_wiki_foundation`，创建：

- `knowledge_wiki_spaces`：绑定既有专题库的受控 Wiki Space；
- `knowledge_wiki_pages`：版本化的 overview/topic/entity/concept/conflict/change_digest 页面；
- `knowledge_wiki_page_sources`：页面事实段落到原始文档、版本、区块和 chunk 的来源映射；
- `knowledge_wiki_page_links`：同一 Space 内的已解析页面链接；
- `knowledge_wiki_compile_runs`：可恢复、可审计的编译运行记录。

兼容迁移 `202609300002_knowledge_llm_wiki_external_compat` 增加 `knowledge_wiki_external_pages`、`knowledge_wiki_external_page_links` 和 Wiki 专用全文索引，保证先前已应用基础迁移的部署也可安全升级。

Wiki 页不能扩大其专题库权限。每次读取页面、检索来源和构造模型上下文都复用当前用户身份；来源版本改变、归档或删除后，关联已发布页会立即变为 `stale`，不再作为正常检索结果。

本版已修复 Wiki Space 列表聚合查询的 PostgreSQL 分组条件：返回专题库当前共享范围时按 `ws.id` 与 `kc.id` 分组，避免 `/api/knowledge/wiki/spaces` 返回 500。

聊天回复中的“修正本轮路由”现改用对话内选择面板。用户选择具体路由场景及其当时允许的替代动作即可提交，不再依赖可能被桌面窗口遮挡的原生输入框或手工输入动作 ID；反馈仍须经过既有核验流程才可进入训练数据，且不会重跑已完成的本轮对话。

Wiki 工作台的“新建 Wiki Space”和“导入 Markdown Wiki”同样不再使用原生输入框：用户可在当前弹窗内选择有管理权的专题库并填写必要信息。没有 Space 时编译按钮会明确显示“先新建 Wiki Space”并禁用；创建后编译会读取当前聊天模型选择器 `model-selector`，不再读取不存在的 `model-select`。

## 3. 编译、审核和重建

- 模型仅能输出受限 JSON 候选，不能直接写数据库或原始文件；
- 每个事实性段落必须引用本轮受控 input manifest 中的 `documentId/versionId/blockId/chunkId`；
- 伪造、越权、缺失或无效来源会使候选失效；
- 默认候选状态为 `review`，管理员/资料所有者发布前会再次校验支持性来源和冲突数量；
- 原始资料重建、手工版本发布、归档和删除会将关联 Wiki 页标记为 `stale`；
- 仅当 Space 显式指定模型且开启自动编译时，资料变更会创建去重的增量编译任务，避免隐式消耗聊天默认模型；
- 后台 Worker 以数据库租约领取 queued/失联任务，服务重启后可恢复；资料管理员可取消 queued/running 任务；
- 编译失败保留现有原始 RAG 和旧已发布页面，不会用失败输出覆盖内容。

## 4. 检索、问答和交互

知识问答的检索顺序为：原始资料 RAG → 已发布且来源仍有效的 Wiki 综合页 → 来源/权限再次校验 → 模型回答。

- 原始 Chunk 始终优先进入上下文；
- 当原始资料未命中时，不会仅凭 Wiki 页生成事实性回答；
- 问答接口返回 `wikiPages` 和 `wikiCitations`，页面与原始依据可区分呈现；
- 聊天 `@` 菜单新增“Wiki 综合”，选择后会同时固定其底层专题库范围；Wiki 仅在该原始资料检索成功后追加到上下文；
- 知识库工作台新增“Wiki 综合”入口，可创建 Space、浏览页面和来源、启动手动编译并发布审核通过的页面。
- 外部 Markdown Wiki 可从安全白名单目录只读导入，解析 YAML front matter、WikiLink 和相对链接；导入数据进入隔离专题库，系统绝不向源目录回写。

## 5. 知识库表格规范化与界面交互优化

- **全局统一数据表格与分列展示**：
  - 知识库“知识使用与治理”弹窗中，“知识内容”与“索引任务”卡片瀑布流全面重构为全局统一数据表格（`.table-container` 与 `.data-table`）；
  - 统一增加居中对齐的“序号”列（`1, 2, 3...`）；
  - 彻底消除换行折叠，实现规范分列呈现：
    - **知识内容**：序号、文档名称、生命周期状态、验证状态、复核时间、操作按钮；
    - **索引任务**：序号、文档编号、任务状态、索引阶段、尝试次数、错误信息、更新时间；
  - 表格行高严格对齐全局 `36px` 规范，内部操作按钮高度收敛为 `22px`，状态标签高度收敛为 `20px`，杜绝内容撑高行距；表头吸顶固定，完整支持暗黑模式。
- **弹窗外层滚动条消除与高度弹性流式布局**：
  - 修复 `.knowledge-product-panel` 盒模型（显式声明 `box-sizing: border-box`）并重构为纵向弹性流式布局（`display: flex; flex-direction: column; height: 100%;`）；
  - 工具栏固定高度，表格容器设为 `flex: 1 1 auto; height: 100%; min-height: 0; overflow: auto;`，自动撑满可用空间；
  - 激活“知识内容”与“索引任务”选项卡时锁定外层主视口垂直滚动（`overflow: hidden`），彻底杜绝弹窗最右侧多余的外层滚动条，保留表格内部单一原生滚动条。
- **知识库文档表格无标签显示优化**：
  - 知识库主界面文档管理数据表中，未配置任何标签的文档在“标签”列直接显示为空白，消除短横线 `-`，保持表格视觉整洁。

## 6. 配置

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `PIVOT_KNOWLEDGE_WIKI_ENABLED` | `true` | 启用 Wiki Space、编译与只读检索。 |
| `PIVOT_KNOWLEDGE_WIKI_MAX_SOURCE_BLOCKS` | `12` | 单次编译最大原始来源区块。 |
| `PIVOT_KNOWLEDGE_WIKI_MAX_PAGES_PER_RUN` | `3` | 单次编译候选页面上限。 |
| `PIVOT_KNOWLEDGE_WIKI_MAX_OUTPUT_TOKENS` | `2200` | 编译输出 Token 上限。 |
| `PIVOT_KNOWLEDGE_WIKI_TIMEOUT_MS` | `120000` | 单次编译模型超时。 |
| `PIVOT_KNOWLEDGE_WIKI_AUTO_COMPILE` | `false` | 是否允许资料变更触发自动编译。 |
| `PIVOT_KNOWLEDGE_WIKI_REQUIRE_REVIEW` | `true` | 候选页是否必须审核后发布。 |
| `PIVOT_KNOWLEDGE_WIKI_SEARCH_LIMIT` | `5` | 单次只读 Wiki 检索最大页面数。 |
| `PIVOT_KNOWLEDGE_WIKI_WORKER_ENABLED` | `true` | 启动可恢复编译 Worker。 |
| `PIVOT_KNOWLEDGE_WIKI_WORKER_POLL_INTERVAL_MS` | `2000` | Worker 领取任务与恢复租约的轮询间隔（毫秒）。 |

生产建议维持“自动编译关闭、审核开启”，先选择一个低风险单专题库试点。多专题库 Space、真实业务指标、外部只读 Markdown/MCP bridge 仍须按 [融合实施方案](../design/Pivot知识库LLMWiki融合实施方案.md) 的验收门槛推进。
