# 智枢 Pivot v0.1.114 发布记录

## 概述

**发布版本**：v0.1.114  
**发布日期**：2026-09-09  
**关注领域**：桌面客户端启动可靠性、窗口可见性保障、连接超时与单例进程守护

---

## 核心修复与优化

### 1. 桌面主窗口不可见与首屏假死根除

- **问题根因**：Electron 桌面客户端创建时采用 `show: false` 防白屏闪烁策略，仅在 `ready-to-show` 事件触发后显式调用 `mainWindow.show()`。当安装包连接的目标服务器因网络波动、防火墙阻断或服务离线时，Chromium 陷入长达数十秒的 TCP 握手与网络探测，期间 `ready-to-show` 永不触发；且网络失败后调用的 `loadErrorPage` 内部未显式调用 `show()`，导致整个客户端完全以无头隐藏进程驻留后台，界面没有任何反应。
- **强制唤醒兜底**：在 `createMainWindow` 中引入 2500ms 安全显示计时器，只要窗口未销毁且仍未处于可见状态，立即强制唤起窗口；正常渲染完成时则无缝清除计时器。
- **错误页可见性保证**：在 `loadErrorPage` 的 `finally` 阶段统一显式执行 `mainWindow.show()`，确保即使在网络中断或致命加载错误时，用户也能在 2 秒内立即看到清晰的错误界面与操作指引。

### 2. 网络加载超时竞态与快速降级

- **8 秒超时守护**：在 `loadTarget()` 异步加载中引入 `Promise.race` 与 8000ms 超时计时器，取代 Chromium 原生默认无超时阻塞机制。
- **主动截断与转入配置**：发生超时后主动停止当前渲染管道（`webContents.stop()`），立即转入本地错误页 `error.html`，展示「重新连接」与「配置服务器」按钮，用户可一键调起配置窗口修改目标服务地址或切换至本地回环模式。

### 3. 多开与单例锁唤醒体验优化

- **多开可见性激活**：在 Windows 环境中，当用户重复双击桌面图标触发 `app.on('second-instance')` 时，除了原有的 `restore()` 与 `focus()` 外，增加 `if (!mainWindow.isVisible()) mainWindow.show();`，确保即使首个实例由于网络挂起尚未显示，再次双击也会立刻强制显现窗口。
- **僵尸进程防御**：消除以往由于后台静默残留进程霸占 `SingletonLock` 导致后续启动直接无任何提示退出的死锁链条。

### 4. IPC 注册生命周期与时序加固

- **注册顺序前置**：将 `setupAutoUpdater`（包括其注册的 `pivot-updater:status` 等 IPC 通信通道）移至 `await loadTarget()` 之前完成初始化。
- **消除未注册异常**：彻底消除页面加载和 `preload.js` 初始化阶段由 `getUpdateStatus()` 触发的 `Error: No handler registered for 'pivot-updater:status'` 控制台报错。

### 5. 模态子窗口挂载防御

- **父窗口状态校验**：调起服务器配置窗口（`showServerConfigDialog`）时，仅当 `mainWindow` 处于可见且未销毁状态时才赋予 `parent` 与 `modal: true`，杜绝因隐藏父窗口关联导致的 Windows 桌面窗口渲染异常。
