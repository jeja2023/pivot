# v0.7.76 跨节点实时恢复阶段记录

日期：2026-10-31。此版本记录已实现的开发成果；多节点实时广播和故障恢复尚未完成验收，不能作为生产多节点就绪的声明。

## 已实现

- **持久 Agent 事件**：事件提交后由 PostgreSQL 通知相关用户所在节点立即补查；通知只包含 schema 和用户标识，数据库持久事件及用户游标仍是数据来源。监听中断时自动重建，通知丢失时按周期补查并提示客户端刷新。
- **状态提示**：任务、通知、演示文稿和流式进度的跨节点提示使用由 `DATA_ENCRYPTION_KEY` 派生的密钥签名，不在通知中传递正文或工具参数。提示不是持久消息，丢失后依靠现有状态读取和补查；所有节点需使用相同密钥。
- **流式快照**：最近一次快照加密存储，读取和写入按用户、运行、有效执行租约及租约代次校验。任务被重新认领时数据库提升代次，以阻止旧执行者覆盖新快照。任务详情可通过授权接口恢复快照。
- **Web 渠道重放底座**：Web 消息入队与独立游标登记由同一数据库事务完成；重放端点按用户分页读取，支持断线续传、背压和按保留期分批清理。新客户端不会自动连接该端点，因为混版握手仍未完成验收；既有本地渠道投递路径保留。

## 验证范围

- 隔离 PostgreSQL 定向 Node 回归共 55 项：54 项通过、1 项压力探针因未启用开关跳过，零失败。压力探针此前在隔离库单独启用通过；该小规模结果不代表生产容量。
- 多节点模式浏览器专项验证快照恢复和直接访问 Web 渠道重放端点通过。此验证不代表普通客户端已启用渠道重放。
- 本轮完整静态检查、针对改动文件的 Lint 和类型检查通过。遵照要求，未运行全量测试回归；目标内网和生产负载尚未验收。

## 限制与部署

- **严格多节点预检继续阻断**。普通客户端渠道握手、新旧节点的游标交接、所有事件类型的故障与滚动升级验收仍未完成；不能依据此版本增加生产副本。
- 流式快照合并写入，进程在写入前退出、数据库不可用或快照超过 32 MiB 时，最新流式片段可能无法恢复。仅有效租约且最近五分钟内的快照可读取；最终任务结果仍使用原有持久化流程。
- Web 渠道已送达重放记录保留七天，超过保留期的离线客户端不能依赖该端点补发全部历史。端点当前可用于受控测试，普通客户端未启用独立连接。
- 部署前备份数据库和受管数据目录，在所有应用节点启动前完成数据库迁移；所有节点需使用相同加密密钥。迁移创建事件通知触发器、渠道重放表及流式快照表和租约代次。混合版本节点仍不能保证所有实时事件一致，回滚前应验证旧版本兼容及既有数据恢复流程。
