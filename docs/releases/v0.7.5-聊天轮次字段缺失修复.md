# v0.7.5 聊天轮次字段缺失修复

普通聊天报“字段 m.conversation_turn_id 不存在”，是数据库实际结构与迁移记录不一致导致。现场只读检查确认：`schema_migrations` 已存在 `202610190002_chat_conversation_turns`，但 `messages` 中没有 `conversation_turn_id`。只重启服务会继续跳过旧迁移。

新增 `202610190004_chat_message_turn_link_repair`，以独立版本补齐字段、外键及用于回复幂等的唯一索引。该修复带真实结构检查，已登记后仍会检查；字段、外键或索引缺失时重新执行受控幂等修复。检查未通过会回滚并阻止服务带病启动。

提供独立命令：

```bash
node scripts/repair_chat_schema.js
```

工具只处理聊天轮次关联结构，事务内校验并记录修复版本；不删除聊天消息，不要求清库或删除原迁移记录。Docker 镜像包含此脚本，可在新版运行容器中执行：

```bash
docker compose exec -T pivot node scripts/repair_chat_schema.js
```

当前配置的数据库已实际执行修复，字段、外键与唯一索引校验通过。其他部署需更新服务镜像以获得该独立迁移，服务启动时自动修复；不要在不明数据库上手动删除迁移记录。详细证据见 [验收报告](../reports/聊天轮次字段修复验收报告_2026-10-19.md)。

工程检查与 ESLint 通过；全量回归 1987 项、受影响回归 22 项、浏览器关键流程 1 项通过。当前库原读取与回复去重写入已通过只生成查询计划的验证。
