# v0.1.190 长期记忆无失败任务重试反馈优化

发布日期：2026-09-27

发布范围：设置工作区“长期记忆 → 抽取任务 → 重试失败”按钮。

## 问题

当长期记忆没有失败的抽取任务时，页面会禁用“重试失败”按钮。虽然接口已经能够安全返回 `queued: 0`，用户却无法触发该操作，也不会得到“当前没有任务可重试”的明确反馈。

## 修复内容

- 无失败任务时，“重试失败”按钮保持可点击。
- 点击后继续调用已有的幂等重试接口：
  - 有失败任务：显示实际重新入队数量；
  - 没有失败任务：显示“没有可重试的失败任务”。
- 操作完成后继续刷新长期记忆任务摘要，确保排队、执行与失败数量同步更新。

## 验收证据

- 更新 `tests/settings-page-contract.test.js`，验证重试按钮不再依据失败数生成禁用属性。
- 新增 Playwright 用例：在没有失败任务的账户中验证按钮可点击、请求 `/api/memories/jobs/retry` 成功、信息提示可见且任务摘要保持 `0 失败`。
- 定向 ESLint、`npm run check:text`、`npm run check:standards:changed` 与 `git diff --check` 通过。

## 升级说明

无数据库迁移、无新增环境变量。部署新版服务端和静态资源后，刷新浏览器或重新打开客户端即可生效。
