# v0.1.38 版本发布记录

**发布日期**：2026-08-24
**版本主题**：模型上下文友好报错、多架构容器运行时与 Agent 体验升级

---

## 一、 更新背景

在实际生产和大模型日常使用中，用户与管理员遇到了以下实际痛点：
1. **模型错误信息生硬难懂**：当用户输入的上下文（或长历史会话）超过模型支持的 Context Window（如 131,072 Tokens）时，上游服务返回原始英文 JSON 报错（如 `exceed_context_size_error: request (132085 tokens) exceeds the available context size...`），普通用户无法理解其含义与解决办法。
2. **多架构 Docker 构建环境兼容性**：在不同 CPU 架构（如 `linux/amd64` 与 `linux/arm64`）上构建 Docker 镜像时，需要动态精准安装对应的 DuckDB 原生二进制依赖，避免手动指定架构包导致跨平台报错。
3. **生产镜像加载自检**：在最终 runtime 镜像阶段建立原生依赖加载契约，确保交付到离线环境的镜像 100% 可用。

## 二、 核心升级内容

### 1. 模型上下文超限智能解析与友好中文化

- **精准特征匹配**：自动识别 vLLM、llama.cpp、Ollama、OpenAI 等主流推理框架返回的 `exceed_context_size_error`、`context_length_exceeded`、`maximum context length` 等错误。
- **动态数字提取与千分位格式化**：
  从报错对象或正则中提取当前请求的 Token 总量（如 `132,085 Tokens`）和模型允许的上下文上限（如 `131,072 Tokens`）。
- **生成结构化可操作建议**：
  ```text
  生成失败：对话上下文超出模型限制
  错误代码：CONTEXT_LENGTH_EXCEEDED
  HTTP 状态：400

  错误详情：
  当前请求的总 Token 数（约 132,085）超出了模型支持的最大上下文窗口（131,072）。

  💡 建议解决方案：
  1. 点击左侧开启新会话，避免长历史对话累积；
  2. 缩短当前提问或减少单次上传的参考文档内容；
  3. 如果是私有部署模型，可在【模型管理】或模型服务参数中调大 Context Size（上下文窗口大小）。
  ```
- **全套常见错误中文化**：
  - `401 / invalid_api_key`：转化为「API Key 无效或未授权」及检查指引；
  - `402 / 429 / insufficient_quota`：转化为「模型服务余额不足或额度耗尽」及充值指引；
  - `429 / rate_limit_exceeded`：转化为「模型服务请求过于频繁（触发限流）」；
  - `404 / model_not_found`：转化为「模型不存在或名称配置有误」；
  - `502 / ECONNREFUSED`：转化为「无法连接到模型服务」及服务排查建议。

### 2. Docker 多架构支持与运行时自检

- **ARG TARGETARCH 动态架构选择**：
  Dockerfile 引入 `ARG TARGETARCH`，在依赖安装阶段根据目标架构自动选择安装 `@duckdb/node-bindings-linux-x64` 或 `@duckdb/node-bindings-linux-arm64`。
- **运行时自检（Runtime Verification）**：
  在最终生产镜像层增加测试指令：
  ```bash
  node -e "require('@duckdb/node-api'); require('sharp'); require('unzipper'); require('better-sqlite3'); console.log('[runtime] 原生模块加载通过')"
  python3 --version
  pg_dump --version
  ```
  在镜像生成阶段即验证所有原生模块和工具已正确加载，防止运行期出现缺失。
- **保持极致精简与非 root 安全**：
  延续多阶段构建（Multi-stage Build），开发编译器与头文件在第一阶段自动丢弃，运行镜像体积维持在 ~532MB，容器默认以普通用户 `node` (UID 1000) 安全运行。

## 四、 升级指南

```bash
# 1. 在生产服务器加载新镜像
docker load -i pivot.tar

# 2. 授权持久化目录（若之前已执行过则无需重复）

# 3. 重新启动服务
```
