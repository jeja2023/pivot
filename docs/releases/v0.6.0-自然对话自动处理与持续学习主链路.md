# v0.6.0 自然对话自动处理与持续学习主链路

发布日期：2026-10-19

## 用户体验

聊天只有一个自然语言入口。系统按当前请求、会话上下文、有效用户偏好、可用能力和运行许可自行选择处理方式：

```text
解释向量检索
  → 直接回答

公司差旅报销标准是什么
  → 自动检索已授权资料并回答

请汇总本周订单、核对异常并生成风险报告
  → 自动创建受控任务并持续处理

先给出修复方案，不要修改代码
  → 只分析和交付计划
```

用户不需要选择“普通模式 / Agent 模式”、输入命令或重复点击“开始处理”。明确委托被识别后，聊天会显示正在建立受控执行、规划、工具处理和完成等状态；用户仍可停止、补充要求、查看详情，或在真实阻断处提供缺失事实和授权。

## 自动处理边界

- 自动路由只决定是否需要持久 Agent Run，不直接赋予任何能力。
- 已授权资料会按需检索；明确点名 CRM、数据库、文件、网页或 API 时，Agent 才能尝试使用用户已有权限内的受控能力。
- 每个具体工具调用继续经过已有的能力过滤、参数校验、审批策略、Execution Grant、事务、检查点和恢复逻辑。
- 发送、写入、删除、发布、付费、登录验证或策略要求人工确认的动作，仍在执行边界暂停；自动路由不会把用户习惯当作永久扩大权限的依据。
- “停止当前任务”等自然语言指令会尝试停止当前会话的活动聊天任务；没有活动任务时正常回答。

## 持续学习

自动任务复用既有长期记忆、个人档案、工具可靠性信号、结果反馈和学习作业：

- 用户表达的交付偏好和纠正由记忆治理处理，可按现有策略查看、修改、遗忘或要求确认；
- 自动任务的成功、恢复和用户纠正会进入学习候选；
- 可复用经验必须经过工具范围、结构、评测和发布治理，才会成为可自动复用的个人 Skill；
- 用户当前要求优先于历史偏好，删除来源或撤销权限后，后续使用仍须重新校验。

这不是对每条消息进行模型权重训练。它是可追溯的偏好、记忆、经验和评测闭环。

## 管理控制

在“系统设置 → 全局参数 → 智能体后台”中：

- **允许聊天启动受控任务**：聊天创建任何 Agent Run 的总许可；
- **自动处理明确委托**：只控制自然语言自动路由。关闭后，普通对话不自动创建任务，既有计划草案、手工 Agent、工作流和普通回答不受影响。

环境变量 `PIVOT_CHAT_AUTO_EXECUTION_ENABLED` 提供首次初始化默认值；保存系统设置后以系统设置为准。

## 工程实现

- 新增 `chat-auto-execution` 服务，输出结构化的直接回答、只规划、任务运行或任务控制决策；
- 决策带有意图、下一步、能力类别、缺失事实与消息相对证据引用；这些字段只用于受控路由与审计，不能表示工具名称、授权或模型私有推理；
- 新增统一 `chat-agent-handoff`，让显式与自动任务复用同一 Chat Bridge、预算、上下文、结果回写和恢复链路；
- 自动运行元数据记录路由来源、置信、原因、是否续接和能力提示，便于审计与后续评测；
- 任务分类只在服务端运行；普通问答不额外调用分类模型，候选任务才读取相关档案，避免无意义前置开销。

## 验证

- 自动路由单元回归：明确委托、探索请求、只规划、续接、停止和能力提示。
- 聊天路由回归：正常聊天仍使用 `chatMode=normal`，但明确委托由服务端返回自动 `agent_handoff`。
- `npm run check`：覆盖配置注册、架构、迁移、SQL 审核、前端资源与安全门禁。
