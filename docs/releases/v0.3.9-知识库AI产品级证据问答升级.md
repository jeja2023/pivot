# v0.3.9 - 知识库 AI 产品级证据问答升级

> **发布日期**：2026-10-16  
> **升级类型**：知识库 AI 检索质量、引用可信度、多轮问答与安全审计升级  
> **兼容性**：向后兼容；保留既有知识库、Graph-RAG、Wiki 和 Agent 链路

## 版本概述

本版本针对知识库 AI 中“资料能够召回，但模型回答未必严格受资料约束”的问题，补齐了从问题规划、混合召回、证据注入到最终回答核验的产品级闭环。

## 一、问题规划与多路检索

- 新增知识库问题规划器：短追问会结合上一轮用户问题恢复完整主题。
- 复合问题按分号、并列关系和子问题边界拆分为有限检索变体，最多并行执行 3 路检索。
- 多路结果统一合并、去重并重新编号，避免不同查询都出现“引用 1”造成引用歧义。
- 复杂问题自动扩大 Top-K，简单问题保持默认召回规模，兼顾召回率、延迟和上下文噪声。

## 二、证据核验与安全交付

- 新增知识库回答依据核验器，检查来源编号、citation key 是否属于本轮真实召回结果。
- 对带引用的回答句增加来源片段支持性核验；引用编号真实但结论与来源内容无关时同样拒绝交付。
- 显式或命中知识库的回答改为服务端核验后交付；没有有效引用或引用不存在时，返回“依据不足”安全答复。
- 新增 `rag_grounding` 流式事件，前端显示“依据已核验/依据待补充”状态。
- 助手消息保存事件和路由元数据记录依据核验状态、引用来源及无效引用信息。
- 知识库正文被明确视为不可信数据，资料中的提示词、命令和权限要求不会被当作系统指令执行。

## 三、检索质量与上下文治理

- 保留并强化词法、向量、图谱候选的 RRF、MMR、确定性重排和可信度门控。
- 动态 Top-K 将复杂问题送入更充分的候选片段，同时继续使用引用可信度阈值拒绝低质量结果。
- 保持 Embedding 异常时的关键词降级、权限过滤、缓存隔离和上下文预算裁剪。
- Wiki 仍作为原始 RAG 的辅助层，原始知识片段优先，避免综合页覆盖原始证据。

## 四、前端和可观测性

- 对话页增加知识库依据核验状态展示。
- 保留原有资料来源摘要、引用键、范围状态和上下文预算事件。
- 新增问题规划、多查询合并、动态 Top-K、引用核验和提示词注入防护回归测试。

## 五、知识资产与全局治理权限

- 知识库文档、集合、标签、来源和索引任务默认由上传/创建用户独立管理。
- 共享专题库管理、全库重建向量和全局删除审计只授予系统 `admin` 账户。
- 非 `admin` 的普通管理员不具备上述跨用户治理能力；服务端、前端入口和回归测试均使用同一权限边界。

## 六、验证与部署说明

- 新增知识库 AI 纯逻辑测试 5 项通过。
- 相关 ESLint、语法检查、安全 HTML 扫描和差异检查通过。
- 真实 PostgreSQL、Embedding、Reranker 和大模型服务的多用户权限、缓存隔离、延迟、Recall@K、引用精确率和拒答准确率，需要在部署环境执行。
- 当前开发环境未配置 `DATABASE_URL`，数据库集成测试无法取得真实运行态证据；这不影响纯逻辑实现和静态门禁结果。
