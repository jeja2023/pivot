# v0.7.74 MCP 流式稳定性与治理优化

日期：2026-10-30。此版本记录本轮 MCP 连接保护和小范围代码治理。

## 更新内容

- 标准 MCP 的流式响应在连续 120 秒未收到任何字节时返回 `MCP_STREAM_IDLE_TIMEOUT`，关闭响应流及底层 HTTP 请求；心跳、进度通知和其他数据都会刷新空闲计时。通知响应的排空也受同样保护。
- 系统设置的模型管理支持“开启/关闭”模型配置；停用模型无需删除即可停止提供服务，配置与凭据保留，自动清理关联的默认模型引用，并从对话模型与 Agent 列表中过滤。
- 该期限独立于既有连接超时，不是整个任务的总时限；结果返回后启用 `keepAlive` 的连接不再受本次请求的空闲计时约束。正常结束后的重连、用户取消及响应大小限制继续生效。
- 模型流沿用已有首响应及空闲期限。定向测试增加了服务端观察连接关闭的验证，未改变模型超时默认值。
- 将设置页一个 `window.Pivot.legacy` 接口迁入 `Pivot` 模块接口，收回聊天模板模块的两个仅供内部使用的路径导出。其他候选导出与旧别名仍需逐项核查。

## 配置与兼容性

通过 MCP 服务创建或更新 API 可设置 `stream_idle_timeout_ms`（也接受 `streamIdleTimeoutMs`），单位为毫秒；未设置时为 `120000`。正值限制在 `1000` 至 `3600000` 毫秒，`0` 关闭流空闲保护；非法或负值回退到默认值。该选项与现有连接超时分别配置，普通页面暂未提供专门的输入项。

如果外部 MCP 在正常执行期间可能连续静默超过 120 秒，应先与服务方确认心跳或进度行为，再按服务需要延长期限；关闭保护会使故障连接可能长期占用资源。超时不表示远端业务操作一定未执行，对于可能产生副作用的工具，不应仅凭超时自动重试。

当前 HTTP 局域网部署方式、Cookie 和 CORS 配置不因本次修改改变。HTTP 本身不提供传输加密；现有网络隔离和访问控制仍需落实。
