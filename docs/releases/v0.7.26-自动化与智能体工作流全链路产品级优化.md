# v0.7.26 自动化与智能体工作流全链路产品级优化

日期：2026-10-21。

### 1. 支柱一：一次性任务资产沉淀与草稿自然语言修正

- **终态运行快速沉淀为计划任务（Run -> Schedule）**：
  - 针对在对话窗口或任务列表完成的智能体运行（包含标准任务与 DAG 工作流任务），在运行详情控制条（`agent-run-detail.js`）与对话终端任务卡片（`chat-task-render.js`）中新增「转为计划」按钮。
  - 用户点击后自动提取运行目标（Goal）、运行模式（`run_mode`）、工具调用配置与完整 DAG Spec 结构，唤起预填充的新建计划任务弹窗，一键打通从“单次验证”到“周期性定时自动化（Crontab/间隔）”的闭环。
- **终态运行快速另存为通用模板（Run -> Template）**：
  - 在运行详情与终端卡片中新增「另存模板」快捷入口。
  - 自动提炼已成功的提示词、参数契约与工作流拓扑结构，保存至常用任务模板库，便于团队复用最佳实践。
- **任务草稿审阅自然语言微调修正（Steering Instruction）**：
  - 在任务草稿审阅弹窗（`chat-shell.html`）中新增自然语言微调输入区（`#chat-task-draft-steering`），支持用户输入补充约束（例如：“请改为只读扫描，不要修改生产数据”）。
  - 在 `chat-task-drafts.js` 中打通 `PATCH /agents/task-drafts/:id` 自然语言修正链路，提交后由草稿规划器动态调整工具集、授权策略与执行预算，彻底消除修改参数需推倒重来的繁琐痛点。

### 2. 支柱二：工作流 DAG 断点续跑与微观编排体验深度升级

- **甘特瀑布图行级断点续跑（Waterfall Breakpoint Rerun）**：
  - 在工作流耗时甘特瀑布图弹窗（`dag-timeline-waterfall.js`）中，对状态为异常（`error`、`continued_error`）或被取消（`cancelled`）的节点行，右侧直观渲染专属「断点续跑」操作徽章。
  - 用户可直接在耗时瓶颈分析视图中针对失败节点发起断点续跑，无需关闭弹窗后寻找节点，大幅提升排错与微调效率。
- **节点检查器（DAG Inspector）断点续跑与运行状态感知**：
  - 节点侧边检查器（`dag-inspector.js`）实时订阅当前运行状态，当选中节点处于失败或中断状态时，在操作区高亮显示「从本节点断点续跑」按钮。
- **节点参数输入行内 `{{` 智能变量补全感知**：
  - 针对常用参数输入框（`data-pivot-dag-input-field`）以及聚合节点字段值（`data-pivot-dag-merge-value`），监听键盘输入。
  - 当用户在任意位置键入 `{{` 时，系统自动在当前光标处弹出智能变量选择气泡（Variable Picker Popover），展示上游节点输出与全局输入字段；选中后自动闭合插值语法，大幅降低手工手写变量路径的心智负担。
- **全链路断点续跑条件放宽与状态包容**：
  - 在画布节点层（`agent-run-visuals.js`）与执行器中，断点续跑状态由仅限 `error` 扩展为完全包容 `error`、`continued_error` 以及手动 `cancelled` 节点，且按钮文案标准化为精准的「从本节点断点续跑」。

### 3. 支柱三：智能体运行控制面与人机协同防护

- **敏感工具审批「本轮运行记住授权（Remember for Run）」**：
  - 针对高危或需要人工确认的工具调用（如数据库写操作、终极执行器、外部通知等），在对话任务卡片与运行详情的审批面板中新增「本轮任务不再重复确认」复选框。
  - 后端在 `server/services/agent-runtime/approvals.js` 与 `approval-decisions.js` 中实现动态授权续期（`rememberForRun`），在同一运行生命周期内相同动作类型自动放行，避免多步自动化任务频繁弹窗打扰用户，兼顾安全性与顺畅度。
- **任务全景交付物与工程凭据包导出（Audit & Evidence Bundle）**：
  - 新增服务端导出路由 `GET /agents/runs/:id/audit-bundle`，支持 Markdown 结构化报告与 JSON 机器可读格式导出。
  - 自动整合任务目标、终态结果、步骤耗时明细、工程凭据哈希（SHA-256）、验收核验结果、浏览器会话及写事务审计日志，满足生产环境严肃交付与审计溯源需求。
- **运行诊断规则引擎扩展与可操作解决步骤（Actionable Steps）**：
  - 在 `server/services/agent-diagnosis.js` 中全面扩充错误诊断规则，新增对请求限流（`rate_limit` / 429）、浏览器连接断开（`browser` Target closed）、权限受限（`permission` 401/403）、数据契约列名不匹配（`schema`）及 JSON 语法错误（`syntax`）的精确识别。
  - 诊断输出新增结构化 `actionableSteps` 操作建议数组，为自动化运维和前端自愈提供标准动作语义。

### 4. 支柱四：调度防雪崩、平滑抖动与可靠性保障

- **平滑抖动打散分发（Smooth Jitter Staggered Dispatch）**：
  - 在 `server/services/agent-schedules.js` 的 `runDueAgentSchedules` 中引入 250ms 的错峰延时抖动机制（Jitter）。
  - 在整点或批量任务同时到期触发时，平滑打散数据库并发写入锁与下游 LLM API 配额竞争，彻底消除服务整点毛刺与雪崩风险。
- **错失执行策略标准化（Missed Run Policy）**：
  - 引入并正规化 `missedRunPolicy` 配置（`skip_missed` vs `fire_once`）。
  - 当系统维护或离线恢复后，若计划任务到期且严重超期（> 15 分钟），配置了 `skip_missed` 的任务将自动记录审计日志并对齐至下一个未来周期，避免队列堆积数十次无效重复跑批。
