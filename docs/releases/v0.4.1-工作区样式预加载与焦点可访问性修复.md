# v0.4.1 工作区样式预加载与焦点可访问性修复

发布日期：2026-10-18

## 版本摘要

本补丁修复聊天工作区的两类浏览器控制台问题：未实际使用的 Agent 工作区 CSS 预加载，以及隐藏工作区时焦点仍停留在其内部导致的 `aria-hidden` 拦截。修复不改变工作区的按需加载策略、权限模型或 Agent 运行语义。

## 问题与根因

### 1. CSS preload 未被使用

旧实现会在鼠标经过、获得焦点或预热自动化入口时，预先创建 `rel="preload" as="style"` 的 Agent CSS 链接。若用户随后没有真正进入该工作区，浏览器会在窗口加载后的数秒内报告“preloaded but not used”。这不是样式文件缺失，而是预加载时机与实际导航不匹配。

### 2. 隐藏容器仍包含焦点

设置页关闭或工作区切换时，焦点可能仍停在 `#admin-modal-close` 等即将隐藏的按钮上。随后父容器被标记为 `aria-hidden`，浏览器为了防止辅助技术失去当前焦点而阻止该变化，并报告 WAI-ARIA 焦点冲突。

## 修复内容

### 受控按需样式加载

- 删除工作区 CSS 的预测性 `rel="preload"` 创建和自动 Agent CSS 预热；不再产生“预加载但未使用”的请求。
- 保留用户真正进入工作区时的 `rel="stylesheet"` 按需加载、版本参数和首帧就绪等待逻辑。
- 模板预热仍可执行，因此不因移除 CSS preload 而牺牲工作区结构的预取能力。

### 可访问性焦点转移

- 新增 `workspace-accessibility.js`，专门负责隐藏面板前的焦点保护。
- 导航层在对每个非目标面板设置 `hidden`、`aria-hidden="true"` 与 `inert` 前，检测活动元素是否位于该面板内。
- 若焦点位于待隐藏面板，优先聚焦目标工作区对应的可见侧栏/底部导航；没有可见目标时主动失焦，绝不保留焦点于不可访问树中。
- 设置关闭流程不再自行给管理容器写 `aria-hidden`，避免绕过上述统一顺序。
- 新模块在工作区导航脚本之前加载，并登记到静态资源标签映射中。

## 验收标准

1. 静态页面契约中不存在工作区 CSS 的 `rel='preload'` 写入。
2. 工作区样式仅在实际进入对应工作区时，以 `rel='stylesheet'` 方式加载。
3. 隐藏任意工作区前，内部活动元素会被移出；隐藏面板同时具备 `aria-hidden="true"` 和 `inert`。
4. 可访问性模块在 `app-workspaces.js` 前加载，工作区导航脚本不突破架构治理的大文件阈值。
5. 浏览器以新版本资源重新加载后，不再出现本版本覆盖范围内的两类控制台告警。

## 部署与复核

部署 v0.4.1 后须重启或滚动重启 Pivot 服务，使 HTML 中的 `__APP_VERSION__` 生效；随后在浏览器执行一次硬刷新，或清除旧页面后重新打开。控制台中仍出现 `?v=v0.3.21` 表示浏览器页面或服务进程仍在使用旧版本资源，不能据此判断 v0.4.1 修复失败。

建议复核路径：打开设置，令关闭按钮获得焦点后关闭设置；再依次进入和离开自动化/Agent 工作区，确认控制台不再出现本版本所修复的 preload 与 `aria-hidden` 焦点告警。
