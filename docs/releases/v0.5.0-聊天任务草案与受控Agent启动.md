# v0.5.0 聊天任务草案与受控 Agent 启动

发布日期：2026-10-19

## 版本摘要

本版本将聊天中的即时“以 Agent 执行”升级为**先规划、后确认、再执行**的受控流程。普通发送继续是默认的快速对话路径；“规划任务”只创建和呈现任务草案，不启动 Agent，也不访问资料库或工具。

```text
输入任务 → 规划任务 → 审阅/编辑草案 → 确认计划 → 创建受控 Agent Run
```

## 用户可见行为

- 输入区保留“发送”和“规划任务”两个清晰入口。Enter/发送始终是普通对话。
- 规划页展示任务目标、交付物、步骤、风险、预算、运行边界和待澄清项。
- 用户可编辑标题与目标并重新生成计划；每次修改都会创建新的草案 revision。关闭审阅页后，以相同目标再次点击“规划任务”会重新打开仍有效的草案，避免静默重复创建。
- 只有“确认计划并开始执行”才会创建持久 Agent Run；创建成功后可直接进入既有运行详情查看进度、审批和结果。
- 目标过于简短时，草案会要求补充信息，不能绕过澄清直接启动。

## 执行与安全边界

- 规划阶段是确定性、无副作用的本地服务逻辑：不调用 LLM、不检索记忆/RAG、不发现或调用工具。
- 草案使用 24 小时有效期、revision、计划摘要和策略摘要，防止用户确认已变化或已过期的内容。
- 确认与启动为独立审计事件；启动路径采用 `approved → starting → run_created` 状态机和数据库行锁，避免重复 Run。
- 首批草案 Run 固定使用 `builtin_only` 工具策略，最大 20 步、60,000 Token、10 分钟与一次重试。外部工具、浏览器写操作、通知、发布、删除等能力不会因草案确认自动取得许可，仍由既有执行期策略与审批控制。
- Run 仍通过现有 `agent-runtime` 创建，继续复用任务事务、执行授权、检查点、恢复、审计和聊天结果回写，不存在平行的未治理执行器。

## 服务接口与数据迁移

新增以下用户隔离接口：

```text
POST  /api/agents/task-drafts
GET   /api/agents/task-drafts/:id
PATCH /api/agents/task-drafts/:id
POST  /api/agents/task-drafts/:id/approve
POST  /api/agents/task-drafts/:id/start
POST  /api/agents/task-drafts/:id/cancel
```

新增 PostgreSQL 迁移 `202610190001_agent_task_drafts`，创建：

- `agent_task_drafts`：目标、计划、策略快照、摘要、revision、过期时间与 Run 关联；
- `agent_task_draft_events`：创建、修订、确认、启动、创建 Run 与失败恢复的不可变审计事件。

应用启动时会按现有迁移机制自动执行；部署前请按常规流程备份数据库并检查迁移日志。

## 本版范围与后续

本版完成了 Plan-to-Run 的核心闭环，但不宣称已开放无监督 Autopilot：

- 尚未自动向用户弹出“任务化建议”，普通对话不会因关键词自动任务化；
- 尚未在草案页预取外部工具、资料或浏览器能力；这避免计划阶段扩大权限；
- 更细的交付物类型、资料/工具候选、任务卡持久展示、协作/后台自主等级与评测灰度，将按 [产品级优化方案](../design/Pivot聊天Agent任务升级产品级优化方案_2026-10-19.md) 的后续阶段实施；
- 启动后的外部能力扩展，必须按能力域分别完成评测、审批、故障恢复、灰度和五分验收证据，不能因为草案流程已上线而默认打开。
