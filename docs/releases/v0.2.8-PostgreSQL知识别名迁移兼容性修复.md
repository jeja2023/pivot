# v0.2.8 PostgreSQL 知识别名迁移兼容性修复

发布日期：2026-10-12

## 概述

本版本修复生产升级时 `202610100002_knowledge_derived_quality` 可能导致服务无法启动的问题。部分历史 PostgreSQL 库的 `knowledge_entities.aliases` 仍是 `TEXT`，而迁移将该列与 JSONB 空数组直接用于 `COALESCE`，会触发 `COALESCE types text and jsonb cannot be matched` 并使整个迁移事务回滚。

## 修复内容

### 兼容 TEXT 与 JSONB 别名列

迁移回填实体别名时统一将来源列转为文本输入，并由当前数据库连接内的临时 PostgreSQL 函数安全解析为 JSONB 数组。因此：

- 历史 `TEXT` 中保存的合法 JSON 别名数组可正常回填；
- 当前 `JSONB` 列继续按原有语义回填；
- `NULL`、空字符串、空白、无效 JSON 与非数组 JSON 统一按空列表跳过；
- 重复执行仍使用唯一约束去重，不会重复创建别名记录；
- 临时函数在迁移结束前删除，不会在数据库中遗留永久函数或对象。

### 可直接恢复失败升级

迁移运行在单一事务中。此前发生类型错误时，已执行的 DDL 和回填都会回滚，`schema_migrations` 不会记录 `202610100002_knowledge_derived_quality`。部署本版本后重启服务即可自动重试；不需要手动转换字段、删除数据或插入迁移记录。

`verify:knowledge-derived-governance` 现会自动加载项目 `.env`，可直接作为部署后的只读验收命令使用。

## 升级步骤

1. 按既有流程备份 PostgreSQL 数据库与同一恢复点的 `uploads/` 目录。
2. 部署 `v0.2.8` 服务端镜像或代码并重启服务。
3. 确认启动日志不再出现 `COALESCE types text and jsonb cannot be matched`。
4. 在受控运维环境执行：

   ```powershell
   npm run verify:knowledge-derived-governance
   ```

5. 仅当验收输出为 `ok: true` 后恢复或扩大业务流量。

如迁移仍失败，应保留完整错误日志并检查应用账户是否有 `CREATE FUNCTION`、`CREATE INDEX`、`ALTER TABLE` 及写入 `schema_migrations` 的权限；不要通过手工写迁移记录绕过失败。

## 验证

- 在本机 PostgreSQL 18.3 中，于事务内分别将 `knowledge_entities.aliases` 置为历史 `TEXT` 和当前 `JSONB`，完整运行迁移后核验表、索引和临时函数清理；两组验证均已回滚，不影响本地数据；
- `PIVOT_TEST_PG_SYNC=true node -r dotenv/config --test tests/knowledge-derived-quality-migration.test.js`：2/2 通过，覆盖 TEXT、JSONB、空值、无效 JSON、非数组 JSON、正常别名和幂等重试；
- `npm run verify:knowledge-derived-governance`：通过，确认三条知识派生迁移记录、关键表、索引和质量字段齐全；
- `node scripts/check_pg_migration_coverage.js`、ESLint 与 `git diff --check` 通过。
