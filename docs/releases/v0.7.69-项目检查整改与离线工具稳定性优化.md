# v0.7.69 项目检查整改与离线工具稳定性优化

日期：2026-10-29

## 更新内容

1. **模板权限与评分**：私有模板的列表和评分沿用访问权限边界，缺少身份时不会列出私有模板；评分只接受 1 至 5 的整数。补充创建、筛选、分页、应用、评分及跨用户权限回归，并迁移不再执行的旧测试。
2. **旧实验接口**：评测、流式、工具推荐、规划和编排中的未完成操作先进行认证，再返回 `503 EXPERIMENTAL_API_UNAVAILABLE`，不把模拟结果当成真实执行结果。编排 DSL 的示例、解析和基础验证保留，修复步骤、Agent 引用和空依赖解析。相关入口与当前能力的区别见[旧实验接口核对与迁移](../reports/2026-10-29-旧实验接口核对与迁移.md)。
3. **离线工具与绘图**：工具服务启动前等待 Mermaid 完成实际渲染健康检查；连接和超时错误提供明确提示。离线导出可选择带标签的本地工具镜像，Compose、归档和清单使用同一标签。独立工具服务是可选组件，不包含在 Pivot 主镜像中；暂不更新已部署服务时，仍沿用原版本。
4. **依赖与工程保障**：聊天静态 KaTeX 从 0.16.9 升至 0.18.2，并通过构建和检查脚本保持静态资源与依赖一致；`diff` 及可兼容的传递依赖已更新。CI 和 `npm test` 增加类型检查、测试位置和 KaTeX 资源检查；指定多个测试文件时，缺失文件会明确报错。

## 验证范围

- 在隔离 PostgreSQL 环境以两个工作组执行全量 Node 测试：2395 项通过、2 项因外部服务条件跳过；之后使用真实 FastMCP、Mermaid 和 Graphviz 容器补测，均通过。全量测试之后补充的模板、离线包导出及文档变更分别执行了定向回归，不能把此前全量结果等同于最终版本的全量发布验收。
- 模板权限、旧接口真实入口、聊天公式布局及按需加载回归通过；离线工具 Python 错误处理、Docker Compose 配置和 Mermaid 健康检查通过。
- 生产依赖 `npm audit --omit=dev` 在检查时无告警；完整依赖树仍有 3 项低危告警，来自开发依赖的 Quill 和 KaTeX，当前思维导图裁剪构建未包含这两个包。依赖告警会随上游公告变化，发布前应重新检查。
- 已构建并验证本机 Linux AMD64 测试镜像和离线包 `artifacts/offline-tools-review-20261029/`，Node 与 Python 物料摘要检查通过。该包不含生产密钥，尚未在目标服务器部署或完成正式交付审核。
- 使用合成数据完成本机 10 万及 100 万行数据分析基准；独立数据库的备份恢复、知识库计数及引用对账通过。这些结果不代表生产负载、原文件、密钥、权限或完整应用恢复验收。详见[隔离基准与恢复演练](../reports/2026-10-29-隔离基准与恢复演练.md)。

## 更新与后续工作

更新主服务需使用当前锁文件重新安装依赖或重新构建主镜像，并重启服务、刷新页面。没有新增数据库迁移或必需环境变量。

如使用独立离线工具服务，需要分别构建或导入经过审核的工具镜像并更新对应 Compose 配置；只构建 Pivot 主镜像不会更新该独立服务。安装及验收步骤见[离线工具服务部署与验收](../deployment/离线工具服务部署与验收.md)。

旧实验接口是否恢复应先核对外部调用方和业务需求；恢复前须接入真实运行时并完成权限、错误和恢复测试。15 条决策案例仍待业务管理员[人工审核](../reports/2026-10-29-决策评测人工审核清单.md)，目标环境的并发负载、完整恢复、物料来源及部署验收仍需完成。
