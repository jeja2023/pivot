# v0.7.116 — BI 容量执行与运营监测

落实方案第十三节及 BI-11、BI-12 的容量执行、监测、告警与事故处置开发。本版为候选建设阶段；目标生产环境认证继续按用户要求暂缓，M5 的安全日志、共同恢复点和交付制品继续实施。

## 目录与执行

目录改为批量读取当前身份可见的摘要、最小图信息和来源字段键，交付前批量复核模型修订与授权。千模型、多个主体、单位/个人共享、旧探索和共享未发布草稿均纳入 HTTP 专项。完整定义和来源名称继续从详情按当前权限加载。

执行器复用编译器选出的关联路径，仅物化对应表和字段；未展示的内关联继续约束事实范围，全部来源仍检查行列总量和不可变对象。长批次期间另一个持久槽位可以继续领取任务，正常的排队/运行状态推进可返回状态摘要，完成数据仍复核对象和清单。

实际百万行宽表摄取暴露了 Parquet 写入 OOM。修复采用受控 CSV 缓冲、较小行组和物理行序设置，硬资源与业务时限保持不变；画像用原值分桶精确去重，预览截断不合并不同长值。格式探测之外的非法行仍全量拒绝。

## 监测与恢复业务

控制接口和已接纳任务分开记录三十天真实窗口、错误预算和延迟分布。完整质量检查发现脏数据属于平台成功，另计质量失败；服务错误、内部超时、系统取消和配额内误拒绝计为平台失败。用户主动取消、非法输入、鉴权和明确超额独立统计，终态重放不重复计数。

运行记录保存排队、来源准备、隔离运行、登记、CPU、RSS、容器峰值和溢写测量。启动和运行配置变化验证完整隔离及真实取消，周期轻量复核数据库保护，另提供维护窗口强制预检。

专用普通账号不签发交互登录凭据。正向探针核对专用数据的独立预期哈希，反向账号必须拒绝。发现错误结果或意外授权后持久关闭业务交付，关闭和响应共用数据库栅栏；修复成功后仍由系统管理员填写原因恢复。

告警复用现有可观测事件、地址检查、Webhook、脱敏和去重。新增服务端运营命令、受鉴权接口，以及[运行与事故处置手册](../BI数据建模运行与事故处置手册.md)。配置、事故关闭、恢复和取消均保留实际主体及变更哈希或原因审计。

## 验证与范围

两档夹具均包含九张一百二十列表、复合键、倾斜、高基数、宽字符串和未匹配明细。百万档位覆盖一百万事实行、两百万维度行，输入原字节约一点六一九 GB；检查、基础与复杂查询通过真实持久任务和 HTTP 读取核算独立黄金值。

本机千模型目录、十会话五秒间隔混合刷新、真实本地 Webhook、统计与权限事故、维护自举、周期预检、非法 CSV 和执行路径均有专项证据。容量脚本固定源码/锁文件/方案指纹并核对运行期间不变，记录输入摘要、镜像、引擎、配置、硬件、p50/p95/p99 和资源。

实测与失败迭代保存在[容量与运营本地证据](../reports/BI建模容量与运营本地证据-20261107.md)。十六 GiB 本机、Docker Desktop、短样本及未受控文件系统缓存均明确标注；此前 OOM、并行构建干扰及阈值未达样本不改写为通过。目标硬件、七十二小时、三十天历史、独立故障域和业务签认尚未执行，G0—G7 不因此获得生产放行。
