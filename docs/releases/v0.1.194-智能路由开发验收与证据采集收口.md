# v0.1.194 智能路由开发验收与证据采集收口

发布日期：2026-09-29

发布范围：智能路由与持续学习的开发机验收、冻结评测集完整性、Laya/Qwen GPU 资源证据采集、配置登记、目标内网交接文档和回归测试入口。

---

## 1. 发布目标

《智能路由与持续学习改造方案》的工程能力已具备，但开发机通过不应被误解为模型已经完成生产上线。本版本收紧开发验收条件、消除 GPU 证据采集的阻塞风险，并将开发机和目标内网的验收职责写入正式文档。

本版本不修改学习型模型的默认运行状态：系统继续保持 `shadow`、`0%` 灰度，且 Laya、Qwen、轻量模型默认不连接真实服务。

---

## 2. 开发验收加固

`npm run verify:decision-development` 现在要求：

1. 决策学习、评测治理和制品训练范围三项迁移已应用；
2. 冻结评测集已导入开发数据库；
3. 数据库中的评测集版本、案例数和源码 SHA-256 摘要与当前仓库一致；
4. 运行时保持非 `active`、0% 灰度；
5. Laya、Qwen、轻量学习型提供器均未连接真实服务。

评测集源码无法加载、数据库读取失败、版本不一致、案例数变化或摘要不一致均会以阻塞项报告。开发验收不会为尚待人工复核的案例生成伪造标签。

---

## 3. GPU 证据采集可靠性

新增共享服务 `server/services/decision-gpu-sampling.js`，供以下入口复用：

- `npm run benchmark:decision-resources`：Laya/Qwen 提供器基准时采样 GPU；
- `npm run report:decision-release-evidence`：生成发布证据快照时采样 GPU。

采样输出只保留 GPU 序号、名称、显存/利用率数值和峰值汇总，不保留原始命令输出。新增配置：

| 环境变量 | 默认值 | 范围 | 作用 |
| --- | --- | --- | --- |
| `PIVOT_DECISION_GPU_SAMPLE_TIMEOUT_MS` | `3000` | 100–30000ms | 单次 `nvidia-smi` 等待上限；超时只记录 `gpu_sample_timeout`，不会无限阻塞证据采集。 |

无 NVIDIA 驱动时，证据快照会正常输出 `gpu.available=false` 及可诊断错误码；在目标 GPU 主机使用 `--require-gpu` 时，资源基准仍会明确失败，防止将未采样环境误判为验收通过。

---

## 4. 开发机完成与目标内网交接

开发机已完成统一决策接口、候选治理、影子审计、冻结集导入和人工复核工作流、时间切分训练、制品/租户门禁、回滚熔断、维护报告、资源基准工具及对应回归。

以下事项必须由目标内网人员以真实业务和真实基础设施完成，不能由源码或开发数据库替代：

- 15 个冻结案例的人工复核；
- 现网基线、轻量模型、Qwen 与 Laya 的同集横向基准；
- 业务完成率、人工改路由率、重复处理率和独立测试集结果；
- Qwen/Laya 共卡、独立 GPU/CPU 的 GPU、吞吐、P50/P95、超时率与不可用率测量；
- Laya 超时、HTTP 500、版本漂移、并发满载和数据库故障的回退演练；
- 低风险租户/场景的受控 Active 灰度与经验证结果积累；
- 满足可靠结果信号与可逆低风险条件后，才评估 Bandit 试点。

相关流程见 [智能路由与持续学习实施验收清单](../智能路由持续学习实施验收清单.md)、[Laya 内网业务决策服务部署与验收](../Laya内网决策服务部署与验收.md) 与 [改造方案](../../智能路由与持续学习改造方案.md)。
