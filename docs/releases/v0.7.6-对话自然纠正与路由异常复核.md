# v0.7.6 对话自然纠正与路由异常复核

用户不再选择内部路由动作或提交独立反馈表单，而是直接在对话中纠正。“我只是问一下，不需要执行”“先给方案，不要修改”“不用工具”“应该查知识库”等明确表达影响本轮处理。其他任务调整继续由现有语义意图器决定；续接纠正关联原任务决策。

明确执行限制会先将唯一活动任务的能力范围收紧为空，再请求暂停；自动执行开关关闭也不能忽略控制要求。多项活动任务要求明确对象，暂停失败明确提示。本轮限制同步作用于知识库与工具路由，以及路由服务故障的回退路径。引用、代码、附件和讨论性表达不会被当成当前授权变更。已完成操作不自动撤销，审批和提交边界保持原有要求。

后台复用 `decision_outcomes`，无需新增表：保留原决策、纠正消息 ID、摘要指纹、本轮应用结果及已有执行证据。常规记录为 `not_required` 自动归档；任务执行范围、同类会话七天内反复纠正、与当前决策独立核验冲突进入 `pending` 异常复核。每个消息和决策保留幂等证据，同一决策的待复核项显示最新建议。旧反馈接口继续兼容历史客户端。

管理员在“系统设置 → 决策审核”查看异常或自动归档，详情包含即时约束与执行证据，覆盖知识库、工具、回复方式、任务执行和续接。用户纠正本身不能成为已核验训练标签；管理员采纳后才生成独立核验记录。

任务执行学习策略还必须通过覆盖 `direct_answer`、`plan_only`、`agent_run`、`continue_run`、`clarify` 的完整独立冻结评测；缺少覆盖时回到影子模式。v3 评测集保留 v2 的 15 个用例，新增 12 个任务与纠正用例，全部保持待人工审核。可以通过以下命令导入候选集，再使用既有双人审核流程：

```bash
node scripts/import_decision_evaluation_set.js <管理员用户ID> docs/decision-evaluation-set.v3.json
```

本次不会自动导入、审核或激活全局学习策略。现有租户边界、工具权限、冻结评测、灰度和回滚继续生效。详见[验收报告](../reports/对话自然纠正与路由异常复核验收报告_2026-10-19.md)。

验证结果：工程检查与 ESLint 通过，全量回归 2000 项、受影响回归 90 项、浏览器关键流程 2 项通过；复核详情在桌面与手机窄屏无横向溢出。
