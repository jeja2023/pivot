# v0.7.38 大模型附件正文上下文修复

发布日期：2026-10-23。版本类型：Agent 文档上下文可靠性修复。

## 问题与修复

聊天上传接口已能抽取 DOCX 正文并保存到本轮用户消息，但 Agent 规划器只处理结构化数组格式的 `currentMessage.content`。自动任务中该字段是字符串，因此规划器只收到简短任务目标，没有收到包含附件正文的原始消息，最终误称无法读取文档。

现在规划与最终总结都会读取字符串形式的当前消息；多模态消息也保留目标中未包含的原始文字及图片。若任务目标已经包含同一消息，则避免重复注入。附件内容明确作为待处理数据使用，不构成指令或执行授权；当前消息只有附件链接而没有抽取正文时，提示规划器先调用 `chat.read_source`。

## 本机复现

通过截图对应的本地任务和上传文件复现：DOCX 正文已成功抽取，数据库中的用户消息长度为 433 字符，Agent 目标仅 35 字；旧规划器因消息正文是字符串而将其丢弃。应用修复后，直接构造该任务的规划消息已确认包含 DOCX 正文。
