## 变更背景与根因分析

在 GitHub Actions CI 流水线（Node 20 & Node 22 双版本矩阵并行测试）中，出现三类关键故障：

### 1. Node 20 矩阵 SQLite 依赖测试大面积失败与段错误
- **故障现象**：在 Node 20 Runner 下，Worker 0 与 Worker 1 中所有直接或间接依赖 SQLite / DesktopAgentRuntime 的 9 个测试套件（`agent-acceptance`、`agent-non-idempotent-fault-matrix`、`enterprise-deployment`、`official-writing-isolation-contract`、`security-rag`、`data-analysis`、`db-migration-snapshots`、`desktop-agent-runtime`、`security-mcp`）在首行全部崩溃并报 `'test failed'`。
- **根本原因**：`better-sqlite3@13.0.3` 官方将运行环境锁定为 `"node": ">=22"`，仅内置了针对 Node 22（ABI 127）的预编译二进制，并配置了 `"gypfile": false`。在 Node 20（ABI 115）环境下 `npm ci` 既无法触发重新编译，Node 20 尝试 `dlopen` 载入 Node 22 预编译二进制时更会直接触发 C++ 段错误（Segmentation fault, SIGSEGV, 退出码 139），彻底阻断测试。

### 2. 上传安全中间件异步清理竞态
- **故障现象**：`tests/security-auth.test.js:1301` 中的用例 `uploadSecurityMiddleware rejects mismatched magic bytes and removes the file` 在高速断言时偶发失败（`true !== false`，期望文件已被移除，但实际仍存在）。
- **根本原因**：`server/upload.js` 中的 `removeUploadedPath`、`removeUploadedFile` 与 `cleanupRequestUploads` 采用无等待的 Promise 链（`fs.promises.unlink(...).then(...)`），`uploadSecurityMiddleware` 在检测到文件魔法字节不匹配后立即响应 HTTP 400，而底层磁盘物理文件的 unlink 尚未完成，导致断言命中竞态。

### 3. 测试环境变量与模块缓存隔离污染
- `tests/data-analysis.test.js` 覆盖 `PIVOT_ANALYSIS_DIR` 和 `DATA_ANALYSIS_MAX_ROWS` 后未在清理阶段还原。
- `tests/db-migration-snapshots.test.js` 在 `finally` 块中调用全局 `clearServerDbModules()` 清理 `require.cache`，导致并发/后续测试的数据库连接模块状态断裂。

## 核心改进与实现

### 1. SQLite 依赖版本对齐与全矩阵免编译直装
- 将 `better-sqlite3` 版本精确对齐至 `^12.11.1`：
  - 官方声明完整支持 `"node": "20.x || 22.x || 23.x || 24.x || 25.x || 26.x"`。
  - 内置 `prebuild-install` 机制，在 Node 20 与 Node 22 环境下均可通过官方预编译包免编译秒级安装，彻底杜绝 ABI 不匹配引起的 Linux 动态链接段错误（Segmentation fault）与测试崩溃。
  - 严格保持标准 CI 安装流水线（`npm ci`），移除所有侵入式的外部二进制修补脚本。

### 2. 上传中间件文件清理异步化改造
- 修改 `server/upload.js`：
  - 将 `removeUploadedPath`、`removeUploadedFile` 及 `cleanupRequestUploads` 改造为纯 `async/await` 函数。
  - 在 `uploadSecurityMiddleware` 拦截非法文件时，显式 `await cleanupRequestUploads(req, root)`，确保物理文件与缓存彻底清除后再发送 HTTP 400 响应。
  - 清理重复冗余函数声明。

### 3. 测试套件环境隔离复原
- `tests/data-analysis.test.js`：记录 `PIVOT_ANALYSIS_DIR` 与 `DATA_ANALYSIS_MAX_ROWS` 的初始状态，并在 `test.after()` 中严格复原。
- `tests/db-migration-snapshots.test.js`：移除破坏全局连接池单例的 `clearServerDbModules()`，确保连接正常关闭且模块引用保持稳定。
