# v0.1.37 安全边界、批量性能与发布治理升级

发布日期：2026-08-24

## 发布范围

本版本针对上一轮项目审阅提出的六项优化建议完成落地，重点覆盖桌面端本机能力安全、依赖供应链审计、管理员批量导入性能、分页资源边界、容器运行权限和持续集成治理。

## 主要变更

### 1. Electron Worker 安全边界

- 渲染页不能再自行声明 `approved: true` 启动本机进程。
- 主进程显示原生确认对话框后签发一次性审批令牌。
- 审批令牌绑定完整请求指纹，修改命令、脚本、参数、输入、任务、超时或工作区都会被拒绝。
- Worker 工作区固定为 `userData/agent-workspaces` 下的任务目录。
- 禁止解释器内联代码、绝对脚本路径、符号链接越权和通用 Worker 网络访问。
- 仅 HTTPS 页面或本地回环页面可以请求本机 Worker。

### 2. 依赖审计与 Electron

- `scripts/check_audit_policy.js` 现在递归保留 npm audit 的传递依赖闭包。
- 字符串型 `via` 不再静默跳过，缺少详情时会使门禁失败。
- `fixAvailable` 支持布尔值和对象形态。
- Electron 更新至 `43.4.1`，修复当前审计链中的 `extract-zip` 高危问题。

### 3. CSV 用户导入

- 密码哈希通过 Worker Thread 执行，默认按 CPU 并发度选择有限 Worker，最多 8 个。
- 数据库插入在单事务中分批执行，单批最多 500 行。
- 重复用户名不再依赖异常控制流程，结果会作为跳过项返回。
- 失败明细最多返回 1000 条，并额外返回 `omittedSkippedRows`。

### 4. 分页边界

以下接口统一采用 `normalizePage` / `normalizeLimit`：

- 管理员用户列表
- 审计日志
- 用量详情
- API 调用日志
- 数据分析产物列表

分页条数统一限制为 1-100，非法值回退到安全默认值。

### 5. Docker 运行时

- Dockerfile 改为 dependencies/runtime 多阶段构建。
- 最终镜像只保留运行依赖和 PostgreSQL 客户端，不包含编译工具链。
- 服务默认以非 root `node` 用户运行。
- Compose 使用只读根文件系统、`no-new-privileges` 和 `/tmp`、Node 缓存 tmpfs。
- `data`、`uploads`、`downloads`、`logs` 宿主机目录权限说明已同步更新。

### 6. CI 与治理指标

- CI 安装 Chromium 并真实运行 `npm run test:e2e`。
- 新增 `npm run check:governance`：存量大文件只允许缩小，禁止新增未登记大文件。
- 新增 `npm run report:governance`：输出生产 JS 数量、大文件清单、legacy 全局预算和 E2E 数量。
- 附件预览接入 `Pivot` 模块命名空间，legacy `window.*` 暴露减少 2 项。
- 优化路线图中的固定测试/漏洞/全局变量数字改为实时指标说明。

## 升级注意事项

1. Docker Compose 首次升级前，为宿主机 `data`、`uploads`、`downloads` 和 `logs` 目录设置容器用户可写权限：`sudo chown -R 1000:1000 data uploads downloads logs`。
2. 远程 Electron 模式下，本机通用 Worker 仅允许 HTTPS 目标或本机回环目标；普通局域网 HTTP 页面不能调用该能力。
3. Linux Docker 镜像运行用户已变更为非 root，依赖宿主机挂载目录权限正确配置。
