# Pivot v0.7.179 发布说明

2026-11-19 · PPT Master 自动修页与交付核验

## 制作与恢复

- 已批准的清单与导出稿不一致时，若能取得失败页、原源页映射和当前导出回执，系统在原任务内只修复失败页，然后复检、重新导出和回读全部清单。未选页及其资源与原草稿核对；自动修复最多两轮，受原任务步骤、用量和权限约束。缺少必要材料或无法完成修复时保留草稿与诊断。
- 引文修复保留待修清单和全部待核对项，支持按页项修正。尚未批准的数值如能从同一来源唯一核实，可展示原值及更正后的值，再由用户确认。实际引文及页面数据校验会区分数字正负号；无法唯一核实或材料有歧义时继续查证。
- 页面检查失败会中止同批后续动作，失败检查须在对应项目复检通过后才能导出。重复检查或重复写入相同内容不再重置停滞检测。引文证据与图片同轮发送时，正确登记已读取的图片，避免重复传图。
- 所选固定模板的规范用于最终清单确认，并安装到实际项目；交付时复核安装记录和原始规范摘要。正式交付验证本次导出摘要，旧导出可供历史查看，但不能当作当前成品。

## 部署与兼容

此批涉及主应用和 PPT Master 独立执行服务，须配套更新。独立服务应支持 `currentExport` 和 `pageRepair`；主应用登录后可通过 `GET /api/apps/presentations/master/info` 核对 `engine.currentExportReady`、`engine.pageRepairReady`。新任务缺少当前导出核验能力时会提示更新服务。

旧任务的检查点绑定原引擎身份。更换镜像前应在原主应用和原引擎处理需要续跑的任务，备份并保留数据库、主应用持久目录、服务 `/data` 卷及连接配置。[数据保留与更新步骤](../deployment/PPTMaster独立服务部署与更新.md#保留原数据卷和任务)

本次不新增数据库迁移或第三方依赖。Linux/amd64 离线升级包使用 `ppt-master:6.8.0-pivot0.7.179` 标签，使用已验收的引擎构建。包内提供 `ppt-master.tar`、SHA-256 校验文件、镜像身份、Compose 配置和升级说明。导入后的镜像清单摘要为 `sha256:e1f8aa256b628d72b0799965fd3124bf2308ae94713108ab492bfb548731bab8`，服务运行身份为 `sha256:33ce2f2155a7217a25df80e0bfbb2add16d8a5c89e25a7d946a4f6594f8464df`。生产部署和生产模型验收仍待执行。

## 本地验收与限制

- 升版前通过 111 项 PPT 专项 Node 测试，以及 26 项 Python 测试；Python 测试按各自依赖在 Linux 容器中分别运行。通过项目检查和 TypeScript 类型检查。
- 隔离环境使用普通账号、可控测试模型与实际独立执行引擎通过 6 项浏览器端到端测试，覆盖长材料、多图、标准工作台补缺、完整制作续作，以及「咨询决策」「学术研究」两个模板的自动修页。
- 两个模板首次导出的第 2 页使用测试错误值 90.25 万元；清单确认后自动修正为 80.25 万元。浏览器下载文件与修订导出逐字节一致，文件摘要与回执一致；LibreOffice 渲染后的第 2 页也读到 80.25 万元。实际引擎拒绝将旧导出登记为当前正式交付。
- 离线包重新导入后，确认独立服务报告 `currentExport: 1`、`deliveryChecklist: 1`、`pageRepair: 1` 和 `progressSnapshots: 1`。配合 Pivot v0.7.180 和受控测试模型复跑两个模板的自动修页及下载场景，两项均通过。包内的验收记录保存镜像和运行身份。
- 自动修页仅覆盖可定位源文件、能由已批准清单判断的情况，不能保证模型或模板的视觉效果、业务判断均正确。测试模型是可控夹具，不能替代生产模型端到端验收；生产部署与生产原任务未检查。
