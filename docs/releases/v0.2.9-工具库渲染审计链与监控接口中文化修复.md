# v0.2.9 工具库渲染审计链与监控接口中文化修复

发布日期：2026-10-12

## 概述

本版本修复工具库手动调用“文档渲染”时被错误拒绝的问题，并完善系统监控“热点接口详情”的中文展示。修复不改变文档渲染权限、工具策略或交付授权边界，也不包含数据库迁移。

## 修复内容

### 手动文档渲染具备完整审计关联

工具库的 `POST /api/tools/invoke` 可执行内置 `artifact.render`。此前该路径只传递了工具库入口信息，未提供渲染所需的工具调用步骤标识，因而返回：

```text
ARTIFACT_RENDITION_TOOL_CALL_REQUIRED
```

现在服务端会为每次手动调用生成 `manual-tool:<用户ID>:<UUID>` 标识，并将同一个标识传给：

- 工具策略调用记录；
- `artifact.render` 生成的 rendition；
- 后续交付审计事件。

该标识由服务端生成，浏览器提交的任意同名字段均不会被采用。`artifact.render` 仍会拒绝没有步骤标识的内部调用，避免绕过工具调用审计链。

### 热点接口详情中文化

系统监控补齐以下高频路由的中文接口名称：

- 本机设备身份挑战、连接器心跳与连接器任务领取；
- 本机交付任务领取；
- 当前生效公告、指定演示文稿和客户端版本信息；
- `unmatched`、未知业务 API 和未知静态资源。

名称列用于阅读，原始地址继续显示在“路由地址”列，方便运维在日志、反向代理或抓包记录中精确定位。

## 升级步骤

1. 按常规流程部署 `v0.2.9` 服务端并重启服务；无需执行手工 SQL、删除缓存或修改迁移记录。
2. 以有 `document.render` 权限的账号在工具库执行一次 `artifact.render`，确认返回 rendition，而非 `ARTIFACT_RENDITION_TOOL_CALL_REQUIRED`。
3. 在“工具库 → 运行与治理”查看调用记录，确认手动执行已产生审计事件。
4. 更新同版本前端资源或桌面客户端后，打开“系统设置 → 系统监控 → 热点接口详情”，确认名称列显示中文名称。

若升级后仍出现错误，请保留返回的 `errorId` 和服务端日志。不要通过删除 `agent_artifact_renditions`、修改 `tool_invocation_events` 或让客户端伪造步骤标识来绕过审计校验。
