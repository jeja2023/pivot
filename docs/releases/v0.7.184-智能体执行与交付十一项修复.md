# Pivot v0.7.184 发布说明

2026-11-20 · 智能体执行与交付十一项修复

本版修复智能体执行审查中确认的 11 项问题（7 项 P1、4 项 P2），另修复浏览器回归发现的工作流结果轮询问题。本版包含 [v0.7.183 智能路由与任务控制修复](v0.7.183-智能路由与任务控制十项修复.md)。

## 逐项修复

| 编号 | 优先级 | 修复 | 实际行为 |
| --- | --- | --- | --- |
| 1 | P1 | 任务创建与入队竞争 | 队列记录、任务事务、初始工作记忆、资源预留和 DAG 初始节点在同一数据库事务内提交。初始化失败会撤销整次接纳及资源预留。并发请求沿用同一幂等键时返回已接纳的同一任务。 |
| 2 | P1 | Agent 模型日额度 | JSON 和原生流式调用在请求上游前预留当前账号的模型日额度，规划、核验与故障切换走同一调用边界。额度不足时在本地拒绝，收到的用量先结算再释放预留。 |
| 3 | P1 | DAG 累计 Token 预算 | 大模型节点的原生请求、兼容回退和 JSON 修复在调用前核对输入与输出额度。并发节点为仍在进行的请求保留额度，等待中的节点在预留释放后重新检查余额。已发生的用量同步计入累计库记录和预算快照。 |
| 4 | P1 | DAG 暂停与迟到核验 | 核验接受当前运行的取消信号。写入报告、推进事务及更新终态前核对运行状态与租约，并在同一数据库事务中保存。暂停后仍处于待补充状态，迟到回复无法登记已核验或已提交。 |
| 5 | P1 | 指定交付格式丢失 | 保存、续接、复验均保留明确要求的文件格式。要求 PPTX 和 PDF 时，核验逐项检查对应登记产物。旧任务在现有权限范围内按原始请求复核格式。 |
| 6 | P1 | 工作台审批缺少绑定 | 批准和拒绝绑定界面显示的参数摘要、审批标识和申请时间。本次任务的记住选项随批准一起提交，过期时可更新授权请求并重新审阅。 |
| 7 | P1 | 事务已提交但任务回执缺失 | 事务提交后如任务终态写入失败，重试或后台恢复可用原提交回执补齐同一任务的状态，既有副作用按原幂等约束处理。 |
| 8 | P2 | 超时误记为主动取消 | 达到运行时限时记录预算诊断，并尽可能保留已有部分结果。任务列表和恢复流程可区分超时、主动停止、暂停和租约丢失。 |
| 9 | P2 | 持续监控结果无法补发 | 监控结果摘要与渠道待发送记录一并提交。首次写入失败时保留待投递状态，后台恢复按原投递键补发。 |
| 10 | P2 | 续跑丢失模型策略 | 从检查点新建续跑、整项重跑和 DAG 节点重跑均继承原运行的模型路由策略，继续根据当前账号复核模型可用性。 |
| 11 | P2 | 队列刚认领时停止失败 | 停止操作同时覆盖排队和执行等可停止状态。队列认领与停止重叠时，一次请求即可停止任务，等待提交仍走事务决定。 |

**工作流结果页**持续跟踪执行和核验状态。表格结果在工作流完成后提供 CSV 与 Excel 下载。

## 升级与兼容

- 本次启用 Pivot 主应用源码版本 v0.7.184。沿用已有 PostgreSQL 数据库及配置即可更新，本版无需新增迁移、依赖或必填配置。[主应用离线部署](../生产环境离线部署.md)
- 自行调用 `POST /api/agents/runs/:id/approval` 的集成应提交布尔值 `approve`，并携带当前审批提供的 `inputHash`、`key` 与 `requestedAt`。遇到审批已变化或已过期的提示时，请重新读取请求并核对后再提交决定。[使用帮助](../../使用帮助.md)
- 渠道补发覆盖已登记的待投递运行。核对历史漏发时，请以任务结果和现存渠道回执为准。
