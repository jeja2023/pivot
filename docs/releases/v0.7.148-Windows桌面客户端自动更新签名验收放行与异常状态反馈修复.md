# v0.7.148 Windows 桌面客户端自动更新签名验收放行与异常状态反馈修复

日期：2026-11-10。归档 Windows 桌面客户端自动更新校验修复、状态机异常反馈与发布加固。

## 使用变化

- Windows 桌面客户端在局域网/内网自签名环境下，点击“检查客户端更新”检测到新版本后，下载完成将正常弹出“Pivot 更新已就绪”对话框并提示“重启并安装”，消除此前下载完成却静默无提示、无法自动安装的阻断缺陷。
- 更新就绪提示框弹出前，主窗口若处于最小化或后台状态将自动恢复并置顶激活，防止系统更新确认弹窗被其他全屏窗口遮挡。
- 客户端更新若因网络中断、校验不匹配或策略拦截发生异常，顶部菜单角标与下载进度将自动复位，并通过提示框（Toast）明确说明失败原因，不再停留在“正在下载更新”的假死状态。

## 执行链改造与根因修复

### 1. 签名验收放行与指纹锁定绑定

- 排查定位了历史提交 `473fb3b1`（v0.7.75）在安全加固时引入的回归：错误地将 Authenticode 校验结果一刀切限制为 `statusCode === 0`，导致 Windows 系统针对本地自签名证书（`CN=Pivot Local Dev`）返回的 `Status: 1`（未受信任根证书）被误杀，进而触发 `ERR_UPDATER_INVALID_SIGNATURE` 并静默清理已下载的安装器。
- 在 `desktop/updater.js` 中恢复对局域网自签名发布者 `Pivot Local Dev` 及 `allowUntrustedRoot: true` 配置的放行判定，允许 `Status: 1`（UnknownError）与 `Status: 6` 进入指纹核验链路。
- 严格绑定 SHA-256 证书指纹锁定（Fingerprint Pinning）：放行 `Status: 1` 的同时必须核验安装包证书的 SHA-256 散列值与内嵌受控分发配置完全一致，彻底防止局域网内被第三方伪造同名自签名证书劫持更新。

### 2. 对话框焦点与状态机反馈加固

- 修复 `desktop/updater.js` 中的 `showUpdateDialog` 调用时序，在呈现对话框前依次执行 `restore()`、`show()` 与 `focus()`，确保安装提示模态框处于视口顶层。
- 完善 `client/chat/desktop-menu.js` 中的 `applyUpdateState`，对 `status === 'error'` 补齐清理与反馈逻辑：移除品牌按钮的 `has-update` 和 `is-ready` 标记，弹出 `客户端更新失败：[错误详情]` 提示。
