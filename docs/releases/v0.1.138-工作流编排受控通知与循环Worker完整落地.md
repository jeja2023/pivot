# Pivot v0.1.138 发布记录：工作流编排受控通知与循环 Worker 完整落地

## 版本概览

- **版本号**：v0.1.138
- **发布日期**：2026-09-18
- **核心定位**：完成工作流编排易用性优化方案阶段 4，建立企业微信/飞书/钉钉受治理通知链路，并为 `workflow.foreach` 提供独立、可取消、可审计的 Worker 执行平面。

## 一、工作流编排体验

- `workflow.template`、`agent.merge`、`workflow.notify` 和 IM 预设进入可发现节点目录；输出 Schema 与后端真实契约保持一致。
- Inspector 支持输入、模型、HTTP、条件、merge、文本模板和受控通知的常用参数内联编辑；复杂 Schema 和高级策略仍通过向导配置。
- 变量选择器、上游依赖提示、测试输出快照和运行详情节点定位链路完善。
- DAG 支持 `pivot.dag.v2` True/False 路由边，保留旧版 `dependsOn + when` 兼容路径，并在运行详情展示跳过原因。

## 二、受控通知连接器

### 支持的平台

- 企业微信：`text` / `markdown` payload；
- 飞书：`text` / `post` payload；
- 钉钉：`text` / `markdown` payload，并支持服务端 HMAC 签名。

### 治理链路

1. 管理员在渠道控制面创建 `agent_channel_bindings`，配置平台、受控 Endpoint 和凭据引用；
2. 工作流节点只填写绑定 ID、平台、正文、格式和幂等键；
3. 服务端校验用户权限、平台与绑定一致性、审批和网络策略；
4. 消息写入 `agent_channel_deliveries`，由投递队列执行认领、发送、退避、重试和死信；
5. 节点返回 `queued`、`deliveryId`、`bindingId`、`status`、`platform` 和 `idempotencyKey`。

工作流不接受裸 Webhook URL。凭据不会回显到前端或节点输出，通知预览和单节点测试不会产生真实外部副作用。

## 三、`workflow.foreach` 受控 Worker

- 服务端进程内直接调用始终拒绝；只有完整 DAG 在审批通过后才能启动 Worker。
- Worker 使用独立子进程、任务工作区 Jail 和无网络策略执行逐项 JavaScript 转换。
- 限制：最多 1000 项、代码 32KB、变量 256KB、并发最多 20、单项超时 50～5000ms、最多 3 次逐项重试、单项输出 200KB、累计输出 1MB、控制面任务最长 10 分钟。
- 运行级 `AbortSignal` 会终止整个 Worker；Worker 返回完成数、失败数、重试数、请求/实际并发、超时、输出字节和错误明细。
- 输出契约包含 `items`、`count`、`inputCount`、`errors`、`stoppedOnError`、`audit` 和 `worker`。

## 四、版本与配置

- 版本号以 `CHANGELOG.md` 为单一来源，已同步到 `package.json`、`package-lock.json` 和 README。
- 新增环境开关 `AGENT_FOREACH_WORKER_ENABLED=true`；设为 `false` 可在部署侧紧急下线循环节点。
