# v0.3.20 - 全域五分验收门禁与可恢复工作区闭环

发布日期：2026-10-18

> 版本性质：工程治理与恢复能力版本。它不表示 18 个领域已达到 5 分，不替代真实生产灰度、跨平台演练或架构委员会认定。

> 记录范围：本记录覆盖 2026-10-17 至 2026-10-18 围绕《Pivot 对照 Claude Code 架构深度剖析与前沿设计指南》的工作区工程增量。为了不把“代码与测试已落地”误写成“生产验收已完成”，每个章节同时保留尚未达成的外部证据边界。

## 1. 五分认定从文本声明升级为受控证据

- 新增 `agent_domain_acceptance_evidence` 结构化证据台账与版本化迁移，覆盖实现审查、自动化、非功能、灰度和委员会五类材料。
- 每个领域的非功能指标、阈值、至少 30 个样本、24 小时完整灰度、P0/P1=0 均由服务端校验；提交者不能通过降低阈值、伪造 `passed` 或自由文本绕过门禁。
- 每份证据要求受控报告引用和 64 位 SHA-256；证据内容、领域、类型和引用共同进入不可变摘要。历史自由文本记录保留审计，但不参与五分就绪度计算。

## 2. 四方委员会的真实身份闭环

- 系统管理员在质量面板配置 `platform_security`、`runtime`、`qa_sre`、`product` 四个角色，对应四位不同的活跃管理员。
- 委员会记录必须先取得前四类已核验证据；每位预配置成员通过本人登录态签署。提交人及任意签署人均不能核验同一委员会记录。
- 面板展示待签数量、独立核验入口和缺失证据；证据齐备仅显示 `ready_for_committee_score`，不会自动调整成熟度评分或创建生产发布。

## 3. Capability Worker 生产前演练

- `npm run preflight:capability-workers` 检查启用状态、签名清单和本机已预置的摘要镜像。
- `npm run drill:capability-workers -- --confirm-staging` 仅允许 staging 执行，复用实际 Worker Docker 参数，验证非 root、只读根、Capabilities 清空、网络禁用；生产环境明确拒绝。
- 预检或演练失败仍会阻断高风险执行，不会回退到宿主机执行。

## 4. 长任务工作区恢复

- 影子工作树的 `workspace.patch` 完成后，在本机受控数据目录创建 gzip 压缩、内容寻址归档；归档不进入控制面、不包含本机路径。
- 归档跳过 `.git`、`node_modules`、符号链接、`.env`、`.npmrc`、`.pypirc`、证书、私钥、PFX/P12、密码库等敏感文件，并限制为最多 1,000 文件、20MB。
- Task Transaction 仅在归档摘要与恢复句柄齐全时标记 `controlled_restore_available`。`workspace.restore_snapshot` 属于 `filesystem.write_workspace` 高风险能力，必须人工确认、重新校验摘要，并且只恢复到 Pivot 管理的全新目录。

## 5. 工具发现、模型路由与执行授权

- **渐进式工具发现**：`search → describe → execute` 维持唯一的自主执行入口；搜索缓存以用户、角色、策略、allowlist、发布版本、契约摘要、风险和审批元数据共同隔离，30 秒到期或目录/授权/发布变化后必须重新发现。执行与批量只读派发前会重新核对当前目录快照。
- **模型路由与降级**：质量路由仅选择样本量、时效、Wilson 下界、未完成率都符合要求的模型剖面；提供方超时、短暂网络错误、429/5xx 或明确结构化输出不兼容时最多切换一次能力兼容候选，固定模型、取消、预算耗尽及安全失败不静默切换。
- **Execution Grant**：高风险代码、终端、工作流 foreach 及可变本机工作区动作均绑定 Run、用户、工具、输入摘要、资源和策略快照；授权短期、一次性消费，且不传入 Worker 容器。
- **受控 Capability Worker**：生产只接受 `image@sha256`、固定命令与 RSA-SHA256 签名清单；Docker 强制 `--pull=never`、非 root、只读根、无网络、Capabilities 清空、PID/内存/CPU 上限和受限挂载。未配置或签名验证失败时 fail-closed。

## 6. 事务、审批与副作用安全

- **业务幂等**：Task Effect 支持按租户的业务幂等键；跨 Run 的并发外部副作用只能有一个实际认领成功，重复请求明确返回冲突而不是重复发送。
- **结果不确定人工处理**：外部响应丢失的非幂等效果不会自动重放；任务所有者必须提交 `committed`/`not_committed` 结论和持久化证据后才可继续处理。
- **资源租约与隔离**：副作用在暂存、执行、失败、回滚和释放时均受跨实例资源租约保护；过期租约不能让执行中或失败效果被无条件接管。
- **审批收紧与撤销**：审批绑定具体工具、输入摘要、资源和有效期；移除宽泛工具白名单回退。排队中的授权可 CAS 撤销为 `needs_input` 并记录审计，执行器已认领后明确拒绝“太晚撤销”。

## 7. 生命周期 Hook、DAG 与多 Agent 协作

- **受管 Hook 包**：新增组织级、不可变签名清单、输入/输出 Schema、范围、超时、稳定排序与脱敏审计；`run.started` 在 queued/resuming 转 planning 前真实 fail-closed 执行，不能通过后置审计伪造前置阻断。
- **Hook 运营治理**：系统管理员可导入、查看、停用和吊销受管包；同组织运行按租户解析，历史多管理员重复导入会保留最新组织版本并停用重复项，跨组织不可读取。
- **协作消息与汇合**：父子消息状态机拆分为 `pending → delivered → applied → acknowledged`；Supervisor 重启不会重复投递 Handoff。只有 `completed + verified + 非空交付 + Handoff 已送达` 的子任务可汇合。
- **组织角色策略**：研究、分析、审阅、写作等委派角色使用版本化组织策略，只能收紧内置工具、审批、步数和 Token 上限；单任务、批量委派和运行时 spawn 都记录并使用策略快照。
- **DAG 预览边界**：顶层 DAG、子工作流和工具编排共用副作用/审批预览限制，避免在预览或恢复路径绕过事务、补偿和资源声明。

## 8. 上下文、提示词与长期记忆治理

- **Working Memory 与压缩**：长任务在创建、人工控制、工具观察和压缩边界写入不可变修订；按 CAS 证据卡、带 ID 的 Working Memory、规则优先历史摘要进行三级压缩，硬约束/未决交付超预算时拒绝而不静默截断。
- **压缩观测**：保存压缩前后 Token、节省率和硬字段丢失数，不保存正文；冻结回归集覆盖约束、待办与 CAS 引用保留。
- **Prompt Registry**：稳定段/动态段分离，稳定段要求影响评测和另一管理员审批，以事务锁原子退役旧版、激活新版；缓存读写 Token 仅在提供方明确返回时显示，缺失时标记“未观测”。
- **记忆来源与效用**：消息、知识文档、工作流、技能和受控工作区来源通过独立 HMAC 指纹关联；来源变化进入 `review_required`，复核后才恢复。月度质量周期记录有用率、冲突、过期命中与撤销残留，导出使用重复读快照且有行数上限。

## 9. 浏览器自动化、多模态与代码语义

- **浏览器写操作证据**：`click/fill/select` 建立脱敏 Observe-before/Act/Observe-after 记录和视觉摘要哈希；写入前持久化恢复屏障，失租约、状态丢失或异常关闭必须进入人工恢复，不自动重放。
- **受控上传下载**：普通页面下载取消；显式下载只留下文件名、字节数和摘要后清理临时文件。上传仅接受当前用户可访问、状态 `ready`、大小及 SHA-256 都匹配的 rendition，不接收调用方路径或正文。
- **浏览器会话租约**：PostgreSQL 会话租约与令牌栅栏阻止跨进程并发写入，控制台错误摘要会脱敏。
- **语音任务控制**：浏览器语音会话仅接受固定暂停/继续/停止口令，并限制为当前用户、当前会话关联 Run；不持久化音频或转写，barge-in 只中断本地播报。
- **JS/TS/Python 语义导航**：已授权工作区和影子工作树支持 symbols/definition/references；JS/TS 使用受控 TypeScript Language Service，Python 使用受控 Pyright LSP。索引按文件版本失效并持久化相对路径/符号摘要，不上传源码；拒绝 `.git`、依赖目录和符号链接越界。

## 10. 评测、发布与可观测性

- **评测发布硬门**：场景/对抗/契约分层评测、双裁判分歧拦截、独立人工金标复核、技能与工作流 Release 归因，以及冻结阈值熔断、自动暂停/回滚均纳入发布链；Node 22 CI 线路强制执行发布质量门禁。
- **运行 SLO**：运行质量面板展示成功率、失败率和 p95 时延；低于 30 样本明确是“证据不足”，不显示为通过。后台调度仅在真实阈值越界时向系统管理员写入稳定去重的高风险收件箱事件。
- **链路观测**：Run、Hook、事务、消息、模型、浏览器、Worker 和评测通过关联 ID 连接；压缩、缓存、隔离、补偿、协作和质量指标均保留面板/审计接点。
- **SLO PostgreSQL 修复说明**：JSONB 存在性判断的生产热修复作为 v0.3.21 单独记录；该修复并不改变 v0.3.20 的验收口径。
