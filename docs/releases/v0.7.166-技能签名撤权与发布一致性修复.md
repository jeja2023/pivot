# v0.7.166 技能签名、撤权与发布一致性修复

日期：2026-11-17。启用源码版本 v0.7.166，归档技能审查后的七项修复。已有测试批次和安装包保留执行或构建时的版本身份。

## 修改内容

1. 组织批准技能时，签名覆盖规范化清单、完整正文和配套包摘要。新导入且要求受信签名的技能包必须使用覆盖整个包的分离签名；仅签署清单的旧格式不能证明正文可信。
2. 技能任务在模型执行、后续使用和结果读取边界复核所绑定发布、当前权限、来源和适用签名；没有读取资源时也会复核正文，资料范围刷新后重新检查。资源读取继续复核内容摘要。
3. 发布 ACL 的替换和删除使用事务和发布记录锁，避免显式拒绝在替换过程中消失或并发写入产生重复记录。
4. 版本创建与验证接口只传递必要的业务字段；工作目录、隔离强度、公钥和能力允许清单由服务端决定。
5. 任务选择提交真实技能名称和发布引用，创建时核对发布 ID、版本和摘要；治理弹窗读取实际版本 ID。
6. 技能列表根据当前用户实际命中的发布版本显示标题、版本及状态。发布、暂停、恢复、回滚与投影刷新在同一事务中处理；手动操作和系统熔断共用状态变更，回滚不会重新启用已暂停或撤回的旧发布。

## 升级与兼容

- 更新 Pivot 主应用服务端和网页资源，刷新页面；从 v0.7.165 升级无新增数据库迁移或第三方依赖，更早环境仍须按项目原有流程完成历史迁移。保留数据库及 `DATA_DIR/agent-skills`；使用自定义 `AGENT_SKILL_ROOT` 的部署继续保留其原目录和挂载。
- 已发布的团队或组织技能如果使用历史仅清单签名，升级后需要管理员重新批准并组织签名，才能继续使用。重新签名前应核对指引及资源；任务已绑定的发布发生变化或授权撤回时，按提示重新选择技能并创建任务。
- 个人无签名配方仍可在个人范围使用。需要受信签名的新导入包，应由签发方生成覆盖完整包的分离签名；旧包不能仅凭清单签名称为完整内容已验证。
- 本次没有新增桌面 IPC，也没有构建、签名或部署新镜像和安装包。现有独立助手包保留 v0.7.164 开发验证身份；正式发布制品及目标环境部署需另行完成。
