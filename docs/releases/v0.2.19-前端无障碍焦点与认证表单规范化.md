# v0.2.19：前端无障碍焦点与认证表单规范化

发布日期：2026-10-13

## 变更摘要

本版本重点治理前端在 Chromium 内核浏览器下首屏加载、登录交互与弹窗操作中暴露的无障碍（Accessibility）、DOM 表单语义和首屏无用请求控制台告警：

1. **未登录鉴权请求与预加载时机收敛**：
   - 修复未登录时打开 `/chat` 首屏立即触发 `/api/chat/capabilities` 401 失败并级联触发 `/api/auth/refresh` 刷新令牌 401 告警的问题。该请求限制为仅在用户已登录（存在 `currentUser` 或接收到 `pivot:app-shown` 事件）后执行。
   - 修复未登录用户停留在登录面板时触发 Agent 工作区样式 prefetch 导致的 `<link rel="preload">` 未使用告警。Agent 样式预取推迟至用户登录成功或主动悬浮对应交互触发器时执行。

2. **无障碍焦点与 aria-hidden 拦截消除**：
   - 修复个人工作台新手引导弹窗（`#personal-agent-onboarding`）在点击“稍后设置”或关闭时，按钮仍持有键盘/屏幕阅读器焦点，导致浏览器抛出 `Blocked aria-hidden on an element because its descendant retained focus` 的缺陷。
   - 关闭弹窗时优先对活动焦点执行 `blur()` 清理，并通过 `inert` 属性阻断屏幕阅读器与 Tab 键对隐藏弹窗内部元素的遍历；打开弹窗时自动解除 `inert`。

3. **密码输入框与表单语义全量规范化（消除 7[DOM] 告警）**：
   - Chromium 要求所有 `<input type="password">` 必须位于语义完整的 `<form>` 容器中，且明确声明相关提交与自动填充属性。
   - 本次全量包裹与治理了 7 处散落在各弹窗中的密码与敏感凭据输入框：
     - 模型配置弹窗：接口密钥（`#m-key`）容器升级为 `<form class="model-form" onsubmit="return false;" autocomplete="off">`，补充 `name="model_key"` 与 `autocomplete="off"`；
     - 用户管理弹窗：初始密码（`#u-password`）容器升级为 `<form class="model-form" onsubmit="return false;" autocomplete="off">`，补充 `name="new_password"` 与 `autocomplete="new-password"`；
     - 检索模型服务统一配置弹窗：向量服务密钥（`#setting-rag-embedding-key`）与重排序服务密钥（`#setting-rag-rerank-key`）容器升级为 `<form class="model-form retrieval-model-config-form" onsubmit="return false;" autocomplete="off">`，补充 `autocomplete="off"`；
     - MCP 工具服务配置：外部工具密钥、数据库密码与 IM Token（`#mcp-edit-key`、`#mcp-edit-db-password`、`#mcp-edit-im-token`）升级为 `<form class="mcp-edit-form" onsubmit="return false;" autocomplete="off">`，补充 `autocomplete` 与 `name` 属性；
     - 账户安全与全局参数：修改密码表单与客户端通信密钥卡片升级为标准 `<form>` 容器，补充完整 `autocomplete` 与 `name`。

4. **认证登录与注册表单体验优化**：
   - 将 `#auth-submit` 提交按钮移入 `<form id="auth-form">` 容器内部，类型设为 `type="submit"`。
   - 规范输入框语义：用户名补充 `name="username"` 与 `autocomplete="username"`；确认密码补充 `name="confirm-password"` 与 `autocomplete="new-password"`。
   - 密码输入框依据当前登录/注册模式动态切换：登录模式为 `autocomplete="current-password"`，注册模式为 `autocomplete="new-password"`，彻底解决 Chrome 报出的建议增加 `autocomplete` 属性告警。
   - 优化表单提交逻辑：引入 `isAuthSubmitting` 防重提交锁，统一回车（Enter）与点击进入的提交管道，并将内联样式抽取至全局模态样式文件。

5. **检索模型服务独立弹窗与交互稳定性**：
   - “模型配置 → 检索模型服务”中的向量生成服务、重排序服务和检索策略拆为三个独立弹窗；每个弹窗只展示自身字段、测试按钮和保存动作，避免在同一弹窗内切换时产生理解或误操作成本。
   - 三种保存动作继续只提交对应配置字段：向量服务不会覆盖重排序/策略，重排序不会覆盖向量/策略，策略不会改变任何模型服务。
   - 服务状态卡使用稳定容器的事件委托处理动态按钮；模型列表或设置数据重新加载后，三个“配置”按钮仍会打开各自对应的弹窗。

6. **知识库跳转模型配置的加载状态修复**：
   - 知识库的“前往模型配置”直接以 `models` 为设置工作区初始分区打开，不再先进入默认分区后再发起第二次切换。
   - 取消中的全局设置读取会递增请求序列并立即清除加载状态，避免 `AbortError` 被正常忽略后，顶部“正在加载配置信息”长期残留。
