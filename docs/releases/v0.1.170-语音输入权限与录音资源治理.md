# v0.1.170 发布记录：语音输入权限与录音资源治理

发布日期：2026-09-24

## 发布摘要

本版本完善聊天语音输入的麦克风权限、故障反馈与资源生命周期。用户点击语音按钮时会立即发起音频输入授权；无权限、无设备、设备占用或浏览器能力不足时可获得可操作的提示。停止、失败和页面卸载不再遗留麦克风流或录音对象。

## 主要变更

### 1. 主动麦克风授权

- 语音按钮在用户点击上下文中调用 `navigator.mediaDevices.getUserMedia({ audio: true })`，主动申请麦克风权限。
- 授权等待期间按钮会显示录音状态；再次点击会取消本次请求。
- 用户在授权弹窗期间取消或离开页面后，即使浏览器随后返回 MediaStream，也会立即停止其全部音轨，避免资源滞留。

### 2. 错误反馈

- `not-allowed`、`NotAllowedError` 和同类权限拒绝错误统一显示为“请在系统或浏览器设置中允许本应用访问麦克风后重试”。
- `NotFoundError`、`OverconstrainedError` 等设备缺失错误提示用户连接或启用麦克风。
- `NotReadableError`、`TrackStartError`、`audio-capture` 等设备占用错误提示用户关闭占用麦克风的应用。
- 浏览器不具备 Web Speech 或 MediaDevices 能力时，直接提示使用支持麦克风访问和语音识别的浏览器。

### 3. 资源释放与桌面权限边界

- 语音会话使用统一清理入口：停止或失败时会解除 SpeechRecognition 回调、终止识别、停止全部 MediaStream 音轨、关闭关联的 MediaRecorder、清空录音分片缓存并恢复按钮状态。
- `pagehide` 与 `beforeunload` 会调用同一清理入口，覆盖页面/组件卸载场景。
- Electron 权限策略默认拒绝全部系统权限；仅当前受信任的 Pivot 渲染页可申请纯音频 `media` 权限。视频、音视频混合以及非受信来源均被拒绝。

## 兼容性与升级说明

- 无数据库迁移，无新增环境变量。
- 浏览器和桌面客户端首次请求麦克风时仍受系统级权限控制。用户需要在系统或浏览器/客户端设置中允许 Pivot 使用麦克风。
- 本次改动不会持久化、上传或复用原始录音数据；浏览器语音识别结束后即释放临时媒体资源。
