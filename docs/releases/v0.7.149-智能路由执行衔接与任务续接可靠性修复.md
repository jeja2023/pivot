# v0.7.149 智能路由执行衔接与任务续接可靠性修复

日期：2026-11-10（Asia/Shanghai）。本版修复普通聊天智能路由与持久任务、来源限制、任务续接及模型选择之间的五项衔接问题，并补齐知识范围变化后的历史证据与在途请求处理。

## 使用变化

- 上传长材料并要求“分析附件并导出 PDF”时，系统以有界目标建立持久任务，通过原始消息分页读取资料；读全前不执行业务工具。创建失败明确提示，不再把任务静默变为普通文本回答。结果以任务详情中的实际交付物为准。
- 已有任务运行期间，本轮即使只是短附件分析，“不要联网”“不要检索知识库”等限制也先传给当前任务。存在多项任务或限制未确认时，系统要求明确目标或重试。
- 续接任务时通过 `@` 改选知识库，并明确要求仅依据新专题继续，新的专题与标签会同步到运行；旧检索结果保留为历史记录，不再支撑本轮结论。已经撤销的来源能力不会由新选择恢复。
- “验证结果中”的任务同样接受聊天停止与暂停；等待审批或外部动作提交时继续显示真实原因，需要在任务详情处理。
- 使用自动模型策略时，当前熔断或拒绝新请求的端点不再因负载低而被选中。端点故障切换避开该端点的其它模型；固定模型保持用户选择，没有可用兼容候选时明确失败。

## 实现与兼容边界

### 长来源与控制指令

聊天入口移除以整条 `modelContent` 长度跳过任务的分支，任务交接分别校验目标和原始资料。目标沿用现有最多 12,000 字符校验；没有规范化目标的旧调用从用户指令提取，附件正文继续留在原始来源中。长来源绑定持久消息，业务工具前置校验和独立验收共同检查分页读取完整度，跨账号或撤回来源拒绝读取。

显式纠正及来源撤销先于短附件直答；附件中的引用和操作词不作为授权。活动任务及可暂停状态由现有运行时统一提供，聊天、续接和生命周期使用相同语义；暂停未确认、审批和提交边界不再被误报成已结束。

### 知识库续接与证据

续接专题、标签和清除选择复用现有权限及范围解析，与项目上限求交集，并通过 JSONB CAS 更新运行选择、能力范围、必要工具白名单和控制消息。清除不回退全库，旧来源撤销继续生效；较旧消息不能覆盖新修订。

检索及图谱结果绑定运行与资料范围修订。模型规划、压缩观察和独立验收对旧范围结果只保留失效说明，完整历史证据仍受当前账号、版本及引用权限检查。工作状态与检索上下文随范围变化更新，JSON 和原生流式规划丢弃迟到计划、答案和观察；恢复后也不重开旧范围。

本版使用已有任务元数据，没有新增数据库表或迁移。未带资料修订字段的旧任务继续使用原有检查；首次改选后按新修订管理。没有新增第三方依赖或必填配置，原审批、网络、预算及副作用限制继续生效。

### 模型端点选择

成本、容量、负载、视觉、质量和成本升级策略先过滤运行时已明确熔断或拒绝准入的端点；同名模型按模型标识或端点身份匹配，避免把其它端点的状态误用。故障切换传入实际错误，端点故障与结构化输出能力拒绝分别处理；后者仍可选择同端点的兼容模型。监测信息缺失时沿用既有准入与能力检查，不推定为健康证据。

1. 按既有流程备份数据库、上传资料、CAS 及配置，再更新主应用源码并重启服务；接口、任务执行进程和静态资源使用同一版本。浏览器刷新以获取新的版本标识。
2. 本版无需新增迁移、依赖或必填环境变量。保留现有原始消息、任务元数据、控制消息和证据文件，不能通过清理历史记录代替升级。
3. 沿用原有学习层 `shadow`、0% 灰度及人工评测门禁；这次修复不自动训练、审核、激活或放量学习制品。主模型语义判断与学习层是不同开关。
