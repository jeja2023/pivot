# Pivot v0.1.128 发布记录：工作流嵌入页面节点与结果呈现能力

## 版本概览

- **版本号**：v0.1.128
- **发布日期**：2026-09-10
- **核心定位**：补齐工作流编排中缺失的“嵌入页面”节点，让工作流可以把页面作为结果的一部分交付，并将画布、运行时、结果渲染和安全策略统一起来。

## 现象与根因

此前工作流画布包含浏览器自动化节点，但没有“嵌入页面”节点。浏览器自动化解决的是“访问或操作页面”，并不能把一个页面作为工作流结果直接展示；工作流输出也只有默认结果、表格和文件三种交付方式，因此用户无法在编排中表达“生成结果后展示一个页面”的需求。

## 核心变更

### 1. 新增嵌入页面节点

节点位于“呈现与交付”分组，名称为“嵌入页面”，工具标识为 `workflow.embed_page`，支持：

- 页面地址：同源路径或 HTTP/HTTPS 地址，可引用 `{{goal}}`、`{{inputs.*}}` 和 `{{nodes.*.output}}` 等工作流变量；
- 页面标题：用于结果区域标题和 iframe 无障碍标题；
- 嵌入高度：限制在 180～1200 像素，默认 480 像素；
- 页面节点可连接到“工作流输出”节点，作为最终结果的一部分交付。

### 2. 运行结果直接呈现页面

嵌入页面节点返回结构化结果：

```json
{
  "type": "embedded_page",
  "url": "/manual?embed=1",
  "title": "使用帮助",
  "height": 640,
  "text": "页面：使用帮助"
}
```

任务结果和执行步骤会将该结果渲染为页面卡片，提供：

- 受限 iframe 预览；
- “新窗口打开”备用入口；
- 页面标题、尺寸和原始结果的可追溯展示。

### 3. 安全边界

- 服务端只校验和返回页面地址，不请求、不抓取、不解析嵌入页面内容；
- 只允许同源绝对路径或 `http:` / `https:` 地址；
- 拒绝 `javascript:`、`data:`、`file:`、协议相对地址以及包含用户名/密码的 URL；
- iframe 使用 `sandbox`，不授予 `allow-same-origin`、顶层导航或脚本访问宿主页面的权限；
- CSP 增加 `frame-src 'self' http: https:`，页面仍可能因目标站点自身的 `X-Frame-Options` 或 CSP `frame-ancestors` 拒绝被嵌入，此时可使用“新窗口打开”。

- 回归覆盖：`tests/security-agent.test.js`、`tests/client-agent-chinese-ui.test.js`。

## 验证结果

- 工作流工具定义包含 `workflow.embed_page`；
- 合法同源路径可生成嵌入描述；
- `javascript:` 地址被拒绝；
- 页面结果包含 sandbox iframe 和“新窗口打开”入口；
- 中文工具标签包含“嵌入页面”；
- 聊天工作区 CSS 已重新构建。

## 升级说明

- 该能力属于服务端工具定义和前端页面资源变更，浏览器部署服务端后即可使用；
- 普通远程模式客户端不需要重新打包；
- 如需让桌面客户端获得同时存在的 Electron preload 修复，仍需单独发布对应桌面安装包；
- 目标页面必须允许被 iframe 加载，否则使用结果卡片中的“新窗口打开”。
