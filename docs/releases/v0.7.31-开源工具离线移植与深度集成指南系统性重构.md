## 1. 版本概述

在政企无外网/局域网私有化部署场景下，引入外部开源算法微服务与技能配方是扩展 Pivot 平台专业能力的重要途径。然而前期编写的《Pivot开源工具离线移植与深度集成全景指南.md》经专业审查（见 [审查报告](../reports/开源工具离线移植与深度集成指南审查报告_2026-10-22.md)），暴露出示例代码无法运行、协议握手与现有客户端流程冲突、文件多容器穿透漏洞、现有能力边界重叠与过度夸大自动集成等 13 项严峻问题。

v0.7.31 版本对照审查报告提出的 F01~F13 缺陷清单与建议顺序，对 [Pivot开源工具离线移植与深度集成全景指南](../design/Pivot开源工具离线移植与深度集成全景指南.md) 实施了**系统性重构、代码实测修正与生产级安全合规加固**，使该指南真正达到生产级落地实施的标准。

## 2. 核心改进与缺陷闭环

### 2.1 核心代码与协议对接层（P1 级致命错误清零）

1. **修正转换后的 Skill 清单（F01 & F10）**：
   - 彻底纠正未登记能力声明（`code_analysis`、`workspace_read`）以及混淆能力与工具名称的问题；
   - 规范声明已登记能力 `network.request` 与 `filesystem.read_workspace`，工具名称严格绑定平台已分配的数字服务 ID（`mcp.42.run_ast_audit`）与登记工具（`workspace.read`）；
   - 规范后的 `SKILL.md` 经平台核心门禁服务 `agent-skill-authoring.js::previewSkillSource` 实测验证，达到 `Valid: true`（0 错误）。
2. **修正 FastMCP Python 启动代码与接口参数（F02）**：
   - 遵循官方 MCP Python SDK v1.x 标准，将 `host="0.0.0.0"` 和 `port=8501` 正确配置于 `FastMCP(...)` 构造函数中，消除与 `mcp.run()` 的参数混淆。
3. **消除旧式 SSE 握手冲突，锁定现代 Streamable HTTP 协议（F03）**：
   - 针对 Pivot MCP 客户端默认向指定 URL 发起 JSON-RPC POST 的流程特性，将传输模式锁定为 `streamable-http`，端点路径统一为 `/mcp`，协议模式配置为 `standard`，与项目既有长连接与无状态测试完全兼容。
4. **剔除虚假 Mock 占位，实现真实 AST 语法树安全扫描器（F04）**：
   - 摒弃仅返回固定安全文字的假函数，采用 Python 内置 `ast` 模块实现完整的 AST 语法树遍历检测类，真实检测 `eval`、`exec`、`os.system`、`subprocess.Popen` 等高危代码注入与危险反序列化调用；
   - 经实测验证，可精准定位危险调用的行号、列号与风险等级。
5. **补全 Kroki 多容器伴随架构与适配器安全加固（F05）**：
   - 明确指出基础网关镜像 `yuzutech/kroki` 默认不包含 Mermaid 渲染组件，Compose 补齐了 `yuzutech/kroki-mermaid` 伴随容器并配置 `KROKI_MERMAID_HOST`；
   - 适配器代码显式设置 `responseType: 'text'`，正确读取 `response.data`，并传入调用者用户上下文 `context.user` 以满足严格出站安全策略检查。

### 2.2 架构隔离与现有能力边界厘清（P2 级架构偏差收敛）

1. **解决跨容器文件传递与暴露风险（F06）**：
   - 纠正了将 Pivot 宿主机相对路径字符串作为参数传递给未共享卷的外部容器的设计漏洞；
   - 方案采用源代码内容直传（`source_code`）或受控临时挂载卷，并在 Compose 中移除宿主机端口暴露，收敛至内网互联，杜绝绕过 Pivot RBAC 与审批审计的后门。
2. **规范 Compose 编排片段（F07）**：
   - 指南中全部 3 个 Compose 片段均补齐顶层 `networks.ai-bridge.external: true` 声明，确保独立验证与叠加运行语法均 100% 正确。
3. **精准划定“四大短板”的增量补强目标（F08 & F12）**：
   - 重新梳理 Pivot 现有成熟底座：澄清系统已具备 Vosk STT、受控 TTS Provider、客户端 `speechSynthesis` 朗读打断、公文段落对照、PDF 逐页像素差分与 `knowledge-sources.js` 哈希增量同步调度能力；
   - 将补强方向精准重写为增量目标：统一部署纯 CPU 离线 TTS 引擎容器、高精字符级与 Word 修订（Track Changes）比对、Mermaid/PlantUML 确定性矢量转图、复杂动态 OA 抓取清洗连接器；
   - 全面核查候选工具的许可证边界（Piper 维护版的 GPL-3.0、Firecrawl 的 AGPL-3.0 传染性边界）与离线硬件基准评测要求。
4. **打通 MCP 工具调用到 CAS 产物与 UI 交互卡片的 5 步交付闭环（F09）**：
   - 破除“外部工具返回 JSON 即可自动变成 ECharts 或 CAS 产物”的错误假定，详尽梳理并制定了规范化适配管线：
     `工具原始数据返回` $\rightarrow$ `适配层解析与规范化` $\rightarrow$ `创建基础产物记录 (agent-artifacts)` $\rightarrow$ `组装 Document IR 结构 (document-ir)` $\rightarrow$ `生成不可变 Rendition 制品 (createRendition)` $\rightarrow$ `前端签发安全下载凭证`。

### 2.3 生产交付规范与链接维护（P2/P3 级工程落地闭环）

1. **规范技能包（ZIP）离线打包与发布全流程（F10）**：
   - 明确单技能 ZIP 包根目录必须直接包含清单文件（`SKILL.md`/`SKILL.yaml`），阐明解包大小、符号链接阻断与脚本供应链安全扫描规则；
   - 明确个人发布与组织共享的签名及审批权限差异。
2. **确立纯离线局域网 9 步生产 SOP（F11）**：
   - 建立涵盖版本 Tag 锁死、BOM 清单与 SHA-256 校验和、CPU 架构与 Linux wheel 区分、目录权限预设、`--no-build --pull never` 离线启动、断网冷启动零出站验证（Zero-Egress Check）、全链审计核查及同时间戳原子容灾回滚的完整规程。
3. **修复死链并迁移为仓库相对链接（F13）**：
   - 彻底清除全篇 28 处绝对 `file:///e:/pivot` 路径，替换为标准仓库相对链接；
   - 修复失效的 `document-rendering.js` 引用，更新至现行目录入口 `server/services/document-rendering/index.js`。
