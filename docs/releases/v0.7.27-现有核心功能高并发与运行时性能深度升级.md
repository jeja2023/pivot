# v0.7.27 现有核心功能高并发与运行时性能深度升级

日期：2026-10-22。

### 1. 支柱一：事件循环主线程同步 I/O 阻塞彻底消除

- **第三方库哈希与 PWA 模板内存单例缓存**：
  - 在 `server/app.js` 中引入 `cachedVendorRevision` 与 `cachedRenderedServiceWorker` 内存单例缓存；
  - 首次计算后，直接复用第三方库静态目录哈希与 Service Worker 注入模板；
  - 彻底消除了客户端高频访问 `/sw.js` 与前端轮询 `/version.json` 时，在 Node.js 主线程重复递归遍历并同步读取第三方静态大文件（包括 1.1MB 的 ECharts 与 277KB 的 KaTeX 等）造成的事件循环卡顿，确保高并发或多标签页场景下 LLM 对话 SSE 流式输出平滑无抖动。

---

### 2. 支柱二：数据库连接池与语句超时基线标准对齐

- **连接池默认上限与语句超时兜底优化**：
  - 对齐 `server/db/pg-connection.js` 在缺少显式环境变量时的默认值与 `server/config/env-registry.js` 统一配置注册表；
  - `PG_POOL_MAX` 兜底默认值由 `10` 提升至标准的 `30`，杜绝系统内置的 25+ 个后台 Worker/Runner（知识库解析、向量修复、Wiki 编译、数据分析刷新等）突发并发时耗尽连接池，导致普通用户 HTTP 请求排队超时报 500 错误的问题；
  - `PG_STATEMENT_TIMEOUT_MS` 单条 SQL 兜底执行超时从 `60000` 毫秒（60s）下调对齐至标准的 `20000` 毫秒（20s），快速熔断慢查询，保护数据库连接迅速归还可用。

---

### 3. 支柱三：智能体队列任务认领升级为 PostgreSQL 原子行锁调度

- **消除多实例/多 Worker 并发认领行锁竞争**：
  - 重构 `server/services/agent-queue.js` 的 `claimNextRun` 任务认领逻辑，将两阶段 `SELECT ... LIMIT 50` 循环更新升级为原生 `WITH ... FOR UPDATE SKIP LOCKED` 原子 CTE 模式；
  - 多进程或集群多实例 Worker 并发调度认领时，PostgreSQL 自动跳过已被其他实例锁定的候选任务，从根本上消除了并发抢占时的行级锁等待、锁冲突（Lock Contention）与空轮询损耗；
  - 单次任务认领的数据库往返由 2 次网络请求收敛至 1 次原子执行，并原子维护用户级并发上限过滤。

---

### 4. 支柱四：实时事件（SSE）连接容量校验与监控算法复杂度降至 O(1)

- **常数级时间复杂度的实时连接状态维护**：
  - 在 `server/services/realtime-events.js` 中引入原子连接计数器 `totalConnectedClients`，利用 `set.delete(client)` 返回值严格保证连接增加与断开时原子同步更新；
  - 客户端握手上限判定（429 检查）以及 `getRealtimeStats` 监控接口从遍历所有在线用户的 $O(N)$ 循环彻底优化为 $O(1)$ 常数时间复杂度，降低大型团队并发重连时的 CPU 损耗。
