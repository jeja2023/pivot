# v0.1.197 Qwen3.8 系统消息顺序修复

发布日期：2026-09-30

发布范围：Qwen3.8-27B 及同类严格聊天模板的模型调用兼容性。

---

## 修复内容

Qwen3.8 的官方聊天模板要求：请求中只能有一条 `system` 消息，并且它必须位于消息列表首位。Pivot 的知识检索、工具上下文及后台任务可能各自追加 system 指令；部分模型会宽容处理，而 Qwen3.8 会返回 HTTP 400：`System message must be at the beginning.`。

本版本在聊天流式主链路和公共非流式模型调用层完成以下修复：

- 在上下文预算与 Qwen `/no_think` 控制文本注入之前，收集全部 system 指令并合并为唯一首条 system 消息；
- 保持所有 user、assistant 与工具消息的原有相对顺序；
- 合并后的 system 指令纳入上下文预算，避免被误当作普通历史消息删除；
- 仅当模型名称匹配 Qwen3.8 时，当前模型对话、最终 Chat Completions 转发，以及复用 `callModelTextWithBudget` 的后台能力（包括知识库综合页编译和评测）才启用该兼容性修复。

该处理不修改用户消息、工具结果或模型输出，也不放宽任何权限、来源或模型访问校验。Qwen3.6、其他 Qwen、OpenAI 与第三方模型保留既有多段 system 消息顺序，避免改变其可能依赖的分段语义。

## 验证

- 新增回归用例，验证任意位置、任意数量的 system 指令会合并为唯一首条，且 Qwen `/no_think` 仅附加到最后一条 user 消息；
- 知识库综合页、中文输出兼容、来源校验、自动编译身份及路由定向回归通过；
- 开发规范、raw SQL、安全 HTML、迁移与架构门禁通过。

参考：Qwen3.8 官方 chat template 对非首位 system 消息会抛出 `System message must be at the beginning.`，因此该修复属于上游模板兼容而非模型能力或凭据问题。
