# v0.7.29 工作流草稿协作加固与智能体诊断优化

**发布版本**：v0.7.29  
**发布日期**：2026-10-22  
**发布类型**：质量提升 / 架构稳定性 / 体验加固  

---

## 概述

v0.7.29 重点对组织协同中的 **工作流产品化画布**、**草稿协同与冲突恢复**、**智能体任务执行详情诊断**、**语音识别网络安全上下文** 以及 **PDF 运行时工具链** 进行了系统性的质量提升与端到端自动化测试覆盖。

本次升级彻底解决了此前复杂场景下工作流草稿因异步渲染事件误判导致恢复提示跳过、双窗口修订冲突覆盖本地编辑、技术诊断面板重复渲染 DOM 元素等关键缺陷，保证端到端回归测试 100% 通过，并为无互联网隔离环境和企业级网关接入提供了权威的技术配置指南。

---

## 核心变更详情

### 1. 工作流产品化画布草稿协作与恢复机制深度加固

- **程序化 spec 写入事件精细化隔离**：
  - 解决草稿离线编辑恢复与双窗口修订冲突时恢复面板被跳过的问题：在 `client/chat/dag-core.js`（`writeJson`）与 `client/chat/agent-workflow-core.js`（`writeAgentWorkflowText`）中为程序化 spec 注入派发带有 `{ programmatic: true }` 的自定义事件；
  - 在 `client/chat/workflow-product-workspace.js` 中精确忽略程序化事件，严格区分用户主动输入与底层框架渲染，避免异步宏任务或渲染帧将刚载入的原样草稿误判为 `dirty`，确保恢复提示 100% 弹出。
- **草稿打开状态机（`isOpeningDraft`）重构**：
  - 优化 `workflowExperience.opened()` 状态机调度，增加打开草稿专用状态保护，避免打开已有本地或远端草稿时被默认新建流程逻辑赋予随机 UUID 草稿标识并触发竞态空载，杜绝恢复提示面板被误隐藏。
- **客户端本地存储健壮性升级**：
  - 增强客户端本地草稿存储与读取回退机制（`getStoredDraft` / `listLocal`），在用户身份初次异步获取（`/api/auth/me`）的短暂延迟期间支持前缀扫描，确保断网或离线暂存草稿在页面刷新后能被立刻感知与恢复。
- **单步测试与发布运行视图联动**：
  - 优化单步调试（Debug）结果历史选项排序，优先展示实际步骤结果；就地测试与发布运行支持输出联动渲染，规范纯表格交付结果展示。
- **窄屏与深色主题交互修复**：
  - 管理菜单折叠时强制隐藏浮层 DOM 矩形，解决窄屏下管理选项误拦截用户点击的问题；
  - 修正结果面板与顶部操作工具栏的定位层级，避免遮挡顶部“运行”等核心按钮交互；
  - 补齐深色主题下输入面板等元素的背景样式。

### 2. 智能体执行详情与技术诊断面板渲染去重

- **DOM 节点唯一性保障**：
  - 在 `client/chat/agent-run-diagnostics.js` 中重构技术诊断渲染逻辑，消除 `renderAgentRunTechnicalDiagnostics` 对 `legacyHarnessMarkup` 与 `traceMarkup` 的重复拼接；
  - 确保 `#agent-run-detail .agent-run-harness-diagnostics` 与 `details.agent-trace-panel` 元素在 DOM 树中全局唯一，彻底修复 smoke e2e 测试与复杂生产排错场景下的节点选择器冲突与冗余渲染。

### 3. 语音识别安全上下文与网关接入最佳实践

- **严格遵循 W3C Secure Contexts 规范**：
  - 明确统一语音识别麦克风采集（Web Audio API / MediaRecorder）强制需要 HTTPS 或受信任本地回环地址（`localhost` / `127.0.0.1`）；
  - 补充并规范了网关反向代理（如 Nginx、Traefik、APISIX）下启用 SSL/TLS 证书终止与 WebSocket 协议头传递的标准配置，以及内网开发测试场景下的浏览器安全白名单配置指引。

### 4. PDF 工具链运行时与容器化选型明确

- **内置工具链与运行时契约保障**：
  - 官方生产 Docker 镜像在构建阶段（`Dockerfile`）已默认内置 `qpdf`、`chromium`、`default-jre-headless` 与 `veraPDF`，并通过 Compose 环境变量自动绑定 `/usr/bin/qpdf`，澄清了容器化环境无需再次手动 apt 安装的机制；
  - 确认了主镜像与解耦后的独立语音服务均基于 Debian `slim`（`node:22-bookworm-slim` 与 `python:3.12-slim-bookworm`）构建，在保证 libc 兼容性与原生 C++ 模块稳定的同时实现轻量化生产部署。
