# v0.1.111 发布记录：生产工作流中文搜索 SQL 热修复

发布日期：2026-09-09

## 生产故障

生产 v0.1.97 调用以下接口时返回 PostgreSQL 语法错误：

```text
GET /api/agents/workflows?limit=100&query=检查客户端更新
syntax error at or near ")"
```

调用链为路由 `agents.js` → 服务 `listAgentWorkflows` → 仓储 `listWorkflowsForUser`。

## 根因

仓储为了把 `%`、`_` 当成普通字符，动态生成了带反斜杠的 `LIKE ... ESCAPE` 片段。反斜杠先经过 JavaScript 模板字符串，再由 PostgreSQL 解析，实际发送的 SQL 丢失了合法的转义字符，最终在搜索条件右括号处报语法错误。没有 `query` 参数时不会拼接该条件，因此普通列表可能仍能使用。

## 修复

- 名称与简介使用参数化 `STRPOS(LOWER(column), LOWER(?)) > 0`；
- 当前版本与发布版本使用参数化 `STRPOS(CAST(version AS TEXT), ?) > 0`；
- 查询值始终作为数据库参数发送，不进入 SQL 文本；
- `%`、`_` 和反斜杠均按字面量处理，无需手动构造 `ESCAPE` 子句。

## 验证

- 在本机 PostgreSQL 上使用生产查询“检查客户端更新”复现原错误；
- 应用修复后，同一查询正常返回结果数组；
- 隔离 PostgreSQL schema 行为测试创建测试工作流，并验证中文与 `_%_` 搜索；
- 全库扫描确认没有其它 SQL `ESCAPE` 动态拼接；
- `npm run check`、`npm run lint` 和专项回归测试通过。

## 生产升级

该热修复不新增表、字段、索引或配置项，无需单独执行数据库迁移。发布 v0.1.111 服务端镜像后滚动重启实例，并复测上述接口即可。不要只在运行中的容器内临时修改文件，因为容器重建后会丢失修改。
