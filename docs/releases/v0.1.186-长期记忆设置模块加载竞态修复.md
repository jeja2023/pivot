# v0.1.186 长期记忆设置模块加载竞态修复

发布日期：2026-09-27

发布范围：设置工作区的长期记忆列表、使用记录弹窗与按需加载的设置脚本。

## 问题与影响

长期记忆的列表操作事件由 `admin-settings.js` 注册，而具体的长期记忆 API 由随后按需加载的 `admin-settings-memory.js` 提供。原实现会在事件注册时立即读取并缓存 `settings.memory`。

首次打开设置页时，如果内存模块尚未执行完成，缓存值为空对象；即使后续模块已加载完成，点击“使用记录”仍会调用旧对象并报错：

```text
memory.openMemoryUsageModal is not a function
```

同一时序也可能影响编辑、批量状态更新、任务维护、评测和合并等长期记忆操作。

## 修复内容

- 移除设置事件注册时对 `settings.memory` API 的一次性缓存。
- 新增统一的动态调用入口，在每次用户触发长期记忆操作时通过 `window.Pivot.getModule('settings.memory')` 获取最新模块实例。
- “使用记录”会调用已加载模块的 `openMemoryUsageModal(memoryId)`，正常请求 `/api/memories/:id/usage` 并展示实际使用事件。
- 编辑、来源、禁用/恢复/删除、批量操作、任务维护、评测、保存和合并同步采用动态模块解析，避免首进设置页的脚本加载顺序影响操作可用性。
- 模块确实尚未就绪时返回中文加载提示，不再向用户展示 JavaScript 方法缺失错误。

## 升级方式

1. 部署 `v0.1.186` 服务端与前端静态资源。
2. 重启服务，使页面注入新的应用版本标签。
3. 用户刷新浏览器页面或重新打开客户端，再进入“设置 → 长期记忆”。

无数据库迁移、无新增环境变量，也不会改写长期记忆数据或使用记录。

## 发布边界

- 本版本修复的是客户端设置脚本加载时序，不改变 `/api/memories/:id/usage` 的权限校验、事件数据或长期记忆检索策略。
- 若浏览器仍显示旧错误，应确认前端资源已部署，并使用强制刷新清除旧的应用脚本缓存。
