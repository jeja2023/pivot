# Pivot v0.1.58 发布记录

**发布日期**：2026-08-27

---

## 概述

Pivot v0.1.58 聚焦于**长期记忆表格操作紧凑化与弹窗规范化、Agent 控制台全子视图分页与统一收件箱详情自动已读、控制台跨视图查看任务详情无缝返回、以及知识图谱文档范围与全局图谱严格隔离**。本次更新解决了知识库文档行打开图谱混入全局数据、控制台长列表缺少分页、从收件箱查看任务详情返回时跳回主任务列表等交互断层，进一步提升系统的严谨性与用户操作体验。

---

## 主要更新内容

### 1. 长期记忆表格与来源操作交互优化

- **表格列布局精简**：
  - 移除了长期记忆表格中独立的「来源」数据列，将「来源」操作按钮整合移入最后一列「操作」列中（与「编辑」、「合并」、「删除」并列），提升表格横向空间利用率与信息排版规整度。
- **来源弹窗关闭操作靠右规范化**：
  - 调整记忆来源追溯弹窗的关闭按钮为右对齐排布（`.modal-footer { justify-content: flex-end; }`），与系统全局弹窗视觉规范保持统一。

### 2. Agent 控制台全模块分页与统一收件箱详情自动已读

- **全量 8 大子视图分页支持**：
  - 为 Agent 控制台中的 **统一收件箱**、**持续目标**、**审批与通知记录**、**评测集列表**、**工具调用样本**、**自进化提案**、**常驻实例运维** 和 **技能资源包** 8 个子视图全部接入统一的标准分页控制器与翻页切换逻辑。
  - 分页栏布局紧凑（`margin-top: 10px; padding: 6px 10px;`），居中对齐，支持上一页、下一页、总条数与页码实时同步。
- **统一收件箱查看详情自动标记已读**：
  - 用户在统一收件箱待办列表中点击「详情」按钮查看任务后，系统自动调用已读标记逻辑将该待办标为已读，并实时同步更新未读徽章红点与数量。

### 3. Agent 控制台任务详情跨视图返回路径精准还原

- **返回导航上下文（Return Context）**：
  - 修复了在统一收件箱或评测中心点击任务运行记录的「详情」后，点击顶部返回面包屑或“返回列表”按钮会误跳回“任务列表（Runs）”的问题。
  - 在 `openAgentRun` 跨视图跳转时携带源页面上下文（例如 `{ returnTab: 'workbench', returnSubview: 'inbox', returnLabel: '统一收件箱' }`），面包屑动态显示「统一收件箱 / 任务详情」，点击返回时精准返回原选项卡及子视图。

### 4. 知识图谱文档作用域与全局图谱严格隔离

- **前端双入口区分与标题上下文**：
  - **顶部菜单入口**：保持展示全局全量知识图谱，展示全部知识库实体与关系。
  - **知识库列表行操作列「图谱」按钮**：携带对应文档 `docId` 打开专属图谱弹窗，标题动态渲染为 `知识图谱 · 文档名称`，附带当前文档范围描述与专属的「重建本文档图谱」按钮。
- **全链路后端接口文档作用域贯穿**：
  - 图谱概览 (`/summary`)、实体列表 (`/entities`)、关系列表 (`/relations`)、实体关系地图 (`/entities/:id`)、实体校准、图谱问答 (`/query`) 和文档重建 (`/docs/:id/rebuild`) 统一接收并处理 `docId`。
  - 后端在数据库层面严格基于文档归属（`knowledge_entity_mentions` 与 `source_doc_id`）过滤数据，确保文档作用域下的实体提及数（`mention_count`）与直接关系数（`relation_count`）仅统计当前文档内部数据，彻底杜绝节点与关系跨文档串扰。
- **实体与关系校准闭环联动刷新**：
  - 实体校准保存、实体合并、关系编辑、关系确认与关系删除完成后，自动联动刷新图谱概览指标、实体列表与选中的实体关系地图，确保数据变更即时响应。
