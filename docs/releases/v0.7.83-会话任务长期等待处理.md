# v0.7.83 会话任务长期等待处理

日期：2026-11-01。本版本记录工作区修改；版本号更新不代表服务器或安装包已经更新。

## 行为变化

普通会话中的任务处于“等待补充信息”并超过期限没有更新时，后台恢复巡检结束本次等待。默认期限为 7 天，以任务最后更新时间计算。已有最终答复的任务转为“部分完成”，答复保留；没有答复的任务转为未完成状态。原有等待原因保存在任务元数据中。任务卡不再显示“停止任务”，终态提供“续跑任务”入口；续跑仍受已有权限和预算约束。

规则只处理带会话关联、非计划任务的 `needs_input` 运行。用户主动暂停的任务，以及等待审批、等待提交、存在外部副作用、未完成非幂等检查点或待处理控制消息的任务不会由该规则自动结束。巡检每批最多处理 100 条，并通过数据库条件更新和行锁避免并发巡检重复处理；这些排除条件可能使部分历史任务继续等待人工处理。

管理员可在主程序环境中设置 `AGENT_CHAT_INPUT_IDLE_DAYS`：默认 `7`，`0` 表示关闭自动结束；无效值回退默认值，最大按 365 天处理。配置及主程序更新后，符合条件的历史任务将在后台巡检中逐批处理。
