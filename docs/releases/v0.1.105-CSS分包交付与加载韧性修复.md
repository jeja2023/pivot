# v0.1.105 发布记录：CSS 分包交付与加载韧性修复

发布日期：2026-09-09

## 根因

上一轮 CSS 分包将新生成的样式文件留在工作区，但开发启动、Docker 最终镜像与桌面打包未统一执行构建。新部署、干净检出或新安装包可能缺少 `chat.shell.css` 或工作区样式包，表现为页面没有样式；样式链接的等待又可能让工作区初始化停在半途中。

## 修复

- `npm start`、`npm run dev` 与 `npm run check` 在执行前自动生成全部聊天样式包。
- Docker 最终运行镜像显式复制 CSS 构建器并在镜像构建期生成产物。
- `.dockerignore` 显式保留运行时需要的 `docs/licenses`，避免 Dockerfile 复制许可证资料时中断镜像构建。
- 桌面开发启动和 Electron 打包在启动/组装 asar 前生成样式包。
- 工作区通用布局、表格和响应式样式纳入 `chat.shell.css`，静态页面和动态页面均有基础外观。
- 对话页底部模型统计（模型、耗时、Token、速度）迁移到首屏消息样式，避免依赖设置工作区专属 CSS。
- 会话列表明确保持独立滚动高度，并提供可见的“加载更多会话”按钮；滚轮、触控板或隐藏滚动条异常时仍可继续加载下一页。
- 会话列表恢复纯滚动连续加载，移除额外分页按钮；滚动到底部自动追加下一页，保持侧栏内容连续。
- 应用、Agent、知识库、工具库和设置的业务样式仍在首次打开时按需加载；加载失败只记录告警，不会阻断模板和点击事件。

## 验证

- 静态资源检查验证所有生成样式包存在且与入口源码一致；
- Docker 与桌面构建契约测试验证构建前必定生成 CSS；
- 浏览器 E2E 验证知识库业务样式加载失败时，页面仍可挂载且关闭按钮的真实点击命中正常；
- `npm run check`、`npm run lint` 通过。
