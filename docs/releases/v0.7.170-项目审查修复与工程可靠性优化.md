# v0.7.170 项目审查修复与工程可靠性优化

日期：2026-11-17。本版启用源码版本 v0.7.170，包含 [v0.7.169 任务与工作流修复](v0.7.169-任务详情与工作流编排体验修复.md)和此前未部署的 v0.7.168 PPT 与技能治理修复。本次未构建、签名或部署 v0.7.170 发布制品。

## 数据、安全与额度

- 自定义上传目录正确识别数据库逻辑文件引用；查询失败时停止清理，继续核对文件身份与目录边界。管理员删除、停用用户及重置密码使用同一事务；登录锁内复核密码、版本和用户状态，防止旧密码越过并发重置。
- 模型日消费保存在持久账本，删除消息、会话及历史文件不返还已登记额度；普通流式聊天复用额度预留。审计及模型用量先加密保留待写记录，数据库恢复后幂等重放。审计未确认时响应提示复核，已提交业务与文件写入不构成跨存储原子事务。
- 认证写入校验来源；同源多标签页协调刷新、登录和退出，内网 HTTP 使用 IndexedDB 回退。附件、PDF、OCR 和 PPT 受控素材禁止缓存；点目录文件仅在归属及路径校验后交付。旧缓存和已下载文件不能由服务端追回。
- 导图协作状态加载期间先禁用编辑，加载后按当前角色恢复操作，避免查看者短暂出现可用编辑入口或协作未就绪时写入。

## 工程与性能

- 知识治理、Wiki 和项目空间脚本按需加载，支持失败重试和账号切换隔离。首屏脚本静态原始体积由 1,196,488 字节降至 1,043,503 字节，约 12.8%；这不是实际页面耗时或生产收益承诺。
- 日消费按账号、模型和北京时间日期查询账本；每日重型维护顺序执行，停机总时限覆盖后台任务、写入和数据库连接池。Compose 停止宽限为 20 秒，主服务总预算为 15 秒。
- 增加事务 executor 架构门禁及关键模块类型检查；测试隔离覆盖业务文件目录与备份 schema。Node.js 支持 `>=20.19.0 <21 || >=22.23.4 <23 || >=24.0.0 <25`，标准容器仍使用 Node 22.23.4；目标版本仍须独立验收。

## 升级与恢复

从 v0.7.169 升级需要执行 PostgreSQL 迁移 `202611170002_model_consumption_ledger`。迁移回填现存消息和模型用量、建立幂等标识及触发器，并对消息和用量表取得写入相关锁。上线前安排维护窗口，准备数据库、受控文件、`DATA_DIR/critical-write-journal` 及原数据加密密钥的完整备份，并在目标环境验证恢复。首次回填包含仍在数据库的软删除消息，已物理删除或从未保存的历史消费无法补造；账本不能为回退版本而直接清空。新旧源码并行运行不在支持范围内。

完整离线备份清单升至 v3，纳入关键待写目录，并继续支持校验旧 v1/v2 清单；旧备份缺失的文件不会自动补齐。单独 `pg_dump` 不代表文件和待写记录已完整备份。其他编排方式应为停机保留与 Compose 相当的宽限时间。

本轮没有新增第三方依赖或桌面 IPC。若从 v0.7.167 或更早版本升级，文件分页和文字校准还需按 [v0.7.168 升级说明](v0.7.168-PPT制作恢复与技能治理修复.md)更新独立 PPT Master 服务，并处理在途任务、保留数据库、CAS、技能目录与 PPT 工作区。现有独立助手开发验证包保留原 v0.7.164 制品身份。
