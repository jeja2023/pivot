# v0.1.82 发布记录：Agent 运行时架构分层治理与统一上下文审计契约升级

发布日期：2026-09-05

## 一、更新背景

随着智枢系统的业务能力与 Agent 执行场景不断扩展，系统底层代码规模与跨端协同呈现出新的架构治理与可靠性挑战：

1. **核心服务端超大巨石模块治理红线**：`server/services/agent-runtime/index.js`（原 2200+ 行）和 `server/routes/mcp/index.js`（原 1400+ 行）随着多次迭代，状态机、任务调度、生命周期钩子、路由解析等不同维度的逻辑高度交织，单文件体量超出工程治理红线（$\le 1000$ 行），维护与单测隔离成本急剧上升；
2. **意图决策与算法逻辑与业务服务耦合**：对话 MCP 上下文中的意图分析规则与备选 Fallback 逻辑，以及知识图谱中的实体提取与模式匹配正则，混杂在业务装配与数据库持久化逻辑中，缺乏纯函数式解耦与独立验证路径；
3. **跨端 Agent 执行上下文审计标准不统一**：系统具备 Web 对话（Chat）、Agent 独立工作台（Agent）与桌面本地执行器（Desktop）三种入口。各入口在记录底层工具调用审计时，字段定义与上下文结构不尽一致，未建立全局版本化、强一致的审计契约；
4. **流式高频数据刷新与审计落库失衡**：大模型流式输出过程中，过于频繁的增量事件会加剧前端渲染与数据库写操作，而若缺乏针对终态（`finishReason`）的保全机制，又极易在流结束时丢失完整执行审计；
5. **前端静态资产标签平衡性缺乏 AST 级静态防线**：前端存在多处纯 HTML 片段与 JS 模板字符串（`TemplateLiteral`）。若发生标签拼写未闭合或多闭合，浏览器会产生隐式容错与 DOM 结构畸变，普通文本正则难以可靠探测嵌套结构；
6. **异步与数据库未等待（unawaited）调用治理需要阻断机制**：既有的未等待异步调用检查脚本处于“仅报告”模式，缺乏在流水线中硬性阻断新增违规调用的能力。

本版本针对上述架构治理、审计契约、采样优化与质量防线进行了系统性重构与全面加固。

## 二、核心变更与技术实现

### 1. Agent 核心运行时架构深度解耦与分层治理
- **巨石文件拆解**：彻底解耦 `server/services/agent-runtime/index.js`，将原本 2200+ 行的大型文件拆分重组为分工明确的三个子模块，主入口代码压缩至约 790 行，完全满足架构治理要求：
  - [`server/services/agent-runtime/run-state.js`](../../server/services/agent-runtime/run-state.js)：专注于 Agent 执行状态机装配、持久化状态快照读取与回写、多轮对话上下文同步；
  - [`server/services/agent-runtime/run-lifecycle.js`](../../server/services/agent-runtime/run-lifecycle.js)：专注于 Run 生命周期事件派发、超时看门狗处理、取消/终止流程、子任务资源释放与完成态落盘；
  - [`server/services/agent-runtime/run-execution.js`](../../server/services/agent-runtime/run-execution.js)：专注于单步规划推理、模型路由自适应升级、工具执行编排与异常诊断自愈。

### 2. MCP 工具库路由模块化拆分与治理
- **路由分层解耦**：重构 `server/routes/mcp/index.js`（原 1400+ 行，重构后约 680 行），将复杂的外部服务交互与诊断接口抽离为两个高内聚子模块：
  - [`server/routes/mcp/configuration-routes.js`](../../server/routes/mcp/configuration-routes.js)：管理外部 MCP 服务注册、健康检查、数据库连接串校验、敏感密钥加解密与测试连通性诊断；
  - [`server/routes/mcp/management-routes.js`](../../server/routes/mcp/management-routes.js)：管理报表目录读取诊断、IM 消息测试投递、工具启用禁用与缓存刷新逻辑。

### 3. 对话 MCP 意图分析与知识图谱抽取引擎解耦
- **MCP 意图规则抽离**：在 [`server/services/chat-mcp-intent.js`](../../server/services/chat-mcp-intent.js) 中通过 `createMcpIntentHelpers` 集中维护数据表、集合、报表目录与浏览器意图规则与 Fallback 策略，使 [`chat-mcp-context.js`](../../server/services/chat-mcp-context.js) 专注于上下文拼装；
- **知识图谱抽取算法独立**：抽离 [`server/services/knowledge-graph-extraction.js`](../../server/services/knowledge-graph-extraction.js)，以纯函数形式承载实体归一化清洗、实体类型推断、多模式关系匹配与别名解析算法，将算法计算彻底与 [`knowledge-graph.js`](../../server/services/knowledge-graph.js) 中的数据库 SQL 读写解耦。

### 4. Agent StepContext 统一审计契约与全端对齐
- **数据库契约升级**：新增数据库迁移 [`server/db/migrations/agent-context-audit-contract.js`](../../server/db/migrations/agent-context-audit-contract.js)（`202609050003_agent_context_audit_contract`），在 `agent_tool_calls` 表增加 `context_snapshot`（JSONB）字段与 `contextHash` 专用索引；
- **标准化快照协议**：在 [`server/services/agent-step-context.js`](../../server/services/agent-step-context.js) 中建立 `AGENT_STEP_CONTEXT_SCHEMA_VERSION = 1` 统一标准，提供 `serializeAgentStepContext` 与 `buildAgentAuditFields`；
- **全端审计对齐**：全面贯通 Chat 对话流、Agent 工作台调度流与 Desktop 桌面本地执行器（[`desktop/agent-runtime/runtime.js`](../../desktop/agent-runtime/runtime.js)），三端在调用工具与记录审计日志时，均统一固化入库不可篡改的标准上下文快照（含 `entrypoint`、`worldStateHash`、`contextWindow`、`policy`、`approval` 与 `sandbox` 状态）。

### 5. Agent 流式输出双轨采样器与完成态快照保全
- **采样双轨解耦**：在 [`server/services/agent-streaming-runtime.js`](../../server/services/agent-streaming-runtime.js) 封装 `createStreamingSnapshotSampler`，对高频 SSE 增量实施双轨控制：
  - **UI 渲染轨**：通过 100ms 时间窗与 120 字符增量阈值进行节流合并，保障前端流畅交互；
  - **审计记录轨**：按独立采样步长归集增量事件，杜绝高频写库；
  - **完成态绝对保全**：当模型流结束（携带 `finishReason` 或显式标记 `completed`）时，采样器强制保留最终完整快照入库，杜绝流式终态丢失。

### 6. 前端 HTML 资产标签平衡性 AST 严格校验
- **Parse5 与 Acorn 深度检查**：升级 [`scripts/check_chat_assets.js`](../../scripts/check_chat_assets.js)，结合 `parse5` 对组装完成的聊天模板 HTML 进行严格的标签栈匹配校验，且基于 `acorn` 语法树自动遍历所有前端 JS 代码中的 `TemplateLiteral` 模板字符串；
- **排查标签配对缺陷**：对带有 HTML 标签的模板字符串进行闭合标签与合法 Void 标签（如 `<br>`, `<input>`, `<img>` 等）的对称性校验，彻底杜绝未配对标签、非法自闭合或多余闭合标签穿透至浏览器。

### 7. 异步与数据库调用门禁强制模式升级
- **强制阻断模式**：升级 [`scripts/check_async_db_calls.js`](../../scripts/check_async_db_calls.js)，新增 `--enforce` 阻断参数与 `--json` 报告导出；
- **白名单机制落地**：引入 [`scripts/async-db-calls-allowlist.js`](../../scripts/async-db-calls-allowlist.js) 与 [`scripts/async_db_calls_allowlist.json`](../../scripts/async_db_calls_allowlist.json)，基线固化既有安全遗留调用；任何新引入的未等待 Promise 或未捕获异步 DB 调用将直接导致 CI / 预检门禁失败退出。
