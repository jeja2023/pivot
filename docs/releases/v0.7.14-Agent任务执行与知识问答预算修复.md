# v0.7.14 Agent 任务执行与知识问答预算修复

日期：2026-10-20。升级基线：v0.7.13。

本版本处理知识库答案已经生成，任务却持续显示“正在规划”，多次出现相同任务卡片，以及点击继续提示父任务没有剩余 Token 预算的问题，并补齐任务恢复、暂停、验收、重试与用量记账的边界处理。

## 任务卡片与状态

等待补充的聊天任务继续执行时复用原运行与累计额度；旧版本已有的父子续跑链只展示最新任务，点击旧卡片的继续按钮会定位到已有续跑任务。前端恢复同时检查运行 ID、会话选择序号和轮询实例，重复响应或并发恢复复用同一消息节点，切换会话后忽略旧请求结果。

等待补充时保留已生成答案并显示具体缺口，停止持续轮询；验收期间显示正在核验答案和资料来源。任务删除或访问权限撤销后停止查询，暂时查询失败采用退避重试。任务用量展示累计输入与输出，避免将答案长度误认为全部模型开销。

## 知识问答预算与验收

- 明确识别的纯知识问答按实际资料量分配累计预算，通常为 32768 Token，最高 131072 Token；管理员更低的显式限额继续有效。
- 每个执行时间片最多 6 轮、最多 6 次工具调用，不自动扩展续跑；复杂任务沿用通用策略。
- 最近对话和单次输入使用较小的上下文范围，优先利用已有检索结果，仅在缺少依据时补充检索。
- 本轮真实知识库快照同时参与规则与语义验收，避免资料已经传给回答模型，却因验收没有收到依据而反复等待补充。
- 继续或恢复时保留累计用量，既有任务预算不会随升级自动增加。预算上限是允许使用的额度，不是每个问题必须消耗的数量。

## 执行、暂停与恢复

流式恢复携带检查点中的工具结果、已应用控制要求与既有验收反馈，减少进度丢失后的从头检索。暂停通过状态条件更新生效，验收链路传播停止信号并在写入前检查；停止父任务时同时处理等待输入及验收中的子任务，审批和外部动作提交仍遵守既有边界。

修复 `retry_after` 没有保存导致退避失效的问题。暂停、租约失效和最终答案收尾故障不再误判成工具协议不兼容；已暂停、等待审批、等待提交或已结束的任务不会被迟到异常重新排队。新运行使用独立的消息与验收关联，避免继承父任务的已回写标记。

## 用量与预算收尾

累计 Token 在恢复后继续计入内存预算，已发生的调用先同步用量，再抛出持久化限额错误。零额度或额度恰好用完时阻止后续模型请求，耗尽后保留已有结果及工具记录，不再追加模型总结。委派结构化输出的原始调用与修复调用分别记录真实输出，修复失败也保留第一轮用量。

## 升级与生效

1. 更新服务端源码或镜像并重启服务，重新加载聊天页面。静态资源 URL 将使用 `v0.7.14` 版本参数。
2. 连接该服务端的桌面客户端重新加载页面即可获取本次修复；没有新增桌面原生接口。
3. 本次修复不新增依赖、数据库迁移或必需环境变量，旧任务记录保留。历史续跑链在展示和继续操作时定位最新任务，不批量删除或重写历史记录。
4. `CHANGELOG.md` 顶部版本驱动 `npm run version:sync`，同步包版本、锁文件根包及 README；服务端运行时和页面静态资源读取统一版本信息。

当前交付为工作区源码、文档与版本元数据，未构建安装包、上传更新包或部署生产。
