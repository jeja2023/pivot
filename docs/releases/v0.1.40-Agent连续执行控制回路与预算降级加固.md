# v0.1.40 版本发布记录

**发布日期**：2026-08-24  
**版本主题**：Agent 连续执行控制回路、预算降级与断点恢复加固

---

## 一、更新背景

本轮审查确认，Agent 的状态机、审批、检查点和预算对象虽然已经存在，但流式默认主路径没有完整接入这些控制回路。长任务因此可能绕过步骤/连续错误熔断，在上下文或 Token 达到上限时直接进入错误状态，已经生成的中间结果和最终总结也可能被丢弃。

## 二、核心升级内容

### 1. 流式执行接入完整预算控制

- 每个流式规划轮次调用 `TaskBudget.consumeStep()`。
- 每个流式工具调用统计工具次数、风险、外部副作用、文件写入和网络请求；工具失败进入连续错误计数，成功会复位连续错误。
- 流式循环使用 `resume_from_step` 作为绝对轮次游标，不再用 `agent_steps` 行数发放相对轮次。
- 流式工具步骤按当前规划轮次记录，与 JSON 规划器保持一致；流式回退不会重新消耗已经完成的轮次。

### 2. 预算/超时触发后保留部分结果

- `AGENT_BUDGET_EXCEEDED` 和 `AGENT_TIMEOUT` 不再默认把运行标记为纯错误。
- 运行会保留已有观察，尝试生成带限制说明的部分总结，并以 `completed_with_errors` 终态和警告通知交付。
- 最终总结的模型用量记账支持“允许记录但不再次熔断”，避免模型已经生成答案后因最后一次 Token 检查抛错而丢失答案。
- `replanning` 状态允许直接进入 `completed_with_errors`，确保连续错误熔断后的终态转换合法。

### 3. 上下文窗口与停滞治理

- 流式每轮请求前执行 `fitMessagesToContextBudget`；模型和全局设置均未配置窗口时使用 Agent 回退窗口（默认 32768 Token，可通过 `AGENT_CONTEXT_WINDOW_TOKENS` 调整）。
- JSON 规划器和最终总结同样使用该回退窗口，避免兜底路径与主路径能力倒挂。
- 连续三次相同工具与相同输入会被识别为无进展，停止继续调用并生成部分总结，避免检查点缓存命中后的高速空转。

### 4. 审批恢复和检查点进度

- 审批通过时保存 `resumeContext`、最近检查点观察、最新步数和已批准输入摘要。
- 恢复任务从原进度继续，已完成的观察继续提供给规划器；幂等操作仍通过 operation key 防止重复副作用。

### 5. 上限和普通聊天入口收口

- 默认最大步骤预算调整为 60，覆盖深度/审计模式的最大轮次。
- 默认运行时间预算跟随 `AGENT_RUN_TIMEOUT_MS`，普通聊天使用统一的 Agent 运行超时和工具超时，不再使用 24 小时运行期限。
- `CHAT_AUTO_AGENT_ENABLED` 默认值改为 `0`。管理员显式开启后，短且不含任务意图的闲聊仍走普通模型流；分析、查询、整理、生成、执行等复杂任务才进入持久化 Agent。

## 三、配置变化

```env
# 普通聊天是否自动创建连续 Agent，默认关闭
CHAT_AUTO_AGENT_ENABLED=0

# Agent 运行和单工具默认超时
AGENT_RUN_TIMEOUT_MS=600000
AGENT_TOOL_TIMEOUT_MS=120000

# 未配置模型上下文窗口时的 Agent 回退窗口
AGENT_CONTEXT_WINDOW_TOKENS=32768
```

已有部署如果在 `.env` 中显式设置 `CHAT_AUTO_AGENT_ENABLED=1`，升级后仍会保持显式配置；如需采用新默认行为，请改为 `0` 或删除该配置后重启服务。

本版本无需数据库迁移。部署后重启服务即可；若需要启用普通聊天自动 Agent，请在系统设置中打开对应开关，并确认运行/工具超时和上下文回退窗口符合本单位策略。
