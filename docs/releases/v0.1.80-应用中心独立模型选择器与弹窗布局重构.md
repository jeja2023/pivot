# v0.1.80 发布记录：应用中心独立模型选择器与弹窗布局重构

发布日期：2026-09-05

## 一、更新背景

在旧版本中，应用中心下辖的各项子应用（包括“公文写作”、“数据分析”、“法规库”）在发起 AI 请求时，存在以下架构耦合与交互痛点：

1. **隐式依赖主会话模型选择器**：各应用前端在获取调用模型时，普遍直接读取聊天主界面的 `#model-selector`，导致用户在聊天会话中切换模型时，会意外影响公文写作、数据分析或法规问答的实际调用模型；
2. **缺乏应用级独立记忆**：公文写作、数据分析与法规问答适合不同类型的模型（如公文写作适合大上下文中文润色模型，数据分析适合代码与推理能力较强的模型），用户无法为每个应用单独记忆默认模型；
3. **弹窗排版紧凑度不足**：法规库“AI问答”弹窗与公文写作“AI全文起草”弹窗上的“模型”标签与下拉框原本采用纵向上下分行排布，占用了宝贵的垂直空间，造成弹窗布局松散且不符合现代高密度工作台标准；
4. **局部改写误唤醒审校建议**：在公文写作中执行选区润色、扩写或压缩时，会错误触发审校建议模态弹窗的弹出，打断用户当前的排版与编辑专注度。

## 二、架构重构与改造方案

### 1. 应用中心通用独立模型选择器（`PivotAppModels`）
- **通用模块封装**：新增 [`client/chat/apps-model-selector.js`](../../client/chat/apps-model-selector.js)，对外统一暴露 `refresh(appId, selectOrId)` 与 `getSelectedModel(appId, selectOrId)` 接口，并通过标准 `Pivot.exposeModule` 注册；
- **用户与应用级隔离存储**：采用 `localStorage: pivot_app_model_<appId>_<userId>` 格式隔离持久化用户的选择偏好；在用户未单独选择时，按“个人默认模型 $\rightarrow$ 系统默认模型 $\rightarrow$ 第一个可用模型”优雅回退；
- **同应用多入口状态联动**：当同一应用内存在多个模型选择器（如公文写作命令栏的局部改写模型与起草弹窗的起草模型）时，通过 `syncAppModelSelectors` 实现双向实时同步；
- **全链路解耦**：彻底改造公文写作（`apps-workbench-ai.js`、`apps-workbench-core.js`）、数据分析（`data-analysis/ai.js`、`data-analysis/core.js`）与法规库（`regulations/core.js`、`regulations/events.js`），所有上层 AI 调用均接入通用模型选择器。

### 2. 弹窗模型选择器同行排版优化
- **公文写作 AI 全文起草弹窗**：
  - 更新 [`client/chat/styles/workspaces/apps/official-writing-extras.css`](../../client/chat/styles/workspaces/apps/official-writing-extras.css) 中的 `.official-writing-draft-model-selector`；
  - 采用 `display: flex; flex-direction: row; align-items: center; gap: 10px;`，将“起草模型”标签与下拉框居中放置在同一行；
  - 标签配置 `white-space: nowrap` 与 `flex-shrink: 0`，消除挤压折行问题。
- **法规库 AI 问答弹窗**：
  - 更新 [`client/chat/styles/workspaces/apps/regulations.css`](../../client/chat/styles/workspaces/apps/regulations.css) 中的 `.regulations-ai-model-field`；
  - 采用 `display: flex; flex-direction: row; align-items: center; gap: 10px;` 水平同行排布，高度统一为 32px 规范尺寸。

### 3. 公文写作选区编辑与审校流程优化
- **消除审校弹窗误触发**：在 [`client/chat/apps-workbench-rewrite.js`](../../client/chat/apps-workbench-rewrite.js) 等模块中，消除选区润色、扩写、压缩后自动唤起审校模态弹窗的逻辑，仅在用户主动点击“审校建议”时才打开弹窗；
- **审校建议模型选择与可中止控制**：审校建议弹窗接入独立模型选择，并增加请求中的 AbortController 中止支持。

### 4. 自动化测试与工程治理
- **新增单元测试套件**：新增 [`tests/apps-model-selector.test.js`](../../tests/apps-model-selector.test.js)，覆盖 4 组核心断言（默认模型初始化与隔离存储、三个应用 AI 请求独立性、审校建议中止与模型切换、选区操作不误开审校建议弹窗）；
- **全套代码规范与门禁通过**：
  - `check_window_globals_usage`：合规通过；
  - `check_large_files` & `check_governance_metrics`：存量大文件行数受控；
  - ESLint 0 错误 0 警告，系统完整性检查 100% 通过。
