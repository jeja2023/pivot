# v0.1.77 发布记录：修复对话能力拦截与视觉输入分支异步缺失异常

发布日期：2026-09-04

## 一、问题背景

在用户与聊天机器人对话过程中，当提问内容涉及当前系统未直接支持的外部多模态或特定生成意图（例如“画一张图片”、“AI 绘画”、“生图”等），或者在文本模型上上传了图片但模型未启用视觉输入能力时，服务端 `/api/chat` 抛出 `HTTP 500` 系统内部错误：
```text
TypeError: Cannot read properties of undefined (reading 'lastInsertRowid')
    at E:\pivot\server\routes\chat\index.js:357:51
    at process.processTicksAndRejections (node:internal/process/task_queues:105:5)
```

## 二、根因分析

1. **异步调用缺少 `await`**：
   - 在 [`server/routes/chat/index.js`](../../server/routes/chat/index.js) 中，当 `detectUnsupportedCapability(modelContent)` 或 `contentContainsVisionInput(modelContent)` 命中时，服务端会调用 `persistAssistantTurn` 将友好提示消息持久化至会话历史中。
   - `persistAssistantTurn` 在 [`server/services/chat-persistence.js`](../../server/services/chat-persistence.js) 中声明为 `async` 异步函数。
   - 原代码使用同步解构 `const { assistantMessageResult } = persistAssistantTurn({...})`，导致解构得到 `undefined`（从未被 await 的 Promise 对象中解构属性）。
   - 后续在组装 SSE 响应时尝试访问 `assistantMessageResult.lastInsertRowid`，触发读取未定义属性的 TypeError 异常。

## 三、修复方案

1. **补齐 `await` 与稳健的 messageId 提取**：
   - 在能力不支持拦截分支与视觉不支持拦截分支中，将 `persistAssistantTurn` 调用全部补齐 `await`。
   - 提取 `persistAssistantTurn` 返回的 `assistantMessageId`，并通过 `assistantMessageId || assistantMessageResult?.lastInsertRowid` 安全获取持久化 ID。
   - 在正常消息生成结束处理分支中统一对齐上述安全提取逻辑。

2. **补充回归测试**：
   - 在 [`tests/security-chat/route-orchestration.js`](../../tests/security-chat/route-orchestration.js) 中新增单元测试：
     - `聊天路由在用户触发不支持的能力时返回友好提示并持久化助手消息`
     - `聊天路由在多模态输入遇到不支持视觉的模型时返回友好提示并持久化助手消息`
   - 验证不支持能力命中后服务端正确持久化助手消息、下发结构化能力事件、携带正确的 `messageId` 并以 `[DONE]` 正常收尾，不再抛出 500 异常。
