# Pivot v0.7.185 发布说明

2026-11-20 · PPT Master 制作续跑与稳定性

本版修复完整制作中归档、重复检查和人工续跑相互影响的问题，并补齐分页、工具兼容、故障诊断和活跃任务续期。PPT Master 继续使用锁定的上游 v6.10.0 和独立服务协议 1。

## 修复内容

| 范围 | 修复后的行为 |
| --- | --- |
| 停滞与检查点恢复 | 按模型当前可见的结果判断回读是否补回信息。同一页恢复次数有界。人工续跑可以先核对文件，停滞修复流程本身无需强制压缩历史。有效写入和确认阶段推进后会重置对应的停滞修复计数。 |
| 上下文归档与分页 | 主动归档线按窗口和配置的输入上限计算。窗口为 256K 且输入上限充足时，归档线为 153,600 估算令牌。为源材料和当前阶段指引保留有界空间，较旧正文仍可分页回读。普通读取单页最多 24,000 字符，小窗口和多项同批读取会缩短页长。 |
| 上游工具适配 | 快速制作可在无 `spec_lock.md` 时通过受控角色参数校准字体，并可在项目目录内同步选定的内置 SVG 图标。宿主负责确认、进度和快照，模板安装继续执行正常校验。 |
| 故障诊断 | 连续工具执行失败单独报告 `PPT_MASTER_TOOL_REPEATED_FAILURE`。制作详情按可用记录显示工具标识、错误类别、退出码或回读位置。 |
| 活跃任务续期 | 检查点和心跳在有效租约内延长到期时间，单次连续执行最多 8 小时。用户确认或手动续跑可开启新的执行段，累计步骤与用量继续计入原任务。 |

## 升级与兼容

- Pivot 主应用启用源码版本 v0.7.185，复用现有数据库和配置。需要恢复旧检查点时，先更新主应用，连接原服务并保留原镜像和工作区，再从原任务续跑。
- Quick 的角色校准与图标同步由新版独立服务镜像提供。待续跑任务处理完毕后再切换镜像，用新建任务核对新增能力。切换后旧检查点仍绑定原引擎身份。[独立服务部署与更新](../deployment/PPTMaster独立服务部署与更新.md#更新服务镜像与主应用)

## 实际验证

- 功能验证在升版前的 v0.7.184 修复工作区执行。通过 92 项 Node 专项测试（包括隔离 PostgreSQL 18）、23 项 Chromium 和客户端测试，以及 17 项 Python 测试。11 项 Linux 专用部署测试在 Windows 上跳过。
- 原先第 3 轮再次报停滞的动作序列，在回归测试中可以核对文件、回读归档指引、提交最终方案，并在获批后写入设计规范。真实数据库测试覆盖续期上限、过期和旧租约写回。[续跑回归](../../tests/presentation-master.test.js) · [数据库回归](../../tests/presentation-master-postgres.test.js)
- 本地固定 v6.10.0 容器以新执行器代码通过 Quick 无锁校准、图标同步、SVG 校验、原生 PPTX 导出和交付清单核验。
- 升版后通过 `npm run check`、版本一致性、发布说明链接检查和 2 项帮助导航契约测试。
- 全仓 `npm test`、真实模型和生产任务仍待验证。v0.7.185 发布镜像和桌面制品待构建，生产待部署。
