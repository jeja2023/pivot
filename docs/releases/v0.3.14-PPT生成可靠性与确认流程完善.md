# v0.3.14 - PPT 生成可靠性与确认流程完善

> **发布日期**：2026-10-16  
> **升级类型**：PPT AI 来源追溯、确认交互、结构化生成稳定性与发布前审查  
> **兼容性**：向后兼容；不包含数据库迁移，不改变既有文稿、模板、素材、版本或导出文件

## 版本概述

本版本完善 PPT 制作应用从上传材料、AI 生成大纲、人工确认到创建可编辑页面的链路。重点解决上传文件具有动态来源标识、而模型沿用固定 `source_1` 示例造成确认大纲无法保存的问题；同时补足确认大纲弹窗的取消出口与确认进度排版。

## 一、上传材料来源可追溯

- 大纲生成提示词为每份材料提供真实来源 ID、标题和内容，并明确要求 `sourceRefs` 只能引用本轮给出的 ID。
- 返回格式的来源示例由固定 `source_1` 改为基于本轮实际材料动态生成；无材料时 `sourceRefs` 必须为空数组。
- 页面生成请求、确认大纲预览和最终服务端保存都依据同一组受控来源过滤引用，确保页面、元素和确认大纲使用一致的来源集合。
- 为平稳升级，旧版大纲若仅有一个真实材料且仍引用 `source_1`，会被无歧义转换为该材料的真实 ID；多材料时不作推测，避免错误归因。

## 二、大纲确认流程

- 模型提出的假设以可勾选的待确认项展示，支持逐项确认与“一键确认全部待确认项”；未完成确认时不允许提交页面生成。
- 确认进度“已确认 X / Y 项待确认内容”向右缩进两个字符，与确认项文字起始位置对齐。
- 弹窗底部新增“取消”：关闭弹窗并清空本次临时大纲、确认勾选和创建参数；“返回调整要求”继续用于回到创建表单修改后重新生成。

## 三、结构化生成预算

- 单次页面生成维持 7200 output-token 受控上限，并限制每页元素数、正文长度和演讲备注长度，降低长 JSON 在闭合前被截断的风险。
- 第一次响应无法解析时，系统从确认大纲以紧凑页面契约自动重试，而不是尝试从截断残片补造缺失内容。
- 生产模型的 256K 上下文窗口用于容纳材料、模板和确认大纲输入；并不意味着应无限提高结构化页面的单次输出预算。

## 四、审查结论与已知限制

- 已核验应用中心入口、按需脚本加载、创建/保存/版本/导出/远程演示、评论协作、模板导入和主要前后端路由接线。
- 当前环境已通过 60 项 PPT 专项测试、前端资源接线检查、全量 JavaScript 语法检查、安全 HTML 检查、PostgreSQL 迁移覆盖检查与相关 ESLint。
- 2 项 PostgreSQL 集成测试因当前环境未配置 `DATABASE_URL` 而跳过；部署前应在隔离数据库运行，以覆盖实际的持久化、导出与协作权限链路。
- 已识别但尚未在本版本代码中修复的限制：PPT “传图片”快捷按钮、3 个 AI 快捷语和“立即体检”采用内联 `onclick`，而生产 CSP 禁止 `script-src-attr`。这些快捷入口在生产浏览器会被拦截；主工具栏的上传、质量检查和 AI 操作入口不受影响。后续应迁移至模块委托事件，并添加 CSP 回归测试。
