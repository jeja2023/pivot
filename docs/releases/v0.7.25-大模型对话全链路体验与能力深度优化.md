# v0.7.25 大模型对话全链路体验与能力深度优化

日期：2026-10-21。

### 1. 中文输入法（IME）回车误触发送问题彻底修复
- **根因分析**：
  - 在 Windows 与 macOS 环境下，用户使用中文拼音输入法输入汉字后按回车键确认候选词时，浏览器会触发输入框的 `keydown` 事件。
  - 原输入框监听器仅判断 `event.key === 'Enter' && !event.shiftKey`，未核验输入法组合键状态 `event.isComposing` 或键码 `229`，导致拼音确认操作误判为发送指令，产生意外发送不完整词句的体验问题。
- **改造与防护**：
  - 在 `client/chat/app-workspaces.js`、`client/chat/chat-auto-route.js` 以及 `client/chat/app/dialogs.js` 等所有涉及聊天与弹窗输入的键盘事件处理逻辑中，前置加入 `if (event.isComposing || event.keyCode === 229) return;` 保护。
  - 彻底规避了中文拼音输入、提到（@）候选菜单选择以及会话设置弹窗输入过程中因确认候选词而导致的误发送与误确认。

### 2. 文档类附件与纯文本大模型能力解耦
- **架构解耦**：
  - 此前前端上传按钮状态及发送校验机制深度绑定了模型视觉属性（`supports_vision === 1`）。
  - 实际上后端的文档抽取与语义注入链路（支持 `.pdf`、`.docx`、`.xlsx`、`.csv`、`.txt`、`.md` 等格式）完全由后台文本提取器与上下文装配器处理并转换为标准文本注入对话，纯文本大模型（如 DeepSeek 全系列、非视觉文本基座模型）完全具备深度解析与长文问答能力。
- **全流程能力重塑**：
  - **上传入口常态可用**：在 `client/chat/ui.js` 中将上传按钮设为常态可用，鼠标悬停时智能区分提示：“添加文件或图片 (支持图片与文档解析)”或“添加文档或文件 (当前模型不支持图片识别，图片需切换至视觉模型)”。
  - **附件队列智能分流**：在 `client/chat/engine-attachments.js` 中，若当前选中的是非视觉模型，用户添加文档类文件正常接纳入队并解析；若包含图片，则友好提示并跳过图片文件，保留全部文档文件。
  - **发送边界精确把关**：在 `client/chat/engine.js` 中，仅在用户挂载了图片附件且当前模型缺乏视觉能力时进行拦截，文档类附件不受任何视觉模型限制，彻底释放非视觉模型的文档理解潜力。

### 3. 会话级系统提示词（System Prompt）全流程交互与配置
- **能力补全**：
  - 后端数据架构早已具备 `sessions.system_prompt` 字段与 `PUT /api/sessions/:id/system-prompt` 持久化接口，并在上下文组装中注入 `history.unshift({ role: 'system', content: session.system_prompt })`，但前端此前缺少配置入口。
- **交互与生命周期闭环**：
  - 在 `client/chat/sidebar.js` 的会话右侧更多菜单中新增「设置提示词」菜单项。
  - 在 `client/chat/app/main.js` 中实现 `setSessionSystemPrompt(id, title)`：打开多行弹窗回显当前会话已设置的提示词，用户可定制人设、专业规范或约束条件，提交后调用后端保存并即时生效，留空则自动清除。

### 4. 推理大模型思考标签（`<think>` / `<thinking>`）标准化与优雅折叠
- **推理模型全兼容**：
  - 随着 DeepSeek-R1、Qwen 系列、Ollama 及各类国产深度思考推理模型的普及，主流模型广泛使用 `<think>...</think>` 或 `<thinking>...</thinking>` 输出内在推导过程。此前前端 Markdown 解析扩展仅硬编码匹配 `<thought>`，导致新一代推理模型的推导过程以外露文本展示。
- **解析与剪贴板协同规范**：
  - **Markdown 语法扩展**：在 `client/chat/render.js` 中扩展 `thoughtBlock` 正则与标记器，统一匹配并解析 `<thought>`、`<think>`、`<thinking>`，在已闭合与未闭合状态下规范呈现为带有思考脉冲、可一键展开/折叠的高质感“模型思考内容”卡片。
  - **流式增量精准更新**：在 `client/chat/engine-streaming.js` 中同步更新思考标签匹配器，流式输出未闭合思考内容时保持内容实时平滑写入与视口跟随。
  - **剪贴板干净脱敏**：在 `client/chat/app/main.js` 的复制清洗器中，一并剔除 `<think>` 与 `<thinking>` 内部推导内容，用户一键复制出的正文纯净整洁。

### 5. 长文本流式渲染自适应阶梯节流与性能优化
- **性能瓶颈根治**：
  - 在大模型输出数千字的长篇公文、详细代码或深度方案时，高频的 SSE 数据包会导致每帧重复执行整篇长 Markdown 的 AST 解析（`marked.parse`）和复杂 DOM 重排，产生明显卡顿。
- **自适应阶梯节流机制**：
  - 在 `client/chat/engine-streaming.js` 中重构 `resolveStreamInterval(contentLength)`：
    - `< 600 字符`：保持 80ms 极速响应，保证短文本与起步输出如同行云流水；
    - `600 - 2000 字符`：适度放宽至 140ms，兼顾流畅度与性能；
    - `2000 - 6000 字符`：调整至 220ms，平衡长文渲染负载；
    - `>= 6000 字符`：收敛至 320ms，消除页面回流重排卡顿，大幅降低客户端 CPU 消耗。
  - 最终帧与 `[DONE]` 阶段确保立即执行 `flushStreamRender`，保证最终内容完整无遗漏。

### 6. 会话标题生成机制重构与端到端秒级即时同步
- **消除延时空等**：
  - 原逻辑在问答流结束后通过 `setTimeout(..., 1500)` 硬编码延时重新拉取会话列表，网络延迟或模型思考较慢时经常导致标题未能及时刷新。
- **服务端推送与前端秒级响应**：
  - 在 `server/services/chat-title.js` 与 `server/services/chat-persistence.js` 中让标题生成逻辑返回最新的会话标题。
  - 在 `server/routes/chat/index.js` 的流式收尾事件 `message_saved` 中，直接携带生成的 `sessionTitle` 字段。
  - 在 `client/chat/engine.js` 中，前端接收到持久化消息后，若存在新标题则秒级同步更新页面顶部 `#current-title` 与侧边栏中对应会话项标题，并移除 1.5 秒空等逻辑。

### 7. 全局搜索历史消息深层定位与微脉冲高亮跳转
- **深层定位与闭环**：
  - 此前从搜索浮层点击搜索结果时仅能打开该会话并滚到底部，面对包含几十上百条消息的长会话时，用户难以快速找到究竟哪条消息命中了关键字。
- **端到端精确定位治理**：
  - **后端结果关联**：在 `server/routes/sessions.js` 的 `/sessions/search/content` 中，通过 PostgreSQL 窗口检索提取具体的 `matched_message_id` 以及命中正文前 150 字摘要 `snippet`。
  - **前端结果绑定**：在 `client/chat/sidebar-search.js` 中将消息 ID 挂载至搜索卡片；在 `client/chat/sidebar.js` 点击时透传 `targetMessageId`。
  - **虚拟滚动与 DOM 滚动对齐**：在 `client/chat/engine-sessions.js` 与 `client/chat/message-virtualizer.js` 中接入 `targetMessageId`，计算消息在视口中的精确偏移量并平滑滚动定位到居中位置。
  - **微脉冲视觉动效**：在 `client/chat/styles/sessions-prompts.css` 中注入 `.message.message-search-highlight` 优雅脉冲动画，指引用户一眼锁定历史关键上下文。
