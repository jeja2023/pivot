# v0.1.189 长期记忆失败任务重试完整性修复

发布日期：2026-09-27

发布范围：设置工作区“长期记忆 → 抽取任务 → 重试失败”及长期记忆提取任务状态机。

## 问题与影响

原有“重试失败”会将当前用户的 `failed` 抽取任务重新标记为 `queued`，但保留了原来的 `attempts` 计数。失败任务通常已经耗尽 `max_attempts`，因此重试后若再次遇到暂时性错误，会在第一次失败时立即回到 `failed`，无法获得完整的自动重试预算。

同时，旧错误、旧结果和完成时间仍残留在记录中，不利于区分新的执行周期与历史失败状态。页面也会固定提示“失败任务已重新入队”，即使并发状态变化后实际没有任务可重试。

## 修复内容

- 手动重试仅匹配当前用户、状态为 `failed` 的抽取任务。
- 可选任务 ID 会去重并限制为最多 100 条，避免异常请求生成过长 SQL 条件。
- 每个被重试任务会：
  - 状态改为 `queued`；
  - `attempts` 重置为 `0`，保留原有 `max_attempts` 作为新的自动重试预算；
  - 清除 `locked_at`、`last_error`、`result` 与 `completed_at`；
  - 设置新的 `next_run_at` 并触发后台提取 Worker。
- 页面根据服务端返回的 `queued` 数量显示结果；没有可重试任务时提示“没有可重试的失败任务”。

## 安全与边界

- 不会重试其他用户的任务，即使请求显式传入其他用户的任务 ID。
- 不会改变 `succeeded`、`running`、`queued` 或 `skipped` 任务。
- 重试仅恢复任务调度状态；抽取仍经过长期记忆启用状态、来源撤回、敏感内容、模型可用性和写入门禁校验。持续性错误仍会在新的预算耗尽后标记失败。
