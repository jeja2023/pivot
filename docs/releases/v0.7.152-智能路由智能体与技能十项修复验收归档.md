# v0.7.152 智能路由、智能体与技能十项修复验收归档

日期：2026-11-11（Asia/Shanghai）。本版在 v0.7.151 的实现基础上，汇总本轮 3 项高优先级、7 项中优先级问题的最终修复、回归结果和升级说明，并启用新的源码版本。历史测试日志仍保留执行时的版本，不因升版改写为 v0.7.152 的重新验收。

## 十项修复

| 编号 | 原问题 | 当前行为 |
| --- | --- | --- |
| F01 | 决策上下文重复脱敏后丢失特征 | 原始任务状态与规范化请求使用同一字段白名单，往返保留任务哈希、证据需求、请求能力与约束计数；缺失租户保持 null。提供器推理、持久化与训练重建使用一致的特征。 |
| F02 | 核验阶段被误判失去租约且无法恢复 | 核验纳入执行租约状态并正常续租；失去执行权或服务退出后保留结果并明确失败，不自动重放外部动作。恢复检查当前状态、心跳和执行代次，旧执行者不能覆盖新执行者。 |
| F03 | 正常队列路径跳过启动 Hook | 认领后在模型和业务来源调用前执行启动检查，前后置审计关联执行代次；启动被拒绝后不自动重试。 |
| F04 | 故障切换的实际模型未持久化 | 普通及 CAS 状态更新支持实际选用模型；初始选择、恢复和故障切换同步数据库与内存身份，备用模型随后失败仍保留实际身份，用于恢复和质量统计。 |
| F05 | 学习决策无法关联任务执行结果 | 实际生效的学习决策贯穿交接、反馈和纠正，语义判断保留独立记录；终态结果按确定性键去重。执行失败率只使用实际生效并已有结果的决策样本，不混入影子建议或未结束任务。 |
| F06 | 已接纳批次去重后不推进数据库水位 | 已接纳批次先于新增运行配额识别；目标、版本和批次内容一致时补交水位，提交须满足有效认领和版本条件。来源内容改变或提交未确认时明确报错。 |
| F07 | 技能正文在规划中静默截断 | 保留 256KB 正文上限，移除 12k/16k 截断；创建、验证、发布与运行统一校验。JSON、流式规划、总结、能力受限答复及独立核验接收完整指引；容量不足明确失败。 |
| F08 | 目录先截取后过滤，合法技能被挤掉 | 键集分页先排除他人个人发布，再逐页检查权限、状态和灰度；有效条目才消耗目录名额。搜索遍历可见目录，详情缩小到指定名称并校验完整引用。 |
| F09 | 匹配旧技能版本却执行另一版本 | 仅对当前实际可用的发布版本匹配；任务创建绑定发布 ID、版本和摘要，解析时复核引用及显式激活要求。发布变化返回冲突，相同发布时间采用稳定排序。 |
| F10 | 多步工具调用稀释技能负反馈率 | 工具错误与有效用户反馈分别使用各自分母和最小样本门槛；反馈按更新时间入窗，运行时结果不算用户评价，迟到收尾保留用户评分、结论和评价时间。 |

工具权限、审批、预算、来源撤销和执行位置边界继续生效。技能文字不会增加权限，启动 Hook 的修复不替代工具执行前的授权检查。

- 后续处理完整验收中的 22 项失败：修复 BI 调度等待竞争与残留唤醒、DuckDB 共享临时目录白名单、浏览器代理长连接与退出确认；物理恢复测试保持持久性并区分初始化预算。逐项状态与复验见[22项失败修复记录](../reports/full-suite-failure-repairs-20261111.md)。最终相关复验 99/99 通过，原 22 项均有通过证据；未重跑完整全仓套件。下方 3,372 项计数为修复前历史记录，不因后续专项通过改写。
- 新增路由、运行时和技能三个项目审查专项测试文件，覆盖真实提供器、持久状态、队列认领、核验恢复、发布版本、目录分页和反馈统计。

## 升级与兼容

- 没有新增依赖、数据库迁移或必填配置；使用原部署流程更新源码并重启服务后，页面和版本接口读取 v0.7.152。桌面客户端与镜像需按原流程另行构建，已有制品仍保留其构建版本。
- 历史路由特征、模型选择和决策结果归因不作无法证明的回填；新记录按修复后的契约生成。旧核验任务由停滞恢复处理，已有结果保留，失败任务需查看结果后决定是否重试。
- 长技能需要足够的模型上下文。容量不足时选择更大上下文模型或将参考材料移入配套资源；不会继续使用被截断的规则。
- 已接纳数据库批次的来源内容或目标版本变化时，需要核对来源和水位后重试；不会凭相同批次键跳过新内容。
- 技能匹配后发布版本变化时，重新创建任务以取得当前版本；发布暂停、撤权和灰度检查仍实时生效。
