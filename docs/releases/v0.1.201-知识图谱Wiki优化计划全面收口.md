# v0.1.201 知识图谱与 Wiki 优化计划全面收口

发布日期：2026-10-10

## 概要

本版本完成《知识库功能优化评估（知识图谱与 Wiki）》中全部实施计划的工程收口。知识图谱成为由原始资料证据约束的派生层，LLM Wiki 成为按固定输入快照生成、可增量重编译与审核发布的综合层；二者均不能绕过原始资料的有效性和权限边界。

## 交付内容

- 图谱采用“规范实体 → claim → evidence”模型。每条进入检索的关系均要求至少一条当前有效的原文证据；支持多来源聚合、支持/反驳立场、摘录与定位、抽取器版本、人工冻结、关系本体、合并审计与回滚。
- 实体消歧由名称归一、持久化别名字典、词法候选和已索引来源分块的向量相似度共同完成。自动清理只处理没有有效证据的自动实体，不影响人工维护实体。
- 资料删除、禁用、归档、过期、重新启用、重建、手工版本发布通过事务 outbox 统一驱动图谱失效/重建、Wiki stale 和 RAG 缓存刷新。Worker 提供 P95 时延及五分钟 SLO 观测。
- Wiki 只检索正向相关页面，并只将逐声明核验、来源仍有效的摘要和原始定位用于问答。编译 run 固定保存版本、block、正文 hash、定位、选择原因和 token 预算；输入失效时 supersede 后重新排队。
- Wiki 编译按变更区块、主题、标签、实体和历史页面规划，并通过跨文档轮转和 token 预算控制覆盖面；未受影响页面不重复编译。页面列表、搜索和来源可见性改为批量 ACL 校验。
- 图谱索引实体、mention 和关系改为批量写入；实体详情一次返回首屏关系，`depth=2` 使用受限 BFS 返回有来源的两跳关系。

## 数据库升级与兼容修复

本版本包含以下顺序迁移：

1. `202610100001_knowledge_derived_governance`
2. `202610100002_knowledge_derived_quality`
3. `202610100003_knowledge_derived_quality_repair`

第三批迁移是幂等的修复迁移，专门补齐部分滚动发布/历史异常环境中缺失的：

- `knowledge_graph_claim_evidence.stance`
- `knowledge_graph_claim_evidence.excerpt_text`
- `knowledge_graph_claims.confidence_reason_json`

因此，图谱查询报出“关系 `knowledge_graph_claim_evidence` 的 `excerpt_text` 字段不存在”时，不应手工修改业务数据。部署本版本并重启应用即可触发正常迁移；随后运行以下只读验证：

```powershell
npm run verify:knowledge-derived-governance
```

验证器会同时检查迁移记录、关键表、关键索引和上述字段。若验证失败，停止对外启用图谱写入/查询，先修复目标 PostgreSQL 的迁移权限或连接配置，再重新启动应用；不要伪造 `schema_migrations` 记录。

## 发布后操作

1. 将本版本部署到具备 PostgreSQL 连接的环境并重启服务，等待三批迁移全部完成。
2. 运行 `npm run verify:knowledge-derived-governance`；只有命令成功才视为目标库升级完成。
3. 在 Wiki 工作台筛选 `stale` 页面，使用新版编译器重新编译、审核并发布历史缺少逐声明来源映射的页面。
4. 在生命周期指标中确认文档变更到派生层失效的 P95 小于 300 秒；抽检 Wiki 引用准确率不低于 95%、已发布页面的声明来源覆盖率为 100%。
