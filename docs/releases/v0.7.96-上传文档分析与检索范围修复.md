# v0.7.96 上传文档分析与检索范围修复

日期：2026-11-05。源码基线：v0.7.95。

## 问题与结果

普通聊天的能力拦截曾扫描拼接后的整条消息，附件正文中的“最新政策、今天新闻、联网搜索”等词可能触发固定的“实时联网检索未接入”提示。结构化任务还会把“文档、资料、来源”等词推断为知识库依据需求，使已有附件在知识库未启用时被固定拒答。部分自然语言排除要求未贯穿意图判断和任务执行。

本次让短附件分析直接使用已提取正文完成回答；知识库和网页只是用户按需指定的额外来源。文档分析不再因为这些额外来源不可用而被拒绝。相关追问可以继续使用当前会话中已有的附件正文。

## 实现范围

- 用户指令与附件正文、附件链接、引用和代码分开处理；能力检查不扫描资料中的指令。
- 来源限制集中解析，明确排除知识库或网页时，模型、历史范围和已选专题不能重新开启对应能力。
- 短附件分析和相关追问不额外调用意图模型或读取工具目录；长附件、导出文件等仍沿用受控任务、来源分页读取、产物核验与交付链。
- 普通聊天的知识库目录、路由、检索和拒答均遵守本轮范围；任务交接和续接写入相同限制，工具目录及实际执行拒绝被排除的能力，并刷新最新执行范围。
- 用户明确要求联网查证或检索知识库时保留原有路径；已有账号权限、工具白名单和审批策略继续生效。

## 验证范围

新增 `tests/chat-source-analysis-http.test.js` 和 `tests/chat-source-scope.test.js`，覆盖普通附件、禁止知识库、禁止联网、知识库关闭、已有正文追问、附件中的指令、显式外部查证、长附件任务交接和执行时限制。HTTP 回归使用真实聊天路由、隔离 PostgreSQL、模拟上游模型，检查正文确实进入模型请求且未调用知识库或意图模型。

本地日志位于 `output/chat-source-scope-*.log`。本次不包含远程环境部署或真实业务模型质量验收。

- 隔离 PostgreSQL 的相关回归共 268 项通过，零失败、零跳过，日志为 `output/chat-source-scope-regression-final.log`。
- 最后补查来源范围、真实 HTTP、意图理解、任务边界和图片生成兼容，共 37 项通过，零失败、零跳过，日志为 `output/chat-source-scope-confirmed.log`。这些用例与上一组有重叠，不累加为独立测试数量。
- `npm run check`、`npm run lint`、`npm run typecheck`、测试位置、开发规范、文本完整性和差异空白检查通过。首次 HTTP 测试曾把标题生成计为正文调用，修正模拟上游对非流式请求的处理后重新通过。

## 升级与限制

更新服务端源码或重建部署制品后重启服务，并刷新客户端。无新增数据库迁移、依赖或环境变量。

截图中的 `AI_ENDPOINT_CIRCUIT_OPEN` 表示上游模型端点曾连续失败后进入暂时熔断；这是独立于附件范围误判的运行状态。此次移除短附件分析对额外意图调用的依赖，但实际回答仍需要可用的模型服务。
