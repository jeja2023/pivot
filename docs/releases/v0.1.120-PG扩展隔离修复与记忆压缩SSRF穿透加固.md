# v0.1.120 发布记录：PostgreSQL 扩展隔离修复与记忆压缩 SSRF 穿透加固

发布日期：2026-09-10

## 版本摘要

本版本主要修复 PostgreSQL 在多 Worker 并行自动化测试及 schema 隔离环境下 `vector` 扩展归属错位导致的致命建表错误，同时彻底解决长会话上下文记忆自动压缩阶段由于参数未向下透传触发的 SSRF 出站拦截，并对测试运行环境中的自检告警日志进行静音净化，保障测试体系与生产环境双向稳定。

## 主要变更

### 1. PostgreSQL 扩展隔离修复与多 Worker 并行建表加固

- **扩展 Schema 归属显式绑定**：在 `server/db/schema/pg.js`、`scripts/setup_pg_test_db.js` 与 `scripts/setup_pg_db.js` 中，将 `vector` 和 `pg_trgm` 扩展的创建语句显式锁定为 `CREATE EXTENSION IF NOT EXISTS vector WITH SCHEMA public` 与 `CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public`。
- **并发 Schema 隔离穿透根除**：彻底解决多 Worker 并行测试（`scripts/run_node_tests.js`）时，未限定 schema 的扩展被安装进 Worker 1 隔离 schema，导致 Worker 2 在不同 `search_path` 下建表无法识别 `vector` 类型抛出 `type "vector" does not exist`，且 Worker 1 清理时将扩展级联删除的问题。
- **异构 Schema 自动平滑回迁**：在 DDL 执行序列前增加自愈逻辑，通过 `DO $$` 块智能检测非 `public` 命名空间下的存量扩展并执行 `ALTER EXTENSION ... SET SCHEMA public`，确保旧环境与测试脏数据平滑回迁。
- **架构隔离断言用例**：在 `tests/pg-schema-isolation.test.js` 中增加针对扩展 schema 归属与回迁机制的自动化断言测试。

### 2. 短期会话记忆压缩 SSRF 穿透与非流式响应闭环

- **用户信息全链路透传**：修复 `server/services/chat-context-assembler.js` 传入的用户对象被 `server/llm.js` 中 `getContext` 与 `runGuardedCompression` 函数签名丢弃的缺陷；全面实现 `options`（包含 `user` 与 `signal`）向下透传。
- **出站 SSRF 管理员身份识别**：彻底消除记忆压缩调用模型接口时因缺失用户身份触发的 SSRF 出站回环拦截（`出站 URL 指向敏感的本地、链路本地或云元数据地址`），确保本地测试上游（`127.0.0.1`）及局域网私有化模型正常访问。
- **用户身份自动兜底**：在 `compressMemory` 中增加异步查询机制，在未显式传参时根据 `userId` 自动兜底获取用户角色信息，防止后台异步任务断漏。
- **手动压缩接口对齐**：在 `server/routes/sessions.js` 的 `/sessions/:id/compact` 路由中显式传入 `user: req.user`。
- **非流式响应模型闭环**：在 `tests/security-chat/chat-route-harness.js` 的假上游服务中支持对非流式（`stream: false`）请求返回标准 OpenAI JSON completion 格式，保障测试闭环。

### 3. 测试环境日志净化与规范校验

- **自检告警日志静音净化**：在 `tests/agent-skill-governance.test.js` 中对验证 CJK 字体缺失下线能力的负向用例进行上下文 `logger.error` 拦截，消除终端测试输出中具有误导性的 `ERROR: CJK 字体自检失败` 告警。
- **架构规范与门禁通过**：通过 `npm run lint`（0 error, 0 warning）、`npm run check:standards`（直接 SQL 基线 1421/1421）、以及全量 22 项静态与架构门禁检查（`npm run check`）。
