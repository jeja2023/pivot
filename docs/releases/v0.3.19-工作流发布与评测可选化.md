# v0.3.19 - 工作流发布与评测可选化

发布日期：2026-10-16

## 版本概述

本版本调整智能体工作流的发布策略：固定评测集由强制发布前置条件改为可选质量检查。此前，首次发布的工作流没有已发布版本可绑定评测集，却又被发布门禁要求先完成评测，形成无法闭合的操作路径。本次调整后，用户可直接发布工作流；需要更严格质量控制的调用方仍可显式要求固定评测通过后再发布。

## 核心改动

### 1. 默认发布不再要求评测

- `POST /api/agents/workflows/:id/publish` 默认不要求固定评测集或已完成评测批次。
- 工作流编辑器的“发布当前版本”会保存并发布当前版本，不再因未评测返回发布门禁错误。
- 首次发布与新草稿版本发布均不再依赖“先发布后创建评测集”的循环前置条件。

### 2. 保留显式评测门禁

- 调用方在发布请求中明确传入 `fixedEvaluationRequired: true` 时，系统仍会校验目标工作流版本是否具有已完成且达到通过线的固定评测批次。
- 默认通过线仍为 80%，并且评测快照必须与拟发布的工作流版本一致，避免使用过期版本的评测结果。
- 评测中心、评测集、用例、批次和历史结果均继续保留，可作为日常回归和质量追踪工具使用。

### 3. 发布界面与审计简化

- 移除“紧急跳过评测门禁发布”入口及填写紧急原因的交互；该流程不再是正常发布的必要补救措施。
- 发布操作仍写入现有审计日志、发布记录与工作流版本信息。
- 拓扑与节点契约校验、共享工作流敏感凭据检查、发布范围权限、租户边界与工具依赖绑定保持为强制校验，未因本次调整而放宽。

## 兼容性与验证

- 现有未传 `fixedEvaluationRequired` 的 API 调用会直接采用新的可选评测策略。
- 需要严格门禁的自动化调用可显式传递 `fixedEvaluationRequired: true`，无需额外的管理员跳过权限。
- 已更新页面契约、PostgreSQL 集成与端到端工作流用例，以覆盖“默认可发布、显式要求评测时仍校验”的行为。
- ESLint、项目 JavaScript 语法检查与自动化页面契约测试通过；需要 PostgreSQL 的集成测试需在配置 `DATABASE_URL` 的环境执行。
