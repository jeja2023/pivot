# v0.7.140：持续目标模型绑定与运行校验修复

日期：2026-11-09。承接[v0.7.139](v0.7.139-智能体工具发现与准备进展修复.md)，本版补齐自动目标从配置保存到任务启动的模型绑定链路，并同步更新日志、使用帮助和设计规范。

## 问题与修复后的行为

原创建表单只有模型策略，没有具体模型选择，也不提交模型标识；后端允许保存该配置，但自主任务启动时要求有效模型，导致目标保存成功后测试运行或触发失败。

- “智能体管理 → 自动目标 → 新建自动目标”新增“执行模型”。复用既有账号模型列表，新建时优先带入可用默认模型；固定策略使用所选模型，其他策略保留该基础绑定。
- 创建、编辑、自然语言草案确认、测试运行和实际触发均传递模型配置。签名草案沿用原确认机制，具体模型通过已有允许覆盖字段显式绑定。
- 保存及运行前复用现有模型权限判断，拒绝缺失、停用、删除或当前账号无权使用的模型，包括其他用户私有模型和单位范围受限模型；模型标识不接受部分数字、非整数或无效类型。
- 编辑回显原模型及目标类型。局部修改模型等字段时保留原工具授权、审批策略、网络配置和授权有效期；兼容已有字段别名。
- 加载中、加载失败、列表为空或未选择有效模型时，前端阻止保存和测试运行。关闭弹窗、切换目标或账号后，迟到的模型列表响应不能覆盖当前选择。

## 使用与升级

1. 新建目标时填写名称和任务描述，选择目标类型、触发方式和执行模型，核对时区及结果渠道后保存。
2. 历史未绑定模型、原模型已失效的目标，需在列表点击“编辑”，重新选择可用模型再保存；系统不会自动为旧目标替换模型。
3. “生成草案”和保存配置不调用大模型。测试运行和每次触发执行需要可用模型并消耗Token；测试运行会执行一次真实任务，沿用工具授权和审批，但不会创建或启用持续调度。
4. 模型列表不可用时关闭弹窗后重试；仍无可用模型时配置个人模型或联系管理员授权。连续失败导致目标暂停后，应先修正失败原因再恢复。

完整操作说明见[使用帮助第6.2.1节](../../使用帮助.md#621-创建自动目标持续目标)。本次复用现有模型、目标存储和任务运行服务，没有新增外部依赖、环境变量或数据库迁移。
