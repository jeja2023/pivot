# v0.7.3 Windows 客户端中文语音通道修复

Windows 客户端点击语音输入和实时语音时，可能都显示“浏览器不支持 zh-CN 的本地语音识别”。原因是 v0.7.2 将浏览器离线语言包当作唯一实现，未使用系统本地引擎。仅设置 `processLocally` 和规范化语言名不能补齐 Chromium 缺少的语言包。

本版为 Windows 客户端接入系统 `System.Speech` 识别引擎；本机探测确认已安装 `MS-2052-80-DESK / zh-CN`。普通浏览器继续使用自身设备端识别，桌面客户端优先走系统通道。两种方式都不把录音上传到服务端。

- 语言参数规范化后再传递；`h-CN` 等无效标识回落为 `zh-CN`。
- 本地识别通过主进程窄 IPC 和专用隐藏进程运行；不接受文件、命令、脚本或任意进程参数。仅受信的主窗口可启动或停止。
- 原生识别不依赖浏览器麦克风 API或浏览器中文包。仍受 Windows 默认麦克风、系统隐私设置和已安装识别语言组件限制。
- 识别确认启动后才进入活动状态。取消探测中的启动、切换会话、页面导航、退出客户端时回收进程；延迟返回不会重新打开已取消的设备。
- 临时对话的文本模型和本地朗读沿用现有链路，未接入外部语音识别服务。

## 必须更新桌面程序

本版修改了 Electron 主进程与预加载桥，已有安装版必须重新构建并升级客户端，再加载新版服务端页面。仅刷新页面或只更新服务端不能获得系统通道；旧客户端会给出明确升级提示。没有改动用户系统设置、安装语言包或自动切换远程识别。

验证记录见 [验收报告](../reports/Windows客户端中文语音修复验收报告_2026-10-19.md)。

工程检查与 ESLint 通过；全量回归 1974 项、最终相关回归 26 项、两条浏览器端到端路径均通过。真实 Windows 中文引擎已用合成 WAV 验证能工作，但存在个别词识别错误；未进行真人麦克风测试。
