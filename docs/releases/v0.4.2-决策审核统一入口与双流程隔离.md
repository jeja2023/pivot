# v0.4.2 决策审核统一入口与双流程隔离

发布日期：2026-10-18

## 版本摘要

本版本将系统设置中的“反馈核验”和“金标审核”合并为一个“决策审核”入口，并在入口内通过双标签呈现两个独立流程。此次调整只收敛信息架构；用户反馈、冻结金标、训练候选、评测基准和发布门禁的业务边界均不改变。

## 页面结构

```text
系统设置
└─ 决策审核
   ├─ 反馈核验
   │  └─ 真实用户建议 → 管理员采纳/不采纳 → 已核验候选样本
   └─ 金标审核
      └─ 冻结案例 → 两名不同管理员独立一致 → 可信评测金标
```

## 保持隔离的强制规则

| 范围 | 反馈核验 | 金标审核 |
|---|---|---|
| 数据来源 | 脱敏后的真实用户单轮路由建议 | 有摘要校验的版本化冻结评测集 |
| 人工结论 | 单个管理员可采纳或不采纳 | 至少两名不同管理员独立选择同一允许动作 |
| 分歧语义 | 不采纳不会生成训练样本 | `human_review_conflict`，持续阻断案例通过 |
| 输出 | 可供后续受控使用的已核验反馈 | 可校准 Judge、评测和发布门禁的金标 |

特别说明：采纳一条用户反馈不会自动把它升级为金标；金标审核也不会修改原用户会话或重放任何原始路由。

## 实现与兼容性

- 设置侧边栏只保留 `decision-review` 主标签；页面内部采用标准 `tablist`、`tab` 与 `tabpanel` 语义管理两个子页。
- `route-feedback` 和 `decision-gold-review` 两个历史设置标签会分别映射到 `feedback`、`gold` 子页，兼容已保存的设置页恢复状态和既有调用方。
- 切换子页时仅请求所选队列：反馈队列继续使用 `/api/stats/observability/decision-feedback`，金标队列继续使用版本化 `decision-evaluation-sets` 接口。
- 双人金标审核状态、候选动作白名单、双盲展示和发布阻断逻辑未修改。
- 重新生成设置工作区 CSS 包，窄屏下子页签可横向均分显示。

## 升级说明

部署后刷新聊天页面即可使用新入口。若用户上一次停留在旧版“反馈核验”或“金标审核”，系统会自动恢复到“决策审核”的对应子页；无需迁移数据库，也不会改变任何既有审核记录。
