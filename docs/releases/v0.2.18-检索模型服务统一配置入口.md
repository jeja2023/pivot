# v0.2.18：检索模型服务统一配置入口

发布日期：2026-10-13

## 变更摘要

向量模型和重排序模型不再由“知识库”功能承担配置入口。它们同时服务于法规查询和知识库，因此统一迁入：

```text
设置 → 模型配置 → 检索模型服务
```

该区域展示并配置：

- Embedding 服务地址、模型、密钥与连接测试；
- Reranker 服务地址、模型、协议、密钥、候选上限和超时；
- 当前检索策略的 Top-K、候选数、分块与阈值摘要。

模型页三张状态卡各自提供独立配置入口；弹窗采用三块清晰分区，并且一次只展示与保存所选分区：

1. 检索策略：阈值、Top-K、候选池与分块；
2. 向量生成服务：地址、模型、密钥、模型发现与连接测试；
3. 重排序服务：启用开关、地址、TEI / llama.cpp 协议、模型、候选上限、超时、密钥与独立连接测试。

重排序测试只会发送固定的两条无敏感测试候选；若服务不可达、鉴权失败或响应格式不兼容，界面会显示具体失败信息，保存的既有配置不会被覆盖。

从模型页进入配置弹窗时，系统会先读取并预填当前 Embedding、Reranker 与检索策略，避免配置表单显示为空而误覆盖既有服务地址或模型名称。

## 知识库行为

知识库工作台不再提供可编辑“检索配置”。它仅展示当前系统检索模型与重排序状态；admin 可通过“前往模型配置”跳转到统一入口。召回测试、知识图谱、文档索引、批量重建和质量治理入口保持不变。

## 安全与兼容

- 只有 admin 权限层级可保存系统检索模型服务配置；
- 知识库和模型页读取同一系统级公开配置摘要，API Key 始终不返回浏览器；
- 无数据库迁移、无索引重建。已经配置的 Embedding/Reranker 地址与密钥保持有效；
- 更换模型本身仍需按 v0.2.17 的步骤重建法规与知识库向量。
