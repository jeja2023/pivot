# Pivot v0.7.178 发布说明

2026-11-18 · PPT 制作快照与引文恢复

## PPT Master 完整制作

- 页面写入时保留待核验源稿，导出后按已批准清单核验并保存快照。已通过页可单独下载为可编辑 PPTX，或转存为独立原稿。待核验页单独标明，正式交付仍核验原任务的完整清单。
- 「完整制作记录」独立打开。关闭任务详情或按 Esc 返回原记录列表，可继续查看下一项。已通过页可在当前窗口放大，并可保存为图片供回看。
- 用户在确认阶段提交的答复，以及从检查点继续时填写的说明，按条登记为任务内可核验来源。引用校验跟踪数据项，支持清单重排。引文仍无法核对时，界面显示具体页项，同模型续作前需补充说明，也可切换模型。修订后的最终清单须重新确认，原任务的已保存快照仍可回看。

## 标准 PPT 工作台与检查修复

- 标准工作台在服务端逐批保存到同一文稿。中断后从文稿库打开草稿，使用「补齐缺页」按原大纲生成缺失页，保留已编辑页面。缺页期间整稿导出受限。
- 修复知识 Wiki 的同步主题收集与 PPT 批次保存同名引起的异步检查误报。
- 主应用启动时运行数据库迁移 `202611180001_presentation_generation_progress`，在 `presentation_documents` 中保存逐批生成进度。沿用现有依赖和必填配置。

## 镜像与升级

此次新增的补充来源、引文恢复和记录导航由主应用实现。已有快照能力的独立服务可直接复用。更新主应用后，用登录请求检查 `GET /api/apps/presentations/master/info`。当 `engine.progressSnapshotsReady` 为 `true`，只需更新主应用。若服务已连接但该字段为 `false` 或缺失，要使用自动快照和通过页 PPTX，应切换到已验证的独立服务构建。

| 已验收镜像项 | 值 |
| --- | --- |
| 标签 | `ppt-master:6.8.0` |
| 平台 | `linux/amd64` |
| Docker 镜像 ID | `sha256:d80dce5a7e5205725b67181033136747f51e2e91a88a041458dff210d1fb502d` |
| 服务运行身份 | `sha256:8235fb3110ee3e328ec0741336d96afcfed31f5aa260d3d6c16fef7b806b100e` |

旧构建也可能使用 `ppt-master:6.8.0`，应核对**运行中的容器**使用的镜像 ID。若目标主机为离线环境且缺少已验收镜像，可从已有镜像导出离线包并生成校验文件。镜像 ID 用于识别运行镜像，归档需使用该文件的 SHA-256 校验。

更换镜像前，先在匹配的旧引擎处理仍需续跑的任务。备份并继续使用原 PostgreSQL、主应用持久目录（包含产物存储和上传文件）、PPT Master 的 `/data` 数据卷与连接配置。在同一个 Compose 项目中重建对应服务。旧检查点继续绑定原引擎，持久保存的快照由主应用提供下载。[保留原数据卷和任务](../deployment/PPTMaster独立服务部署与更新.md#保留原数据卷和任务)
