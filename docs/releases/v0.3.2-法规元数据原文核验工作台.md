# v0.3.2 - 法规元数据原文核验工作台

> **发布日期**：2026-10-15  
> **升级类型**：审核体验与稳定性补丁  
> **兼容性**：向后兼容 v0.3.1；无需数据库迁移或额外配置

---

## 版本概述

元数据审核的结论必须以法规原文为依据。此前，审核表单以浮层形式覆盖在原文详情之上，审核人需要反复关闭表单、查看正文、重新进入编辑，既降低效率，也容易在标题、发布机构、效力时间和权威来源等字段上产生误填。

v0.3.2 将元数据审核重构为同屏核验工作台：原文是持续可见的证据区，表单是独立的审核操作区。该变化只作用于元数据审核，不改变普通法规阅读、检索、AI 问答、版本对比或追加版本的使用方式。

## 一、审核工作台布局

### 宽屏

- 左侧：法规原文证据区，可独立滚动，顶部固定显示“法规原文 / 审核依据”与核验提示；
- 右侧：元数据审核表单，包含标题、法规层级、分类、发布机构、适用范围、维护人、元数据审核状态、权威来源以及当前版本效力和审核信息；
- 表单底部的保存/取消操作固定在当前审核面板内，长表单滚动时无需回到顶部或底部寻找操作。

### 窄屏

在窗口宽度不足以安全并排展示时，布局自动变为上下结构：法规原文位于上方，审核表单位于下方。这样仍然先呈现核验依据，不会出现表单覆盖正文的情况。

## 二、审核行为

1. 在“质量概览 → 元数据治理待办 → 处理元数据”，或法规详情的“编辑信息”中进入审核。
2. 对照原文核验标题、法规层级、发布机构、适用范围、发布日期/生效日期及官方来源。
3. 信息完整且可确认时，将“元数据审核”设为“已审核”；不能确认时保留“待审核”或选择“驳回”。
4. 保存后，审核工作台退出，原有质量概览、待办队列和列表状态按既有机制刷新收敛。

原文面板的滚动位置会在审核过程中的重新渲染时保持。选择取消、关闭详情或按 Escape 会同时关闭审核表单并退出审核布局，不会遗留覆盖层或错误的模式状态。

## 三、法规分类目录卡片紧凑重构与视觉升级

1. **主题色彩体系替代单调纯灰**：针对分类卡片原有单调的纯灰轮廓，建立分类语义与主题色彩映射体系（国家法律为科技蓝、刑事安全为深玫瑰红、行政规章为天青蓝、地方规范为翡翠绿、行业规范为琥珀黄、司法解释为优雅紫、企业团体标准为靛蓝等），顶部增加 2.5px 强调条，左上角辅以柔和微色相背景。
2. **纯矢量线框图标（无 Emoji）**：完全摒弃非正式的 Emoji 表情符号，采用描边粗细一致（stroke-width: 1.8）且极具现代感的 SVG 矢量线框图标（如天平、盾牌、楼宇、图钉、书籍、文档与文件夹），全面提升企业级合规场景的严谨度与品质感。
3. **紧凑卡片尺寸规范**：针对多分类下屏幕垂直高度浪费问题，将卡片最小高度由原约 196px 显著精简收敛至 120px 紧凑规范，内边距优化至 12px，网格自适应最小宽度设为 230px，大幅提升一屏信息密度，减少上下滚动负担。
4. **清除标题附属标签与右上角冗余箭头**：彻底移除分类卡片标题旁的类型微型标签与右上角常驻箭头，标题独享完整展示宽度不被截断，精简头部视觉噪点。
5. **治理健康度状态与进度**：卡片底部集成绿/黄双色微型健康状态圆点与当前分类治理就绪度文字提示，配合 3px 极细平滑进度条，直观反映各分类下法规条文的维护就绪程度。

## 四、稳定性修复

本次同时修复了法规分类目录渲染模块中的重复残留文本和缺失摘要渲染依赖。该修复避免 JavaScript 模块加载中断，确保分类目录、法规详情、质量概览和治理入口都能正常初始化。此外，修复了法规治理浏览器测试中 `window.getComputedStyle` 全局变量显式引用，规范了评测、规划、工具推荐及工作流服务中的未使用变量与参数，确保全量 ESLint 检查零警告、零错误。

## 五、验证

- 浏览器回归覆盖元数据审核双栏模式、原文证据提示、取消后恢复普通详情布局；
- 浏览器回归验证法规分类卡片紧凑排版、线框 SVG 图标无 Emoji、右上角无箭头与健康度状态显示；
- 法规治理、分类目录权限、法规检索范围与检索中防重复提交回归通过；
- 执行 `npm run build:chat-css`、`npm run check:text`、`npm run check:safe-html` 和差异空白检查。

## 六、升级说明

直接部署 v0.3.2 并重启服务即可。版本号由 `CHANGELOG.md` 作为运行时单一来源，静态资源会自动使用新的 `v0.3.2` 缓存标识。无需变更数据库、环境变量或既有法规数据。
