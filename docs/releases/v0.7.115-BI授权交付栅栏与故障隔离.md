# v0.7.115 — BI 授权交付栅栏与故障隔离

落实方案第 19—22 节和第 24.2 节的关键本地竞态、崩溃及资源隔离要求。生产环境认证仍按用户此前约定暂缓，恢复后的安全重放与共同恢复点继续在后续阶段完成。

## 授权及交付

统一先锁全部参与主体，再锁模型和来源。旧部署补齐原有账号、模型、数据集缺失的授权修订，保留已经递增的值；运行时缺失修订记录直接拒绝访问。复核、交接和发布预先锁定参与人员，模型写入在行锁之前取得排他授权栅栏。

响应准备和实际交付分别核验当前身份、共享与所需字段。JSON 在持有授权锁时同步发送，视图和仪表盘同时核验当前资产修订。版本和模型定义按照当前可见字段裁剪，派生指标的间接依赖也纳入检查。受控工具的检查点不缓存授权决定，站内事件发送前再次核对运行回执。

下载首块在授权锁内发送，每块不超过 64 KiB；活动下载定期复核当前授权，撤权或无法确认授权后五秒内停止调度新字节。分页、范围重试和下载令牌均不能越过当前身份及授权修订。

## 执行和文件故障

数据库保护正式任务的领取代次、执行者、槽位和租约，旧领取 SQL 不能更新正式任务。过期执行进程恢复后不能续租、提交或增加成功审计。取消与完成依照事务提交顺序产生唯一终态；发布与查询同时发生时，运行仍固定所选发布版本。

文件原子提升逐级校验目录及目标，不穿过符号链接；读取复核真实受控路径、摘要和长度。超过一天且符合服务端暂存命名合同的半写文件由既有完整性巡检清理。事务借出的 PostgreSQL 连接发生断连时接收错误事件并销毁失效连接，避免未捕获异常或坏连接回池。

- 72 项组合回归通过，覆盖预算、公平性、百万行摄取、迁移、交接、对象与巡检、正式消费、共享、渠道、工具库和检查点边界。
- 新增授权专项覆盖真实 HTTP 的已准备响应、缺失修订、单位/账号/字段撤销、固定随机种子竞争、慢客户端长下载和受控 AI 交付。

- Linux 容器故障试验通过实际 2 GiB cgroup OOM、64 MiB 临时目录满、只读根目录、不兼容协议和暂停后强制终止；持续请求 API，并确认相应容器回收。该故障镜像只存在于测试支持目录，不进入生产执行入口。
