# v0.7.130 — 数据建模列表规范统一与操作流升级

日期：2026-11-08。上一版本：v0.7.129。

针对数据建模列表页面在表格视觉规范、序号列缺失、行高不统一、分页自制、操作列缺少编辑/删除、旧版过渡文案残留、所有者硬编码以及模型名称与用途说明折行混排等问题，完成列表视图、操作交互与后端元数据查询的端到端深度优化与全局规范对齐。

## 主要改进

### 1. 数据表格全局视觉规范与统一分页
- **新增序号列**：列表表头首列增加「序号」列（类名 `text-center col-index data-analysis-row-index`），基于当前页码与每页偏移量自动计算连续编号，始终居中对齐。
- **全局统一表格样式**：全面接入项目统一的 `.data-table.compact-table` 样式体系，固化表格行高为 **38px**，统一 13px 字体大小与行距，表头背景色与行悬浮高亮效果完全契合全局规范。
- **按钮防撑高行高**：操作列按钮类名规范化为 `.data-analysis-table-btn`，限定高度为 **24px** 并垂直居中排布，彻底杜绝按钮撑大单元格行高导致的视觉参差。
- **接入全局统一分页器**：彻底移除原先自制简易的分页 HTML，改用系统工作区全局通用分页组件 `window.Pivot.legacy.renderWorkspacePagination`，提供统一样式的上一页、下一页、数字页码按钮与总条数联动。

### 2. 操作列功能完善与旧版过渡内容清理
- **新增行内「编辑」功能**：
  - 在操作列新增「编辑」按钮；
  - 点击弹出标准模态对话框，支持查看与修改模型基本信息（模型名称、用途说明、业务负责人与维护联系人）；
  - 确认提交后调用后端 `PUT /apps/data-analysis/models/:id` 保存生效，并自动刷新列表。
- **新增安全「删除」功能**：
  - 在操作列新增红色警示「删除」按钮（类名 `.data-analysis-table-btn.is-danger`）；
  - 点击调起全局标准确认弹窗（`showConfirm`），提示用户删除风险；
  - 用户确认后调用后端 `DELETE /apps/data-analysis/models/:id` 执行软删除安全归档（`deleted_at = NOW()`），自动重置当前选中态并刷新列表。
- **清理旧版过渡性文案与流转**：
  - 移除「关联探索」与「创建正式草稿」等历史过渡文案；
  - 统一规范操作流：
    - 正式模型：提供「打开」、「编辑」、「删除」；
    - 探索模型：提供「打开」、「编辑」、「升级模型」（一键流转升级为正式模型草稿）、「删除」。

### 3. 元数据展示对齐与所有者真实显示
- **显示真实用户名，废除“我”**：
  - 后端模型目录查询层通过 `LEFT JOIN users u ON u.id = m.user_id` 查询用户真实账号名称 `u.username AS owner_name`；
  - 前端取值逻辑修正为优先展示真实用户名（如 `admin` 或实际账号），彻底解决单一人称代词硬编码。
- **模型名称与用途说明分列展示**：
  - 将原先混排折行的「模型名称与用途」彻底拆分为两个独立列：「模型名称」列与「用途说明」列；
  - 「模型名称」加粗单行展示，溢出自动省略并支持鼠标原生 hover 提示完整名称；
  - 「用途说明」独立成列，为空时灰色显示“未填写用途说明”，单行省略并支持悬停查看全貌，保持整行高度整齐划一。

### 4. 环境变量与配置项严格对齐
- 对齐 `.env` 与 `.env.example` 中的数据建模运行时与安全配置（`DATA_ANALYSIS_MODEL_*`），行数保持 1015 行完全一致，消除多余空行与隐式差异。
- 同步更新《使用帮助》与设计规范。
