# v0.1.81 发布记录：动态代码沙箱收口与多节点持续调度及检索下沉优化

发布日期：2026-09-05

## 一、更新背景

在系统向高并发生产环境与多节点集群部署演进的过程中，核心运行链路与安全架构暴露出多项 P0–P1 级别的架构与可靠性痛点：

1. **服务端动态代码沙箱隐患**：原先服务端主进程中使用 Node.js 内置 `vm` 模块执行用户编写的 JavaScript 代码，存在沙箱逃逸与宿主进程被击穿的潜在风险；
2. **Agent 工作台目标创建传参与竞态缺陷**：工作台新建持续目标时将浏览器点击事件误作为目标对象传入，且缺乏并发请求序列管理与中断保护，易导致界面状态错乱；
3. **数据语义分析批次崩溃一致性风险**：语义分析批次初始化未加行级锁与原子事务，若中间进程崩溃会遗留残缺批次，恢复逻辑无法准确判断边界；
4. **知识库与法规库全量检索内存瓶颈**：RAG 向量与文本检索原先在 Node.js 内存中遍历计算向量距离并进行词法重排，当数据规模扩大后对主进程内存和 CPU 造成显著冲击；
5. **多节点部署能力虚报风险**：部署画像仅凭环境变量是否存在即判定就绪，但在适配器未实际接通运行时的情况下容易误报集群已就绪；
6. **持续目标调度多实例争抢冲突**：多节点部署时，多个应用实例会在同一到期时刻重复捞取相同目标，依赖末端 Run 去重造成无谓的计算浪费与锁争用。

本版本针对上述 6 项 P0–P1 级关键隐患进行了系统性重构与修复，并全面通过了自动化回归测试与工程规范验收。

## 二、核心变更与技术实现

### 1. 动态代码执行安全收口与独立沙箱强制隔离
- **移除服务端主进程 vm 执行**：从 [`server/services/agent-tools.js`](../../server/services/agent-tools.js) 和 [`server/services/agent-tools-workflow-nodes.js`](../../server/services/agent-tools-workflow-nodes.js) 中彻底移除 `vm.runInNewContext` 及其相关的执行逻辑；
- **沙箱隔离硬性门禁**：直接调用 `agent.code` 或 `workflow.foreach` 时，通过 `assertDynamicCodeExecutionIsSandboxed` 进行统一策略阻断。未配置并接入独立 Worker 隔离沙箱环境时，一律返回 HTTP 403 / 错误码 `AGENT_SANDBOX_REQUIRED`（`category: policy`）；
- **前端预设与工具策略提示对齐**：同步更新 [`client/chat/dag-node-presets.js`](../../client/chat/dag-node-presets.js)、[`client/chat/agent-run-tool-labels.js`](../../client/chat/agent-run-tool-labels.js)、[`client/chat/tool-policy.js`](../../client/chat/tool-policy.js) 以及 [`使用帮助.md`](../../使用帮助.md)，明确告知涉及 JavaScript 的代码与批处理节点必须在受控桌面 Worker 沙箱中执行。

### 2. Agent 工作台目标创建传参修复与请求竞态消除
- **消除 Event 对象传参污染**：在 [`client/chat/agent-harness.js`](../../client/chat/agent-harness.js) 中，将原 `el.addEventListener('click', openGoalModal)` 调整为包装函数 `() => openGoalModal()`，防止 DOM `PointerEvent` 对象被当作既有 `goal` 参数传入，根除模态弹窗初始字段错乱；
- **控制面加载请求竞态消除**：为 `loadControlPlane()` 引入全局自增序列号 `controlPlaneLoadSequence` 与 `AbortController` 机制。切换 Tab 或高频触发刷新时，上一轮未结束的请求即刻被 `abort()` 中止；晚到达的陈旧响应被自动丢弃，彻底消除多请求异步竞态引发的数据覆盖与界面闪烁。

### 3. 语义分析批次事务化、行级排他锁与断点恢复一致性校验
- **原子事务与 FOR UPDATE 锁**：在 [`server/services/data-analysis/semantic-analysis.js`](../../server/services/data-analysis/semantic-analysis.js) 中，将 `ensureSemanticBatches` 重构为基于 `transaction` 的原子操作，并在读取任务和批次时显式加上 `FOR UPDATE` 行级排他锁；
- **断点恢复与边界一致性校验**：支持异常中断后的断点恢复。在恢复已有批次时，严格校验 `segment_start`、`segment_end`、`row_start`、`row_end`、`segment_count`、`row_count`、`char_count` 等切分边界；如遇边界不一致或存在非法多余批次，立即抛出 409 `SEMANTIC_BATCH_DEFINITION_MISMATCH` / `SEMANTIC_BATCH_COUNT_MISMATCH` 阻断执行；
- **增量安全幂等写入**：缺失批次通过 `ON CONFLICT (job_id, batch_index) DO NOTHING` 幂等补齐，确保任务完整性。

### 4. RAG 检索与法规检索运算全面下沉 PostgreSQL
- **向量检索下推 pgvector**：在 [`server/repositories/knowledge.js`](../../server/repositories/knowledge.js) 与 [`server/services/rag-index/index.js`](../../server/services/rag-index/index.js) 中，向量相似度排序与截断下推至数据库层（`ORDER BY c.embedding <=> ?::vector ASC LIMIT ?`），并在 SQL 条件中施加 `vector_dims(c.embedding) = ?` 维度一致性过滤，避免全库 embedding 载入 Node.js 内存计算；
- **词法相关度评分下沉**：利用 PostgreSQL `pg_trgm` 的 `similarity()` 函数在数据库内计算文本相关度评分 `lexical_score` 并直接排序，同时在扩展不可用时保留无缝降级回退；
- **法规库检索同步优化**：在 [`server/services/regulations/search.js`](../../server/services/regulations/search.js) 中，条文全文检索与向量近邻检索（`1 - (a.embedding <=> ?::vector)`）全面下沉 PostgreSQL，配合维度过滤与分页截断，大幅降低应用层资源消耗。

### 5. 多节点企业级部署画像适配器真实验收与就绪状态解耦
- **解耦声明配置与运行时就绪**：在 [`server/services/deployment-profile.js`](../../server/services/deployment-profile.js) 与 [`server/services/deployment-providers.js`](../../server/services/deployment-providers.js) 中，将 Provider 状态细分为 `configured`（配置存在）、`adapterWired`（适配器接入）与 `ready`（真实验收就绪）；
- **消除虚报与告警闭环**：S3 兼容对象存储、分布式队列、分布式锁在未实际接入运行时适配器前，保持 `multiNodeReady: false` 与 `adapterWired: false`。若系统请求多节点部署模式，系统将明确报告 `multi_node_provider_adapter_not_wired` 告警，不再提前虚报就绪。

### 6. 持续目标调度多实例租约机制（PostgreSQL Claim Lease）
- **数据库租约字段迁移**：新增迁移脚本 [`server/db/migrations/agent-goal-dispatch-lease.js`](../../server/db/migrations/agent-goal-dispatch-lease.js)（`202609050002_agent_goal_dispatch_lease`），为 `agent_goals` 表新增 `claim_token` 与 `claim_expires_at` 字段，并建立复合调度索引 `idx_agent_goals_claim`；
- **原子领任务与多实例防重**：在 [`server/services/agent-goals.js`](../../server/services/agent-goals.js) 中引入 `claimAgentGoal`，通过原子 `UPDATE` 竞争租约，只有抢占成功的实例才允许推进目标调度，配合下游 Agent Run 的 `dedupe_key` 形成双重防重保障；
- **周期续租与故障接管**：长任务调度期间通过 `startGoalClaimRenewal` 每 15 秒自动续租（默认租约 5 分钟，可通过 `.env` 中 `AGENT_GOAL_CLAIM_LEASE_MS` 调整）；任务完成或失败时在 `finally` 中安全释放租约；若节点宕机，到期后其他存活节点可自动接管抢占。
