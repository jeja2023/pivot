# v0.1.183 实时语音与本机文件交付完善

发布日期：2026-09-26

发布范围：聊天实时语音、Windows/Linux 桌面客户端的受控文件交付，以及网页“保存到本机”的首次配置与设备就绪流程。

## 发布摘要

本版本处理两条客户端侧的可靠性链路。实时语音不再将可选音频增强能力作为打开默认麦克风的前提，避免部分设备驱动将请求错误报告为“找不到设备”。本机文件保存补齐了首次状态初始化、目录授权、当前登录账户设备登记、目录有效性筛选与状态窗口惰性初始化，保证用户从网页首次保存即可完成受控落盘。

## 1. 实时语音麦克风兼容性

### 默认输入设备优先

- 启动实时语音时改为通过 `navigator.mediaDevices.getUserMedia({ audio: true })` 请求系统默认输入设备。
- 回声消除、降噪和自动增益不再作为首个硬性约束。它们不是实时语音识别的必要条件，且部分 Windows 驱动会因组合约束错误返回设备不存在。
- 麦克风流成功取得后，才创建服务端实时语音会话；设备打开失败不会产生无效的语音会话记录。

### 可操作的错误提示

- `NotFoundError` 及同类错误会提示检查系统默认输入设备、设备启用状态和桌面客户端/浏览器的麦克风权限。
- 权限拒绝、设备被占用、音频约束不兼容及非安全上下文均有对应的中文提示，不再直接展示 Chromium 原始错误文本。
- 当前会话停止、启动取消、识别失败、`pagehide` 和 `beforeunload` 继续通过统一清理路径停止音轨、识别和本地朗读。

### 隐私与功能边界

- 实时语音仍要求浏览器能确认设备端语音识别，并要求存在本地 TTS 声音；不满足条件时保持关闭。
- 录音不会上传。识别文本仅用于当前模型请求，不写入聊天消息、长期记忆、会话标题或独立语音转写记录。
- 助手播报继续由浏览器本地 `speechSynthesis` 完成，用户说话时可打断当前播报。

## 2. 客户端本机文件保存设置

### 首次保存与目录授权

- 网页调用 `getDeliveryStatus()` 时会惰性初始化桌面交付执行器；此前尚未初始化时可能被误判为“本机交付不可用”。
- 没有可用目录授权时，点击“保存到本机”会打开桌面系统目录选择，完成目录安全校验、设备签名和服务端授权登记后再创建交付意图。
- 客户端菜单中的“查看文件交付状态”同样会惰性初始化执行器，可在未发生保存操作前查看、配置或撤销已授权目录。

### 当前会话与目录有效性

- 创建交付意图前新增受控的交付就绪检查。客户端使用当前 Web 登录会话重新证明设备身份并启动交付轮询，避免刚登录后立即保存时设备尚未登记完成。
- 本机状态读取会清理已过期目录映射；网页不会选择过期目录，也不会展示不支持当前产物格式的目录。
- 多个可用目录使用 `1`、`2` 等序号选择，不要求用户输入内部授权 ID。
- 客户端会将设备身份、目录授权映射和已写清单分别以受保护的原子文件保存；重启后自动启动交付轮询，服务端待交付任务可继续领取。

### 安全边界保持不变

- 用户只能授权具体、可写的子目录；盘符根、用户主目录、系统目录以及非可写路径均被拒绝。
- 文件名、格式、路径穿越、Windows 保留名、符号链接越权、单次写入体积、每日配额和 SHA-256 摘要继续由既有受控交付链校验。
- 目录完整绝对路径只保留在客户端本机受保护存储和本地状态窗口；服务端和网页仅使用脱敏目录提示与授权 ID。
- 设备与目录授权必须通过当前登录账户的服务端校验。账户切换、设备撤销或授权失效时，创建或领取交付任务会被拒绝，不会写入未授权目录。

## 兼容性与升级

- 无数据库迁移，无新增环境变量。
- 远程 Web 页面需要连接更新后的服务端静态资源；“保存到本机”还需要升级到本版本的桌面客户端，以获得新的状态初始化和 `prepareDelivery` IPC。
- 已有本机目录授权和已写清单保持可用。过期授权会在状态读取时移除，需由用户重新选择目录完成授权。
- 浏览器外运行或未安装桌面客户端时，“保存到本机”仍不可用；可继续使用受控浏览器下载。
