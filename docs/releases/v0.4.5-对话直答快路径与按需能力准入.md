# v0.4.5 对话直答快路径与按需能力准入

发布日期：2026-10-19

## 版本摘要

本版本将普通聊天从“所有消息都进入完整路由决策”改为三层能力准入。它降低纯大模型对话的无效处理成本，同时保留知识库、工具、授权、审批与审计的受控执行边界。

## 准入模型

```text
用户消息
├─ direct：无能力信号 → 主模型直答
├─ candidate：疑似资料/工具意图 → 渐进发现受治理候选
└─ explicit：手动范围、@选择、明确检索 → 固定能力范围并执行
```

### `direct` 直答路径

- 适用于普通问答、创作、翻译、润色及没有资料/外部能力信号的消息。
- 不调用 `DecisionProvider`，因此不读取路由偏好、策略制品或学习型决策器。
- 不生成 Query Embedding，不读取知识库或工具目录，不写入逐条决策记录。
- 返回标准、安全的 `routePlan` 兼容对象，RAG 与工具均为 `skip`，最终直接调用聊天主模型。
- 只写入异步、聚合且不包含用户原文的 `direct` 路由指标；指标写入不阻塞回答。

### `candidate` 与 `explicit`

- 内部制度、知识库依据、实时数据库、本机文件、网页或外部操作意图进入候选路由；仅加载访问控制过滤后的有限候选集合。
- 用户选择资料范围、手动开启检索、使用 `@` 指定资料/工具时进入显式路径；该意图不会被自动决策改写为跳过。
- 工具候选不等于工具执行。未确认 MCP 时系统只请求用户确认；确认后仍经白名单、策略与审批控制。

## 可逆配置

新增 `PIVOT_CHAT_DIRECT_PATH_ENABLED=true`，默认启用。设为 `false` 后，普通消息恢复原有完整路由链，便于灰度、对照或应急回退；无需迁移数据库或清理历史记录。

## 验收标准

1. 无能力信号的普通消息 `mode=direct`，不调用业务决策器、知识库目录、工具目录或 Embedding。
2. 内部资料与真实外部操作继续进入候选路由；显式资料范围和 `@工具` 继续进入强制路径。
3. `direct` 路径的 RAG、工具规划和工具执行均为 `false`，且不要求 MCP 确认。
4. 关闭 `PIVOT_CHAT_DIRECT_PATH_ENABLED` 后恢复原有 `chat.next_step` 决策行为。
5. 路由指标可识别 `direct` 模式，且不包含用户原文或 Query Vector。

五分验收台账 UI 的安全 HTML 访问也已收敛至 `Pivot.legacy.PivotSafeHtml`；安全渲染器不存在时仅写入纯文本，避免引入未命名空间化的全局变量访问。

## 生产发布建议

1. 先保持 `PIVOT_CHAT_DIRECT_PATH_ENABLED=true`，观察 `direct`、`auto`、`explicit` 的异步路由指标以及“路由复核”队列中的误分流反馈。
2. 若发现高风险误分流，可先将该变量设为 `false` 回退完整路由链；无需停机迁移。
3. 不应仅以直答比例判断效果；还需结合知识依据拒答率、工具确认率、工具执行成功率和管理员采纳的路由复核反馈评估。
