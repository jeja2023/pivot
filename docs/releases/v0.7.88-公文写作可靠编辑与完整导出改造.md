# v0.7.88 公文写作可靠编辑与完整导出改造

日期：2026-11-04。

## 更新内容

- **正文编辑**：输入期间保持编辑区 DOM 稳定，修复逐字输入错序、中文组合输入干扰、空行丢失和撤销失效。普通输入、粘贴、模板、AI 采纳与版本载入使用统一撤销/重做事务。
- **AI 生成与审校**：起草、全文润色、局部改写先展示结果与差异，再由用户采纳。请求绑定发起公文和原文快照，切换文档不会把结果写到其他正文；正文变化或无法唯一定位时拒绝直接替换。所有生成模式可取消，保留有内容的未完成结果供查看和复制。
- **建议契约**：问题说明、替换文字和严重程度分别保存；空数组表示没有审校问题，格式无效、截断和中断分别反馈。已采纳/忽略建议不再提供重复应用动作。流式路径显式处理错误、结束原因和完成标记，服务端跨块过滤思考标签。
- **保存与恢复**：显示等待保存、保存中、保存成功、失败和冲突状态；失败可重试，冲突可比较服务端版本、复制当前稿或另存副本。加载失败保留当前内容；离开应用时冲刷保存，仍有脏状态时关闭页面提示。登出和鉴权失效清理当前账号的内存正文及结果。
- **文档列表**：新增名称检索、文种筛选和更新时间/名称排序；新客户端使用服务端摘要分页，打开时才读取正文。列表与编辑页共用状态规则，不再把任何非空正文都标记为“可导出”。
- **历史与备份**：材料快照去重，自动草稿按时间采样，手动/自动历史共同受数量和字节预算控制；支持清理历史和载入版本时选择恢复材料。提供 JSON 备份导出、校验并导入为新公文，恢复时不继承其他文档的导出绑定。
- **材料与来源**：TXT、Markdown、CSV、JSON 支持 UTF-8/GB18030 读取；Word、PDF、图片复用统一文档处理任务与 OCR，导入任务随公文保存并可在再次打开时继续查询。引用记录保留片段、版本、页码和来源标识，可查看与检查来源变化；异步导入绑定原文档。
- **导出**：每篇公文由服务端维护独立产物绑定，保存与导出版本冲突会明确反馈。增加普通/红头版式和实际 PDF 页面预览；签发人、发文机关、落款、成文日期、抄送、印发机关、印发日期、密级及保密期限分别进入 DOCX/PDF。修复可变中文字体子集造成的页面字形缺失。DOCX 参考预览明确提示换行以 Word 为准。
- **结构与效率**：拆分文档库、列表、编辑器、事务历史、建议、材料、产品接线和后端公文路由；原编辑器约 1,400 行收敛到 500 行内，并移除大文件豁免。规则与引用分析缓存，隐藏辅助面板按需渲染，审校条目批量保存。

## 升级与兼容

1. 备份数据库及现有公文，更新并重启主服务，文档处理工作进程同步更新；刷新客户端页面。
2. 自动执行迁移 `202611040001_official_writing_library`，增加摘要和独立产物绑定，按旧正文回填列表摘要。旧正文不因迁移重写。
3. 旧标签页仍可读取完整正文；对升级后的文档写入会收到升级提示，需要保留正文并刷新。新客户端使用 `view=summary` 和分页参数；单篇详情通过 `GET /api/apps/official-writing/documents/:clientId` 读取。
4. 旧文档中的历史快照和旧版 JSON 备份在加载/保存时转换为去重状态；超出历史预算时优先裁剪较旧快照，不裁剪当前正文和材料。重要版本请导出备份。
5. 导出继续使用服务端 Renderer。无需新增 npm 依赖或环境变量；PDF 页面预览使用已有 PDF.js 包的固定浏览器入口，运行时无需外网。

真实业务模型质量、全部 Windows 输入法、目标打印机和组织公文规范仍需在使用环境核对；本次验证不构成国家标准或人工审签结论。
