# v0.2.23 文字识别按钮对齐与OCR模型服务收拢系统设置

发布日期：2026-10-14

## 交付内容

- **桌面本机能力兼容与升级引导**：
  - 本机 OCR 的「授权监控目录」「停止目录监听」与「截取已授权窗口」在调用 Electron IPC 前读取桌面端 `supportedTypes`。旧主进程未包含 `local_ocr_watch_dir` 或桌面控制路由时，界面明确提示升级至 `v0.2.23`，不再将版本不一致显示为内部 MCP/授权类型异常。
  - 当前桌面主进程已注册 `local_ocr_watch_dir`，并将 `ocr.watch.read`、`desktop.screenshot` 分发至受控目录和原生桌面控制处理器；截图仍要求先授权目标窗口并保留每次操作确认。
- **文字识别工作区操作按钮 2×2 网格对齐**：
  - 将侧边栏 4 个核心操作按钮（「创建任务」、「截取已授权窗口」、「授权监控目录」、「停止目录监听」）由原有流式换行重构为 `repeat(2, minmax(0, 1fr))` 双列等宽等高网格对齐布局（8px 间距，文字居中与多行防折行）。
  - 为各操作按钮补充原生 `title` 气泡提示；按钮文字超出时自适应省略，单按钮或奇数按钮自动跨满整行，彻底解决不同屏幕分辨率下按钮高低不平与不对齐问题。
- **OCR 识别模型服务彻底收拢至系统设置**：
  - 将系统级 OCR 模型服务与业务工作区操作彻底解耦。移除文字识别业务侧栏冗余的内联配置表单（`#ocr-settings-form`），保持业务侧专注任务创建与文档处理。
  - 在「系统设置 → 模型配置（基础模型与算法服务）」中新增第 4 张服务状态卡片「OCR 识别服务」，与向量生成（Embedding）、重排序（Reranker）、检索策略（Strategy）保持统一风格与栅格自适应。
  - 新增独立的 `#ocr-service-modal` 配置弹窗，支持外部 OCR HTTP 服务地址配置（`setting-ocr-service-url`）及实时联通性测试（`ocr-service-test-btn`）。
  - 服务端提供超管专属的 `GET /api/settings/ocr`、`PUT /api/settings/ocr`、`POST /api/settings/ocr-test` API，并在全局设置接口返回只读脱敏的 `ocrConfig`；对非超管及非用户自配的基础模型服务（向量生成、OCR识别、重排序），接口与状态卡片统一脱敏掩码显示服务 URL。
- **工作区状态降级与跨模块联动引导**：
  - 文字识别工作区侧栏新增紧凑型提示条（`#ocr-service-alert`）。当外部 OCR 服务未连接或不可用时温和提示，并提供「前往系统设置配置」快捷按钮，管理员可一键跨工作区跳转至系统设置模型服务页；服务连接正常时自动隐藏不打扰。
- **Ubuntu 离线镜像内置 qpdf**：
  - `Dockerfile` 在运行阶段安装 qpdf，默认使用 `/usr/bin/qpdf`，构建期间执行 `qpdf --version` 作为 fail-closed 自检。
  - `docker-compose.yml` 在 `.env` 未显式指定 `DOCUMENT_QPDF_PATH` 时自动解析为镜像内路径；生产机无需联网安装，也不需要在只读、非 root 容器中临时修改系统包。
- **Ubuntu 离线镜像内置 veraPDF**：
  - 使用官方固定版本的 Greenfield 安装包、SHA-256 校验和无交互 CLI-only 安装脚本构建 `/opt/verapdf/verapdf`；GUI、示例插件和安装器临时文件不进入运行镜像。
  - 运行镜像内置 JRE，`DOCUMENT_VERAPDF_PATH` 默认指向镜像内 CLI；构建期间执行 `verapdf --version`，Compose 允许通过 `.env` 受控覆盖路径。
- **法规待治理工作队列**：
  - 质量概览中的“版本待治理”不再只是计数，管理员可直接进入待治理队列；队列仅包含当前未归档法规的当前版本中效力待核验、审核未通过或缺少当前版本的记录。
  - 每条待办显示效力和审核状态，并提供“处理治理”入口，直接打开对应版本的效力/审核表单；缺少当前版本的法规会引导补充版本。
  - 质量统计与队列均按当前版本口径计算，排除历史版本带来的重复数字，确保“待治理数量”与可处理数量一致。
- **法规质量治理完整闭环**：
  - “元数据待审核”和“缺少维护人”分别进入独立的法规工作队列。管理员在同一份法规编辑表单内补齐法规层级、权威来源、元数据审核状态或维护人后保存，已处理记录会自动从相应队列消失。
  - “索引未完成”队列可对当前版本单项重新入队；该动作只重建向量索引，不会重新 OCR、上传或解析原始文件。索引状态为空、失败、排队或处理中都会被正确计入待办。
  - “条文缺少定位”队列可以按当前版本已抽取正文重建页码与字符范围。若正文不存在，接口明确拒绝并提示需补充原文件后重新解析，避免生成伪定位。
  - “未解析引用”进入单独的引用治理面板：可先执行全库当前版本回连；确属库外资料时可逐条标记为外部/不采用。“引用待审核”则只展示已回连库内条文但尚未人工确认的引用，可逐条确认、驳回，或一次确认置信度不低于 80% 的候选。
  - 质量统计、治理列表及引用队列统一排除已归档/历史版本；全量计数查询与列表查询采用相同口径，消除“概览有数字但点开没有待办”的不一致。
- **法规质量治理一键与批量处理**：
  - 每个法规治理队列均可进入「批量处理」，点击「全选当前治理队列」即可跨页选中当前类别待办（最多 2,000 份）。
  - 元数据、维护人和版本治理通过批量表单一次设置所选字段；未勾选字段保持原值，批量修改保存审计记录并支持在后续未发生修改时安全撤销。维护人仅可选择仍启用的账户。
  - 索引未完成队列可对选中法规一键重新入队；该操作只清理当前版本旧向量、进入可恢复索引队列，不重新上传、OCR 或解析。
  - 条文缺少定位队列支持选中项一键重建。前端每批最多提交 100 份法规以避免大规模请求超时，无法从正文生成定位的法规保留待办并在结果中列出原因。
  - 两类引用队列都支持表头全选与批量结论：已回连引用可批量确认或驳回，未解析引用可批量标记为外部/不采用；保留原有高置信（≥80%）一键确认和全库回连入口。
- **生产向量类型兼容与重排序稳定性**：
  - 新增 `202610140001_regulations_vector_column_compatibility` 迁移。迁移检测到历史 `regulation_articles.embedding` 为 `text`/旧类型时，不在启动事务中改写列类型或重建生产已有 ANN 索引，避免无维度 pgvector 列触发 `column does not have dimensions` 并阻断服务启动。
  - 检测到旧类型后，所有未归档法规的当前版本会清空旧向量并进入 `retry_wait`，由后台索引巡检按当前系统向量模型重新生成，避免旧模型、旧维度或旧 profile 混入语义召回。迁移仅在检测到旧列类型时执行一次，正常 pgvector 新库不会重复全量重建。
  - 法规语义检索和相似条文查询显式使用 `embedding::vector` 与 `vector_dims(embedding::vector)`，兼容迁移前后的短暂窗口，并避免再次出现 `operator does not exist: text <=> vector`。
  - 外部重排序默认候选数调整为 20、请求超时调整为 5 秒，更适合独立 GPU 服务的模型冷启动和短暂排队；只会更新仍为历史默认值的系统设置，既有生产自定义值不被覆盖，失败仍自动保留现有排序。

## 兼容性与安全

- 外部 OCR 服务配置继续复用 `DOCUMENT_PROCESSING_OCR_SERVICE_URL` 环境变量及数据库运行态设置，已配置的服务地址平滑继承。
- OCR 服务的读取、修改与连通性测试接口严格限定为超级管理员权限（`isSuperAdmin`）。
