# v0.2.10 单 IP 网页会话安全加固

发布日期：2026-10-12

## 概述

本版本限制同一账号的网页会话只能使用一个来源 IP。此前刷新令牌绑定浏览器设备标识，但同一账号可在不同 IP 并存登录；本版本为网页访问令牌与刷新令牌建立来源 IP 绑定，并在新 IP 登录时撤销旧 IP 会话。

## 安全行为

### 新 IP 登录接管会话

当用户从新的来源 IP 使用正确密码登录时，服务端在同一数据库事务中：

1. 删除该账号已有的刷新令牌；
2. 递增 `users.token_version`，使旧访问令牌立即失效；
3. 为新 IP 签发绑定来源 IP 的访问令牌和刷新令牌。

因此同一账号不能跨 IP 同时保持网页登录。相同 IP 下的多个浏览器或设备不受影响。刷新令牌若被复制到不同 IP，服务端会撤销对应账号会话并要求重新登录。

### 可信反向代理要求

部署在反向代理、负载均衡、Docker 网关或 CDN 后时，必须配置 `TRUSTED_PROXY_IPS`。系统只会从该列表中的上游读取 `X-Forwarded-For`；未登记代理的转发头一律不可信，并且无法用于建立 IP 绑定会话。

```dotenv
# 示例：仅填写实际直接连接 Pivot 的受控代理地址或私网 CIDR。
TRUSTED_PROXY_IPS=172.20.0.10,10.10.8.0/24
PIVOT_SINGLE_IP_SESSION_MODE=true
```

不要填写任意公网网段或客户端地址段。代理层还应确保 Pivot 端口不被绕过直接暴露，否则请求来源策略将被破坏。

## 升级步骤

1. 在部署前确认反向代理 IP/CIDR，配置 `TRUSTED_PROXY_IPS`；直连部署无需此项。
2. 按常规流程备份 PostgreSQL 数据库并部署 `v0.2.10` 服务端。
3. 重启服务，等待 `202610120002_refresh_token_single_ip_binding` 自动完成。
4. 通知用户重新登录。历史 JWT 不含 IP 绑定声明，升级后会被安全拒绝。
5. 使用两个不同来源 IP 验收：IP-A 登录后，IP-B 再次登录；确认 IP-A 的受保护 API 返回 401、IP-B 可继续使用。

本版本不要求手工删除 `refresh_tokens`，不修改用户密码，也不影响 API Key。若确需临时恢复旧行为，可显式设置 `PIVOT_SINGLE_IP_SESSION_MODE=false` 并重启；生产环境应只将其作为短时故障处置，不应长期关闭。
