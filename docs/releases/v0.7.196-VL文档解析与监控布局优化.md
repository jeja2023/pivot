# v0.7.196 文档解析（VL）与监控布局优化

发布日期 2026-11-21

## 文字识别与文档解析

- 上传图片或 PDF 时可按任务选择「文字识别」或「文档解析（VL）」。普通 OCR 与 VL 使用各自的 HTTP 地址，两个服务可同时运行；任务按所选模式分流。
- 打开任务可逐页对照原件和 Markdown。预览支持标题、表格和公式，外部资源链接不在预览中加载。原版式以页面预览为准。
- Markdown 按原页码输出，并标出失败页和未解析页。已修订的页面使用保存后的文字。失败页重试沿用原模式，保留成功页并生成新版导出。

## 应用服务设置

- 最高管理员可在「系统设置 → 应用服务 → 文字识别 OCR → 配置」分别保存两个地址并测试连接。普通 OCR 使用 `OCR_SERVICE_URL`，VL 可在环境中通过 `OCR_VL_SERVICE_URL` 配置，保存到数据库的地址优先。
- 点击保存立即显示进度，写入完成后关闭弹窗并更新服务卡片，失败时保留输入。外部服务的 DNS 和健康检查由连接测试执行，发起连接时继续校验目标地址。 [OCR 接入协议](../OCR服务对接协议.md)

## 系统监控

「服务与资源」中，硬盘用量与剩余容量、CPU 累计耗时与进程常驻内存分别成对对齐。空间不足时纵向展示。磁盘探针缺少数据时显示「暂无数据」。

## 升级与验证

- 本版源码以 `CHANGELOG.md` 为版本来源。直接运行 Node 的环境重启 Pivot 后刷新页面，访问 `/version.json` 可核对运行版本。OCR 和监控改动无新增数据库迁移，沿用既有任务与配置。
- 本机 Node 访问独立 OCR 容器时，填写 Node 可访问的宿主机地址和实际映射端口。配置后分别测试普通 OCR 与 VL，再提交实际图片和扫描 PDF 核查版面及单页耗时。
- 已通过 OCR 与文档处理专项回归、Chromium 配置面板回归和 13 项监控测试。真实 VL 模型识别质量和性能仍需在部署环境验收。应用服务隔离端到端测试曾因测试服务器启动超时未完成。
