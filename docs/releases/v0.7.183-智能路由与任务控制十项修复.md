# Pivot v0.7.183 发布说明

2026-11-20 · 智能路由与任务控制十项修复

本版修复对话任务控制、知识库和 MCP 路由、自动模型选择及决策治理的 10 项问题。其中 P1 与 P2 各 5 项。

## 十项修复

| 优先级 | 修复项 | 现在的行为 |
| --- | --- | --- |
| P1 | 自动换模型的凭据 | 自动初选、故障切换与成本升级使用当前账号有权调用的模型配置。执行候选使用解密后的 API Key，解密失败的候选会退出选择。 |
| P1 | 模型不可用时的任务控制 | 在验证会话归属后处理明确的停止与暂停。所选模型停用或日额度耗尽时，仍可控制会话里的后台任务。 |
| P1 | 按名称停止与较早任务定位 | 按名称或 ID 定位当前会话的活动任务。活动任务查询按状态过滤，覆盖普通历史列表以外的记录。重名时提示从对应任务卡操作。 |
| P1 | 工具目录异常时的显式范围 | `@工具` 和本轮排除项在正常排序、目录异常、关闭路由或自动发现以及影子模式下共同约束 MCP 规划候选。 |
| P1 | 引用误触发来源撤销 | 行内代码和围栏代码作为待分析内容处理。诸如解释 `不要联网` 含义的消息会保留原文供模型理解，明确提出的来源限制才进入硬规则。 |
| P2 | 影子模式及自动发现开关 | 在整体路由或意图判断处于影子模式时，判断成功或失败都沿用用户显式选择的知识库范围和工具授权。关闭自动发现或进入整体路由影子模式会阻止语义建议自动开启只读工具。 |
| P2 | 执行模型上下文预算 | 选模使用统一的输入预算和消息估算，计入总上下文窗口、输出预留和视觉输入。任务首轮选模会考虑当前消息与历史上下文。 |
| P2 | 正常交付的成本升级 | JSON 和流式交付都能在最终核验前，用剩余时间和额度尝试升级一次总结，并预留核验资源。升级失败保留首次回答，成功采用的新答案按实际模型归因。 |
| P2 | 意图与学习记录的租户归属 | 同一轮对话按可信组织成员关系关联意图、学习和后续路由决策。租户白名单使用解析出的组织 ID，无法确认的归属记录为空。 |
| P2 | 模型调用前的超时明细 | 历史读取等前置阶段达到路由总时限时，系统监控登记一条脱敏事件。错误明细展示失败阶段及可用的阶段耗时，内外层回退共用记录标识。 |

## 升级与使用

- 本次启用 Pivot 主应用源码版本 v0.7.183。沿用已有配置和 PostgreSQL 数据库即可更新，当前修复无需新增迁移、依赖或必填配置。历史决策的租户及模型归因以原始记录为准。
- 对话的任务控制入口和操作示例见[使用帮助的任务控制章节](../../使用帮助.md)。整体路由、意图判断和持续学习的影子开关继续由服务端分别配置。[智能路由实施验收清单](../智能路由持续学习实施验收清单.md)
