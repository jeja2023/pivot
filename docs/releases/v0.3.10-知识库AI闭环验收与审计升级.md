# v0.3.10 - 知识库 AI 闭环验收与审计升级

> **发布日期**：2026-10-16  
> **升级类型**：知识库 AI 统一证据链、语义核验、评测一致性与上线验收升级  
> **兼容性**：向后兼容；不改变用户自有知识库、文档和已授权共享资料的隔离边界

## 版本概述

本版本完成知识库 AI 的剩余产品化闭环：聊天、知识库工作台和黄金集评测不再各自执行不同的检索或回答规则，而是统一经过问题规划、受权限约束的证据召回、引用核验和可追溯审计。

## 统一问答与证据链

- 工作台 `/knowledge/ask`、聊天 RAG 和黄金集评测都复用问题规划与多查询证据合并逻辑。
- 短追问会保留最近一轮用户问题的主题；复合问题最多生成 3 个受控检索变体，合并后重新编号引用。
- 回答只可引用本轮真实、权限过滤后的原始知识片段；Wiki 仅作辅助导航，不能替代原始依据。
- 没有入选证据时稳定返回“知识库中未找到足够依据”，不以模型常识补全。

## 双层依据核验

- 第一层校验引用编号、citation key 与来源片段归属，并对结论与被引用片段进行确定性支持性检查；同一回答中夹带的未引用事实句也会被拒绝。
- 第二层启用模型语义蕴含复核，逐句判断结论是否被其标注的原始来源完整支持。
- 任一核验不通过、核验器不可用或返回格式不完整时，系统以安全依据不足答复替换原模型结论；不会把未核验内容先流式展示给用户。
- 核验状态同步写入聊天 SSE、助手消息路由元数据、工作台响应和评测逐题指标。

## 评测、审计与可观测性

- 黄金集评测的模型答案改用和线上相同的语义核验标准，汇总新增 `groundingAcceptanceRate`；回归比较和缺口报告会识别依据核验失败。
- 新增 `knowledge_ai_answer_logs`：按用户保存提问、改写检索词、最终答复、受控证据摘要、核验结果与用量，不写入跨用户资料。
- 新增当前用户限定的接口：`GET /api/knowledge/answers/metrics` 与 `GET /api/knowledge/answers/history`；不提供非 `admin` 管理员跨用户读取入口。
- 知识库评测页增加近 30 天线上问答次数、依据核验率、平均候选数和平均证据数，区分离线黄金集表现和真实使用质量。

## 权限与治理边界

- 用户继续独立上传、管理和使用自己的知识库、文档、评测集与问答审计。
- 只有系统 `admin` 账户拥有全库重建、共享专题库管理和全局删除审计；其他角色为 `admin` 的账号不获得跨用户治理权限。
- 问答审计、引用解析和多查询合并都建立在既有 ACL/Collection 过滤之后，不能借由审计或指标接口发现他人资料。

## 配置与上线验收

- 新增 `PIVOT_KNOWLEDGE_SEMANTIC_VERIFIER_ENABLED=true`，默认开启语义蕴含复核。
- 新增 `PIVOT_KNOWLEDGE_SEMANTIC_VERIFIER_MAX_TOKENS=700`，限制复核调用的输出预算。
- 新增只读上线验收命令：

  ```powershell
  npm run verify:knowledge-ai-readiness -- --require-256k
  ```

  命令会确认审计迁移、表、索引、语义核验开关以及至少一个活动模型具有不低于 256K tokens 的上下文窗口；不会发送模型请求或读取知识库正文。

## 验证范围

- 知识库规划、证据合并、引用/语义核验、评测指标、权限边界与审计迁移自动化测试已覆盖。
- PostgreSQL 迁移覆盖、索引基线和配置注册表检查已通过。
- 自动化测试已在隔离 PostgreSQL schema 中完成架构初始化和新审计迁移执行；目标生产数据库、QWEN3.6-35B、Embedding 与 Reranker 的真实连通性仍需由部署环境执行上述上线验收命令和实际黄金集验证。
