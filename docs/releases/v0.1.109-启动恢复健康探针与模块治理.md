# v0.1.109 发布记录：启动恢复、健康探针与模块治理

发布日期：2026-09-09

## 缺陷修复

- 服务启动后的知识库索引恢复和智能体恢复均通过统一后台任务包装执行。该包装同时处理同步抛错和异步拒绝，避免数据库短暂不可用时触发全局 `unhandledRejection`。
- 健康检查改用 `peekPgPool()` 读取现有连接池；当连接池尚未初始化时返回退化状态，不以健康检查为副作用创建连接。
- 查询健康探针的竞争超时计时器在任一结果落定后立即释放，并以 `unref()` 保证不会单独阻止进程退出。

## 性能与连接稳定性

- 本机 MCP 连接器的失败重试保持原有 10 秒到 60 秒的指数退避上限，并加入固定范围的 ±20% 随机抖动，平滑同一局域网内多客户端的断网恢复请求峰值。
- RAG 检索的关键词回退结果已写入既有通用结果缓存；该缓存包含用户、检索范围、权限与索引版本，因此没有增加会绕开失效治理的重复缓存层。

## 架构治理

- `client/chat/admin-settings-memory.js` 承载长期记忆的查询、质量看板、批量治理、编辑和分页；`admin-settings.js` 保留全局运行参数与事件协调。
- `server/db/schema/comments.data.json` 承载表级、字段级中文数据字典；`comments.js` 只负责安全转义并生成 PostgreSQL `COMMENT ON` 语句。
- 两个原超千行模块均从架构治理豁免清单移除，后续新增职责将重新受到默认千行门禁保护。

## 验证

- 新增启动异步拒绝捕获、健康探针不建池/清理定时器、重试抖动边界和静态注释 SQL 一致性测试；
- 通过专项 Node 测试、架构门禁、死导出门禁、完整 `npm run check` 与 ESLint。
