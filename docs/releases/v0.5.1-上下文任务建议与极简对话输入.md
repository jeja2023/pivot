# v0.5.1 上下文任务建议与极简对话输入

发布日期：2026-10-19

## 版本摘要

本版本移除聊天输入区常驻的“规划任务”按钮。普通用户不需要先理解 Agent、计划或后台运行等概念：输入区默认只保留“发送”；只有当前输入明显是可执行任务时，系统才在发送按钮旁展示轻量的“生成执行计划”建议。

```text
普通问答 / 创作 → [发送]
高置信任务输入 → [生成执行计划] [发送]
```

点击建议仍然只创建 v0.5.0 的任务草案，进入审阅、编辑与确认流程；不会立即执行。

## 建议出现规则

建议由浏览器本地规则判断，不调用模型、RAG、长期记忆、工具目录或任何远程接口。仅在以下条件之一满足时出现：

- 输入包含明确任务或后台意图，例如任务、工作流、自动化、失败重试；
- 输入包含两个或以上不同执行动作，例如“查询订单、汇总异常并生成报告”；
- 输入同时包含一个动作和明确交付物，例如“整理材料并输出项目风险报告”；
- 用户显式输入 `/task <任务目标>`。

以下内容不会出现建议：概念问答、解释、翻译、润色、改写、续写，以及“写一封邮件”等单次创作诉求。建议并不等于任务已被识别为可执行，也不会提升权限。

## 用户控制与安全边界

- 建议的标题和无障碍标签均说明“先审阅计划，不会执行”。
- 用户关闭建议后，同一会话相同类别的建议不会再次出现。
- 点击“发送”始终按普通聊天处理；不会因为出现建议而自动创建草案或 Run。
- 发送流式回复和草案创建期间，建议自动隐藏，避免重复提交。
- 管理员关闭聊天 Agent 执行能力时，建议不显示。
- 草案仍使用 revision、计划/策略摘要、24 小时过期、确认后启动与 `builtin_only` 的首批受控 Run；执行期审批边界不变。
