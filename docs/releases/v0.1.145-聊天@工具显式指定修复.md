# Pivot v0.1.145 发布记录：聊天 @ 工具显式指定修复

## 问题修复

此前聊天输入框仅输入“@”时，前端把空查询错误地视作不需要加载工具目录；工具候选因此无法显示，用户只能看到知识库。即使工具 API 已按权限返回可用工具，该能力也无法在首个 `@` 操作中被发现。

## 变更内容

- 裸“@”现在会请求当前用户可访问、已通过 Capability 治理的 MCP 工具目录；
- 知识库和工具候选各最多展示 4 项，避免任一类别占满首屏；继续输入可按名称、工具服务或完整工具标识筛选；
- 工具候选使用与实际聊天执行相同的已保存工具白名单过滤，避免“候选可见但发送后必定被排除”的不一致；
- 选择工具会写入本轮 `routeOverrides.tools`，只收窄路由候选，不自动授权、更不会直接执行；未授权时仍由回答中的“启用工具库”操作要求用户确认并重新发送；
- 修复数据节点契约弹窗与向导输入头部标题继承全局 `.modal` 居中对齐的问题，显式重置为靠左对齐以保持界面排版一致。

## 验证

- 专项 Node 回归：聊天输入菜单、自适应路由、安全 MCP、安全聊天及 DAG 编排增强用例共 214 项通过；
- 真实浏览器 E2E：验证裸“@”加载白名单内工具、排除非白名单工具，并确认选择后形成正确的工具路由覆盖；
- 完整 `npm run check` 通过。
