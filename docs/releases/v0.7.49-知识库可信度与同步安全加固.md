# v0.7.49 知识库可信度与同步安全加固

发布日期：2026-10-28

## 改动

- 所有 PDF 原生文本页均进入提取；仅对空白页应用 OCR 预算，逐页记录失败及超限。知识库保存页数、遗漏页、失败页、字符数和截断信息，列表及统计显示“部分就绪”，不把系统截断提示写进正文。
- 正文及向量索引通过暂存事务切换，保存解析覆盖率和索引配置指纹。显式单文档、批量、全库重建以及 Embedding profile 不匹配恢复强制执行；去重时同时核验内容哈希和配置指纹。切换前锁定未删除文档并保留既有启用状态。
- 严格核验时，含拒答标记的回答统一替换为服务端受控拒答；引用编号与 citation key 必须对应相同来源。过滤正文中的伪造引用边界和内部标记。明确需要知识依据且没有结果时，直接返回服务端拒答，不把无依据回答交给模型补写。
- 多查询只对匹配路由查询的子查询复用向量；其他子查询独立计算。个别查询失败不使其他成功结果丢失。
- 本地目录发生截断、跳过软链接或超限文件、处理失败时禁止缺失归档；HTTP 清单需显式声明 `complete: true`，数据库结果需显式证明完整，且不能截断。缺失至少 5 项且超过既有数据 20% 时阻止自动归档。外部 Wiki 页面仅在启用删除同步且保护条件通过时归档；受保护或部分失败的同步标记为部分完成并给出提示。

## 部署与限制

新增 PostgreSQL 迁移 `202610280001_knowledge_index_coverage`，更新服务端并完成迁移后重新加载页面。历史文档在下一次重建后补齐覆盖率和配置指纹；不会自动批量重建历史资料。

扫描页 OCR 预算为每次 10 页，超限或失败会标记部分就绪；按页续处理和删除审批已在 v0.7.50 提供。远程清单没有完整性证明、数据库连接未提供完整结果证明或命中删除保护时，系统保留既有资料，需要管理员检查来源状态。v0.7.50 将权限统一为严格所有者隔离。

验证以隔离 PostgreSQL、可控解析与测试模型为主；生产模型质量、OCR 环境、真实数据源、撤权传播、规模压测及备份恢复仍需在部署环境验收。
