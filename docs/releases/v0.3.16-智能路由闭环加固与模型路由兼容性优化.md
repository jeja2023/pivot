# v0.3.16 - 智能路由闭环加固与模型路由兼容性优化

发布日期：2026-10-16

## 版本概述

本版本对对话自适应路由、统一业务决策器和 Agent 模型路由进行端到端加固。目标是让用户显式选择、检索范围、受治理工具候选、决策输出和最终执行开关保持同一语义，避免在回退、影子观测或异常决策输出时出现意外检索、范围扩大或能力不兼容的模型选择。

## 核心改动

### 1. 显式路由意图优先

- 用户通过 `@工具` 选择受治理工具，或通过 Collection、标签、“带着资料去聊天”指定知识库范围时，下一步决策不再允许把本轮改写为“先澄清”。
- 决策器仍可为资料和工具提供排序建议，但不能取消已经明确选择的执行路径；MCP 授权、白名单、能力过滤和审批链路保持原有约束。
- 路由执行层新增候选一致性校验：只有决策上下文中存在且 `allowed !== false` 的动作才可覆盖基线结果。缺失候选、过时动作或不允许动作均安全回退。

### 2. RAG 回退与影子模式修正

- `ragEnabled` 在自动模式中被明确为“可由路由器使用”的许可，不再在关闭自动路由、关闭自动检索或影子模式中等同于“每轮全量检索”。
- 现代客户端的 `ragPreference=auto` 保持按需路由；手动开启、显式范围、一次性强制检索以及旧客户端未提供偏好字段的请求仍保留检索兼容性。
- 普通问候和一般问答在关闭或影子模式下不会因为回退逻辑触发知识库读取。

### 3. 一次性资料范围闭环

- `routeOverrides` 现在规范化并保留 `tagNames`，Collection 与标签会一并形成服务端检索范围。
- 从召回测试进入聊天仅通过一次性覆盖传递范围；不再复制到聊天区控件，也不再写入持久 RAG 开关或偏好。
- 覆盖在消息提交后清理；如因 MCP 授权需要续跑，已清理的覆盖会随授权续跑事件安全传回，确保同一轮仍使用原范围。

### 4. 模型路由兼容性

- `auto-vision`、`auto-context`、`auto-cost`、`auto-load`、`auto-quality` 与 `auto-escalate` 均从同时满足视觉能力和输入窗口的候选中选择。
- 自动选择找不到兼容模型时会给出明确失败，不再静默回退到不支持图片或无法容纳上下文的端点；固定模型策略仍保持原行为并由既有预检提示不兼容配置。
- `auto-escalate` 先过滤掉并不比当前模型更强的候选，再按最小成本增幅与可用上下文排序，避免“更贵但窗口更小”的模型遮蔽真正可升级选项。

## 兼容性与迁移

- 不新增数据库迁移，不改变既有决策审计、权限、授权或审批数据结构。
- 保留旧客户端显式 `ragEnabled` 请求的兼容处理；新客户端在 `auto` 状态下继续采用按需检索。
- 已保存的 `pivot_chat_rag_preference=enabled` 或 `disabled` 会继续生效；一次性 `@` 选择和召回调试不再改变该长期偏好。
