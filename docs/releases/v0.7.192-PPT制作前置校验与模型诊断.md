# Pivot v0.7.192 发布说明

2026-11-20 · PPT 制作前置校验与模型诊断

## 引文核对与续作

- 在宿主管理的完整制作中，最终清单阶段发送制作协议、材料及所选模板规范。绘制流程文档留在检查点，进入制稿阶段恢复。引文修复轮提供保存的完整清单及当前待核对项，避免多次续跑时重复发送旧修复提示。
- 待核对项使用与页码、项号、标题和当前正文绑定的条目标识。模型提交标识、来源路径和连续原文即可定向修复。仍兼容按页码、项号和原正文提交的旧版局部修复。
- 同批有效修正通过原文校验后可保留。失效、重复或格式错误的修正条目单独处理，无依据的正文或数值更改会撤回。保存的完整清单继续约束页序、已核实事实和模板使用。
- 待核对阶段的格式错误和页数错误也计入修复限额。已有完整清单时，限额用尽后仅对还不能核实的内容使用「数据待核对」占位。缺少可用完整清单时保存检查点。补充的事实继续作为独立来源核验。

## 写入与项目校验

- 默认完整制作写入设计规范和执行锁后，宿主根据两份文件的有效写入回执自动调用项目校验，通过才继续写页面。失败时模型收到执行器回执，明细显示设计规范、执行锁、沟通字段或模板引用等问题类别。相同内容可复用失败结果，文件修正后复检。恢复时可接续尚未执行的校验。
- 在宿主管理的默认和快速初稿中，源页文件名页码与清单顺序绑定。逐页写入前检查 SVG 中的完整标题及可见正文，支持原生表格单元格及同行数据。首张有效写入后自动执行单页版式检查，通过才继续批量制作。版式失败时展示可识别的具体原因，例如模块缺少边界、字号未声明、文字溢出或区域重叠。
- 已通过的写入与检查进度在检查点保存。重启时可补做尚未完成的首张检查。已有首张写入回执的旧任务可按原流程续作。整稿复检、按页修复以及最终 PPTX 页序、正文、图表和保留页核验继续执行。

## 动作兼容与诊断

- 写入动作可使用 `content` 作为 `text` 的兼容写法，零偏移按完整文件写入。仅作说明的短文本字段由宿主移除。未知参数、正文冲突或非零写入偏移会被拒绝，诊断显示同批序号、动作和字段要求。
- 读取当前项目中尚未生成的可选校验记录时，记录显示「记录尚未生成」，同批其他动作可继续执行。重复读取这种记录不会计作进展。
- 每轮明细区分清单页数错误、引文修正、源稿不符、单页 SVG 失败、宿主复检失败、模型连接提前关闭、上游 HTTP 504 和 Pivot 等待超时。连接失败后保存检查点，续跑优先整理历史。

## 升级与复验

- 容器部署构建并替换包含 v0.7.192 前端、后端及更新日志的 Pivot 主应用镜像。保留现有兼容的 PPT Master v6.10.0 独立服务镜像、访问配置和持久任务卷。相对 v0.7.191 无新增数据库迁移或必填配置。[部署说明](../deployment/PPTMaster独立服务部署与更新.md#v07192-ppt-制作前置校验与模型诊断)
- 使用原材料、同一模型端点和相同请求配置做升级前后复验，记录首张写入、项目校验、最终回读、耗时和令牌。若生产端点仍在约 150 秒中断，按失败时间核对网关和推理服务日志。截图中的 Pivot 请求时限为 300 秒，实际断开位置尚未确认。

- 升版后通过 `npm run check`、`npm run lint`、`npm run typecheck`、96 项 PPT 定向测试及 12 项隔离 PostgreSQL 测试。软件包、锁文件、README 和运行时版本一致，7 个发布文档链接有效。本地 3002 的 `/version.json` 返回 `v0.7.192`。
- 用开发环境「汇报测试」已保存的 SVG 回放。首次自动修页前取到的前 6 张，均在新的写入前校验中定位到内容不符。修正后的 8 张 SVG 全部通过新校验。
- 升版前通过 3 项 Docker 端到端回归。测试使用模拟模型和真实 PPT Master v6.10.0 执行器，覆盖默认制作、所选模板的修页交付、引文占位及 PPTX 回读。
- 本次启用源码与本地开发版本。正式发布制品构建、生产部署、自部署端点同单复验以及真实模型耗时和令牌对比仍待进行。
