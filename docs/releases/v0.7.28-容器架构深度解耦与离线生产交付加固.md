# v0.7.28 容器架构深度解耦与离线生产交付加固

## 一、版本概述

**发布版本**：v0.7.28  
**发布日期**：2026-10-22  
**更新定位**：生产环境交付与架构重大演进（Docker 生产镜像解耦瘦身、通用语音微服务化、离线无网加载加固）

针对生产环境容器打包体积偏大（由 PyTorch 深度学习依赖导致的 1.41GB tar 归档）、无网络隔离环境直接导入镜像（`docker load`）时的超时风险、以及语音模型与主系统品牌强绑定的问题，本版本进行了深度架构重构与交付加固：

1. **AI 语音大模型引擎彻底解耦为通用独立微服务**：将 PyTorch 2.8 CPU、TorchAudio 与 FunASR 离线推理引擎完全剥离为主应用外的独立微服务容器（`speech-service:latest`），去除私有品牌前缀，支持内网多项目通过标准 REST/WebSocket 协议共享调用；
2. **切换 slim 基础镜像，生产归档体积锐减 57%（1.41G -> ~600MB）**：运行时基于官方 `node:22-bookworm-slim` 精简基线，彻底剔除 Debian buildpack 中近 813MB 无用编译器与头文件；
3. **无互联网生产环境直接加载（`docker load`）深度加固**：配置 `pull_policy: never` 杜绝离线卡死，参数化镜像标签与端口映射，修复 Linux 挂载目录 `logs` 权限盲区，并全面规范了根目录下所有 Compose 配置文件的专业注释说明。

## 二、核心架构升级详情

### 1. 深度学习引擎彻底解耦与通用语音微服务化

* **架构解耦**：
  * 主应用容器专注于 Web 交互、知识库路由、工具编排与 Agent 任务生命周期，不再嵌入笨重的 PyTorch 深度学习运行时；
  * 主应用保留轻量级（未压缩仅 ~110MB）的 Vosk 离线模型作为默认单机兜底识别（`PIVOT_VOICE_PROVIDER=local`），实现零外部依赖开箱即用；
  * 高精度中文双遍语音识别（FunASR Paraformer + CT-Transformer + Silero VAD）由专用独立微服务容器 `docker/speech-service` 承载。
* **通用微服务命名与共享能力**：
  * 镜像命名由特定专属标签 `pivot-speech:1` 重构为通用的 **`speech-service:latest`**，容器名为 `speech-service`；
  * 对外暴露标准 HTTP 接口（`POST /v1/speech/transcriptions`）与 WebSocket 接口（`/v1/speech/stream`），支持 Bearer Token 鉴权与单模型会话锁；
  * 局域网内的任何其他项目、会议记录系统或业务系统均可直接复用该服务，主应用通过外部共享网桥 `ai-bridge` 接入。

### 2. 运行时基线切换与镜像体积锐减（1.41G -> ~600MB）

* **剔除无用构建工具链**：
  * 运行时基础镜像由完整版 `node:22-bookworm` 切换为官方精简版 `node:22-bookworm-slim`；
  * 彻底剔除 Debian buildpack-deps 中包含的 gcc、g++、make、ImageMagick、git、subversion 等近 813MB 编译器及开发工具链；
  * 在依赖预构建阶段清理 `__pycache__`、测试用例与开发缓存，添加 `PYTHONDONTWRITEBYTECODE=1`；
* **归档体积与交付效率**：
  * `docker save -o pivot.tar pivot:latest` 导出归档体积由 **1.41 GB 缩减至约 600 MB**，减幅超过 57%；
  * 日常业务补丁发布构建与网络传输时间大幅降低，极大缓解离线介质刻录与专网文件传输压力。

### 3. 无互联网隔离环境直接加载（`docker load`）深度加固

* **显式声明 `pull_policy: never`**：
  * 在完全断网或无公网访问权限的涉密/专网服务器上，若镜像未提前载入或标签拼写微差，Docker 默认尝试连接 Docker Hub 会导致 30~60 秒的 TCP SYN 超时卡死；
  * 显式指定 `pull_policy: never`，强制 Docker Compose 仅从本地镜像池读取；若镜像未载入则秒级抛出明确提示，零网络等待。
* **镜像标签与端口动态参数化**：
  * 镜像配置升级为 `image: ${PIVOT_IMAGE:-pivot:latest}` 与 `image: ${SPEECH_IMAGE:-speech-service:latest}`，支持在 `.env` 中无缝指定私有 Harbor/Nexus 仓库前缀；
  * 宿主机端口支持通过 `${PIVOT_HOST_PORT:-9006}:3000` 覆盖，防止生产机 9006 端口冲突时需要改动 Compose 文件。
* **Linux 宿主机挂载目录权限防漏**：
  * 针对非 root（UID 1000）运行机制，同步修复了离线部署脚本中此前遗漏 `logs` 目录授权导致的 `EACCES: permission denied` 隐患，确保 `./data`、`./uploads`、`./downloads`、`./logs` 权限一致。
* **全面规范根目录 Compose 说明注释**：
  * 重新梳理规范了 `docker-compose.yml`、`docker-compose.speech.yml`、`docker-compose.gpu.yml`、`docker-compose.speech.gpu.yml`；
  * 保留了前置命令、环境覆盖、安全挂载、GPU 调度等全部关键配置说明，消除了冗余废弃字段。
