# Pivot v0.7.194 发布说明

2026-11-21 · PPT Master 制稿校验与续跑修复

## 模型预检与上下文

- 模板预检计入所选模板规范、制作要求和清单页数的基础输入。制稿时按当前模型窗口装载必要指引，其余正文可按文件路径和字符偏移回读。
- 项目校验前后使用实际可见的指引区间去除重叠分页。正文内容不同或未被覆盖的区间继续呈现，保留原始检查点。
- 模型预检默认等待 60 秒，支持 `PIVOT_PPT_MASTER_MODEL_PREFLIGHT_TIMEOUT_MS` 配置，取 5000 至 120000 毫秒范围内的值，并受平台单轮模型请求时限约束。预检等待超时提供专用诊断。

## 标题来源、模板规则与整稿修订

- 标题中的业务数字与同页已核对的引文绑定。缺少对应指标、单位和原文依据时进入引文纠正或待核对流程。普通年份及页码按页面标注处理。
- 修改整份初稿时，新任务沿用仍有权访问的原材料、已批准清单和原编号的补充答复，包括续跑中登记的说明。较长的修订资料按页回读后再接纳新清单。
- 模板规则引用须来自规范正文。表格分隔行、表头及字段名不能充当规则，交付继续核对模板、对应页及可见文字。

## 写入参数与旧任务恢复

- 写入、读取和运行动作各自使用独立示例。较早写入在模型历史中改用回执摘要，已完成的写入正文和核验信息仍可回读。旧检查点继续时也会使用更新后的示例。
- 写入接受含义一致的 `file_path`、`filePath`、`content` 别名以及显式 UTF-8 整文件写入。宿主清理零偏移、关闭追加标记和空工具参数等冗余字段。字段冲突、追加、非零偏移或混入其他动作参数时，会在执行前拒绝当前批次。
- 失败轮次记录批内序号、动作类型、可公开的被拒字段和允许字段。其他键只记录位置。自动纠正仍失败时可从原任务的检查点继续，复用已确认的写入回执。

## 素材、执行器与交付

- 浏览器上传前和服务端接纳任务前均核对执行器的 50 MiB 单文件上限，提前提示超限文件。
- 输入快照在完整写入并核对摘要后原子登记。中断可重试，已封存的输入仍按原内容校验。项目校验仅缓存可确定的规范结构错误，临时故障或依赖变化可以重新校验。
- 初稿完成时自动刷新文稿库。离线打包检查 `selectedTemplateRecovery` 和 `atomicInputSnapshots`，复用已构建镜像时也会核对。

## 升级与兼容

- 此次升版无新增数据库迁移。先更新 Pivot 主应用，再在原执行器和任务卷上处理需要续跑的旧任务。原子输入快照由新版 PPT Master v6.10.0 独立执行器提供，建议在旧任务处理完毕后安排切换。 [升级与复验步骤](../deployment/PPTMaster独立服务部署与更新.md#v07194-ppt-master-制稿校验与续跑修复)

## 验证记录

- 本次升版通过 `npm run check`、`npm run lint` 和 `npm run typecheck`，并核对软件包、锁文件、README、设计基线及 8 条发布文档链接。独立本机实例的 `/version.json` 返回 `v0.7.194`。
- 修复批次通过 158 项 PPT 定向回归及项目检查、ESLint、TypeScript 检查。9 项 Linux 执行器测试通过，覆盖输入快照中断和重试。对两个实际镜像的打包门禁复验确认，具备所需能力的镜像通过，缺少能力的旧镜像被拦截。
- 14 个内置模板在 42,000 令牌输入上限下通过清单阶段并进入首轮制稿。模拟端点延迟约 19.35 秒返回有效 JSON，预检通过。
- 在兼容的既有 v6.10.0 执行器上使用模拟模型故意返回错误写入编码。「咨询决策」通过自动纠正交付，「学术研究」在两次拒绝后从同一任务续跑交付，均成功下载 PPTX。加入写入参数修复前，带原子输入快照的新版执行器也已通过这两种模板的交付复验。
- 本版启用源码版本号。正式制品构建、生产部署和自部署模型原任务复验待进行。生产旧记录只有失败动作位置，原轮次被拒绝的字段仍待确认。
