# v0.7.153 图片核验证据与智能路由失败恢复优化

日期：2026-11-12（Asia/Shanghai）。本版针对生产监控截图对应的图片核验证据缺口、意图格式错误、上游超时和文件格式补全完善当前实现，并启用新源码版本。功能阶段在 v0.7.152 / `8b825196` 工作区完成，已有测试日志保留原版本身份。

## 修复后的行为

| 场景 | 本版行为 |
| --- | --- |
| 执行模型能看图，独立核验却只见消息链接 | 核验从当前任务授权的持久消息重新读取上传原图，通过原生图像输入核对答案。图片可以作为识读依据，不需要额外 OCR 调用；`verifiedArtifacts` 仍只表示交付文件，未要求文件时清单为空不表示缺少图片依据。 |
| 图片删除、过期、撤权或核验期间内容变化 | 复用账号、会话和上传路径检查，核验前后比较消息与图像摘要。失效或变化拒绝迟到通过结果；图片超限或模型不支持视觉时明确保留核验缺口。报告仅记录来源编号和摘要，不保存 Base64 或文件路径。 |
| `intent_invalid_contract` 响应损坏或无效 | 剩余预算至少两秒时，针对损坏 JSON、无效字段及输出截断最多补判一次，保留原总截止与相同校验。未知能力、无权来源和越权续接仍被拒绝；两次有响应的实际用量累加记录。 |
| `intent_timeout` 上游提前超时 | 可在原预算内重试一次连接/首响应超时；持续上游超时准确归为意图超时，并保留失败路径排队和上游耗时。总截止与取消不重试，认证、熔断及长 Retry-After 仍遵守既有拒绝边界。 |
| 已有成果缺少指定文件格式 | 先检查已有文件完整性并保留已交付清单，将 `artifact_format_missing` 纳入原有最多两次受限补全，复用成果导出缺失格式，不重复已有业务操作。文件完全未生成仍须通过原有产物检查。 |

工具授权、逐操作审批、来源限制、执行轮次和累计预算继续生效。失败恢复不把模型承诺、文件名或工具契约视为真实交付。

## 升级与兼容

- 没有新增依赖、数据库迁移或必填配置，沿用现有部署流程。更新源码并重启服务后，页面资源版本及 `/version.json`读取 v0.7.153；桌面安装包和容器镜像需另行构建，旧制品保持原构建身份。
- 默认 30 秒意图总预算保持不变，提前超时的重试与格式补判都在原预算内完成。持续慢响应仍可能超时，不能承诺消除所有上游故障。
- 图片任务应选择支持视觉输入的模型，并确保原图仍在当前账号和会话的授权范围内。原图失效或超过单次数量上限时，按缺口提示重新提供或分批处理。
- 已有失败事件保留原始记录。升级不会自动重放任务或把历史失败改成成功；先查看已完成结果和外部操作记录，再决定是否重试，避免重复副作用。
- 本版同步使用帮助、设计规范和修复记录；原工作区中其他审查报告的修改保持原样。
