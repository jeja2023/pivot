# v0.7.85 已停用全局模型可见性隔离

日期：2026-11-03。本版本记录工作区改动；更新版本号不表示已经构建、部署或完成生产验收。开发基线为 v0.7.84。

## 行为变化

- **已停用全局模型对普通用户隐藏**：管理员在后台将全局模型停用（`status = 'disabled'`）后，普通用户调用 `GET /models` 获取模型配置列表时，全局模型强制仅返回 `active`（已启用）状态的模型。普通用户的“模型配置”列表与对话模型下拉选择框不再展示带有“(已停用)”占位且无法操作的全局模型，避免界面混乱。
- **普通用户私有模型停用管理不受影响**：普通用户自行创建的私有模型在停用时，依然正常展示在个人模型配置列表中，状态标记为“已停用”，且保留“开启”按钮供用户自主管理。
- **全局停用模型测试门禁加固**：后端 `getTestableModel` 与前端 `canTestModelConnection` 增加状态阻断；普通用户不能对处于停用状态的全局模型发起测试请求（接口返回 403 权限拒绝），前端对已关闭的全局模型不再渲染“测试”按钮，仅允许管理员对停用模型进行运维测试。
- **模型选择框空状态防残留**：对话界面顶部模型下拉选择框在可用模型列表为空（`models.length === 0`）时，除了展示“暂无可用模型”并将选择按钮禁用外，同步清空 `hiddenInput.value`，防止表单中残留已下线的模型 ID。

## 验证与限制

- 隔离 PostgreSQL 测试（`tests/model-status.test.js`）通过，覆盖管理员管理停用全局模型、普通用户列表彻底隐藏停用全局模型、普通用户正常保留本人停用模型，以及普通用户测试已停用全局模型被 403 阻断。
- 文本规范与相关代码检查通过。未执行全量回归或生产环境联调，未构建发布包。此前关于多节点演练和生产部署的既有限制继续适用。
