# v0.3.21 - Agent 运行 SLO 监视 PostgreSQL 语法修复

发布日期：2026-10-18

## 问题

维护调度器执行 Agent 运行 SLO 监视时，日志可能出现：

```text
运行 SLO 监视执行失败：语法错误 在 "$1" 或附近的
```

根因是上下文压缩指标查询使用 PostgreSQL JSONB 的 `?` 存在性运算符；项目数据库客户端兼容 `?` 形式的参数占位符，会将该运算符错误转换成 `$1`，使最终 SQL 无效。

## 修复

- 改用等价且不与参数占位符冲突的 `jsonb_exists(e.payload, 'compaction')`。
- 新增系统管理员实际执行 `getAgentMetrics` 的 PostgreSQL 回归，确保 SLO 监视路径能够完成压缩指标聚合。
- 保持低样本不告警、阈值越界才通知系统管理员的既有语义不变。

## 部署

修复发布后需重启 Pivot 服务或执行滚动重启；已运行的 Node.js 进程会继续保留旧模块，直到重新加载。重启后下一轮维护调度即可使用新查询。

## 验证

- `tests/agent-monitoring-slo.test.js`：6/6 通过。
- PostgreSQL 指标查询在管理员作用域下实际执行，通过 JSONB 压缩条件聚合。
- SQL 审核与架构治理检查通过。
