# v0.7.0 自然对话架构闭环与产品验收

发布日期：2026-10-19。

本版补齐 v0.6.0 复核中发现的语义误路由、任务续接、幂等、能力约束、交付验收、偏好治理、学习评测与效果指标缺口。工程实现与目标环境运营验收分开记录；没有真实生产数据或独立审核签署时，不认定五分生产成熟度。

## 1. 用户行为

| 输入 | 处理 |
|---|---|
| 解释向量检索、翻译或写一份报告 | 直接回答，不调用任务分类模型 |
| 可以帮我分析附件并生成报告吗 | 语义解析后自动建立受控任务，无需选模式 |
| 他让我完成报告的要求是什么 | 讨论与引用，不建立执行授权 |
| 按刚才方案修改并测试 | 解析相关方案；有活动任务时绑定同一 Run；没有活动任务且目标充分时建立新任务 |
| 这次只给摘要 | 活动任务通过持久控制消息修订目标、限制和交付要求 |
| 先给方案，不要改代码 | 暂停相关活动任务、撤回后续执行能力，仅交付计划 |
| 停止、暂停当前任务 | 定位当前会话唯一活动任务；多任务时只澄清对象 |
| 以后报告先列异常 | 在自动学习与记忆许可内保存有来源的个人偏好；关闭时仅影响当前对话 |
| 这个口径只用于当前项目 | 将最近偏好收窄为当前资料项目或会话项目 |
| 忘掉刚才那个偏好 | 撤销唯一对应记忆并抑制同来源自动重建 |

当前项目由服务端根据有权访问的资料范围生成稳定标识；未选择资料时使用当前会话项目。它不会将一句自然语言中的任意项目名视为跨会话访问权限。组织规则沿用会话系统要求、企业权限和共享资产发布治理，个人纠正不能修改其他用户的默认行为。

## 2. 工程模块

| 需求 | 实现 |
|---|---|
| 语义契约 | `chat-intent-resolver.js`：动作、目标、限制、交付物、已注册能力、消息引用及续接目标校验；候选调用有超时与取消 |
| 持久身份 | `chat_conversation_turns`：请求摘要、唯一键、用户消息、运行、任务身份、租约、结果和安全路由摘要 |
| 助手回写 | `messages.conversation_turn_id` 唯一关联，覆盖落库后进程中断的重试恢复；Agent 结果继续使用原有 `agent_run_id` 唯一关联 |
| 多轮接续 | `chat-task-continuation.js`：控制消息使用当前消息幂等键，等待输入时按同 Run 检查点恢复；已结束任务不会原地重开 |
| 能力边界 | `agent-policy`、工具目录准备、执行计划与 Orchestrator 同时收窄；每次调用重新读取当前范围；历史批准不覆盖新撤回 |
| 后台审查 | `chat-action-review.js`：只允许平台已知的只读适配器进入独立范围审查；强制人工或有副作用的动作不参与 |
| 验收 | `chat-task-verification.js`：逐项交付语义核验、真实 rendition 及 CAS 字节摘要检查；失败进入未完成状态 |
| 长附件 | `chat.read_source`：只读取当前用户、当前任务、原消息和有效会话的分页内容；覆盖区间可核验 |
| 偏好 | `chat-memory-actions.js`、`chat-preference-context.js`：直接对话操作、事实键纠正、项目范围、有效来源、遗忘抑制 |
| 学习 | `agent-learning-evaluation.js`：独立人工正面样本、冻结评测、候选版本摘要绑定、异步恢复、个人灰度、用户纠正暂停 |
| 开关竞争 | 学习设置每次新鲜读取；关闭与发布共用设置行锁；记忆修订栅栏阻止关闭前抽取继续提交 |
| 指标 | `/api/chat/execution-metrics`、系统监控：路由版本、动作、核验、纠正、复用、首字时延与模型开销；不收集新一份问题正文 |

## 3. 评测与学习门禁

个人 Skill 自动推广需要：来源仍有效；至少五个与技能相关且不重复、非来源任务的独立人工正面样本；候选已通过既有结构、能力、供应链和隔离验证；评测结果逐一绑定该候选版本及内容摘要；冻结结果通过 contract/scenario 质量门禁。模型生成候选、用户沉默和单次任务状态均不能替代这些证据。

自动经验匹配先对个人请求稳定抽样 20%；至少十次终态运行、五次真实正面反馈和不低于 90% 的独立交付核验通过后才扩大至 100%。这些是保守的发布策略参数，不是宣称业务已经达到相应效果。任何自然纠正或低评分都会暂停当前自动经验；已有版本、技能熔断、回滚和来源复核机制继续负责复用治理。

没有足够独立样本时，系统自动完成可完成的候选与验证工作，保留待审阅草稿，准确说明缺少证据。不能复制来源任务凑足样本，不能拿其他技能/工作流评测冒充当前候选验证。

## 4. 配置与回退

| 配置 | 默认 | 作用 |
|---|---|---|
| `PIVOT_CHAT_INTENT_MODE` | `active` | `shadow` 只记录语义建议并直答；`disabled` 停止任务语义调用 |
| `PIVOT_CHAT_INTENT_TIMEOUT_MS` | `30000` | 候选任务裁决总超时，包含排队；失败保留请求并说明阻断 |
| `PIVOT_CHAT_INTENT_ROLLOUT_PERCENT` | `100` | 按用户和会话稳定分桶，0 立即回到影子 |
| `PIVOT_CHAT_BACKGROUND_REVIEW_ENABLED` | `true` | 已知只读适配器的独立范围审查 |
| 系统设置“自动处理明确委托” | 开启 | 关闭自然语言自动创建任务 |
| 系统设置“允许聊天启动受控任务” | 开启 | 聊天创建任何 Run 的总许可 |

停止、暂停和遗忘属于用户控制行为，不因自动执行开关关闭而失效。既有已批准具体动作仍须核对输入摘要、对象、有效期及撤销；普通习惯绝不能签发执行授权。

升级会执行迁移 `202610190002_chat_conversation_turns`，新增账本及消息关联列、索引，无破坏性数据转换。回退先将语义路由设为 shadow 或关闭自动处理，保留账本、来源、运行和审批记录。不要删表或回滚已经发生的外部操作来模拟版本回退。

## 6. 生产验收边界

仓库可交付的行为、迁移、权限、故障恢复与评测机制均须有自动化回归。生产真实数据上的成功率、长期习惯改善、部署环境负载、目标浏览器与设备矩阵、第三方可用性、独立人工核验和委员会签署只能在目标环境测得。本版本提供指标和验收入口，不能代替这些真实观测或伪造其结果。
