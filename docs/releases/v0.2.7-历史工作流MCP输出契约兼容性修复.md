# v0.2.7 历史工作流 MCP 输出契约兼容性修复

发布日期：2026-10-12

## 概述

本版本修复了历史工作流调用 MCP 查询工具时可能出现的 `TOOL_OUTPUT_INVALID` 错误。问题发生在工具本身已经成功返回数据后：更新后的统一工具策略执行点会把未声明输出 Schema 的旧工具当作“必须返回对象”，从而错误拒绝实际为数组或文本的有效查询结果。

## 修复内容

### 未声明输出 Schema 不再隐式要求对象

工具的输出契约现在只在作者明确提供 `outputSchema` 或 `output_schema` 时生效。

- 未声明输出 Schema：保留工具返回的对象、数组或文本结果，不进行类型收窄校验。
- 明确声明输出 Schema：继续按声明进行严格校验；不符合契约的结果仍返回 `TOOL_OUTPUT_INVALID`，以便定位工具实现或契约配置问题。

这一区分同时适用于历史 MCP 缓存和统一工具策略执行路径。历史缓存通常只保存输入 Schema，缺少输出 Schema 现在表示“未声明”，而非“返回对象”。

### 对既有工作流的影响

- 不需要编辑、重新发布或迁移既有工作流。
- 不需要修改查询 SQL、节点参数或下游变量引用。
- 数据查询返回数组、纯文本或包含 `structuredContent` 的 MCP 结果时，系统会保留其原有形态供工作流后续节点使用。
- 已显式配置输出 Schema 的工作流与工具维持现有严格校验，不会因为本次兼容修复放宽已声明的结果结构。

## 升级步骤

1. 按常规流程部署 `v0.2.7` 服务端与桌面客户端版本。
2. 重启服务，使新的工具契约归一化逻辑生效。
3. 使用原有输入重新运行此前失败的工作流。
4. 如果错误仍然发生，检查该工具是否明确配置了输出 Schema；此时错误表示实际结果确实不符合该已声明的契约，而不是旧工具兼容性问题。

本版本不包含 PostgreSQL 迁移，也不会改写历史工作流、工具缓存、工具目录版本或调用记录。升级前后仍建议遵循既有流程备份数据库和附件目录。
