# v0.1.89 发布记录：Agent 持久执行与智能体交互升级

## 版本概述

**发布日期**：2026-09-07  
**版本号**：v0.1.89  
**适用范围**：Pivot Web 端、Agent 运行时、聊天 Agent、任务中心和服务端模型转发链路

本版本针对长时间思考模型、连续代码任务和 Agent 运行中断问题，参考 ChatGPT Agent 的过程可见、可中断、关键动作确认，以及 Claude Code 的持久会话、后台任务、会话恢复和并行任务管理思路，对 Pivot 的 Agent 运行时进行可靠性升级。

## 一、核心更新

### 1. 持久执行与自动续跑

Agent 不再把一次模型 HTTP 请求视为完整任务。现在任务被拆成多个可恢复时间片：

```text
任务目标
  → 规划时间片
  → 工具执行
  → 持久化检查点
  → 观察与重新规划
  → 时间片结束时自动排队
  → 从检查点继续
```

当模型请求超时或当前时间片结束时，系统会：

- 保留已完成的规划、工具结果、检查点和审计事件；
- 同一个任务重新入队，不创建用户难以追踪的重复任务；
- 从最新安全检查点继续，而不是从头执行；
- 显示自动续跑次数和当前恢复位置。

自动续跑默认最多 12 次、总运行时长最多 2 小时，并继续受 Token、步骤、工具、风险和文件写入预算限制。

### 2. 非幂等操作安全恢复

如果时间片结束时存在尚未提交的工具检查点，系统不会直接重放：

- 幂等只读操作允许由检查点恢复流程重新确认；
- 非幂等写操作、删除、发送、导出等动作进入审批门；
- 用户拒绝后任务停止，用户批准后才继续；
- 不会因为自动续跑造成重复文件、重复通知或重复外部副作用。

### 3. 模型请求与任务总时限分离

旧逻辑把 Agent 模型调用固定限制在 180 秒，慢速思考模型容易在正式输出前被中断。本版本拆分为三个独立概念：

- `AGENT_RUN_TIMEOUT_MS`：单个运行时间片的总时限；
- `AGENT_MODEL_REQUEST_TIMEOUT_MS`：单轮模型请求的最长时限；
- `AGENT_MODEL_FIRST_RESPONSE_TIMEOUT_MS` / `AGENT_MODEL_STREAM_IDLE_TIMEOUT_MS`：首响应和流式无进展看门狗。

持续产生数据的长推理不会被“空闲超时”误杀。只有模型没有开始响应，或已建立流但持续没有新数据，才会被判定为调用链异常。

### 4. 流式链路可诊断

每次 Agent 流式模型调用记录：

- 请求发起时间；
- 首字节时间；
- 首个有效 SSE 帧时间；
- 累计收到字节数；
- 流完成时间；
- 首响应超时或流空闲超时原因。

因此，任务详情可以区分“模型推理慢”“模型网关缓冲”“Pivot 转发异常”“上游流断开”和“任务预算耗尽”。

### 5. 工具规划阶段降低思考开销

新增：

```env
AGENT_TOOL_PLANNING_THINKING=false
```

默认关闭工具选择、参数组装和结构化 JSON 规划阶段的长思维链。最终总结仍可以沿用思考模型配置。这样简单的“写一个 Python 五子棋程序”不会把大量 Token 消耗在工具选择上。

如确实需要复杂工具规划，可以设置：

```env
AGENT_TOOL_PLANNING_THINKING=true
```

### 6. 运行中调整方向

聊天页面和 Agent 任务详情增加「调整方向」操作。任务运行期间，用户可以追加：

- 变更实现重点；
- 指定输出格式；
- 要求先测试再交付；
- 要求停止某个探索方向；
- 补充验收条件。

新指令通过 AgentControl 持久化消息进入下一轮规划，原任务继续沿用已有检查点和权限边界。

### 7. 统计口径修正

修复长任务中 `73 Tokens / 0.3 t/s` 这类误导性展示：

- Agent 最终错误提示不再被当作模型输出 Token；
- 任务总墙钟时间不再直接冒充模型 decode 速度；
- 无法获得可靠模型输出用量时显示“模型未返回可计量输出”；
- 聊天 Agent 任务展示真实任务耗时、累计模型用量和运行状态。

## 二、配置项

`.env.example` 与 README 已补充以下配置：

```env
AGENT_RUN_TIMEOUT_MS=600000
AGENT_MODEL_REQUEST_TIMEOUT_MS=600000
AGENT_MODEL_FIRST_RESPONSE_TIMEOUT_MS=300000
AGENT_MODEL_STREAM_IDLE_TIMEOUT_MS=120000
AGENT_TOOL_PLANNING_THINKING=false
AGENT_AUTO_CONTINUE_ON_TIMEOUT=true
AGENT_MAX_AUTO_CONTINUATIONS=12
AGENT_MAX_TOTAL_RUNTIME_MS=7200000
AGENT_TOOL_TIMEOUT_MS=120000
```

生产环境建议先观察模型实际首响应和流式进展，再按模型部署方式调整请求时限；不要仅通过无限放大总超时掩盖网关缓冲或模型端点异常。

## 四、升级说明

本版本的 Agent 与聊天前端资源由服务端统一提供，远程模式部署服务端后即可生效。若使用打包桌面客户端，只要客户端已能加载当前远程 Web 资源，不需要因为 Agent 运行时改动单独重新打包；涉及前置桌面交付窗口或本机能力变更时，仍需同步更新桌面安装包。
