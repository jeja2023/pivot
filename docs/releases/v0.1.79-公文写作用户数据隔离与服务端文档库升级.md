# v0.1.79 发布记录：公文写作用户数据隔离与服务端文档库升级

发布日期：2026-09-05

## 一、更新背景

在旧版本中，公文写作应用（Apps Workbench）的多文档库状态管理（包括公文正文、素材、批注、建议、版本快照等）依赖于浏览器客户端的 `localStorage`（如 `pivot_official_writing_library_v2` 与 `pivot_official_writing_state_v1`）。这种实现方式存在如下安全与架构瓶颈：

1. **跨账号数据暴露隐患**：当不同用户共用同一台终端电脑，或在同一个浏览器上切换不同账号登录时，后登录的用户可能读取到前一用户残留的公文草稿和内容，违背企业级应用的数据安全隔离原则；
2. **浏览器本地存储容量受限**：`localStorage` 通常只有 5MB 容量上限，长篇公文、复杂批注及多版本历史容易触发 `QuotaExceededError`；
3. **多端同步缺失**：用户的公文数据绑定在单一浏览器本地，换机或跨设备后无法漫游与协同。

## 二、架构重构与改造方案

### 1. 服务端用户专属文档库架构
- **双栈数据库表设计**：在 SQLite 和 PostgreSQL 双栈架构中新增 `official_writing_documents` 业务表（`server/db/migrations/official-writing-documents.js` 与 `server/db/schema/base.js`），核心字段包含：
  - `id`: 主键自增 ID；
  - `user_id`: 所属用户 ID（外键级联，强制隔离边界）；
  - `client_id`: 客户端稳定标识，设置 `UNIQUE(user_id, client_id)` 唯一索引；
  - `title`, `manual_title`: 公文标题与手动命名标志；
  - `state`: 序列化状态 JSON（正文、素材、批注、建议与快照）；
  - `version`: 服务端持久化版本；
  - `deleted_at`: 软删除时间戳。
- **全量数据字典与迁移拓扑扩充**：在 `server/db/schema/comments.js` 中补齐表级与字段级中文元数据注释字典，业务表覆盖数量由 79 张扩充至 80 张；在 `scripts/migrate_sqlite_to_pg.js` 与 `scripts/verify_pg_migration.js` 中纳入该表的数据迁移与一致性核验拓扑。

### 2. 服务端数据服务与安全路由
- **严格用户隔离服务层**：新增 [`server/services/official-writing-documents.js`](../../server/services/official-writing-documents.js)，提供列表查询、幂等保存与软删除方法。所有 SQL 查询与更新均将 `user_id = ?` 作为强制条件，杜绝任何形式的跨用户横向越权。
- **RESTful 安全接口**：在 [`server/routes/apps/index.js`](../../server/routes/apps/index.js) 中新增标准接入路由，均配置 `authMiddleware` 强鉴权与安全审计日志：
  - `GET /api/apps/official-writing/documents`
  - `PUT /api/apps/official-writing/documents/:clientId`
  - `DELETE /api/apps/official-writing/documents/:clientId`

### 3. 前端彻底剥离本地存储与安全擦除闭环
- **全链路服务端 API 驱动**：在 [`client/chat/apps-workbench-core.js`](../../client/chat/apps-workbench-core.js) 与 [`client/chat/apps-workbench-editor.js`](../../client/chat/apps-workbench-editor.js) 中，彻底废弃对 `localStorage` 的读取与写入，改为从服务端 API 加载与持久化。
- **防抖与即时保存机制**：普通内容输入采用 450ms 防抖保存；文档切换、新建、重命名、删除或退出时触发立即保存，保障编辑体验丝滑且数据不丢。
- **本地残留缓存主动清理与登出擦除**：
  - 启动时自动执行 `purgeLegacyOfficialWritingStorage()` 清理旧版 localStorage 存储；
  - 在登出流程（[`client/chat/auth.js`](../../client/chat/auth.js)）与 401 鉴权失效拦截（[`client/chat/config.js`](../../client/chat/config.js)）中，主动移除 `pivot_official_writing_*` 键值，彻底杜绝换登后的本地数据残留。

### 4. 架构治理与新增大文件防护
- 将通用 AI 调用驱动函数 `runAppsAiCompletion` 抽取并封装至 [`server/routes/apps/helpers.js`](../../server/routes/apps/helpers.js)，使核心路由文件 [`server/routes/apps/index.js`](../../server/routes/apps/index.js) 控制在 ~820 行，严格遵守存量文件 $\le 1000$ 行的架构治理红线。
