# v0.1.163 发布记录：对话执行凭据与交互体验优化

发布日期：2026-09-22  
版本号：v0.1.163

## 发布结论

本版本收敛聊天中的内部路由展示，并修复首次启用工具时需要用户重新发送消息的交互断点。路由仍在后台进行，用于知识库与工具选择，但只有实际影响回答依据或需要用户操作的执行信息才会展示。

## 对话：从“路由提示”到“执行凭据”

普通对话不再出现“智能路由”或“本轮按普通对话处理”等固定卡片。聊天界面现在遵循以下规则：

| 场景 | 展示方式 |
| --- | --- |
| 普通对话 | 不显示内部路由信息 |
| 知识库命中 | 回答底部显示“参考资料 · N 份资料”，可打开引用来源 |
| 工具执行中 | 仅在生成前显示短暂执行状态 |
| 工具执行完成 | 回答底部显示“已使用工具 · 工具名” |
| 首次需要工具 | 显示“允许并继续 / 直接回答”决策提示 |
| 工具失败、缺少工具或需要修复配置 | 保留带操作入口的提示 |

长期记忆属于后台上下文增强，不再占用每条回答的可视区域。

## 工具授权与无重发续跑

当自适应路由发现当前问题可由已授权工具处理、但当前浏览器会话尚未授权工具库时：

1. 服务端保存用户消息后暂停本轮，不调用模型生成一份无工具的重复回答，也不执行工具；
2. 界面提供“允许并继续”与“直接回答”；
3. 选择“允许并继续”后，用户完成会话级工具授权，系统自动以原始消息 ID 续跑，同时保留 `@` 指定的工具和知识库范围；
4. 选择“直接回答”后，系统复用同一条原始消息生成普通回答，并显式跳过本轮工具发现；
5. 两条路径均不会重复写入用户消息。

授权只在当前浏览器会话有效。工具的白名单、能力治理、只读数据库限制，以及写入、外发和高风险操作的审批策略不因本次优化而放宽。

## 公文与公告

- 聊天 Markdown 会识别公文末尾采用空格右对齐的“落款单位 + 成文日期”，以右对齐正文显示，避免被 Markdown 当作缩进代码块；显式代码围栏和真实缩进代码不受影响。
- 普通管理员发布自己创建的公告时，可选择全员、单位、角色或指定用户作为投放范围，范围值不再被限制为所在单位。普通管理员仍不能管理他人公告，登录页公告仍仅限系统管理员发布。

## 兼容性与升级

- 无新增数据库迁移或环境变量。
- 可按既有流程备份 PostgreSQL 与上传文件后升级。
- 历史聊天记录不会被改写；重新打开时仅按新的展示规则隐藏默认路由提示。

## 验证

- 覆盖自适应路由、工具授权续跑、指定原消息重试、路由覆盖清理、聊天执行凭据渲染、公文落款渲染和公告权限边界的自动化测试已通过。
- 前端静态资源检查通过。
