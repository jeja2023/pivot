# v0.7.90 公文写作截图标准版式全面落实

日期：2026-11-04。

本次以用户提供的七项格式截图为版式依据，统一应用于公文编辑静态显示、DOCX 和 PDF；不将原来的通用仿宋/黑体或左右不对称页边距称为达标。

| 截图要求 | 实现 |
| --- | --- |
| 页面 | A4；上3.7、下3.5、左2.7、右2.7厘米；页眉1.5、页脚3.0厘米；22行/28字文档网格；固定28磅行距；对齐网格与自动调整右缩进开启 |
| 标题 | 2号方正小标宋_GBK，居中，按词边界排为梯形/菱形；可在发文要素中仅调整标题换行，不允许与原题文字不一致 |
| 主送 | 3号方正仿宋_GBK，标题下空一行，左顶格，续行仍顶格，末尾全角冒号 |
| 正文 | 3号方正仿宋_GBK，首行空二字、续行顶格；四级层次依次为“一、”“（一）”“1.”“（1）”，字体依次为方正黑体、方正楷体、方正仿宋、方正仿宋；数字使用 Times New Roman |
| 附件 | 新增独立附件名称/正文编辑。正文下空一行、左空二字生成附件说明，多份自动编号，名称末尾不加标点；悬挂缩进确保长名称续行与首字对齐。附件正文另起页，首行顶格3号方正黑体标注“附件”，不加冒号 |
| 署名日期 | 3号方正仿宋_GBK；署名置于日期上方并以日期中心排布；日期右空四字，年份完整，月日不补零 |
| 页码 | 4号宋体半角数字，左右一字线；主文和全部附件连续编号 |

DOCX Renderer 升至 `docx-2.0.0`，PDF Renderer 升至 `pdf-2.0.0`，旧渲染结果不会被当作新版格式复用。

## 验证

- 78 项相关 Node 回归通过，覆盖原有编辑/AI/保存功能、截图格式契约、原字体嵌入、纯正文22行28字及28磅基线、附件操作、标题分行和连续页码。
- 8 项完整应用 E2E 通过，包含有附件的实际 PDF/DOCX 下载、预览及字体/网格核对。
- 本机 Word 实际读取 DOCX：22行、28字；边距对应上104.85/下99.2/左右76.5磅，页眉42.5/页脚85磅，均为厘米要求换算后的 Word 存储值。
- 5页样稿的 PDF 与本机 Word 导出页面均逐页查看，核对标题、四级字体、长附件说明、附件另起页、落款和1至5连续页码。
- 项目检查、Lint、类型检查及本轮格式模块增量检查通过。实现和证据详见[截图版式验收记录](../reports/公文截图标准版式验收-20261104.md)。

## 字体与升级

本机已安装截图要求的四种方正字体、宋体及 Times New Roman。服务端对字体真实族名和可嵌入标记进行检查，PDF 嵌入相应原字形；缺字体或不允许嵌入时，明确拒绝严格公文导出，不静默回退。

字体文件不随仓库分发；其他服务器请安装有授权的原字体，或按[字体配置说明](../../assets/fonts/official/README.md)挂载目录。DOCX 接收端也需安装对应字体；固定版式流转可使用已嵌入字体的 PDF。

更新后重启服务并刷新客户端。本次无新增数据库迁移或 npm 依赖。长标题的业务词意和正式行文内容仍需人工确认，应用提供换行调整和实际版式预览。
