# v0.7.156 Windows 安装器进程检查与旧版自动升级修复

日期：2026-11-13。启用源码版本 v0.7.156，归档 Windows 内网安装、旧版更新提示及发布端统一签名的相关修改。

**后续更正**：生产旧版本已确认为 0.7.76，直接安装卡住的是 0.7.155。0.7.74 的历史验签结果仅证明该版本兼容，不能证明生产 0.7.76 可以自动升级。0.7.76 原代码对实际自签名修复包返回“Authenticode 签名无效（状态 1）”，需要管理员统一完成一次客户端恢复，不能仅靠替换服务器更新包修复。新增原位检查排除自身、安装阶段日志及只读诊断；生产安装停滞的具体阶段仍待确认，见[后续排查记录](../reports/windows-client-076-followup-20261113.md)。

## 问题与行为变化

首次排查按当时反馈的 0.7.74 客户端与 0.7.148 安装器进行，曾报告菜单显示“重启并安装更新／已就绪”，直接运行安装器出现“无法核对安装目录的运行状态，已停止安装”。这条明确报错来自安装器依赖的 CIM/WMI 查询；后续确认的 0.7.76 下载 100% 与 0.7.155 安装卡住需要分别排查，不能根据前次菜单状态认定本次已经通过验签。

- 安装器改用 Windows 原生进程快照和完整映像路径查询，不再依赖 PowerShell 模块或 CIM/WMI 服务。保留目标目录边界与失败阻断，不终止其它目录中的同名客户端。
- 自动更新通过 `--updated` 交接时，最多等待十秒让旧客户端自然退出，避免更新器先启动安装器、旧客户端尚未退出时立即阻断。
- 服务端页面分别记录发现更新与下载完成的通知，修复同版本完成提示被去重吞掉的问题；重新加载页面后提示已有就绪更新，迟到的初始状态不覆盖新事件。
- 普通用户无需处理证书。签名证书、私钥、内嵌指纹与更新文件由发布端统一管理；修正部署文档和构建提示，保留现有签名、发布者及证书指纹校验。

## 升级与兼容

本次没有新增依赖、数据库迁移或必填配置。`package.json`、锁文件、README 和设计基线同步至 v0.7.156。

生产仍运行 0.7.74 的客户端可使用原内网更新源检查更高版本；新安装器须沿用固定签名身份及分发配置。发布维护者先上传安装器和 blockmap，最后替换 `latest.yml`，普通用户保存工作后确认重启安装。内网无互联网不影响从可达的单位服务器获取更新；目标 Windows 企业应用控制仍由管理员集中配置。

服务端页面提示修复在部署页面资源后可被旧客户端加载；安装器修复必须随重新构建的安装包交付。已经缓存故障版 0.7.148 安装器的客户端须重启并重新检查更新，不能继续运行原故障文件。
