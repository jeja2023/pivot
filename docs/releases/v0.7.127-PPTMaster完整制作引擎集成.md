# v0.7.127：PPT Master 完整制作引擎集成

日期：2026-11-08。

PPT 制作新增可选“完整制作引擎”，按固定版本复用 PPT Master 6.8.0 的完整工作流、参考、转换脚本、模板和资源。Pivot 负责当前账号的模型、材料、交互确认、后台任务与文件交付。

独立执行镜像使用通用名称 `ppt-master:6.8.0`，可由其他宿主按同一 JSON 协议接入；构建、验收与部署示例统一使用该名称。

- 生成、模板创建和原稿编辑走各自上游流程；生成支持默认、快速、美化和图片重建画像。图片重建向视觉模型传入真实图片。
- 持久保存阶段、步骤、实际模型用量、确认问题和检查点，支持取消和条件恢复；并发接纳、租约和终态写入防止重复执行或旧实例覆盖。
- 界面可设置累计预算与执行轮次，达到上限后可在允许范围内增加并继续，保留已发生用量。默认累计上限为 40 万令牌，最大 50 万。
- 执行单元沿用 Capability Worker 签名、摘要、隔离、资源与超时合同，无网络、无任意 Shell、无宿主脚本回退。最终文件须经过实际上游导出、源稿指纹和包结构检查。
- 交付原生 PPTX 与完整项目源包；Brand/Style 等可仅交付通过上游校验的模板源包。文件沿用 Artifact/CAS、账号鉴权和一次性下载令牌。

固定提交为 `769547394107870a0c7b5ad8d1c0c75035123aef`，完整技能包共 13,089 个文件。构建保留上游内容和完整性门禁；依赖按精确版本锁定，当前不安装 PyMuPDF，材料文本提取复用 Pivot。

实际容器通过原生生成、箭头与 Office 公式回读、两页未修改原稿 XML 保留和模板源包校验。测试、浏览器和本机 Office 证据及限制见[验证报告](../reports/PPTMaster完整引擎集成验证-20261108.md)。测试模型验证操作与交付链路，真实模型的设计质量和同预算盲评仍未完成。

运行开关默认关闭，正式启用需要固定镜像摘要与正式签名信任，详见[部署与验收](../deployment/完整PPT制作引擎部署与验收.md)。尚未适配联网图像/语音供应商、视频制作和复杂原生对象到浏览器画布的双向编辑；未构建桌面安装包或部署生产。
