# v0.2.16：法规全库向量重建与 GTE-Qwen2 纯 CPU 索引

发布日期：2026-10-13

## 目标

本版本将法规库的向量索引从“按上传者配置、单版本手工恢复”升级为共享、可恢复、可控速的后台队列。适用于已存量导入 1,800+ 份法规、使用 `Alibaba-NLP/gte-Qwen2-1.5B-instruct`，且 Embedding 服务部署在纯 CPU 服务器上的场景。

## 功能变更

- 法规分类页进入“批量处理”后，可执行“重建当前分类向量”；在全部法规目录中执行即为全库重建。
- 重建只处理未删除、未归档法规的**当前版本**。历史版本、归档法规和原始文件不被重新解析。
- 系统先清空范围内的旧向量，立即回落到既有关键词检索，再以 `retry_wait → indexing → vector_ready` 状态持续处理。临时故障仍遵循有上限退避；配置错误不会循环请求。
- 队列状态写入 `regulation_versions`，服务或容器重启不会丢失已排队任务。
- 上传、自动恢复、单版本重建、批量重建与法规检索统一使用系统级 Embedding 配置。管理员的个人模型设置仍可供个人知识库使用，但不再影响共享法规库。
- 对 `gte-Qwen2-*-instruct` 自动把查询编码为 `Instruct: …\nQuery: …`；法规条文的入库编码保持原文，符合 Instruct 检索模型的查询/文档分工。

## 纯 CPU 推荐起点

在 256GB 内存、40 核 CPU 的服务器上，先采用以下保守配置，再依据模型服务 P95 延迟和 CPU 利用率调整：

```dotenv
EMBEDDING_MODEL=Alibaba-NLP/gte-Qwen2-1.5B-instruct
RAG_EMBEDDING_MAX_CONCURRENCY=1
RAG_EMBEDDING_BATCH_MAX_INPUTS=4
RAG_EMBEDDING_BATCH_MAX_TOKENS=8000
EMBEDDING_REQUEST_TIMEOUT_MS=60000
RAG_INDEX_EMBEDDING_TIMEOUT_MS=120000
REGULATION_INDEX_RECOVERY_BATCH_SIZE=1
REGULATION_INDEX_RECOVERY_INTERVAL_MS=5000
```

`RAG_EMBEDDING_MAX_CONCURRENCY` 是 Pivot 对 HTTP 请求的保护阀，不等于模型服务内部线程数。确认模型服务仍有 CPU 余量、前台检索没有明显排队后，可逐步把并发和每轮版本数提高到 `2`，每次只改一个参数。

## 升级步骤

1. 在**系统设置**配置统一的 Embedding URL、模型和密钥，确认连接测试成功。
2. 部署 v0.2.16 并重启服务；本版本没有新的数据库迁移。
3. 进入法规查询的全部法规目录，打开“批量处理”，执行“重建全库向量”，确认提示。
4. 重建期间可继续使用关键词检索；在法规详情的版本状态中查看 `retry_wait`、`indexing`、`vector_ready` 或 `lexical_ready`。
5. 待队列清空后，用具有代表性的法规问题进行混合检索验收。

## 验证

- 查询模板测试：GTE-Qwen2-Instruct 自动添加查询指令，普通模型保持原始查询。
- 配置隔离测试：个人 Embedding 设置不影响系统共享法规库配置。
- 队列测试：全库重建仅排队当前有效版本，清空对应旧向量，归档法规与原文解析链不受影响。
- 运行时参数进入类型化环境变量注册表、`.env.example` 与配置文档。
