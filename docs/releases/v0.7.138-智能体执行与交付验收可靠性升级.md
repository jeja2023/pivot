# v0.7.138：智能体执行与交付验收可靠性升级

日期：2026-11-09。版本汇总涵盖本轮智能体执行对照、协议与运行链路修复、预算和验收优化、缓存索引检查及历史失败复测。前一版本的应用服务设置调整继续保留在[v0.7.137发布记录](v0.7.137-应用服务配置独立页面.md)。

## 智能体执行和审计

- 工具名称、历史函数调用及指定工具选择使用同一稳定协议映射，模型响应还原为真实受控工具名。处理非法/长名称、合法名称碰撞、分段函数名及结束完整快照，不改变工具参数、实际权限或审批范围。
- 提供方返回的调用ID原样保留；省略ID时只生成一次，使历史消息和工具结果引用一致。
- 流式执行、审计和产物渲染共享稳定的内部步骤标识。长步骤超过64字符、操作关联键超过255字符时使用摘要，旧短标识保持原值；审计保留脱敏后的原始关联，读取兼容历史文本JSON与PostgreSQL JSONB。
- 协议转换也覆盖流式工具执行后的非流式总结及回退请求，避免历史工具名称再次被上游拒绝。没有引入第二套Agent运行时或整体接入Hermes。

## 风险预算与交付验收

- 新任务默认`risk_budget`从20调整为80，覆盖多步发现、读取、校验和交付；没有采用条件评测中的500作为产品默认。
- 显式值（含0）、旧任务配置/用量快照中的限额、累计记账和父任务约束继续生效，新建子任务不能通过默认值或显式大额度扩大父任务风险上限。工具调用数、网络、文件写入、外部副作用及审批门限独立保留。
- 直接创建的自然语言任务和旧空验收契约默认独立核验交付，不再把“最终答复非空”单独当作成功。已有结构化验收条件继续使用，工作流沿用节点和终点契约，不额外插入隐式总结。
- 核验区分内部交付缺口和真实缺少用户业务输入：内部具体缺口在当前权限、剩余轮次和预算内最多修复两次；用户输入缺失时进入待补充状态。核验服务不可用、来源撤销或预算耗尽均不能伪装为成功，也不触发无界重试。
- 用户侧使用路径、任务状态和收尾用量说明已同步到[使用帮助](../../使用帮助.md)。

## 缓存索引检查

迁移结构检查和BI运行就绪检查同时限定当前命名空间、`analysis_query_jobs`表和索引有效状态。当前表缺索引时，后备命名空间或其他表的同名索引不能替代。

沿用已有迁移编号及幂等建索引流程：已登记迁移在结构不符时重新校验/修复缺失索引；同名索引位于错误表时拒绝就绪，不自动删除未知对象。没有新增数据库字段、配置或依赖。

真实PostgreSQL回归在回滚事务中主动创建后备同名索引，验证缺失、错表、正常、重复修复及后备对象不被改写。增强后的测试在修复前确实失败，产品修复后通过。详见[缓存索引修复记录](../reports/缓存索引命名空间检查修复-20261109.md)。
