# v0.7.135：PPT Master独立服务与标准制作回退

日期：2026-11-08。

PPT Master优先作为独立常驻HTTP服务提供完整制作、模板工具、原稿对象编辑和离线页面视频。Pivot配置一次内网服务地址与访问密钥，通过文件和动作接口调用；不需要为PPT挂载Docker socket、共享任务目录、登记镜像摘要或配置发布签名。

服务镜像默认启动8502端口的协议1接口，独立Compose只加入内网，不映射公网端口。以后在服务目录导入新版`ppt-master.tar`并重建`ppt-master`即可，访问密钥和任务数据卷保留。兼容协议的升级无需重建或重启Pivot；上游固定提交由服务镜像自校验，不再由Pivot强制要求同一提交。

服务未部署、停机或协议不兼容时，AI自由设计进入标准工作台，标准创建、结构化编辑、故事线和标准PPTX/PDF导出继续使用。完整制作窗口也提供进入标准制作的操作，原稿编辑与视频明确显示依赖服务；正在执行的原稿或制作任务不会自动切换到另一种实现或被标为成功。

执行仍使用固定上游完整包和工具参数白名单，输入快照不可覆盖，任务文件和动作均受身份、路径、大小、超时与并发约束。动作进程不继承服务密钥，借助Landlock限制文档目录、seccomp拒绝Internet socket及进程内存读取；取消和服务关闭会终止子进程组。文件传输核对SHA-256，同版本服务重启可保留任务，运行包变更后旧检查点明确拒绝续接。

旧的直接Docker执行方式继续兼容；配置独立服务地址后优先使用服务方式。迁移时撤销仅供PPT使用的旧Compose覆盖与socket挂载，保留其他业务实际需要的Docker配置。

构建、启动和升级命令见[独立服务部署说明](../deployment/PPTMaster独立服务部署与更新.md)，实际验证范围见[专项报告](../reports/PPTMaster独立服务与标准回退验证-20261108.md)。未部署生产。
