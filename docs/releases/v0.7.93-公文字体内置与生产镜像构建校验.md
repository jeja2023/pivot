# v0.7.93 公文字体内置与生产镜像构建校验

日期：2026-11-04。

本版本解决严格公文导出依赖服务器另行安装字体、无授权字体的源码 CI 直接执行真实渲染测试失败的问题。生产镜像携带固定版本原字体，构建时完成校验，离线运行时直接使用镜像内资产。

## 变更内容

| 项目 | 行为 |
| --- | --- |
| 内置字体 | 方正小标宋_GBK、方正仿宋_GBK、方正黑体_GBK、方正楷体_GBK、宋体、Times New Roman；合计 69,533,296 字节（66.31 MiB） |
| 字体清单 | `assets/fonts/official/manifest.json` 固定用途、文件名、内部字体名、大小和 SHA-256；字体二进制作为受控构建资产，不提交 Git |
| 准备命令 | `npm run prepare:official-fonts -- <已授权字体目录>` 检查来源后复制；重复执行可复验，已有不同版本会报错并保留原文件 |
| 校验命令 | `npm run check:official-fonts` 只读取包内文件，检查大小、摘要、内部名称及嵌入权限，不借用系统字体或环境变量补齐 |
| 生产构建 | 最终默认 `runtime` 阶段以 `node` 用户执行校验；缺失、损坏或不符合清单时构建失败 |
| 源码 CI | 构建 `runtime-base` 验证运行依赖，并尝试最终生产构建，确认缺少字体包时被拒绝；基础阶段用于 CI 验证 |
| 渲染测试 | 缺少指定原字体时明确跳过依赖真实字体的测试；其他加载异常继续失败，缺字体导出返回 503 的回归始终执行 |

加载器继续校验原字体，缺字体时 DOCX/PDF 返回 `OFFICIAL_FONTS_UNAVAILABLE`；普通版式与红头版式都执行相同校验。PDF 嵌入所用字形子集，DOCX 写入准确字体名称，接收 DOCX 的电脑仍应安装相应字体。

字体部署和镜像交付须由发布方提供相应授权。字体文件的嵌入标记与完整性检查用于技术校验，授权凭证由发布方单独保管。

## 构建与升级

构建机器安装项目依赖并取得受控字体包后执行：

```bash
npm run prepare:official-fonts -- /srv/pivot-authorized-fonts
npm run check:official-fonts
docker build -t pivot:0.7.93 -t pivot:latest .
docker run --rm --network none --read-only pivot:0.7.93 node scripts/official_fonts.js check
docker save -o pivot-image.tar pivot:0.7.93 pivot:latest
```

也可按[字体配置说明](../../assets/fonts/official/README.md)核验并解包本机构建目录中准备好的受控字体归档。正式发布使用 Dockerfile 默认最终阶段。

生产机导入完整镜像后重新创建容器；离线环境使用 `docker compose up -d --no-build --force-recreate pivot`，再执行 `docker compose exec -T pivot node scripts/official_fonts.js check`。无需新增字体挂载、环境变量、项目依赖或数据库迁移。

项目版本由 `CHANGELOG.md` 驱动，通过 `npm run version:sync` 同步到项目清单、依赖锁文件和 README。本次启用源码版本 v0.7.93，生产服务更新与客户端安装包按各自发布流程执行。
