# 历史向量只读检查与检索验收

`scripts/audit_vector_data.js` 用于检查知识分块、长期记忆或法规条文的历史向量元数据，不修改数据，也不输出向量、正文、用户或模型配置值。使用具有目标表只读权限的 PostgreSQL 账号，并在目标数据库可承受扫描的时间执行；命令只接收显式提供的连接地址，不读取应用的数据库配置。

PowerShell 示例：

```powershell
$env:VECTOR_AUDIT_DATABASE_URL = 'postgresql://只读账号:密码@数据库主机:5432/数据库名'
$env:PIVOT_VECTOR_AUDIT_CONFIRM = 'YES'
node scripts/audit_vector_data.js --schema=public --target=knowledge --limit=2000
```

`--target` 支持 `knowledge`、`memory`、`regulations`。每次最多读取 20,000 条向量记录，默认 2,000 条；输出 `nextCursor` 非空时，可用 `--after=<nextCursor>` 继续。每次执行使用独立的只读重复读事务；分页执行之间的数据可能变化，因此汇总不能视为全库同一时刻的精确快照。单次处理约 30 秒后停止，单条数据库语句超时为 5 秒。

结果只包含计数和继续游标：`legacyDimensions` 表示维度字段为零或空，`dimensionsMismatch` 表示已声明的维度与可解析向量不一致或元数据本身无效；`missingProfile` 表示配置标识为空；`zeroVector` 与 `exceedsHnswDimensions` 标记余弦检索或 HNSW 索引需要另行处理的情况。`oversized` 是超过检查大小上限的文本；`notJsonArray` 只表示不符合 JSON 数组格式，**不能据此断定 PostgreSQL 向量无效**。数值检查同样不能替代 pgvector 实际输入验证。

该工具不会清洗、删除、回填或创建索引。检查结果需要结合数据版本、权限、模型维度和目标 PostgreSQL/pgvector 版本制定迁移与回滚步骤；不要仅按计数直接删除历史数据。生产验收还需使用代表性数据与标注查询集测量实际查询计划、延迟和召回；现有 `scripts/benchmark_knowledge.js` 通过授权接口统计文档级命中率，不能替代权限隔离及答案质量验收。
