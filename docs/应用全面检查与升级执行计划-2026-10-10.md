## 2. 当前能力边界

### 2.1 数据分析工作台：已具备

- 导入 CSV、XLS/XLSX、SQLite/SQLite3/DB 文件，以及受控数据库查询结果；内部统一转换为 Parquet。
- 数据集概览、分页预览、字段画像、质量体检、数据集编辑、CSV/XLSX 导出和删除。
- 非破坏性清洗：空值处理、去重、文本/日期格式化、数值转换、替换、离群值处理；生成派生数据集并保留可回放谱系。
- 可视化查询与受限只读 SQL 查询。
- 透视分析、数据集比对、柱状/折线/面积/饼图、表格和图片导出。
- 普通 AI 分析及全量长文本语义分析任务：支持分批、进度、取消、重试、恢复和历史回放。

### 2.2 已落实的运行保护

| 项目 | 当前限制 |
| --- | --- |
| 单数据集导入 | 默认最多 200,000 行、120 列 |
| 分析内存 | DuckDB 默认 1 GB |
| 数据查询 | 最多 5,000 行、SQL 最长 5,000 字符、默认 60 秒超时 |
| 透视表 | 最多 200 行 × 50 列 |
| 图表分类 | 最多 80 个分类 |
| AI 深度分析 | 默认最多 3 步、最多 5 步；输出上限最多 2,400 token |

这些限制是安全和稳定性保护，不应通过简单提高配置来满足大数据需求。

### 2.3 已完成的企业分析能力

- 已实现字段字典、计算字段、指标口径、可复跑分析资产、跨数据集 Join、仪表盘、计划刷新、阈值告警、字段敏感性投影与异步查询。
- 开发环境新增受控本地存储的数据版本、增量导入、分区 Parquet 和物化聚合；每项均绑定数据集所有者、字段 ACL 和可回放版本元数据。
- 已新增“上传 → 清洗 → 图表 → 字段治理 → 分区/物化 → 资产 → 仪表盘 → 后台查询”的真实浏览器端到端验证。
- 外部数据库/对象存储连接器和千万级 OLAP 集群仍应按具体生产部署规模单独选型，不能通过放大单机 DuckDB 限额替代。

## 3. 风险与处置优先级

### P0：已完成

#### P0-1：生产依赖漏洞

**实施结果**：已执行非强制常规依赖升级。`npm audit --omit=dev --audit-level=high` 已通过，production critical/high 为 0。

| 严重性 | 组件 | 风险 |
| --- | --- | --- |
| Critical | `proxy-addr@2.0.7`（由 Express 间接引入） | IPv4-mapped IPv6 信任边界绕过，可能造成 IP 伪造。 |
| High | `compression@1.8.1` | 过早关闭响应时可能导致内存泄漏型拒绝服务。 |
| High | `sharp@0.35.4` | `librsvg` 相关漏洞。 |
| Moderate | `multer`、`ip-address`、`fast-copy`、`sprintf-js` | 上传中断、SSRF/IP 分类及拒绝服务相关风险。 |

**实施步骤**：

1. 创建独立依赖修复分支，先保存当前知识库改动。
2. 执行常规依赖修复并审阅 lockfile：

   ```powershell
   npm audit fix
   npm audit --omit=dev
   ```

3. 重点确认以下预期升级未破坏桌面端原生依赖和数据库连接器：
   - `proxy-addr` → `2.0.8`
   - `compression` → `1.8.2`
   - `sharp` → `0.35.5`
   - `multer` → `2.4.0`
   - `mssql` / `tedious`、`ip-address`、`fast-copy` 的联动升级
4. **禁止直接执行** `npm audit fix --force`。`sprintf-js` 经 `mssql/tedious` 间接引入，强制方案涉及不兼容版本，必须由人工完成连接器回归后决定。
5. 运行完整验收命令，并在修复后确认 audit 不再存在 critical/high：

   ```powershell
   npm run check
   npm run test:coverage
   npm run test:e2e
   npm audit --omit=dev --audit-level=high
   ```

**剩余约束**：`mssql → tedious → sprintf-js` 的中危告警需使用破坏性版本替换才可消除，不能用 `--force` 绕过。SQL Server 真实环境兼容性验收仍属于发布前外部演练。

#### P1-2：补齐数据分析端到端验收

**实施结果**：已新增真实浏览器 E2E，覆盖 CSV/XLSX/SQLite 上传、派生清洗、图表、字段治理、分区、物化聚合、计算预览、保存视图、仪表盘刷新、后台查询及全量语义任务取消/重试/页面恢复。SQLite 上传同时由专用白名单与 SQLite 文件头校验保护；非法查询和浏览器网络中断会提供中文可操作提示。

#### P1-3：缩小高耦合前端模块

**实施结果**：新能力拆入 `governance.js`、`semantic-models.js`、`dashboards.js`、`async-query.js`；旧入口只做页面挂载与受控模块分发。

**拆分原则**：

- 状态模型、DOM 渲染、事件绑定、请求适配和导出逻辑分离。
- 保持当前 `window.Pivot` 受控模块 API，不增加 legacy 全局变量。
- 每次拆分后运行数据分析单测、E2E 和 CSS 门禁。

**验收标准**：功能无变化、无循环依赖、相关模块可单独测试；新增功能不再持续扩大既有大文件。

## 4. 功能升级路线

### 阶段 A：已完成

1. **数据字典与字段治理**：允许用户确认字段类型、单位、日期格式、敏感级别与业务含义。
2. **计算字段**：提供表达式编辑器、预览、版本和依赖检查，避免将业务口径散落在 SQL 中。
3. **保存的分析视图**：保存查询、透视、图表配置及其数据集版本，支持一键复跑。
4. **图表扩展**：增加散点、堆叠、漏斗、热力、箱线图和双轴图；保留现有数据截断提示。
5. **AI 结论可验证**：每条结论附带使用的 SQL、数据范围、字段、数据集版本和置信提示。

### 阶段 B：已完成基础实现

1. **指标语义层**：集中定义指标、维度、口径、权限和有效期。
2. **跨数据集模型**：受控 Join、关系图、主键质量检查及字段血缘。
3. **仪表盘**：多图拼接、筛选器联动、版本化、组织共享、只读链接和导出。
4. **自动化**：按计划刷新、阈值告警、异常推送和工作流触发。
5. **权限治理**：数据集/字段/指标/仪表盘多层权限，并为敏感字段提供脱敏投影。

### 阶段 C：已完成单机可恢复查询基础

1. 将大查询迁入异步任务队列，提供取消、恢复、配额与可观测性。
2. 引入对象存储、分区 Parquet、增量摄取和物化聚合。
3. 对超过当前 DuckDB 单机边界的查询，引入专门 OLAP 引擎或受控查询集群。
4. 建立性能基准：10 万、100 万、千万行的导入、查询、透视、导出和 AI 成本/延迟指标。

**开发环境实施结果**：第 1 项已在单机工作台实现并通过浏览器与服务回归。第 2 项已落地为受控本地/共享文件存储实现：增量文件生成新数据版本，分区副本与物化聚合均写入受控数据集目录，PostgreSQL 保存版本、分区和物化元数据；现有开发环境无需 S3 即可验收功能。第 3 项在开发环境继续使用有资源上限、字段 ACL、只读 SQL 校验和后台队列保护的 DuckDB 列式 OLAP 执行面。第 4 项的本地可复现数据路径基准已完成：新增 `npm run benchmark:data-analysis`，并执行 10 万、100 万、千万行 CSV→Parquet、聚合查询、透视聚合和 CSV 导出，报告见 `docs/reports/data-analysis-capacity-benchmark-100k-2026-10-11.json`、`docs/reports/data-analysis-capacity-benchmark-1m-2026-10-11.json`、`docs/reports/data-analysis-capacity-benchmark-10m-2026-10-11.json`。它不会伪造真实模型成本/时延；模型端点恢复后仍须补入真实 AI 指标。S3 和多节点专用 OLAP 集群仍属于生产替换适配器与部署演练范围，不影响开发环境功能验收。

## 7. 结论

Pivot 的安全边界、Agent/工作流可靠性、知识库治理、迁移机制和自动化测试均处于较好的工程状态。最优先的动作不是无边界增加功能，而是先关闭依赖漏洞和评测证据缺口；随后以“语义指标层、保存的分析视图、仪表盘、刷新告警”为主线，将数据分析工作台升级为可协作、可治理、可复用的企业分析产品。
