# 智能路由与持续学习实施验收清单

本清单将《智能路由与持续学习改造方案》的工程交付、人工核验和生产环境门槛分开管理。只有同时满足三类证据，才允许称某个提供器已经上线：代码和数据库迁移已交付、冻结评测集已人工核验、目标内网环境已完成性能与故障演练。

## 已实现的工程控制面

- 统一 `DecisionProvider`：现有启发式路由、Laya HTTP 服务、本地线性轻量模型和当前 Qwen 的结构化 JSON 决策均使用相同的脱敏输入和受控候选输出。
- 策略层：校准、低置信度回退、高风险/审批动作禁自动执行、影子模式、按场景/租户/稳定分桶灰度。
- 闭环审计：决策、候选集、提供器输出、实际检索/工具规划结果、用户修正、管理员核验和经验证标签均使用 `decision_id` 关联。用户修正不是训练标签；只有管理员/系统核验事件才进入训练集。
- 数据隔离：训练查询排除已禁用/已删除账号，支持按租户筛选；训练 CLI 默认要求 `--tenant-id`，跨租户训练必须显式使用 `--allow-global`；相同任务哈希会整体分入同一个时间分区，避免跨训练/校准/测试集泄漏。
- 模型治理：模型权重哈希、数据版本、代码版本、校准参数、评测报告都记录为候选制品。只有独立测试集门槛通过的制品才能激活；active 流量默认要求已激活制品。
- 运维：管理接口提供决策运行指标、人工核验、模型制品查看/激活/回滚；Laya 健康检查进入系统健康快照。

## 开发环境验收

开发环境不要求连接真实 Qwen、Laya 或 GPU，也不要求人工业务结论。开发完成的安全标准是：三项决策迁移（学习底座、评测治理、制品训练范围）均已应用，冻结集已导入本地数据库且其版本、案例数与源码摘要一致，运行保持非 `active` 且 0% 灰度，Laya/Qwen/轻量学习型提供器未连接真实服务。人工审核、模型制品、GPU 压测和业务结果明确属于目标内网生产验收。

~~~powershell
npm run verify:decision-development
~~~

该命令在当前开发数据库中只读检查上述条件；生产就绪度仍会因待人审或未放量显示 `degraded`，这是预期结果，不能被开发完成状态掩盖。它不会把源码中的 `pending_human_review` 伪造为人工标签。

## 业务工作流选择

已发布且当前用户有权运行的工作流可通过以下接口获得受控推荐：

~~~text
POST /api/agents/workflow-recommendations
{ "prompt": "汇总本月订单并生成报表", "maxCandidates": 8 }
~~~

服务先从可访问的发布工作流中用本地词法排序缩减候选，再通过统一决策器返回建议。推荐不会自动创建运行、不会绕过工作流发布、权限、审批或执行预算；客户端或调用方必须使用现有工作流启动入口明确确认后才会执行。

## 冻结评测集流程

评测集位于 [decision-evaluation-set.v2.json](decision-evaluation-set.v2.json)，覆盖中文短指令、否定表达、长上下文、跨部门/权限边界、少见任务、工具授权、本地文件、高风险审批、英文输入、直接回答/澄清提问，以及已发布工作流选择。它目前故意不包含推测标签。v1 保留为已导入历史版本，不应修改。

1. 管理员先在目标环境导入冻结集：`npm run import:decision-evaluation-set -- <管理员用户ID>`，或调用 `POST /api/stats/observability/decision-evaluation-sets/import`。导入后同版本源码摘要不可变，避免审核期间静默改题。
2. 由具备场景权限的复核人员在管理接口 `POST /api/stats/observability/decision-evaluation-sets/:version/cases/:caseId/review` 为每项选择当时允许的 `expectedActionId`，并保留审核人、时间和备注。内网命令行可先使用 `npm run list:decision-evaluation-review-queue -- --reviewer-id <管理员ID> --version v2` 查看仅包含合成指令和允许候选的审核队列；随后使用 `npm run review:decision-evaluation-case -- --reviewer-id <管理员ID> --version v2 --case-id <案例ID> --expected-action-id <允许动作ID> --note "<审核依据>"`；该命令会校验审核人账号为有效管理员，且只允许提交该案例当时允许的动作。每次修改会写入不可变 review 审计记录。
3. 执行 `npm run verify:decision-evaluation-set` 检查源码契约；active 发布预检会额外要求数据库中该版本所有案例均已审核。任一未核验、标签不在候选中或源摘要不一致都会失败。
4. 正式提供器基准使用 `--reviewed-set-version <version>` 从数据库读取审核后的案例；不要将任一提供器的内部样本或用户原文加入该文件。

## 统一提供器基准比较

冻结集内的路由指令是人工编写的合成文本，不是用户原文；校验脚本会拒绝疑似邮箱、电话、证件号或密钥。完成全部人工核验后，用同一组候选动作、同一组预期结果与同一份评测集比较提供器：

~~~powershell
# Laya 与轻量模型；会输出准确率、校准、P50/P95 与错误率。
npm run benchmark:decision-providers -- --reviewed-set-version v2 --providers laya,light --light-model-file tenant-12.json --laya-url http://laya-decision:8080/decision --report artifacts/decision-provider-benchmark.json

# Qwen 比较必须指定一个有权使用该模型的内部用户和模型标识。
npm run benchmark:decision-providers -- --reviewed-set-version v2 --providers qwen --qwen-user-id 12 --qwen-model Qwen3.6-35B --report artifacts/qwen-decision-benchmark.json

# 现网基线路由从影子期捕获的结果文件读取，不允许用预期标签伪造基线。
npm run benchmark:decision-providers -- --reviewed-set-version v2 --providers existing-router --baseline-results artifacts/current-route-shadow-results.json --report artifacts/baseline-benchmark.json
~~~

命令拒绝存在未核验条目的冻结集。基线结果文件必须来自同一测试请求的影子记录；不得使用期望标签来构造基线。

## 训练与模型注册流程

~~~powershell
# 默认按单个租户训练，使用已核验业务结果的时间顺序切分。
npm run train:decision-light-model -- --tenant-id 12 --minimum-samples 30 --critical-scenarios chat.rag,chat.tools --report artifacts/decision-eval-tenant-12.json

# 只有数据治理已经批准跨租户、脱敏特征训练，且目标环境已设置 `PIVOT_DECISION_ALLOW_GLOBAL_TRAINING=true`，才可显式执行全局训练。
npm run train:decision-light-model -- --allow-global --minimum-samples 30 --critical-scenarios chat.rag,chat.tools --report artifacts/decision-eval-global.json
~~~

训练命令固定按时间划分训练集、校准集和测试集，输出校准 Brier 分数、准确率、P50/P95、关键场景结果及发布门槛。`--write-candidate` 只会写本地候选文件，`--register` 只会登记候选制品；二者都不能替换生产决策器。决策记录和关联结果默认保留 180 天，可用 `PIVOT_DECISION_RECORD_RETENTION_DAYS` 按组织治理要求调整；后台维护任务只清理到期决策记录，保留模型制品和冻结评测审核。

管理员在候选通过独立测试集门槛后，才能调用模型制品激活接口。发生退化时，优先将 `PIVOT_DECISION_ROLLOUT_PERCENT=0` 或模式改回 `shadow`，再通过回滚接口退役 active 制品。

## 策略参数版本化发布

阈值、校准缩放和截距属于生产策略制品，不应在 active 灰度时仅靠修改环境变量上线。管理员先通过策略制品接口登记候选，候选的独立评测报告必须包含 `releaseGate.passed=true`；之后使用通用模型制品激活接口激活 `providerId=decision-policy` 的该版本。

active 灰度默认要求 `PIVOT_DECISION_USE_ACTIVE_POLICY_ARTIFACT=true`，且激活制品版本必须等于 `PIVOT_DECISION_POLICY_VERSION`。制品缺失、版本不一致或数据库读取超时时，运行时自动降回 shadow；发布预检也会失败。紧急回退可将灰度比例设为 0、改回 shadow，或通过模型制品回滚接口退役策略制品。

## 灰度熔断与自动回退

候选模型或策略制品的独立评测报告可冻结以下熔断阈值：

~~~json
{
  "breakerThresholds": {
    "minSamples": 30,
    "maxProviderErrorRate": 0.05,
    "maxExecutionFailureRate": 0.10
  }
}
~~~

后台熔断巡检只检查拥有上述冻结阈值的 active 制品。窗口内样本达到 `minSamples` 后，提供器错误率或执行失败率超过阈值会自动退役对应制品；由于 active 路由只接受已激活制品，下一次请求会自动回到影子/既有路由。阈值、窗口和轮询间隔由 `PIVOT_DECISION_BREAKER_*` 配置，默认每五分钟检查最近三十分钟。熔断不会自动切换到未经评测的“上一版本”。

## 部署就绪度

目标环境可通过以下接口查看决策上线阻塞项：

~~~text
GET /api/stats/observability/decision-readiness
~~~

系统健康快照也会包含 `decisionDeployment` 检查项，统一说明决策迁移是否已应用、冻结集是否已完成数据库审核、active 策略制品是否匹配、Laya 健康是否正常以及当前灰度状态。它不会替代业务验收，但可避免将“影子准备中”误判为“已完成生产上线”。

## 持续优化与错误分析

管理员可读取最近窗口内按租户、场景、结果状态和 `reasonCode` 聚合的决策维护报告：

~~~text
GET /api/stats/observability/decision-maintenance?lookbackDays=30&minimumVerifiedSamples=30
~~~

报告同时列出各场景达到训练样本门槛的进度。它仅用于分析与排程，不会自动训练、激活制品或改变灰度流量。
## 发布前强制检查

~~~powershell
npm run verify:decision-evaluation-set -- --require-verified
npm run preflight:decision-release
npm run preflight:deployment
~~~

`preflight:decision-release` 检查冻结集、Laya 健康和 active 灰度的模型制品；数据库不可达时会在有限时间内失败，不会无限等待。默认配置为 `shadow` 且灰度比例为 `0`。

## 目标环境证据快照

在每次目标内网影子期、基准、故障演练和灰度前后，执行以下只读命令并归档 JSON。报告不会写入用户请求原文、模型端点 URL 或密钥：

~~~powershell
npm run report:decision-release-evidence -- --lookback-days 30 --output artifacts/decision-release-evidence.json
~~~

报告会记录冻结集审核状态、当前灰度、已激活制品的可追溯摘要、Laya 健康、GPU 采样和错误类型聚合；GPU 单次采样受 `PIVOT_DECISION_GPU_SAMPLE_TIMEOUT_MS` 限制，超时只写入 `gpu_sample_timeout`，不会阻塞证据采集或掩盖后续验收失败。它是验收佐证，不会绕过任何发布门槛。

## 目标环境仍需实际取得的证据

以下项目不能由代码仓库代替，必须在无互联网目标环境执行并留存报告：

- Qwen3.6-35B 与 Laya 共卡/独立 GPU/CPU 三种部署的 GPU 显存、Qwen 吞吐、端到端 P50/P95、超时率和模型不可用率；
- 冻结评测集的人工核验结论，及每个候选提供器在相同输入上的端到端业务完成率、人工改路由率和重复处理率；
- Laya 超时、HTTP 500、权重版本不一致、并发满载、数据库暂不可用等故障演练和回退记录；
- 基于组织数据治理规则的跨租户训练许可、数据保留期限和删除流程审批。

如经数据治理审批需要让 Laya/Qwen 使用自然语言线索，可将 `PIVOT_DECISION_INCLUDE_REDACTED_ROUTING_TEXT` 从默认的 false 改为 true。只有有限长度、规则脱敏后的文本进入提供器请求；决策审计、训练数据和模型制品不保存该字段。

在上述证据齐全前，不应把 Laya、Qwen 或轻量模型标记为已完成全量生产上线，也不应启动 Bandit。Bandit 只可在低风险、可逆动作且选择概率和可靠结果信号已完整记录后另行小流量试点。
