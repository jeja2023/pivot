# 生产环境离线部署

本文档用于完全离线或受限内网生产环境。项目统一使用根目录的 `docker-compose.yml`，不额外维护离线专用 compose 文件。当前先使用轻量 PP-OCRv6 提供基础 OCR；PaddleOCR-VL-1.6 后续作为高级文档解析能力单独接入。推荐做法是在有网构建机完成镜像构建、依赖安装和可选 OCR 运行时验证，生产机只导入镜像并挂载数据、上传文件、客户端安装包和 PaddleOCR 模型目录。

## 一、离线包内容

建议最终交付一个目录，例如 `pivot-offline-release/`：

```text
pivot-offline-release/
  pivot-image.tar
  docker-compose.yml
  .env
  models/
    paddleocr/
      det/
      rec/
      cls/
  downloads/
    Pivot-Setup.exe
  README-offline.txt
```

其中：

- `pivot-image.tar`：在有网构建机上 `docker save` 导出的 Pivot 镜像。
- `docker-compose.yml`：生产机直接使用项目根目录的编排文件。
- `.env`：生产环境配置文件，按 `.env.example` 对齐后填写真实密钥、域名、模型服务地址和 OCR 配置。
- `models/paddleocr/`：PaddleOCR 模型外部挂载目录；模型不进入 Docker 镜像层。
- `downloads/`：可选，用于 Web 页面提供 Windows 客户端下载。

## 二、有网构建机准备

在源码目录执行：

```bash
docker build --build-arg PIVOT_BUILD_REVISION="$(git rev-parse --short HEAD)" -t pivot:latest .
docker run --rm pivot:latest node -e "require('@duckdb/node-api'); require('pdf-lib'); console.log('runtime ok')"
docker save -o pivot-image.tar pivot:latest
```

如果生产环境需要 OCR，当前基础镜像默认不内置 `paddleocr` 命令。必须在有网构建机完成其中一种准备：

1. 基于当前镜像制作包含 PaddleOCR/PaddlePaddle 运行时的自定义镜像，但仍把模型文件放在外部挂载目录。
2. 准备可挂载进容器的 PaddleOCR 可执行环境，并在 `.env` 中把 `PADDLEOCR_CMD` 指向容器内路径。
3. 不启用 PaddleOCR，改用已验证可用的其他 OCR 命令，并同步设置 `DOCUMENT_PROCESSING_OCR_ENGINE`。

完成后至少验证：

```bash
docker run --rm pivot:latest node -e "require('./server/services/document-processing/ocr/adapters/paddle').checkAvailability().then(console.log)"
```

如果返回 `available: false`，说明镜像或挂载环境里还没有可执行的 `paddleocr` 命令。离线生产机上不会自动补装。

## 三、准备 PaddleOCR 模型

模型建议放在离线包的 `models/paddleocr/` 目录下：

```text
models/paddleocr/
  det/  # PP-OCRv6 文本检测模型，必需
  rec/  # PP-OCRv6 文本识别模型，必需
  cls/  # 文本行方向模型，可选
  fonts/
    simfang.ttf  # 结果可视化字体，避免离线运行时下载
```

`docker-compose.yml` 会把宿主机目录挂载到容器内 `/app/models/paddleocr`。由于容器工作目录是 `/app`，生产 `.env` 中建议沿用项目相对路径：

```env
DOCUMENT_PROCESSING_OCR_ENGINE=paddle
PADDLEOCR_CMD=paddleocr
PADDLEOCR_LANG=ch
PADDLEOCR_CLI_VERSION=3
PADDLE_PDX_CACHE_HOME=data/paddlex-cache
PADDLE_PDX_LOCAL_FONT_FILE_PATH=models/paddleocr/fonts/simfang.ttf
PADDLEOCR_DET_MODEL_DIR=models/paddleocr/det
PADDLEOCR_REC_MODEL_DIR=models/paddleocr/rec
PADDLEOCR_CLS_MODEL_DIR=models/paddleocr/cls
```

如果不使用文本行方向模型，可不配置 `PADDLEOCR_CLS_MODEL_DIR`，并保持 `PADDLEOCR_ARGS=` 为空。旧版 PaddleOCR CLI 需要设置 `PADDLEOCR_CLI_VERSION=legacy`。

## 四、生产机导入与启动

将离线包上传到生产机，例如 `/data/pivot/`。如果 `docker-compose.yml` 使用外部网络 `ai-bridge`，生产机需要先创建该网络：

```bash
cd /data/pivot
mkdir -p data uploads downloads models/paddleocr
docker network create ai-bridge || true
docker load -i pivot-image.tar
docker-compose up -d --no-build
docker-compose ps
docker-compose logs -f --tail=100
```

如果生产机使用 Docker Compose v2，也可以把 `docker-compose` 替换为 `docker compose`。

验证健康状态：

```bash
curl -f http://127.0.0.1:3000/api/health
```

验证 OCR 命令和模型目录：

```bash
docker exec pivot sh -lc 'command -v paddleocr && ls -lah /app/models/paddleocr'
docker exec pivot node -e "require('./server/services/document-processing').getOcrEngineStatus().then(console.log)"
```

## 五、生产配置要点

- `COOKIE_SECURE=true`：生产 HTTPS 场景建议开启。
- `TRUST_PROXY=true`：如果前面有 Nginx、Ingress 或负载均衡，建议开启。
- `JWT_SECRET`、管理员密码、数据库和模型服务密钥：生产环境必须改成真实强密钥。
- `PIVOT_DOCUMENT_PROCESSING_DIR`：可按需指定文档处理输出目录；默认写入应用数据目录。
- `DOCUMENT_PROCESSING_MAX_CONCURRENT`：离线生产服务器资源有限时建议从 `1` 或 `2` 开始。
- `DOCUMENT_PROCESSING_MAX_OCR_PAGES`：控制单个任务 OCR 页数上限，避免大 PDF 长时间占用 CPU/GPU。

## 六、升级流程

有网构建机：

```bash
docker build --build-arg PIVOT_BUILD_REVISION="$(git rev-parse --short HEAD)" -t pivot:latest .
docker save -o pivot-image.tar pivot:latest
```

生产机：

```bash
cd /data/pivot
docker-compose down
docker load -i pivot-image.tar
docker-compose up -d --no-build
```

`data/`、`uploads/`、`models/` 和 `downloads/` 都是宿主机挂载目录，升级镜像不会覆盖这些数据。

## 七、回滚流程

如果保留了上一版镜像 tar：

```bash
cd /data/pivot
docker-compose down
docker load -i pivot-image-prev.tar
docker-compose up -d --no-build
```

回滚前建议先备份：

```bash
tar -czf pivot-data-backup-$(date +%Y%m%d%H%M%S).tgz data uploads models downloads .env
```

## 八、常见问题

### 1. 生产机执行 `up` 时尝试构建镜像

离线生产启动请使用 `docker-compose up -d --no-build`。如果镜像没有提前 `docker load`，该命令会直接失败，避免在生产机联网构建。

### 2. OCR 提示找不到 `paddleocr`

模型文件只解决权重问题，不等于 OCR 运行时。需要确保镜像或挂载环境中存在 `paddleocr` 命令，并且 `.env` 的 `PADDLEOCR_CMD` 指向正确路径。

### 3. PaddleOCR 首次运行仍尝试下载模型

说明模型目录未完整挂载，或 `.env` 中的 `PADDLEOCR_*_MODEL_DIR` 指向了错误路径。生产离线环境建议显式配置 `PADDLEOCR_DET_MODEL_DIR`、`PADDLEOCR_REC_MODEL_DIR`，并确认容器内路径存在。

### 4. 容器无法加入 `ai-bridge` 网络

当前 `docker-compose.yml` 使用外部网络 `ai-bridge`。生产机离线部署前执行 `docker network create ai-bridge` 即可，不需要联网。
