# 生产环境离线部署（v0.1.15）

本文档用于完全离线或受限内网生产环境。Pivot 主应用和 OCR 服务彻底解耦：本仓库只交付主应用镜像和主应用 `docker-compose.yml`，OCR 由独立项目单独交付和部署。Pivot 只通过 `OCR_SERVICE_URL` 调用外部 OCR HTTP 服务。

## 一、离线包内容

建议最终交付一个目录，例如 `pivot-offline-release/`：

```text
pivot-offline-release/
  pivot-image.tar
  docker-compose.yml
  .env
  data/
  uploads/
  downloads/
    Pivot-Setup.exe
  README-offline.txt
```

其中：

- `pivot-image.tar`：在有网构建机上 `docker save` 导出的 Pivot 主应用镜像。
- `docker-compose.yml`：只编排主应用 `pivot`；离线生产必须在 `docker load` 后使用 `--no-build` 启动。
- `.env`：主应用配置文件，按 `.env.example` 对齐后填写真实密钥、域名、模型服务地址和 `OCR_SERVICE_URL`。
- `data/`、`uploads/`、`downloads/`：主应用持久化目录。

OCR 镜像、OCR compose、OCR 模型目录和 OCR 缓存目录不属于 Pivot 离线包，由独立 OCR 项目提供。

## 二、有网构建机准备

在源码目录执行：

```bash
docker build --build-arg PIVOT_BUILD_REVISION="$(git rev-parse --short HEAD)" -t pivot:latest .
docker run --rm pivot:latest node -e "require('@duckdb/node-api'); require('pdf-lib'); console.log('runtime ok')"
docker save -o pivot-image.tar pivot:latest
```

主业务镜像不提供把 OCR 打进镜像的构建参数；OCR 运行时由外部项目部署。Pivot 对接协议见 [OCR服务对接协议.md](./OCR%E6%9C%8D%E5%8A%A1%E5%AF%B9%E6%8E%A5%E5%8D%8F%E8%AE%AE.md)。

## 三、OCR 服务准备

生产环境如需 OCR，请先部署独立 OCR 项目，并确保 Pivot 容器能访问它的 HTTP 地址。主应用 `.env` 中配置：

```env
DOCUMENT_PROCESSING_OCR_ENGINE=http
OCR_SERVICE_URL=http://ocr-service:9100
OCR_SERVICE_HEALTH_TIMEOUT_MS=3000
OCR_SERVICE_MAX_IMAGE_BYTES=52428800
DOCUMENT_PROCESSING_OCR_TIMEOUT_MS=120000
```

如果 OCR 服务不叫 `ocr-service`，可以把 `.env` 中的 `OCR_SERVICE_URL` 改成实际地址，也可以部署后由管理员在文字识别页面保存服务地址，例如：

```env
OCR_SERVICE_URL=http://ocr-service:9100
OCR_SERVICE_URL=http://10.0.0.25:9100
```

如果主应用和 OCR 服务都运行在 Docker 中，建议两边加入同一个外部网络：

```bash
docker network create ai-bridge || true
```

## 四、生产机导入与启动

将离线包上传到生产机，例如 `/data/pivot/`。如果 `docker-compose.yml` 使用外部网络 `ai-bridge`，生产机需要先创建该网络：

```bash
cd /data/pivot
mkdir -p data uploads downloads
docker network create ai-bridge || true
docker load -i pivot-image.tar
docker-compose up -d --no-build
docker-compose ps
docker-compose logs -f --tail=100
```

如果生产机使用 Docker Compose v2，可以把 `docker-compose` 替换为 `docker compose`。

验证主应用健康状态：

```bash
curl -f http://127.0.0.1:3000/api/health
```

验证 OCR 对接状态：

```bash
docker exec pivot node -e "require('./server/services/document-processing').getOcrEngineStatus().then(console.log)"
```

主应用返回的 `http.available` 为 `true` 表示外部 OCR 服务可达。

## 五、生产配置要点

- `COOKIE_SECURE=true`：生产 HTTPS 场景建议开启。
- `TRUST_PROXY=true`：如果前面有 Nginx、Ingress 或负载均衡，建议开启。
- `JWT_SECRET`、管理员密码、数据库和模型服务密钥：生产环境必须改成真实强密钥。
- `OCR_SERVICE_URL`：必须指向独立 OCR 项目的 HTTP 服务地址。
- `PIVOT_DOCUMENT_PROCESSING_DIR`：可按需指定文档处理输出目录；默认写入应用数据目录。
- `DOCUMENT_PROCESSING_MAX_CONCURRENT`：离线生产服务器资源有限时建议从 `1` 或 `2` 开始。
- `DOCUMENT_PROCESSING_MAX_OCR_PAGES`：控制单个任务 OCR 页数上限，避免大 PDF 长时间占用外部 OCR 服务。
- `DOCUMENT_PROCESSING_OCR_TIMEOUT_MS`：控制单页 OCR 识别请求超时。
- `OCR_SERVICE_MAX_IMAGE_BYTES`：控制单页图片发送给外部 OCR 服务前的字节上限，默认 50MB。
- `LONG_TERM_MEMORY_LLM_EXTRACTION_TIMEOUT_MS`：长期记忆模型抽取超时时间，默认 15000ms。
- `LONG_TERM_MEMORY_LLM_EXTRACTION_MAX_TOKENS`：长期记忆模型抽取最大输出 Token 数，默认 800；生产环境建议保持在 800~1200，避免 JSON 输出过长。
- `LONG_TERM_MEMORY_LLM_FAILURE_COOLDOWN_MS`：模型抽取超时后的按模型熔断冷却时间，默认 120000ms；冷却期间使用启发式规则，不会阻塞聊天主链路。
- `LONG_TERM_MEMORY_LLM_EXTRACTION=false`：如果生产环境模型端点不稳定或不需要模型抽取，可关闭模型抽取，仅保留启发式长期记忆提取。

## 六、v0.1.15 升级检查

升级前请备份 `data/`、`uploads/`、`downloads/` 和 `.env`，再导入新镜像并使用 `--no-build` 启动。升级后建议检查：

1. 打开智能体工作台，启动一个短任务，确认运行状态和执行步骤无需刷新即可更新。
2. 打开工作流、计划任务和评测中心，确认列表、运行批次和通知会自动同步。
3. 查看长期记忆任务，确认模型端点超时时只产生启发式结果，不会导致聊天请求失败或持续重复等待。
4. 生产 `.env` 至少补齐 `LONG_TERM_MEMORY_LLM_EXTRACTION_MAX_TOKENS` 和 `LONG_TERM_MEMORY_LLM_FAILURE_COOLDOWN_MS`；未配置时会使用安全默认值。

## 七、升级流程

有网构建机：

```bash
docker build --build-arg PIVOT_BUILD_REVISION="$(git rev-parse --short HEAD)" -t pivot:latest .
docker save -o pivot-image.tar pivot:latest
```

生产机：

```bash
cd /data/pivot
docker-compose down
docker load -i pivot-image.tar
docker-compose up -d --no-build
```

`data/`、`uploads/` 和 `downloads/` 都是宿主机挂载目录，升级镜像不会覆盖这些数据。OCR 服务按独立项目自己的流程升级。

## 八、回滚流程

如果保留了上一版镜像 tar：

```bash
cd /data/pivot
docker-compose down
docker load -i pivot-image-prev.tar
docker-compose up -d --no-build
```

回滚前建议先备份：

```bash
tar -czf pivot-data-backup-$(date +%Y%m%d%H%M%S).tgz data uploads downloads .env
```

## 九、常见问题

### 1. 生产机执行 `up` 时尝试构建镜像

根目录 `docker-compose.yml` 保留了 `build` 配置，方便有网环境直接构建；离线生产启动必须使用 `docker-compose up -d --no-build`，确保只使用已导入的镜像。如果镜像没有提前 `docker load`，启动会直接失败，避免在生产机联网构建。

### 2. OCR 服务连接失败或不可用

请确认：

- 独立 OCR 项目已经启动并提供 `/health` 和 `/ocr` 接口。
- 主应用 `.env` 中 `DOCUMENT_PROCESSING_OCR_ENGINE=http`。
- `OCR_SERVICE_URL` 是 Pivot 容器内可访问的地址。
- 如果使用 Docker 服务名，两边容器加入同一个外部网络，例如 `ai-bridge`。

### 3. 页面仍提示本地 OCR 命令不存在

说明运行环境仍使用了旧配置或旧镜像。请重新部署最新主应用镜像，并确认 `.env` 中 `DOCUMENT_PROCESSING_OCR_ENGINE=http`。

### 4. 容器无法加入 `ai-bridge` 网络

当前 `docker-compose.yml` 使用外部网络 `ai-bridge`。生产机离线部署前执行 `docker network create ai-bridge` 即可，不需要联网。
