# 多节点部署预检

**当前状态：多节点尚未就绪。** 多节点配置下，持久 Agent 事件已支持按用户游标从共享 PostgreSQL 补查，隔离测试覆盖两个进程及节点崩溃后续传；演示文稿、即时通知和流式快照仍缺少完整的跨节点投递与恢复，补查的生产负载也尚未验证。因此即使共享存储、队列和锁均已配置，预检仍报告 `multi_node_realtime_broadcast_unavailable`。生产环境应保持单节点，直到全部实时事件及故障恢复通过验收。

演示文稿可见编辑器提供文稿及评论的周期补查和连接恢复后同步，补查发现访问被撤销时退出编辑器。这只能缓解通知丢失，不覆盖所有实时类型，也不等于多节点就绪。

多节点模式下演示文稿在线状态使用共享 PostgreSQL，45 秒未续期后不再显示；每次读取重新过滤已经撤权或停用的账号，旧记录按批次清理。在线状态接口要求文稿访问权。该能力需要所有节点先完成数据库迁移；滚动升级时旧节点仍使用本地在线状态，不能保证新旧节点看到相同结果。在线状态共享不解决演示文稿事件、即时通知和流式快照的完整跨节点投递。

Pivot 的多节点运行使用 PostgreSQL 的持久化任务队列、`SKIP LOCKED` 声明和租约锁；所有节点还必须看见同一份业务数据与上传文件。仅设置 Redis、S3 或“集群模式”环境变量不会让实例进入多节点模式。

## 必需配置

```dotenv
PIVOT_DEPLOYMENT_MODE=multi_node
# 正式集群必须启用：预检不通过时应用拒绝启动。
PIVOT_REQUIRE_DEPLOYMENT_READY=true
PIVOT_DB_PROVIDER=postgres
DATABASE_URL=postgresql://pivot:***@postgres.internal:5432/pivot

# 由 NFS、SMB、CephFS 等提供，并挂载到每一个 Pivot 节点的相同业务目录。
PIVOT_SHARED_STORAGE_ROOT=/srv/pivot-shared
DATA_DIR=/srv/pivot-shared/data
PIVOT_UPLOAD_DIR=/srv/pivot-shared/uploads
```

`DATA_DIR` 和 `PIVOT_UPLOAD_DIR` 都必须位于 `PIVOT_SHARED_STORAGE_ROOT` 内。这样附件、知识库源文件、Agent 产物、任务恢复状态和审计大对象不会被困在某一台节点的本地磁盘。

## 发布前检查

### 持久事件补查索引

多节点 Agent 事件按 `(user_id, id)` 分页补查。对大型历史表，在代表性数据上通过 `EXPLAIN (ANALYZE, BUFFERS)` 测量并评估构建期间的 I/O、空闲空间和写入负载，再决定是否创建复合索引。工具默认只检查，不输出事件内容：

```powershell
$env:REALTIME_INDEX_DATABASE_URL = 'postgresql://运维账号:密码@数据库主机:5432/数据库名'
node scripts/realtime_event_index.js --schema=public
```

确认需要创建且在受控维护窗口执行时，使用表所有者或具有适当权限的账号，显式设置 `PIVOT_REALTIME_INDEX_CONFIRM=YES`，并在上述命令末尾添加 `--create`。脚本使用 `CREATE INDEX CONCURRENTLY`，构建前后校验目标结构，已有有效等价索引时跳过；名称冲突、其他工具实例持锁时退出。构建有 30 分钟语句超时与 5 秒锁等待上限，失败可能留下无效索引，脚本不会自动删除或重试；应由运维确认是否仍有构建、检查失败原因并在适当窗口处理。执行此工具不解除多节点实时预检阻断。

在每台节点的同一运行环境执行：

```bash
npm run preflight:deployment -- --require-multi-node
```

只有所有依赖与跨节点实时广播均已就绪时才能通过。未通过时进程会以非零状态退出，且服务健康详情会把部署状态标记为异常；应用保持单节点生效模式，不会虚报集群可用。

生产集群还应设置 `PIVOT_REQUIRE_DEPLOYMENT_READY=true`：若该开关与 `PIVOT_DEPLOYMENT_MODE=multi_node` 同时存在，启动阶段会拒绝任何未通过预检的配置。这样错误的副本不会以“单节点降级”方式加入负载均衡器。基础设施灰度迁移期间可暂不设置此开关，但不得增加副本。

## 说明

- 当前可运行的共享存储适配器是 `shared_fs`：由运维提供受控共享卷。S3 兼容对象存储的环境变量仍会被识别，但在完整文件读写适配器接入前不会获得多节点就绪状态。
- 显式配置 Redis/RabbitMQ/etcd 会被识别为外部适配器请求；当前不会把它们当作已经接线的生产能力。不要依靠仅有的 URL 进入集群模式。
- 所有节点必须使用同一 PostgreSQL 数据库、相同的加密密钥与共享卷权限；容器运行用户需要能读写 `data` 与 `uploads`。
