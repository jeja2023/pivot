# 工具库数据接入与本机能力设计方案

## 1. 状态与范围

- 状态：已按 v0.0.238 落地，持续维护
- 更新时间：2026-08-01
- 适用范围：工具库、会话工具调用、自主任务、工作流、数据分析工作台、桌面客户端、本地助手
- 核心命名：服务器可访问数据库
- 相关现状证据：
  - `client/chat/mcp-workbench-common.js`：工具库当前分为系统工具、报表文件、IM 通知、数据库连接和外部工具服务。
  - `server/services/database-mcp/`：数据库连接由后端执行，已有只读 SQL、白名单、脱敏、超时、TLS 和 SSRF/DNS rebinding 防护。
  - `server/services/builtin-mcp-reports.js`：报表文件由后端使用 `fs` 在配置根目录内读取，已有根目录约束、扩展名限制、大小限制和文件摘要/查询工具。
  - `使用帮助.md`：工具库面向普通用户、会话、自主任务和工作流，需持续明确本机路径、服务器路径和实际执行位置。

## 2. 设计结论

工具库应从“工具列表”升级为“数据来源 + 处理工具 + 输出动作”的工作台。用户先选择数据在哪里，再选择怎么处理，最后选择如何交付。

核心入口固定为三类：

- 服务器可访问数据库：由 Pivot 后端服务器发起连接，适合服务器本机、内网或云上数据库。
- 导入我的数据文件：用户上传 Excel、CSV、SQLite 等文件后转为数据集，适合网页版和一次性分析。
- 连接本机数据源：由桌面客户端或本地助手在用户电脑上执行，只把授权后的查询结果回传。

报表文件也按同样原则拆分：

- 服务器可访问报表目录：由 Pivot 后端服务器读取服务器目录、NAS 或共享目录。
- 导入我的报表文件：上传文件后进入数据集或临时分析。
- 授权本机报表目录：由桌面客户端或本地助手只读扫描用户电脑目录。

这套命名的目的，是让用户一眼知道“谁在执行、访问哪台机器、能不能用于自动化”。

### 2.1 v0.0.208 落地补充

- remote 桌面端不需要改成 local 模式：服务器继续提供统一模型、OCR/PDF、法规查询和工具治理，本机资源只通过桌面端反向执行。
- 聊天页必须默认加载本机执行器桥接脚本，并在发送启用工具库的消息前同步授权快照，避免工具库页面已显示 `mcp.0.*`，但普通对话请求里没有本机心跳。
- 对“查询本机目录下有哪些文件”这类文件清单请求，普通对话应确定性选择 `mcp.0.reports.list_files`，不得回退为让用户手工运行终端命令，也不得误用数据库 SQL 工具。
- 诊断提示按“桌面端心跳、报表目录授权、工具治理过滤”三层输出，帮助管理员快速判断问题落在客户端、授权还是服务端治理配置。


### 2.2 v0.0.211 落地补充

- remote 模式继续作为生产推荐形态：服务器统一提供模型、OCR/PDF、法规查询、文档处理和工具治理；用户电脑上的 SQLite 与报表目录仍由桌面端反向领取任务并只读执行。
- 本机报表目录的自然语言请求需要识别授权根目录名称。当授权目录标签或末级目录名命中用户问题（如“法律目录”）时，工具输入应为空过滤条件并列出根目录，而不是把“法律”作为文件名搜索词。
- 桌面端 IPC 执行结果必须结构化返回成功、状态码、错误码和错误消息；服务端据此区分 `ENOTDIR`、`ENOENT`、`EACCES` / `EPERM` 等本机路径错误，避免统一降级为 HTTP 500。
- `mcp.0.*` 是本机虚拟 MCP 服务，不对应数据库中的真实 MCP 服务行；调用日志应使用空服务 ID 和“我的电脑”展示名，避免外键约束失败。
- 本机报表目录工具应避免提前加载数据库 MCP 原生依赖，确保只列文件时不受数据库驱动或 asar 原生模块影响。


### 2.3 v0.0.212 落地补充

- 本机报表目录的 `reports.list_files` 必须保持轻量，只执行目录扫描和扩展名过滤，不应在列目录阶段初始化 Excel/工作簿解析依赖。
- 桌面端反向执行错误需要在服务端再次归一化状态码，避免 Electron IPC、前端脚本或旧客户端丢失 `status` 字段后把本机路径错误呈现为 HTTP 500。

### 2.4 v0.0.213 落地补充

- remote 桌面端本机执行器虽然不启动本地 Pivot 服务，但仍会加载部分服务端工具模块；执行前必须初始化 `DATA_DIR`、`PIVOT_UPLOAD_DIR`、`PIVOT_ANALYSIS_DIR` 和 `LOG_DIR` 到桌面端用户数据目录，避免打包后模块默认写入 asar 内部路径。
- 本机授权执行器应固定读取桌面端用户数据目录中的授权文件，不能被外部环境变量改写到另一份授权记录，避免“工具库显示已授权、执行器读到另一份配置”的状态差。
- 反向执行通道的错误结果应保留受控底层细节，服务端日志需要能区分授权路径错误、打包运行目录错误和权限错误。

### 2.5 v0.0.214 落地补充

- remote 本机 MCP 通道以 `mcp.0.*` 作为虚拟服务入口，服务端只负责任务登记、领取、结果回传、治理过滤和审计展示；本机 SQLite 与报表目录读取继续由桌面端/本地助手在用户电脑上执行。
- 普通对话对“本机目录/授权目录/我的电脑下有哪些文件”类请求必须优先匹配本机报表目录清单工具，且当查询词命中授权根目录名称时应列根目录，不把根目录名当作文件过滤条件。
- 工具库首页应把本机授权状态、可用工具数量、工具弹窗和刷新同步放在同一入口内，避免“已授权但看不到工具”或“工具库能看到、聊天页用不到”的状态差。
- 本机桥接诊断需要区分普通浏览器、旧桌面客户端、授权缺失、执行接口缺失、心跳失败、治理过滤和本机路径错误，并以中文提示用户下一步处理方式。
- 发布文档、用户帮助和项目汇报统一以 `v0.0.214` 作为当前版本锚点，后续远程桌面端打包和服务端部署均以该版本口径验收。

### 2.6 v0.0.216 落地补充

- 普通对话中的 MCP 工具结果必须被视为本轮最新事实，优先级高于长期记忆、历史对话和模型常识；尤其是 `mcp.0.*` 本机虚拟工具已返回结果时，不应再回答“无法访问本机文件系统”。
- 成功工具结果统一包裹 `PIVOT_MCP_TOOL_RESULT_BEGIN/END`，便于上下文预算、测试和后续诊断识别“已执行且可用于最终回答”的工具结果。
- 面向思考模型的最终上下文采用“assistant 工具结果 + user 基于结果回答”的末尾轮次，而不是仅依赖后置 system 消息，降低推理模型忽略工具结果或被长期记忆覆盖的概率。
- 上下文裁剪需要识别 `PIVOT_MCP_CONTEXT_*` 与 `PIVOT_MCP_TOOL_RESULT_*` 标记，将其作为本轮生成上下文保护；若工具结果仍不足，回答应说明缺少的信息，而不是回退为让用户手工查看目录。

### 2.7 v0.0.238 信息架构落地补充

- 工具库作为单层左侧导航中的一级入口，统一管理数据源、处理工具、输出动作和连接状态，不使用二级菜单承载这些资产。
- 用户侧统一使用“工具库”，不保留“工具箱”作为输入识别兼容；历史版本记录可保留旧称，但当前界面、帮助和提示必须使用新名称。
- 会话、自主任务和工作流共享同一套工具治理与授权结果：会话处理即时调用，自主任务执行多步目标，工作流承载可复用和计划运行的自动化。
- 工具库负责能力资产与连接治理，不重复提供会话或任务创建入口；用户在实际工作入口中选择已授权工具并查看调用结果。

## 3. 产品目标

- 降低误解：明确 `localhost`、本机目录、服务器目录分别指什么。
- 提升成功率：普通用户优先走导入文件，管理员和技术用户再配置服务器可访问数据源。
- 支持自动化：服务器可访问数据源可用于工作流、定时任务和共享服务。
- 支持个人即时分析：本机数据源用于当前设备、当前用户、当前授权场景。
- 统一下游工具：图表、报告、数据处理、格式转换都消费统一结构化结果，不关心数据来自哪里。
- 保持安全默认值：只读、最小授权、可审计、可诊断、可撤销。

## 4. 非目标

- 不让网页版绕过浏览器沙箱直接读取任意本机文件或连接任意本机端口。
- 不让服务器主动访问用户电脑的 `localhost`。
- 不把本机数据源默认放进定时工作流。
- 不在第一阶段实现完整 ODBC、Access、DBF 等历史数据库格式。
- 不把工具库变成复杂数据库管理器；它只提供 AI 分析所需的只读数据访问。

## 5. 用户与使用场景

### 普通用户

常见任务：

- 上传 Excel/CSV，询问趋势、异常、汇总和报告。
- 上传 SQLite 文件或导出文件，希望像数据库一样查询。
- 使用桌面客户端读取自己电脑上的报表目录。

默认引导：

- 优先展示“导入我的数据文件”。
- 对数据库术语做解释，不要求用户理解服务器网络。

### 业务管理员

常见任务：

- 配置内网业务数据库，供自己或团队分析。
- 配置共享报表目录，供周期任务读取。
- 设置白名单、脱敏字段和最大行数。

默认引导：

- 使用“服务器可访问数据库”和“服务器可访问报表目录”。
- 保存前必须测试连接或诊断目录。

### 系统管理员

常见任务：

- 配置全局共享数据源。
- 治理工具风险等级、审批要求、调用日志和告警。
- 限制普通用户可配置的私网目标。

默认引导：

- 在工具策略里管理系统工具和全局工具服务。
- 个人连接仍归所有者管理，但风险策略由系统规则兜底。

## 7. 数据源分类与执行位置

| 数据源 | 执行位置 | 适用终端 | 是否可共享 | 是否可用于工作流 | 典型例子 |
| --- | --- | --- | --- | --- | --- |
| 服务器可访问数据库 | Pivot 后端服务器 | Web / 桌面 | 可个人或全局 | 可 | `10.0.0.8:3306`、云 PostgreSQL、服务器 SQLite |
| 服务器可访问报表目录 | Pivot 后端服务器 | Web / 桌面 | 可个人或全局 | 可 | `\\nas\reports`、服务器 `D:\reports` |

| 外部工具服务 | 外部服务端 | Web / 桌面 | 可个人或全局 | 视服务能力 | 技术同事提供的 MCP 服务 |

所有卡片都显示四个标签：

- 执行位置：服务器 / 我的电脑 / 外部服务
- 归属范围：个人 / 全局
- 风险等级：低 / 中 / 高
- 自动化：可用于工作流 / 仅当前设备在线 / 不建议自动化

## 8. 服务器可访问数据库

### 8.1 命名与文案

入口名称：服务器可访问数据库。

说明文案：

> 由 Pivot 服务器发起连接，适合连接服务器本机、内网或云上数据库。`localhost` 指 Pivot 服务器，不是你的电脑。

### 8.2 支持范围

- PostgreSQL
- MySQL / MariaDB
- SQL Server
- MongoDB
- SQLite 文件路径

SQLite 在此入口中指服务器文件系统里的 SQLite 文件，不是用户电脑文件。

### 8.3 配置向导

步骤建议：

1. 选择数据库类型。
2. 填写连接地址、端口、库名、账号、密码或 SQLite 路径。
3. 设置安全策略：最大返回行数、查询超时、表白名单、字段白名单、敏感字段。
4. 测试连接并读取少量元数据。
5. 保存连接，刷新工具。

表单必须就近提示：

- `localhost` / `127.0.0.1` 指 Pivot 服务器。
- 生产库建议使用只读账号。
- 未配置白名单时仍受只读 SQL 和最大行数限制。

### 8.4 工具能力

SQL 数据库：

- `db.list_tables`：列出可查询表。
- `db.count_tables`：统计表数量。
- `db.describe_table`：查看字段结构。
- `db.run_readonly_query`：执行只读 SQL。
- `db.group_count`：按字段分组统计。

MongoDB：

- `db.list_collections`
- `db.count_collections`
- `db.sample_collection`
- `db.aggregate`

### 8.5 诊断结果

诊断应返回：

- 网络是否可达。
- 端口是否可连接。
- 账号密码是否通过。
- TLS/证书状态。
- 当前用户是否受私网地址限制。
- 可见表/集合数量。
- 白名单和脱敏配置摘要。
- 查询超时与最大返回行数。

诊断失败时给出业务可读建议，例如“服务器无法访问该地址，请确认数据库是否在服务器所在网络开放”。

## 9. 服务器可访问报表目录

### 9.1 命名与文案

入口名称：服务器可访问报表目录。

说明文案：

> 由 Pivot 服务器读取目录，适合服务器目录、NAS 或共享目录。填写的路径必须能被 Pivot 服务器访问。

### 9.2 支持范围

- CSV
- XLS / XLSX
- JSON
- TXT
- Markdown

后续可扩展 PDF、DOCX 等文档型报表，但不应混入第一阶段的表格查询工具。

### 9.3 配置向导

步骤建议：

1. 填写一个或多个根目录。
2. 设置允许扩展名。
3. 设置单文件大小上限。
4. 设置单次最大读取行数。
5. 执行目录诊断，预览可读文件。
6. 保存并刷新工具。

表单必须就近提示：

- `D:\reports` 是服务器上的目录。
- `\\nas\share\reports` 必须能被服务器进程访问。
- 不支持任意路径跳出授权根目录。

### 9.4 工具能力

- `reports.list_files`：列出授权目录内文件。
- `reports.read_file_summary`：读取文件摘要、表头、工作表和样本。
- `reports.query_table`：查询 CSV/XLS/XLSX。
- `reports.compare_files`：对比两个报表结构。

### 9.5 诊断结果

诊断应返回：

- 可读根目录数量。
- 不可读目录及原因。
- 可读文件数量。
- 被扩展名过滤的文件数量。
- 被大小上限跳过的文件数量。
- 前 5 个预览文件。

## 10. 导入我的数据文件

### 10.1 定位

这是普通用户的默认入口。用户无需理解连接概念，只需要选择文件，系统导入为数据集，然后用数据分析、会话、自主任务或工作流继续处理。

### 10.2 支持优先级

第一阶段：

- Excel
- CSV
- SQLite

第二阶段：

- JSON Lines
- Parquet
- 压缩包内单个数据文件

后续评估：

- Access
- DBF
- ODBC 导出

### 10.3 导入流程

1. 用户选择文件。
2. 系统上传到服务器受控目录。
3. 自动识别类型、表/Sheet、字段、行数和大小。
4. 用户选择导入范围。
5. 系统生成数据集。
6. 展示推荐问题和可用动作。

SQLite 导入建议：

- 展示库内表清单。
- 用户选择一张或多张表。
- 可选填写只读 SQL。
- 导入结果转成数据分析工作台的数据集。

### 10.4 与工具库关系

导入后的数据集应在工具库“数据来源”里出现。模型可调用数据集工具，而不是直接反复读取上传文件。

## 11. 连接本机数据源

### 11.1 定位

本机数据源只在用户显式授权后可用，由桌面客户端或本地助手执行。服务器不能直接访问用户电脑的 `localhost`、本机数据库或本机目录。

### 11.2 桌面客户端模式

适合已安装 Pivot 桌面客户端的用户。

能力：

- 选择本机 SQLite 文件。
- 配置本机 MySQL/PostgreSQL/SQL Server。
- 授权本机报表目录。
- 本地执行只读查询。
- 把结构化结果回传给服务器和模型。

优势：

- 权限弹窗更自然。
- 能复用 Electron 本地能力。
- 可本地保存密钥，服务器只保存连接摘要和授权状态。

### 11.3 浏览器 + 本地助手模式

适合必须使用 Web 的用户。

机制：

- 用户安装 Pivot 本地助手。
- 助手与服务器建立 WebSocket 或长连接反向通道。
- 浏览器作为控制台发起授权和查询。
- 本地助手执行只读查询并回传结果。

限制：

- 未安装助手时不可用。
- 当前设备离线时不可用。
- 默认不进入定时任务。

### 11.4 本机数据源卡片提示

卡片应显示：

- 执行位置：我的电脑
- 当前设备：设备名或助手名
- 在线状态：在线 / 离线 / 未授权
- 自动化：仅当前设备在线时可用
- 授权范围：数据库、表、目录或文件

### 11.5 当前落地状态

v0.0.202 已完成桌面客户端/本地助手授权中心的第一步闭环：工具库本机入口可打开授权中心，桌面客户端可选择本机 SQLite 文件或本机报表目录，并可撤销当前设备授权。完整本机路径只保存在桌面客户端本机配置中，页面只显示资源名称、设备名、授权时间和路径摘要。

当前已补齐桌面端/本地助手本机只读执行器：在桌面端本地运行的 local/direct 模式下，可由服务进程直接读取桌面端写入的授权摘要文件并执行只读工具；在生产 `remote` 模式下，服务器保持统一业务能力，只接收桌面端心跳上报的授权摘要和在线状态，并通过反向任务通道让桌面端领取 `mcp.0.*` 调用后在用户电脑本机执行。授权存在且本机执行器在线时，工具库会动态暴露“我的电脑”虚拟 MCP 工具：`mcp.0.db.*` 对应本机 SQLite 只读 SQL，`mcp.0.reports.*` 对应本机报表目录列出、摘要和表格查询。服务器仍不允许主动访问用户电脑的 localhost、任意本机路径或未授权目录，也不保存完整本机绝对路径。
## 12. 其它工具的协同边界

### 12.1 文档解析

文档解析不直接管理数据源。它消费：

- 上传附件的文本。
- 知识库文档的文本。
- 报表或本机目录中被用户选中的文档文本。
- 工作流上游节点输出的文本。

它输出大纲、键值、分段，不负责读取任意本机文件。

### 12.2 数据处理

数据处理只消费结构化 rows。来源可以是：

- 数据库查询结果。
- 报表查询结果。
- 导入数据集。
- 上游工具输出。

它输出字段画像、筛选结果、聚合结果和标准化 rows。

### 12.3 图表生成

图表生成只消费结构化 rows 和字段配置。它不访问数据库、不读取文件，只负责输出图表配置或表格展示。

### 12.4 报告编排

报告编排消费：

- 文本摘要。
- 表格。
- 图表。
- 指标块。
- 来源说明。

报告中必须保留关键数据来源标签，例如“来自服务器可访问数据库：销售库”或“来自导入数据集：2026销售表.xlsx”。

### 12.5 格式转换

格式转换只做轻量结构转换，包括 Markdown 表格、JSON 和规范化文本。不得承担数据源访问职责。

### 12.6 消息通知

消息通知只发送：

- 任务结果摘要。
- 报告链接。
- 审批提醒。
- 失败告警。

它不直接访问数据库或文件目录。

### 12.7 外部工具服务

外部工具服务保留给技术用户。必须显示：

- 服务地址。
- 认证方式。
- 健康检查状态。
- 工具 Schema 校验结果。
- 风险等级。
- 是否允许进入工作流。

## 14. 权限、审计与安全策略

### 14.1 默认只读

- SQL 禁止写入、DDL、多语句和管理类关键字。
- MongoDB 仅允许样本读取和只读聚合。
- 报表目录只允许在授权根目录内读取。
- 本机数据源只允许用户授权的连接、文件或目录。

### 14.2 最小返回

- 默认限制最大返回行数。
- 大结果分页或只返回样本。
- 图表和报告默认使用聚合结果，不直接塞入大表。

### 14.3 脱敏

- 调用日志脱敏密钥、Token、密码。
- 数据结果按敏感字段配置脱敏。
- 报告导出保留脱敏状态说明。

### 14.4 审计

所有工具调用应记录：

- 用户。
- 数据源。
- 执行位置。
- 工具名。
- 查询摘要。
- 返回行数。
- 耗时。
- 成功/失败。
- 是否触发审批。

本机数据源额外记录：

- 设备标识。
- 授权范围。
- 本地助手版本。
- 在线状态。

### 14.5 审批

高风险场景需要审批：

- 全局共享生产数据库。
- 未设置白名单的生产库。
- 返回行数较大的查询。
- 向 IM 群组发送包含数据摘要的报告。
- 外部工具服务调用高风险工具。

## 15. 工作流与自动化规则

可用于定时工作流：

- 服务器可访问数据库。
- 服务器可访问报表目录。
- 已导入数据集。
- 系统工具。
- 稳定外部工具服务。

默认不可用于定时工作流：

- 连接本机数据库。
- 授权本机报表目录。
- 浏览器本地助手能力。

如果后续需要允许本机数据源参与工作流，必须满足：

- 用户明确勾选“允许当前设备参与自动化”。
- 本地助手支持后台运行。
- 工作流展示“依赖某台设备在线”。
- 失败策略包含跳过、重试、通知用户。

## 16. 界面设计要求

### 16.1 工具库首页

首页不再只按 MCP 服务平铺，应以用户任务组织：

- 我要连接数据源。
- 我要导入文件。
- 我要处理数据。
- 我要生成图表或报告。
- 我要发送通知。

每个入口保留紧凑卡片，但卡片内必须包含执行位置和自动化状态。

### 16.2 配置向导

数据库和报表目录不要共用一个大表单。应按类型进入独立向导：

- 服务器可访问数据库向导。
- 服务器可访问报表目录向导。
- 导入我的数据文件向导。
- 连接本机数据库向导。
- 授权本机报表目录向导。

### 16.3 连接卡片

卡片字段：

- 名称。
- 类型。
- 执行位置。
- 归属。
- 状态。
- 最近诊断。
- 可用工具数。
- 操作：编辑、诊断、工具、停用、删除。

### 16.4 空状态

工具库空状态建议：

> 还没有数据来源。你可以先导入 Excel/CSV，或连接服务器可访问数据库。

不要默认推荐用户配置数据库，普通用户更适合先导入文件。

### 16.5 错误提示

错误提示必须说清楚执行位置：

- “Pivot 服务器无法访问该数据库地址。”
- “该路径是服务器路径，不是你的电脑路径。”
- “本机助手离线，无法读取当前电脑的数据源。”
- “该文件已上传，但超过单次分析大小上限。”

## 17. 后端架构建议

### 17.1 数据源注册表

新增或抽象统一数据源模型，兼容现有 MCP server：

- `source_type`
- `execution_location`
- `owner_scope`
- `workflow_availability`
- `status`
- `last_diagnosed_at`
- `diagnostic_summary`
- `metadata_json`

现有 `mcp_database_connections` 和 `mcp_builtin_configs` 可逐步映射到该模型，不要求第一阶段大迁移。

### 17.2 数据源执行器

执行器按位置分层：

- ServerDatabaseExecutor
- ServerReportDirectoryExecutor
- ImportedDatasetExecutor
- LocalDatabaseProxyExecutor
- LocalReportDirectoryProxyExecutor
- ExternalToolExecutor

下游统一返回结构化结果契约。

### 17.3 本机代理通道

本机能力需要双向通道：

- 桌面客户端：Electron IPC + 后端 API。
- Web 本地助手：本地助手与服务器建立 WebSocket 反向连接。

服务器不得主动调用用户电脑的 `localhost`。

## 18. 分期落地

### 第一阶段：命名和边界清晰化

- 将数据库入口命名为“服务器可访问数据库”。
- 将报表入口命名为“服务器可访问报表目录”。
- 配置表单增加 `localhost` 和服务器路径提示。
- 工具库卡片增加执行位置标签。
- 使用帮助同步更新。

验收：

- 用户能从界面判断路径/数据库由哪台机器访问。
- 诊断失败时能看到服务器网络相关提示。

### 第二阶段：导入我的数据文件

- 数据分析导入支持 SQLite 文件。
- Excel/CSV/SQLite 导入统一生成数据集。
- 工具库首页出现“导入我的数据文件”入口。
- 导入后展示推荐问题。

验收：

- 普通用户无需配置数据库即可分析本机文件。
- 导入数据集可被会话、自主任务和工作流引用。

### 第三阶段：配置向导重构

- 拆分服务器可访问数据库向导和服务器可访问报表目录向导。
- 增强诊断结果。
- 连接卡片展示执行位置、自动化能力、风险等级。

验收：

- 数据库、报表、IM、外部工具配置不再挤在一个复杂弹窗里。
- 管理员能快速定位连接失败原因。

### 第四阶段：桌面客户端本机 SQLite 与本机目录

- 桌面客户端支持选择本机 SQLite 文件。
- 桌面客户端支持授权本机报表目录。
- 工具库提供本机授权中心，展示设备、授权状态和可撤销入口。
- 完整本机路径只保存在桌面客户端或本地助手本机配置中，页面和服务器只接触授权摘要。
- 接入本机执行只读查询、目录扫描和文件摘要。

验收：

- 用户可在桌面端完成本机 SQLite 和目录授权，并能撤销授权。
- Web 端仅在检测到桌面端/本地助手并存在有效授权时暴露本机只读工具；未检测到客户端/助手时提示需客户端。

### 第五阶段：本机数据库与 Web 本地助手

- 支持本机 MySQL/PostgreSQL/SQL Server。
- 评估 ODBC/DSN。
- Web 端支持检测并唤起本地助手。
- 本机能力支持在线状态、版本检查和授权撤销。

验收：

- Web 用户安装助手后可访问本机数据库。
- 本机数据源默认不进入定时工作流。
