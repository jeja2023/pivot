## Shared resource boundaries

- Knowledge collections, database MCP connections and published agent workflows may be shared with an explicit unit or individual-user allowlist; all other assets remain personal by default. Knowledge collections are created and maintained by their owners; only the system `admin` account may manage a collection's shared scope, rebuild the whole knowledge index, or read the global deletion audit. Other administrator accounts retain only their own knowledge assets and do not receive these cross-user capabilities.
- Recipients have read-only access to shared knowledge, governed database read tools and published workflow definitions. Ownership, mutation, refresh, diagnosis, version management and secret management stay with the owner or administrator.
- Shared workflow execution resolves models, tools and credentials against the recipient account. Bindings are pinned to a published version, become stale after republishing, and must be reconfirmed before execution; credential secrets never enter the recipient payload.
- Every shared workflow response must redact direct HTTP credentials, and publishing or sharing a workflow containing sensitive HTTP literals is rejected.
- Every list, detail, retrieval, graph and cached result path must apply the same visibility predicate before returning data.

## 个人项目空间与技能资料（v0.7.147）

- 项目是当前账号的任务与资料工作区，集中维护规则、资料范围、文件和里程碑；复用任务创建、结果查看及产物预览，不新增另一种执行状态。
- 每次任务冻结项目规则版本，同时在规划和独立核验中使用；新任务与持续目标触发校验项目有效性，归档不改写旧任务。项目里程碑是进度记录，人工确认和已核验任务关联明确区分；关联依据失效应显示。
- 资源技能以指引和摘要绑定的配套文本/图片形成声明式配方；配套读取仍需显式工具授权。脚本、钩子和依赖不自动迁移，资源中的指令不提升权限。发布撤回及内容变化阻断后续使用和交付。
- 项目编辑使用修订冲突检查，异步结果绑定账号，退出清空界面；列表、表单、弹窗和移动布局沿用全局体系。具体限制和证据见[项目与技能资源升级](../reports/Pivot项目空间与技能资源升级-20261110.md)。

## 智能体执行协议与持续目标（v0.7.147）

- 工具截图属于受权限保护的观察资料，经格式校验后作为模型图像输入；支持视觉与否保持显式，不把截图文本、权限或模型说明当作实际操作成功。
- 最终验收读取完整持久证据，规划压缩不缩减验收范围；证据缺失、过期、撤权或超限时保留结果并明确未核验，不能改写为完成。
- 完成型目标接续同版本前次未完成事项、验收反馈和交付版本；前次任务未结束时继续处理原任务，定时任务和监控保留独立运行语义。触发资料与历史输出均不提升权限。
- 质量路由按最近窗口的唯一任务与执行模型身份计算，缺样本不虚报质量通过。升级不以更高价格直接推断任务能力更强。
- 本轮保持单组织范围；具体实现、合成真实模型验证和未完成方向见[改造与验收记录](../reports/Pivot智能体执行底座改造-20261110.md)。

## Docker 单镜像完整打包与运行依赖（v0.7.144）

- 默认主镜像完整包含 Git、ripgrep 和终端协议脚本，普通构建命令即可交付，不把终端必需依赖留给额外镜像或运行时安装；继续使用 slim 底座，并在构建阶段以非 root 身份检查工具和脚本。
- 主服务与隔离终端可以复用同一镜像的已登记不可变身份；终端实际执行继续经过原有签名、审批、Execution Grant 和容器隔离，打包完整不等于自动授权。
- PDF/A 的启动探测区分超时、缺少运行环境与配置失败；服务端保留30秒启动预算和短暂失败缓存，页面等待覆盖探测预算，恢复后允许重新检查。报告合规结果继续以实际验证证据为准。
- 构建依赖通过 npm 发布包与锁文件校验来源，保留原生编译和查询自检。源码版本、已构建镜像与历史导出包分别记录，体积变化或版本文档同步不能代替运行验证。范围见[v0.7.144发布说明](../releases/v0.7.144-Docker单镜像完整打包与运行依赖修复.md)。

## 制度材料审查与可编辑报告（v0.7.146）

- 法规查询中的材料审查复用制度文档、已复核效力版本、文档提取、持久任务及Word产物交付；普通公文格式/表达审校继续保持原语义。
- 用户显式选择业务日期、制度、材料与执行模型。按业务日期唯一匹配有效且已复核的版本；材料和制度不截断，超过当前模型上下文或产品范围时拒绝并说明分次处理方式。
- 逐条初审显示符合、不符合、待核实和不适用。制度与材料引用由服务端逐字检查；引用不全时降为待核实，不用原文片段匹配替代业务语义复核。结论、原文、版本、页码/字符定位及人工修订来源保持可见。
- 报告修订按版本保存，迟到响应不能覆盖保存中的新输入；未保存时不能导出或切换报告。导出覆盖全部所选条目及未完成项，直接产物编辑不能移除来源绑定。来源变更或撤回使旧报告读取和下载失效，已下载文件仍由持有人管理。
- 分批结果和累计计量持久保存，取消、过期、原任务停止和租约失效不得被迟到结果恢复为成功；从Agent发起时收紧剩余额度并计入既有用量，重启恢复与显式续跑不重置累计成本。
- 文本材料、TXT/Markdown、DOCX文字及文本型PDF为当前范围，Word图片与嵌入附件不参与审查；扫描或空白PDF页先要求文字识别复核。功能和验收边界见[v0.7.146发布说明](../releases/v0.7.146-制度材料审查与可编辑报告.md)。

## 数据分析至汇报 PPT 与任务交付体验（v0.7.143）

- 图表结果可直接生成已保存的可编辑汇报，复用既有文稿、模板、版本、检查与下载链；Agent 使用相同的固定快照转换，不重新编写数值。创建请求可重复接续，当前仅支持标准数据集图表，不将正式模型运行结果或复杂图类型静默降级。
- 汇报区分来源数据行数与当前展示分类，保留统计口径、排序、分类上限、导入截断及范围未知说明；图表与分页明细使用相同快照，不将类别排序描述为时间变化。
- 分析来源绑定在保存时保留，并在正文、历史版本、投屏与下载读取时重新检查当前账号、数据版本、字段权限和摘要。数据变化显示来源提示，用户编辑不因版本变化提示而自动丢弃；原权限撤回沿用现有访问失效处理。
- 对话任务优先显示核验缺口与结果文件。业务输入缺失、核验服务故障和内部交付缺口分别表达；部分完成、取消及核验未知不能呈现为完整核验成功。
- 实际验证与边界见[v0.7.143 发布说明](../releases/v0.7.143-数据分析至汇报PPT与任务交付体验升级.md)。不以该专项推断整体效率追平、所有办公软件兼容或生产就绪。

## 智能体执行、证据核验与Token优化（v0.7.142）

- 工具契约批量读取共用当前授权目录并整批确认，版本冲突、取消及不可见项不能遗留半批执行权限；发现与契约准备不作为业务交付证据。
- 长材料的模型侧结构化展开及压缩保留每项业务事实、错误、早期约束与原文引用；完整协议和持久记录继续用于审计及恢复。记忆核验绑定真实注入内容版本和当前范围，学习绑定服务端实际业务调用。
- 父任务等待子任务时持久回队并释放执行槽，恢复前核对直接子任务、当前权限、原始截止、控制消息和租约代次；规划消费的完成回执同时进入独立核验。批量创建保留父任务收尾额度并返回部分创建结果。
- 成功搜索与契约全文只在原工具消息中展开，任务事实摘要简述准备状态并保留原文引用；相同目标仅在当前请求已完整携带时去重。核验参数预览脱敏且限长，区分历史失败与后续修正，不替代实际执行和交付证据。
- 固定请求输入减少8.96%、四项任务总Token减少13.21%属于单模型专项证据；最终版本未重跑全部32次，不能认定整体效率追平。升级和验证边界见[v0.7.142发布说明](../releases/v0.7.142-智能体执行证据核验与Token优化.md)。

## 持续目标模型绑定（v0.7.140）

- 自动目标必须显式绑定当前账号可用的执行模型；新建时优先使用可用默认模型，编辑保留原绑定。原模型不可用或旧目标未绑定时要求重新选择，不静默替换；模型策略不能代替具体模型绑定。
- 创建、编辑、签名草案确认、测试运行和实际触发共用模型配置；保存及运行前检查模型状态和当前使用权限，局部编辑保留原授权、审批和目标类型。
- 模型列表复用既有账号模型来源；加载中、失败或为空时不能提交。响应同时绑定编辑序列和账号，关闭弹窗或切换目标、账号后旧响应不得覆盖当前选择。
- 用户可见说明区分配置和执行：生成草案、保存配置不调用模型，测试运行和每次触发执行会消耗模型用量；测试运行是一次独立真实任务，不启用持续调度。历史目标修复方法与验证边界见[v0.7.140发布说明](../releases/v0.7.140-持续目标模型绑定与运行校验修复.md)。

## 智能体执行与交付验收（v0.7.139）

- 工具发现的风险筛选与目录使用同一等级语义；能力和来源为可选精确筛选，空结果区分条件未匹配与没有授权工具，并只反馈当前任务可见目录的可用值。首次读取不同工具的有效契约可获得有界准备机会，重复读取不延长停滞窗口，契约准备不计业务进展或自动续跑依据。
- v0.7.139修复代码在单模型10项合成场景中通过独立验收：9项交付、1项正确等待业务输入。未读取恶意说明材料的样本不能证明暴露后的防护效果，也不等于全仓或生产认证；范围与升级说明见[v0.7.139发布说明](../releases/v0.7.139-智能体工具发现与准备进展修复.md)。
- 模型工具协议与内部工具标识分层映射，历史消息、指定工具和增量响应保持相同关联；转换不改变实际工具目录、参数、权限及审批。内部步骤标识在执行、审计和产物间一致，超长值使用稳定摘要并保留受控原始关联。
- 直接自然语言任务及旧空契约使用独立交付核验，回复非空不代表交付完成。真实缺少用户业务输入时等待补充；可自行修复的具体缺口在原授权和剩余额度内最多修复两次。核验不可用、来源撤销和预算耗尽不能记为成功。
- 新任务默认风险容量覆盖多步发现和交付；显式限额、旧快照、父子任务边界及累计计费继续生效。缓存就绪以当前命名空间和目标表的有效索引为准，不能用后备同名对象替代。
- 真实模型对照、合成业务夹具、工程回归和生产验收分别记录；19项历史失败复测通过不能替代全仓门禁或生产认证。发布范围与验证证据见[v0.7.138发布说明](../releases/v0.7.138-智能体执行与交付验收可靠性升级.md)。

## PPT 原稿编辑与离线视频

- v0.7.137设置将“模型配置”和“应用服务”分开：前者维护聊天、向量、重排序模型与检索策略；后者集中OCR、语音识别和PPT Master等应用连接，直接展示全部服务并复用既有配置模块。应用服务页仅管理员可见，写入和测试继续服从各服务原有权限，不复制配置值或另建密钥存储体系。

- v0.7.136系统admin可在模型配置页维护PPT Master全站连接并测试草稿，保存立即生效。地址和密钥加密保存且不回显密钥，更换地址不复用旧密钥；修改与任务接纳串行，运行/等待确认时提示先结束任务。页面设置优先于环境默认值，停用不回退旧连接，标准制作继续可用。

- v0.7.135完整PPT引擎优先作为独立内网HTTP服务，主应用仅配置地址和密钥；兼容协议的更新只替换服务镜像，PPT路径不授予主应用Docker权限或共享任务目录。服务不可用时保留标准创建、编辑、故事线与导出，完整引擎专属功能明确依赖状态；正在处理的原稿或制作任务不静默切换实现。

- v0.7.133生产部署把发布签名与镜像登记收进构建工具；首次登记发布公钥后，生产用单命令导入、验签、切换和检查。PPT信任与其他Worker隔离，失败恢复原配置，活跃任务不被更新中断；默认部署不启用Docker socket，显式安装后才授予可信协调进程。

- v0.7.131默认从AI自由设计开始，单位模板与原稿保留按需选择。内置用途、单位/个人和PPT Master模板进入同一目录，分别说明可用制作方式；旧配色从默认选择收起，历史版本与文稿快照保留。明确换主题时一起处理背景和文字，普通保存不主动改色；编辑画布、缩略图与导出使用文稿自己的颜色，不继承工作区主题。
- v0.7.132创建前统一填写整稿目标并自动带入结构化初稿；编辑侧栏保持“结构”短标签，主要维护逐页职责、结论和衔接，整稿目标默认折叠。“按故事线调整”独立调用模型，方案在统一弹窗中对比页序、结构和文字，显式确认后保存新版本；生成、预览、取消与保存状态分明，旧稿变化后拒绝应用。

- v0.7.128原稿工作台以源PPTX包为权威，逐类开放字段并定点写回，保留未知原生内容；下载后可再导入，版本冲突不能覆盖新稿。
- 使用局域网内的禁网受限执行镜像，无需模型或公网。页面视频必须明确确认，不把静态页面和静音轨道宣称为原生动画或真实旁白。
- 原稿版本和预览以既有CAS持久保存，修改、恢复和交付按租户/账号、任务租约及预期版本共同约束；静态预览与目标Office兼容性分别验证。

## Brand

- Personality: 稳定、可信、清爽、内网办公友好，强调可控、可审计和高效率。
- Trust signals: 来源可见、权限清楚、操作可撤销或可追踪、重要结论有依据、失败原因可理解。
- Avoid: 营销页式大英雄区、过度装饰、炫技动画、隐式上下文、模糊权限边界、让底层实现名主导用户表达。

## Product goals（产品定位）

- Goals:
  - 为私有化、离线化和企业内网场景提供统一 AI 工作入口。
  - 让普通用户能围绕资料、数据、工具和应用完成具体工作，而不是学习底层技术。
  - 让管理员能治理模型、知识、工具、数据源、审计和系统状态。
  - 让统一任务中心承接执行过程，让自动化中心承接工作流与计划资产。
- Non-goals:
  - 不做开放互联网营销站。
  - 不把普通用户暴露在 MCP、RAG、向量库、服务端路径等底层概念里。
  - 不让单个业务应用自成一套导航、样式或权限模型。
  - 不牺牲安全审计来换取短期便利。
- Success signals:
  - 用户能清楚判断本轮回答是否使用了知识库或工具库。
  - 用户能理解数据来源在哪里、由哪台机器执行、是否可用于自动化。
  - 管理员能快速定位模型、知识库、工具库和任务运行问题。
  - 新增业务应用能复用全局工作区、弹窗、表格、分页、上传和状态反馈。

## Personas and jobs

- Primary personas:
  - 普通业务用户：提问、上传资料、查询知识、导入数据、生成报告。
  - 业务管理员：维护知识库、法规资料、工具连接、规范库和部门工作流。
  - 系统管理员：配置模型、全局参数、API Key、工具策略、审计和系统状态。
  - 技术实施人员：接入外部工具服务、数据库、部署环境和本地助手。
- User jobs:
  - 从内部资料中获得可靠回答。
  - 把表格、数据库、报表和文档转为分析结论。
  - 起草、审校和导出正式办公材料。
  - 将临时任务沉淀为可复用工作流。
  - 在出错时知道下一步该检查什么。
- Key contexts of use:
  - 内网、私有化和弱网环境。
  - 多角色权限共存。
  - 中文办公材料、制度、法规、表格和报告为主。
  - Web 与桌面客户端并存，桌面端可承担本机能力。

## Information architecture（信息架构）

- Primary navigation（左侧仅使用一级菜单，不设置二级菜单）:
  - 搜索：打开全局搜索弹窗，默认搜索会话，可切换任务和工作流。
  - 应用：打开应用中心，承载公文写作、数据分析、数据建模、法规查询、OCR/PDF 等业务应用。
  - 任务：打开统一任务中心，汇总自主任务、工作流任务和计划运行记录；新建任务按需展开。
  - 自动化：打开工作流和计划资产中心；默认展示资产列表，编辑时进入工作流画布。
  - 知识库：打开知识库管理工作台，承载资料上传、专题库/标签、召回测试、质量报告和知识图谱。
  - 工具库：打开数据源、工具和连接管理，承载系统工具、个人连接、外部服务和治理诊断。
  - 最近会话：直接打开对应会话，承担高频上下文切换。
  - 设置：管理员进入系统设置，普通用户进入个人设置。
- Core routes/screens:
  - 聊天主界面：会话、输入、附件、知识库/工具库状态、回答来源提示。
  - 主工作区：知识库、工具库、应用中心和设置等都在统一工作区中打开。
  - 应用工作台：面向具体业务流程，强调列表、详情、任务、结果和导出。
  - 弹窗/抽屉：承载配置、上传、确认、审校、资源选择和详情查看。
- Content hierarchy:
  - 先展示当前任务和可操作状态。
  - 再展示来源、范围、配置和治理信息。
  - 复杂说明放入帮助、详情或模块设计文档，不占据高频工作区首屏。

## Design principles（交互原则）

- 渐进展开：首屏只放高频任务和必要状态；配置、治理和高级能力按需进入弹窗或详情。
- 依据可见：知识库引用、文件来源、数据源、工具调用和报告依据必须可见。
- 执行位置清楚：涉及文件、数据库和本机能力时，必须说明由服务器、我的电脑还是外部服务执行。
- 状态就近：加载、失败、诊断、审批、任务进度应出现在对应操作区域，不漂移到底层工具条。
- 入口去重：同一能力只保留一个主入口；不同入口必须对应不同用户心智或执行位置。
- 管理与使用分离：普通用户看到任务入口；管理员看到治理入口；系统管理员看到全局策略。
- Tradeoffs:
  - 低门槛优先于一次性暴露全部能力。
  - 可审计和安全边界优先于“看起来更方便”的隐式调用。
  - 复用全局组件优先于局部页面视觉创新。

## Visual language（视觉与组件）

- Color: 使用项目全局主题变量。主色表达可执行操作，危险色只用于破坏性操作，状态色表达成功、警告、错误和禁用。
- Typography: 中文办公阅读优先，字号层级克制；工具、卡片、表格内不使用英雄级标题。
- Spacing/layout rhythm: 工具型界面保持紧凑但留足扫描间距；列表、表格、筛选、分页节奏与现有工作区一致。
- Shape/radius/elevation: 卡片和弹窗半径控制在 8px 内；阴影只用于弹窗、浮层和必要层级，不制造装饰性漂浮感。
- Motion: 仅用于加载、展开、切换和反馈；尊重减少动态效果设置，不做持续吸引注意力的动画。
- Imagery/iconography: 工具入口优先使用清晰图标和短标签；业务应用可使用轻量图标，但不使用纯装饰图。

## Components

- Existing components to reuse:
  - 全局按钮、输入框、表格、分页、弹窗、上传控件、状态徽标和确认框。
  - 主工作区布局、应用中心工作台布局、设置页表格与筛选布局。
  - 知识库、法规查询、数据分析中已经沉淀的列表、详情、上传和诊断模式。
  - 应用中心任务型工作台必须复用法规查询沉淀的数据表格、分页、弹窗和操作列模式；OCR/PDF 等处理型应用主页面只承载上传、筛选和任务列表，识别/处理结果、预览和输出明细进入查看弹窗、详情页或独立结果页。
- New/changed components:
  - 聊天输入操作区：附件、知识库、工具库、上下文、模型名称和发送动作按使用顺序排列；不提供重复的清空按钮。
  - 模型选择触发器：位于输入框右侧、发送按钮左侧，仅显示当前模型名称；能力标识与说明放在展开列表中，长名称省略且不挤压发送按钮。
  - 数据源卡片：显示执行位置、归属范围、风险等级、工作流可用性。
  - 配置向导：数据库、报表目录、本机能力和外部服务分类型配置。
  - 来源提示条：展示回答、报告或图表来自哪些知识、文件、数据源和工具。
  - 本机助手状态：展示设备、在线状态、授权范围和不可用原因。
- Variants and states:
  - 加载、空、失败、禁用、无权限、待审批、已脱敏、离线、部分成功。
  - 个人、全局、服务器执行、我的电脑执行、外部服务执行。
- Token/component ownership:
  - 组件和样式实现规则归 `开发规范.md`。
  - 本文件只定义产品语义、信息层级和交互意图。

## Accessibility

- Target standard: 以键盘可达、焦点清晰、语义明确、文字可读为最低要求。
- Keyboard/focus behavior:
  - 弹窗、确认框、上传区、表格操作和工具卡片必须可键盘操作。
  - 关闭、取消、提交、危险确认要有稳定焦点顺序。
- Contrast/readability:
  - 状态徽标、辅助说明、错误文本必须满足可读对比度。
  - 禁止仅靠颜色表达风险或状态。
- Screen-reader semantics:
  - 上传、进度、错误、审批和工具调用状态应有可读文本。
  - 图标按钮必须有可理解的 `aria-label` 或同等文本。
- Reduced motion and sensory considerations:
  - 长回答回放、进度动画和图表动画应支持降低动态效果。

## Responsive behavior

- Supported breakpoints/devices:
  - 桌面浏览器和桌面客户端为主要生产力场景。
  - 移动端支持查看、轻量提问、审批和简单管理，不追求复杂工作流编辑。
- Layout adaptations:
  - 桌面端优先左右或上下分区，保证列表与详情可并行扫描。
  - 窄屏下将侧栏、筛选、详情和操作区堆叠，核心动作靠近内容。
  - 表格在窄屏应优先保留关键列，复杂字段进入详情。
- Touch/hover differences:
  - 不依赖 hover 才能发现关键操作。
  - 悬浮信息必须有点击或详情替代入口。

## Interaction states

- Loading: 显示正在处理的对象、阶段和可预期结果；长任务进入任务状态而不是无限等待。
- Empty: 给出下一步主动作，例如上传资料、导入数据、连接数据源、创建工作流。
- Error: 说明发生在哪个执行位置、用户能做什么、是否需要管理员处理。
- Success: 提供后续动作，例如查看结果、生成图表、加入报告、发送通知、保存为工作流。
- Disabled: 说明禁用原因，例如无权限、工具停用、设备离线、配置不完整。
- Offline/slow network:
  - 服务器能力失败时提示网络、权限和服务状态。
  - 本机能力失败时提示桌面客户端或本地助手状态。

## Content voice

- Tone: 简洁、明确、稳重，不把技术细节推给普通用户。
- Terminology:
  - 用户侧统一称“工具库”，不以 MCP 作为主名称。
  - 数据库入口使用“服务器可访问数据库”。
  - 报表目录入口使用“服务器可访问报表目录”。
  - 本机能力使用“连接本机数据库”“授权本机报表目录”。
  - 知识库强调“资料”“来源”“命中”“依据”。
- Microcopy rules:
  - 先说结果，再说原因，再说下一步。
  - 涉及 `localhost`、路径、数据库、权限时必须说明执行位置。
  - 错误提示避免暴露密钥、完整连接串、敏感路径和内部堆栈。
  - 面向普通用户少用底层实现名；必要技术名词放在中文解释中。

## Implementation constraints

- 代码审查模板沿用技能导入与个人发布入口，只提供当前授权的本机工作区只读工具。用户显式选择后才生效；模板加载、文件上传和预览的旧响应不得覆盖新选择。审查报告明确实际范围、证据与未验证项，不能直接批准生产发布。详见[代码审查指引与对照评测方案](代码审查指引与对照评测方案-2026-11-08.md)。
- Framework/styling system:
  - 实现必须遵守 `开发规范.md` 的 UI 复用、样式来源、文件拆分和测试要求。
  - 本文件不重复列出 `.btn-primary`、`.form-input` 等 class 规则；具体实现以 `开发规范.md` 为准。
- Design-token constraints:
  - 不新增局部主题体系。
  - 新语义状态确实需要颜色或尺寸 token 时，先评估是否应进入全局样式。
- Performance constraints:
  - 首屏避免加载低频工作台和大图表库。
  - 大文件、OCR、PDF、数据库查询和智能体运行走任务或分页，不阻塞普通请求。
- Compatibility constraints:
  - 私有化、内网、Docker、桌面客户端和弱网场景都要保留清晰失败路径。
  - 已废弃的用户侧名称不保留输入识别兼容；底层协议与历史数据只在确有迁移需要时兼容。
- Test/screenshot expectations:
  - UI 改动需要覆盖桌面和窄屏布局、空状态、错误状态和长文本。
  - 涉及工具库、本机能力、上传和数据源时，必须验证权限与执行位置提示。

## Module Design Index

- PPT 视觉品质与设计技能：`docs/design/PPT视觉品质与设计技能升级方案.md`
  - 完整制作弹窗将制作要求与参考材料分区，使用共享弹窗表单控件；预算和轮次折叠至高级设置，底部主操作固定可达。Word、文本型PDF及文本材料复用既有PPT材料解析，保留文件来源；空白、失败与截断材料阻止启动，取消读取后不接纳迟到结果。
  - 设计主题、语义布局、字体测量及视觉复核协同工作，保持原生可编辑内容与来源。
  - 视觉检查明确具体页和当前内容版本，未检查或模型不可用不能冒充通过；先修正再重检。
  - 新主题按语义页面编译并保留全文拆页；整稿检查在后台执行，排版建议确认后应用，避免覆盖后续编辑和批准页面。
- 对话文档生成 PPT：`docs/design/对话文档生成PPT任务方案.md`
  - 会话任务复用 PPT 工作台的源稿、模板、检查、导出与交付链；读取完整材料后一次生成全部页面。
  - 完整 PPTX 与单页 SVG/PNG 明确区分，交付验收检查真实文件格式；任务标题保留附件名并隐藏路径。
- 公文写作：`docs/公文写作设计方案.md`
  - 首页列表化，单篇编辑聚焦正文，辅助能力通过弹窗进入。
  - 备份与恢复属于低频管理操作，放入“更多”，按“备份这篇公文／用备份恢复公文”成对命名；普通用户首屏只需理解创建、查找和编辑，不暴露备份文件的技术格式。
  - 本篇材料和知识库引用必须可见，并作为 AI 起草、审校和改写依据。
- 工具库数据接入：`docs/design/工具库数据接入与本机能力设计方案.md`
  - 工具库采用“数据来源 + 处理工具 + 输出动作”心智模型。
  - 明确服务器可访问数据库、服务器可访问报表目录、导入数据文件和本机能力的执行位置。
- 文档处理、OCR 与 PDF：`docs/design/文档处理底座与OCR_PDF工具应用分阶段开发方案.md`
  - 先建设共享文档处理底座，再复用到 OCR、PDF、知识库、法规查询和聊天附件。
  - OCR 与 PDF 能力应区分文本抽取、版面预览、识别结果和导出结果。
  - OCR/PDF 任务列表必须沿用法规查询的数据表格布局，表头、完整边框、行高、状态徽标、操作列和分页保持全局一致。
  - OCR 识别结果、PDF 处理结果和输出文件清单不得直接铺在主页面；通过查看入口进入弹窗/详情页，下载入口统一放在操作列或结果弹窗中。
- 知识库：
  - 以专题库、标签、召回测试、质量报告和来源可见为核心。
  - 普通聊天按需启用知识库，不默认把整库注入上下文。
- 数据分析：
  - 以导入数据集、字段画像、查询、透视、图表、对比和导出为核心。
  - AI 结论必须保留数据集和查询来源，正式汇报前提示人工复核。
  - BI 数据建模生产建设基线：[Pivot BI 数据建模生产级建设方案 v2.0](Pivot_BI数据建模产品级建设方案-2026-11-06.md)；状态为方案设计，生产门禁尚未执行。
  - 正式模型以事实粒度、受控维度关联和统一指标为核心；生产必交包括版本/文件一致性、当前权限、隔离执行器、容量认证、备份恢复及 G0—G7 上线门禁。遵守当前单活部署与多节点预检边界，保留旧关联探索兼容行为。
- 法规查询：
  - 以法规文档、版本、条文级检索、来源下载、归档治理和基于条文的 AI 问答为核心。
  - 法规结论必须能回到条文和源文件。
- 任务与自动化：
  - 自主任务用于探索和试跑，工作流用于稳定、可审计、可复用流程，计划任务用于周期执行。
  - 任务中心管理运行，自动化中心管理工作流和计划资产，两者不再作为同一“智能体”菜单的二级入口。
  - 新建自主任务的快捷目标属于配置预设，只填入目标和推荐策略，不应绕过用户确认直接启动；当前配置可以保存为模板复用。
  - 最大执行轮次属于高级安全边界，默认按运行模式自动选择而不是使用偏小的固定值；标准模式 30 轮，深度模式 60 轮，审查模式 50 轮，人工配置受对应模式上限约束。单次任务 Token 上限独立控制累计输入和输出，留空或 `0` 表示不限。
  - 达到执行轮次或 Token 上限时必须保留已有结果并明确提示可能不完整；运行详情应区分模型“执行轮次”和持久化“执行记录”，工作流 DAG 继续以节点记录为主。
  - 自主任务必须把“正在规划、正在执行、等待审批、已完成、部分完成或失败”作为可理解的运行状态呈现；恢复、重试和重复唤醒不能制造重复的外部副作用。
  - 工具调用先经过权限、风险、预算、网络和副作用策略，再进入具体执行器；只读操作可按输入哈希和操作键幂等重放，写操作恢复必须显示审批和影响范围。
  - 任务事实摘要只简述成功的搜索和契约准备，不重复展开工具消息中已有全文，错误与业务事实及原文引用保留。当前请求已携带完全相同目标时可去重，目标变化仍完整显示；持久状态与独立核验不随提示精简而省略。
  - 涉及本机文件、数据库、命令或浏览器时，必须明确执行位置；桌面 Worker 使用授权工作区、命令白名单、超时、输出上限和网络白名单，不能把服务器路径或隐式权限带入本机执行。
  - 运行详情应提供结果优先的摘要，同时保留步骤、审批、策略决定、重试、用量和审计引用；大结果通过安全 Blob 引用展示，不把完整敏感载荷直接铺在页面。
  - 工作流名称和简介在资产列表中独立编辑，详情页专注节点编排；节点名称允许就地编辑，但提交边界必须清晰，不能因逐字保存导致焦点丢失。
  - 节点输出统一提供格式化文本、纯文本和结构化数据三种用户模式；结构化数据绑定 JSON Schema，并以可视化编辑、预览、校验和字段选择降低使用门槛。
  - 下游引用应根据上游 Schema 提供字段选择器；表格和文件产物属于 JSON 数据与文件引用的展示层，不引入 YAML/XML 作为内部承载格式。
  - 工具范围、审批、失败重试和结果产物必须可见。
- 个人自主进化与组织受控共享：`docs/design/Pivot个人自主进化与组织受控共享实施方案.md`
  - 个人域允许在无权限扩大、无副作用的范围内自动沉淀并启用已验证经验；组织域只能通过脱敏候选、评测、审批、签名、灰度和回滚发布。
  - 用户侧使用“我的记忆、我的经验、待确认改进”三个概念；底层版本、Trace、评测和签名只在高级治理视图出现。
- 系统设置与治理：
  - 面向管理员，使用高密度但清晰的表格、筛选、详情和诊断布局。
  - 全局策略与个人资源管理边界必须清晰。
  - 系统监控分为运行概览、服务与资源、对话质量。概览提供运行异常摘要，资源详情与用量归入服务页，质量统计与异常复核归入质量页；评测案例与标准答案由独立“评测审核”菜单管理。
  - 任务理解故障不等于业务目标不明确；故障时允许受限文本回复并关闭未确认执行。监控区分24小时决策组件错误与30天任务交付失败事件，提供分页明细、缺项及历史报告来源。
  - 监控使用自然高度及响应式列数，不通过固定面板数量和整体高度缩放隐藏内容；全部健康检查可访问。
  - 指标必须注明实例/全局范围和采样时段；无样本、探针不可用与平台不支持不得表达为健康零值。

## 已有功能可靠性要求（v0.7.94）

- 编辑中的“已保存”以服务端确认对应快照为准；返回列表或切换文稿前保存最新修改，失败保留输入并提供重试，关闭页面覆盖在途保存。
- 本机草稿绑定当前账号。迟到的保存、加载与恢复回调必须同时核对原账号和编辑会话，不能通过猜测本机缓存键恢复其他用户内容。
- 数据分析的查询、图表、透视、指标和计算字段共用显示数值转换规则；原始数据保留。关联质量与业务统计口径分开显示，扩行和未匹配记录需要清楚提示。
- 页面异步结果绑定请求序列和当前资源；切走后再回到相同资源，也不能接收旧编辑周期的结果。隐藏工作区停止相关轮询，替换图表释放旧实例。
- 普通聊天生成请求按账号和会话持有，站内切换只切换展示；恢复已有流式正文，避免重复挂载已保存消息。停止与新消息替换只作用于同一会话，后台完成不能覆盖当前会话按钮或内容。
- 停止普通回复时保存已公开正文并标记未完成，刷新后可读取；中止与结束只确认一次保存，不把未核验知识内容、工具参数或临时语音写入历史，也不自动从半截答案提取长期记忆。
- 保存的分析快照读取时复核当前来源版本与字段权限；缺少必要版本时提示重新生成，不用历史缓存绕过权限收紧。
- 多项目处理区分成功、部分完成和失败。取消、失效执行权与来源变更不能被后续重试回调恢复为执行中或成功。
- 文件清理只有在引用查询成功、目录边界及文件身份确认后进行；数据库不可用保留文件。验证报告区分固定源码回归、受控服务与目标环境验收。
- 模型端点故障统计只反映真实上游失败，用户取消、调用方截止、排队拒绝和熔断准入拒绝不得增加失败计数。熔断提示保留最初根因，重复请求不得续期；实际上游超时和连接失败继续受保护，成功响应后恢复。

## 聊天图形展示要求（v0.7.95）

- Mermaid 回复默认显示图形，源码置于同一区域的切换视图。流式未完成、加载中和失败状态在图形区域内显示，失败提供源码与重试入口。
- 任务已有可下载 SVG 时，结果文件统一承担图形预览、下载和本机保存；正文源码收起为补充内容，展开后仅保留查看和复制，避免重新出现重复按钮。不能仅凭标题或文件类型宣称正文源码与生成文件一致。
- 图形下载与源码保存使用明确的不同文案；SVG 来自实际渲染结果，本机源码保存沿用现有授权目录和交付流程。
- 放大查看复用全局工作区弹窗与按钮，支持缩放、键盘关闭和焦点恢复；桌面与窄屏均可访问全部操作，图形沿用当前主题。
- 图形组件按需加载本站离线资源，在隔离页完成布局后以静态图片展示。主页面不直接插入第三方 SVG，下载前也检查外部资源、动态内容与尺寸。
- 重绘、节点移除、账号切换及页面离开后释放旧图片和渲染资源，迟到结果不能恢复旧内容。

## 上传资料与检索范围（v0.7.96）

- 用户上传的正文就是附件分析的依据；没有外部查证请求时，不自动要求联网或知识库。附件、代码、引用和文件名里的能力词不构成用户指令。
- 短附件的分析及相关追问直接进入回答；长附件和文件交付保留受控任务与原始来源分页读取，不把全文塞入意图决策提示。
- 当前用户明确排除的来源优先于历史范围、默认开关和模型建议。该限制同时约束普通聊天的路由、任务交接、续接、工具目录和实际执行。
- 知识库不可用不阻断已有附件的分析；未核实的外部事实须说明限制，不能虚构检索结果。用户明确要求查询外部资料时继续走对应授权和检索路径。

## 对话智能路由判断与续接（2026-11-06）

- 本轮限制先收紧当前任务与来源范围；同一句话仍包含实质工作时继续统一语义判断，纯纠正、停止和撤销保留即时控制。
- 记忆快速路径只处理可确定的纯偏好；混合偏好和工作、词语讨论交给语义入口。短附件快速路径仅承载文本分析，文件交付和实际操作使用任务路径。
- 路由 Schema、必填校验与跨字段规则保持一致；原生结构化输出使用按动作区分的最小字段分支；不兼容时仅对供应方明确能力拒绝进行一次兼容调用。瞬时服务故障在原预算内最多重试一次，认证、权限、输入错误、取消与截止不能触发重试。
- 任务续接用结构化业务范围替换时间、地区、对象和格式，保留安全限制及仍需能力；已撤销来源不能由历史能力恢复。明确继续且唯一活动中的已有任务可直接续接，暂停、歧义或新主题仍使用语义判断。更新经任务契约、控制消息和运行工作状态保持一致。
- 上下文读取、排队、模型和学习建议共用截止与取消信号；可选记忆和目录不可用不等于目标不明确。观测区分上下文、排队、上游和总等待时间。
- 裁剪目录必须显示真实完整度，显式选择优先保留。长请求保留中段限制片段并标记不完整；需要业务工具时先受控读取完整原文，目录和实际执行均校验读取进度。
- 工程边界集、保留验证集、入口级评测、多轮控制消息和真实模型证据分别记录；禁止行为、实现摘要和配置也是验收的一部分。

## 智能路由执行衔接（v0.7.149）

- 自动任务的目标长度与原始资料长度分别校验。长附件通过持久消息分页读取，业务工具执行前须读全来源；无法创建任务时明确返回失败，不把已经识别的任务静默改为普通回答。
- 显式纠正、来源撤销先于短附件直答，核验阶段同样接受停止与暂停。任务控制复用运行时状态，等待审批和等待提交不得显示成已经结束。
- 续接更换知识库或标签时重新校验权限与项目范围，更新运行选择并清除旧检索上下文。资料修订约束控制消息、JSON/流式规划和独立验收；旧结果保留审计与当前权限复核，但不再作为新范围的依据，迟到计划不能继续执行。
- 自动模型策略先排除明确熔断和拒绝准入的端点，再比较成本、容量、负载或质量。端点故障不切换到同端点的另一模型；模型能力不兼容与端点故障分别处理，固定模型继续保持用户选择。

修复范围、升级边界见[v0.7.149发布说明](../releases/v0.7.149-智能路由执行衔接与任务续接可靠性修复.md)，实际验证与剩余验收边界见[智能路由执行衔接修复记录](../reports/chat-routing-fixes-2026-11-10.md)。历史测试的版本身份及未通过记录保留，源码升版不表示生产验收通过。

## 数据建模可视化补充（2026-11-07）

应用中心提供与「数据分析」并列的独立应用「数据建模」，进入后隐藏左侧数据分析菜单栏，释放 100% 全宽沉浸式画布工作区；数据分析内保留「数据建模」入口，双方支持一键互跳并恢复原分析子页签。模型工作区采用一体化全屏 DAG 可视化画布（取消人工四步分段导航与常驻底栏/侧栏），配置工具统一收纳至右侧按需滑出抽屉（点击节点或顶栏「维度与指标」「检查」「试算与分析」弹出，点击空白画布或按 Esc 收起）。画布节点统一为固定尺寸紧凑卡片，不在卡片内堆叠字段，每个节点左右至多保留单一输入/输出端点，宽表字段检索与语义快捷建模收归右侧抽屉。左侧可折叠组件栏提供数据输入、多表关联、数据筛选、函数计算、分组聚合、字段清洗、上下合并、只读自定义 SQL 八类 DuckDB 算子及分类内置函数库；算子流水线随草稿节点配置持久化，不改变发布版语义哈希。底部可折叠实时数据预览面板支持按节点查看上游流转链路、输入输出行数对比、字段类型与抽样数据，并支持将节点输出物化为受治理数据集。画布移动、缩放与自动整理仅改变展示位置；共享接收者/归档状态不能借端点或快捷键写入。手机保留抽屉表单与图内滚动，不撑宽页面。完整交互和验收见 BI 方案第 25 节。

## 数据建模来源与缓存（2026-11-07）

来源业务元数据随不可变版本保存；补录使用当前所有权和来源修订，不更新历史水位。追加按批次与原文件身份幂等，合并版本和原持久任务原子确认。结果缓存只复用固定数据，不缓存永久授权；每次命中及响应交付仍复核当前权限，原计算时间和来源截止时间不可改成当前时间。

## 数据建模节点治理与目录（v0.7.145）

- 节点预览和输出物化复用分析持久任务、统一预算与隔离执行器；关闭执行服务或归档模型后拒绝新运行。任务支持进度查询、取消、幂等重试和重开后的历史查询；API 与 Worker 的能力预检同时包含节点流能力。
- 节点结果和输出提交均复核当前账号、模型、全部来源及所需字段权限；已准备的结果不能绕过撤权。物化数据集、不可变版本、全部来源血缘和任务成功状态在同一事务内确认，取消及失效租约不能提交。
- 输出继承部分或未知来源范围，业务截止时间保留最早来源水位；历史输出的预览固定到对应版本。缺少血缘的旧节点输出保守标为未知范围，需要重新生成，不改写原发布快照。
- 数值筛选的等于与不等于采用互补规则，可明确选择文本编号或数值比较。最大最小值默认按数值统计，文本统计需显式选择；无效数值提示清洗。明确取消全部输出字段时阻止执行。
- 预览结果绑定编辑修订、账号和编辑会话，上游变更使下游字段缓存失效；历史或过期结果明确标注。算子属于数据准备流，物化完成后可基于输出新建正式模型，正式分析继续使用明确的发布版本。
- 模型目录使用服务端搜索、筛选、分页及真实总数；问数目录和分析来源选择同步支持分页，不能以只加载前二百个模型代替完整检索。
