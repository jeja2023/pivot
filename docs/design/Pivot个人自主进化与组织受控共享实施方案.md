# Pivot 个人自主进化与组织受控共享实施方案

> 文档状态：实施方案
>
> 版本：v1.0
>
> 更新日期：2026-09-01
>
> 适用范围：Pivot Agent、Skill、工作流、长期记忆、自动化与组织共享

## 1. 结论与目标

Pivot 应建设为“一套学习引擎、两个生效域”的 Agent：

- **个人域**提供接近 Hermes 的体验：Agent 在完成任务后自动复盘，沉淀安全的记忆和个人 Skill；当再次遇到相似任务时，自动使用已验证的经验。用户不需要学习工作流、版本或审批概念才能获得成长感。
- **组织域**提供企业级受控进化：个人验证有效的 Skill 或工作流，可由用户主动申请共享；系统将其转为组织候选，经过脱敏、安全检查、固定评测、审批、签名、灰度和熔断后才向组织发布。

两者的边界是：**个人自动学习不得扩大权限、产生未审批副作用、跨用户泄露数据或修改安全边界；组织共享不得直接读取个人对话、记忆和文件。**

本方案不建设第二套 Agent Runtime，也不引入一个难以维护的“全自动超级 Agent”。它复用现有的 Agent Run、Trace、记忆、Skill 版本、评测、发布、灰度、熔断、审批和审计能力，将它们连成一个可验证的闭环。

## 2. 成功标准

### 2.1 个人自主进化体验

个人用户完成下列流程时，不需要手工编写 Skill 或工作流：

1. 用户首次完成一个多步骤任务，或纠正 Agent 的错误。
2. Agent 在后台识别出可复用的经验，生成一条记忆或一个个人 Skill 草稿。
3. 对于不新增权限、只使用已授权只读工具的低风险候选，系统自动完成验证并启用个人版本；其他候选留在“待确认的改进”中。
4. 用户下一次处理相似任务时，Agent 自动加载该经验，并在结果中简要说明“已使用个人经验：xxx”。
5. 用户可在一个页面内查看、暂停、编辑、撤销或申请共享，不必进入复杂的底层管理界面。

达到该标准后，Pivot 在“从经验中形成可复用程序性知识并在后续任务复用”这个核心体验上接近 Hermes；但不会复制其默认无边界写入的风险模型。

### 2.2 企业受控进化体验

组织共享只接受已经有来源和证据的能力：

1. 每个候选都能追溯到来源 Run、脱敏的 Trace 摘要、用户反馈和验证结果。
2. Skill、工作流和提示模板都以不可变版本发布；草稿、验证通过版本、已发布版本严格分离。
3. 新增工具、文件目录、网络域名、凭据或副作用必须显示权限差异，并重新审批。
4. 组织发布必须经过固定评测集和安全检查；发布后先灰度，质量恶化时自动暂停或回滚。
5. 组织只共享已发布的版本和聚合效果指标，不共享个人记忆、原始对话、文件内容或密钥。

## 3. 范围与非目标

### 3.1 本期范围

- 个人长期记忆的自动沉淀、检索、解释、暂停、编辑和删除。
- 从成功 Trace、失败恢复路径和用户修正中生成个人 Skill 候选。
- 个人 Skill 的真实草稿、验证、启用、运行时匹配、效果回收和回滚。
- 从用户明确选择的 Run 生成工作流草稿；不自动把复杂任务直接变为生产工作流。
- 从个人已验证能力申请组织共享，并复用现有 Skill/工作流发布治理。
- 统一展示“已学到什么、为何生效、效果如何、如何撤销”。

### 3.2 明确不做

- 不训练或微调基础模型，不把个人数据自动用于模型训练。
- 不允许 Agent 修改 Pivot 自身代码、PEP/PDP、网络基线、租户权限、审计规则或管理员策略。
- 不自动安装第三方包、执行 Skill 包内脚本、扩大本机目录、配置新凭据或放开新网络域名。
- 不将每一次对话都转换为 Skill；只处理重复、可验证、低歧义且有收益的经验。
- 不建设新的多 Agent 编排平台、独立“学习数据库”或并行发布系统。

## 4. 简洁性原则

### 4.1 用户侧只保留三个概念

普通用户只需要理解：

| 用户看到的名称 | 作用 | 用户可做的动作 |
| --- | --- | --- |
| 我的记忆 | Agent 记住的偏好和稳定事实 | 查看、编辑、暂停、删除 |
| 我的经验 | Agent 学到的做事方法（个人 Skill） | 查看效果、暂停、撤销、申请共享 |
| 待确认改进 | 涉及新权限、工作流或不确定性较高的改进 | 查看差异、确认或拒绝 |

“Trace、Manifest、DAG、评测、签名、灰度”等术语只在管理员详情或高级视图中出现。

### 4.2 服务端只新增最少编排能力

- 保留现有 `agent_evolution_proposals` 作为候选、审批和审计载体，不另建第二套提议模型。
- 仅新增一个可靠的 `agent_learning_jobs` 队列表，用于保证任务后反思在服务重启后仍可恢复、可去重、可限流。
- Skill 和工作流必须直接创建现有的真实版本、验证和发布记录；禁止只更新“进化提议”的状态而不产生实际制品。
- 复用现有 Event Outbox、后台调度器、模型并发与 Token 预算，不新增常驻服务进程。

### 4.3 默认克制

- 每个用户默认每 24 小时最多启动 3 次学习分析；同一来源 Run 只分析一次。
- 一次学习任务最多产生 1 条记忆、1 个 Skill 候选或 1 个工作流草稿，不批量制造低质量资产。
- 运行时最多注入 3 个匹配 Skill，并设定独立上下文预算；无明显收益的 Skill 自动降级为待复查。
- 个人自动启用仅限低风险且权限差异为空的版本；其余均进入待确认状态。

## 6. 两个生效域与权限等级

### 6.1 生效域

| 域 | 默认可见范围 | 谁可启用 | 谁可修改 | 典型用途 |
| --- | --- | --- | --- | --- |
| 个人 | 仅创建者 | 系统自动或本人 | 本人 | 个人偏好、稳定处理方法 |
| 组织候选 | 创建者与指定审核者 | 不可运行 | 创建者/审核者按职责 | 等待验证和审核的共享能力 |
| 组织发布 | 明确的用户/单位范围 | 已发布范围内的用户 | 发布者/管理员 | 标准业务处理流程 |

个人域和组织域均使用同一份 Skill/工作流版本格式；差异只在作用域、发布门禁和可见性，不复制资产实现。

### 6.2 变更等级

| 等级 | 可包含内容 | 个人自动启用 | 组织发布要求 |
| --- | --- | ---:| --- |
| L0：记忆 | 偏好、项目事实、成功经验摘要 | 是，受记忆策略控制 | 不共享原文；只能共享脱敏聚合指标 |
| L1：安全过程 Skill | 文本步骤、已授权只读工具、既有文件/网络范围 | 是，通过验证且无权限差异 | 固定评测、人工审批、签名 |
| L2：工作流草稿 | 已有节点、只读工具、可预览的文档/报表处理 | 否，只生成草稿和预览 | 评测门禁、审批、版本发布、灰度 |
| L3：副作用能力 | 写库、发消息、改文件、新域名、新凭据 | 否 | 风险审批、专门评测、管理员发布 |
| 禁止域 | 安全策略、权限、审计、生产代码、自我提权 | 永不允许 | 永不允许 |

## 7. 个人自主进化闭环

### 7.1 触发条件

学习任务由以下事件触发，且必须先经过去重、限流和敏感信息过滤：

1. Agent Run 成功完成，且包含至少两个有效工具步骤或用户明确标记“这个方法可复用”。
2. Agent 经失败、诊断、重试后成功，且恢复路径可概括为稳定规则。
3. 用户给出低评分并提供修正，或直接修改最终答案。
4. 用户在结果详情点击“记住这个方法”或“保存为个人经验”。

以下情况不触发自动学习：任务失败且无成功路径、包含敏感数据、依赖临时文件/一次性凭据、涉及高风险副作用、来源 Run 已被删除、用户关闭自动学习。

### 7.2 学习任务状态机

```text
queued -> analyzing -> candidate_created -> validating ->
  ├-> personal_active
  ├-> waiting_user_review
  ├-> validation_failed
  ├-> rejected
  └-> archived
```

- `queued/analyzing` 仅在后台出现，不占用用户任务队列。
- `candidate_created` 必须有来源 Run、摘要、适用范围、风险级别和预期收益。
- `validating` 必须创建真实资产草稿；不能用仅包含文字的“成功状态”代替验证。
- `personal_active` 只允许 L0/L1 且没有权限差异的候选进入。
- 用户可从任何非终态恢复为“待确认”，但不能绕过验证直接发布。

### 7.3 反思器输出契约

反思器必须返回受限 JSON，而不是直接写文件或调用工具：

```json
{
  "kind": "memory | skill | workflow",
  "title": "不超过 80 字",
  "summary": "不超过 500 字，脱敏",
  "evidence": { "sourceRunId": "...", "stepIds": ["..."] },
  "applicability": { "taskTypes": ["..."], "requiredCapabilities": ["..."] },
  "permissionDiff": { "added": [], "removed": [] },
  "draft": {},
  "confidence": 0.0,
  "expectedBenefit": "quality | time | reliability"
}
```

服务端必须重新计算来源归属、工具能力、权限差异和风险等级；任何来自模型的 `scope`、`published`、`approved`、凭据、网络白名单或安全策略字段一律忽略或拒绝。

### 7.4 个人 Skill 的真实落地

对于 `kind=skill` 的有效候选，按以下顺序处理：

1. 使用既有 `SKILL.md` 解析器生成个人作用域的不可变版本草稿。
2. 使用既有 Manifest 校验、能力白名单、供应链扫描和静态检查；不执行候选内脚本。
3. 对只读能力执行最小回归：至少验证输入契约、输出契约和一条来源任务的无副作用预览。
4. 无权限差异、风险为低、置信度达阈值的候选，发布为个人版本并记录 `personal_active`；否则放入待确认列表。
5. 运行时仅解析个人已发布版本，并在 Run metadata 中记录 `skillId/version/proposalId/matchReason`。

个人自动启用不是“自动执行 Skill 的外部动作”。Skill 只是在下一次任务中作为受现有 PEP/PDP、预算、审批和工具策略约束的程序性上下文；每一次工具调用仍按正常策略处理。

### 7.5 工作流处理

工作流的风险和维护成本高于个人 Skill，因此采用更克制的方式：

- 系统可以自动形成工作流草稿，但不自动发布、不自动安排计划任务。
- 草稿必须来自 Trace 编译器或用户选定的 Run，保留节点、输入输出、审批点和副作用说明。
- 用户只有在点击“试运行”后才开始预览；预览模式禁止外部副作用。
- 通过固定评测并由用户确认后，才走现有工作流发布流程。

## 8. 组织共享与受控进化闭环

### 8.1 申请共享

个人用户在“我的经验”中点击“申请组织共享”后，系统不复制原始数据，而是：

1. 基于个人已验证版本创建组织候选版本。
2. 仅附带脱敏摘要、适用任务类型、成功率、样本量、失败类型和权限差异。
3. 不附带个人聊天原文、记忆原文、附件、文件路径、数据库结果、密钥和用户身份细节。
4. 指定目标范围为个人、单位或组织候选；默认仅审核者可见。

### 8.2 组织发布流水线

```text
个人已验证版本
  -> 申请共享
  -> 组织候选草稿
  -> 安全/权限/供应链检查
  -> 固定评测与无副作用预览
  -> 审批与组织签名
  -> 小范围灰度
  -> 效果监控与熔断
  -> 组织发布 / 暂停 / 回滚
```

组织候选必须调用现有 Skill 和工作流的真实发布服务。`agent_evolution_proposals.status = published` 不能单独代表真实发布；只有关联的 `release_id` 为已发布状态，运行时才可发现该能力。

### 8.3 灰度与熔断

- 首次组织发布默认灰度至明确的测试用户或目标单位，禁止“全组织自动生效”。
- 观察窗口至少记录样本量、成功率、超时率、用户有帮助率、审批拒绝率和回滚次数。
- 样本不足时不作自动扩大范围判断。
- 达到既有熔断阈值时立即暂停或回滚，不等待下一次人工巡检。
- 回滚只能切换到上一已验证版本，不能回到未验证草稿。

## 9. 最小数据与接口设计

### 9.1 数据模型

新增或调整应保持最小化。

#### 新表：`agent_learning_jobs`

| 字段 | 用途 |
| --- | --- |
| `id` | 学习任务 ID |
| `user_id`、`tenant_id` | 权限和隔离范围 |
| `source_run_id` | 唯一来源 Run；与用户组成幂等约束 |
| `trigger_type` | success、recovery、correction、explicit |
| `status`、`attempts`、`next_run_at`、`locked_at` | 可靠队列与恢复 |
| `model_id`、`budget_snapshot` | 模型与预算审计 |
| `result_summary`、`error_code` | 脱敏结果和失败原因 |
| `proposal_id` | 生成的提议引用 |
| `created_at`、`updated_at`、`completed_at` | 审计与可观测性 |

唯一键：`(user_id, source_run_id, trigger_type)`；同一任务只生成一次同类型学习结论。

#### 扩展：`agent_evolution_proposals`

新增以下字段或等价 JSONB 字段：

| 字段 | 用途 |
| --- | --- |
| `source_type`、`evidence_summary` | 标明来源和脱敏证据 |
| `artifact_type`、`artifact_id`、`artifact_version_id` | 指向真实 Skill/工作流/档案版本 |
| `release_id` | 指向真实个人或组织发布记录 |
| `scope` | personal、organization_candidate、organization |
| `activation_mode` | auto、user_confirmed、admin_approved |
| `confidence`、`benefit_metrics` | 形成与复核依据 |
| `review_reason` | 进入待确认而非自动启用的原因 |

不保存原始对话、完整工具输入输出或凭据。大体积证据继续使用现有 Trace/Blob 引用，并在读取时按用户和租户范围校验。

### 9.2 API

用户高频界面只需要少量接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/agents/learning/overview` | 我的记忆、经验、待确认改进和近期效果摘要 |
| PUT | `/api/agents/learning/settings` | 自动学习开关、低风险自动启用开关、通知偏好 |
| POST | `/api/agents/runs/:id/learn` | 用户主动要求从某个 Run 学习 |
| POST | `/api/agents/evolution/proposals/:id/pause` | 暂停个人经验，不删除历史 |
| POST | `/api/agents/evolution/proposals/:id/restore` | 恢复已暂停的个人经验 |
| POST | `/api/agents/evolution/proposals/:id/share-request` | 创建组织候选申请 |

管理员和审核者使用既有 Skill/工作流版本、验证、发布、灰度与回滚接口；不再另建平行的“进化发布 API”。

## 10. 界面与交互

### 10.1 个人侧

在 Agent 工作台的“能力与治理”中，将现有入口整理为三个高频页签：

1. **我的记忆**：沿用现有记忆治理能力，突出“已被使用 / 已暂停 / 来源”。
2. **我的经验**：展示个人已启用 Skill，默认只显示标题、适用范围、最近使用、效果和“暂停/撤销/申请共享”。
3. **待确认改进**：只展示需用户处理的项，明确说明“为什么需要确认”，提供确认、拒绝、查看差异。

学习成功只在任务完成后显示一句简短提示，例如“已记住这次的报告整理方法”；不弹出干扰性对话框。失败或被跳过时默认静默记录，仅在用户打开详情时可见。

### 10.2 组织侧

组织管理员在现有 Skill/工作流发布页中看到“来自个人经验”的候选标签、脱敏证据摘要、权限差异、评测结果、灰度状态和回滚入口。审核动作仍沿用现有发布交互，不新建复杂的审核工作台。

## 11. 实施阶段与交付物

### 阶段 0：范围冻结与基线（1 周）

- 明确 L0-L3 规则、自动启用阈值、每日学习预算和数据脱敏策略。
- 定义“相似任务”的初期规则：任务类型 + 工具集合 + 目标关键词；不先建设复杂向量分类器。
- 为现有 `agent_evolution` 补齐真实产物关联和测试基线。
- 输出：数据迁移、状态机、接口契约、指标字典和风险清单。

验收：不存在仅改变提议状态就被运行时加载的路径。

### 阶段 1：个人学习任务与可观察候选（2 周）

- 建立 `agent_learning_jobs` 队列、去重、限流、预算和恢复。
- 在 Run 成功、失败后恢复成功、用户修正和显式请求时投递学习任务。
- 实现受限 JSON 反思器、来源校验、敏感过滤、候选创建和 Inbox 通知。
- 完成“我的经验 / 待确认改进”最小页面。

验收：任务完成后可稳定生成可追溯候选；服务重启不丢失或重复学习任务；敏感来源不会进入候选摘要。

### 阶段 2：个人 Skill 自动闭环（2～3 周）

- 将 Skill 候选接入真实的版本创建、静态验证、最小评测和个人发布。
- 建立运行时匹配、上下文预算、Run metadata 记录和效果回收。
- 支持个人 Skill 暂停、恢复、回滚和过期复查。

验收：低风险重复任务可在无人操作下完成“学习 → 验证 → 个人启用 → 下次复用”；任何工具调用仍经过原有 PEP/PDP。

### 阶段 3：工作流草稿与组织申请共享（2 周）

- 将 Trace 编译结果绑定为真实工作流草稿；预览运行禁用副作用。
- 增加“申请组织共享”，将个人已验证版本转为组织候选并进行脱敏。
- 建立候选到 `artifact_version_id/release_id` 的强关联。

验收：组织候选不能被普通运行时解析；个人数据无法通过候选详情或 API 读取。

### 阶段 4：受控发布、灰度与运营（2～3 周）

- 复用组织签名、固定评测、灰度、熔断和回滚服务完成共享发布。
- 按版本输出聚合质量指标，接入统一收件箱和管理员质量页。
- 完成安全、故障和数据隔离演练。

验收：组织能力可完整经历“候选 → 验证 → 审批 → 灰度 → 回滚”；任何发布均具备审计证据。

### 总工期与优先级

在现有底座稳定的前提下，建议 7～10 周完成个人闭环和组织共享闭环。优先级为：

1. 真实产物关联与个人 Skill 闭环。
2. 运行时复用与效果回收。
3. 组织申请共享与发布治理。
4. 工作流草稿自动生成和运营体验优化。

若资源有限，先只支持“个人记忆 + 个人 Skill”，不要同时扩展多渠道、多 Agent 和 Skill 市场。

## 12. 测试、审计与验收

### 12.1 必须新增的测试

- 学习队列：幂等、并发、重启恢复、限流、预算耗尽和失败退避。
- 数据隔离：不同用户、不同租户不可读取彼此的学习任务、候选、证据和个人版本。
- 敏感防护：密码、Token、证件、附件正文和工具原始输入不进入候选摘要或组织申请。
- 真实制品：Skill/工作流提议必须有实际版本 ID；无版本或未发布 release 的候选不可被解析。
- 自动启用：仅 L0/L1、无权限差异、验证通过的个人候选可自动启用。
- 策略不变性：候选无法修改 PEP/PDP、网络、租户、审计或管理员配置。
- 运行时：下一次相似任务能选择匹配版本，记录选择理由，并在暂停后不再选择。
- 组织发布：评测失败不可发布；灰度坏版本触发暂停/回滚；接收者只见已发布版本。
- 故障演练：反思模型失败、数据库短暂不可用、发布中断、非幂等工具、Outbox 重投和回滚重试。

### 12.2 核心审计记录

每个学习和发布动作都要记录：操作者或自动来源、用户与租户、来源 Run、模型与预算、候选摘要、权限差异、验证结果、实际版本与 release、灰度范围、回滚目标和时间。

审计只存脱敏摘要与引用；完整 Trace 仍受原始用户/租户权限保护。

### 12.3 量化指标

| 指标 | 个人阶段目标 | 组织阶段目标 |
| --- | ---: | ---: |
| 低风险候选验证通过率 | ≥ 70% | ≥ 80% |
| 已启用个人经验的后续任务成功率改善 | ≥ 10% | ≥ 15% |
| 用户暂停/撤销后的继续误用率 | 0 | 0 |
| 未授权能力扩大或敏感信息泄露 | 0 | 0 |
| 组织候选可追溯到来源与验证的比例 | - | 100% |
| 灰度异常后的暂停/回滚可用率 | - | 100% |

指标必须带样本量和时间窗口；样本不足时不能声称能力“更好”。

## 13. 运维与维护边界

- 学习任务使用独立、低优先级并发与 Token 配额，绝不挤占前台聊天和业务自动化。
- 反思模型优先使用成本更低的已授权模型；模型失败时不影响原任务结果，只记录学习任务失败。
- 候选版本保持不可变，更新通过创建新版本完成；不在运行时原地修改 Skill 内容。
- 定期归档长期未使用的个人经验，但只归档不删除；用户可恢复。
- 学习规则、阈值与权限等级集中配置，禁止散落在 Prompt 或前端判断中。
- 用户关闭自动学习后，停止新建学习任务、停止自动启用与运行时匹配；既有个人经验可保留、暂停或删除。

## 14. 关键决策

1. **个人自动启用仅限低风险 Skill，不包括工作流和副作用。**这是简洁体验与企业安全可以同时成立的前提。
2. **组织共享是“晋升”而不是复制。**组织版本必须有自己的验证、签名、灰度和回滚，不能因个人版本成功就直接共享。
3. **提议必须绑定真实制品。**`agent_evolution_proposals` 只负责决策和审计，Skill/工作流是否可运行由真实版本与 release 决定。
4. **默认最小学习。**宁可少产生、可解释、可撤销，也不要把每段对话都变成难以管理的资产。
5. **安全控制面永远不属于进化范围。**Agent 可以优化业务方法，不能优化或改写自身的安全边界。

## 15. 最终验收场景

1. 用户完成三次同类只读报表整理任务后，系统生成一个个人 Skill；第四次任务自动使用该 Skill，且所有工具调用仍受既有策略控制。
2. 用户修改一次结果中的固定格式问题后，系统将其记录为个人偏好或 Skill 补丁；用户可一键暂停并使后续任务立即停止使用。
3. 带有 API Key、身份证号或本地敏感路径的任务不能生成可共享候选，摘要中也不出现原文。
4. Agent 试图通过候选新增网络域名、文件目录或写入工具时，自动启用失败并进入待确认；无审批不得执行。
5. 用户申请共享一个有效个人 Skill 后，管理员只能看到脱敏证据和验证结果；通过签名、评测和灰度后，目标组织成员才可使用。
6. 灰度版本的超时率或错误率超过阈值后，系统暂停或回滚到上一版本，并在统一收件箱通知责任人。
7. 服务在学习、验证、发布或回滚过程中重启后，任务恢复且不重复创建 Skill、不重复发布、不重复触发外部副作用。
