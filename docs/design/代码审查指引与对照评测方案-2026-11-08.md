# 代码审查指引与对照评测

日期：2026-11-08。版本：v0.7.129。

## 接入决策

选择性适配 Ponytail 5.3.3 的审查方法及复用原则，固定来源提交 `96608e078b2d5ea607c5c3b8b5a54d1c1fba6846`。产品提供中文“代码变更审查”和“代码仓库审计”两份模板，研发规范补充最小完整改动。不安装上游宿主钩子、模式切换、全局状态及统计面板，不向聊天、PPT、BI 系统提示词注入规则。

复用既有技能导入、能力登记、严格验证、个人发布、版本、暂停及运行上下文；不新增存储、权限体系、依赖或数据库迁移。模板位于服务端发行目录，Docker 与桌面已有打包规则可携带；第三方原始许可随 `docs/licenses/PONYTAIL-MIT.txt` 分发。

## 入口与权限

“技能 → 创建 / 导入技能 → 内置指引模板”读取当前账号目录，仅绑定由 `localWorkspaceConnector=true` 标识的本机连接器工具，完整名称须为 `mcp.<id>.workspace.<只读动作>`。动作限于 inspect、read、search、symbols、definition、references、git_status、git_diff；声明的能力只能是 `filesystem.read_workspace`，有副作用的契约拒绝。不能使用裸 `workspace.*`、终端、测试执行、补丁或 Git 写操作。

`GET /api/agents/skills/import/tools` 增加模板目录；`GET /api/agents/skills/import/templates/:id` 返回固定文本及过滤后的当前工具。两者均沿用账号认证。`POST .../import/preview` 支持 `templateId`，服务端重新读取固定文本、过滤当前目录后调用原转换逻辑，不信任客户端替换的模板正文。用户可取消部分工具，预览中核对实际能力与审批要求；缺少必要工具时审查须如实降级说明。

导入仅生成可审阅草稿，发布仍需用户确认并经过原门禁；不在服务启动时自动发布或授予工作区访问。提交前重新读取模板可用工具，身份、工具范围及审批变化使旧方案失效。选择新模板或文件使旧预览失效；生成序号阻止迟到请求覆盖新内容。

## 显式调用与报告

模板来源元数据包含 `metadata.activation: explicit`。规范化来源中的此标记只用于排除关键词自动匹配，不授予工具或运行权限，其他值不能开启额外宿主行为。现有普通技能的匹配行为保持原逻辑，显式选取仍由已发布版本及当前权限决定。

指引要求追踪调用方、权限、数据流和部署负载；发现必须有实际位置、具体触发条件、后果与最小修复。仅输出报告，不执行代码、测试或修改。保留校验、安全、审计、恢复、兼容及可访问性，精简不能以行数优先。没有发现只表示已读范围内未发现可确认问题，不得据此宣称整仓安全或批准发布。

## 对照评测办法

任务清单见 `docs/evaluations/code-review-cases.json`，源自零值图表、技能权限、画布布局隔离、原稿版本冲突四类历史问题。清单为计划，不预置当前缺陷结论或真实模型结果。

每个模型分别选择固定仓库快照及已知缺陷/正确对照，重复至少三次。基线使用当前任务规则，候选仅增加审查指引；冻结相同目标、代码与上下文、工具白名单、权限、预算、模型及采样参数，交替运行两组。通过既有任务入口显式选择技能，停用个人经验自动匹配和模型自动路由，避免额外因素。不要在生产仓库注入故障。

独立验收以预先冻结的可达触发条件、正确对照、误报、遗漏及只读约束为准。模型自己的“完成”或“通过”不构成验收证据，验收应保存可追溯位置并盲审两组输出。所有失败、超时、取消都应保留；不能仅收集成功任务。

导出已有 `GET /api/agents/runs/:id` 详情（run、steps 和 warnings），整理为下列结构；摘要由评测组织者冻结，报告不能独立证明环境相同。输出不复制任务正文、工具结果或密钥，应按项目数据策略保管输入记录。

```json
{
  "schemaVersion": 1,
  "evidenceType": "measured",
  "pairs": [{
    "caseId": "zero-value-chart",
    "repeat": 1,
    "baseline": {
      "contextDigest": "sha256:<冻结代码、上下文、工具和预算的64位摘要>",
      "modelConfigDigest": "sha256:<冻结模型与采样配置的64位摘要>",
      "instructionDigest": "sha256:<基线实际指引的64位摘要>",
      "detail": { "run": {}, "steps": [], "warnings": [] },
      "quality": { "passed": false, "regressions": 0, "evidence": "独立验收记录位置" }
    },
    "candidate": {
      "contextDigest": "sha256:<与基线相同>",
      "modelConfigDigest": "sha256:<与基线相同>",
      "instructionDigest": "sha256:<候选实际指引的不同摘要>",
      "detail": { "run": {}, "steps": [], "warnings": [] },
      "quality": { "passed": false, "regressions": 0, "evidence": "独立验收记录位置" }
    }
  }]
}
```

`run` 须保留 id、goal、model_id/实际 chosen_model_id、status、input_tokens、output_tokens、total_tokens、started_at、completed_at。`steps` 须为完整记录，按 `type=tool` 计调用数；详情读取警告、缺失指标、不同配对条件、相同指引、重复运行或未终态记录都会拒绝。时间差为任务起止间的实际墙钟时间，包含中途等待。

运行 `npm run compare:code-review -- 对照记录.json 新报告.json`；省略输出路径时打印报告，已有报告不会覆盖。按模型输出配对数、用例数、独立验收通过数、回归缺陷、输入/输出/总 Token、工具调用、耗时及差值，零基数比例为 null。`fixture` 只验证统计逻辑，不能获得试点资格；`measured` 且候选全部通过、配对质量未下降才标为 `eligibleForPilot`，仍需结合样本量和覆盖人工决定是否扩大试点。

不估算缺失用量或费用，不使用上游 Claude Code 的百分比推算 Pivot 收益。当前版本交付接入及工程验证；真实模型效果应以实际导出的记录另行形成报告。

可用 `npm run compare:code-review -- docs/evaluations/code-review-comparison.example.json` 检查汇总命令。该示例明确标为人工夹具，生成结果的 `eligibleForPilot` 必须为 false，不能改名作为实测结果使用。
