# 技能多格式兼容与统一运行时

日期：2026-11-07。范围：外部技能指引导入、格式识别、元数据保留、兼容诊断及现有验证/个人发布流程。

本轮实现纳入 [v0.7.126 发布说明](../releases/v0.7.126-PPT原生能力与技能格式兼容升级.md)。完整 PPT Master 引擎属于单独的运行时集成，不等同本方案的指引转换，见[整体引擎集成与复用方案](PPTMaster整体引擎集成与复用方案-2026-11-07.md)。

## 1. 决策

加强通用格式适配层，运行时仍只接受 Pivot 的规范化契约。不能为每个开源项目分别放宽核心字段白名单，也不能把原技能的工具、脚本或宿主配置直接解释为 Pivot 授权。

此前的 `metadata` 报错发生在严格原生解析器。Pivot 已有外部单文件转个人草稿入口，原实现能读取部分外部头部，但丢弃多数元数据，且只给出统一提示。因此本次扩展现有导入流程，不另建技能存储、发布或权限体系。

```text
上传文件
  → 文本与体积检查
  → 按容器解析（Markdown / JSON / YAML）
  → 按格式特征选择适配器
  → 描述字段映射 + 原始字段来源记录 + 兼容性报告
  → 用户选择当前账号可用工具
  → Pivot 统一清单 + 原始工作指引
  → 原有严格校验、能力覆盖检查、版本草稿与个人发布
```

## 2. 当前覆盖

| 来源特征 | 当前处理 |
| --- | --- |
| Pivot 原生 v1 | 识别现有清单；作为新的个人指引转换时仍重新绑定工具和身份 |
| Agent Skills 标准及元数据扩展 | 识别 name、description、license、compatibility、metadata、allowed-tools；保留扩展值 |
| Claude Code 风格扩展 | 识别 context、agent、hooks、model、shell、调用控制等字段；报告宿主行为尚未适配 |
| 通用 YAML 头部 + Markdown | 保留描述及未知字段，正文作为指引，不猜测额外字段的执行含义 |
| 纯 Markdown / 文本指引 | 沿用现有人工选择工具的方式，不伪造外部清单 |
| JSON / YAML 清单 | 接受顶层描述加 instructions / instructions_md / body，或 manifest + 正文封装；有冲突正文时拒绝 |

容器由明确文件类型决定；未提供类型时，可识别 JSON 对象。明确的 Markdown 文件不会仅因正文以 `{` 开始就被误作 JSON。YAML 文档起始符 `---` 与 Markdown 头部按文件类型区分。

尚未支持的 Pivot 清单版本、文件类型和外层封装返回明确错误，不按最接近的格式静默执行。完整 ZIP/Git 技能包、插件清单、资源安装和运行环境建设不在本次单文件转换范围内；原有独立包校验/签名/供应链路径继续适用。

## 3. 字段处理原则

1. 名称、说明和许可证用于填写新草稿；原版本与作者等来源信息保留，新的个人技能使用自身的标识和版本。
2. `metadata` 和未知描述字段保留到经过限制的 `importSource.originalFields`，不直接变成运行配置。原始值不静默截断；超出保存上限时要求精简。
   v0.7.129 增加唯一的收紧行为：来源 `metadata.activation: explicit` 排除个人经验关键词自动匹配，仅允许显式选择；它不授予权限，不启用原宿主功能，其他值不产生额外执行语义。详见[代码审查指引方案](代码审查指引与对照评测方案-2026-11-08.md)。
3. tools、allowed-tools、capabilities、permissions、scope、ownerKey、签名和摘要等原始声明只作为来源资料。有效工具来自当前账号目录中的本次选择，有效能力从登记表解析，并沿用现有严格验证。
4. hooks、fork/context、宿主变量与动态命令不自动生效。预览逐项列出未适配项；运行时给转换后的指引增加固定兼容说明，不假定原技能已完整安装。
5. 检出 scripts、references、assets、templates、workflows 的本地引用时报告“配套文件未导入”；compatibility、dependencies 报告环境未验证，不自动安装依赖或联网取文件。
6. 格式兼容与运行就绪分开：`compatible` 仅表示指引格式可以转换，`adaptation_required` 表示存在待处理要求；两者均不作为完整业务流程已经验证的证明。

## 4. 来源、版本与往返

`importSource` 是新增的、有明确结构和大小限制的原生来源字段：保存来源格式、容器、适配器版本、原始文件名、文本摘要和原始字段。原始摘要针对去除 UTF-8 BOM 后的输入文本计算，不作为发布者认证或可信签名。

导入、版本持久化和导出使用相同清单字段，来源信息参与现有内容摘要与发布校验；重新转换已含来源记录的规范化技能时保留原始来源，避免无限嵌套。原生解析器对其他未知顶层字段继续拒绝，并提示使用兼容预览。

描述信息的保留不改变签名信封的信任链，不使用原始 metadata 中的授权或“已验证”声明。技能发现会明确标记转换指引的范围和运行未验证状态，不返回原始来源中的完整数据。

## 5. 安全与失败边界

- 外部文件合计不超过约 272KB，头部不超过 16KB，正文不超过 256KB。原始字段来源记录不超过 8KB，完整来源记录不超过 12KB，并限制节点数及嵌套深度。
- YAML 使用实际语法事件检查锚点、别名、合并键及标签；普通引用文本中的 `&`、`*`、`!!` 不再误判。JSON/YAML 重复字段仍拒绝，原型相关键、二进制和解码异常拒绝。
- JSON、YAML 的正文必须是明确的字符串；多个正文别名内容不一致时拒绝，不选择其中一份后继续。
- 导入仅处理文本数据，不执行自定义适配器、脚本、安装命令或钩子，也不读取前端提供的宿主路径。
- 草稿验证与发布继续使用当前权限、能力、签名和供应链机制；兼容识别不替代任何发布门禁。
- 文件或工具变化使预览失效，迟到的文件识别响应不得覆盖新文件、用户输入或已准备的预览。

## 6. 扩展方式

后续遇到新格式，应在适配器注册表增加独立识别条件及映射规则，补充真实样本和回归测试。每次明确：哪些字段可映射、哪些仅保留来源、哪些执行语义需要另行实现。运行时契约、授权判断和既有包校验保持统一。

涉及新的执行语义时，必须增加对应能力实现和运行验证；不能仅增加字段名，就把兼容状态升级为“完整可运行”。

## 7. 依据与验证入口

- [Agent Skills 官方格式规范](https://agentskills.io/specification)：标准含 metadata、compatibility 和试验性的 allowed-tools。
- [Claude Code 官方技能文档](https://code.claude.com/docs/en/skills)：标准与宿主扩展字段具有不同适用范围。
- 实现：`agent-skill-format-adapters.js`、`agent-skill-import-provenance.js`，复用 `agent-skill-import-assistant.js` 和原生 authoring/release 路径。
- 自动化：`agent-skill-format-adapters.test.js`、原有技能导入/治理/包/发现测试，以及 `tests/e2e/skill-import.spec.js`。
- PPT Master 实际样本已验证：原生格式预览可通过，元数据保留，配套文件与宿主占位符明确列为未适配；不以该结果宣称其完整 Python 工具链已经可运行。
