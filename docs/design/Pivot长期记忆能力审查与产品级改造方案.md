## 3. 代码审查发现

### P0：正确性和隐私

**M1. 聊天转 Agent 记忆丢失。**`buildLongTermMemoryContextMessage()` 返回 `{role, content, metadata}`，`prepareChatAgentContext()` 将对象赋给 `memoryContext`，桥接 `clampText()` 的 `String(value)` 将其变为 `[object Object]`。Planner/streaming runtime 无法获得记忆正文；渠道入口复用桥接路径。证据：`server/services/chat-agent-bridge.js`、`server/services/agent-runtime/planner.js`、`server/services/agent-streaming-runtime.js`。现有测试仅传字符串；审查时已用现有函数复现对象串化。

**M2. 关闭/遗忘不闭合。**开关控制入队、抽取入口和召回，但 `upsertMemory()` 自身没有统一检查开关。个人数据删除仅软删记忆，未取消待处理抽取；删除会话只软删会话和消息，没有处置其派生记忆。抽取期间撤回还存在写入竞争。证据：`server/services/long-term-memory/index.js`、`server/services/agent-data.js`、`server/routes/sessions.js`。需要分别定义暂停、单条忘记、来源删除与个人数据删除的重建/保留语义，不能把软删表述为彻底擦除。

**M3. 策略服务失效开放。**`resolveMemoryGovernance()` 在读取/评估策略异常时继续返回 `allowed: true`。要求确认或禁止自动捕获的用户可能被旁路。证据：`server/services/memory-governance.js`。自动写入失败时应拒绝并记录可重试原因。

**M4. 持久化 Prompt 注入面。**敏感识别主要靠凭据/号码模式，而自由文本记忆被组装为 `system` 消息；候选还可能来自助手回复。证据：`server/services/long-term-memory/memory-utils.js`、`memory-extraction.js`、`memory-retrieval.js`。这属于需加固的攻击面，不代表已证实线上攻击。

### P1：质量与规模

**M5. 召回候选截断、无关注入。**按重要度和置信度先查 200 条，再算问题相关性；后续记录无法命中。过滤条件允许相关性零但重要度高的条目注入。检索返回即更新 `last_used_at`，未区分真正注入、预算裁剪与回答采纳。证据：`server/services/long-term-memory/index.js`。

**M6. 冲突及索引漂移。**相似合并仅扫描最近 200 条同类型记忆，包含关系可能误合并；合并选更长文本而非最新真实版本，内容改变后可能保留旧 embedding。证据：`server/services/long-term-memory/index.js`。

**M7. 抽取误记。**模型合法返回空候选也会规则兜底；规则扫描用户和助手，可能把一次性讨论或助手推断变成用户事实。候选常共享本轮全部消息 ID，不足以逐条解释来源。证据：`server/services/long-term-memory/memory-extraction.js`。

**M8. 作用域和配置口径。**可写 `project/session/global`，检索却只按用户筛选；个人档案与单独策略都有 `memoryPolicy`，可能出现两个配置视图。质量摘要未收到开关回调时默认 `enabled: true`。证据：`server/services/long-term-memory/index.js`、`agent-profile.js`、`memory-governance.js`、`long-term-memory/memory-quality.js`。

### P2：产品完善

“为何使用”当前给出通用排序说明，而非某次回答的实际命中证据；默认导出最多 500 条，不能保证全量；过期归档主要通过维护入口操作。自动记忆审批和可见通知也需要完整用户旅程。这些不应阻塞 P0 修复。

## 4. 目标架构和数据契约

```text
对话/Agent/渠道/显式操作
  -> 统一候选提取与来源验证
  -> 策略决策（开关、类别、来源可信度、敏感度、审批）
  -> 待确认/拒绝/版本化写入
  -> 按用户和项目/会话范围生成候选
  -> 相关性重排、冲突过滤、上下文预算
  -> 带来源和使用事件的回答上下文
  -> 用户纠正/遗忘/来源撤销 -> 索引和后台任务联动
```

1. **单一策略权威。**以服务端长期记忆开关和 `agent_memory_policy` 为写入/召回权威；个人档案的 `memoryPolicy` 只读映射或迁移下线，不独立生效。自动捕获与用户显式“记住”分别决策并清楚说明。
2. **分层而非平行建库。**继续使用 `memories`；新增必要的项目/会话标识、声明者、来源证据、有效时间、事实键、版本关系和审核状态。档案放明确的用户偏好，会话搜索找原始对话，Skill/工作流不充当事实记忆。
3. **来源可信度。**用户直接声明、已确认纠正、助手推断和外部工具/文档分别标记。只有满足证据和策略的稳定事实才能自动入库。共享资料仍需实时 ACL，不复制成脱离原权限的私人事实。
4. **冲突而非拼接。**同一主体和属性的新值通过版本替代或待确认；旧值留作受控审计但不再召回。语义近似只能产生候选，不能自动合并相反命题。
5. **低信任注入。**记忆正文是资料而不是新的系统指令；可信系统提示只规定如何使用证据，正文要有边界、来源和有效期。不得依赖单一正则承诺免受注入。
6. **可解释使用事件。**区分候选、通过门槛、实际注入、被裁剪及回答采纳；UI 的“为何使用”关联具体 Run/消息。常规日志和指标不写记忆正文。

## 5. 分期实施及验收

### 阶段 A：P0 正确性与隐私闭环（粗估 1～2 周）

- [x] 建立唯一 `MemoryContext` 契约；聊天、Planner、streaming、渠道统一读取正文，禁止对象串化；已补真实契约回归。
- [x] 将开关和策略检查收敛至所有写入入口；策略读取失败时自动写入拒绝，区分显式确认和自动捕获。
- [x] 增加用户级记忆修订号及行锁：入队、提取和提交写入前核验；关闭或个人数据擦除会取消排队任务并阻止在途任务写回。
- [x] 落地来源删除语义：只由被删来源支撑的自动记忆撤回；多来源记录保留剩余证据；显式记忆可在来源删除后保留。
- [x] 对单条“忘记”建立不含正文的抑制指纹及来源抑制，阻止同来源的改写候选重建；显式再次记住可解除抑制。
- [x] 增加指令注入扫描、来源分级和低信任资料上下文；自由文本不再作为系统规则注入。
- [x] 实施最低相关性门槛，取消“高重要度即注入”；质量摘要读取实际启用状态。

**发布门槛：**四种入口能看到真实记忆正文且无 `[object Object]`；关闭、删除、来源撤销与并发抽取后，新请求误注入/重建为 0；策略服务故障时自动写入为 0；跨用户越界为 0。已发送给外部模型的在途请求无法即时抹除，承诺范围应明确为后续新请求和本地存储。

### 阶段 B：评测与生命周期（粗估 3～5 周，可与 A 后半并行）

- [x] 建立 100 条脱敏多轮样例，覆盖稳定偏好、项目事实、短期任务、纠正、矛盾、无候选、敏感信息、来源撤销、注入和作用域；试点匿名反馈仍待目标环境采集。
- [x] 模型合法返回空集合时不回退规则；仅在超时、服务不可用或格式错误时受限兜底。候选逐条绑定真实消息 ID、声明者和证据片段。
- [x] 通过增量 PostgreSQL migration 补作用域、事实版本、有效期、搜索投影和索引元数据；旧记录默认用户范围并异步补向量。
- [x] 写入使用事务、幂等和修订锁；纠正采用新版本激活、旧版本停用。编辑/合并重算向量或降级词法检索。
- [x] 后台自动归档过期和低价值历史片段；来源撤销、有效期和作用域在排序前过滤。

**发布门槛：**冲突旧版不再注入；来源逐条可追溯；模型“无候选”不制造记忆；索引失败仍可安全降级；存量数据抽样与迁移回滚演练通过。

### 阶段 C：召回、解释与体验（粗估 3～4 周）

- [x] 在用户及有效作用域内独立生成词法和 pgvector 语义候选，RRF 融合重排并严格门槛，替代“重要度前 200 条”预截断；中文候选保留确定性词法降级。
- [x] 区分用户、项目、会话和全局范围；历史片段默认限制在来源会话。按模型预算记录实际注入与裁剪，不把未注入条目计为使用。
- [x] 聊天、Agent 运行详情和记忆中心展示实际使用理由、来源和时间，支持暂停、忘记、更正和待确认自动候选。
- [x] 导出支持循环分页、总数、完整性及导出条数；个人数据擦除与普通逻辑遗忘分别处理。
- [x] 增加影子排序开关和新旧候选使用事件，影子模式不改变回答；紧急关闭仍由长期记忆总开关控制。

**发布门槛：**真实试点与分层离线样例上，召回率和用户评价改善且安全指标无回退；报告 token、延迟和抽取成本，不能只以命中数量判断收益。

## 6. 指标、测试矩阵和发布门禁

先建立旧版基线，再冻结目标。以下为首轮建议值，报告必须注明样本量、模型、数据集版本、时间窗和置信区间；小样本不得宣称达标。

| 指标 | 口径 | 建议门槛 |
|---|---|---|
| Recall@8 | 应召回稳定事实进入最终注入集合 | 相对旧版提升，目标 >= 85% |
| 错误/无关注入率 | 注入中无关、过期、冲突事实占比 | <= 5%；高风险场景 0 |
| 自动抽取准确率 | 持久化候选经人工标注稳定且正确的比例 | >= 95% |
| 纠正生效率 | 下一次新请求不再使用旧值 | 100% |
| 禁用/删除后误用 | 后续新请求仍注入或重建已撤回记忆 | 0 |
| 越界/注入成功 | 跨用户/项目命中或记忆正文改变系统行为 | 0 |
| 成本/延迟 | 每千轮抽取与查询成本、召回 p50/p95、新增输入 token | 设预算并与旧版对比 |

回归矩阵至少覆盖：普通聊天、聊天转 Agent、直接 Agent、渠道；无 embedding、慢 embedding、模型空输出；并发关闭与队列重试；删除消息、会话、个人数据；同用户多项目、不同用户/租户；历史升级和回滚；用户文本、助手文本、工具结果中的注入样例。用 `tests/chat-agent-bridge.test.js`、`tests/security-rag/memories.js` 扩充契约测试，另建 PostgreSQL 集成与离线回放评测。持续运行仓库现有静态门禁、全量 Node 回归和真实模型试点。

## 7. 迁移、回滚与风险

1. **兼容迁移。**先加列/表/索引与兼容读取，再回填、影子评测和切流。生产大表索引采用非阻塞策略；遵守仓库 PostgreSQL migration 规范，不改已有 migration 的历史语义。
2. **独立开关。**抽取、自动写入、新候选召回、新排序及 UI 可分别关闭；紧急回滚先关新注入/写入，不执行破坏性数据库降级。保留旧格式读取直到验证结束。
3. **观测与隐私。**低基数日志只记动作、结果、策略版本、延迟和错误码；正文及凭据不进入指标标签。评测数据脱敏、按授权范围采集。
4. **事故恢复。**对误记、越权、重建提供用户级撤回、队列暂停、索引清理和影响范围查询；明确逻辑删除、硬删除、备份到期及法定留存边界。
5. **非目标。**本期不引入强制公网依赖、不替换知识库或会话搜索、不允许 Agent 自行修改权限策略；不能承诺撤回已发送到第三方模型的内容。

## 8. 待确认决策与首批任务

已按保守默认值实现：自动捕获默认不逐条审批但可在个人 Agent 工作台开启确认；删除来源时撤回无剩余证据的自动记忆；普通“忘记”保留不含正文的抑制信息，个人数据擦除删除正文、证据、使用事件、评测和队列记录。备份保留期及真实生产擦除证明仍需由部署方按组织政策确认。

下一步不是继续扩展功能，而是执行真实模型/试点评测：导入脱敏基准、运行影子排序、采集第 6 节所列 Recall@8、误注入、纠正生效、延迟和成本；达到门槛后再启用目标租户灰度。详细操作见对应版本发布记录。
