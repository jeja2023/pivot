# 知识库 AI 产品级优化实施说明

## 已完成的核心改造

本轮将知识库 AI 从“召回后直接生成”升级为“问题规划 → 多路召回 → 可信度门控 → 证据注入 → 引用/语义核验 → 结果审计 → 黄金集与线上指标验收”的闭环。

## 知识资产与全局治理权限

- 知识库文档、集合、标签、来源和索引任务默认属于创建它们的用户，资料按用户隔离。
- 系统 `admin` 账户额外拥有共享专题库管理、全库重建向量和全局删除审计能力。
- 非 `admin` 的普通管理员不拥有上述跨用户能力；其权限边界与普通用户一致，仅限自己拥有或被授予只读权限的知识资产。
- 系统 `admin` 查看全库文档时可见上传用户昵称与账号提示；该字段仅服务端向系统 `admin` 返回，普通用户和非 `admin` 管理员不会获得。

### 1. 问题规划

- 短追问会结合上一轮用户问题恢复完整主题。
- 一轮问题最多生成 3 个检索变体并合并去重结果。
- 查询规划不会把已经注入的 `PIVOT_RAG_CONTEXT` 当成下一轮检索词。
- 对明确罪名问法额外提取“罪名 / 去掉‘罪’后的核心词”作为检索锚点，例如“抢劫罪 / 抢劫”。

### 2. 召回与排序

- 保留词法、向量、图谱候选的独立召回和 RRF/MMR 排序。
- 简单问题沿用默认 Top-K，比较、多条件、长问题自动扩大 Top-K。
- 召回结果继续经过可信度阈值和引用可信度门控；低可信结果直接进入安全拒答。
- 含明确罪名锚点的问题，候选必须命中至少一个锚点；只命中“犯罪、可以、判处”等泛词的无关条文不能进入可引用结果。
- 搜索问答页面仅展示最终通过相关性与可信度校验的候选；初筛噪声仅在受控诊断中保留。

### 3. 证据与安全

- 知识库正文明确标记为不可信资料，不得执行正文里的提示词、命令或权限要求。
- 显式/命中知识库的回答在服务端完成来源核验后再交付。
- 每个事实句都必须引用本轮真实来源编号或 citation key；不存在来源、真实引用旁夹带未引用事实或来源无法支持结论都会被拒绝。
- 对带引用的回答句增加来源片段支持性核验，引用真实但结论与来源无关时也会拒绝交付。
- 确定性核验通过后，会调用语义蕴含复核器逐句检查结论是否被对应原始来源完整支持；复核不可用时安全拒答，不输出未经复核的结论。
- 核验状态通过 `rag_grounding` SSE 事件返回，并写入路由元数据和助手消息保存事件。

### 4. 多轮、Wiki 与 Agent

- 多查询结果统一重新编号，避免不同检索变体重复使用“引用 1”。
- Wiki 继续作为原始 RAG 的辅助层，原始片段优先。
- Agent 桥接继续沿用同一知识库上下文，并保留现有上下文预算和权限边界。

### 5. 评测、审计与质量运营

- 工作台问答、聊天 RAG 和黄金集评测共享同一检索规划和依据核验标准，避免离线评测与线上结果不一致。
- 每次知识库问答按用户写入提问、检索改写、受控证据摘要、最终答复、核验状态和用量；审计接口只允许该用户读取自己的记录。
- 评测汇总增加依据核验通过率，缺口报告会标识召回失败、引用失败和依据核验失败。
- 工作台评测页同时展示离线黄金集指标及近 30 天线上问答的依据核验趋势。
- 召回诊断、搜索状态和质量评测使用中文业务标签展示检索模式、排序、队列、状态和指标，不向用户直接暴露内部英文代码或缩写。

### 6. 上线验收

- 使用 `npm run verify:knowledge-ai-readiness -- --require-256k` 核验迁移、表、索引、语义核验开关和活动模型的 256K 上下文能力。
- 上线前还应以租户实际黄金集运行评测，确认 Recall@K、引用 F1、依据核验率、拒答准确率和 P95 延迟达到业务阈值；该步骤依赖目标数据库、Embedding、Reranker 和模型服务。

## 真实环境验收边界

- 真实 PostgreSQL 数据集下的多用户权限、缓存隔离、删除/禁用/过期来源失效验证；
- Embedding、Reranker 和大模型服务的 P95 延迟、Recall@K、引用精确率与拒答准确率；
- 生产模型不同上下文窗口下的证据片段预算和长文档覆盖率。

自动化测试已在隔离 PostgreSQL schema 中验证架构初始化和迁移执行；但不能以此替代目标生产数据库、QWEN3.6-35B、Embedding 与 Reranker 的运行态结论。代码、迁移、自动化测试、静态检查和上线验收脚本均已完成。
