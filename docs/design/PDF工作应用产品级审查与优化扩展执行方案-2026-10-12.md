# PDF工作应用产品级审查与优化扩展执行方案

审查日期：2026-10-12。适用产品：Pivot 内网 PDF 工具应用与共享文档处理底座。交付对象：产品负责人、研发负责人、交互设计、测试与运维。方案版本：1.0。

> 实施状态（2026-10-13，v0.2.21）：S0-S3 中可由 Pivot 仓库交付的可信处理、页面工作区、批量与分发已落地；qpdf 授权解密/保护/优化、veraPDF 验证、页面编排、栅格化永久脱敏、PDF 比较、轻批注、AcroForm 填写和可复核 Word/Excel 导出均已接入并有正式回归。质量基准集已扩展为 60 份可重复生成的非敏感夹具。证书私钥、时间戳/撤销服务、PDF/A **转换**引擎、复杂正文编辑、真实用户研究、生产压测、灰度与回滚演练属于外部环境验收，不会因代码存在而被虚报为完成；产品界面会明确能力边界与引擎不可用原因。

## 1 核心结论与执行决策

建议把当前 PDF 工具升级为“可验证结果的内网文档处理工作应用”。当前代码已具备合并、拆分、旋转、删页、重排、提取文本、PDF 转图片、图片转 PDF、可搜索 PDF 共 9 类操作，具有持久化任务、用户隔离、受控路径、输出归档、取消、重试、租约恢复和过期输出清理，具备继续产品化的基础。

当前首要问题是处理结果与用户意图不一致。审查已用实际函数和 Chromium 复现 13 项问题：包括页码越界被解释为最后一页、重排隐式丢页或复制、渲染默认只处理前 3 页、页面范围未生效、多文件操作只处理首文件、中文可搜索 PDF 失败、物理纸张尺寸改变、原图缺失仍生成结果、密码进入公开任务配置。现有 11 项文档处理回归测试全部通过，但未覆盖这些边界。

执行顺序为 S0 可信结果与凭证修复、S1 可视化操作与复核、S2 高频工具与批量闭环、S3 业务协同与自动化。高级内容编辑、真正脱敏、证书签署和 PDF/A 转换采用独立验证与发布门槛，不提前承诺与成熟商业编辑器相同的能力。

建议先启动 S0 与 S1，共 6 周；S2、S3 在各阶段验收后进入，主干方案总计 14 周。估算基于 1 名前端、1 名后端及测试、设计、运维的部分投入，属于规划估算，排期前按现有任务负荷校准。第 2 周交付可靠性修复，第 6 周交付可视化基本工作区，第 10 周形成高频批量办公闭环，第 14 周接入 Pivot 的业务分发和自动化。

### 1.1 必须接受的产品原则

- 原件保持不变，每次处理产生独立输出与可追溯版本。结果的输入文件数、页数、成功数和失败数必须可核对。
- 超出限制、密码不受支持、缺页、缺图、字体缺失、低置信度以及转换降级必须明确反馈，不能静默返回“全部完成”。
- 页面操作以可视化预览为主，页码表达式作为快捷输入；预览状态与服务端执行计划使用同一个契约。
- 主页面沿用项目的创建区、筛选区和任务表格；页面编辑、结果预览和复核进入统一弹窗或独立详情页。
- OCR 继续使用共享底座和外置 HTTP 服务；模型、权限、任务、日志、工作流、样式均复用 Pivot 已有体系。

### 3.3 面向的用户与目标任务

普通办公人员需要把若干材料整理成可提交的 PDF；档案人员需要扫描件可搜索且页数完整；业务审核人员需要比对两个版本并保留处理依据；管理员需要确认文档在哪处理、保留多久、哪些引擎可用，以及失败是否会影响全站服务。

推荐产品定位是“内网文件整理、扫描数字化和业务交付工作区”。核心价值是中文办公、结果完整、处理过程可追溯、能继续进入知识库、公文或自动化。暂不以完整专业排版编辑器作为首期定位。

## 5 已复现问题与修复规格

优先级定义：P0 表示凭证处理或高影响静默结果错误，必须阻断新的生产发布；P1 表示核心正确性、稳定性或能力不成立，S0 修复；P2 表示明显体验或扩展缺口。P0 分类是本方案的工程排期判断，不等同于已经确认跨用户安全事件。

### F01 P0 密码明文进入任务记录并由任务接口回传

证据 A09：normalizeConfig 保留 password，serializeJob 原样返回 config。createJobRecord 将 normalizeConfig 写入 config_json，因此密码同时进入持久化配置。探针只使用合成密码，没有读取用户真实密码。位置：settings.js:96、119；jobs.js:267。

修复：从公开配置中删除 password；序列化采用白名单。需要重启恢复的凭证存入现有加密机制支持的独立短期 secretRef，解密仅在 worker 内发生。新任务按文件管理密码，结束或超过有效期后删除。历史记录迁移时取出旧明文、加密或要求重新输入，再移除旧字段。日志、错误、审计、JSON 导出和缓存均不含密码。

验收：创建、列表、详情、导出和日志扫描全部无密码；密文不能被其它用户解密；任务结束即失效，过期重试进入“需要密码”；旧记录迁移可重复执行。

### F02 P0 渲染默认仅返回前 3 页且输出完整性不可见

证据 A03：6 页文件请求 maxPages=100，实际返回 1、2、3 页。document-text.js:361 使用 `Math.min(options.maxPages || 3, 3)`。preparePagesForJob 把已渲染数量写为文件 pageCount；OCR truncated 仅比较已渲染页面与 OCR 限额，无法识别渲染前漏掉的原始页数。

修复：预检先取得真实 totalPages，选择页集合后分批渲染；预览页数与实际处理页数使用不同参数。记录 totalPages、requestedPages、renderedPages、processedPages、skippedPages 和 missingPages。服务端限额超过时在创建前拒绝或要求明确选择部分处理；禁止静默缩短任务。succeeded 仅用于 requestedPages 与实际产出一致且质量校验通过的任务。

验收：6、10、100 页夹具能完整处理；请求第 8 页可准确产出第 8 页；超过部署上限返回可解释错误；20 页输入只完成 3 页不能显示全部成功。共享聊天附件与 OCR 渲染调用必须同步回归。

### F03 P1 PDF 转图片不应用页面范围

证据 A04：6 页文件填写 5-6，输出仍为第 1 至 3 页。pdf/index.js:309 未使用 pages；renderers.js 支持 first/last，但调用处未传。

修复：选页统一编译为服务端 pageMap，非连续页面按集合渲染；输出文件名和 manifest 保留原页码。分辨率按真实 PDF 点尺寸计算 `pixels = points × dpi / 72`，替代 `dpi × 6.4` 固定宽度。

验收：1,3,6 只导出 3 张且对应内容与名称正确；A4、A3 和横向混合尺寸在指定 DPI 下的像素尺寸误差不超过 1%；PNG/JPEG 输出各有明确质量设置。

### F04 P0 页码越界被解释为有效页面

证据 A01：6 页输入 99，实际选中最后一页；原因是范围上限截断后又反向遍历。无效片段被忽略，混合有效和无效输入可能造成用户误判。

修复：严格解析每个 token，页码必须为 1 至 totalPages 的整数；反向区间、非法字符和越界返回字段错误，不部分接受。明确支持中文逗号等分隔符；长范围只计算长度并限制展开，避免不受控循环。空值仅在操作允许“全部”时使用默认值。

验收：0、99、9-2、abc、1-x、超大数字、1,abc 均被拒绝；1-3,5 得到准确集合；输入错误在前端即时显示并由后端再次校验。

### F05 P0 重排允许隐式丢页和重复页面

证据 A02：6 页输入 3,1 被接受并只生成 2 页；2junk,2,1 被解析为 2,2,1。pdf/index.js:108 使用 parseInt 并未检查完整排列。

修复：“重排”要求原页面的完整无重复排列；“提取页面”和“复制页面”作为独立操作使用明确语义。页面编辑器可同时记录排序、删除和复制，但必须展示变更摘要。执行前校验输出页数与 pageMap。

验收：3,1,2 在 3 页文件中成立；少页、重复、垃圾后缀均报错；提取与复制显示输入输出页数，不借重排隐式实现。

### F06 P0 多文件输入只处理首文件

证据 A05：rotate 接收两份文件，只生成第一份输出。processPdfToolJob 对通用操作使用 files[0]；同样影响拆分、删页、重排、文本抽取、PDF 转图片。searchable_pdf 分支也只选择一个目标文件。结果 fallback `processedFiles || files.length` 可能把未处理的文件计入完成量。

修复：S0 中合并与图片转 PDF 使用多文件，其余操作暂限单文件且服务端拒绝多文件；S2 增加显式 batch 模式，为每份输入产生子项记录。文件清单展示顺序、大小、类型和错误；任何过滤或跳过都进入清单，不静默略过。

验收：单文件模式上传 2 份直接拒绝，避免产生看似完整的任务；batch 模式 N 份输入有 N 条结果，成功与失败总和为 N；界面显示成功数而非上传数。

### F07 P1 合并未执行页数总量限制

证据 A06：两份各 6 页输入，maxToolPages=1 仍成功合并 12 页。pdf/index.js:177 没有 clampToolPageCount。

修复：预检累计输入总字节、总页数、预计像素和输出量；所有操作执行统一预算约束，限制取部署策略与用户请求的较小值。超过上限拒绝并指出文件或页数，不在高成本复制完成后才检查。

验收：限额恰好允许时通过，超过 1 页时拒绝；文件数、累计大小与高分辨率图像解码也有对应上限。

### F08 P1 中文可搜索 PDF 使用 Helvetica 导致导出失败

证据 A08：调用真实导出函数，输入“中文识别结果”返回 `WinAnsi cannot encode "中"`。pdf/index.js:420 使用 StandardFonts.Helvetica；项目已有共享 CJK 模块。

修复：复用 CJK 字体自检、fontkit 和字体资产，采用字体子集嵌入；根据 glyph 覆盖率报缺字，不静默删除。透明文本使用 PDF 的不可见文本绘制模式，避免以 0.01 透明度产生残留视觉字符。复核文本变化后重新生成文本层。

验收：中文、英文混排及常见标点可以搜索复制；提取回读与校对文本一致；字体缺失时能力显式不可用；跨 Chrome、Edge 和 Acrobat/Reader 样本验证。

### F09 P1 可搜索 PDF 改变物理页面尺寸

证据 A12：原件页面 320×240 pt，渲染成 160×120 px，导出变成 160×120 pt。页面表的 width/height 来源于图像元数据，createSearchablePdfOutput 将其直接作为 PDF 点单位。

修复：分别保存 pdfWidthPt、pdfHeightPt、pixelWidth、pixelHeight、rotation、cropBox 和 transform。OCR 坐标先从像素变换为 PDF 坐标，再处理旋转与裁切。对于源 PDF 优先保留原页面外观并叠加文本层；纯图片则由明确 DPI 或纸张策略生成物理尺寸。

验收：原 PDF MediaBox/CropBox 尺寸误差不超过 0.1 pt；90/180/270 度和裁切页面中文本定位误差不超过 2 pt；打印纸张尺寸与原件一致。

### F10 P0 原图缺失仍生成可搜索 PDF

证据 A13：传入不存在的源图路径，函数仍生成一页仅有近透明文本的文件。图像读取以条件判断跳过，没有失败处理。

修复：原始视觉数据为必需输入，缺失立即失败；输出生成后检验页数、页面背景、文本层覆盖和可读性。仅明确的“文本重排导出”才允许无原图模式，并使用不同格式名称。

验收：损坏或缺失原图返回 SOURCE_VISUAL_MISSING，不注册 ready 输出；取消和恢复中源图丢失同样不能发布结果。

### F11 P1 非法操作静默回退为提取文本

证据 A07：unknown-operation 被 normalizePdfOperation 转成 extract_text。修复为显式枚举验证；兼容旧别名可以保留，但未知值返回 400。验收：所有未知枚举不创建任务、不登记输出，旧有效别名继续工作。

### F12 P1 排队状态命名错误影响显示筛选取消与轮询

证据 A11：后端返回 queued，前端按 pending 展示、筛选、取消与轮询。Chromium 中显示 queued，没有取消按钮，等待一个轮询周期仍未再次请求。位置：前端第 75、167、231、588 行；后端 constants.js:2。

修复：共享状态契约统一为 queued；兼容旧 pending 只在边界归一化。服务端提供 allowedActions，前端按真实动作渲染。后台标签暂停轮询，活动时使用单次完成后再排下一次的轮询，失败重连采用退避；首期无需新增 SSE 基础设施。

验收：排队可筛选、可取消、自动更新；待复核和已取消可筛选；没有活跃任务时停止高频请求；慢请求不会叠加。

### F13 P1 模块校验发生在重试和取消副作用之后

证据 A10：真实 PDF retry 路由以替代服务验证，服务已执行一次重试后，才因 sourceModule=ocr 返回 404。代码检查确认 cancel 同样在操作后检查；范围是同一用户跨应用任务，不是已经复现的跨用户越权。

修复：retryJob/cancelJob 接受 expectedSourceModule，读取用户与模块范围后才允许状态改变；下载和复核入口遵守同样边界。验收：错模块、错用户、不存在任务均无状态修改、文件删除、输出生成和日志副作用。

## 6 代码审查发现的专项风险与验证任务

本节是代码审查确认的设计缺口或待补动态验证，不计入 13 项已复现探针。

### R01 加密 PDF 的结构操作能力不成立

loadPdf 将 password 传给 pdf-lib，但当前 1.17.1 的 LoadOptions 不包含 password；官方明确说明不支持加密文档 [S09]。PDF.js 文本与图片路径能使用密码，不能据此推断合并、旋转等结构操作可解密。

S0 将能力声明为“当前结构操作不支持加密文件”，预检后禁用并解释；S2 增加受控 qpdf 适配器进行授权密码验证、临时解密或保护输出。禁止以 ignoreEncryption=true 替代解密。验收使用 AES-128、AES-256、错误密码、多文件不同密码夹具，并检查临时明文清理。

### R02 取消和删除存在继续生成产物的竞态

普通 PDF 操作循环没有取消检查，touchProgress 遇到取消返回 null 但不停止计算。删除先清理文件、删除任务，worker 仍可能写入新文件；这里只确认缺少阻止条件，尚未压力复现泄漏或孤儿输出。

每次子步骤检查 cancel signal，worker 或子进程可中断；输出先写 staging，最后在带 attemptToken 的事务中发布。请求删除先转 deleting，等待当前执行确认停止后释放文件。每次 worker 进度写入和发布都校验 leaseOwner、attemptToken、状态，防止过期 worker 继续提交。

### R03 租约与资源控制需要强化

已有数据库抢占与 15 分钟默认租约及恢复扫描，不能描述为“没有持久队列”。但进度回调承担租约刷新，长时间渲染或保存阶段可能没有独立心跳；并发数是进程内计数，跨进程全局预算未统一。

为 document worker 复用平台租约模式，增加独立心跳与令牌；重计算移入受限 worker/子进程，限制 CPU、内存、像素、时间、临时磁盘和输出数。服务重启恢复与旧 worker 同时存活时只允许一个版本提交。全站聊天和其它应用仍可响应。

### R04 已完成任务重试会先删除旧结果

retryJob 接受 succeeded 和 needs_review，先 cleanupJobArtifacts。新执行失败会使旧有效结果与复核记录丢失。改为失败任务重试当前失败尝试，已完成任务使用“再次处理”创建新版本；版本发布成功后再更新当前指针。验收：新版本失败不影响旧下载与复核来源。

### R05 原件预览与中间文件生命周期不完整

cleanup.js 定期清理 ready outputs，未覆盖全部 originals、未关联预览、上传中断和登记中途失败。多文件登记循环在任务创建的 try 外面，后续文件登记失败可能留下前面已登记文件。保留“删除任务清理相关文件”已有行为，并增加引用检查及周期性对账。

建立原件、预览、staging、输出、归档不同保留策略；有任务引用或业务入库引用的文件不可被清理；运行和下载中使用短租约。建议默认原件/输出保留 30 天，预览 7 天，staging 24 小时，归档 24 小时，最终以组织策略覆盖。任务显示 expiresAt，到期状态区别于失败。

### R06 ZIP 与浏览器整包下载放大内存

当前服务器逐个 readFile 再内存 ZIP，默认归档总输入限制 256 MB；浏览器再完整 blob。改为归档任务、文件流输出和受控下载，避免多份 Buffer 复制；沿用下载鉴权或使用用户绑定、短期且可撤销的令牌，不能把会话 Token 放 URL。缺失输出应给出清单，不能静默生成不完整 ZIP。

### R07 文本抽取缺少页面来源与扫描判定

PDF 工具抽取只有全文，pages/blocks 为空，截断没有公开完整性标记。空文本也能生成结果。改为逐页提取，保存来源页与块；混合 PDF 仅对无文本页调用 OCR，避免重复层；超长文本记录 truncated、originalLength、exportedLength；空文本提示转 OCR。

### R08 原件结构与交互细节需补兼容性检查

copyPages 不能据此保证书签、链接、表单、注释、标签、附件和数字签名全部保留；由复杂夹具逐项验证。任何改写都须识别签名并提示其状态会改变。前端文件行辅助信息常驻第二行、原生 window.confirm、详情按钮无条件提供重试和取消、摘要字段与 processedPages 不一致、焦点管理缺失，应按统一 UI 修正。

## 7 目标交互与用户流程

### 7.1 页面组织

主页面保留创建入口、状态/操作/日期筛选、任务表格与分页。创建区采用拖放或选文件、明确的操作入口和常用预设。默认不显示 DPI、技术上限等高级参数；只有图片导出、OCR、压缩等相关操作才展示对应参数。部署限制用自然语言呈现，用户不能通过填写更大数字绕过策略。

点击“新建处理”或文件进入创建弹窗或详情工作区。工作区分为文件清单、页面缩略图/预览、当前操作设置；文件顺序和页面顺序可拖动，也提供键盘“前移/后移”按钮。横向、竖向、裁切、旋转和总页数清楚可见。提交前显示“输入 3 份，共 28 页；删除 2 页；预计输出 26 页”。

任务详情提供“摘要、页面、输出、处理记录”标签。摘要展示阶段、真实已处理量、缺页或告警；页面用于比对和 OCR 复核；输出提供预览、单项或全部下载、继续处理及业务分发；记录包含时间、参数版本、引擎版本和错误恢复建议。结果页不铺到主任务列表。

### 7.2 四条标准流程

1. 材料合并：上传多份 PDF → 预检 → 排文件和选页 → 展示页数摘要 → 执行 → 核对输出 → 下载或继续加页码。
2. 页面整理：单文件 → 缩略图选择 → 旋转/删除/重排/插空白页 → 撤销与重做 → 变更摘要 → 发布新输出。
3. 扫描件归档：检测无文本或混合页 → 选择 OCR 范围 → 完整页处理 → 标记低置信度 → 人工复核 → 中文可搜索 PDF → 入库，保留原文件与页码来源。
4. 批量提交：选择同类文件及预设 → 建立父任务与子项 → 局部失败不阻断无关联项 → 复核结果数量 → 只重试失败项 → 下载包含清单的归档。

### 7.3 交互规则与可用性指标

创建失败保留文件清单和参数；加载和错误在对应区域显示，Toast 只做补充。操作不允许时显示原因；危险操作使用项目统一确认弹窗并说明版本、文件及引用影响。已完成显示“再次处理”，失败显示“重试”，待复核显示“复核”，处理中显示“取消”。

支持 1366×768、1920×1080 及 200% 缩放；表格受控滚动，弹窗适应可用高度。键盘可完成文件排序、选页、保存；焦点锁定、Esc 关闭、焦点归还、可读标签、对比颜色配合文本提示，满足项目无障碍规范。屏幕阅读器操作不依赖缩略图。

可用性验证计划：8 名覆盖 3 类岗位的代表用户，每人完成合并、删页、扫描处理和失败恢复。目标任务完成率≥90%，单项工具可发现率≥90%，误删/漏页未发现次数为 0，关键操作无需培训说明。该验证在 S1 结束前实施，当前并无对应测量数据。

## 8 功能扩展规格与依赖

### 8.1 S1 页面工作区与基本整理

扩展选页、成组提取、按范围/固定页数/输出数量拆分、插入空白页、跨文件追加、复制页及裁切。裁切仅修改可见区域，不宣称删除隐藏内容。页面编辑保存为明确 pageMap 与变更集，至少支持 20 步草稿撤销/重做；执行产物采用新版本，不覆盖原件。

验收：文件顺序、页序、删除和旋转与预览一致；选择范围与缩略图互相同步；对已签名、包含表单等特殊文件预检显示结构风险；不能删成零页。先实现单文档稳定交互，再开放跨文件页面拖动。

### 8.2 S2 水印与页码

水印支持文本和图片、位置、角度、透明度、页面范围及奇偶页；页码支持起始数字、总页数、前缀、页边距和跳过封面。使用受控 CJK 字体，坐标基于 CropBox 与旋转转换，中文不出现方块。提供企业预设，但首次运行和修改后仍可预览。

验收：中文水印在横竖混排和旋转页面定位正确；“跳过封面，从 1 开始，共 20 页”的语义由预览说明；多次连续处理标记版本，避免不知情重复叠加。

### 8.3 S2 压缩与图片转 PDF

压缩分为结构无损优化与图像有损优化。先接入 qpdf 结构优化；图像压缩必须有嵌入图片重采样能力的专用引擎，不能把整页截图作为默认实现。显示压缩前后体积、比例、图像质量、文本/链接等是否保留，以及未达到目标体积的原因。目标大小是尽力约束，不保证任意输入可达到。

图片转 PDF 支持 A4、A3、原始比例、横纵向、页边距、适应/填充、EXIF 方向、JPEG 质量和图片排序。支持格式由 capability 决定，不以扩展名静默过滤。

验收：文字型 PDF 压缩后文本仍可检索；扫描夹具不得丢页；输出更大时允许保留原版本并报告“未获得收益”；填充裁切须可见。图像质量阈值由扫描样本集设定，不宣称统一压缩比。

### 8.4 S2 批量处理与结果继续使用

合并定义为多输入单输出；图片转 PDF 定义为多图片组合输出；其它操作在 batch 模式中是每份输入独立处理。父任务显示整体统计，子项各自有错误码、输出、耗时和重试次数。共享同一合并输出的步骤只能原子失败，不能把缺一份材料的合并标记部分成功。

加入命名模板、结果清单 manifest、失败清单、重复文件提示、参数预设和“继续处理”。复用已存在文件输出时以 outputId 注册受控引用，校验用户访问及文件未过期；不能接受前端任意路径。首期保留每批 20 份限制，扩容必须有资源压测依据。

### 8.5 S2 文本提取与 OCR 质量升级

逐页文本导出 TXT、Markdown、JSON，并保留页码与块；扫描或混合文件提供“转文字识别”及“生成可搜索 PDF”同一底座路径。扫描增强和去倾斜仅在服务声明支持时开放，保存参数与原件。复核可编辑文本并跳转原图位置，低置信度页默认不直接宣称入库内容已可靠。

验收：人工确认后导出包含修订文本；长文截断可见；混合页无重复文字层；中文可搜索 PDF 同时满足视觉、纸张和逻辑文本验收。

### 8.6 S3 业务分发与自动化

PDF 结果提供发送到知识库、法规导入、公文素材或聊天附件。源文件、页码、outputId、版本、SHA-256、OCR 置信度和人工复核状态均随分发保留；目标模块照常执行自己的解析、权限、必填字段和人工审核，不能自动把普通 PDF 当有效法规。

首批自动化模板为“材料合并→页码→水印→下载”和“扫描识别→复核→归档”。复核为可暂停节点，失败策略可配置；引用已发布工作流版本，执行时使用运行用户的模型、凭证和权限。文件夹监听复用既有工具库本机能力与白名单，不能让服务端访问任意客户端路径。

AI 优先提供页码定位的摘要、材料目录建议、分类和操作计划。AI 不能直接修改原件；“删除/脱敏/提交”计划需要展示具体页面和变更摘要，执行前按平台已有副作用策略确认。引用包含 sourceVersion、pageNumber、bbox，证据不足则明确说明。

## 9 技术架构与引擎方案

### 9.1 目标链路

受控上传或引用 → 文件预检 → 操作参数编译 → 任务队列 → 受限 worker → staging 输出 → 质量检查 → 原子发布 → 鉴权预览与下载 → 业务分发与生命周期清理。

前端提供预览和意图编辑；路由仅负责用户、模块、枚举、数量、权限和响应；共享文档服务完成业务执行。预检与 worker 使用相同 engineCapabilities 和 validator，防止 UI 支持但服务不支持。所有引擎使用服务端生成路径，执行进程传参数数组，禁用 shell 拼接；日志只记录参数摘要和 secretRef 状态。

### 9.2 引擎取舍

| 能力 | 首选方案 | 约束 |
| --- | --- | --- |
| 页面结构、叠加、基础表单 | 复用 pdf-lib、sharp、CJK 字体模块 | 不承担加密解密、真正脱敏或复杂正文编辑 [S09] |
| 前端预览与选择 | 受控引入 PDF.js 浏览器构建及本地 worker [S11] | 本地静态资源、版本锁定，禁止 CDN；限制脚本和外链行为 |
| 授权解密、保护、结构优化 | 隔离 qpdf 适配器 [S10] | 服务端部署依赖、启动健康检查、密码不进命令行与日志 |
| OCR | 继续外置 HTTP OCR 服务 | language/geometry/timeout 契约；不可用时普通页面工具仍可用 |
| 归档验证 | veraPDF [S12] | 为验证器；转换由单独引擎承担 |
| 压缩高级档、脱敏、签署、格式转换 | 可替换专项或商业引擎 PoC | 许可、平台、内网部署、效果与安全验证后选型 |

技术选型暂不引入完整 Stirling 服务替代现有底座；可用其交互及 API 模式作为参考。是否采购商业 SDK 由高级功能 PoC、目标平台与授权成本决定，首期不预设采购或调用外部云服务。

### 9.3 模块拆分与代码落点

后端 pdf/index.js 变为薄入口，拆分 `pdf/validation.js`、`operations/`、`preflight.js`、`quality.js`、`engines/`；任务服务按 repository、runner、lifecycle、review、dispatch 分职责逐步拆分。数据库通过现有 client 与迁移流程访问，不新增同步数据库或独立任务系统。路由新增能力和预检入口，禁止把图像处理和业务分发逻辑追加到路由。

## 10 API 与数据契约

### 10.1 兼容策略

保留现有 `/api/apps/pdf-tools/jobs` 创建与读取接口；S0 修正无效值、用户/模块范围和多文件约束，并提供 configVersion。旧 pending 仅在兼容入口映射 queued；旧页面参数可解析为新版 pageMap，不能继续静默忽略非法输入。新增接口是目标设计，当前尚未实现。

| 接口 | 作用 | 必须校验 |
| --- | --- | --- |
| GET /capabilities | 公开可用操作、限额、参数与降级原因 | 用户权限；仅返回用户可理解的能力信息 |
| POST /files | 登记上传文件并发起预检 | 类型签名、单个/总字节、数量、用户配额 |
| GET /files/:id/preflight | 真实页数、尺寸、文本/扫描、加密、签名摘要 | 用户范围；密码只通过安全提交入口 |
| GET /files/:id/pages | 分页获取受控缩略图或预览 | 资源引用和用户权限；限制分辨率与页数 |
| POST /jobs | 输入 fileId/outputId 与 operationPlan | 所有权、模块、能力、参数、预算、幂等键 |
| GET /jobs/:id | 父子项、阶段、完整性、输出与 allowedActions | 用户与 sourceModule；不返回 secret |
| POST /jobs/:id/retry | 重试失败项 | 失败类型、attemptToken、预算和 secret 有效期 |
| POST /jobs/:id/reprocess | 创建新的处理版本 | 来源仍可读、参数版本和 lineage |
| POST /jobs/:id/cancel | 发起取消并反馈确认状态 | 仅活跃态；不直接宣称计算已经停止 |
| POST /jobs/:id/archive | 建立流式归档产物 | 输出完整性、配额、大小、过期与下载租约 |
| POST /jobs/:id/dispatch | 分发至已有业务模块 | 目标权限、质量门槛、来源、幂等和目标必填项 |
| DELETE /jobs/:id | 请求删除任务及可释放文件 | 运行停止、共享引用、用户与模块范围 |

### 10.2 操作计划与公开结果

operationPlan 至少包含 configVersion、operation、mode（single/combine/batch）、sourceRefs、fileOrder、pageMap、outputPolicy、qualityPolicy 和 idempotencyKey。pageMap 的每一项包含 fileId、sourcePage、rotation 和 crop，坐标单位固定为 PDF pt；客户端不能传磁盘路径。密码按 sourceRef 单独提交并转换 secretRef，公开计划只包含 requiresPassword。

公开结果至少包含 stage、progress、totalFiles、successFiles、failedFiles、totalPages、requestedPages、processedPages、missingPages、truncated、warnings、qualityStatus、expiresAt、outputManifest 和 allowedActions。progress 表示阶段内已完成工作量，不能以 100% 替代成功状态；没有可信估算时显示“正在处理第 N 页”。

错误保持项目统一响应封装，error.code 稳定：INVALID_OPERATION、INVALID_PAGE_RANGE、UNSUPPORTED_INPUT_COUNT、PDF_PASSWORD_REQUIRED、PDF_PASSWORD_INVALID、PDF_ENCRYPTION_UNSUPPORTED、PAGE_LIMIT_EXCEEDED、OUTPUT_INCOMPLETE、SOURCE_VISUAL_MISSING、FONT_UNAVAILABLE、ENGINE_UNAVAILABLE、QUOTA_EXCEEDED。公开错误提供修复动作并过滤内部路径。

### 10.3 状态机

保留 queued、processing、succeeded、failed、needs_review、cancelled。processing 的 stage 为 preflight、rendering、ocr、transforming、validating、publishing；S2 父任务增加 partial_success，取消增加 cancelling，删除增加 deleting。needs_input 用于需要密码或其它补充输入，expiresAt 对应输出 expired，输出状态与任务状态分开。

非法状态转换返回冲突并给出 allowedActions。只有全部子项成功且输出校验通过的父任务为 succeeded；独立文件批量可 partial_success；合并缺输入必须 failed。取消以 worker ack 或受限进程终止完成为准。

### 10.4 数据扩展与索引

复用现有 document_files/jobs/pages/outputs/ocr_blocks/reviews。jobs 增加 config_version、parent_job_id、stage、worker_id、attempt_token、lease_until、cancel_requested_at、next_retry_at、idempotency_key、error_code。pages 增加原始 PDF 点尺寸、像素尺寸、crop_box、rotation 和坐标 transform。outputs 增加 version_id、sha256、page_count、quality_json、expires_at 和引用标记。

按职责新增 document_job_items（每输入子项）、document_artifact_versions（来源与父版本）、document_artifact_refs（任务与业务引用）、短期 document_job_secrets 或复用等价秘密存储。所有表包含 user_id，并遵守平台已存在的租户或单位范围，不强行建立新租户模型。

建议索引：jobs(user_id,source_module,status,created_at DESC)、jobs(status,next_retry_at,lease_until)、items(parent_job_id,status)、outputs(user_id,job_id,status)、outputs(status,expires_at)、refs(artifact_id,ref_type)。幂等键按 user_id+source_module+idempotency_key 唯一，attempt 发布也有唯一约束。初始化、迁移、快照、注释和索引基线同步更新。

### 10.5 迁移与回滚

采用扩展→双读兼容→旧数据回填→切换写入→移除旧字段。先完成密码去明文与序列化白名单，再发布其它字段。旧页数不足时标记 completeness=unknown，不凭已有 pageCount 宣称完整；缺原件的历史任务不能恢复为“已验证”。

新增版本不回写或删除旧有效产物。发布功能以开关分阶段启用；降级可以关闭新入口并恢复旧读取，凭证白名单与正确性校验保持。取消/删除改造期间保持 staging 清理和扫描对账，数据库回滚不得以恢复明文密码为方案。

## 11 质量安全性能与运营验收

### 11.1 质量基准集

建立不少于 60 份可公开或自建夹具，覆盖文本、纯扫描、混合、中文英文、横竖混排、旋转裁切、1/3/6/20/100 页、大图、损坏、加密、书签、链接、表单、注释、附件、签名、重名和异构字体；每类至少 3 份，分类允许交叉。记录真实页数、尺寸、文本、顺序、关键对象、预期警告和图像参考。

页面操作验收同时检查结构、内容和视觉；原文件 SHA-256 不变；输出 manifest 与实际文件一致；中文回读关键文本 100% 一致。自动图像差异可采用同一渲染器固定参数、基准 SSIM≥0.995 作为辅助门槛，允许变化区遮罩后比较；阈值按样本校准，最后人工核对，不作为所有转换的通用保证。

OCR 的字符错误率按清晰中文、低清扫描分别报告，不混合平均。首期建议清晰打印中文样本 CER≤3%，明显低清样本允许待复核；识别置信度需校准后才能作为过滤阈值。数字、金额、日期等关键字段需要人工确认或专门字段验证，指标不构成真实 OCR 服务已经达标的声明。

### 11.2 可靠性和安全门槛

- 无静默漏页、漏文件、缺图成功或重排隐式丢页；公开凭证字段为 0；未授权读写和错模块副作用为 0。
- 取消、删除、恢复、重试和归档各进行故障注入：处理中崩溃、磁盘满、OCR 超时、字体缺失、慢 worker、旧 worker 迟到、下载过期、文件登记中途失败。
- 同一 attempt 只允许发布一次；已取消不新增 ready 输出；再次处理失败保留旧版本；运行文件不被 GC 删除。
- 输入校验包含文件魔数、扩展名和解码结果；压缩炸弹、高像素图片、PDF 大量对象、恶意脚本/附件样本在资源上限内失败。
- 审计覆盖创建、改参、取消、删除、复核、下载、分发、解密/加密及预设执行，记录文件哈希与版本，避免记录全文或秘密。

### 11.3 性能目标与测量方法

参考环境为 Linux 8 vCPU、16 GB 内存、本地 SSD、PostgreSQL；OCR 服务单独记录 CPU/GPU、并发与模型版本。服务端主部署与 Windows/企业 Linux 支持目标分别验收。上传耗时受网络影响，单独统计，不与执行延迟混为一项。

| 指标 | 建议验收目标 | 测量条件 |
| --- | --- | --- |
| 文件预检 | p95≤2 秒 | ≤20 MB、≤100 页文本 PDF，热缓存与冷缓存分别报告 |
| 首屏缩略图 | p95≤3 秒 | 首屏最多 12 页，1366×768，内网网络 |
| 基础结构处理 | p95≤8 秒 | 单任务总输入≤20 MB、≤100 页；混合复杂文件单独报表 |
| 任务查询 | p95≤300 ms | 20 并发用户，至少 10 万历史任务数据 |
| 取消响应 | ≤1 秒受理，≤5 秒 ack | 非可中断引擎有单独最长超时，不假报取消完成 |
| 资源稳定 | 单 worker RSS≤1 GB 起步预算 | 20 MB/100 页基线；重图任务按部署预算拒绝或转专用队列 |
| 全站稳定性 | PDF 重负载下常规请求 p95 增幅≤20% | 聊天、列表同时运行，进程隔离有效 |

这些指标先做基线测量，再结合典型文档调整。不能通过降页数、降低质量或漏文件满足延迟目标。OCR 按每页 p50/p95 和并发吞吐独立报告，不给所有引擎统一时间承诺。

### 11.4 运营可观测性

按操作、引擎和文件类型统计成功率、业务错误率、系统错误率、排队时间、处理耗时、完整性失败、复核占比、取消确认、重试、过期下载、临时磁盘和峰值内存。版本维度可追溯，不将用户输错页码计作系统处理失败。

管理员健康页显示 PDF 结构能力、预览、字体、OCR、qpdf 和存储可用性。业务页只呈现能力是否可用与可操作建议。告警针对队列长期增长、staging 超期、孤儿引用、持续失败和缺页成功；不向普通用户显示服务路径或内部堆栈。

## 13 发布门禁与实施治理

### 13.1 正式开发完成标准

每个工作包包含缺陷或需求编号、参数契约、迁移方案、正式回归、用户帮助和可截图的结果。共享底座变更必须回归 OCR、知识库、法规导入和聊天附件。新增索引、配置和依赖更新各自基线及许可证清单，遵循开发规范和 DESIGN.md。

建议执行命令为现有 `npm run check:text`、`npm run check:architecture`、`npm run check:pg-migrations`、`npm run check:pg-indexes`、`npm run check:standards:changed`、`npm run check:licenses`、`npm run lint`，并通过 `node scripts/run_node_tests.js` 运行相关正式测试；UI 进入现有 Playwright 门禁。最终合并前按仓库要求运行完整检查。当前仅实际运行文档处理 11 项回归与 13 项审查探针，不声称全部工程门禁已通过。

### 13.2 灰度与回滚

顺序为测试环境→5 名内测用户→单单位约 10% 用户→约 50%→全面开放；比例按实际组织规模调整。每阶段至少覆盖 100 个可核对任务或 2 个工作日，以较晚达到为准。监控完整性、错误、队列、取消、内存和过期行为。

出现任意静默漏页、密码回传、错权限副作用或原件损坏立即停止放量。系统错误率高于 2% 或普通请求 p95 增幅超过 20% 持续 15 分钟，暂停新任务并检查；先保留已完成产物与任务记录，再关闭新功能。回滚演练验证旧版本读取与新任务恢复，不进行不可恢复数据删除。

| 新引擎跨平台和许可 | 无法内网部署或发行 | 运维健康检查、版本锁定、许可评审，独立服务边界 |
| 批量引入计算和存储增长 | 全站延迟、磁盘满 | 后端 worker 隔离、组织配额、阶段压测与 GC |
| 自动化继承错误来源或权限 | 误入库、重复执行、泄露 | 分发保留来源，使用运行用户权限及幂等 |
| 复杂 PDF 转换保真不足 | 用户误以为完全还原 | 限定文件类、报告降级、专门 PoC |
