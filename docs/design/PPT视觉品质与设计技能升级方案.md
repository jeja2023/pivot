# PPT 视觉品质与设计技能升级方案

状态：v0.7.104 已完成语义生成、整稿检查与确认式优化升级，长期增强项见下文。编制日期：2026-11-06。

本方案深化现有 PPT 工作台及 v0.7.101 对话生成链路，重点是成稿设计质量，不替换现有编辑器、权限和文件交付体系。

## 本期已实施范围（v0.7.102）

- 新增咨询式简报、政企正式、培训讲解三套主题，每套十八类语义布局，原有商务蓝和森林绿继续可用；提供三套八页样稿用于本地验收。
- 增加内置中文演示设计配方，复用现有 SKILL.md 清单解析协议，工作台自动载入设计指导，任务通过 `presentation.design_info` 读取技能与有权模板目录。此入口不自动发布组织共享技能。
- 聊天工具支持新布局、关键指标与受控图片输入，默认使用咨询式简报；工作台 AI 扩大元素容量并使用布局槽位指导。
- 按受控中文字库测量文本，数字和常见单位一同换行。新设计正文适配以 24px（导出 18pt）为下限，放不下时检查阻断并要求拆页；不会静默截断正文。
- 新增 `presentation.review` 按页视觉复核、`presentation.relayout` 单页重排。重排保留内容、来源和锁定元素，拒绝已批准页面，保存新版本。
- 编辑器的 AI 助手新增“视觉复核当前页”，结果标注具体页面；未配置视觉模型时显示未完成，文稿变化后提示重新复核。

## 本轮功能升级（v0.7.104）

- 使用同一份验收材料制作原商务蓝与新培训讲解的完整八页对照，覆盖封面、目录、章节、结论与证据、比较、图表、行动和总结；同步输出三套新风格的原生可编辑 PPTX、逐页 PNG 和内容核验记录。
- 工作台新主题生成改用语义页面协议。模型给出观点、要点、双栏、指标或真实数据，布局引擎确定坐标、字号和槽位。聊天任务与工作台复用同一编译器，兼容已有 IR 输出。
- 根据真实字体容量保留全文拆页，保持来源与讲稿，报告大纲页数和实际页数。单条要点、封面或数据页仍无法容纳时明确要求调整，不静默截断正文；长标题避免末行孤字。
- 新增可取消、可查询进度的整稿后台任务，复用现有 `tool_tasks`。刷新或重新打开文稿可读取最近任务；原稿变化、权限撤回或所属 Agent 停止时，不再把旧版本结果标记为通过。任务最长十五分钟，服务中断后请停止旧检查再重新启动，过期状态明确可见。
- 整稿排版优化至多进行两轮候选评估，只接受可验证的改善，保留文字、数值、来源、讲稿、锁定元素及已批准页面。优化先形成建议稿，用户确认后应用，可通过编辑器撤销；后台不直接覆盖源稿。
- 在服务端读取真实 PPTX，核对页面、正文、表格和原生图表，缺失内容时阻断文件交付。此项属于文件内容核验，不等同独立 Office 视觉渲染。

多轮自主内容改写、联网配图、复杂第三方模板保真，以及最终 PPTX 的独立 Office 渲染仍属于后续增强。本轮没有把这些目标标记为完成，以下章节保留完整目标与实施依据。

## 1. 建议结论

建议采用“经过设计评审的模板包 + 按内容匹配的布局库 + 内置中文演示设计技能 + 受控素材 + 渲染后视觉复核”。

技能负责怎样组织内容、选择视觉表达和修正问题；模板包提供经过设计的母版、构图、字号与素材；布局引擎保证执行结果；质量检查核对画面与导出文件。四者共同决定成稿质量。单独加提示词、换导出库、增加颜色或给每页添加卡片，不能形成稳定的品质提升。

用户提供的其他平台截图显示其读取技能、编写文件并调用视觉分析检查溢出与遮挡。截图未展示完整成稿及技能内容，不能据此判断其最终质量或直接复制其实现。值得借鉴的是生成、渲染、看图、修正的闭环。

上轮“无需用户另装技能”指用户不必自行配置才能生成文件；本方案建议由系统提供经过验证的设计技能，并在合适任务中自动加载。两者可以同时成立。

## 2. 代码现状核对

| 项目 | 当前证据 | 对品质的限制 |
| --- | --- | --- |
| 内置模板 | `presentation-templates.js`：商务蓝汇报、森林绿简报，两套均有十类布局 | 可选设计语言有限，既有装饰、页眉和卡片模式重复 |
| 聊天生成 | `presentation-task-content.js`：七类语义输入，固定几何后应用模板重排 | 不能表达时间线、矩阵、关键指标、证据与结论等更多结构，也没有图片字段 |
| 工作台 AI | `presentation-ai.js/buildSlidesMessages`：每页最多四个元素，仅 text/shape/table/chart，不允许 image | 曾用于控制输出可靠性的限制，同时限制了构图、图示和图文能力 |
| 字号 | 部分正文槽位为 18，PPTX 导出将字号乘 0.75 | 对应输出约 13.5pt；需要明确编辑器单位、物理页尺寸与导出 pt 的换算及最低可读字号 |
| 文字测量 | `presentation-validation.js` 主要按宽度、字号和字符数估算 | 中文、英文、数字、粗体及字体替换的真实断行不能充分反映 |
| 质量检查 | `presentation-render-quality.js` 逐页渲染并验证 PNG 尺寸、格式，叠加结构检查 | 没有模型观看渲染图，也未完成最终 PPTX 的独立渲染核验 |
| 已有基础 | 版本化模板、素材、品牌约束、布局候选、源稿 IR、PPTX 导出、技能发布与发现 | 可渐进扩展，具备复用基础，无需重建整套系统 |

以上是升级前本地代码审计结论，改进见前面的已实施范围；远程生产配置与部署状态需单独核验。

## 3. 设计目标与首期范围

### 3.1 先做成套设计样稿，再固化为模板

首期建议三套风格，每套先精修八页样稿：封面、目录、章节、结论与证据、双栏对比、图表、行动计划、总结。应使用相同长短材料交叉验证，不只做漂亮封面。

| 风格 | 主要场景 | 设计方向 |
| --- | --- | --- |
| 咨询式简报 | 经营复盘、项目决策、管理汇报 | 结论标题、清晰网格、留白、少量强调色、图表与证据主导 |
| 政企正式 | 工作汇报、制度宣讲、会议材料 | 稳定阅读顺序、适度文字密度、克制品牌元素、统一来源与编号 |
| 培训讲解 | 操作培训、课程与流程说明 | 步骤、场景示例、概念图解、讲解节奏，详细内容进入讲稿 |

样稿须经历设计评审和真实投屏检查，通过后转为模板包。模板包至少包含主题令牌、母版、不同结构的布局、槽位约束、受控素材、中文字体策略、短文与长文样例以及预览图。模板的价值是构图、层级、节奏和适配能力，而不仅是配色。

### 3.2 布局按信息关系选择

建议逐步形成约 18–24 类可组合的语义布局。数量是建设范围建议，不作为验收成绩；每类须有明确适用内容与容量边界。

| 信息关系 | 推荐布局 |
| --- | --- |
| 一条核心判断及依据 | 大结论 + 证据；重点数字 + 解释 |
| 同类事项比较 | 双栏对比、前后对照、比较表 |
| 时间或步骤 | 时间线、里程碑、步骤流程 |
| 层级或关系 | 组织层级、模块架构、因果关系 |
| 数值变化 | 趋势、构成、差异分析、关键指标 |
| 执行落地 | 责任与时限、路线图、风险与措施 |
| 图像解释 | 大图标注、图文对照、案例剖析 |

例如“收入、成本、交付风险、回款安排”应分别使用指标/图表、风险与措施、行动计划等表达，不能全套进“三个圆角卡片”。同一份文稿保持统一设计语言，同时允许不同信息结构。

首期优先利用现有文本、形状、图表、表格与受控图片组合实现。暂不以复杂动画、SmartArt 或任意第三方母版无损还原作为前置目标。

## 4. 技能应包含的内容

建议先内置一个中文演示文稿设计技能，按场景加载章节，并复用现有技能发布、版本、权限和停用机制。

1. **内容提炼**：确定受众与演示目的；每页明确核心信息；将背景、结论、证据、假设和待办分开。详细事实保留在备注或附录，关键事实不能为了美观被删掉。
2. **设计选择**：选择已发布模板及可用布局，解释内容与布局的匹配关系；不能使用工具契约不支持的元素。
3. **排版规则**：标题、正文、数据、注释的层级；中文断行、数字与单位、图表标注、图片裁剪和对齐。
4. **整稿节奏**：章节过渡、重点页与解释页的安排，避免所有页面重复构图，也避免为了多样性随机变换样式。
5. **视觉复核**：检查越界、截断、遮挡、弱对比、过小文字、无效留白、焦点不清和整稿不一致；返回具体页及元素定位。
6. **修正规则**：先换布局、调整内容分组、拆页或把细节移入备注，再考虑在可读范围内调整字号；不能把缩小字体当成默认解决方式。

技能应绑定可用模板和工具的版本快照。模板或工具不可用时给出可执行的替代建议，不能承诺不存在的能力。技能也不能替代结构校验和权限检查。

## 5. 统一生成与修正链路

```text
完整材料与来源
  → 内容规划：每页核心信息、证据、备注
  → 设计规划：模板、语义布局、素材需求、内容容量
  → 布局实例化：槽位填充、字体测量、对齐、品牌约束
  → 页面渲染与结构检查
  → 视觉模型逐页复核及整稿总览
  → 按页修正并重测受影响页面
  → 导出 PPTX，并对导出文件独立渲染核验
  → 交付源稿、文件和检查状态
```

聊天与工作台应调用相同的内容规划、布局实例化和检查服务。保留 v0.7.101 简单工具输入作为兼容路径，逐步扩展到带语义块及 layoutId 的结构，而不是让模型一口气输出全稿自由坐标。

以下为长期职责划分。本期已接入模板目录、单页布局重排、页面渲染和指定页视觉复核；自动逐页设计规划和独立导出核验仍需后续建设：

| 能力 | 主要职责 |
| --- | --- |
| 模板与布局目录 | 返回当前账号可用的模板预览、布局槽位、内容限制与版本 |
| 文稿设计规划 | 从已确认内容形成逐页布局与素材计划 |
| 单页布局与修改 | 生成指定页、替换布局；事实、来源及锁定元素保持可追溯 |
| 页面渲染 | 返回受控页面图、整稿缩略总览及元素位置索引 |
| 视觉检查 | 将页面图交给支持图像输入的模型，输出具体问题与修正建议 |
| 导出核验 | 读取生成的真实 PPTX，检查页数、文字、图表和独立渲染结果 |

已有“布局候选”能力可以保留为用户侧入口，但应接入同一套布局与容量规则，避免模型坐标提案与模板重排互相覆盖。

## 6. 字体、素材与渲染

### 6.1 先统一物理单位与文字测量

设计令牌用输出 pt 定义，内部统一换算到画布坐标。投屏模式可先以标题 28–36pt、正文 20–24pt、注释 12–14pt 为评审起点；正文通常不低于 18pt。具体范围须在项目选定字体、页尺寸、PowerPoint/WPS 和实际投屏中验证，不能把这一组建议当作所有页面的绝对标准。阅读型文稿单独定义密度规则，并与投屏模式区分。

中文字体选择需要同时验证真实字体文件、回退路径和嵌入许可。文字测量采用实际字体的字形宽度、行高、字重和段落间距，不能继续仅用字符数估算。表格文字、图表轴标与数字也纳入同一可读性规则。

### 6.2 素材分层

优先复用用户上传材料中的有权图片、组织素材和离线图标库。需要时接入已有的图片生成或检索能力，由管理员配置可用来源；材料包含的数据图表优先原生绘制。

照片与插画作为素材插入，正文、数字、表格与主要图表保持可编辑。整页图片不应作为默认 PPTX 交付方式。图中重要文字、图示标注和图表数值须单独核对。

### 6.3 核验最终文件

现有同源 IR 预览继续用于快速检查；增加可选的独立 Office 渲染适配器，例如用 LibreOffice 无界面转换真实 PPTX 为 PDF 后逐页检查。该方式可发现部分预览与导出差异，但不等于 PowerPoint/WPS 的完全一致，因此仍保留目标软件抽检。

先明确支持的字体、对象和版本矩阵，再决定是否需要更换或补充导出引擎。当前已有 PptxGenJS；仅改用 Python 的另一套导出库不会自动改善设计品质。

## 7. 视觉检查的执行与边界

以下为完整闭环的目标规则。v0.7.104 已提供逐页后台视觉检查与确认式排版优化；人工或 AI 改写内容后仍需重新检查。

- 结构检查覆盖每页；首次正式生成的视觉检查也覆盖每页，并检查整稿缩略总览。
- 用支持图像输入的已配置模型，结合页面图、逐页目标、元素索引和字体信息定位问题。输出区分阻断问题与设计建议，不以未经校准的“美观分数”判定是否可交付。
- 修正通过结构化补丁完成，保留版本，不能任意改写事实、删掉来源或移动用户锁定的元素。
- 建议最多自动修正两轮；只重测受影响页和整稿一致性，按模板、字体、页面内容及模型版本对检查结果做可失效缓存。
- 没有视觉模型时执行结构检查并明确标注“尚未视觉复核”，提供人工检查入口；不能把它显示为视觉检查通过。
- 导出后的变化需要重新检查；不能在预览稿检查通过后任意修改文件仍沿用原检查状态。

## 8. 产品体验

普通用户先选场景和风格，查看真实内容的样张；默认自动推荐布局。首次可展示三个代表页的风格提案，确认后生成整稿，也可沿用用户明确要求的一次生成方式。业务界面不要求用户理解技能名称或操作工具契约。

编辑器提供“换一种布局”“提高可读性”“减少本页文字”“保持内容重新排版”等具体操作。应用前显示受影响页，支持撤销；“减少文字”不能删除关键事实，应同步处理备注或附录。高级技能、模型和组织模板治理继续放在既有管理入口。

## 9. 分阶段交付与验收

| 阶段 | 交付范围 | 验收方式 |
| --- | --- | --- |
| A：先确认设计标准 | 三种风格各八页精修样稿、字号/留白/图表规范、投屏与阅读模式 | 同一真实材料对比现版与新版；内容完整、阅读清楚、具有明显构图差异，经人工评审通过后固化 |
| B：形成可复用生成能力 | 三套模板包、首批高频语义布局、真实字体测量、设计技能、聊天/工作台共用编译服务 | 长短材料均可生成；不依赖手工改坐标；正文和图表可编辑；旧文稿仍可打开和导出 |
| C：视觉与导出闭环 | 图像模型审查、局部修正、整稿总览、最终 PPTX 独立渲染、素材与组织模板增强 | 无裁切/非预期遮挡；页数、事实与来源保持一致；出现问题能定位、修正、重检并追溯版本 |

验收材料至少包括经营汇报、制度宣讲、项目进展、培训课件和包含长中文标题/混排/大表格的边界文稿。建立固定回归样本，先做同材料盲评，再根据问题调规则；不把模板数量、动画数量或技能调用次数当作效果指标。

阶段 A 应先交付一套完整八页样稿供评审，再扩展其余风格，避免在设计标准尚未确认时批量生产几十套同质模板。本方案不承诺固定工期；开发排期应在样稿标准、字体、视觉模型和目标 Office 环境确认后估算。

## 10. 与现有模块的对应关系

- `presentation-templates.js` 与模板服务：模板包、语义布局、容量约束及版本。
- `presentation-task-content.js`、`presentation-ai.js`：统一内容/设计规划，兼容旧工具输入，减少直接生成自由坐标。
- `presentation-template-reflow.js`：逐步让布局约束替代按元素名称推断位置，保留品牌层及用户锁定项。
- `presentation-renderer.js`：字号与几何单位一致、字体与对象支持矩阵。
- `presentation-validation.js`、`presentation-render-quality.js`：真实文字测量、视觉模型审查与独立导出核验适配器。
- 现有技能与模型管理：发布、发现、加载设计指导，按账号解析视觉模型，记录模型与技能版本。
- 现有源稿、Artifact 与交付服务：继续负责版本、权限、缓存、下载与保存。
