# Pivot 工具与知识库调用、交付和展示全链路实施方案

日期：2026-11-01  
基线：工作区 v0.7.83；以当前代码和已有记录为准。本文是待执行的开发与验收方案，不能视为生产验收报告。现有工作区包含未提交改动，实施时先确认其归属并避免覆盖。

## 1. 目标与范围

让用户在普通会话、Agent 和工作流中完成同一类任务时，能够明确看到：使用了哪些资料和工具、当前授权与执行状态、结果是否真正生成，以及如何预览、下载或处理失败。将知识库作为独立的受控资料来源纳入全链路，而不是只检查外部 MCP 工具。

覆盖：用户选择与意图路由、知识库摄取与索引状态、资源范围与 ACL、检索与引用、工具目录与发现、授权与审批、执行与恢复、结果交付与内容核验、界面展示、诊断审计、评测与现场验收。涉及普通会话、会话转 Agent、独立 Agent、工作流节点、Skill、内置及外部 MCP、数据库连接、离线绘图和文档产物。

不在本方案中直接接入新的业务系统、批量修改生产授权、自动扩大内网范围、上线多节点部署或替换现有模型。模型无法通过提示词自行获得权限；搜索结果、知识库内容和工具输出均按不可信数据处理。

## 2. 当前基线与问题判定

### 已有能力

- 会话可按当前路由和范围进行知识库预检索；Agent 提供 `rag.search`、`knowledge.list`、`knowledge.graph.query`；知识库检索具备范围过滤、混合召回、引用和部分无依据处理。会话资料也可进入任务验收。
- Agent 工具采用搜索、契约读取和执行；工具目录、能力策略、审批、连接治理和网络检查组成多层约束。已有空搜索停止、受控产物、授权下载、右侧预览和部分审计诊断。
- v0.7.77 的隔离测试、v0.7.79 的绘图与文件核验测试、v0.7.81 的 DOCX 预览测试提供了局部证据；它们不证明目标生产环境从会话到结果下载的整条链路已通过。

### 代码中可直接观察的限制

1. 工具排序在 `server/services/tool-discovery.js` 中基于名称、标题、说明和能力的词语匹配；`chat-capability-scope.js` 通常只向意图判断提供 24 项候选，显式选择可扩展但有上限。业务说法、同名工具和大目录需要测量，不能假设模型总能命中。
2. `agent-discovery-progress.js` 在同一目录版本、目标和用户修订下累计四次空搜索暂停。它能避免无效循环，也可能对多目标任务过早停止；必须以业务样本验证并设计恢复。
3. `rag.search` 当前返回 `docName`、分数、`hit` 和截断内容；需逐入口核对引用标识、文档版本、位置及状态是否可稳定传递。`knowledge.list` 和图谱的访问路径与检索路径不同，应做共享权限差分验证，不能直接推定已越权。
4. `tool-result-artifacts.js` 只对登记的 `audit`、`diagram` 结构化契约自动生成相应产物。不能承诺任意第三方工具返回的文件都会自动成为可交付产物。
5. 默认 DOCX 内容预览依据受控文档数据生成，分页、字体和图片可能与原文件不同；ONLYOFFICE 是可选只读接入，生产代理、JWT、回源及实际浏览器尚需现场联调。
6. 历史知识库审计中的某些问题已有后续代码与测试，例如引用配对校验、多查询向量处理。把历史问题列为**回归验证项**，先复现当前基线，不按旧报告直接宣布仍存在。

### 需要通过测试或现场证据确认

知识库权限在缓存、续接、图谱与工作流之间是否一致；资料撤权时流式文本是否已泄露；多轮专题范围是否被错误扩大；文件生成、独立验收与展示是否始终使用同一版本；生产环境连接、重启、超时、网断和多节点事件恢复。这些是待验证风险，不是本文声称已发生的故障。

## 3. 目标链路与状态契约

```mermaid
flowchart LR
    A[用户目标与明确选择] --> B[意图与资源范围]
    B --> C[知识库 ACL 与检索]
    B --> D[工具目录与任务策略]
    C --> E[来源与引用验证]
    D --> F[契约、审批、网络与执行]
    E --> G[模型综合与结构化结果]
    F --> G
    G --> H[产物登记与完整性校验]
    H --> I[业务验收]
    I --> J[状态、来源、预览与下载]
```

定义统一的**阶段状态**：`not_requested`、`pending`、`running`、`succeeded`、`failed`、`blocked`、`waiting_user`、`partial`。各入口可沿用原有数据库状态，但对用户应投影为同一语义；一个阶段成功不能自动代表后续阶段成功。每条状态关联 `runId`、`stepId`、受控资源标识、版本或摘要、时间与脱敏原因码。不要向用户展示密钥、文件系统路径或未授权资源名称。

知识检索结果至少区分：未请求、未选择范围、范围无权限、未就绪或部分索引、无可靠命中、服务失败、命中且可引用、来源撤权或版本已改变。工具至少区分：未找到、不可见、任务/Skill 范围不允许、服务停用、需要审批、审批过期、网络拒绝、执行失败、输出契约失败、产物登记失败。安全敏感的“不存在/无权限”仍可对普通用户合并；管理员诊断需以权限控制展示更多原因，避免成为资源枚举接口。

交付状态分开记录：业务工具成功、受控文件已登记、文件完整性通过、内容/证据核验通过、预览可用、下载可用、本机保存完成。模型答案不得凭自身文字把任一状态标成成功；已产生的部分结果与验收未通过的原因可以同时展示。

## 4. 分阶段开发任务

### P0：基线、统一追踪与可信阻断

**任务 T01 — 建立基线和场景矩阵。** 冻结当前代码版本、模型/工具服务版本、测试配置和账号角色；从以下最小场景建立可重复样本：知识库制度问答、文档无答案、跨用户撤权、离线流程图、Word 交付、只读数据库查询、带审批的外部操作。每项记录输入、资源 ID、期望步骤、可验证结果、失败和耗时，不保存密钥与生产敏感正文。输出测试清单和当前结果，标注未运行及失败，不根据旧报告推断现状。

**任务 T02 — 衔接状态和原因。** 在现有事件/调用记录基础上统一 `requestId → conversation/message → run → step/toolCall → resource/version → artifact/rendition` 关联；补充结构化阶段与原因码，并分别映射会话、Agent 详情、工作流节点和审计包。已有事件兼容读取；原因码枚举、权限投影及旧数据缺字段的显示规则需在实现前冻结。验收：同一失败在四个入口指向同一实际步骤；HTTP 成功但业务失败不能显示成功；脱敏日志不包含令牌、SQL 参数、文档正文。

**任务 T03 — 先关闭证据绕过。** 针对当前 `knowledge-grounding.js` 复跑“纯拒答夹带事实、引用编号和 key 错配、无来源、伪造引用、引用被撤权、流式先输出后失败”的反例。若未通过，修复为只允许受控纯拒答，无支持事实不得放行；引用编号、key、版本和片段必须逐对核对。严格依据场景在输出前完成可信校验，或使用能撤回/屏蔽未核验文本的协议；不能只在最终答案补一个警告。独立语义评审不可替代确定性权限与引用验证。验收：反例不产生未经验证的事实文本，合法引用可用，已有引用配对测试不退化。

### P1：知识库的选择、授权、检索和引用

**任务 K01 — 建立统一的知识来源契约。** 为会话预检索、`rag.search`、工作流知识节点和图谱定义规范结果：资源类型、专题 ID、文档 ID、版本/索引代次、片段 ID、可选页码/偏移、授权引用 ID、截断/覆盖状态、命中与降级原因。正文和敏感元数据按权限与体积限制返回。兼容现有 `docName`、`hit` 和引用格式，采用双读/双写或适配层渐进迁移；记录哪些旧数据无法定位，不能虚构页码。

**任务 K02 — 统一范围和 ACL。** 整理个人、共享用户、单位、管理员、禁用用户、租户隔离矩阵；盘点列表、候选召回、向量/词法、精排、缓存、原文/片段、引用打开、图谱、Wiki、Agent 和工作流的鉴权入口。显式 `@专题` 或资料包以 ID 记录来源和有效期；无权、删除或重命名时重新校验，不能回退为全库。继续任务或切换会话必须校验当前 ACL。先保留现有共享语义，变更前由业务权限负责人审核。验收：A/B 用户、跨租户、共享撤销、禁用、缓存命中和运行中撤权均不返回受限正文；后台日志与诊断不泄露资源名称。

**任务 K03 — 摄取与覆盖。** 复核长 PDF、扫描/混合页、OCR 失败、表格/附件、字数截断与索引失败的状态。页面展示总页数、成功/未处理范围、失败原因和索引版本；部分可用不能标为完整。验证显式重建对解析、切分和 embedding 配置变化的响应、失败恢复与版本切换；数据源扫描不完整时禁止依据缺失记录自动归档。验收：多页 PDF、部分失败、重试、版本切换、源端删除和截断扫描均有可追踪结果，原数据不因不完整扫描误删。

**任务 K04 — 检索质量与引用打开。** 多查询保证向量与原查询对应；验证词法/向量单路失败、空库、超时、索引延迟与部分可用降级。引用点击时重新校验当前权限、文档版本和定位，旧引用明确提示失效，不静默跳到不同版本。制定含制度、长 PDF、扫描件、表格、近义词、跨语言、多轮指代、资料冲突和无答案的黄金集；人工双人标注并版本化，生产语料仅留在受控环境。测 Recall@K、MRR、引用配对正确率、事实支持率、拒答准确率、覆盖率和 P95；先测基线，由业务负责人给出上线阈值，不在开发文档中虚构目标。

### P2：工具发现、执行与恢复

**任务 T04 — 发现评测与改进。** 汇总经授权的工具名称、中文业务别名、能力、参数、数据边界及示例；构造同义词、模糊意图、同名服务、大目录、不可用或撤权工具样本。先统计候选命中率和选择正确率，再评估扩充词法别名、重排或混合检索；任何排序只能缩小经过 ACL 过滤的集合，不能引入未经授权工具。四次空搜索规则按本任务目标/目录/授权变化重新评估：验证多目标任务、无关候选、并发搜索、恢复后重置；必要时给出可调限制和人工选择入口，不通过增加预算掩盖错误。

**任务 T05 — 授权和审批体验。** 展示实际目标、执行范围、风险、副作用及到期时间；审批绑定用户、任务、工具版本、参数摘要、连接与有效期。验证目录更新、参数变化、授权撤回、审批等待与服务重启后的再次检查；继续或并发运行不能使用陈旧权限。网络测试包含同源重定向、DNS 重解析、私网委托、元数据/回环拒绝和端点变化；不要求用户关闭 SSRF 才能运行。

**任务 T06 — 执行、重试与幂等。** 将传输成功与业务 `isError`、输出 Schema、超时和任务取消分开记账。只对可安全重试的操作重试；写入或发送类操作使用幂等键、检查点和“结果未知”状态，故障后查询真实状态或要求人工决定，禁止盲目重复副作用。覆盖超时前后提交、连接中断、进程重启、重复请求、审批与取消竞争；普通对话、Agent、工作流各执行至少一次同样场景。

### P3：交付、展示与可操作诊断

**任务 D01 — 产物闭环。** 明确第三方工具输出如何通过契约登记文件：白名单类型、大小、MIME、内容摘要、所属用户/租户/任务、来源调用及版本；非法 SVG 和外部资源拒绝。任务验收以真实登记文件及完整性为依据，再做语义验收；文件存在不代表内容正确，语义模型不可用不能伪造通过。检查过期、删除、撤权、CAS 缺失或篡改和一次性下载令牌；确保 `tools.execute` 嵌套只生成一次产物。

**任务 D02 — 预览与无障碍。** 会话、Agent、工作流统一“查看/下载/保存”的文件版本与授权；图片可预览，DOCX 明确区分 IR 内容预览和 ONLYOFFICE 对原文件的只读预览。验证多页文档、表格、中文字体、图片、窄屏、右侧面板、键盘关闭、切换文件、加载失败和旧请求迟到；不把内部 JSON 或 CAS 地址当正文。生产 ONLYOFFICE 验收必须检查同源代理、服务间回源、JWT、不同用户隔离、禁用账号、过期票据、资源回收与日志脱敏；不要求用户上传生产密钥。

**任务 D03 — 诊断与审计。** 给普通用户提供“发生了什么、可做什么、任务是否已执行”的文字；管理员可看到原因码、资源 ID、版本和安全的相关性 ID。审计包记录状态与必要来源摘要，严禁输出密钥、Bearer、私有 URL 参数和未授权正文；对外部副作用区分已完成、失败和状态未知。验收覆盖匿名、不同用户、管理员权限、导出脱敏和错误分支；消息不得把“无权限”变为可枚举资源的接口。

### P4：生产准备与持续质量

**任务 O01 — 运行与灾备。** 单节点先验证任务与知识队列重启、长任务租约、审批超时、等待输入过期、临时文件回收及备份恢复；多节点在独立环境验证重复执行、事件丢失补查、滚动升级和跨节点权限撤销。v0.7.76 严格多节点预检保持现状，不能因本方案测试通过自动解除。ONLYOFFICE 和 Kroki 需核对镜像/版本、网络、资源、日志、备份、故障回退。

**任务 O02 — 监控与质量看板。** 从关联 ID 聚合工具发现命中、权限拒绝原因、调用成功/业务失败/超时、审批等待、知识命中/拒答、引用通过、产物登记/预览/下载、P50/P95、成本和任务终态。按模型、工具、入口和版本分组，统计分母与样本量；不记录敏感正文。设置告警需业务基线和运维确认，不能把有调用记录当作成功率。

## 5. 验收场景与执行步骤

| 编号 | 入口与前提 | 操作 | 必须观察到的结果 |
| --- | --- | --- | --- |
| A1 | 普通会话，用户有制度专题权限 | 指定专题询问有答案的问题 | 只检索该范围；答案可回到正确版本和位置；可见真实引用 |
| A2 | 同上，无答案或检索故障 | 提问不存在的条款，分别模拟空结果与服务超时 | 清楚区分无依据和服务故障；无未经支持的事实或伪造引用 |
| A3 | 两用户、两个租户/共享关系 | 检索、缓存后撤销共享，再查看引用及续接 | 无权用户及撤权后不能取得正文、片段、缓存或下载；旧引用安全失效 |
| A4 | 长 PDF 和混合扫描文档 | 导入、制造某页失败、恢复处理 | 显示页级覆盖及部分就绪；未处理内容不宣称已索引；复处理后可定位 |
| A5 | 会话 `@` 绘图，普通授权账号 | 生成登录流程图 | 搜索到实际工具，执行并登记 SVG；文件通过校验，可右侧预览、下载 |
| A6 | Agent，已选资料和绘图工具 | 基于制度资料生成带来源的流程图和 Word | 检索来源、工具调用、文件、引用和验收对应同一运行；均可追溯 |
| A7 | 工作流，含检索、模型、生成文件节点 | 使用固定输入运行并更换权限后重跑 | 每节点显示实际状态与原因；撤权后阻断，旧版本引用不可冒用 |
| A8 | 受控外部写入测试桩，要求审批 | 审批前后修改参数、模拟提交后超时 | 参数变化需重审；未知状态不自动重放；审计记录实际决定 |
| A9 | ONLYOFFICE 测试环境及未配置环境 | 同一 DOCX 分别打开两条预览路径 | 右侧只读显示；本地预览说明差异；无权限/过期不泄露，关闭释放资源 |
| A10 | 大工具目录、无目标工具 | 多种关键词搜索后改选工具继续 | 适时暂停并说明缺口；新选择生效；不反复烧预算，不扩大权限 |
| A11 | 任务已产生文件但核验未通过 | 打开任务详情及审计包 | 分别显示文件存在与内容未通过；导出无密钥、业务参数或越权资源 |
| A12 | 可控故障环境 | 重启 Pivot、断开工具和数据库后恢复 | 状态不假成功，副作用不重复；恢复或人工处理路径明确 |

每个场景记录：代码提交、镜像摘要、部署拓扑、用户角色、资源及授权设置、测试时间、步骤/事件 ID、实际结果、预期结果、附件摘要、负责人和结论。所有“应拒绝”的场景同样需要可核对证据。若已有文件或回答仅来自模拟，标记为模拟，不作为真实服务验收。

## 6. 自动化测试与执行命令

## 8. 发布、回滚与验收门槛

1. 先完成兼容的事件/结果字段和读取路径，再灰度切换路由、权限投影与界面；旧运行缺少新字段时显示“无记录”，不能推断成功。数据库迁移需向前兼容、备份并在隔离环境验证；索引重建采用受控版本切换，旧索引保留至验证通过。
2. 使用受限账号和隔离数据先跑自动测试、A1–A12；再由业务方在目标内网验证实际模型、工具、知识库、Kroki、ONLYOFFICE 和下载。核对日志不含密钥，明确结果保存位置与清理责任。
3. 先选小范围用户灰度，比较工具选择、引用准确、权限拒绝、失败率、延迟和 Token 消耗；异常停止扩大并保留追踪 ID。生产阈值由业务方依据基线和风险确认，不以本文提议代替签认。
4. 回滚通过受控版本/配置切换回上一个已验证主程序；新字段不得被旧版本误认成功。不得为了恢复可用性关闭授权、审批或 SSRF；知识库索引与数据恢复按隔离演练及备份流程执行。已发生的外部副作用需单独核对、补偿或人工处置，应用回滚不会撤销它们。
5. 放行条件：权限与副作用阻断反例全部通过；关键场景真实运行有证据；文件、引用和语义验收结果一致；失败可诊断；业务、运维、安全分别确认。模型质量与性能指标满足约定阈值，未测试项目和剩余风险得到明确记录。未经确认不标记“全链路生产就绪”。
