# 浏览器本机控制助手实施方案

状态：独立助手、浏览器配对和账号隔离已实现并完成本地开发验收；正式签名与生产验收待目标环境完成。范围：Windows 浏览器所在电脑的原生桌面应用控制。浏览器不能直接执行本机操作；服务端也不能把自身的本机路径当作用户电脑。

实现归档于[v0.7.164发布说明](../releases/v0.7.164-Windows独立助手与浏览器本机控制.md)；功能及布局证据保留 v0.7.162 身份，正式发布以已构建并签名的实际制品为准。

后续远程HTTP确认和下载入口随[v0.7.165发布说明](../releases/v0.7.165-智能路由与助手HTTP下载体验优化.md)归档；当前源码基线v0.7.167，已有HTTP兼容开发包仍为v0.7.164，本轮升版不表示已重新构建或部署。

## 目标与已有能力

- 用户在浏览器发起任务；已安装的独立 Windows 助手在用户当前电脑执行，用户明确授权目标应用并逐次确认本机操作。
- 复用 `desktop/local-desktop-control.js` 的前台窗口和进程名匹配、可访问性控件操作、密码字段拒绝、截图范围和大小限制；不能通过引入助手绕过现有确认。
- 复用服务端设备公钥签名、短期挑战和连接器任务、账号与租户授权、审计、工具治理及结果回传。设备私钥由操作系统保护，只保存在本机。
- 首期能力为既有 Windows 桌面控制工具：检查、截图、点击、输入及等待；不承诺跨平台或任意桌面坐标操作。用户日常浏览器的 Profile 和凭据不因本功能自动开放。

## 配对与会话边界

远程 HTTP 直连由助手本机在发送配对信息前确认具体服务 Origin；确认范围随当前连接加密保存，重新配对或更换地址重新确认，取消不覆盖旧连接。状态持续显示明文模式，不跟随重定向或静默降低 HTTPS。此模式保留既有账号、浏览器、设备及操作权限边界，但不提供传输机密性或等同 TLS 的服务端身份和完整性保证。实现及验证见[HTTP 兼容记录](../reports/windows-local-helper-http-20261116.md)。

1. 助手本机生成设备密钥并连接用户指定的 Pivot 服务；浏览器登录后发起短时、一次性的配对申请。助手通过本机界面确认服务地址、账号及本机身份，双方核对短码；未确认不能建立可执行连接。
2. 配对码必须短时有效、只可消费一次，服务端仅持有摘要并对尝试次数限流；配对应绑定用户、租户、浏览器会话、助手公钥与设备，不能使用账号下“唯一在线设备”自动冒充当前电脑。
3. 助手凭据仅允许设备注册、心跳、领取及回执等必需操作；不得复制浏览器 Cookie、持有通用用户密钥或获得普通 API 的完整权限。凭据及设备签名均须可撤销、轮换和过期，登出或撤权后拒绝新动作。
4. 浏览器发起本机任务时携带已绑定的设备引用，服务端在创建和实际执行前核验当前账号、租户、会话、设备和授权。多个浏览器或多个设备并存时不得猜测目标；绑定缺失、过期或目标离线时明确拒绝。
5. 授权由助手的本机界面完成并可撤销；窗口标题和进程名必须由用户核对。服务器下发的授权摘要不能替代本机授权；点击、输入和截图继续由本机确认后执行。

配对绑定登录账号、服务端签发的浏览器设备 Cookie 摘要与保存在页面会话中的随机绑定证明；浏览器每15秒续期，45秒无续期后拒绝新助手操作，配对最长8小时。普通登出、重新登录、重建配对、助手断开及换号均撤销旧连接。助手不持有浏览器 Cookie 或普通用户令牌；受限凭据仅可访问专用通道且每次仍需设备签名与一次性挑战。后台任务只持久化服务端读取的浏览器绑定列，执行时恢复该上下文；调用方元数据不能扩大设备访问范围。

## 执行与恢复

- 任务由助手主动向服务端领取，不开放未经认证的任意本机命令或远程控制端口。任务参数沿用工具白名单、目标校验、执行授权与审计。
- 助手在执行前复核当前授权、活动身份、任务有效期及前台应用；授权撤销、设备换绑或浏览器会话失效后不得执行尚未开始的动作。
- 被领取的桌面操作如果租约或任务过期，服务端标记执行结果不明，不自动重放。用户应先核对目标应用实际状态；迟到回执不能把已失效任务重新标记为成功。此保护已经在现有连接器中补充，不等于助手已实现。
- 连接器与独立助手均在停止后等待在途执行结束，不把旧动作结果转给新会话。Windows 驱动收到停止信号后需等待子进程退出；本机确认期间停止或授权变更后不启动动作。独立助手切换账号会撤销旧配对、清除本机应用授权并生成新设备密钥。
- 现有连接器按设备最近心跳判断在线状态，离线设备不进入可用工具列表，显式指定离线设备时拒绝创建任务；设备表返回的 PostgreSQL 时间对象也参与真实在线判断。
- 助手停止、网络中断、服务重启、取消和超时要有明确状态；不得静默转成服务器端执行。若执行已开始，必须区分已停止与结果不明。

## 交付与验收门槛

1. 独立 Windows 安装、升级、启动、退出、连接与诊断；服务地址与账号可明确识别，默认不授予任何本机资源。需要清楚展示助手在线状态、授权窗口和撤销入口。
2. 浏览器配对、短码确认、超时、重放、并发消费、恶意账号、跨租户、多设备和浏览器登出/撤销的真实接口与数据库测试；私钥和凭据不进入日志、模型输入或网页脚本。
3. 真实 Windows 目标应用测试：授权、前台切换、截图、点击、非密码输入、取消、本机确认拒绝、助手掉线与租约到期；检查不能对其他应用或错误设备执行。
4. 浏览器和助手端到端测试：选择当前电脑、发起实际任务、在本机确认、返回结果、撤销后阻断；分别标明受控替身和真实生产环境验收范围。
5. 使用帮助和构建脚本已提供，Windows NSIS 开发验证包已生成；正式构建必须提供代码签名凭据，缺失时失败。真实浏览器、HTTP、数据库、Electron助手和Windows驱动的合成目标测试已完成；本机原生确认在端到端测试中由测试主进程自动批准，拒绝/撤权由独立回归验证。正式签名、生产服务器部署与业务应用兼容仍需验收。操作说明见[独立助手部署](../deployment/Windows独立本机助手.md)。
