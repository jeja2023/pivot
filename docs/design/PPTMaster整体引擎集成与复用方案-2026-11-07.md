# PPT Master 整体引擎集成与复用方案

日期：2026-11-07；实施更新：2026-11-08。关联Pivot版本：v0.7.128。完整发行包、受限执行、模型编排、模板及原稿路径已接通；新增离线页面视频和按类型定点写回的原稿工作台。默认关闭，生产须配置签名镜像。自动媒体服务、原生动画视频播放及全部复杂对象内容编辑仍未完成。

## 1. 决策与理由

可以整体复用 PPT Master 的完整技能发行包及其运行工具，推荐将其作为 Pivot PPT 的可选制作引擎。上游已经建设的复杂原生对象、模板、既有 PPTX 保留、公式、图像重建、动画和旁白路径，应优先验证复用，避免逐个用另一种语言重新实现。

“整体”指按固定版本保留完整工作流、参考文档、脚本、模板、资源与许可，并在受控运行时中执行。它不意味着把整个 Git 仓库放进普通技能导入器后，所有能力便自动出现在浏览器编辑器中。项目实例、历史记录及示例可以与运行时分开交付，但不能删去正式技能包所需文件或绕过完整性门禁。

上游本质是供 Agent 驱动的工作流与本地工具链。Pivot 仍需承担宿主职责：理解用户目标、调用模型、操作受限任务工作区、响应确认、持续多步执行和交付结果。调用一个 SVG 转换脚本只能完成其中一个环节。

本次审查固定基线：`hugohe3/ppt-master@769547394107870a0c7b5ad8d1c0c75035123aef`，技能元数据版本 6.8.0。后续实施应从该基线或重新审查后的固定提交构建，不在任务运行期间自动拉取 main。

## 2. 全量复用与 Pivot 价值的分工

| 能力 | 优先实现方式 | Pivot 保留的职责 |
| --- | --- | --- |
| 全新制作、快速制作、美化及图片重建 | 复用 Generate 对应路径与画像，遵守其输入/校验合同 | 表单或聊天收集要求，映射来源和资源，驱动模型及过程状态 |
| Brand/Style/Layout/Deck 模板创建 | 复用 Create Template 的完整模板工作区 | 模板版本、可见范围、品牌资产授权、复用和审计 |
| 既有 PPTX 填充/修改和未修改对象保留 | 复用 Edit Native PPTX 及原生资源往返合同 | 原始文件快照、选择/修改范围、版本和结果差异 |
| 形状、自由路径、公式、原生图表/表格、动画与旁白 | 优先调用上游已实现工具，逐项验收 | 当前素材、模型/语音服务映射、预算、工作区隔离及交付 |
| 在线编辑、故事线、论点证据与数据协同 | 沿用已经实现的 Pivot 工作台 | 现有文稿与历史数据继续可用，来源/计算/失效检查复用 |
| 最终文件核验 | 结合上游自检与独立 Office 检查 | 区分检查范围、文稿/文件摘要、权限和结果登记 |

已经完成的 187 类形状、共享图形场景、原生连接、图表数据核验、故事线、证据和交付检查仍服务 Pivot 文稿与工作台，不应因引入上游而删除。这些是产品层和浏览器编辑能力，也能用于上游产物的检查与可编辑子集接入。

对于上游尚未覆盖的企业协作、权限、证据和增量治理，继续建设 Pivot 增量价值；对上游已成熟的底层格式能力以适配、固定版本和验收替代重复重写。

## 3. 当前阻止“直接上传即用”的具体差异

1. **普通技能包合同不同**：`agent-skill-packages.js` 默认最多 128 个条目；`agent-skill-supply-chain.js` 对普通技能包的 scripts 目录等可执行内容直接拒绝。完整上游发行包应进入受管理执行引擎的发行/审核路径，不应放宽所有用户技能包的执行权限。
2. **宿主能力有缺口**：单文件兼容仅映射指引和元数据；上游依赖包内工作流读取、脚本调用、工作区、阶段状态与确认结果，不能用仅含 Markdown 正文的个人草稿替代完整发行包。
3. **依赖没有锁定到 Pivot 交付环境**：上游 requirements 使用多项下限约束。需要为目标 Python/操作系统/架构解析并固定依赖，准备离线资源、字体和完整第三方许可；不能运行时临时 pip install。
4. **数据模型不同**：上游使用项目专用 SVG 和源 OOXML 保留路径，Pivot 编辑器使用结构化文稿格式。取得可编辑 PPTX 不表示所有对象已可在 Pivot 画布中逐项编辑。
5. **交互和供应商接口不同**：上游本地确认界面、预览服务、模型/图片/语音调用需要接到 Pivot 的现有交互、账号及凭据体系，不能在每个任务中额外暴露独立本地服务或复制用户密钥。

## 4. 目标接入结构

```text
Pivot 聊天 / PPT 工作台
  → 原有鉴权、材料授权、任务与预算
  → 制作引擎适配器
      ├─ Pivot 原生文稿引擎：现有在线编辑及确定性导出
      └─ PPT Master 固定版本引擎：完整上游工作流与工具
           → 受限执行单元 + 只读完整发行包 + 任务专属可写目录
  → 上游校验结果 + 最终文件回读 / 独立 Office 渲染
  → 受控 Artifact / CAS / 文稿版本 / 下载交付
```

### 4.1 发行包与执行单元

- 引擎包保持完整并按内容摘要固定，保存上游提交、许可证、依赖锁、构建指纹、测试报告和安装清单。引擎目录只读，任务目录与业务数据分离。
- 复用现有 Capability Worker 的不可变镜像和签名验证、任务授权、资源/时限、取消与清理。桌面模式复用桌面受控运行机制或经验证的独立服务；未准备相应运行时的平台显示不可用，不自动退回任意宿主 Shell。
- 原始资料从当前授权对象以快照形式复制到任务目录。外部脚本只能访问这次明确提供的输入，生成输出登记后再交付。取消、超时、重启不应留下可继续写入旧结果的执行进程。
- 上游的归属与完整性检查照常执行。上游更新通过新的引擎版本发布，不在正在运行的任务中原地替换文件。

### 4.2 工作流状态和交互

上游三个顶层路径分别对应“生成演示”“创建可复用模板”“编辑原有 PPTX”；Generate 内的快速、美化、图片重建作为对应画像，严格按输入和用户意图选择。确认问题在 Pivot 中展示，将实际答复写回上游约定文件；不会把用户尚未确认的内容记成已批准。

用户已明确要求快速生成或沿用既有确认时按授权范围继续，不为适配宿主反复添加无意义确认。读取工作流、模型生成、页面制作、校验、修复和导出阶段写入已有任务进度，失败返回原阶段、可修复原因和已完成范围。

### 4.3 适配器合同

建议使用平台内部结构化请求，并由服务端解析受控标识，禁止客户端传任意路径、可执行文件或完整命令：

```json
{
  "engine": "ppt-master",
  "engineRevision": "769547394107870a0c7b5ad8d1c0c75035123aef",
  "operation": "generate|create_template|edit_native",
  "profile": "default|quick|beautify|image_to_pptx",
  "brief": {"audience": "...", "purpose": "...", "pageCount": 12},
  "sources": [{"assetId": "...", "digest": "..."}],
  "templateVersionId": "...",
  "outputPolicy": {"nativePptx": true, "includeNotes": true}
}
```

这是待实现接口示意，并非本版已提供的公开接口。实际合同需区分各路径合法字段，固定依赖/资产/模型版本并通过现有服务解析，不能接受伪造摘要代替源对象校验。

结果至少包含任务/阶段状态、引擎版本、逐页产物、原生 PPTX、可回放的项目源包、质量报告及支持级别；内部执行路径和凭据不进入用户响应。

### 4.4 模型、图片与语音

文本/视觉规划继续使用 Pivot 当前账号可用模型和计费预算。上游生成结果质量取决于驱动模型及输入资源；引擎接通不保证任何模型达到相同设计效果。

优先接入既有素材库、受控图片生成和语音服务；需要其他外部服务时采用现有网络策略和凭据解析，清楚标记数据发送范围。未配置供应商时保留缺失状态，不拿整页截图或无声视频冒充原生/旁白完成。

## 5. 在线编辑与保真边界

建议引入明确的逐对象支持等级：

- **Pivot 可编辑**：能完整映射到当前文稿模型，并由浏览器、预览及 PPTX 输出端共同支持。
- **上游原生保留**：源 OOXML 或上游工作区是权威，Pivot 展示预览、可编辑范围和批注；由上游修改/导出，避免现有导出器重建后损失对象。
- **需要人工处理**：源对象或语义不在任何已验证的支持合同内，明确提示并保护源文件。

用户修改 Pivot 可编辑元素后，需通过可验证的对象补丁或上游合同导出；不能把“打开预览”记为全量导入，也不能将静态预览图登记为可编辑原生对象。原有源对象、页码、动画、备注和关系的身份必须保持可追溯。

## 6. 许可与依赖

上游主体为 MIT，保留版权与许可，并保留发行包要求的归属文件和完整性检查。预设形状等第三方数据继续带对应许可。

上游 requirements 明确注明 PyMuPDF 的 AGPL-3.0 和商业许可选项。优先复用 Pivot 已有材料提取并避开无必要的 PDF 后端；若确需分发该依赖，按实际使用/分发模式核对许可。旁白、图像、OCR、字体、模板和模型权重分别按实际引入项审核，不能把上游 MIT 当成全部第三方组件的统一许可。

## 7. 分阶段验收与减少重复开发

1. **完整发行与最小工具闭环**：固定引擎包/依赖/运行环境，保留完整性检查；完成受控输入 → 校验 → 原生 PPTX → Artifact 的链路及取消/隔离验证。
2. **Agent 驱动完整制作**：把当前模型与工具接到上游完整 Generate，支持实际进度、确认和恢复；与上游同模型/材料/资源运行对照，确认没有丢失路径要求。
3. **模板与原稿路径**：接通 Create Template 和 Edit Native，验证复杂对象、模板母版、未修改页面/资源保留及修改范围，支持项目源包版本保存。
4. **图片/旁白/动画及工作台融合**：逐项开放通过验证的能力，连接现有素材、语音和品牌体系；浏览器只暴露已验证的编辑范围。

上游已能完成的底层功能先做复用验证，再决定是否需要 Pivot 额外实现。只有上游缺失、当前宿主无法满足或产品体验有明确收益时，才单独开发替代能力。

## 8. 本版状态与出处

2026-11-08补充：v0.7.128新增无需模型或公网的原稿编辑与页面视频路径，以源PPTX包为权威，按对象类型定点修改并保存持久版本，支持下载后再次导入。页面视频包含静态页面、明确转场及上传的本地音轨，不等于原生对象动画或嵌入视频播放。具体可编辑字段、保留范围及离线依赖见[离线部署说明](../deployment/PPT原稿编辑与视频离线部署.md)，不将此路径扩大为全部复杂对象内容可编辑。

v0.7.126 提供通用指引适配与 PPT 原生/证据/交付基础。v0.7.127 新增完整引擎的发行构建、受限运行与模型编排，接通工作台和聊天工具、确认及检查点、原生文件/模板源包交付。本机实际容器验收覆盖生成、原生形状与公式、未修改原稿页面保留及模板校验。完整文件包的接入不等于所有宿主服务已适配，也不等于所有对象已可在浏览器编辑。
