# Pivot 工作流编排产品体验升级方案

文档版本：3.0。日期：2026-10-20。方案基线：v0.7.14；工程交付：v0.7.17。状态：A—D 工程任务已落地，专项验收通过；生产用户试点经用户确认暂缓，不能视为已达业务指标。逐项实现和验证见 [交付验收报告](../reports/v0.7.17-工作流产品体验升级验收报告_2026-10-20.md)。

本方案作为本轮产品交付主方案，[技术复核](Pivot工作流编排深度复核与优化方案_2026-10-20.md)中的 F01—F10 为其正确性底线。产品设计遵守 [项目设计规范](DESIGN.md) 与 [开发规范](../../开发规范.md)，继续复用现有工作流、工具库、权限、版本和运行体系。

## 1. 产品目标与关键取舍

让业务用户从“描述要完成的工作”出发，逐步获得可验证、可复用的结果。用户应始终知道下一步可以做什么、当前内容是否已保存、测试用了哪些数据、正式运行会执行哪个版本，以及失败后怎样恢复。

本轮确定以下产品决策：

1. **默认提供业务起点。** 新建首先提供场景模板与示例结果；自然语言生成草稿和空白编排作为相邻入口，不要求先理解节点类型、变量表达式或 JSON。
2. **一份流程，两种查看方式。** “步骤”便于按顺序阅读，“画布”便于处理分支与并行。二者共用同一份 DAG、选择状态和撤销记录，不引入两套流程定义，也不要求新用户先选择简单/专家模式。
3. **参数优先选择，表达式按需展开。** 默认显示中文字段、类型和样例，插入后呈现来源标签；表达式和 JSON 放入高级设置。
4. **编辑与试验连在一起。** 节点配置、输入样例、测试结果和错误定位在当前工作区完成，避免反复打开多个弹窗和任务详情。
5. **草稿可未完成，运行必须可执行。** 自动保存不以配置完整为前提；试运行与发布继续使用严格检查。保存成功、测试通过、发布成功和自动启动是不同状态。
6. **日常使用者直接运行。** 接收已发布流程的人默认进入“填参数—查看结果”页面，编排画布作为有权限人员的入口。

目标是减少理解与操作成本。首次体验的成功以完成业务结果衡量；节点数量、画布面积和高级配置数量不作为产品成熟度指标。

## 3. 以三类用户的实际任务组织体验

| 用户及任务 | 默认看到的内容 | 必须容易完成的动作 |
| --- | --- | --- |
| 首次搭建的业务用户：根据资料生成报告 | 场景模板、需要准备的材料、示例结果 | 换材料、选已有模型/连接、试运行、拿到结果 |
| 经常维护的流程作者：替换数据源、调整判断或提示词 | 当前草稿、线上版本、最近测试、需要修改的步骤 | 选择字段、复制子图、修改后测试、比较并发布 |
| 运行和接收结果的人：执行团队已发布流程 | 发布版说明、参数表单、可见的数据范围、结果与历史 | 填参数、运行、处理待补充或审批、查看交付结果 |

高级能力在对应任务中出现：需要复杂分支时展开画布，需要排错时打开执行过程，需要原始表达式时进入高级设置。权限差异控制可操作范围，不再增加一层通用“用户模式”开关。

## 4. 信息架构与界面布局

### 4.1 工作流列表

保持现有“自动化 → 工作流”入口与全局列表样式。每行核心内容为名称、用途、发布状态、最近一次运行状态与主要动作；所有者显示“编辑”，运行者显示“运行”。最近失败可直接进入该次结果，不先要求用户查找运行 ID。

“新建工作流”打开一个轻量入口：常用模板、自然语言描述、从空白开始。模板展示用途、需要的数据、预期产出和当前缺少的依赖；依赖未配置时允许先用标明来源的示例了解流程。

### 4.2 编辑工作区

| 区域 | 常驻内容 | 按需展开 |
| --- | --- | --- |
| 顶部 | 返回、流程名、真实保存状态、线上版本、试运行、发布更新 | 版本历史、共享、导入导出等更多操作 |
| 主区域 | 当前流程的步骤或画布，当前选中节点 | 节点库在“添加下一步”时打开；复杂分支的整体结构 |
| 配置区域 | 当前节点的业务参数、上游数据入口、单步测试 | 重试、超时、失败策略、原始表达式与 JSON |
| 结果区域 | 最近测试或运行的结果摘要 | 输入、执行过程、完整表格、技术日志与耗时详情 |

在同一状态只突出一个主动作：尚缺材料时“补齐配置”；可执行时“试运行”；有效测试后“发布更新”。按钮位置稳定，仅调整强调程度；次要动作仍可访问，不能因状态变化让按钮突然消失或移动。

桌面支持流程与参数并列；中等宽度收起节点库与辅助栏；窄屏采用纵向步骤和配置区切换，输入值及选中节点保持不变。小屏提供参数填写、结果查看、审批及轻量修改，复杂布局编辑引导回桌面，不缩小整张画布强塞进手机。

## 5. 关键用户旅程与交互细节

### 5.1 第一次使用：先看到结果，再替换为自己的材料

建议首批提供三个与现有工具可匹配的模板：“资料问答”“表格分析”“批量内容检查”。模板应绑定已有节点和契约，展示可用连接，缺少依赖时在当前页选择等价项。

默认路径：

1. 选择模板，看到流程用途、步骤与一份明确标为示例的结果。
2. 选择自己的资料或当前账号可用的数据源；没有材料时可继续用示例。
3. 在必要字段中选择输入、已有模型或已授权连接；其余使用可解释默认值。
4. 点击试运行，在当前页查看结果；出错直接定位到需要补充的参数。
5. 确认结果后发布，选择需要时再配置计划或事件启动。

示例预览不冒充模型实际执行结果。使用真实模型试运行时，是否会调用模型、读取业务系统或消耗用量应在提交前简明可见。现有预览禁止副作用的边界继续有效。

### 5.2 添加与修改步骤：在操作位置给出下一步

- 从节点下方“添加下一步”打开适合当前输出类型的候选，例如表格结果优先给出筛选、汇总和报告。可用性与输入类型是明确依据，不伪装为已经建立的智能推荐系统。
- 候选先显示常用项，全部工具按需展开；不可用工具说明缺少哪项连接，并给当前账号允许的配置入口。
- 插入在线路中时展示前后关系，确认后同时更新依赖与引用。删除有下游引用的节点先解释影响；普通移动、改名、对齐、复制提供即时撤销。
- 分支使用“满足条件 / 不满足条件”“合并已执行分支”等中文标签，旁边保留查看执行语义的入口。
- 节点支持改名、复制、删除、测试等就地操作；触屏提供显式入口，不能依赖右键或悬浮。快捷键限定在可见的编辑区域。

步骤视图是同一份图的阅读投影。存在并行、互斥分支、重复汇聚和子工作流时必须保留这些结构；不能为简化界面虚构先后顺序。不适合安全投影的复杂图保留画布，并用可定位的大纲辅助阅读。

### 5.3 配参数：选择字段并立即确认取到了什么

字段默认使用中文业务名，显示类型、必填情况和一份来自所选测试样本的值。点击“选择数据”打开当前节点可访问的上游输出；候选优先显示匹配类型，其他类型可查看转换说明。

插入后显示可点击来源标签，例如“销售明细 → 明细列表”，用户可再次打开查看来源、字段路径和样例。存储仍采用原有表达式；标签视图与高级文本编辑必须无损往返。

必须补齐以下场景：

- 不兼容时明确“这里需要记录列表，你选择的是文字”，给出重新选择或受支持的转换；不静默强制转换。
- 数组、对象、数字、日期、文件各用相应控件；空值、0、false 与缺失区分处理。
- 变量删除、改名、复制或源契约改变后，在受影响参数处提示，并可定位原节点。
- 错误保留用户已填内容及编辑焦点；不通过整页刷新解决字段错误。
- 技术键名、工具 ID、原始 JSON 和并发环境变量只在高级设置或诊断中显示。

### 5.4 调试：在当前流程内完成“发现—修正—再验证”

在已有能力上统一四个入口：“测试当前步骤”“测试到这里”“试运行全部”“从失败处继续”。未接好上游的节点可填写模拟输入进行独立测试；实际提交前仍检查授权及副作用约束。

底部或侧边结果区域默认展示可读内容：表格用表格、报告用文档、文件给预览或下载入口。输入与执行过程作为相邻标签，日志按需展开。点击错误步骤同时定位节点、字段和最近失败原因。

测试来源始终可见：实际测试、模拟样本、历史复用、已过期。固定样本仅用于试验。修改布局不清空有效结果；修改配置或运行输入只使相关结果失效。旧请求返回不能恢复已经失效的结果。

“从失败处继续”只复用契约、版本、输入和授权仍匹配的已完成结果；不因方便而重复发送、写入或执行其他副作用。试运行、发布版运行与历史结果在同一结果区域内分别标明身份，不能互相覆盖。

### 5.5 保存、发布与自动启动：每一步都有明确含义

| 状态或操作 | 用户看到的意思 | 约束 |
| --- | --- | --- |
| 自动保存草稿 | 编辑进度已经保留，可以稍后继续 | 允许节点未配置完整；不改变线上版本 |
| 试运行草稿 | 使用本次输入验证当前编辑内容 | 保存身份、输入、测试来源与运行记录；遵循预览工具限制 |
| 发布更新 | 将选定草稿冻结为新的可用发布版本 | 固定目标版本与依赖；执行既有发布检查 |
| 运行发布版 | 按该账号实际可用的发布版本执行 | 参数表单、检查和执行使用同一版本 |
| 启用自动启动 | 已发布流程可以按计划或事件自动执行 | 单独显示触发器状态；不等同于发布成功 |

自动保存采用输入停顿后合并写入，拟定约 1 秒触发，最终参数经测试确定。显示“保存中、已保存、仅保存在本机、保存失败、存在冲突”的真实状态；只有相应存储确实成功才能显示“已保存”。失败可重试或导出副本，不阻断继续编辑。

发布面板说明版本、相对线上版本的关键变更、会影响的参数及计划/共享依赖，并支持查看完整差异。默认复用现有审批与发布规则，不额外为所有个人草稿增加审批。高影响更新、依赖失效或既有制度要求审阅时，明确列出需要处理的事项。

发布失败保留草稿和当前线上版本；发布已完成但触发器未启用时显示“已发布，自动启动待配置/失败”。按钮不能先显示“发布成功”再悄悄回滚状态。

### 5.6 团队复用与日常运行：让接收者少走编辑流程

共享流程的默认入口为用途说明、发布版本、参数表单和结果历史。连接或模型需映射时，在表单旁列出缺少的项目与当前账号可选项，复用既有依赖映射，不让接收者接触所有者秘密或重建工作流。

运行后先展示报告、文件或核心结果，再提供执行过程与耗时入口。缺少材料、等待审批、已完成部分结果、失败和取消分别表达；每种状态只给与当前任务相关的恢复动作。

高频流程支持收藏、最近使用与“再次使用上次参数”，但不默认复用敏感或已过期输入。初次发布和测试复用不能自动开启通知、计划或外部写入。

## 6. 系统状态、错误文案与可恢复性

| 情况 | 建议文案 | 就近动作 |
| --- | --- | --- |
| 缺少必填参数 | “还需要选择销售明细，才能测试经营分析。” | 选择数据，焦点进入该字段 |
| 字段失效 | “原来的‘明细列表’已不存在，请重新选择来源字段。” | 重新选择、查看来源 |
| 样本过期 | “上一步输入已修改，这份结果需要重新测试。” | 测试到这里 |
| 连接失败 | “销售数据库暂时无法连接，已保留其他步骤的结果。” | 检查连接、重试失败步骤 |
| 保存冲突 | “该流程已在另一窗口更新，你的修改仍保留在当前页面。” | 查看差异、另存副本、加载最新 |
| 版本参数不同 | “当前运行的是已发布版本 V3，草稿中新加的参数尚未发布。” | 查看发布版参数、返回草稿 |
| 自动启动异常 | “流程已发布，定时启动未启用。” | 查看原因、重试启用 |

错误使用“出了什么问题、影响什么、下一步怎么做”的顺序。Toast 用于短反馈，不能作为保存失败、连接问题或阻断项的唯一承载。长任务状态来自服务端，刷新页面后仍可恢复查看。

视觉与交互遵循统一样式：克制字号、清晰选中、主题变量、可读对比度、键盘可达；状态同时使用文字与标识，不只靠颜色。遵循减少动态效果偏好，运行中不持续闪烁整张画布。常用操作目标按触屏需求保留约 44 像素有效点击区域，不以缩小字体解决拥挤。

## 7. 产品验收：用任务完成验证方便程度

### 7.1 首轮试点目标（生产阶段暂缓）

以下是待实测的产品目标，不是当前成绩或对外承诺。用户已确认真实业务需在生产环境完成，本轮暂缓试点。后续先采集基线，再用相同任务比较；工程回归不能替代这些业务实测。

| 任务 | 初始验收目标 |
| --- | --- |
| 新用户用内置示例完成一次结果预览 | 中位时间不超过 5 分钟，无需查文档或填写 JSON |
| 6—8 名代表性业务用户完成首次模板任务 | 至少 80% 无主持人代操作完成；样本仅用于发现问题，不作为统计性证明 |
| 给模型输入绑定一个上游字段 | 从字段入口到插入来源不超过 3 次选择动作，不计输入搜索词 |
| 修正一个失效字段并再次验证 | 问题在当前页可定位、可修正、可重试，不丢失其他已填内容 |
| 编辑未完成草稿后刷新或关闭再打开 | 已确认保存的修改可恢复，保存失败状态不会误显示为成功 |
| 修改草稿并运行线上流程 | 线上参数、版本和结果不被草稿污染 |
| 恢复一次允许局部重跑的失败 | 不重做无关成功步骤，不重复已经提交的副作用 |

### 7.2 必做的用户验证

采用三个固定任务：“用模板生成结果”“增加筛选或条件并改字段”“从一次错误中恢复并发布”。记录完成率、耗时、错误入口、回退次数、求助点与操作后信心；不要只问是否喜欢界面。用至少一位没有编排经验的人测试全部默认路径，并让日常运行者验证发布表单。

用已有真实浏览器测试补齐桌面、1024、768、390/320 像素宽度，以及深浅主题、键盘操作、慢网、保存失败、冲突、权限不足、连接失效和长结果。UI 响应目标为普通输入、选择和拖动在约 100 毫秒内给出反馈；复杂验证和运行使用异步状态，不以伪造完成度代替实际进度。

遥测仅记录经许可的操作事件、耗时及错误类型，不默认采集资料正文、参数值、密钥或模型输出。没有可靠基线时，先报告实际观察，不计算虚构的提效百分比。

## 8. 按可感知的产品闭环交付

| 批次 | 用户可以完成什么 | 主要范围 | 上线门槛 |
| --- | --- | --- | --- |
| A：第一次就能用 | 从模板获取示例，换入自己的材料并在当前页看到结果 | 新建入口、常用字段、目标版本参数、就近错误、可靠保存状态；优先修复 F01—F05 与保存去重 | 关键任务可独立完成，版本与数据不串用，既有权限边界通过回归 |
| B：修改和排错顺畅 | 选择字段、局部测试、保存未完成草稿、恢复错误与冲突 | 来源标签、输入输出预览、样例复用、草稿恢复、对齐与撤销、F06—F09 | 用户能在当前工作区完成一次修改—排错—再次验证—发布 |
| C：团队日常运行 | 接收者直接填表运行，作者能确认发布和启动状态 | 运行表单、依赖映射入口、结果优先、版本影响说明、触发状态恢复 | 接收者无需学习画布；发布与实际运行身份可追溯 |
| D：复杂流程与效率 | 多分支和长流程易阅读，短支线不被无关慢节点阻挡 | 分组与大纲、子流程定位、F10、按实际流程测量执行耗时 | 审批、延时、失败停止、取消、预算与恢复语义不变 |

每批交付一条可演示的用户路径，并用任务完成数据决定下一批细节。F01—F10 修复可拆分并行排期，但首批验收不能仅展示新外观而遗漏正确性约束。具体工期需根据前后端投入、草稿存储设计与试点结果估算。

AI 辅助生成与自然语言修改作为可插拔增强：先展示计划、变更范围和缺少的依赖，应用后成为可撤销草稿。不得把“生成了图”显示成“运行成功”，也不能直接发布、绑定所有者秘密、启动计划或扩大已有权限；不可用时模板与手工编排仍完整可用。

## 9. 技术接线与兼容策略

| 产品能力 | 复用位置 | 必要补强 |
| --- | --- | --- |
| 工作流列表、新建与版本 | `agent-workflows.js`、`agent-workflow-library.js`、`agent-workflow-versions.js` | 业务模板入口、可靠状态与保存上下文；规范化比较 |
| 步骤/画布与就地操作 | `agents-dag-editor.js`、`dag-render.js`、`dag-interaction.js` | 同一 DAG 的阅读投影，引用安全的复制删除，工作区键盘作用域 |
| 参数与来源选择 | `dag-inspector.js`、`dag-variable-picker.js`、`dag-readiness.js` | 类型、样例、来源标签和无损表达式编辑；共享引用解析 |
| 测试与结果区域 | `dag-inspector-testing.js`、现有运行详情与瀑布图 | 测试身份、失效提示和结果合并展示，复用局部重跑 |
| 草稿、发布与运行输入 | 现有工作流资产、版本、预检与发布服务 | 草稿修订与不可变发布快照明确分开；表单按实际目标版本生成 |
| 团队运行 | 共享可见性、发布版本与依赖映射 | 接收者默认运行表单，复用现有连接与授权选择 |

未完成草稿的保存不能通过放宽现有运行版本校验实现。应为现有资产增加明确的草稿修订语义，保存时允许编辑期问题；发布快照继续经过归一化、契约、权限和版本冲突检查。自动保存合并写入，不能把每次按键都变成正式版本。

所有新增数据字段同时设计迁移、旧数据读取、恢复和撤回策略。新增试运行界面与运行表单复用统一执行链路，不能另建一个绕过预算、审批、预览限制或共享访问控制的执行器。
