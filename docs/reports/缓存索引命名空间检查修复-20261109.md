# 缓存索引命名空间检查修复

版本归档：[v0.7.138发布汇总](../releases/v0.7.138-智能体执行与交付验收可靠性升级.md)。该修复与执行链路升级共同纳入本版本，以下测试结果保留原始验证口径。

本次针对[19项复测](19项失败用例复测-20261109.md)中唯一仍失败的缓存迁移用例，修复迁移结构检查和BI运行就绪检查对同名索引的误判。

## 变更

`analysis-model-result-cache.js`和`analysis-model-readiness.js`现在同时限定当前命名空间的索引、当前`analysis_query_jobs`表及索引有效状态。当前表缺少索引，或同名索引属于其他表时，不能借`search_path`中的后备对象通过检查。

沿用已有`format('%I.%I', current_schema(), ...)`命名方式处理标识符引用；没有新增依赖、配置、迁移编号或数据库字段。已登记迁移仍由既有迁移运行器校验，缺失正确索引时重新执行幂等建索引；同名索引挂在错误表上时拒绝就绪，不自动删除未知对象。

## 回归

增强原有PostgreSQL用例，在一个回滚事务中主动创建后备命名空间和同名有效索引。分别验证：

- 当前索引正常时通过；
- 删除当前索引后，即使后备同名索引存在，迁移检查返回false、运行就绪检查拒绝；
- 重复执行建索引后恢复就绪；
- 当前同名索引属于错误表时仍拒绝；
- 修复后后备索引的对象标识不变，没有误改其他命名空间。

测试在产品修复前确实失败、修复后通过。测试使用既有连接作用域，让两处真实SQL在同一事务和`search_path`中运行，不模拟数据库判断，不依赖本机`public`索引是否存在。
