# 中文语音识别企业化改造验收记录

日期：2026-10-20。面向 Ubuntu、无法连接互联网、4 张 2080 Ti、256 GB 内存及独立局域网语音服务器的部署条件。

## 已完成的代码与交付物

- Pivot 服务端提供统一的本地、内网网关、音频转写兼容 API 与 Qwen 音频接口适配；目标地址、模型、热词和密钥由管理员配置，客户端不能指定任意出站地址。
- 默认仅允许内网，公网服务需要显式启用并使用 HTTPS；请求固定解析后的地址，禁止重定向、URL 凭据与敏感目标，密钥不返回页面。
- 网页和桌面在配置统一服务后优先使用相同引擎；主服务失败明确提示，不静默切回系统识别。统一采集要求受信任的 HTTPS 或本地安全地址。
- 可选双遍流式通道通过短期单次票据和当前登录态代理，账号在连接与每句开始前复核；临时识别不提交，句末结果才可进入实时对话。
- 前端累计保留已成功启用的回声消除、降噪、自动增益和单声道设置，优先让 Web Audio 在 16kHz 下处理；具备句首缓冲、连续起录、瞬态抑制、中文句末等待与有界背压。
- 句末识别期间继续保留有限录音，点击完成时立即释放麦克风，再处理已录入的下一句；取消、切换与迟到回调不会重新使用旧音频或关闭新连接。
- 独立 Python 网关常驻加载本地模型；FunASR 流式 Paraformer + SeACo Paraformer + 标点组成双遍识别，Silero VAD 在最终识别前过滤无语音。Qwen3-ASR-1.7B 提供独立的句级精度候选。
- 两遍数字分歧、上游低置信度或音频削波进入人工核对，不自动补写金额、人名或条款编号。模型不提供置信度时保留未知值。
- HTTP 与流式通道共用每用户/每实例容量保护，模型实例使用独立锁；具备超时、错误熔断、音频长度和消息大小上限，日志不记录音频与转写正文。
- 新增离线 wheels/模型准备与 SHA-256 清单校验、独立 Dockerfile/Compose、GPU 叠加配置、基础 VAD 探针和中文现场语料评测工具。

部署步骤、配置、反向代理与验证边界见 [中文语音服务离线部署与验收](../deployment/中文语音服务离线部署与验收.md)。新增生产依赖 `ws` 用于双向音频分片与停止控制，版本已锁定并登记许可。

## 主容器内置 CPU 语音与真实模型验证

按后续确定的部署方案，中文双遍识别已集成到 Pivot 主镜像，标准 Docker 默认使用 `embedded`。主容器由 Node 管理一个 Python 3.12 常驻子进程，加载 SeACo Paraformer、流式 Paraformer 和 CT-Transformer 标点模型，使用 CPU；HTTP 与双遍流式复用相同模型实例和推理互斥锁。无需另起语音容器，无需语音 GPU，也无需管理员填写内部地址或共享密钥。

主镜像包含离线准备的 CPU 版 `torch==2.8.0+cpu`、`torchaudio==2.8.0+cpu`、FunASR、Silero VAD、FastAPI/Uvicorn 等依赖；构建时不联网安装这组包，并检查没有 CUDA 运行时。默认不安装 Qwen-ASR 包，外部 Qwen API 调用继续由 Node 协议适配器提供。现有离线 wheelhouse 共 85 个 wheel，约 385.6 MiB，文件摘要记录在 `artifacts/speech-assets-manifest.json`；其中包含准备过程中保留的两个 WebSocket wheel 版本，安装使用清单固定的 17.2。

内置进程采用随机回环端口和临时密钥，禁止公网端点覆盖，默认 CPU/BLAS/Numba 线程上限为 4；启动预热不阻断主应用文字服务。具备并发预热去重、启动超时、退出冷却、单个请求取消隔离、幂等停止、父进程退出监测和强制回收期限。只读根文件系统下，必要缓存放在临时目录，不保存录音与转写正文。首次模型加载默认允许 180 秒，避免冷启动时限过短。

实际 `.env` 已选择 `embedded`，项目 `data/speech-models/` 已放入三个完整目录，33 个文件再次通过上游 SHA-256 校验。主 Compose 使用 `./data/speech-models:/models:ro`，仅发布主应用端口。选择 `gateway/openai/qwen` 后不启动内置模型，可调用其他内网服务器；源码和桌面环境未显式选择新模式时保留旧 `local` 默认值，标准主镜像与主 Compose 的默认值为 `embedded`。
