# Windows 客户端中文语音修复验收报告

版本：v0.7.3；日期：2026-10-19。

用户报告两个语音入口都被浏览器中文本地识别检查拦截。复查确认此前缺少独立桌面实现，本次新增 Windows 系统识别通道，保留浏览器通道并按运行环境自动选择。

## 验证范围

| 检查 | 结果与证据 |
|---|---|
| 本机真实系统引擎探测 | 已安装 `MS-2052-80-DESK`，语言 `zh-CN`；通过产品识别代理的能力接口读取 |
| 原生识别实测（合成文件） | 真实加载中文 DictationGrammar，将本机生成的 WAV 输入 Windows 引擎，得到“你好这是一个本地语音特许”；音频原文是“你好，这是一个本地语音测试。”，存在末词识别错误，不能宣称准确率达标。未打开麦克风，也未上传音频 |
| 服务生命周期与授权 | 定向测试覆盖隐藏进程、固定脚本与参数约束、进程归属、取消探测竞态、启动失败及 IPC 拒绝 |
| 客户端路由 | 模拟浏览器中文包不可用且语言标识错误，自动使用桌面 `zh-CN`，不调用浏览器识别接口 |
| 两种页面路径 | 浏览器路径与桌面桥路径分别验证两个按钮、两轮文本模型请求、本地朗读及停止 |

全量通过后对异常信息收敛及非 Windows 的浏览器回退保护进行了最终定向复验；不将工程检查当作真实麦克风的识别质量验收。

## 限制与交付

本机上一轮探测没有可用麦克风输入，本轮使用明确的合成 WAV 检查真实引擎，不将其冒充真人发音、实时音频设备或扬声器听感验收。识别质量由系统语言引擎决定，合成测试已保留实际错误。

新增原生桥必须随新版桌面程序安装，服务端更新只能更新页面。没有发布、自动安装或重启用户客户端，也没有改变系统的麦克风授权或语言设置。

实现复用微软公开的本地引擎 API，参见 [SpeechRecognitionEngine](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine?view=netframework-4.8.1)。
