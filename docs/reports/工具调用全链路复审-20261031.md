# 工具调用全链路复审

日期：2026-10-31。基线：v0.7.76 工作区及本次未提交修复。

## 结论

工具发现、权限执行、MCP 传输和产物交付均有现成实现，但入口之间存在信息丢失和结果处理不一致。不能据“单步测试成功”判断会话任务全链路可用，也不能据本次定向测试宣称全部场景已完善。

本次修复了明确选择工具的交接与混合连接问题、续接时丢失已选工具能力、任务编辑器误传空授权、MCP 业务失败被记为成功，以及渐进式执行重复处理产物的问题。工作区版本已更新至 v0.7.77；未修改生产服务，未构建发布镜像。

## 核查路径

1. `client/chat/chat-auto-route.js` 将列表选择转换成 `routeOverrides.tools`；输入框中的展示文字不是工具标识。
2. `chat-preflight` 清理请求，聊天路由判断是否进入自动任务；`chat-agent-handoff` 创建持久任务。
3. `agent-tool-catalog` 按账号可见性和治理状态建立目录；`agent-tool-discovery-scope` 叠加任务、会话和 Skill 范围。
4. `tools.search → tools.describe → tools.execute` 使用目录版本与摘要验证引用，执行前重新读取目录。
5. 统一策略引擎和编排器检查输入、能力、审批、重试与资源限制；MCP 客户端再次检查服务状态、工具缓存及治理权限。
6. 外部 MCP 请求继续经过任务 Origin/端口策略、连接可见性、SSRF 与 DNS 检查，不能仅凭选中工具绕过这些检查。
7. 工具输出经业务错误判定、输出契约验证、产物生成、验收和授权下载。

## 后续开发已落实（同日续改）

1. **不使用 `@` 的自动调用**：明确任务路由给出的真实工具名进入同一选择校验；未指定具体工具时，按已授权能力和用户目录生成 `mcp_endpoints` 工具到登记端点的映射。适配器只对匹配的工具和完全一致的端点建立单次 Origin/端口策略；普通 HTTP 工具不能借用此映射。服务变更、撤权和 SSRF 检查仍可拒绝调用。
2. **运行中更换工具**：`continue_run` 接收本轮 `routeOverrides`，重新校验工具后，以元数据 CAS 同步修改 `tool_policy`、`tool_allowlist` 和 `network_policy`。比当前修订更旧的消息被拒绝。发现、规划和实际调用前重新读取范围；旧快照不能继续调用被替换的工具。授权修改先持久化，再投递带幂等键的控制消息，投递中断可以重试。
3. **候选覆盖**：候选先受手动白名单过滤，再按明确选择、当前目标相关性和原目录顺序排序。显式选择优先保留，通常只传 24 项；多项显式选择最多保留 100 项。部分目录仍会明确标注，不保证模型每次都能正确识别业务意图。
4. **空搜索停止**：同一目标、同一目录版本和同一用户修订中累计四次空搜索即暂停为 `needs_input`。更换关键词或得到无关候选不清空计数；业务执行成功、目录变更或用户修订后重置。普通及流式真实运行器均已验证会暂停，不继续预算消耗或自动修复循环。
5. **审计诊断**：JSON 和 Markdown 审计包加入请求目标工具标识、错误码和已有策略拒绝原因。只投影允许字段，不导出本次新增诊断中的业务参数、自由文本和凭据。HTTP 测试验证所有者可见、其他账号拒绝及测试秘密不出现在导出中。
6. **系统 MCP 别名**：当前可见、通过治理的系统服务别名可映射到对应内置工具。外部服务不按短名映射，数据库继续固定连接；映射失效时拒绝，避免名称碰撞扩大执行范围。

## 验证边界

上述已识别的代码缺口均有实现和回归证据。生产端 Linux、Kroki、真实模型的完整会话到图片下载验收仍需部署后执行。模型意图判断可能需要澄清；目录变化、凭据失效、工具审批或网络限制引起的拒绝仍是正常运行边界，不能承诺所有请求自动成功。

## 现场验收

主程序更新后，用普通账号从列表选择真实绘图工具，确认搜索、描述和执行使用同一工具标识；生成 SVG 产物，并验证预览与下载。再验证非法 Mermaid 报失败、取消授权后调用被拒绝、混合选择不丢失目标工具、续接保持原选择。无需重建已经单步测试成功的 Kroki 服务来代替主程序更新。
