# 工具输入契约修复与任务连续性

日期：2026-11-04，承接 v0.7.87 工作区改造，未部署或打包。

## 原因与处理

此前输入契约错误统一包装为 `TOOL_POLICY_DENIED` / `AGENT_POLICY_DENIED`，只返回第一条错误。诊断优先匹配策略类别，建议申请放行；普通和流式任务同时把参数错误算作连续业务工具失败，模型可能在修复参数前就触发错误上限。另有共享校验器把必填字段中的空文本视为缺失，即使契约未声明最短长度。

本轮将纯参数错误分类为 `TOOL_INPUT_INVALID`（HTTP 400），记录 `executed:false`、具体字段问题和有大小上限的输入规则。反馈不附带原参数、默认值或示例，契约过大时明确标记截断并提示读取工具契约。原样自动重试关闭，由规划器依据反馈重新提交修正输入；未知字段、越界值和错误类型仍不能直接执行，不自动猜填业务事实或删除多余业务参数。

Agent 策略、统一工具入口和编排器使用同一错误类型。输入错误合并任务范围等拒绝时仍作为策略拒绝，不授予参数修复豁免；修正输入后继续完整检查目录、来源、连接、审批、路径、网络、沙箱与预算。只有本进程执行前创建的参数错误实例进入修复路径，业务工具抛出的同名错误不能凭字符串取得豁免。

普通与流式任务将字段问题和契约返回模型，参数修正消耗正常规划轮次和实际模型用量，不挤占业务工具连续失败额度，也不算新进展。现有无进展上限、单段/累计轮次、工具和活动时长上限继续生效；达到上限后沿用受限答复与来源核验。概念和写作可给模型答复或文本草稿，内部数据、文件和外部操作不以文字冒充完成。固定工作流仍使用节点配置的失败策略，不自动改写工作流业务映射。

必填字段改按存在性校验；空文本仍会受到类型、枚举、正则和明确 `minLength` 约束。该修正应用于共享契约校验器，输入和输出规则保持一致。
