## 定位证据

- 服务启动期间没有数据集上传，也没有 PostgreSQL 查询或锁等待。诊断栈停在 Node CommonJS 模块路径解析；临时模块计时观察到多个普通依赖各耗时数秒。服务健康后关闭计时，再运行浏览器测试。
- 分离启动等待后，仍出现约 169 秒的 XLSX 请求，说明不能只把剩余超时归因于服务启动。
- SQLite 请求约 1.1 秒，没有出现同等级耗时。接下来如修复 XLSX 性能，应分别计量工作线程初始化、工作簿解析、Parquet 写入、线程退出及字段画像，现有日志不足以将 169 秒精确分配到这些步骤。
- 本轮不扩大超时、不跳过断言、不修改业务实现。使用现有单线程 DuckDB、128MB 预算；本机可用内存在约 0.7–1.3GB 间波动。
