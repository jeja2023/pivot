## 导出视觉核验

初次生成 PDF 的可复制文字完整，但 Poppler 页面存在缺字。定位到默认 CJK 可变字体的 TrueType 复合字形子集，先实例化 wght=400 后再子集嵌入，页面中文字、数字、密级标识恢复完整。新增渲染器版本 `pdf-1.2.0`、`docx-1.2.0`，避免历史 rendition 去重误用旧版字节。

普通与红头 PDF 实际页面均检查；DOCX 用本机 Word 导出 PDF 后检查，内容无重叠、缺字、越界，落款、双日期、抄送和版记完整。Word 与 PDF 使用各自字体/布局，DOCX 预览标为参考，不承诺跨软件像素一致。标准 `render_docx.py` 因缺少 LibreOffice 不能执行，使用已安装的 Word 完成替代核验。

前端预览不能依靠模板内 iframe：工作区安全净化会移除 iframe，而且现有 CSP 不允许 blob frame。本次采用已有 PDF.js 固定入口及 canvas 页渲染，不扩大 HTML 净化与 CSP 权限。最多预览 20 页，下载仍包含全部页面。

## 受控体积基准

18 万汉字材料、8 次短正文历史：旧状态 **4,860,885 字节**，新状态 **1,081,600 字节**，降低 **77.75%**。历史材料只存一份；10 篇摘要约 **2,050 字节**。本机 20 次归一化中位数约 **8.51ms**、P95 约 **15.46ms**，仅作为可重复样例，不代表生产吞吐。

## 数据与部署边界

- 迁移增加 `summary JSONB` 与 `artifact_id`，当前公文正文不重写。新客户端摘要分页，兼容旧列表读取；旧客户端写入升级格式文档被拒绝并提示刷新。
- 产物绑定由服务端事务维护，JSON 备份与导入不会继承其他公文的绑定。旧全局缓存不会迁移进新账号。
- 历史按预算保留最近记录，裁剪不触及当前正文和材料；不适合把应用内历史作为唯一归档，重要稿请备份。
- 材料解析复用文档处理执行器，扫描件需要可用的外部 OCR 服务。真实 OCR 质量、业务事实、组织格式规则、目标打印机及全部 Windows 输入法仍需现场核对。
- 本次仅更新源码与版本文档，没有启动对生产环境的部署、安装包发布或 Git 推送。
