## 首次失败与修复

1. 初次新增浏览器用例用 APIRequestContext 直接发写请求，被现有 CSRF 防护返回 403，未进入模板工具校验。改用页面既有 `apiFetch` 后，错误工具在业务校验中返回 422，保留原 CSRF 防护。
2. 并行全盘 `eslint .` 扫描期间，曾出现目录加载超时和原技能发布验证超时；该扫描进程内存约 2GB。停止全盘扫描后串行重跑三项浏览器用例全部通过，未放宽业务请求或验证超时。新模板目录等待与原目录测试一致使用 15 秒。
3. 首次通用检查在 Mermaid 资源检查进程异常退出；单独重跑原命令通过，随后整条 `npm run check` 串行重跑返回0。原始退出情况保留，不归因于模板功能，也不以单项重跑冒充整条检查通过。
