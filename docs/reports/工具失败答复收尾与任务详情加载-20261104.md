# 工具失败答复收尾与任务详情加载

日期：2026-11-04。承接 v0.7.87 工作区改造，未构建安装包或部署生产。

## 问题与改造

截图中的直接故障是 `tools.execute` 引用缺少 `toolRef.toolName`。旧版本会重复提交错误引用，再被重复调用规则提前终止；当前工作区上一批已移除机械三次停止，但缺失工具引用及无进展后的收尾还需修复。

- 统一归一化 `toolName`、`tool_name`、`name`、`fullName` 及受限嵌套引用；空引用不遮蔽明确名称。名称冲突仍拒绝，版本/摘要继续严格核对。没有明确目标时返回 `executed:false` 与可操作说明，不能根据单个候选静默执行业务。
- 无进展、连续空搜索或连续工具失败时，结束工具循环并进行一次有时限的答复收尾。概念和写作可以基于模型知识回答；要求文件时可先给文本草稿。内部依据或数据缺失、外部操作无法确认时，返回明确缺口，不编造事实、下载文件或操作成功。
- 已取得的知识片段先复核当前来源，再对受限答复做引用配对与确定性检查；撤权或核验失败时隐藏不可信事实。取消、暂停、租约失效、权限阻断不作为调用工具的降级授权。结果标为部分完成或待处理，原任务验收要求不降低。

任务详情原本在首屏等待步骤、节点、调用实例、Trace、检查点、验收、证据、事务、工作记忆、提示词记录及浏览器证据等多类数据，同时多次重复读取来源。新的默认 `view=overview` 只读取核心信息、最近 100 条步骤及至多 100 个节点，限制单字段体积，保留核验快照和按需诊断入口。长输出显示延后读取说明；完整详情端点继续兼容，核心记录失败仍返回错误，可选诊断失败/超时则单独提示。

前端在模块准备阶段显示加载提示，模块等待上限 15 秒、详情请求上限 12 秒，完整详情各读取部分上限 6 秒；这些是等待控制，不保证目标网络或数据库总能在该时间完成。关闭/切换任务会取消旧请求，迟到结果不得覆盖新任务。来源检查只在同一 HTTP 请求内合并，不跨请求复用授权，当前用户和来源校验仍在核心数据返回前执行。

## 验证与边界

新增测试覆盖引用归一化、未执行修复、模型答复/文本草稿、无内部依据拒答、来源变化、取消和核验故障；真实隔离 PostgreSQL 配合本地模型服务测试普通/流式运行器空搜索后的答复；详情测试覆盖大输出限制、用户隔离、禁用账号及可选诊断超时。真实 Chromium 检查加载提示、重试、取消、完整视图、迟到响应和错误文字转义。

完整链路入口：

```powershell
node scripts/verify_tool_knowledge_chain.js --isolated-postgres --report output/tool-knowledge-chain/20261104-capability-gap-detail-final.json
```

报告保留当前源码指纹、通过/失败/跳过计数和环境；模型服务及故障场景包含测试桩，不等于目标生产模型质量和性能验收。项目通用检查、Lint、类型及规范结果单独核对。本轮保留工作区同时出现的附件/消息样式改动，不将其算入本次工具和详情改造；增量规范中附件样式硬编码颜色的问题需在对应改动中处理。

最终结果：160 项单元、77 项隔离 PostgreSQL 集成、45 项恢复/网络、5 项 Chromium 浏览器测试，合计 287 项全部通过，无失败或跳过；验证前后源码指纹一致，报告与当前实现匹配。项目通用检查、ESLint 零警告、类型检查、文本完整性、SQL、异步调用与架构治理通过。增量开发规范仍报告 `client/chat/styles/base/attachments.css` 中 5 处硬编码颜色，这些属于本轮过程中出现的并行样式改动，本轮未修改或回退该源文件。

部署需要更新并重启服务、重新加载客户端。旧进程仍可能产生旧的“三次重复”提示，历史任务日志也不会自动改写。没有现场环境，真实业务任务、外部工具、模型回复质量及实际详情耗时仍待复核。
