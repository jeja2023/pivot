# 语音功能版本对比与优化验收

日期：2026-10-19。修复归属：v0.7.12。范围：实时语音、语音输入、Windows 原生识别与浏览器部署内识别。本文保留 0.7.10 与 0.7.11 的历史对比；完整版本范围见 [v0.7.12 发布记录](../releases/v0.7.12-工作流瀑布图与语音续跑修复.md)。

## 0.7.10 与 0.7.11 的实际差异

对比基线为 `75c2cee9`（0.7.10 发布）与 `2c2144ee`（0.7.11 发布），另行检查发布提交之后的插话实现，区分正式版本差异与后续修复。

| 项目 | 0.7.10 → 0.7.11 发布提交 |
| --- | --- |
| 识别引擎与选择顺序 | 未变。仍优先桌面 Windows 系统识别，再尝试部署内识别、浏览器本地识别 |
| 语音输入逻辑、PCM 编码、服务器录音分段 | 未变 |
| Windows 识别脚本、服务器识别模型 | 未变 |

| 朗读语言 | 从浏览器语言改为已选本地声音的实际语言 |

## 已定位的问题

1. 修复前的插话实现会在中间识别结果出现时立即取消朗读与模型请求，仅用精确文本匹配屏蔽回声。回声中出现同音错字、漏字时，容易被当成新问题。这能解释未读完就中断和自问自答造成的体验下降；无法仅凭源码判断用户现场的声学识别准确率。
2. 既有朗读队列对单段文字使用 `slice(0, 2000)`，超出部分丢失；最终全文比流式文本更完整时没有补齐尾部。
3. 0.7.11 的启动看门狗依赖 `onstart`。部分声音事件异常但实际正在播放时，可能误结束整场语音会话。
4. 语音输入的普通停止与取消未充分区分。浏览器停止时应允许最后识别结果返回；Windows 旧原生停止直接杀进程，会丢掉尚未提交的尾句。浏览器音频线程不足 2048 采样的一块也未在停止时排空。
5. 部署内识别使用固定 0.008 能量阈值及约 700ms 句末静音，可能漏掉较轻的声音或在自然短停顿处提前分段。Windows 识别采用系统默认句末静音阈值，未对中文听写调节。

## 本次修改

- 临时识别结果只更新识别状态，最终确认的新话才中断回复；回声比对容忍少量错字、漏字及跨朗读分段结果，保留纠正、否定等明确的新意图。
- 保留生成中和朗读中的插话能力，停止旧请求、清空旧播放队列，忽略旧回复的迟到内容及取消回调。
- 长回答拆成不超过 120 个 UTF-16 单元的短段，保留全文及代理对；最终全文只补齐新增尾部，重复完成事件不重读。连续播放在上一段结束后调度下一段。
- 播放启动观察延长到 15 秒，实际仍在播放或等待播放时不因缺少 `onstart` 误报故障；没有新增回答朗读总时长上限。
- 完整识别到“退出”“退出实时语音”“关闭语音”等命令时，本地结束实时语音，取消模型请求、清空临时上下文和播放队列、释放麦克风；不把退出命令发给模型或后台任务。
- 语音输入点击完成时使用收尾流程，最终文字返回后再清理；页面关闭、切换语音模式、退出实时语音仍立即取消。英文分段保留必要词间空格。
- 浏览器录音停止前取回音频线程的尾包，并等待已排队的转写，不因第一段结果返回而取消第二段尾句。取消后仍丢弃迟到结果。
- 部署内采集保留约 400ms 句首预录，降低低音量触发门槛并按低噪声底调整，句末静音延长到约 950ms。默认麦克风采集成功后再尝试回声消除与降噪；不支持增强参数的设备仍可使用原轨道。
- Windows 桌面与服务器识别的句末静音改为 850/1200ms。桌面原生工作进程支持 `finish`：先完成缓存音频的识别再结束，并保留原来的立即取消通道。新 IPC 与旧页面/客户端通过可选接口兼容。

浏览器停止与取消的区别参考 [SpeechRecognition.stop()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/stop)。Windows 两项句末静音默认值分别为 150ms 和 500ms，属性用于控制确认一句话前的等待时长，参考 [EndSilenceTimeout](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.endsilencetimeout?view=netframework-4.8) 与 [EndSilenceTimeoutAmbiguous](https://learn.microsoft.com/en-us/dotnet/api/system.speech.recognition.speechrecognitionengine.endsilencetimeoutambiguous?view=netframework-4.8)。这些参数调整不等同于升级声学模型。

## 验证与实际限制

- 53 项语音相关测试通过，覆盖最终/中间结果、错字回声、长文全文、尾部差量、重复完成、退出命令、资源释放、低音量 PCM、800ms 停顿、停止尾包、排队转写、桌面收尾权限及旧响应隔离。
- Windows 真实中文工作进程测试在内存中合成固定中文音频，运行实际原生工作脚本，分别检查自然结束与发送 `finish` 两条路径；均得到 `started → result → ended`，未打开麦克风或播放声音。
- 另用同一段带 500/600ms 停顿的中文合成语音对比 Windows 默认参数与新参数：原先返回两段，新参数返回一段完整文本；两者都有同一处识别错字。这证实了分段变化，没有证据证明整体字错率提升。
- 变更文件 ESLint、开发规范增量门禁、`git diff --check` 与项目 `npm run check` 通过。
- 尚未用用户的实际麦克风、扬声器和说话环境做对比录音。纯文本回声比对无法可靠区分所有同音错字或与回答高度相似的真实插话；最终字词准确率仍取决于已安装识别引擎与声学环境。

## 生效范围

网页代码及部署内识别改动需更新服务端并重新加载页面。Windows 原生工作进程、句末参数及尾句收尾 IPC 需重新构建并升级桌面客户端，仅刷新网页无法更新这些组件。修复已归入 v0.7.12 源码版本；没有更换识别引擎、新增数据库迁移或启用外部语音服务。当前交付未生成安装包或部署服务。
