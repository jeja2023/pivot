## 检查结论

在前两轮工具发现修复基础上，本轮继续检查对话理解、任务创建与续接、工具目录、契约、策略、审批、预算、执行恢复、验收、事务收尾和结果展示。检查发现了新的实际堵点，并补充代码修复和可重复测试。

本报告的“通过”指列明的场景和检查条件。它不等同于所有生产模型、所有第三方 MCP 服务或所有复杂任务均已验收。生产故障记录尚未提供，本轮没有连接、重启或变更生产。

## 本轮发现与修复

| 环节 | 修复前行为 | 本轮处理 |
| --- | --- | --- |
| 普通 JSON 规划验收 | 执行器未注入持久化验收入口，任务可能显示完成而事务仍为 executing | 注入与流式入口相同的持久化验收，真实运行验证事务最终 committed |
| 任务续接与长资料 | 新决策替换能力集合时可能丢失 conversation.read_source | 保留当前任务绑定的来源读取能力，不保留已撤回的旧业务写入能力 |
| 数据库工具身份 | 目录将具体 MCP 数据库工具投影为 db.*，策略却只认可具体白名单字符串 | 在任务与 Skill 两层匹配实际连接，目录与 Schema 同步缩窄；另一连接仍拒绝 |
| 需要审批的内置/API 工具 | 预检查主要处理 MCP 与 alwaysRequiresApproval，可能由后续策略抛出审批错误但未正确暂停 | 审批预检查使用同一策略判定，保持拒绝与等待审批边界一致 |
| 普通执行审批恢复 | 步骤号变化后审批键变化，可能重复要求审批 | 恢复同一已批准操作的键，并继续绑定参数、有效期和运行身份 |
| 单次授权 | 审批有效期内可能再次用于相同工具参数 | 完成后记录 consumedAt；再次操作申请新授权，rememberForRun 保留显式选择的语义 |
| 新任务审批上下文 | 调用方元数据或父任务元数据可能带入审批记录 | 新运行删除审批授权及恢复中的授权指针，只由服务端审批决定写入 |
| 包装层预算 | 普通 tools.execute 与内部业务工具重复扣调用次数及风险 | 业务执行在目标工具记账；缺契约的读取恢复单独记账；批处理中每个目标继续记账 |
| 元工具检查点 | 重放旧搜索/描述输出不能重建新的运行发现状态；路由包装层可能产生非幂等恢复审批 | 内置发现元工具重建当前状态；实际业务工具继续使用持久检查点 |
| 无参数工具 | tools.execute 的输入 Schema 允许省略 input，预检查却拒绝 | 省略时规范化为对象；数组、null 等无效输入仍拒绝 |
| 输入摘要 | JSON 键顺序变化可能导致同一参数的审批/检查点匹配失败 | 使用稳定键顺序，并兼容旧检查点和旧审批摘要 |
| 运行中撤回 | 发现步骤可能使用执行器旧会话能力快照 | 发现前重新检查当前授权；暂停、撤回或来源失效时停止读取目录 |
| 内部交付缺口 | 资料未读完、文件未生成或输出格式问题直接进入等待用户状态 | 在剩余轮次和预算允许时最多继续修复两次，事务保持可执行，最终仍须验收 |

有限修复不覆盖来源撤回、业务事实缺失、验收服务不可用或预算不足；也不会直接重放已完成的发送、写入或外部提交。外部副作用仍受审批、检查点和事务提交约束。

## 完整运行验证

新增 `agent-full-run-discovery.test.js` 启动本地 HTTP 模型测试服务，并使用真实模型访问层、运行创建工厂、普通 JSON 规划器、原生工具流式规划器、工具运行时、PostgreSQL 检查点、验收器和事务完成逻辑。

两种模式均按以下流程验证：

1. 模型直接请求 tools.execute，并省略无参数工具的 input。
2. 运行时先返回当前工具契约，`executed:false`，没有执行业务工具。
3. 模型下一轮再次明确调用，实际查询 models.list 一次。
4. 模型第一次最终答案缺少验收要求，运行时继续内部修复。
5. 模型补齐结果后通过验收；运行 completed、事务 committed，只有目标业务工具的持久执行检查点。

测试只使用本地模型协议服务和只读内置查询，未调用生产模型、第三方服务或发送外部业务消息。它验证执行流程，不代表真实大模型总能作出相同决策。
