# 离线绘图任务验收与预览修复

日期：2026-10-31。问题来源为目标环境截图：工具调用已生成 SVG 结果文件，但任务验收提示缺少文件和资料来源；结果文件的“查看”展示内部 IR 文本。

本次修改已记录为工作区 v0.7.79，发布与现场验收边界见 [v0.7.79 发布记录](../releases/v0.7.79-离线绘图验收与图片预览.md)。

## 原因与修复

- 原任务验收从模型观察中寻找带名称的文件引用，与受控渲染文件的持久化记录没有对齐。自动任务现在使用当前用户和运行所关联、状态就绪且内容完整的渲染文件作为文件存在依据；独立语义核验仍须检查交付内容。模型伪造的名称不能替代受控文件。
- `network.request` 是工具访问能力，不足以证明用户要求外部资料。仅因使用该能力不再自动要求来源；知识检索、网页检索以及用户明确要求依据时仍保留证据要求。意图判断指令也说明将用户提供的内容绘图不必自行要求外部资料。
- 对话结果卡片的图片“查看”通过现有一次性令牌读取已就绪的渲染文件，以图片方式展示，并在关闭时释放临时地址；不把 SVG 作为 HTML 脚本执行。其他格式继续使用原有查看路径。
- 工具已将 SVG 保存为受控文件时，传给模型的 MCP 内容改为产物摘要，避免重复携带整份 SVG。等待补充信息的任务状态图标改为提示色，避免显示成功勾号。

## 验证与边界

- 31 项定向测试通过；隔离 PostgreSQL 的 26 项测试通过，其中包括真实 SVG 产物持久化、运行与用户隔离、文件就绪状态和交付验收。图片预览测试使用客户端模拟接口，未代表真实浏览器或目标内网验收。
- 本次未部署主程序，也未在用户的 Linux、Kroki、模型和浏览器环境重新运行。已有任务的验收报告是历史结果，更新程序后需要重新发起或按现场流程重新执行验收；文件仍需通过任务归属、权限、有效期和完整性检查。
- 模型可能仍根据具体请求要求证据或判定内容不完整；要求依据的任务不能因产物存在就自动通过。多节点预检和渠道重放的既有限制不受本次修复影响。
