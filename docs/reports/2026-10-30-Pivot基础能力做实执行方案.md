# Pivot 基础能力做实与分阶段执行方案

日期：2026-10-30；基线：v0.7.69，Git `495f2db9`。

## 方向调整

先把常用功能做到**能配置、能正常使用、出错有提示、重启后数据不丢、遇到问题能恢复**。本阶段不要求先建设新的证据中心、行业方案、多 Agent 市场或完整企业级平台；已有权限、安全和审批边界继续生效，不为方便而绕过。

“基础能力做实”指对每个功能明确入口、输入输出、支持范围和异常行为，使用真实或明确标记的测试依赖验证，而不是以代码文件、功能菜单或单一演示作为完成依据。范围及顺序基于现有代码和项目文档，尚未逐项进行现场生产验证。

## 实施原则

1. 优先修复已经提供给用户的功能；不为了竞品功能数量新建一套 Agent、知识库或工作流体系。
2. 每项先跑通完整路径，再检查常见失败、性能和用户操作；发现问题按影响排序修复。
3. 记录“代码已接入、隔离环境已验证、目标环境已验收”三个不同状态；真实模型、真实业务数据和生产环境结果不能用模拟测试代替。
4. 不强制把所有应用绑定到单一业务场景；先打通聊天、文件、知识库、工具和自动化这些共同能力。
5. 保留用户已有数据和工作树；数据库迁移、共享存储、生产发布及恢复按既有流程进行。

## 分阶段执行

### 第 0 阶段：建立当前基线

- 记录版本、运行方式、数据库、操作系统、模型服务和可用可选服务；不记录凭据。
- 用隔离 PostgreSQL 执行 `npm run check`、`npm run lint`、`npm run typecheck` 和相关自动化测试；检查已有 E2E 测试是否覆盖真实用户入口。
- 建立功能清单：入口、依赖、成功路径、失败路径、已有测试、未测内容和负责人。把本地模拟、隔离测试和目标环境验收分开记录。
- 对之前已通过的测试保留记录；只有新改动或未解决问题需要重新执行时才重复。此前全量 Node 测试记录为 2395 项通过、2 项跳过，随后两项离线工具集成补测通过；该记录不是本次最新代码或目标服务器的验收结论。

完成标志：可列出哪些功能能在当前环境运行、依赖什么、哪些尚未测，且不影响现有服务和数据。

### 第一阶段：模型与聊天

- **模型**：新增/编辑、连接测试、模型列表刷新、个人与全局可见范围、默认模型、上下文与输出上限；覆盖服务不可达、认证错误、超时、并发限制和额度不足。
- **对话**：新建、发送、流式输出、停止、重试、历史恢复、切换会话、复制及附件；检查断线、重复片段、空回复和客户端迟到响应。
- **模型兼容**：选一至两个目标环境实际使用的模型端点验证请求、流式及工具调用差异；无法访问的供应商标为未测，不修改真实配置或发送业务内容进行无授权测试。

完成标志：正常路径和上述异常路径可复现并有回归；用户能理解失败原因并继续使用，服务重启后历史不丢。性能指标先实测再设目标。

### 第二阶段：文件与知识库

- 选择小型合成样本，分别覆盖可提取文本 PDF、扫描 PDF、图片、DOCX、XLSX 和 TXT；清楚标记需要外部 OCR 的场景。
- 走通上传、解析、失败提示、重试、导入知识库、检索、打开来源、删除及重启后的状态；检查页码、表格、中文编码和文件大小边界。
- 在隔离数据上核对用户/共享范围、原文件路径、删除和重复导入；目标环境使用的 OCR 和模型服务不可用时必须明确记录，而不是判定功能通过。

完成标志：每种受支持格式有样本和实际结果；不支持和未覆盖格式有提示，失败任务可定位和处理。

### 第三阶段：工具、任务和自动化

- 工具库覆盖列表、授权、连接测试、参数和结果展示，选择本地文件、只读数据库和 HTTP/MCP 各一条代表性路径。
- Agent 覆盖单任务创建、进度、暂停/继续/停止、失败和重启恢复；工作流覆盖编辑、保存、试运行、发布版本和运行结果。
- 遇到网络中断、重复请求、权限撤销、审批过期及外部结果不确定，沿用已有控制；不通过复制试验性路由或放宽权限来取得通过。
- 明确区分已配置的真实工具、可选服务未安装和旧实验接口不支持。Mermaid/Graphviz 独立服务是可选组件，不作为普通聊天/知识库的必需部署条件。

完成标志：至少一条实际接入的工具和一个小工作流从创建到完成能稳定重复；异常不丢状态，操作结果与实际一致。

### 第四阶段：重点应用与体验

- 按用户实际使用频率排序选择数据分析、公文、PDF/OCR、PPT 和思维导图；每个应用分别检查打开、处理、保存、刷新、导出以及失败提示。
- 分离内容正确性和格式兼容性：先验证内容和数据，再在目标 Office 软件、浏览器和设备上验证版面。
- 大文件和样式按使用过程定位瓶颈后再拆分或优化；避免为缩减行数进行无关重构。

完成标志：优先选定的应用有可复现样本、浏览器或桌面回归以及目标环境验证记录；未选中的应用保持原样并列入后续队列。

## 第一批建议实施工作包

建议从“模型配置与基础聊天”开始，具体顺序：

1. 盘点实际入口及现有测试，列出模型新增、测试、选择、发送、停止、重试和历史恢复的调用链。
2. 在隔离数据库与可控假模型上复现成功、认证失败、429、超时、断流、空回复与重复片段；检查是否准确提示、是否可继续操作。
3. 在目标模型服务可用且获得授权时，使用不含业务数据的测试提示验证实际流式和工具调用；记录模型和部署条件，不记录密钥。
4. 只修复实际复现或明确确认的缺陷，补充能验证用户行为的回归。
5. 运行相关测试、项目检查与必要的浏览器测试，记录通过、失败、跳过和未覆盖范围；完成后再进入文件与知识库工作包。

## 保留的后续事项

- 人工评测：15 条决策案例仓库状态仍待人工审核；该状态不能被程序自动替代，也不作为基础聊天使用的前置条件。主动决策灰度按现有门禁管理。
- 生产环境：目标服务器的模型吞吐、OCR 质量、P95/P99、磁盘、外部服务和完整备份恢复需要现场验证。本机合成基准和数据库计数对账不等于生产验收。
- 离线工具：Linux AMD64 测试包已经生成并校验；只有需要 Mermaid/Graphviz 或该源码检查服务时才需按部署文档安装，现有主服务无需因该可选包而停用。
- 产品定位：待基本能力稳定、用户使用情况和真实需求明确后，再决定是否聚焦制度审查等特色场景；之前的竞品分析保留为参考。

本方案是优先级与实施清单，尚未在本次文档调整中修改运行代码或声称各项已经全部完成。
