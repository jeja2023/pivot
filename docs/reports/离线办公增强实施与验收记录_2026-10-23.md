## 实测结果

- 全量 Node 回归：2,244 项，2,242 通过、0 失败、2 跳过。两个跳过项是前版离线 SDK/Kroki 的显式运行测试，本次没有把跳过计为通过。
- 后续针对性回归：54 项通过，包含现有语音、媒体 Provider、知识来源、DOCX、脑图/网页和新代理权限；补充分段修订、统一朗读取消及最终编辑改动后，29 项和最终功能 5 项均通过。
- 真实浏览器：动态脚本生成政策正文可提取，导航噪音和跨域外连不进入结果；脑图页面可增删、改文字和保存，节点文字不会注入脚本。
- 隔离 PostgreSQL：脑图版本递增，跨用户编辑拒绝；比较导出产生可下载 DOCX Rendition；无凭据朗读拒绝、超限文本拒绝。
- 脑图移动端编辑截图已人工检查，390 像素视口的页面滚动宽度为 390，无横向溢出；截图保存在 `artifacts/acceptance/mindmap-editor-mobile.png`。
- 真实中文模型加载后执行纯 CPU 推理。断网 Linux 容器设置 `--network none`、只读根目录、非 root、2 CPU、2 GiB，无 GPU，样本耗时分别 7.852、8.137、7.521 秒，音频长度约 3.605、4.331、4.693 秒。三条包含多音字、数字及中英混读，均产生 WAV；不声称发音质量已人工验收。
- 样本性能中位 7.852 秒，实时系数约 1.60—2.18。该资源限额下不能承诺即时全双工播报，现场应按容量要求测量并调参。单请求有并发、体积、音频时长和超时限制。
- 实际 `pg_dump`/`pg_restore` 在随机隔离 schema 中恢复 1 条凭据记录，恢复后 2 个 CAS/上传样本文件摘要一致，随机 schema 和临时文件清理完成。只测试自建数据，无生产 schema 恢复或覆盖。

## 修复的实际兼容问题

中文 ONNX 与 SDK 默认英文词表不一致时会产生过短无效音频，本次显式加载同模型中文词表。固定 SDK 的新版导出语速类型也与模型不一致，按 ONNX 元数据修正请求 dtype 后验证真实输出。

英文混读依赖 espeak 临时共享库，`/tmp:noexec` 会导致加载失败。仅增加受 UID 1000、容量和权限限制的 `/runtime` exec tmpfs，其他安全边界保留。模型、音色、词表及模型卡均在启动前校验，服务不在线拉取模型。

PostgreSQL CLI 的数据库 URL 被严格拆成 PGHOST/PGPORT/PGDATABASE/PGUSER/PGPASSWORD 环境传递，并禁用交互密码提示，避免把连接串放进命令行或在演练中等待输入。

## 明确的使用边界

DOCX 修订是以提取后的正文为输入生成新修订稿，不承诺还原原 DOCX 的复杂布局、表格结构、脚注、域或嵌入对象；原件必须保留。扫描 PDF 的原始版式比较继续走现有 PDF 工具。

OA 抓取支持已授权 Bearer/Cookie 登录会话，不绕过验证码/MFA，不自动提交业务表单；跨源 SSO 应先在既有受控登录流程取得会话。来源截断或认证失败不得触发删除同步。

脑图使用有界树结构与原生控件编辑；不支持任意 HTML 节点，超限明确拒绝。统一 TTS 在配置后故障明确报错，不静默外发云端；未配置统一服务时保留现有本机朗读。
