# Pivot 智能体执行底座改造与验收

日期：2026-11-10。基于当前 v0.7.146 工作区，保留其他未提交改动；尚未部署。不以功能接线或单元测试宣称追平商业产品。

版本归档：本报告中的改造现归入 [v0.7.147](../releases/v0.7.147-智能体协议视觉核验与项目技能资源升级.md)。下文 v0.7.146 为开发及测试基线，原测试阶段和失败记录保留；文档升版不表示重新执行功能验收。

## 已实施

1. Agent 的 Responses 请求与响应适配：官方 OpenAI 端点的 GPT-5/6、o1/o3/o4 自动采用 Responses；其他网关保留现有协议，显式 `/responses` 端点启用 Responses。工具名映射、调用 ID、系统角色、图像、结构化输出、用量与终止状态统一转换。继续经过原出网、并发、预算、首响应、空闲超时和取消边界。拒绝未完成、重复标识与超额工具调用。
2. 当前执行进程内的 Responses 工具轮次保留服务方返回的加密推理项，只用于同端点、同模型的后续请求，不进入公开步骤或普通审计；进程重启后继续依赖已持久化的工具事实，不宣称保留加密推理。更换模型不复用旧推理。
3. 工具截图与 MCP 图像经 sharp 校验、像素/大小限制及 PNG 转换，按用户封装进入既有 CAS；模型侧发送真实图像块。每次读取重查对象归属、类型、有效期、大小和摘要；文本模型明确收到不可用提示。每次请求最多四幅最近工具图像，超出有提示。持久观察保留引用，可跨检查点恢复；外部工具自报引用会移除。
4. 最终核验从持久工具步骤、DAG 节点、已应用控制回执及工具检查点补齐历史证据，并保留完整答复；跨 Run 续跑及完成型目标接续追溯原运行，操作完成后界面步骤落库前中断也不能丢掉检查点结果。同内容的两次真实操作按次数保留，持久记录与内存窗口的重叠去重。规划摘要出现受控原文引用时，核验重新读取完整原文，不再固定取最后二十四条或仅五百字输出。缺失、无权限或失效原文不能判定通过；超出本次原文容量或模型上下文明确保留未核验状态，任务界面显示原因。
5. 质量路由直接使用每个 Run 唯一的最新验收记录，按首次验收时间计算三十天窗口；重复修复不会增加样本，旧任务重验不会把旧样本刷新为新样本。执行中、待提交与已删除任务不进入样本。历史累计聚合表保留兼容，但不再充当新路由依据。运行期绑定实际模型端点与名称摘要，路由切换同步核验模型；部分完成、核验缺口和无效核验响应不会因缺少成功响应身份而被丢出样本。
6. 自动升级优先使用同类任务的合格质量证据；无质量证据时只允许上下文容量扩大，不再仅用价格判断模型更强。保留当前模型可见性、视觉与上下文准入限制。
7. 显式 Responses 地址在共享模型地址解析、普通聊天和聊天工具规划同步识别；Responses 请求不再混入 Chat Completions 专属采样/长度字段，系统消息不降格为用户消息。
8. 持续目标完成回执以事务锁绑定目标版本、活动状态和真实验收结果，旧版本或已暂停目标不再被迟到回执完成；同一 Run 回执只应用一次，失败计数不被重复投递放大。旧记录缺少目标版本时保守忽略，不自动完成当前目标。
9. 完成型目标接续同账号、同版本的前次终态任务，读取未完成事项、历史答复、验收反馈和当前产物版本；最终验收同时核对前次实际交付与本次结果。前次仍在执行或等待处理时拒绝另起接续；普通定时和监控任务继续独立运行。修复触发参数在上下文规范化中被丢弃的问题，文件/数据行等本次触发资料进入流式及 JSON 规划。
10. 历史接续不继承审批，旧内容不构成新的指令授权。运行读取、后续模型轮次和答案交付沿接续来源再次校验；删除或撤权会阻断后代读取。证据链限制为 128 层、权限检查最多 256 次；核验记录最多 2000 条、原文总量 32 MiB，超限明确保留未完成核验状态。
11. 失败调用缺少输出时，不再把整条观察（含未经脱敏的原参数）误当作输出传入核验模型；数值零和布尔 false 保持原样。图像核验复用受控图像引用。

## 验收入口

`npm run test:agent:frontier` 集中覆盖新增协议、视觉及质量窗口；原 `test:agent:quality`、`test:agent:parity`、`test:agent:release-gates` 继续保留。测试使用隔离 PostgreSQL schema、本机 HTTP 模型夹具和合成图像，不使用生产业务数据。

- 最终 `npm run test:agent:frontier`：59/59 通过，包含全部新增协议、图像、质量窗口、持久证据和目标接续测试。
- 扩展核心专项（当时 frontier 全部文件，加执行链和生命周期）：68/68 通过；后续的检查点来源与接续验收补充由最终 frontier 和下表专项覆盖。
- 智能体质量组 `test:agent:quality`：216/216 通过，覆盖预算、恢复、浏览器、协作、Worker、事务和发布相关边界。该组在最后的模型身份补充前通过，后续变更由最终 frontier、执行链及下表专项覆盖。
- 持久证据、事务、来源撤权组合回归：70/70 通过；与上述测试有重叠，不相加为独立场景数。
- 类型检查、改动代码 ESLint、死导出及 SQL 审核门禁通过；`npm run check` 在允许启动子进程的环境下完成最终复核。早期检查遇到临时文件扫描竞争及沙箱 EPERM，不能把这些环境失败记为通过。
- 初始全仓测试共 3271 项：3166 通过、96 失败、9 跳过。此批发生在本轮中间版本，且临时目录使用 C 盘，不能作为最终版本全绿结论。已修复本次观察预处理的一项兼容回归，磁盘准入和执行器配置相关失败已按文件独立复验；明细见下表。

### 真实模型验证

使用当前配置的 `gpt-5.6-terra`，只发送合成图像和合成任务，不使用业务资料。模型名是当前供应方配置，不能据此证明模型内部版本或与其它商业产品的差距。

1. 直接协议往返：当前聊天协议、显式 Responses 各执行一次“请求合成截图 → 识别随机字符”，均准确返回图中文字。共四次模型请求；这两项使用内存图像存储，真实 CAS 权限和恢复由本机 HTTP/数据库回归另外验证。
2. 完整任务入口：通过 `runtime.createAgentRun` 入队，实际执行渐进发现、契约读取、MCP 截图、原生图像回传、合成提交及独立核验。任务为 `completed`，核验为 `verified`，提交值与随机图像字符一致；9 次模型请求、21157 Token，运行内约 88.9 秒。隔离 schema 已清理。
3. 完整入口验证的首轮驱动器使用了错误的视觉标志字段类型，模型调用为零；修正为数据库实际整数类型后完成上述验证。保留夹具失败与成功范围，不把首轮算作模型失败。

## 明确边界与后续工作

- 当前完成执行底座的上述代码改造，不代表此前全面差距清单全部消失。
- 用户已明确本轮暂不接入 OA/邮件/日历系统，也不扩展多租户。
- 后续已补个人项目空间、里程碑编辑和技能静态配套资料，见[项目与技能资源升级验收](Pivot项目空间与技能资源升级-20261110.md)。跨账号项目共享、普通会话归档到项目、外部技能脚本与宿主行为全兼容、通用跨平台电脑操作与整站多节点就绪仍未完成。这些需要各自的实现和目标系统验收，不能通过修改就绪标志代替。
- 现有工具授权、逐操作审批和隔离 Worker 没有放宽。当前视觉闭环提供图像观察，不自动赋予坐标点击、任意桌面应用或日常浏览器 Profile 权限。
- 语义核验仍使用任务执行模型；原文超长时会保守拒绝完整验收，尚未引入分层语义核验。工具参数预览继续脱敏且限长。
- 质量证据绑定当前端点与模型名摘要，修改模型条目后旧样本不参与路由；没有该摘要的历史样本保留但不作为新质量证据；跨模型工作流仍需分别归因，当前不将无明确模型身份的旧 DAG 样本计入。这不是独立人评，也不证明供应方内部权重固定。
- 尚无最新商业产品同任务实测、目标 Office/WPS 往返及目标企业基础设施验收，不能报告追平百分比、生产 SLA 或整体成本收益。
