## 2. 验证分层

### 2.1 工程回归

执行 `npm run check`，覆盖迁移、配置注册、关键索引、架构、SQL 审核、中文规范、前端资源、安全 HTML、异步数据库、热路径 I/O、全局 API 和安全回归矩阵。执行 `npm run lint` 和 `npm run test:all`；定向复核额外运行聊天控制、事务恢复、长期记忆和安全 HTTP 用例。

新增自动路由单元与集成用例不以复制实现公式为目标，而是验证可观察行为：同一请求只保存一次、过期执行器不能更新、同任务不建第二个 Run、当前只规划撤回写能力、缺少真实成果不能完成、遗忘后不能重建、学习开关关闭不能发布。

最终运行数量与退出状态记录在第 5 节。

### 2.2 浏览器

真实启动隔离后端、PostgreSQL schema 与假模型 HTTP 服务，验证普通发送仍使用自然入口，简单问题直答、明确委托由服务端进入持久任务，且不弹任务选择卡；任务详情与受控摘要正常懒加载。该层证明协议与交互接线，不将假模型当作真实语义质量证据。

### 2.3 真实模型合成问题

通过 `scripts/evaluate_chat_intents.js` 使用项目已配置且指定用户有权调用的模型，逐个运行公开合成问题，不执行业务工具。保留规则基线和候选语义结果及耗时；超时、无效 JSON、非法能力均记为失败，不能以兜底“澄清”伪造成功。

本轮观察到模型调用存在 15 秒及 30 秒内未返回的情况。候选裁决失败会保留请求并明确阻断。该可用性限制与真实模型能力必须在部署环境按服务等级观测；不能以通过工程回归消除上游超时。

## 3. 运行与回退

1. 升级前保留既有数据库与产物备份；执行非破坏迁移 `202610190002_chat_conversation_turns`。
2. 在目标环境先使用 `PIVOT_CHAT_INTENT_MODE=shadow` 或较低稳定灰度比例，按真实可完成任务对照，冻结路由质量与时延门槛后放量。代码默认值可用于开发验证，不是目标环境已完成放行。
3. 发生误路由或时延退化，设 `PIVOT_CHAT_INTENT_ROLLOUT_PERCENT=0` 或关闭“自动处理明确委托”；保留已有任务与审计，必要时明确停止任务。
4. 错误偏好直接更正/忘记；错误个人经验自动暂停或使用原有版本回滚；不扩大共享发布或授权规则。
5. 没有充分独立评测样本时，允许继续产生与验证草稿，禁止自动推广。对外发送、写入、删除等未决效果仍需在既有事务边界核对，不因版本回退而伪称撤销。

## 4. 必须由目标环境提供的证据

- 经授权的真实任务集、独立盲测标注与业务采纳记录。
- 同一用户、项目、能力与模型版本下的成功率、追问次数、重复纠正、经验复用质量/耗时/成本对照。
- 部署负载、浏览器/设备、断网、数据库故障、外部系统故障、授权撤销与运维回退演练记录。
- 生产灰度观察、独立核验与五分委员会签署。

这些属于实测和人工认定，仓库已提供状态、指标、评测、回退和证据入口；当前没有这些真实记录，不将它们记为“已经验收通过”。
