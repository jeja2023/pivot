# Pivot 智能体执行链路与验收修复

版本归档：[v0.7.138发布汇总](../releases/v0.7.138-智能体执行与交付验收可靠性升级.md)。下文保留本阶段的实际验证及当时未通过项；后续19项复测和缓存修复结果见发布汇总。

本次修复针对[智能体执行对照](Pivot-Hermes智能体执行对照-20261108.md)实际暴露的协议、步骤标识、预算容量及默认验收问题。未引入 Hermes、第三方依赖或数据库迁移，未修改其他正在进行的 PPT、BI 等工作区改动。

## 已修改的行为

1. **模型工具协议。** 工具名称、历史函数调用及指定工具选择统一转换为长度不超过64且只含字母、数字、下划线和连字符的名称，模型响应还原为原始受控工具名称。合法名称保持兼容；保留别名前缀、摘要及冲突检查，防止与合法工具或长公共前缀发生碰撞。支持增量返回的函数名。工具参数、已返回的provider调用ID、权限和审批关联不改写；提供方未返回调用ID时只补全一次，使历史和结果共用同一标识。
2. **步骤和审计标识。** 流式执行、审计和产物渲染共享稳定的内部步骤标识，超过64字符时使用SHA-256。旧短标识保持原值；原始provider调用ID仍保存在模型会话和计划记录中。操作关联键在超过255字符时也规范化，审计上下文保留经过既有脱敏处理的原始值，避免步骤修复后再次触发操作键长度错误。审计读取同时兼容历史文本JSON与PostgreSQL JSONB，不再因重复解析丢失输入和原始关联。
3. **默认风险容量。** 新任务默认risk_budget从20调整为80，覆盖发现、读取、校验与交付的多步调用。未采用评测中的500作为产品默认。显式值（包括0）、旧任务配置或用量快照中持久化的额度、累计记账、审批、并发、工具调用数、网络请求和副作用上限继续生效；新建子任务也不能通过新默认值或显式大预算扩大父任务既有风险上限。
4. **默认交付验收。** 直接任务及旧的空验收契约在最终答复非空之外，增加独立交付核验；无法核验或尚未交付时不标为completed。明确的结构化验收条件继续保留，DAG按既有节点和终点契约处理，不额外引入隐式总结调用。
5. **核验后的处理。** 明确缺少用户才能提供的业务信息时进入needs_input，不继续自动修复；可由智能体修复的具体交付缺口在当前权限、剩余轮次与预算内最多修复两次。核验不可用、来源撤销和预算耗尽均不能当作成功，也不能开启无界重试。

主要实现位于 `model-tool-protocol.js`、`agent-tool-call-identity.js`、`agent-model.js`、`agent-streaming-runtime.js`、`agent-tool-audit.js`、`agent-budget.js`、`agent-verification.js` 和 `chat-task-verification.js`。

## 回归覆盖

- 新增工具协议测试：合法/非法/长名称、别名碰撞、历史消息、tool_choice、分段函数名、原始调用ID保持、缺失调用ID补全，以及64字符步骤和255字符操作键边界。
- 新增真实PostgreSQL/HTTP执行测试：长步骤可落库、不同调用不碰撞、原始审计关联、原生工具执行、未交付回复被拒、内部缺口有界修复、缺少用户输入时停止。
- 验证默认风险容量可以覆盖多步读取；显式20/0等限额和审批、副作用门限仍拒绝超限操作。
- 保留并回归JSON降级、渐进式工具发现、工作流终点结果、暂停/取消、来源撤权、持久化失败和续跑预算。
- 工具协议、执行链路、预算恢复和有界验收修复回归已加入现有 `test:agent:quality` 门禁，不新建并行门禁体系。

上述测试组有重叠，不相加为独立样本数，不能把夹具或模型自报完成当成真实任务成功率。

## 真实模型检查与限制

复用此前冻结的任务资料和业务工具，转发层取消名称和调用ID适配，使用修复后的产品实现及默认风险预算。首项跨文件对账已实际生成正确JSON、校验通过并提交；之后原生调用和独立核验收到上游502，任务保持needs_input，未误报完成。

后续尝试连续收到Cloudflare `origin_bad_gateway`，直接向原模型服务发送相同流式请求也复现502；短非流式请求可成功。已停止故障期间的批次，保留成功交付、失败及中断记录。这些记录不能作为修复后的10项完整通过率，不将此次外部故障描述为模型推理差距。

真实模型的全面重测、生产账号、多用户负载、真实外部渠道和终端/浏览器任务仍未完成。独立核验会消耗模型请求与预算；服务不可用时选择保留未核验状态，而不是把未确认的结果标为成功。
