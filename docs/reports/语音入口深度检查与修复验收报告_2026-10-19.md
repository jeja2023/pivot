# 语音入口深度检查与修复验收报告

检查日期：2026-10-19；修复版本：v0.7.2。

## 结论

两个入口原本都绑定了处理函数，脚本也在首屏加载。但语音输入依赖浏览器原生识别而没有强制本地处理；实时语音只接入设备端识别和合成，后端语音会话接口只管理生命周期，不是音频转发服务。此前还有按钮状态、识别启动、模型上下文和临时正文持久化问题，不能将其认定为完整可靠可用。

当前修复的是设备端识别 → 文本模型 → 设备端朗读链路，未接入模型原生音频服务；本地语音能力不足时明确保持关闭。

## 问题与修复

| 检查点 | 发现与处理 |
|---|---|
| 入口绑定 | 两个按钮分别绑定语音输入和实时语音，相关脚本均已加载；增加共享能力检查 |
| 本地隐私说明 | 语音输入此前未设置 `processLocally`；现与实时语音统一强制本地识别，检查语言包，绝不静默远程回退 |
| 假启动与停止按钮 | 原启动异常被吞掉、未设置按钮活动状态；现等待识别器 `start` 事件，失败清理，成功后切换停止状态 |
| 模型真正收到语音内容 | 临时用户文本不落消息表，旧上下文组装没有可靠补入；现显式加入当前识别文本与有界临时历史 |
| 临时正文落入其他表 | 旧通用组装会创建持久任务上下文快照；临时语音现跳过路由/任务快照持久链路 |
| 连续多轮 | 临时历史仅在浏览器内存保留最多四轮；二轮正确携带上下文，不保存数据库 |
| 中间识别与朗读 | 修复已完成文本和中间结果拼接、逐轮重置与串话；仅当前活动语音请求能触发朗读 |
| 回声与并发 | 朗读期间暂停识别，结束后恢复；两种输入方式互斥，不覆盖草稿或附件 |
| 释放与会话切换 | 停止、错误、离页、换会话均释放设备资源和临时历史，并中止对应模型请求 |
| 服务端控制 | 复验用户归属、语音会话绑定、暂停/继续/取消与过期回收 |

实际运行时只进行了非录音能力探测：本机 Playwright Chromium 153，可信本地地址，存在识别接口与本地标记；等待声音列表加载后发现三种 Windows 中文本地声音。属性存在不证明识别语言包已安装。无头运行时调用语言包可用性接口曾使测试页崩溃，未据此宣称实际语言包就绪。

本机 Windows 设备探测中，`waveInGetNumDevs()` 返回 **0 个音频输入设备**；已连接的 AudioEndpoint 列表只出现显示器音频与扬声器。因此目前没有完成该电脑的真实录音验证。需要先使操作系统识别到麦克风，再验证浏览器语言包和权限；不能把设备问题当作前端开关未开启，也不能承诺代码修复后当前设备立即可录音。上述探测均没有打开输入流或开始录音。

浏览器端到端测试使用模拟识别器、音轨和朗读器，真实经过页面按钮、服务端语音会话、聊天接口与测试模型。服务端测试核对上游实际收到的当前文本及历史，确认聊天、记忆与任务快照没有新增正文。未请求用户真实麦克风、未录音，也没有执行真人发音或扬声器听感验收。

## 参考

浏览器文档说明原生识别的本地标记默认关闭，浏览器可自行选择远程或本地处理；设备端识别还依赖语言包。参见 [MDN processLocally](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/processLocally)、[MDN available](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/available_static)。这些兼容性约束不能通过服务端启用开关消除。
