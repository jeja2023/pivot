# 全仓 22 项失败修复与复验

日期：2026-11-11。对应此前完整验收的 3,372 项：3,341 通过、22 失败、9 跳过。保留该历史结果；本文记录后续修复与复验，不改写旧日志。

## 根因与修复

### BI 调度接纳与任务完成竞争

释放槽位后的后台调度可以提前认领下一项任务；原 `processModelJobs` 在发现调度已运行时立即返回，或只等待自己认领的任务。调用方随后读取仍为 queued/running/cancelling 的任务，导致空结果、视图/导出拒绝及恢复演练失败。重复调用或扩大固定等待不能消除竞争。

现将调度接纳做成共用的单次在途 Promise，任务执行独立登记。后台调用只等待本轮认领，显式处理入口等待本进程已认领任务及后续可执行队列收敛；排空期间取消并合并后台唤醒，返回后不遗留回调认领下一批任务。停止时先中止并等待执行收尾。就绪检查失败不推进维保时间，下一次调用继续失败关闭。查询提交、后台轮询同步使用接纳入口，避免普通请求等待全部长任务。权限、持久槽位、执行代次、预算、取消及交付校验不放宽。

### DuckDB 继承外部访问白名单

连接可继承临时目录白名单。只设置 `enable_external_access=false` 和本次 `allowed_paths` 仍保留旧目录授权，位于临时目录的测试秘密文件可被读取。

锁定前显式清空 `allowed_directories`，用本次允许导出的精确路径替换 `allowed_paths`（包括空列表），并将溢写目录换成操作独占目录。DuckDB 关闭外部访问时会再次自动授权当前溢写目录，不能只清空旧白名单；行为与[官方设置实现](https://github.com/duckdb/duckdb/blob/v1.5.0/src/main/settings/custom_settings.cpp)一致。普通查询关闭连接后清理私有目录，隔离节点任务复用受控输出目录下的独占溢写目录及任务清理。测试预先写入目录与文件授权，要求锁定后拒绝旧路径、拒绝重新开启外部访问/扩展，仍能导出到指定文件。

### 浏览器关闭确认与配置文件清理

历史失败包括 Windows 配置目录删除 EPERM 及关闭未确认。原五秒关闭预算较短，重试调用也可能在页面关闭后提前返回；页面关闭不证明完整退出。现复用同一次完整关闭 Promise，失败后允许重试，关闭阶段保留十五秒预算及原人工恢复语义。关闭前终止该会话出站代理的 HTTP/隧道长连接，直接调用 context.close 同样共用确认；代理关闭幂等。Playwright 持久上下文已负责浏览器退出，不重复发出浏览器级关闭。未确认退出时保留运行态；恢复前再次确认旧上下文退出。受控目录边界保持不变，删除增加有限重试。

### 模型质量样本与物理初始化夹具

模型质量样本断言在上一批已将模型身份固定，并让验收时间明确早于统计截止，消除 PostgreSQL 微秒与 JS 毫秒时钟边界竞争；本轮继续复验。

物理恢复复验还遇到 `initdb` 持久初始化在 fsync 阶段被普通六十秒进程限时终止。持久初始化改为一百八十秒有限预算；保留 fsync、WAL、同步提交和真实恢复断言，未使用 `--no-sync` 替代持久演练。
