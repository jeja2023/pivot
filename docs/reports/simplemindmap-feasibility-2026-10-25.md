# SimpleMindMap 初步验证与工程量评估

日期：2026-10-25。项目基线：Pivot v0.7.42。路线：开源编辑器内核 + Pivot 应用集成。

## 结论与建议

SimpleMindMap 可以作为优先内核继续集成。已验证开源发布包能在不放宽 Pivot 脚本安全策略的前提下运行，并复用多布局、编辑、撤销重做和导出能力；不需要从零开发布局算法或整体移植 Vue2 Web 应用。

原始 UMD 发布文件不可直接接入；ESM 加载路线可行。纯文本 SVG 需要去除 SVG.js 编辑器元数据后，才能进入现有安全清洗与服务端 PNG 渲染链。5000 个全展开节点在本机一次重绘约 32 秒，不能作为首版流畅编辑承诺。

建议正式首版预算 **20–30 人日，约 4–6 个工作周**，假设一名熟悉仓库的全栈开发者、1 人日为 8 小时有效工程投入；包括集成、测试与常规修复。该数字是基于任务拆分的工程估算，不是由性能测量直接推导的期限承诺。

## 取证与验证环境

- npm 精确版本：`simple-mind-map@0.14.0-fix.3`，获取自 [npm 官方分发地址](https://registry.npmjs.org/simple-mind-map/-/simple-mind-map-0.14.0-fix.3.tgz)，SHA-512 与 registry 的 `dist.integrity` 一致。
- 包声明 MIT，上游提供 [MIT 许可文件](https://github.com/wanglin2/mind-map/blob/main/LICENSE)；本次解包未发现独立 LICENSE 文件，正式 vendor 时需补齐版权/许可并审查所选插件的依赖，不将包声明代替完整治理。
- 系统：Windows 10，Intel i5-10500，12 逻辑处理器，16GB 内存；Node v24.22.0，Playwright Chromium 153.0.8010.12；浏览器视口 1440×900。
- 本地 HTTP 隔离页面复用实际 `client/chat/pivot-core.js`，按 `server/app.js` 配置等价 CSP：同源脚本/连接、允许样式内联，禁止 `unsafe-eval` 与内联事件。
- 阻止并记录外部 HTTP 请求；ESM 运行期间观测到的外部请求、页面异常和 CSP 违例均为 0。
- 正式应用路由、登录会话和数据库未接入。机器已安装 Electron 43.6.0，但本次未启动 Electron 做实测。

本地可复查的初测脚本和样例保存在 `.tmp/simplemindmap-feasibility-20261025/`，未纳入生产代码或修改根依赖。初测命令：

```powershell
node .tmp/simplemindmap-feasibility-20261025/probe.cjs
node .tmp/simplemindmap-feasibility-20261025/export-bridge.cjs
```

第一条生成浏览器观察与样例，第二条检验导出归一及现有服务端清洗/渲染桥接。归档结果：[结构化观测数据](simplemindmap-feasibility-2026-10-25.json)。

## 加载与构建结果

| 文件 | 原始大小 | gzip 体积 | 结果 |
|---|---:|---:|---|
| `dist/simpleMindMap.umd.min.js` | 6,826,711 字节 | 1,238,294 字节 | 含 1210 处 eval 调用；实际被 CSP 拦截，未得到可用内核对象；脚本 onload 仍触发，需检查模块就绪状态 |
| `dist/simpleMindMap.esm.min.js` | 1,605,792 字节 | 516,831 字节 | 本次启用功能路径可在当前 CSP 下运行，初次加载和 15 节点渲染约 359ms |

ESM 全量包仍携带多个插件的代码。本次为隔离验证，保留 Drag、KeyboardNavigation、Export、Select、AssociativeLine、TouchEvent、Search 的实例化，未启用 RichText/Formula/协作；正式版应显式选择源码插件构建，避免在共享全局类上随意修改插件列表。该实验并不证明包中所有功能路径均符合 CSP，也没有证实全部功能无动态代码风险。

集成路线：同源 ESM 桥接 + `Pivot.exposeModule`；或构建无 eval、只包含所需插件的 IIFE，再复用普通脚本加载器。源版本、构建参数、依赖锁和资源摘要应一起归档。

## 编辑、数据和导出结果

| 项目 | 观察结果 | 尚需完成 |
|---|---|---|
| 中文编辑 | 实际双击节点，输入中文并失焦提交后，树中文本正确 | 原生拼音输入法 composition、快捷键及 Electron 验收 |
| 命令历史 | 插入子节点后节点数从 15 到 16，撤销恢复 15，重做恢复 16 | 批量选择、剪贴板、复杂操作组合 |
| 布局 | `logicalStructure`、`logicalStructureLeft`、`mindMap`、`organizationStructure`、`catalogOrganization`、`timeline`、`fishbone` 均触发完成渲染事件 | 各结构的完整视觉、拖拽、折叠及导出一致性验收 |
| 数据适配 | 样例 `id↔data.uid`、文本及结构往返保持，颜色和纯文本备注经 JSON 序列化/重载保持 | 正式 Schema、插件字段与数据库保存；剔除 `isActive`、分离 `view`，防止无效版本累积 |
| 浏览器导出 | SVG、PNG、Markdown 返回有效数据，PNG 生成文件 121,271 字节 | 接入受控产物交付，规范尺寸/背景/字体，导入解析及异常路径 |
| 服务端 SVG/PNG | 原始 SVG 被现有清洗器拒绝；定向去除编辑器元数据后通过现有清洗，由现有 Sharp 生成 759×518 PNG，32,307 字节 | 富文本/图片等首版关闭；跨布局/长文本/透明背景和源版本交付验收 |
| 文本安全与销毁 | 一条纯文本 HTML 载荷未执行；销毁后画布 SVG 被移除 | 不能据此认定全部输入安全；导入、链接、插件字段和完整页面生命周期需专门测试 |

SVG 拒绝原因是 `xmlns:svgjs="http://svgjs.dev/svgjs"` 声明及 `svgjs:data` 编辑器元数据。本次用结构化解析移除该声明和 32 个元数据属性，继续调用原有 `sanitizeSvg`，未放宽任何安全规则。仅去除声明会留下未定义的 `svgjs:data` 前缀，Sharp 仍会拒绝，二者应一起处理。

服务端 PNG 已人工查看，样例的中文与分支结构可读；仍需明确透明背景与实色背景的导出选项，不能以「能生成 PNG」等同于与浏览器完全一致。11 个初测观测检查均完成，其中 UMD 拦截、原始 SVG 拒绝和大图耗时是明确限制，不是完整应用验收通过。

## 单次容量观测

使用每节点最多 8 个子分支的全展开中文树，计时从 `setData` 到 `node_tree_render_end`，包含当前调用的重绘等待；未测持续拖拽、长会话撤销栈、多标签竞争或峰值内存。

| 节点数 | 重绘耗时 | 画布内 DOM 元素数 | 原生 JSON 大小 |
|---:|---:|---:|---:|
| 120 | 458ms | 979 | 11,941 字节 |
| 1000 | 3911ms | 8129 | 98,951 字节 |
| 5000 | 32287ms | 40629 | 502,451 字节 |

这些是当前机器的一次顺序样例，不能作为稳定基准或性能 SLA。首版沿用现有服务端 120 节点上限；后续须通过多次测试、折叠/懒渲染和具体交互预算验证后逐级放宽，1000/5000 节点不自动视为已支持。

## 首版工作量

| 工作包 | 人日 | 主要交付 |
|---|---:|---|
| 资源与插件接入 | 2–3 | 模块桥接或裁剪构建、CSS、版权/依赖治理、缓存与 CSP |
| 应用外壳 | 4–5 | 应用入口、文档列表/分页、编辑工具栏、布局/主题/基础样式/备注面板、全局样式适配 |
| 数据与权限 | 5–7 | 自有规范格式、历史兼容、版本/回滚、软删除、所有导图写入口的鉴权和原子冲突控制 |
| 保存可靠性 | 2–3 | 串行自动保存、内容去重、草稿、错误与断网恢复 |
| 导入与交付 | 3–5 | 原生 JSON/受限 Markdown 导入导出、SVG/PNG 适配、源版本关联及受控下载 |
| 验收与修复 | 4–7 | HTTP/浏览器/Electron、输入法、主题、安全、历史入口及回归 |
| **合计** | **20–30** | **约 4–6 个工作周，单名熟悉项目的全栈开发者** |

小型可演示版本约 2–4 人日，只覆盖加载、基本操作和简单手动保存。加入 AI、模板库、PDF/XMind 和更多插件面板后，整体暂按 35–50 人日预算；此范围未逐项原型验证，须在首版接口稳定后重新细化。多人实时协作、复杂富文本/附件和大图优化另外立项。

主要不确定性在所有入口的历史兼容与并发语义、导出格式和浏览器/Electron 一致性、上游低维护下的缺陷修复。现成开源布局与插件减少算法开发量，不替代 Pivot 的产品界面和业务集成。
