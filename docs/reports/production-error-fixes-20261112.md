## 修复内容

| 现象 | 当前处理 | 回归范围 |
| --- | --- | --- |
| 图片已由执行模型识读，独立核验仍认为没有视觉依据 | 核验从任务授权的持久消息重新解析上传图片，复用聊天图片读取与当前账号、会话、路径、删除和过期检查；以原生图像输入核验。明确区分图片来源与文件交付，不要求为了证明读图额外调用OCR。 | 真实数据库及上传图片、模型请求组装、删除、过期、撤权、图像变化、数量与模型能力边界 |
| 核验与执行读取的资料不一致 | 核验前后重新读取原图，比较消息与图像摘要；失效或变化拒绝迟到通过结果。持久报告只保存来源ID及摘要，不写Base64或文件路径。 | 图像替换及消息删除；元数据伪造图像不能引入来源 |
| `intent_invalid_contract` | 原响应无效或截断且至少剩余2秒时，在相同总截止内最多补判一次；补判继续经过全部动作、能力、来源与续接校验，失败保留文本降级。两次实际用量累加记录。 | 损坏JSON、缺字段、截断、未知能力、越权续接、低预算与取消 |
| `intent_timeout` | 提前发生的上游连接/首响应超时可在原预算内重试一次；总截止和取消不重试。持续上游超时准确归为意图超时，失败路径保留排队与上游耗时。 | 上游恢复、持续超时、总截止、取消；既有认证、长Retry-After及熔断边界 |
| 文件已生成但缺少指定格式 | `artifact_format_missing`纳入原有最多两次受限补全；先验已有文件完整性，再保留已交付清单并请求复用成果导出缺失格式。 | 部分格式、已有清单、补全次数、轮次及预算边界 |

没有新增依赖、必填配置或数据库迁移。默认30秒意图总预算保持不变；慢服务超过截止仍会失败，不能承诺消除所有上游超时。已有文件完全未生成时继续沿用原有受限补全与真实文件验收，不能用模型承诺代替交付。
