# 自动记忆链路优化验收报告

日期：2026-10-19；版本：v0.7.1。

## 产品行为

用户正常聊天，后台自动提炼稳定偏好和事实、去重、更新并在相关任务中使用。输入框无需记忆按钮，日常无需手动确认或维护。当前任务要求优先；用户仍可在设置中查看、删除、导出和关闭。已有关闭、禁止类别和主动选择的确认策略保持生效。

## 检查与修复

| 发现的问题 | 最终处理 | 验证证据 |
|---|---|---|
| 采集隐含依赖任务经验学习开关 | 由独立记忆门禁和采集策略控制；经验学习关闭不阻止正常记忆 | `automatic-memory.test.js` 正常聊天自动入库 |
| 临时要求、引用和附件可能误入个人记忆 | 共用候选策略过滤；校验实际用户原文、置信与来源，自动收窄范围 | 临时/引用/附件/伪造证据用例 |
| 项目事实缺少持久抽取范围 | 新增 `project_id` 迁移与普通/Agent 完成链路传递 | 项目范围端到端用例 |
| 会话限制可能被当成项目限制，任务经验事实可能扩散为个人事实 | 显式区分会话与项目；任务事实默认限定运行所属范围 | 当前会话不串用用例、既有学习回归 |
| 问题不含偏好关键词时，已保存风格未必召回 | 独立召回通用回答偏好，合并排序并限制预算 | 在无关普通问题中自动调用偏好 |
| 新旧抽取乱序、并发时可能重复或回退 | 门禁锁内查重，旧来源不得覆盖新值 | 乱序、并发及版本停用用例 |
| 一条内容同时保存多个偏好，修改某个属性容易误覆盖其他属性 | 按语言、篇幅、顺序、格式拆开维护 | 多偏好独立纠正用例 |
| 单条遗忘错误匹配整个会话 | 有消息来源时按消息/内容抑制；新消息可继续学习 | 遗忘后同会话继续采集用例 |
| 模型失败后需人工重试、自动候选逐条向量化 | 规则兜底后有限持久重试，向量恢复交给现有后台维护 | 后台重试持久状态用例 |
| 偏好与当前任务同句表达时任务可能被吞掉 | 保留当前委托，偏好交给自动采集 | `chat-auto-execution.test.js` 同句任务用例 |
| 输入框菜单和第二输入弹窗重复要求用户操作 | 清理入口、事件和样式；设置保留管理入口，高级治理折叠 | 浏览器聊天/设置开关用例 |

## 边界

自动提炼仍取决于当前模型能力；模型不可用时采用受限规则并有限重试。未知项目仅保留在来源会话中，避免错误扩散。长期使用效果需要真实使用积累，本报告不把合成场景或工程回归外推为所有偏好都能被准确理解。知识库、工作流等外部来源发生变化后仍遵守既有来源复核机制，不自动认可已失效的来源。
