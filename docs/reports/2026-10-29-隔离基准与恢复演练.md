# 隔离基准与恢复演练

时间：2026-10-29（北京时间）。结果仅适用于本机测试条件，不代表生产容量或生产恢复验收。

## 数据分析基准

执行 `npm run benchmark:data-analysis -- --rows=100000`，使用脚本生成的 10 万行合成数据，DuckDB 线程数由脚本限制在最多 4 个。

| 操作 | 耗时 |
| --- | ---: |
| 生成 CSV | 474 毫秒 |
| 导入 Parquet | 622 毫秒 |
| 分组聚合 | 334 毫秒 |
| 透视聚合 | 15 毫秒 |
| 导出 CSV | 123 毫秒 |

这是单次执行，不是延迟分位数；未测真实模型、网络、并发用户和生产数据。

随后以同一脚本执行 100 万行合成数据，单次结果：生成 CSV 4552 毫秒、导入 Parquet 604 毫秒、分组聚合 378 毫秒、透视聚合 34 毫秒、导出 CSV 47 毫秒。数据和临时文件由脚本清理，机器可读结果保存在 `artifacts/data-analysis-review-20261029-1m.json`；未测模型。

## 数据库恢复演练

在本机独立 PostgreSQL 实例中建立两个专用测试数据库，初始化当前 schema 和迁移，写入一条合成知识库文档和一个关联分块。通过 `pg_dump` 自定义格式备份并用 `pg_restore --exit-on-error` 恢复到另一个测试数据库；运行 `npm run verify:knowledge-restore` 只读对账，七张表的计数一致，文档和分块各一条，恢复库孤儿分块为零。

该演练不含真实用户数据，只验证数据库备份可恢复以及有限的计数、引用对账。原文件、密钥、权限、索引检索、时间一致性和应用恢复仍需在目标部署环境单独验证。
