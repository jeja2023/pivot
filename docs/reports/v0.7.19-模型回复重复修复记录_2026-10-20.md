# v0.7.19 模型回复重复修复记录

日期：2026-10-20。问题：同一条大模型回复中的全部内容完整出现两遍。

## 原因与证据

只读核对近期助手消息，确认部分普通聊天回复已在服务端保存为两份相同正文，属于内容拼接问题。检查未向日志输出用户消息原文，也未修改生产历史数据。

1. Responses API 先发送 `response.output_text.delta`，在 `response.completed` 再携带完整输出。旧累加器将两者都直接追加，因此正文变成“完整答复 + 完整答复”。Provider 状态记录与兼容接口的完整 `message` 回传也存在同类风险。
2. 关闭思考显示时，短回复可能整体仍在内部控制内容过滤器中。旧收尾流程提前结束下游可见文本过滤器，先按完整结果回放，再排空上游缓冲，再次发送同一正文。该路径会造成流式过程重复，即使最后的保存通知替换了界面正文。

新增最小协议测试在修复前稳定复现整段重复。进一步采用真实聊天路由检查逐片发送文本，发现并修复第二条收尾路径；验证同时检查流式内容、数据库内容与最终保存通知，不仅检查最终页面。

## 改动

- 新增 `server/streaming-text.js`，按事件语义区别增量与完整快照；已接收正文不重复追加，仅补齐同一完整结果的缺失后缀。普通聊天累加器、Provider 记录和工具调用文本共用。
- 保留正常增量中用户确实要求的重复表达，思考与正文分别累计；不采用“看见相同句子就删除”或“把字符串砍一半”的规则。
- 仅有完整结果、部分增量后完整结束、多消息/多文本部分均保留；完整快照携带的用量正常记录。
- 调整 `server/routes/chat/index.js` 的收尾顺序，先排空上游过滤器，再完成下游过滤器，避免短回复重复回放；完整文本回退仅用于非 SSE 响应，聊天流显式声明 UTF-8。
- 增加 Responses 测试上游及真实浏览器回归，核对逐片输出、最终页面、保存内容与刷新历史。

## 验证

1. `tests/streaming-text-deduplication.test.js`：结束快照、兼容完整消息、正常重复、快照单独返回、部分补齐、思考分离、多部分和快照不一致处理。
2. `tests/chat-stream-final-snapshot.test.js`：实际 Responses 上游 → 真实聊天路由 → SSE 正文 → 保存通知 → 数据库，内容逐一相等且仅出现一次。
3. 与协议、Agent 原生流、工具调度、模型响应和空闲超时相关的 8 个文件专项共 35 项通过，无失败或跳过。
4. 浏览器使用真实应用、模型接口和独立数据库，检查流式正文拼接、最终单条回复、入库内容和刷新后的历史；同时回归原对话任务体验，共 6 项通过。
5. 完整 `npm run check`、本轮相关文件 ESLint 检查通过。版本同步为 0.7.19。

扩大执行范围时，包含安全聊天的 4 个文件共 167 项，166 项通过，1 项为既有“普通聊天超出会话 Agent 桥接上限时回退模型流”失败，与正文拼接无关；相同失败已记录于 [v0.7.17 验收报告](v0.7.17-工作流产品体验升级验收报告_2026-10-20.md)。本次未修改该独立路由行为，也不宣称整库全部测试通过。

## 生效与边界

更新并重启服务端后，新回复使用修复后的流式逻辑。仅刷新网页不能替代加载服务端新代码。已入库的旧重复文本不会自动消失，本次没有对历史消息做推断性改写。

不新增依赖、数据库迁移或必需配置。验证使用受控上游和真实应用链路，未为此向生产模型发送额外对话，未构建安装包或部署生产。
