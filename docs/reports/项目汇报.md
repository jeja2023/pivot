## 历史版本更新（v0.1.3）

- **Webhook 异步分发等待修复**：入站 Webhook 触发路由 `/workflow/:token` 补齐 `await dispatchWebhookTrigger`，确保在响应 HTTP 202 及写入操作审计前完成工作流运行实例的创建与入队分发，彻底消除时序竞争与误报成功风险。
- **Electron 本地服务生命周期等待**：桌面客户端引入 `resolveInitializedServer`，显式 `await` 服务端 `initPromise` 异步初始化完成，保证本地 HTTP 实例及端口就绪后再建立连接，杜绝启动阶段偶发的缺少服务器实例异常。
- **PostgreSQL 参数占位符词法状态机**：重构 `toPostgresParams` 词法解析器，精准识别单/双引号、转义字符、行注释（`--`）、嵌套块注释（`/* ... */`）和 PostgreSQL Dollar 引用（`$$` 与 `$tag$`），仅在有效 SQL 表达式中转换 `?` 占位符为 `$1, $2, ...`，彻底避免字符串内容或注释中的问号被误替换。
- **E2E 独立 Schema 与端口隔离**：Playwright E2E 测试支持 `PIVOT_E2E_ISOLATED=true`，自动分配唯一 PostgreSQL 测试 Schema（`pivot_e2e_*`）、临时数据隔离目录与空闲随机端口（`PIVOT_PORT=0`），禁用服务复用，实现端到端测试与本地开发/生产服务的完全隔离与自动资源回收。
- **PostgreSQL 原生热备份与轮转引擎**：全面接入 `pg_dump` 自定义格式（`--format=custom --no-owner --no-privileges`）备份引擎；支持 `PG_DUMP_BIN`、`PG_DUMP_TIMEOUT_MS` 超时熔断及子进程环境变量凭据隔离，并按 `DB_BACKUP_RETENTION_DAYS` 与 `DB_BACKUP_MAX_VERSIONS` 自动轮转清理历史备份。
- **PostgreSQL ANALYZE 运维对齐**：清理已废弃的 SQLite 增量整理参数 `getIncrementalVacuumPages`，统一收敛至标准 PostgreSQL `ANALYZE` 统计信息采集，消除多余配置对运维监控的干扰。
- **跨平台 npm 启动脚本优化**：移除 `package.json` 启动脚本中 Windows cmd 专有的 `chcp 65001 >nul &&` 前缀，全面支持 Linux、macOS 与标准 Docker 容器化开箱即用。
- **GPU 显存阈值校验与安全回退**：新增 `normalizeGpuThresholds` 严格校验显存警戒与恢复水位递增约束（`safe < critical < reject` 且 `recover < reject`），当外部环境变量非法或乱序时输出中文告警并安全回退到系统默认值（85% / 95% / 97% / 90%）。
- **交付验证**：新增覆盖 Webhook 异步等待、SQL 占位符词法解析、GPU 阈值与并发恢复、HTTP 生命周期的 18 项专项回归测试全部通过；全量 Node 测试套件 `476/476` 100% 全部通过，`npm run check`（457 个 JS 文件与静态资产）与 ESLint（0 错误 0 警告）全部通过。

## 一、项目是什么

**Pivot（智枢）** 是一款面向**私有化、离线化、企业内网**场景的全栈 AI 会话、统一任务与自动化平台。

它把“接入大模型、检索知识库、调用工具、运行自主任务、管理自动化、治理权限、审计监控”这些原本分散的能力，整合为一个**可控、安全、可审计**的统一 AI 工作入口，部署在企业自己的服务器或局域网中，数据不出内网。

- **技术形态**：Node.js + Express + SQLite 单体应用，支持 Docker 离线打包部署。
- **交付形态**：Web 应用 + PWA（可安装到桌面/移动端）+ OpenAI 兼容 API 网关。
- **定位**：企业内部的"AI 中枢"，而非面向公网的对话产品。

### 6 种自主任务模型路由策略

自主任务执行时，可在**该用户有权限的模型池内**按任务特征自动挑选最合适的模型，而非固定指定。路由不会越权、失败自动回退到原模型，并记录选择理由。

| 策略 | 名称 | 选择逻辑 | 适用场景 |
|------|------|----------|----------|
| `fixed` | 固定模型 | 始终用指定模型（默认，等同旧行为） | 已明确知道该用哪个模型 |
| `auto-vision` | 视觉优先 | 输入含图片时选支持视觉的模型，否则按上下文兜底 | 图文混合任务 |
| `auto-context` | 上下文匹配 | 在能容纳输入的模型中选窗口最小但够用的 | 节约大窗口模型配额 |
| `auto-cost` | 成本优先 | 在够用模型中选输入+输出单价之和最低的 | 成本敏感任务 |
| `auto-load` | 负载均衡 | 选当前活跃占比最低的端点 | 降低长任务排队等待 |
| `auto-escalate` | 成本升级 | 先用最便宜模型出结果，置信不足时自动升级到更强模型重做 | 成本与质量自动权衡 |

> `auto-escalate` 通过启发式判断输出置信度（空/过短/异常结束/低置信短语），不达标时升级到单价更高或窗口更大的模型重新合成，实现"简单任务省钱、难任务才升级"。

## 三、能做到什么

- **统一管理多个大模型**：在一个平台接入云端、本机、局域网的多种模型，按部门和用户分配可见范围与额度，并自动统计 Token 用量与成本。
- **基于私有资料回答**：把企业内部文档导入知识库，让模型优先依据内部资料作答；资料规模增长后，可按专题库和标签只引用相关资料，标签会跟随专题库联动过滤，并可视化验证是否真正命中。
- **承载具体业务写作场景**：通过应用中心进入公文写作工作台，在同一页面完成材料整理、正文起草、对照审改、版式化正文编辑、规范检查、批注和版本对比。
- **让 AI 自主完成多步任务**：自主任务可拆解目标、调用工具、查询数据库、生成图表与报告；成熟步骤可生成工作流草稿，再通过可视化工作流编排固化为业务流程（如“取数 → 大模型解读 → 图表 → 报告 → 内网通知”）。
- **对接企业现有系统**：通过 OpenAI 兼容 API，让其他业务系统直接调用平台的模型与向量能力。
- **全程可审计可监控**：所有敏感操作、模型调用、工具调用均留痕，管理员可导出合规审计包，运维可接入企业监控体系。

## 四、解决哪些问题

1. **数据安全与合规**——避免企业数据流向公网 AI 服务；私有化离线部署，全链路审计，满足内网管控与合规留存要求。
2. **模型资源碎片化**——统一纳管多模型与多端点，提供并发保护、熔断、额度、成本治理和运行时全局参数配置，避免资源滥用和服务雪崩。
3. **知识难以被 AI 利用**——通过 RAG 与知识图谱，把企业文档转化为模型可检索、可追溯的知识来源，降低"幻觉"。
4. **AI 落地停留在聊天**——自主任务与自动化把 AI 从“对话”推进到“自动完成业务任务”，并把临时任务沉淀为可复用、可发布、可审计的流程资产。
5. **权限与治理缺位**——三级权限模型（超级管理员/管理员/普通用户）、工具策略、个人连接隔离、资产隔离，让 AI 能力在组织内可控分发。
