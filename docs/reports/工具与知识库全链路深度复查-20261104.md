## 确认的问题与修复

| 问题 | 触发与影响 | 修复 |
| --- | --- | --- |
| 契约部分规则未执行 | `anyOf` / `oneOf` / `allOf` 未校验；动态字典值和数组第 101 项之后可能绕过校验；非法根参数可能被归一化为空对象 | 执行组合与动态字典规则，检查全部受限数组项；超过校验层级或数量限制返回问题；原始非法根参数保留到校验阶段 |
| 引用版本被归一化丢弃 | 名称在嵌套 `toolRef`，版本/摘要在另一层时，旧实现只选一份引用；多个别名冲突也可能未发现 | 合并全部已支持别名，保留版本与摘要；名称、版本和摘要冲突或格式错误均拒绝，不静默改成当前版本 |
| 批量知识结果丢失顶层来源 | `tools.batch_read` 把知识正文放在子结果，来源提取仅认识顶层 | 批量结果汇总独立来源清单；历史嵌套批次也能提取和复核；来源不完整时保守阻断 |
| 单项业务失败覆盖整批 | 批次中一项失败会抛出，调用方拿不到其他已成功读取的结果 | 每项保留结果和安全错误摘要，整体显示部分完成；权限、审批、取消、租约和资源控制错误仍整体交还控制权 |
| 并发批次提前返回 | `Promise.all` 首个拒绝后，其他读取可能仍在执行，下一轮可能与旧批次重叠 | 首次失败后停止派发后续项，等待在途操作结束再返回错误，不自动重放业务操作 |
| 自主执行缺少统一来源边界 | 旧来源可能继续进入下一轮模型或工具；恢复和观察截断可能丢掉较早来源 | 恢复时加载完整持久来源清单；合并并保留来源清单，在规划、后续工具和答案发布前重新复核。相同来源在一次边界内合并，避免逐观察重复读同一来源 |
| 流式完成快照泄露核验前正文 | 增量推送已拦截，但完成快照仍携带原始正文；旧测试未监听发布通道 | 完成快照沿用相同的正文保护；测试监听真实发布回调，检查增量、完成快照和落库步骤均不含核验前正文 |
| 授权失效误入普通纠错 | 审批过期、版本变化或授权撤回可能累积为工具错误，甚至被标为模型原生调用失败 | 统一执行控制错误识别，普通与流式路径立即停止该调用，进入待处理状态，不借模型降级继续处理 |
| 空结果误记进展 | 空行结果含不同统计信息时，可能生成不同指纹；元执行未稳定使用嵌套目标名称 | 空行、全失败批次和契约读取不记新进展；批量进展基于实际成功结果，元执行按实际目标身份计数 |
| 受限收尾存在时间窗口 | 生成答复前来源有效，生成期间撤权后仍可能发布旧正文；批量上下文未参与收尾引用核验 | 收尾发布前再次核对来源与聊天快照；批量知识上下文合并后参与引用核验，持久来源清单同样保留到验收 |

主要实现位于 `agent-knowledge-boundary.js`、`agent-execution-control.js`、`knowledge-evidence-lineage.js`、`agent-tool-scheduler.js` 及现有契约、发现和运行器模块。没有新增数据库表、依赖或可扩权的配置开关。

新增测试使用明确的反例：非法数组第 101 项、冲突版本、批量查询中单项失败、在途调用尚未结束、读取后撤权、核验期间撤权、恢复时较早来源未进入最近观察、流式完成事件泄露及审批失效。数据库测试还把嵌套批量结果保存到实际步骤，验证版本变化后运行读取和来源复核一起失效。
