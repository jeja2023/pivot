**F1 · P1：超过 12,000 字符的普通聊天任务不进入持久执行**

位置：`server/routes/chat/index.js:452`；相关定义 `server/services/agent-validators.js:82`；消费者 `server/services/chat-agent-handoff.js:98`。

触发：普通聊天上传较长的正文，要求“分析附件并导出可下载的 PDF”，语义判断已经返回 `agent_run`。只要包括附件正文在内的 `modelContent.length > 12000`，入口就跳过整个交接分支。

HTTP 对照结果：

| 请求总字符数 | 路由发出“正在建立受控执行” | 任务工厂调用次数 | `agent_handoff` | 后续行为 |
| --- | --- | --- | --- | --- |
| 142 | 是 | 1 | 有 | 创建合成测试任务 |
| 12,542 | 是 | 0 | 无 | 返回普通流式回答，没有错误事件 |

影响：用户明确要求的文件或多步骤任务没有进入执行；前端却已收到任务识别提示。`chat-agent-handoff` 原有的长来源分页读取与完整来源验收逻辑也无法在这条新建任务路径上被触发。普通回答不能代替所要求的文件交付。

最小修复：分别校验规范化任务目标与原始来源长度；新建任务使用有界 `automaticExecution.objective`，原始材料继续通过持久消息和 `chat.read_source` 分页读取。保留消息、上下文和来源完整性限制。如果不能接纳，应明确返回失败，不能静默落回普通回答。补充真实 `/chat` 的临界长度及长附件交付回归，断言实际任务创建和来源读取要求。

**F2 · P1：短附件直答绕过对活动任务的来源撤销**

位置：`server/services/chat-auto-execution-handler.js:47`；紧随其后的纠正入口在第 49 行，实际限制写入位于 `chat-route-correction-handler.js`。

触发：会话已有可联网的活动任务，本轮附上短材料并说“不要联网，继续分析这份附件”。`directSourceAnswer` 在 `detectChatRouteCorrection` 之前提前返回。

定向结果：返回 `direct_answer`，当前回复的 `excludeWeb=true`；但活动任务读取次数、元数据更新次数和控制消息次数均为 **0**。

影响：本轮文本回复受到限制，原活动任务却没有收到撤销，后续仍可能按旧能力范围联网。原有“局部来源限制先约束现有任务”的回归只覆盖没有触发短附件快速路径的输入，因此未检出此组合。

最小修复：显式纠正和来源撤销先于短附件直答；成功更新活动任务之后，纯附件分析仍可零模型直答。保留多任务歧义处理，不能以快速路径绕过目标确定。测试同时断言当前决定、旧任务元数据以及实际控制消息，而不只断言 `requestScope`。

**F3 · P1：任务续接接受了新知识库选择，但运行仍使用旧范围**

位置：`server/services/chat-task-continuation.js:71`、`:82`、`:90`。调用方在 `server/routes/chat/index.js:341` 保存了 `knowledgeScope`；实际知识工具在 `server/services/knowledge-tool-results.js:29` 使用 `metadata.chatBridge.ragScope`。

触发：任务原本绑定专题 A，用户通过 `@` 选择自己有权访问的专题 B，并明确要求仅依据 B 继续总结。续接函数只为 `routeOverrides.tools` 和 `excludeTools` 更新范围，未消费新的 `decision.knowledgeScope` 或 `routeOverrides.collections/tagNames`。

定向结果：`continued=true`，运行的专题仍为 `[11]`；新选择 `[22]` 未写入。随后调用真实知识工具范围解析函数请求 `[22]`，得到 `KNOWLEDGE_SCOPE_DENIED`。

影响：界面可以提示已经把新要求交给任务，但执行仍受旧专题约束：默认检索可能沿用旧资料，显式请求新专题则被拒绝。若旧范围原本未收窄，本轮新选的专题也没有形成应有的运行限制。此处是用户指定业务范围未生效，复现没有证明跨账号权限绕过。

最小修复：续接时复用知识库权限及范围解析，明确区分“未选择”“显式替换”和“清除”；将确认后的范围、来源消息修订和控制消息一致更新，并清理过期 `ragContext`。保留已有安全撤销规则与执行时权限复核。回归覆盖 A→B、全范围→单专题、标签收窄、无权限专题及旧消息不能覆盖新修订。

**F4 · P1：核验阶段无法通过聊天停止任务**

位置：`server/services/chat-auto-execution-handler.js:119`。真实状态写入见 `server/services/agent-runtime/run-execution.js:645`；状态机包含 `verifying`，并允许转为 `cancelled`。

触发：唯一任务处于 `verifying`，用户发送“停止当前任务”。聊天控制函数的活动状态硬编码列表漏掉 `verifying`。

定向结果：取消函数调用次数为 **0**，回复为“当前会话没有正在处理的任务。”

影响：用户停止请求未被执行，核验继续消耗资源；若核验判定可修复，执行循环还可能继续进入修复步骤。此问题不是已经结束的任务无需停止，而是有效活动状态与聊天控制状态列表不一致。

最小修复：复用运行时统一的活动/可取消状态判断，覆盖 `verifying`；暂停的可用性按状态机单独处理，不能盲目复用取消的目标状态。新增核验期间聊天停止测试，断言运行时取消被调用且后续修复不再执行。

**F5 · P2：自动负载选择和故障切换不排除熔断端点**

位置：`server/services/model-router.js:106`、`:178`。运行时已提供 `circuitOpenMs`，并在 `server/services/model-runtime.js:196` 拒绝熔断端点的请求。

触发：端点 A 已熔断，挂载模型 1、2，活动请求数为 0；健康端点 B 的模型 3 负载为 1/4。当前模型 1 遇到可恢复故障，自动选择备用模型。

定向结果：`pickFailoverModel` 选择同一熔断端点上的模型 **2**；`auto-load` 选择模型 **1**，健康模型 **3** 未被选择。探针使用与运行时返回结构一致的注入状态，未向外部端点发送请求。

影响：负载最低被误当成可用，降级仍会被同一熔断器拒绝。实际故障切换函数只尝试这一个备用模型，失败后直接抛出，因此即使存在兼容的健康模型，也可能结束本轮执行。

最小修复：自动策略先排除明确熔断/拒绝准入的端点，再排序兼容候选；对端点级故障避免切换到同一失败端点的另一个模型。保留固定模型语义以及模型自身能力不兼容与端点故障的区别。测试加入共享端点、多模型和全部端点不可用场景。

**当前功能与配置核实**

当前实现不是单个分类器，而是如下相互衔接的功能：

| 层次 | 已有实现 | 本轮检查结论 |
| --- | --- | --- |
| 聊天输入 | `@` 知识库、Wiki、工具选择；手动工具白名单与来源覆盖 | 服务端再次验证所选资源；续接知识范围存在 F3 |
| 意图判断 | 直答、仅计划、新任务、续接、澄清；停止和记忆控制快速路径 | 有结构化输出、跨字段校验、超时降级；F2、F4 是前置分支/状态遗漏 |
| 知识与工具路由 | RAG 目录、词法/向量候选、自动只读能力判断 | 请求来源限制、可见目录和工具合同多层过滤；学习建议只能在允许动作内选择 |
| 任务交接 | 消息关联、能力限制、预算、受控工具、原文分页及交付核验 | 已有底座；F1 阻断新建长材料任务的实际入口 |
| 续接与纠正 | 控制消息、任务契约、业务范围更新、来源撤销 | 工具选择有修订检查；知识范围未同步，部分快速路径未应用纠正 |
| 模型路由 | 固定、视觉、上下文、成本、负载、质量及成本升级 | 候选来自可运行模型；质量策略有样本门槛；熔断状态未进入负载/备用选择 |
| 学习治理 | 决策审计、反馈审核、冻结评测、制品激活/回滚、灰度 | 工程机制存在；当前学习层未主动放量，不能描述为已上线自学习 |
| 工作流推荐 | 从可访问的已发布工作流生成建议 | 推荐接口不创建运行；本轮检查了代码和相关回归，未启动实际工作流 |

“语义意图判断 active”与“学习决策层 shadow”是两组不同开关；后者不会关闭前者的主模型意图判断。当前开发就绪度通过也不表示学习模型已上线。
