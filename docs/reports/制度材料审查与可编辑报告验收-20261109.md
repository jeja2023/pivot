# 制度材料审查与可编辑报告验收

日期：2026-11-09。源码版本v0.7.146。按用户要求完成“制度材料审查 → 可编辑报告”，没有新增应用运行依赖或数据库表。本轮不提交、部署或构建安装包。

## 交付结果

法规查询新增材料审查入口。用户选择制度、业务日期、材料与执行模型后，任务按八个条目一批持久执行；全部所选制度上下文和待审文字参与每批判断。仅匹配已复核有效版本，版本重叠、未复核、归档或来源变化时不继续生成结论。超过文字、条目或模型上下文边界时拒绝，不通过截断制造完整审查印象。

审查项分别为符合、不符合、待核实和不适用。符合/不符合必须带可逐字匹配的制度和材料引述，缺少或伪造引用转为待核实。原文引用包含制度版本、条文、可信页码或材料字符定位；片段匹配只是引用检查，不是业务结论已独立验证。报告保留初审和人工修订来源、未完成项及人工备注。

报告在同一查看页修订并保存新版本，再生成可编辑Word。服务端修订与导出登记使用预期版本和行锁，重复请求/同版本导出复用原记录；保存中继续输入的新内容不会被迟到响应覆盖，旧详情响应不覆盖新保存版本。续跑保留已完成批次、人工备注和累计用量，同时生成新的报告版本，不复用旧版导出。

来源检查覆盖审查查看页、通用工具任务读取、产物、所属Agent历史与文件下载。制度内容/效力变化、上传材料修改或撤回、账号失效及报告撤回后阻止旧结果读取。直接编辑普通产物不能改写审查报告绑定。已下载文件不在服务端撤回控制范围内。

Agent工具`policy.review_report`复用创建、进度、续跑、停止和Word导出链。仅登记任务不代表审查或交付完成；只有真实渲染结果才挂载文件。从Agent发起时收紧到原任务剩余额度，调用用量写入既有计量，并核对原任务状态、截止及持久化预算。界面任务继续接受用户模型权限和个人用量限制。

## 修复和环境记录

- 扩展故障回归发现默认取消信号的错误码可能为数值，错误分类原先调用字符串方法会二次异常；改为归一化分类，并验证取消后迟到结果不恢复为完成。
- 上下文预检在既有预算适配器可能抛错前先判断完整输入，统一返回分次处理提示，且检查适配前后消息一致，防止工具材料被静默裁剪。
- 修复保存期间继续输入和旧详情迟到覆盖的边界，浏览器实际保持新备注并再次保存成功。
- 最终扩展的账号重置复验中，后台同版本详情刷新偶发替换前端对象，使已成功导出的文件没有继续发起下载；将在途动作绑定改为报告标识和版本，保留跨任务/版本隔离，不把同版刷新当作用户切换报告。
- 来源校验收口到通用产物、交互空间与渲染入口：报告类型不能在另一套产物接口中被改写/公开分享；复制旧绑定的新假产物、任意IR冒充报告文件均拒绝。初次增加文件摘要检查时直接比较了未规范化IR，导致真实导出也被阻断；改为使用既有IR规范化结果比较，最终回归通过，未移除校验。
- 第一次Word页面检查发现大写页码占位符被当作字面量输出，改为现有渲染器支持的页码字段并新增真实DOCX页脚回归；正文段距和行距经再次渲染确认。
- 桌面没有LibreOffice，规范渲染脚本首次报告缺少可执行文件；Windows Word COM打开失败。后续建立仅用于本轮验收的独立渲染镜像，运行时禁网、只读根目录，仅挂载合成报告目录，使用规范`render_docx.py`完成页面检查。该环境不进入产品依赖或主镜像。
- 一次并行检查与浏览器启动同时生成样式文件，发生文件占用；后续顺序执行。异步扫描曾因新局部函数与存量同步函数同名误报，改为明确的审查函数名消除冲突，没有放宽白名单或门禁。

## 支持范围与未检查项

当前最多三份制度、四份材料、一百六十个条目，文字合计六万字符。上传支持TXT/Markdown、DOCX文字和文本型PDF，每份最多8MB；Word图片、嵌入附件和扫描识别不属于本次直接审查范围。PDF存在无法提取文字的页面时要求先完成文字识别复核。日期匹配只使用已登记的效力区间及复核状态，不能替代制度维护者确认真实适用性。

任务读取可在租约过期后恢复；没有打开任务且没有调用方查询时，本轮未增加独立扫描调度器。单次独立审查最多四十次模型调用、二百万计量Token，从属任务进一步收紧；中断在途请求的实际用量可能没有完整回执，不凭空补齐，也不清零已持久计数。

本轮没有真实业务部门签认、复杂例外与跨制度冲突的大规模金标评测、所有模型/格式/平台兼容、多节点、生产容量或灾备验收。没有运行全仓`npm test`/`npm run verify`。保留其它会话的并行BI/PDF/容器修改，不把这些修改算成本轮新增且已验收的功能。
