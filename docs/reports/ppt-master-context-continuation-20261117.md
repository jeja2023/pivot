# PPT Master 长任务续跑与阶段上下文优化

日期：2026-11-17。接续 [用量、轮询与恢复修复](ppt-master-repair-20261117.md)；未部署生产或构建新服务镜像。

## 已实现

- 长任务消息超过50万字符时，尝试归档较早的已确认写入正文和旧 `read` 观察。归档采用有界压缩、摘要校验，随原任务检查点在数据库保存；保留用户要求、确认答复、运行包权威指引和最近四轮模型动作。
- 归档前保存对应原始消息，模型可通过 `read_history` 按归档和消息编号分页读取原文。归档与更新后的消息在同一租约检查点持久化；读取任务仍绑定原账号。旧检查点在下一次模型调用前先尝试归档，不需要从头执行原有文件操作。
- 默认 Generate 仅在两次实际确认、同一项目的设计规范及锁文件有摘要匹配的写入回执、随后项目校验成功时，收起固定版本工作流的步骤1至3。保留跨阶段规则及步骤4至7、用户答复和原始检查点。需要旧章节时可通过 `read_runtime` 读取；版本或内容不匹配、证据不足、相关文件更改、工具失败、续跑或收到新的确认答复时回退完整指引。
- 固定包示例的确定性输入对照：项目估算器从 **23,650** 降至 **20,614 Token**，每次减少约 **3,036**。这是合成模型输入估算，不是供应方实际分词或生产费用；是否命中阶段条件取决于任务实际操作。

## 验证

- `presentation-master-history`、驱动、上下文、PostgreSQL及浏览器等相关批次 **39项通过**；后续加入超过旧限制的续跑和 `read_history` 动作后，驱动、上下文及PostgreSQL补充批次 **29项通过**。批次有重叠。
- 测试覆盖消息超65万字符后的归档与分页重建、摘要损坏拒绝、账号隔离、数据库保存与读取、保留最近动作和用户要求、续跑不重新执行历史文件动作；阶段测试覆盖确认不足、非默认流程、指引变化、写入摘要不符、锁文件修改与工具执行不明时回退。
- 项目 `npm run check`、改动文件 ESLint、SQL审核和治理指标检查通过。以上为本地隔离数据库、浏览器夹具和确定性模型测试，未调用生产收费模型。

## 剩余边界

- 阶段优化只覆盖该固定版本的默认 Generate 前置章节，不自动裁剪完整规划、制图和导出规则；其它模式或服务版本走完整指引。图片仍按现有策略重复发送，视觉复核未在本轮补齐。
- 为防资源耗尽，归档总编码大小上限8 MiB、最多64份；若不可归档的内容本身仍超65万字符或达到归档上限，任务会保留现有状态并提示分批处理。归档是模型可回读的原始消息，不等于生成的PPTX已完成或已通过视觉验收。
- 模型请求或外部动作在完成与保存之间中断，实际用量或动作结果仍可能不确定，继续前须核对。已丢失的生产工作区不能由本次代码重建。
- 未验证生产任务、真实计费、真实模型下的长文稿质量、多实例压力、完整Office视觉或灾备恢复，也未运行全仓测试。独立服务的读取及校准修复仍需重建部署，切换运行身份前须处理在途任务。
