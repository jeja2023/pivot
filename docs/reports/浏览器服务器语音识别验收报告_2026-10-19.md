# 浏览器服务器语音识别验收报告

日期：2026-10-19；版本：v0.7.4。

## 方案与授权

用户反馈普通浏览器仍因缺少 `zh-CN` 本地包而无法启动。经明确选择，允许短录音发送当前 Pivot 服务器识别，不保存录音、不转发第三方。本版新增部署内服务器通道，桌面原生桥和浏览器本地识别仍保留。

## 实现与边界

| 环节 | 行为 |
|---|---|
| 浏览器 | 同源 AudioWorklet 获取 PCM，按语音/静音切段；内存编码为单声道 16kHz PCM16 WAV，不写浏览器存储 |
| 传输 | 同源已登录接口；页面提示使用服务器识别；单段不超过 20 秒，最多两个待处理片段 |
| 服务器 | 验证 WAV 头、大小与语言，单用户一并发、全局两并发；每分钟最多 60 次；识别最长 30 秒，断线可取消 |
| 引擎 | Linux/Docker 使用镜像内置 Vosk 中文模型和 Python 工作进程；Windows 使用 `System.Speech` 内存 WaveStream。音频均经 stdin 输入，不创建录音文件，不发网络请求 |
| 释放 | 服务端结束后清理音频 Buffer 和请求引用；浏览器手动停止即释放麦克风，取消丢弃迟到结果 |
| 内容 | 临时文字沿用有界内存对话，不保存聊天、长期记忆和任务快照；普通语音草稿只有用户发送后才按聊天保存 |
| 不可用环境 | 镜像缺少 Vosk 依赖/模型、Windows 缺少语言引擎或管理员关闭时返回明确原因，不伪造可用或改用外部服务 |

用户进一步明确目标为 Linux/Docker，因此补齐 Docker 离线 Vosk 引擎并将轻量中文模型加入标准镜像。模型构建下载摘要为 `3af8b0e7e0f835ae9d414ce5df580237a3cfb08d586c9fbbb0f7ff29ad5b14ba`，运行期不会自动下载或把音频发到模型站点。识别准确率由引擎与模型决定，不宣称合成测试代表真实业务效果。

Docker 验证构建了语音阶段，使用本机已有 Pivot Linux 镜像作为兼容基础层；实际 HTTP 验证将本轮服务端源文件只读挂载到测试容器，确认新路由与运行库协同工作。没有将该测试阶段冒充完整生产镜像发布，也未更新用户远程部署。

真实引擎验证使用合成音频“你好，这是一个本地语音测试。”，经过浏览器相同 WAV 编码和真实 HTTP 识别接口。Windows 引擎返回“你好这是一个本地语音测序”，保留末词错误；目标 Linux/Docker 的 Vosk 引擎实际返回“你好这是一个本地语音测试”。测试没有使用真人麦克风，不能作为真人发音质量验收。

浏览器测试替换了音频硬件与识别响应，验证缺少中文包时仍使用录音路径、上传有效 WAV、填入草稿、连续两轮文本模型对话、朗读及停止。独立 HTTP 服务测试覆盖登录、无缓存、清理、参数和并发。聊天 SSE 与文本模型链路仍走真实测试服务，未被浏览器路由替换。

## 部署

Linux/Docker 需执行 `docker compose build pivot` 和 `docker compose up -d --no-deps --force-recreate pivot`，使运行库、模型和服务端代码一起进入新容器。页面刷新后加载音频采集脚本。无需新增数据库迁移或更新桌面程序。HTTPS/可信本地地址、客户端输入设备和麦克风授权仍是浏览器录音前提。
