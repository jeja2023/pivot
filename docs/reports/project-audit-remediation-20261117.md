## 持久化、性能及工程治理

- 审计与模型消费复用受控内容存储的异步文件写入、同步刷盘和原子提升，使用 `DATA_ENCRYPTION_KEY` 加密待写记录，目录为 `DATA_DIR/critical-write-journal`。成功确认前先保留恢复记录，数据库以 `delivery_id` 幂等写入；提交后删除恢复文件。数据库不可用、队列满载及记录异常不会按普通观测事件策略丢弃关键记录。
- 用量快照等待在途持久记录并与批次提交协调；有未加载的恢复积压或用量持久写失败时拒绝新的限额接纳。普通流式聊天也复用统一额度预留，并等待回复持久处理后释放。原有历史消息估算口径保留，不将估算冒充供应方精确账单。
- 审计响应边界位于压缩中间件之后，响应结束前等待审计文件确认；失败返回明确状态或结束已开始的流。数据库事务提交与本地审计文件写入并非跨存储的单一事务：业务已执行但审计写入失败时必须先刷新业务状态，不能盲目重复动作。
- `PIVOT_DB_WRITE_QUEUE_DISABLED` 只停用普通 API/MCP 观测缓冲，不能关闭关键审计和模型消费。现有队列监控增加持久化、恢复积压与消费存储故障状态。
- 完整离线备份清单升至 v3，加入关键待写目录；继续校验旧 v1/v2 包。物理恢复目录自动包含该目录，应用恢复演练同时验证待写审计只重放一次。
- 每日重型清理、备份、统计维护按顺序执行；单步失败记录后继续，停止后不启动剩余步骤。高频任务仍保留各自调度与防重叠控制。
- 知识治理与 Wiki 随知识工作区加载，项目空间复用现有脚本加载器按需加载；加载失败可重试，迟到结果须核对账号与编辑序列。未迁移 UI 框架、未新增依赖或独立样式体系。
- 首屏脚本原始审查基线为 72 个、1,196,488 字节、逐文件 gzip 322,413 字节；本轮加入刷新协调器并延迟加载三个大型模块后，最终测得 71 个、1,043,503 字节、逐文件 gzip 287,997 字节，原始字节减少约 12.8%，gzip 字节减少约 10.7%。不将静态字节减少等同于首屏时间改善。
- 新增来源校验、日账本查询和审计响应边界的 `@ts-check`，继续使用现有 tsc；新增事务 executor 架构门禁。没有宣称主项目所有 JavaScript 已获得类型检查。
- 测试临时盘预检同时检查可用容量与分析批处理的 85% 使用率门槛，避免进入场景后才因存储保护失败。
- Node、浏览器与应用恢复测试共用隔离存储环境，覆盖所有显式文件根及备份 Schema，避免继承开发环境的真实目录。恢复时额外发现受控文件位于点目录下会被 Express 默认隐藏规则拒绝，附件及 PDF/OCR/统一文档交付仅在归属与路径校验后允许该情况，继续禁止缓存。
- 样式生成跳过内容相同的文件，变更时先生成完整临时文件再替换，避免 Windows 文件读取期间无意义的截断写入；对应构建回归验证不变文件的时间戳保持和完整替换。
- 全量回归额外发现导图查看者首次打开时，编辑禁用晚于协作模块异步加载。现已在画布挂载后立即应用只读状态；协作浏览器回归故意延迟查看者模块下载，检查首帧按钮状态，再继续验证断网编辑与撤权。服务端权限边界保留。

## 升级、数据和恢复

迁移 `202611170002_model_consumption_ledger` 创建 `model_daily_consumption`，为审计和模型用量增加幂等标识及索引，安装消费捕获与共同恢复屏障。首次回填包含仍留在数据库内的历史消息（含软删除）和用量事件；对账本已存在的日期不重复回填。过去已经物理删除或从未持久保存的用量无法由此重建，不补造历史数字。

迁移需要对消息和用量表取得写入排他相关锁，生产升级应保留维护窗口，并先做与数据文件匹配的完整备份。日消费账本是持久事实，不可为了回退版本直接清空。新旧源码并行运行不在本轮支持范围内。

主服务停止总预算为十五秒，标准 Compose 的停止宽限设为二十秒；使用其他编排方式时需保留相应退出余量。总截止只约束本进程的退出，不承诺外部服务已完成业务动作。

恢复需要同时保留数据库、完整文件包和原数据加密密钥。不能把例行 `pg_dump` 成功视为包含所有文件和待写记录的完整恢复点。日志和用量目录损坏时应保留现场、恢复记录并对账，不得删除待写文件来消除告警。

`Clear-Site-Data` 是否生效取决于浏览器与安全上下文；旧版本已经缓存或用户已下载的文件不能被服务端追回。新响应禁止存储，受支持浏览器切号时另行清理缓存。内网 HTTP 的原有助手确认与签名边界不变。

继续保持单节点支持边界；多节点实时广播尚未就绪，不因本轮使用数据库账本就宣称支持集群。跨实例额度预留、事件传播与生产集群验收需要明确的容量需求后另行建设。
