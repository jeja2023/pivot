# Pivot 数据分析至汇报 PPT 体验改造验收

日期：2026-11-09。源码版本 v0.7.143。按用户选定的“数据分析 → 图表 → 汇报 PPT”落地本轮改造，复用现有分析、文稿、任务和下载能力，没有新增依赖。本轮未提交、部署或打包桌面安装程序。

## 交付结果

1. 分析图表可直接创建已保存的可编辑汇报，包含封面、结论与统计范围、原生图表和全部展示数据的分页明细。固定样例中，三条销售数据合并为华南180、华东150，生成四页文稿；刷新后保留，真实下载的PPTX含原生图表和嵌入工作簿。重复请求及并发请求复用同一文稿，修改标题后仍可按原请求打开。
2. 新增 `presentation.from_analysis` 工具，读取服务端实际图表快照，复用版式检查、PPTX内容核验和任务文件挂载，不要求模型重新抄写数值。该转换不额外调用生成模型；本轮验证直接工具执行，没有测量真实模型的工具选择成功率或整体Token降幅。
3. 快照记录来源版本、生成时间、统计口径、排序、分类上限、原始/导入范围及截断说明。数据或字段权限变化后，文稿、历史版本、投屏、产物及文件下载均重新核对；任务历史也复用来源读取门禁，不能从旧任务正文和文件入口绕回。保存不能移除已有分析来源绑定。
4. 类别排序不再描述为时间增长；空值不使最高值错配分类；图表有限数值不再强制截断到六位小数，舍入的文字摘要标为近似值。修复当前PPT导出库要求字符串讲稿、旧调用传数组导致多行备注核验失败的问题。
5. 对话任务把具体核验缺口和文件入口放到执行日志前，区分业务输入缺失、核验服务异常与内部交付缺口；部分完成和取消不再呈现为完整成功。分析请求绑定账号，旧响应不跨账号或数据集覆盖。
6. 浏览器回归实际暴露数据库连接超时被误判成无效令牌、继而退出登录的问题。服务端读取/刷新故障改为503，刷新故障不清理Cookie，浏览器不因暂时服务故障或断网关闭会话；真正失效、过期、来源不符或重放的凭证仍拒绝。

## 失败与环境记录

- 早期真实导出被多行备注核验阻断，按已安装导出库的字符串接口修正后通过，未关闭内容核验。
- 系统盘空间触发分析存储保护，后续隔离测试临时目录移至空间充足的测试盘，没有降低保护阈值。
- 共享PostgreSQL在并行测试时资源不足，改用独立临时PostgreSQL18集群并提高该测试集群锁资源，业务数据库和部署配置未改动。建表/启动超时保留为环境失败，未计入通过结果。
- 初次浏览器整组12/13通过：先发现旧提示断言，随后实际复现临时认证存储故障导致退出登录；修复前后端分类并增加故障恢复用例后最终14/14通过。
- 工作区同时存在其它BI、PDF和容器改动。早期全仓检查分别遇到其它改动的SQL审核、死导出、帮助文案及大文件门禁；这些记录不当作本轮功能测试通过。生成的证据/构建归档排除出源码lint与文本检查，源码、当前文档和密钥检查保留。

## 当前边界与后续验收

当前快捷入口支持标准数据集的柱形、折线、面积及饼图，最多80个分类、11个数值序列；饼图仅一个序列、最多20个分类。超过20个分类的图表分页，明细每页最多8行，保留全部已展示分类。复杂图类型和正式BI模型运行结果未接入此快捷入口；旧图表缺来源版本时需重新生成。汇报说明当前快照和统计范围，不自动推断因果、预测或批准业务结论。已下载文件无法由服务端撤回。

没有进行真实用户盲评、真实模型对本场景的连续任务评测、完整Hermes同模型成对复跑、Office/WPS兼容矩阵、生产容量/多节点/灾备验证或全仓`npm test`/`npm run verify`。本次结果证明所列功能与固定用例，不代表头部产品的综合体验已追平。

下一轮应以真实脱敏销售/经营资料建立固定验收集，分别记录业务结论正确性、来源支持率、编辑修改量、完整交付率、人工介入次数、时间与Token；再接正式模型结果和目标单位实际使用的办公连接器。没有连接系统与业务样例前，不虚构已接通的集成或收益。
