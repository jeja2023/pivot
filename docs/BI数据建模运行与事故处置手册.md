# BI 数据建模运行与事故处置手册

独立安全记录中断、恢复撤权重放与当前身份授权签认，按[安全日志与恢复授权核对](BI安全日志与恢复授权核对.md)执行；日志待确认与恢复读取关闭不能通过执行开关或旧客户端绕过。

适用范围：生产级建设方案 v2.0 的 BI-11、BI-12，以及后续恢复和发布工作。本文随候选实现交付；目标生产硬件、七十二小时稳定性、独立故障域恢复和业务签认仍按用户要求暂缓。生产开放须完成方案 G0—G7，不以本机通过项代替目标环境认证。

## 1. 运行合同与部署核对

保持单活 API 和控制服务。正式重型分析在带摘要的 Linux 容器内执行，镜像预先安装，运行时不联网拉取。启用前确认数据库迁移、对象内容校验、只读输入和根目录、禁止网络及扩展、真实终止检查均通过。

完整隔离与主动取消预检在进程启动、镜像/运行模式变化和强制核查时执行，保留独立时间戳；空间每次准入检查，数据库保护每分钟轻量复核。周期检查不重复创建取消试验来阻塞业务请求，保护缺失仍立即停止该次准入。

- 全局运行二个任务、排队十六个；每人运行一个、排队三个。模型与原有重型数据分析共用数据库预算。
- DuckDB 内存一 GiB，容器硬内存二 GiB、二线程、六十四个进程、溢写八 GiB。导入、检查和导出使用批处理队列，最多一个批次占用运行槽。
- API 每秒尝试领取任务；正在运行的长任务不阻止另一个槽位继续调度。排队截止一百二十秒，交互执行六十秒，检查和导出三百秒；重试保留业务总截止。
- 输入档位为二十万或一百万事实行、维度合计不超过两百万行、每表一百二十列、八条关系、模型总输入二 GiB。普通上传入口保持原上限，百万行使用受控分块摄取。
- 交互最多展示五千组，默认预览一百行；导出最多二十万结果行或二百 MiB。总计覆盖完整过滤范围，去重和比率在对应统计范围重算。
- 空间达到百分之七十预警、八十五停止批量写入、九十五停止新写入；还须保留至少两个最大并发任务的绝对空间。有效引用不参与按年龄腾挪。

受控导入逐字节验证分块，保留 UTF-8、引号内换行和文本编码。格式探测行数仅用于解析准备，后续严格读取完整文件。Parquet 写入采用受控缓冲和较小行组；模型按业务粒度、成员键及显式排序计算，不承诺以文件物理行序作为分析顺序。宽字符串画像使用哈希分桶规划内存，每桶仍按原值精确去重。

调优依据见 [DuckDB 1.5 工作负载调优](https://duckdb.org/docs/1.5/guides/performance/how_to_tune_workloads)、[CSV 参数](https://duckdb.org/docs/1.5/data/csv/overview)和 [Parquet 行组说明](https://duckdb.org/docs/1.5/data/parquet/tips)。所有调整须保留构建、参数和原始报告，禁止提高资源或超时上限以改写验收结果。

## 2. 初始化专用合成监控

先在已完成迁移和执行器预检的候选服务上，由系统管理员核对并初始化。下列命令读取服务端既有环境配置，不在命令行传连接串或密钥；`1` 替换为实际系统管理员账号 ID。

```text
node scripts/bi_operations.js --admin-id 1 --bootstrap-probe
node scripts/bi_operations.js --admin-id 1 --preflight
node scripts/bi_operations.js --admin-id 1 --check
node scripts/bi_operations.js --admin-id 1
```

自举使用现有数据集、草稿、检查和发布链路，创建两个普通专用账号、个人验收来源和个人验收模型。账号不签发交互登录凭据、会话或 API Key。正向数据固定三条验收记录，金额总计 `250.00`、记录数 `3`；反向账号没有模型及来源权限。重复初始化返回已有配置。专用账号、来源和模型不得混入业务数据，也不得授予管理员角色或全库连接。

运行时每十五秒巡检，一分钟登记一次幂等正向任务并验证反向账号拒绝；完成后比较独立预期哈希。检查内容仅来自已配置的专用模型、发布版本和个人来源，配置时核对所有者、普通账号、禁用交互登录标记及来源范围。停用、账号变化或合同缺失显示明确失败，不伪造成功历史。

系统管理员还可调用以下受鉴权接口，普通用户不能使用：

| 接口 | 用途 |
| --- | --- |
| `GET /api/apps/data-analysis/operations` | 三十天 SLI、观察起点、队列、空间、数据库池、执行资源、探针及事故状态 |
| `POST /api/apps/data-analysis/operations/preflight` | 在维护窗口、现有任务排空后执行完整隔离与真实取消预检 |
| `POST /api/apps/data-analysis/operations/probe` | 配置或停用专用探针；指标至多三个，不接受任意分组和筛选 |
| `POST /api/apps/data-analysis/operations/check` | 立即核查状态与告警 |
| `POST /api/apps/data-analysis/operations/fence` | 填写原因并暂停业务读取和新分析 |
| `POST /api/apps/data-analysis/operations/resume` | 最近九十秒正反向探针成功后，填写原因恢复业务 |

上线前必须完成探针初始化并演练关闭、核查、恢复。事故关闭后保留原有专用配置；关闭期间仅允许配置中的专用账号核对该验收模型，业务结果继续拒绝。

## 3. SLI 口径与误差预算

控制接口和已接纳任务分开统计，固定类型与结果类别按分钟持久聚合，保留三十天。用户、模型、版本、任务和执行代次保留在受控运行与审计记录，避免作为无限增长的监控标签。返回真实观察起点；观察不足三十天时标明窗口尚未完整，零样本可用性为空。

| 分类 | 计入平台成功率分母 | 处理 |
| --- | --- | --- |
| 授权范围内的正常请求或完成任务 | 是 | 成功 |
| 服务错误、内部超时、执行失联耗尽重试、配额内误拒绝 | 是 | 平台失败 |
| 完整质量检查正确发现脏数据 | 是 | 平台成功，另记质量失败 |
| 鉴权拒绝、非法输入、明确超出公布配额 | 否 | 独立记录数量 |
| 用户主动取消 | 否 | 独立记录数量和终止情况 |
| 内部截止、系统取消或过载取消 | 是 | 平台失败，不能改写为用户取消 |

任务终态与 SLI 同事务登记，重复完成、失败或取消不重复计数。持久取消原因区分 `user` 与 `system`；重复取消不重置首次意图。重试仅在最终失败时消耗终态预算。计划维护造成的有效请求失败继续计入窗口。

默认目标为控制接口及任务成功率各百分之九十九点九。报告同时提供实际分母、失败数、允许失败数、剩余预算和延迟直方图；累计分位数给出桶上界，不冒充逐请求精确分位数。预算耗尽时暂停非修复性生产变更，先完成事故修复。

运行记录包含排队、来源准备、隔离运行、结果登记、Worker CPU、进程 RSS、容器峰值和溢写采样；缺失的故障测量保持缺失。结果登记测量覆盖对象固定和提交准备，数据库最终提交尾耗时由完整请求或任务可读时延包含。

## 4. 告警路由与独立探活

复用“系统设置”的可观测事件与 Webhook 配置。事件来源使用 `data-analysis.bi.*`，正文为中文。事件持久去重五分钟，状态恢复后再次出现会重新登记事件；Webhook 沿用既有安全地址检查、超时、去重和脱敏，仅发送定位摘要及哈希。

必须处理：误差预算耗尽、存储阈值、等待超过三十秒、失联槽位、资源越界、完整性发现、陈旧或刷新失败、共同恢复点超过十五分钟、审计副本待确认、探针失败或陈旧、调度心跳超过三十秒以及统计/权限事故关闭。

在独立监测位置每十五秒探测 `/api/health`，连续失败立即通知值班人员；通知链路不得与唯一 API 主机同故障域。应用内巡检每十五秒检查调度心跳和探针状态。独立探活、Webhook 接收、升级联系人与值班备份须在目标环境实测并登记；本机本地 Webhook 接收试验仅证明接线和脱敏行为。

## 5. 事故首要动作

| 级别 | 触发 | 首要动作 |
| --- | --- | --- |
| SEV1 | 已确认错误结果、越权、对象损坏或硬资源越界 | 五分钟内响应、十五分钟内初步隔离；暂停受影响业务，保护证据与当前成功版本，通知业务和安全负责人 |
| SEV1 | 服务不可用、数据库或主存储故障 | 五分钟内响应，停止接纳，保护队列与最后成功状态，按单活接管或恢复合同处理 |
| SEV2 | 持续延迟、误差预算耗尽、恢复点/安全副本或数据时效超限 | 十五分钟内响应，暂停非修复变更，核对数据库、版本存储、备份和安全日志，不开放未经核验的恢复数据 |
| SEV3 | 非关键展示、受控配额或个别可解释输入失败 | 保留诊断并进入维护排期；定位来源、口径或范围，确认后重新检查或提交 |

暂停与恢复可使用受鉴权接口，也可在受控服务端执行：

```text
node scripts/bi_operations.js --admin-id 1 --fence --reason "已发现统计或权限异常，开始核查"
node scripts/bi_operations.js --admin-id 1 --check
node scripts/bi_operations.js --admin-id 1 --resume --reason "已完成修复及正反向核对"
```

自动探针确认错误结果或反向意外准入后，先持久关闭业务交付并记录审计，再发告警。关闭与响应共用数据库栅栏：已取得读取栅栏的响应先完成，关闭提交后的新业务交付被拒绝。更正预期值或恢复配置不会自动开放业务，须由系统管理员在最近成功核查后填写原因恢复。

排障时记录构建标识、模型及版本、运行 ID、执行代次、错误代码、最近成功清单、资源测量和时间范围。普通日志不保存筛选原值、SQL 参数、下载凭据或密钥。进程强制退出时保留的阶段诊断仅含阶段、列序号和 RSS，读取上限四 KiB。

## 6. 容量重现与证据边界

```text
node scripts/benchmark_bi_modeling.js --runtime development_process --samples 3 --report output/bi-capacity-development.json
node scripts/benchmark_bi_modeling.js --runtime docker --image sha256:实际已安装摘要 --samples 3 --report output/bi-capacity-docker.json
```

脚本复用隔离 PostgreSQL schema、受控分批摄取、持久任务、当前身份授权和真实 HTTP 读取。两档包含九张一百二十列表、复合键、倾斜、高基数、宽字符串及未匹配记录；每个输入记录行数、字节和 SHA-256，单独报告导入、全量检查、常用/复杂查询、持久结果读取与资源。

每次查询采用新的执行器进程，当前没有查询结果缓存；文件系统缓存未受控时明确标注。短样本的 p95 仅描述该批样本。十会话、五秒间隔与混合刷新专项是本地调度烟测，报告源数据规模和持续时间；七十二小时及完整缓存场景仍在目标环境认证。

参考认证环境最低八 vCPU、三十二 GiB 内存和五百 GiB 可用 SSD，数据库至少四 vCPU、十六 GiB。配置达标后仍须实测。当前本机内存十六 GiB，Docker Desktop 启动及后台构建会影响尾延迟；失败样本和阈值未达项保留，不能以功能断言通过代替性能达标。

## 7. 值班与交接登记

以下信息由目标环境责任人签认，当前暂缓，不填入假姓名或虚构值班表：业务负责人、模型维护人、API/执行器值班、数据库与 WAL 负责人、版本存储与独立备份负责人、安全事件副本负责人、告警接收地址、升级备份联系人，以及 G0—G7 签认和最近演练证据包路径。

独立安全日志、共同恢复点、隔离恢复、升级回退与离线制品按 M5 配套交付。上述能力未通过相应门禁前，候选功能保持候选状态。

## 8. 共享整库恢复

每日完整物理备份、连续 WAL、五分钟共同恢复点与独立安全日志分别监测。恢复点不能只有数据库成功或对象仍在复制；缺少对象、密钥、链或当前授权证明时保持关闭。部署与实际全失还原步骤见[共享数据库与文件共同恢复手册](BI共享数据库与文件共同恢复操作手册.md)，本地工程结果见[证据报告](reports/BI共享整库物理恢复本地证据-20261107.md)。

## 9. 发布维护与兼容回退

通过 `node scripts/bi_operations.js --admin-id <当前系统管理员ID> --release-status` 核对开关、修订、队列、槽位及实际执行单元。操作使用当前系统管理员身份、原因和预期修订，例如 `--release-action stop_admission --expected-revision <当前修订> --reason <维护原因>`；`drain` 允许已排队任务继续执行，`pause` 停止领取，`--cancel` 将剩余任务记为系统取消。单次 `--wait-seconds` 最多三十秒。

替换制品前执行 `prepare_rollback`，核对 `readyForBinaryChange` 为真，再隔离旧进程，使用已核对兼容的固定制品启动单个服务。不得降级 Schema、删除新发布资产或并行保留旧调度。恢复使用 `resume` 并重新携带当前修订；完整预检、当前授权、队列和执行单元核对通过后才开放领取/准入，`--reopen-writes` 明确同时恢复新建/发布。日志副本异常时收紧可能已经提交，对待确认操作按同一事件继续确认，不重复假装回滚。见[实际冻结制品证据](reports/BI升级回退本地证据-20261107.md)。
