# BI 数据建模支持矩阵与交付清单

## v0.7.145 节点流与目录增量（2026-11-09）

- 节点预览及物化采用统一持久队列与隔离 Worker，支持状态、取消、幂等、当前权限交付及历史查询；物化数据集与任务成功原子登记。关闭执行开关、归档模型或来源撤权时拒绝相应操作。
- 输出版本保存全部来源、原截止时间、部分/未知覆盖声明和固定预览。迁移将没有完整血缘的旧 `modeled` 数据集保守标为未知范围；原发布快照保持不变。
- 目录支持服务端搜索、归属/生命周期/数据状态筛选、稳定分页和真实总数，分析来源选择与问数目录同步适配。
- 节点接口改为 `202 { job }`，通过现有异步查询接口读取任务。旧客户端缺少请求标识或修订时提示刷新，不回退至 API 进程内直接执行。部署时先排空任务，升级数据库/API 和 Worker；Worker 就绪探针必须声明 `node_flow` 能力。保留兼容读取端后再启用，不能运行只理解旧任务类型的调度器。
- 本增量不改变下文历史生产容量、安全/签名及 G0—G7 的记录；实际专项验证见[八项优化交付记录](reports/数据建模八项优化交付-20261109.md)。

本次通过版本同步启用 v0.7.145 源码标识；接口、迁移和 Worker 升级合同见[发布说明](releases/v0.7.145-数据建模八项治理与计算一致性优化.md)。已有本机镜像、归档和安装包继续使用其原始身份，不因版本号变更视为完成新制品验证。

核对日期：2026-11-07。范围为建设方案 v2.0 M0—M5、BI-01—BI-16，以及用户补充的第25节可视化拖拽。当前为本机隔离候选验证，目标生产环境验证依用户要求暂缓；本文不授予部署或生产开放权限。

## 容量、语义与权限

正式语义上限为一个事实节点、最多八张不同维度表/八条关系、一至三对等值键、仅左/内关联及根向外一对一/多对一；查询最多五个分组维度和十个指标。派生依赖最多三层、一百个AST节点；结构化条件、参数、请求体、交互展示及导出均执行固定配额。范围外操作明确拒绝，不通过隐藏开关开放多事实、桥接、任意脚本或SQL。

P-Standard为二十万事实行，P-Large为一百万事实行、维度总量不超过二百万行；两档均包含九来源、一百二十列、倾斜、复合键、宽字符串和未匹配样本的本机原始结果。百万档位走独立受控摄取，不扩大普通上传入口。目标硬件认证、冷/热存储的完整测量及七十二小时持续负载暂缓；当前标准常用p95为7302ms，超过5000ms；大档常用/复杂p95为14875/27811ms。旧失败保留，目标生产容量未认证。

所有者维护、显式只读共享、已有来源权限的另一人业务复核、当前主体/单位及字段授权均沿用项目既有体系。共享模型不扩大来源权限；管理员身份不新增跨用户数据读取特权。工作流与计划固定运行主体，实际交付前复核接收者。所有者交接须双向确认并重新核对历史依赖及计划；转移模型不转移数据集或凭据。

## 发布、安装与恢复检查

- 最终API、协调器和Worker以不可变镜像摘要执行本机验收；安装包、锁文件、组件清单和日志均登记SHA-256。镜像离线加载后再执行原生模块、字体、版本与真实链路校验。
- Windows安装前仅核对目标目录的运行进程，发现仍在运行或查询不可用时停止，不自动终止其它同名客户端。本机验收使用独立AppID、NSIS GUID、安装路径和明确的Electron用户数据目录；不能只靠`APPDATA`环境变量隔离用户配置。
- 当前已有`Pivot Local Dev`自签名证书没有受信任根链，项目签名门禁实际拒绝；不调整系统信任、不跳过签名门禁，也不将本机功能安装等同于正式可信签名交付。组织正式证书和发布授权在目标环境核对。
- 升级先关闭新建/发布和接纳、排空或取消并确认执行单元结束，再替换兼容读取端和Worker。保留旧快照及受控文件；回退使用支持新Schema的兼容服务，不执行破坏性降级DDL。
- 共同恢复点覆盖共享整库及其它应用必要文件、配置和密钥；本机已验证源数据目录全失、新PGDATA/WAL还原、独立当前授权核对、旧令牌拒绝及业务重算。目标生产100GiB、异机故障域、TLS/静态加密与密钥保管责任不由小样本本机演练代替。
