# 统信 UOS 桌面客户端打包指南（AMD64 / ARM64 与龙芯限制说明）

本文档介绍如何在 **Linux 原生或同架构容器打包机环境** 下构建用于 **离线内网统信 UOS 电脑** 的 Pivot 智枢 Linux 客户端。当前正式支持范围为 **AMD64** 和 **ARM64**；龙芯 3A6000 / LoongArch64 暂未纳入正式发布范围。

---

## 一、 核心机制：离线电脑如何安装运行

`electron-builder` 构建的 `.deb` 安装包内置 Electron、Node.js 和应用代码，但仍声明 UOS 系统运行库依赖；离线部署必须提前核对这些依赖是否已在系统镜像中安装。

- 包内已内嵌：**Electron 运行时** + **Node.js 引擎** + **客户端 UI** + **内置服务逻辑** + **已编译好的 Native C++ 动态库**。
- **离线电脑要求**：AMD64/ARM64 统信电脑无需连接互联网即可安装，但必须预装 `.deb` 声明的 GTK、NSS、通知和桌面集成依赖；若系统缺少依赖，应准备离线 apt 仓库或依赖包集合。

---

## 二、 硬件架构与打包命令

| 目标芯片 | 架构名称 | 离线终端类型 | Linux 打包命令 | 产物安装包 |
| :--- | :--- | :--- | :--- | :--- |
| **麒麟 9000 系列** | `arm64` (`aarch64`) | 华为擎云 / MateView 统信桌面电脑 | `npm run dist:linux:arm64` | `pivot_0.1.36_arm64.deb` |
| **x86 架构** | `x64` (`amd64`) | 标准 x86 统信 / Ubuntu 电脑 | `npm run dist:linux:x64` | `pivot_0.1.36_amd64.deb` |
| **龙芯 3A6000** | `loong64` | 暂不支持正式打包 | `npm run dist:loong64`（明确拒绝） | 无 |

---

## 三、 在 Ubuntu 打包机上操作步骤

在可连网的 Ubuntu 打包机上执行：

```bash
# 1. 安装基础构建工具链（Node.js 22.12+，Electron 43 构建要求）
sudo apt update
sudo apt install -y build-essential python3 g++ libvips-dev xz-utils ruby ruby-dev rpm

# 2. 进入项目根目录
cd pivot

# 3. 使用干净的目标架构工作区安装依赖
rm -rf node_modules
npm ci

# 4. 准备目标架构运行包。Linux 发布要求内置 Python；浏览器必须是 Linux 目标架构版本。
npx playwright install chromium
export PIVOT_AGENT_PYTHON=/opt/pivot-python/bin/python3
export PIVOT_REQUIRE_BUNDLED_PYTHON=true

# 5. 执行构建前门禁
npm run check:desktop:linux

# 6. 执行对应架构的打包命令
# 打包 麒麟 9000 (ARM64) 包：
npm run dist:linux:arm64

# 打包 龙芯 3A6000 (LoongArch64) 包：
# 龙芯命令会明确失败，不生成不可运行的伪安装包
npm run dist:loong64
```

## 四、 跨 CPU 架构打包（QEMU / Docker 推荐方案）

如果 Ubuntu 打包机是普通 **x86_64 CPU**，推荐使用 QEMU 运行目标架构 Linux 容器构建 ARM64。LoongArch64 不属于当前 Electron Builder 支持架构，不能通过普通 Node 容器解决：

```bash
# 在 Ubuntu 上开启 QEMU 跨架构支持
docker run --rm --privileged tonistiigi/binfmt --install all

# 使用 ARM64 容器打包麒麟 9000 离线包；工作区不得复用宿主机 node_modules
docker run --rm --platform linux/arm64 -v $(pwd):/app -w /app arm64v8/node:22-bookworm \
  bash -lc "rm -rf node_modules && npm ci && npx playwright install chromium && npm run check:desktop:linux && npm run dist:linux:arm64"

# LoongArch64 当前不构建。只有完成自定义 Electron、DuckDB、Sharp 和 Chromium 适配后才能重新开放。
```

## 五、 离线统信电脑安装部署

1. 在目标架构 Linux 打包机上完成后，在 `downloads/` 目录中找到生成的 `.deb` 文件：
   - `pivot_0.1.36_arm64.deb`（适用于麒麟 9000 统信电脑）
   - `pivot_0.1.36_amd64.deb`（适用于 AMD64 统信电脑）
2. 使用 **U 盘 / 安全光盘** 拷贝对应的 `.deb` 安装包至离线统信电脑。
3. 先检查依赖：`dpkg-deb -I pivot_*.deb`；确认目标系统已安装依赖后，再双击 `.deb` 或执行 `sudo dpkg -i pivot_*.deb`。
4. 若 `dpkg -i` 报缺少依赖，不要在离线机执行联网修复；应从同版本 UOS 安装介质或离线 apt 仓库补齐依赖后重试。

## 六、运行包与架构验收

每个 Linux 构建必须在封装前通过以下门禁：

```bash
npm run check:desktop:linux
node scripts/verify_desktop_runtime.js linux "$(uname -m | sed 's/aarch64/arm64/;s/x86_64/x64/')"
```

门禁会验证 Electron Builder 目标、Linux 元数据、PNG 图标、浏览器/Python manifest，并实际加载 `better-sqlite3`、DuckDB、Sharp 和 unzipper。目标架构与构建机架构不一致时默认拒绝，避免把宿主机原生模块混入安装包。

Linux 发布文件应分平台保存：

```text
SHA256SUMS-linux-amd64.txt
SHA256SUMS-linux-arm64.txt
SHA256SUMS.txt                 # 两个平台清单的合并索引
```

## 七、当前明确不支持的能力

- LoongArch64 / 龙芯 3A6000：Electron Builder 架构枚举、Electron 官方二进制、DuckDB、Sharp 和 Playwright Chromium 尚未形成完整发布链。
- 在 Windows x64 工作区直接交叉生成可运行的 UOS ARM64 包：除非使用目标架构 Linux 容器并设置经过验证的交叉构建方案。
- 未配置 `PIVOT_AGENT_PYTHON` 时生成“完全离线”的 Linux 客户端：Linux 构建会直接失败，避免把宿主机 Python 回退误包装成内置运行时。
