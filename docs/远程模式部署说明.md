# Pivot Windows App 远程模式部署说明

本桌面包支持“一个安装包 + 外置 config.json”的分发方式。IT 可以给所有用户分发同一个安装器；需要切换生产、测试或 UAT 环境时，只替换 config.json，终端用户无感。

## 分发文件

- `Pivot Setup <version>.exe`：由 `npm run dist:win` 生成的 Windows 安装器。
- `config.json`：真实环境配置文件，安装后放到 `Pivot.exe` 同目录，或通过 `--config <path>` 指定。
- `config.example.json`：配置模板，随包放入 `resources`，仅供复制修改，不会自动作为真实配置加载。

## 配置加载优先级

桌面端按下面顺序查找配置，找到第一份存在的 `config.json` 后停止：

1. 命令行：`Pivot.exe --config C:\Pivot\config.json`
2. 环境变量：`PIVOT_DESKTOP_CONFIG=C:\Pivot\config.json`
3. `Pivot.exe` 同目录下的 `config.json`
4. 安装包 `resources/config.json`

如果以上位置都没有配置文件，应用会进入本地模式默认配置。

## 内网 HTTP 配置示例

适用于无互联网、无公网 IPv4/IPv6、无域名、无 HTTPS 证书、只能通过局域网 HTTP 访问 Pivot 的生产环境。复制为 `config.json` 后，把 `remoteUrl` 改成客户端实际能够访问的局域网地址。

Pivot 不要求公网 IP、DNS 域名或证书，但远程模式必须存在一种可达地址：私有 IPv4（如 `http://192.168.10.20:3000/`）、IPv6 字面量（如 `http://[fd00::20]:3000/`）或局域网可解析的操作系统主机名（如 `http://PIVOT-SERVER:3000/`）。如果网络中确实既没有任何 IP 地址，也没有可解析的主机名，客户端与服务器之间无法建立 HTTP 连接，应使用桌面本地模式或先建立局域网寻址。

```json
{
  "mode": "remote",
  "environmentName": "Production LAN",
  "remoteUrl": "http://192.168.10.20:3000/",
  "partition": "persist:pivot-production",
  "windowTitle": "智枢 Pivot",
  "allowExternalOpen": false,
  "allowedExternalOrigins": [],
  "autoUpdate": {
    "enabled": false,
    "path": "/downloads/",
    "url": "",
    "checkOnStart": true,
    "autoDownload": true,
    "allowPrerelease": false,
    "allowInsecureHttp": false,
    "allowedOrigins": [],
    "installOnQuit": true
  }
}
```

## 字段说明

- `mode`：`remote` 连接已有 Pivot 服务；`local` 启动安装包内置的本地服务。
- `environmentName`：显示在窗口标题中，建议填写 `Production LAN`、`UAT`、`Test` 等环境名。
- `remoteUrl`：远程模式必填，只允许 `http` 或 `https` URL。
- `partition`：Electron 会话分区。建议每个环境使用不同值，隔离 Cookie 和缓存。
- `windowTitle`：窗口标题前缀。
- `allowExternalOpen`：默认 `false`。只有同时配置 `allowedExternalOrigins` 时才允许在系统浏览器打开外链。
- `allowedExternalOrigins`：受信任外部站点的完整 Origin 列表，例如 `["https://docs.example.com"]`。不得填写路径、查询参数、账号信息或通配符。

## 自动升级配置

在没有 HTTPS 证书和 Windows 代码签名证书的局域网中，建议保持 `enabled=false`，通过受控共享目录或离线介质分发安装包，并使用构建时生成的 `SHA256SUMS.txt` 校验完整性。业务页面使用 HTTP 不要求同时启用 HTTP 自动更新；只有发布链可信时才单独启用更新能力。

`autoUpdate` 控制 App 自动升级。默认情况下升级目录可与业务服务器同站复用 `/downloads/`；如填写 `autoUpdate.url`，则升级服务器地址可以与业务服务器地址相互独立。

- `enabled`：是否启用自动升级。正式启用时改成 `true`。
- `path`：同站更新目录，默认 `/downloads/`。当 `url` 为空且自动升级启用时，会基于 `remoteUrl` 推导更新源。
- `url`：独立更新文件目录。为空时使用 `path`；填写时会覆盖同站推导结果，程序会自动补齐目录末尾的 `/`。
- `allowInsecureHttp`：是否允许 HTTP 更新源。默认 `false`；无 HTTPS 的离线局域网生产环境需要显式设为 `true`。
- `allowedOrigins`：允许的更新源 origin。启用 HTTP 更新且不是本机 loopback 时必填，可直接使用内网地址，例如 `["http://192.168.10.20:3000"]`，不要求域名或证书。
- `checkOnStart`：启动后自动检查更新。
- `autoDownload`：发现新版本后自动下载。
- `allowPrerelease`：是否允许预发布版本。
- `installOnQuit`：下载完成后，退出 App 时自动安装。

下载完成后，App 会提示用户重启并安装更新。生产环境建议配合代码签名证书，降低 Windows SmartScreen 和 UAC 干扰。

## 自动升级发布流程

每次发布新版本时：

1. 更新 `CHANGELOG.md` 顶部版本号，并执行 `node scripts/sync_version.js` 同步 `package.json` 和锁文件。
2. 执行 `npm run dist:win`。
3. 打包脚本会自动把下面文件复制到 `downloads/`：
   - `Pivot Setup <version>.exe`
   - `Pivot Setup <version>.exe.blockmap`
   - `latest.yml`
   - `Pivot-Setup.exe`（网页登录页下载入口）
   - `SHA256SUMS.txt`（上述发布文件的 SHA-256 完整性清单）
4. 如果生产环境通过 Docker volume 挂载 `downloads/`，同步或替换该目录文件即可发布新客户端。
5. 已安装客户端启动后会检查 `latest.yml`，发现新版本后自动下载并提示安装。

## 换环境方式

从 UAT 切换到生产时，只需要把用户机器上的 `config.json` 替换为生产配置。安装包和应用本体不用重新分发。

## 异常页与重试

远程服务不可达、VPN 未连接或证书/网络异常时，应用会显示内置错误页，页面包含环境名、目标地址和“重试”按钮。用户恢复网络后可直接重试，不会看到原始 Chromium 错误页。

## IT 注意事项

- 有 HTTPS 时优先使用 HTTPS；无公网地址、无域名、无证书的隔离局域网可直接使用 HTTP。业务访问只需配置可达的 `remoteUrl`，不需要设置 `autoUpdate.allowInsecureHttp`。
- 在纯 HTTP 环境中通过防火墙只向受控网段开放服务端口，并保持 `COOKIE_SECURE=false`；不要把该监听端口直接暴露到公网。
- 只有明确启用 HTTP 自动更新时才设置 `allowInsecureHttp=true` 和 `allowedOrigins`；`allowedOrigins` 必须与更新源的协议、主机和端口完全一致。
- 确认 `remoteUrl` 和自动更新目录（默认 `remoteUrl + /downloads/`，或显式 `autoUpdate.url`）在用户内网中可访问。
- 同一环境保持 `partition` 稳定，便于保留登录状态。
- 测试和生产使用不同 `partition`，避免 Cookie 或缓存串环境。
