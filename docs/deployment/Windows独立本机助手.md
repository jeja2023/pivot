# Windows 独立本机助手

源码发布基线为 v0.7.165，汇总HTTP直连和网页下载入口，完整范围见[v0.7.165发布说明](../releases/v0.7.165-智能路由与助手HTTP下载体验优化.md)。早期功能和布局验证保留v0.7.162身份；现有HTTP兼容安装包仍为v0.7.164未签名验证包，范围及制品见[HTTP兼容记录](../reports/windows-local-helper-http-20261116.md)，不因本次升版改名或重新打包。源码版本及开发包不代表已签名或部署生产，原助手基础范围见[v0.7.164发布说明](../releases/v0.7.164-Windows独立助手与浏览器本机控制.md)。

独立助手安装在浏览器所在的 Windows 电脑，支持当前前台且已授权应用的控件摘要、截图、点击、非密码字段输入和等待。服务器处理模型调用与任务治理，助手执行本机动作。助手不会开放任意 Shell、屏幕坐标注入或浏览器密码库。

## 部署与使用

1. 更新 Pivot 主应用并执行正常启动迁移，确认 `202611160001_web_local_helper` 已完成。助手支持 HTTPS、本机 HTTP 和经本机确认的远程 HTTP 直连。如果已部署这些配对接口，本次 HTTP 兼容只需更新助手，无新增迁移。
2. 在要操作的 Windows 电脑安装助手。启动后，在浏览器中登录 Pivot，进入“工具库 → 本机授权中心”，点击“生成助手配对码”。将完整配对码复制到助手，填写同一服务根地址并配对；协议、主机和端口均应与浏览器一致，不能附带页面路径。配对码五分钟内有效且只能使用一次。远程 HTTP 会先弹出本机确认，显示具体地址和明文传输说明；选择继续后才向该地址发送配对信息，取消不影响原有连接。
3. 在助手本机确认服务地址和账号。随后填写目标应用的完整窗口标题与进程名，点击“授权应用”。在浏览器中刷新工具库，可以看到当前浏览器绑定的助手能力。
4. 将目标应用置于前台，再通过已授权工具发起任务。助手会在本机逐次确认；填写操作展示拟输入文字，截图会说明回传当前服务。允许后请在3秒内切回授权应用，执行时再次核对前台窗口。目标应用不匹配、密码字段、过期任务或撤销授权会被拒绝。
5. 浏览器配对期间保持页面打开。浏览器连接超过45秒未续期后停止接纳新的助手操作；正常退出账号会撤销绑定。关闭助手会停止本机驱动并断开连接，再次启动需要重新配对。异常退出后的凭据采用系统安全存储加密恢复，但仍受服务端到期和撤销约束。

助手“断开并更换账号”会先停止并等待旧任务结束，再撤销连接及清除本机授权。新账号重新配对并授权，使用独立的新设备身份。撤销应用授权不会删除目标应用的数据；已开始的外部操作不能承诺回滚，结果不明时先核对目标应用。

远程 HTTP 可直接填写现有 `http://服务器地址:端口`，不需要 HTTPS 反向代理或隧道。连接后状态栏持续显示“HTTP 明文直连”。确认仅随当前连接保存到本机加密存储，恢复时必须与原 Origin 完全一致；更换地址或重新配对需重新确认，不跟随重定向，也不自动从 HTTPS 降级。

HTTP 不加密传输，配对凭据、截图和操作内容仍可能被窃听或篡改；设备签名、账号与浏览器绑定及逐次本机确认继续生效，但不等于具备 HTTPS 的传输保护。HTTP 站点还需保证服务端登录 Cookie 配置与协议匹配，不能要求浏览器通过 HTTP 发送仅限 HTTPS 的 Cookie。

助手默认窗口为620×620，采用紧凑的横向标签表单；最小支持540×600。进程名可以选择常用建议或自行输入，仍需核对真实窗口标题和进程。支持尺寸下明暗主题及长状态布局验证见[布局记录](../reports/windows-local-helper-layout-20261116.md)。

若断开时网络不可用，助手先停止本机执行并清除本机连接，服务端撤销可能未确认；请在浏览器点击断开旧连接。旧连接仍受浏览器在线续期及凭据到期约束，不能把离线撤销当成已获服务端确认。

## 构建与升级

### 用户下载入口

网页用户在“工具库 → 本机授权中心”顶部点击“下载 Windows 本机助手”，安装并启动后继续生成配对码。登录页的“下载客户端与本机助手”打开下载窗口，分别展示独立助手和完整桌面客户端；助手显示版本、适用系统、发布类型和安装说明。未发布、包缺失或元数据无效时不提供可点击下载地址。

### 发布至服务器下载目录

目录不会由服务器启动自动发布。构建机执行 `npm run publish:local-helper` 时会自动创建本机的 `downloads/local-helper/`；服务器首次部署需手动创建同名子目录，或由文件同步工具连同目录一起复制。主应用只读取已经发布的文件和清单，不会从构建机自动获取安装包。

在 Windows 构建机生成安装包后，执行 `npm run publish:local-helper`。命令读取 `dist-local-helper/latest-build.json`，校验构建目录、版本、文件类型和校验值，复制安装包并更新 `downloads/local-helper/latest.json`；同名且内容不同的包拒绝覆盖，请提高版本号后重新构建。开发包始终保留“开发验证版（未签名）”标识。

部署时将 `downloads/local-helper/` 中的安装包和 `latest.json` 一并同步至服务器现有 `downloads` 挂载目录，并给予主应用读取权限。该目录不会随镜像自动交付，也不提交 Git。`latest.json` 仅用于下载展示，不是自动更新通道，不能覆盖完整客户端的 `latest.yml`。独立助手下载不受 `ENABLE_DESKTOP_DOWNLOAD` 控制；该开关只管理完整桌面客户端。

在服务器的 Compose 部署目录操作：

```bash
mkdir -p downloads/local-helper
```

然后上传本地已发布目录中的安装包和 `latest.json`，保持原文件名及内容一致；不需要手写清单。当前包为 `PivotLocalHelper-Dev-Setup-0.7.164.exe`，主应用源码版本为v0.7.165，两者版本不同属于已构建制品保留原身份。按部署中的 `PIVOT_UID`、`PIVOT_GID` 给目录和文件设置可读取权限，刷新下载窗口即可重新读取状态。

Compose 将宿主机 `./downloads` 挂载到容器 `/app/downloads`。即使镜像内预建了目录，宿主机挂载也不会自动获得安装包；仅更新镜像不能完成助手文件发布。目录或两个发布文件缺失时，页面显示“暂未发布”。

本次下载入口需更新主应用并刷新网页；已生成的 HTTP 兼容助手包可复用，不需要为新增下载按钮重新打包完整客户端或助手。当前本地发布文件及验证范围见[下载入口设置记录](../reports/local-helper-downloads-20261116.md)。

### 安装包构建

源码调试：`npm run start:local-helper`。

正式构建：`npm run build:local-helper`。沿用项目的 Windows 发布者和代码签名凭据配置；缺少凭据时正式构建失败，不生成冒充正式版的包。

开发验证包：`npm run build:local-helper -- --unsigned`。此包明确命名为 `PivotLocalHelper-Dev-Setup-<版本>.exe`，用于受控开发验证，不作为已签名的生产交付。最近构建目录记录在 `dist-local-helper/latest-build.json`。每次构建使用独立目录，以免覆盖正在运行的旧验证包。

升级前退出助手并核对旧任务状态，再运行同一发布身份的新安装器；安装包提供卸载入口。卸载或退出后，浏览器中的连接应同时撤销。当前版本通过手动安装更新，不提供自动升级。

## 验证范围

浏览器脚本、真实HTTP和隔离PostgreSQL已验证配对、签名领取、回执、跨浏览器拒绝、一次性挑战重放拒绝、账号更换、离线和普通退出撤销。真实Electron窗口和Windows可访问性驱动在专用验收应用中完成读取、输入、点击和截图。使用的测试目标和输入为合成数据，不代表所有 Windows 应用均兼容。

当前环境缺少正式代码签名凭据，产出为未签名开发验证安装包；未在生产服务器或业务应用上部署执行。管理员应使用正式签名包并在目标 Windows、实际服务协议和业务应用中验收后开放。
