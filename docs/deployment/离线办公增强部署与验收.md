# 离线办公增强部署与验收

本轮在 v0.7.32 接入底座上增加统一中文离线朗读、精细比较与 DOCX 修订、动态 OA 来源和交互式脑图。不自动启用生产服务，不修改原数据库结构。

## 1. 统一中文离线朗读

选定 Kokoro 中文 v1.1 ONNX int8，代码使用固定 `kokoro-onnx==0.4.9`、`misaki==0.9.4`；全部传递依赖和分发摘要在 `docker/tts-service/requirements.lock`。原始权重由 [hexgrad](https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh) 以 Apache-2.0 声明，ONNX 导出来自 [kokoro-onnx 固定发布](https://github.com/thewh1teagle/kokoro-onnx/releases/tag/model-files-v1.1)。代码、模型卡、配置和音色应一同交付，并遵守依赖各自的许可；不要把 Piper 的未知许可音色混入本包。

联网准备机先执行：

```bash
python docker/tts-service/prepare_assets.py
docker build -f docker/tts-service/Dockerfile -t pivot-tts:1.0.0 .
node scripts/package_office_extensions.js --export /secure-delivery/office-extensions-1.0.0
node scripts/package_office_extensions.js --verify /secure-delivery/office-extensions-1.0.0
```

准备目录 `artifacts/tts-models` 包含 ONNX、100 个中文音色、中文词表、模型卡及摘要清单；运行时强制校验所有本地物料，不调用在线下载。清单首次制作应由联网准备机核对来源后经可信渠道交付。

内网载入 `tts-image.tar`，将 `tts-models/` 放到部署目录 `data/tts-models/`，将 Compose 放到部署根目录。沿用受控的 `data/secrets/offline-tools-token`，确认 UID 1000 可读，禁止公开密钥。配置 `ai-bridge` 和出口策略，启动：

无 Node 源码环境时可在交付目录执行 `python3.12 verify_bundle.py .` 核对全部物料；先核对可信 BOM，再导入镜像。

```bash
docker compose -f docker-compose.tts.yml config --quiet
docker compose -f docker-compose.tts.yml up -d --no-build --pull never
```

`/tmp` 保持 noexec；`/runtime` 是仅 UID 1000 可读写的有限 exec tmpfs，供固定 espeak 依赖加载临时共享库。不允许挂载任意可执行脚本，也不需要 root/GPU。服务仅接受 Bearer，限制请求体、单任务并发、文本 2000 字和音频 180 秒；过载返回 429，超时不放行另一个推理覆盖正在运行的计算。

在 Pivot 凭据库创建朗读密钥引用，并按现有凭据共享规则授权用户。主程序配置：

```env
PIVOT_TTS_ENDPOINT=http://tts:8502/speech
PIVOT_TTS_CREDENTIAL=对应的凭据引用名
```

目标固定于管理员环境配置；浏览器不提供任意 URL。仅内网、DNS 复核和非敏感地址可用。修改后重启 Pivot；录音仍使用原语音识别服务，新的统一朗读取代系统音色，播放经当前登录用户的服务端代理返回，不向浏览器暴露密钥。

统一服务配置后不可用时明确报错，不静默转到云或系统音色；未配置时保留原有本机朗读。当前账号无凭据使用权时拒绝。说话打断、停止或退出会取消合成请求并停止播放。浏览器首次音频自动播放仍受终端策略约束，设备应先授予音频播放权限。

Agent 的 `agent.text_to_speech` 同样支持此后端，并须显式配置任务 Origin/端口白名单、满足审批；音频通过 CAS、WAV Rendition 和已有授权下载链路交付。旧 JSON URL Provider 在未配置统一端点时继续保留。

## 2. 精细比较与修订文档

公文工作台的版本比较现在调用 `/api/apps/official-writing/compare`，输出字符增删、完整唯一段落移动定位，以及真实 `w:ins`、`w:del` 和段落标记修订的 DOCX。比较最多两份各 30000 字符，算法有耗时/编辑量上限，超限应分章节处理，不静默截断。

Agent 可用 `document.compare`，参数为已授权来源读取的 `before/after` 文本；结果保存到原有产物面板下载。非 DOCX 格式不能保留修订语义时明确拒绝；HTML 提供插入/删除对照。相同 IR 重复渲染确定性一致。

当前是正文语义比较和新修订稿生成，不覆盖原文件；不声称保留原 DOCX 的复杂模板、域、脚注、嵌入对象或扫描 PDF 像素版式。上传资料先走既有解析链路，复杂格式原件应保留作为审阅依据。唯一且完全相同的段落才标为移动，重复或修改后的段落不冒充移动判断。

## 3. 动态 OA 来源与知识同步

知识库“内网 HTTP”来源可配置 `crawl`；删除 `crawl` 后沿用原 JSON 清单来源。

```json
{
  "url": "http://oa.internal/policies/",
  "credentialRef": "授权的Bearer凭据引用",
  "crawl": {
    "pathPrefix": "/policies/",
    "selector": "main article",
    "waitForSelector": "main article",
    "maxPages": 10,
    "cookieCredentialRef": "可选登录Cookie凭据引用"
  }
}
```

仅管理员创建和运行网络来源。Cookie 凭据是 `[ {"name":"session","value":"…"} ]` 的受控凭据值，不写在来源 JSON 中；按页面实际认证方式选择 Bearer 或 Cookie。支持现有登录会话注入，不绕过 MFA/验证码，也不会自动猜测密码或点击提交业务表单。

动态 Chromium 的全部网页、脚本与 XHR 经既有 DNS 固定安全客户端转发，只允许同源 GET/HEAD；屏蔽 WebSocket、下载、图片/媒体/字体和跨源外连。页面最多 30 个、90 秒总预算、300 次资源、单资源 2 MiB；资料路径按前缀限制，HTTP 重定向拒绝。先用明确正文选择器与就绪选择器在测试门户验证，再扩大采集。

清洗删除导航、脚本、表单、侧栏，保留标题、段落、列表和表格文本为 Markdown。资料 URI、正文 hash、版本、索引和定时调度复用现有知识来源流程。网页抓取结果可能因分页、登录或额度而不完整，因此本连接器不自动删除旧知识。同步失败不会声称成功或清空原知识。

## 4. 脑图编辑

在会话要求“生成可编辑思维导图”时，Agent 使用 `viz.mindmap` 创建节点树和 SVG。原生产物面板显示节点编辑区，支持改文字、添加子节点、上移、删除分支、预览及保存新版本。保存生成同一脑图产物的新版本及新的 SVG Rendition，所有图形下载继续使用原授权链路。

树最多 120 个节点、6 层、每节点 120 字；重复标识、循环、空节点或越限拒绝。节点文本转义，预览复用安全 SVG 入口；不执行任意 HTML。允许用户改写节点，不允许通过客户端指定别人的产物来覆盖。

## 5. 性能及恢复演练

目标机可运行 `scripts/benchmark_offline_tts.py --token-file <密钥文件> --output <记录文件>`（端点默认本机 8502，可通过参数指向受控内网服务）。记录每条样本合成耗时、音频长度、实时系数和摘要，不记录密钥。发音质量、多音字、数字及中英混读需人工试听签认。

在测试 PostgreSQL 上运行 `scripts/rehearse_offline_restore.js`，可用 `PIVOT_RESTORE_PG_BIN` 指定 PostgreSQL 客户端目录。只创建随机隔离 schema 和临时文件，执行实际 pg_dump/pg_restore 及恢复文件摘要对账，完成后清理；不接受外部恢复 schema，不进行生产切换。测试记录位于 `artifacts/acceptance/offline-restore.json`。

正式生产前仍需落实维护窗口、真实数据同恢复点备份、密钥保管、目标终端体验与容量阈值。开发机和隔离 schema 的演练不能替代现场签认。
