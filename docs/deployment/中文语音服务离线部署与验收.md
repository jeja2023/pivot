# 中文语音服务离线部署与验收

适用环境：Ubuntu、禁止访问互联网，现有 4 张 2080 Ti 运行 Qwen3.6-35B，256 GB 内存。默认在一个 Pivot 主容器内集成 CPU 中文双遍语音识别，无需增加语音容器，也不占用聊天模型的 GPU；需要独立扩容时可切换到其他局域网服务器的语音 API。

## 组件与能力

| 环节 | 本次实现 |
| --- | --- |
| 采集 | 默认设备成功后逐项请求回声消除、降噪、自动增益和单声道；驱动不支持时保留基础采集 |
| 前端断句 | 有界句首预录、连续起录判定、瞬态抑制、可配置中文句末等待；前端能量判断不冒充声学模型 |
| 统一服务 | 默认 `embedded`，网页和桌面通过 Pivot 调用同一个内置 CPU 进程；`gateway/openai/qwen` 可接其他服务器，故障明确提示 |
| 无语音过滤 | 服务端 Silero VAD；静音和无语音段不进入最终识别模型 |
| 双遍实时识别 | FunASR 流式 Paraformer 生成暂态文本，句末由带业务热词的 SeACo Paraformer 再识别，按需补标点 |
| 准确度候选 | Qwen3-ASR-1.7B 使用 Transformers 路径按句识别；当前独立网关的 Qwen 后端不宣称支持双遍流式 |
| 数字与存疑结果 | 两遍数字存在分歧、上游报告低置信度或音频削波时保留输入供核对，停止实时自动提交 |
| 回答与朗读 | 继续使用聊天界面选中的文本模型和系统本地朗读；本次重点改造识别与抗干扰 |

ASR 与 VAD 不能确认某个声音是否来自当前用户。旁人说话需要近讲/定向麦克风或额外的目标说话人方案；本次没有声纹注册或目标说话人分离，也没有声称能消除所有环境声。

## 部署选择

默认使用 `PIVOT_VOICE_PROVIDER=embedded`。主镜像内置 Python 3.12、CPU 版 PyTorch/FunASR/Silero VAD 及语音代码，Node 负责管理一个常驻 Python 子进程；三个识别模型只加载一份，CPU 推理默认 4 个线程，模型锁约束同时推理数。模型加载失败不会阻断主应用的文字对话、知识检索和其他功能。

三个下载模型的文件总量约 2.18 GB；推理还需要运行库、模型展开和临时计算内存，文件大小不能当作运行内存上限。256 GB 对语音模型自身有较大余量，但部署时仍要检查文本模型、文档处理和其他业务占用后的可用内存。实际吞吐主要受 CPU 型号、频率、可用核心和请求量影响；不能用总内存推算支持多少路实时会话。CPU 模式不需要 NVIDIA 驱动、CUDA、GPU 透传或 vLLM。

内置进程使用动态回环端口和随机临时凭据，只在容器内通信，不发布 8000 端口；`.env` 无需填写语音 IP、HTTP/WS 地址或共享密钥。随主应用启动预热、按需检查，启动超时或进程退出后进入短暂冷却；主应用退出会清理语音进程，父进程异常退出也会触发子进程回收。

选择 `gateway/openai/qwen` 时不启动内置模型，可让另一台内网服务器提供语音 API，按后文配置端点和鉴权。原 `local` 保留为管理员明确选择的 Vosk 或系统识别兼容模式，不会在内置模型失败后静默降级。

Qwen3-ASR 可作为独立服务器上的准确率对比候选，随附可选独立网关使用 `SPEECH_BACKEND=qwen`、本地模型目录及 `SPEECH_DEVICE=cuda:0`。其依赖需额外准备 `--qwen`，镜像构建使用 `--build-arg SPEECH_INCLUDE_QWEN=true`；默认主镜像不安装 Qwen-ASR 包、不下载其权重。其真实显存和 2080 Ti 兼容性仍需实测。

## 联网准备机

### Windows 源码开发环境

模型文件存在不等于 Python 推理依赖已经安装。Docker 镜像内的运行库与 Windows 系统 Python 相互独立；Windows 直接执行 `npm run dev` 或 `npm start` 时，先在项目根目录使用 Python 3.12 准备专用环境：

```powershell
python scripts/setup_speech_runtime.py
# 后续只检查依赖，不重新安装：
python scripts/setup_speech_runtime.py --check
```

脚本将 CPU 版 PyTorch、FunASR、Silero VAD 等安装到 `.venv-speech/`，不修改系统 Python 包；Windows 的 PyTorch CPU 安装包缓存在 `artifacts/speech-wheelhouse-windows/`，不与 Linux wheelhouse 混用。该目录已包含完整离线依赖包时可加 `--offline`。源码服务会自动优先选择项目 `.venv-speech`，无需把 Windows 的绝对解释器路径写进生产 `.env`。

显式配置 `PIVOT_EMBEDDED_VOICE_PYTHON` 时仍优先使用该值；相对解释器、工作进程和模型路径统一相对项目根目录解析，不受 Python 子进程工作目录影响。标准 Docker 始终优先使用镜像内置环境。安装完成后重新启动开发服务，或在已更新代码的语音设置面板点击“保存并应用”重试加载。

Windows 保活管道使用非阻塞断开探测，避免标准输入阻塞读取与 SciPy/Fortran 原生库加载互锁；仍会在父进程退出后回收模型。开发机实测 Python 3.12.4 与 CPU 版 PyTorch 2.8.0 下三模型约 49.1 秒就绪，示例音频的 HTTP 转写和 7 次流式临时结果均通过；该时间仅代表此次开发机测试。

内置进程会在加载前检查必要依赖与三个模型目录，启动失败返回受控的具体原因，例如缺少 FunASR/Silero VAD、解释器不存在、模型文件缺失或加载超时；不会把原始进程错误、凭据和录音回显到页面。

### Linux 离线镜像准备

项目 Python 基线为 3.12：主服务镜像的 Agent Python、本地 Vosk 虚拟环境及独立语音容器均使用同一小版本系列；Windows 开发机可以继续使用现有 Python 3.12。主镜像从官方 CPython 镜像复制项目解释器到 `/usr/local`，保留发行版 `/usr/bin/python3`，不修改 Ubuntu 或 Debian 的系统 Python。

准备机使用与目标相同架构的 Linux、Python 3.12，并具备构建 Python wheels 的工具链。依赖与模型仅在这里下载，不能在生产容器启动时联网安装。旧 Python 3.11 的 wheelhouse 应在独立目录归档后重新生成，不能将 `cp311` 二进制包当作 `cp312` 包使用；三个模型的权重目录可继续复用。

```bash
python3.12 -m venv .speech-prepare312
. .speech-prepare312/bin/activate
pip install modelscope
python docker/speech-service/prepare_assets.py --download --device cpu
# 已有三个模型时，只更新依赖，不重新下载权重：
# python docker/speech-service/prepare_assets.py --dependencies-only --device cpu
python docker/speech-service/prepare_assets.py --verify
docker build -t pivot:latest .
docker save -o pivot-image.tar pivot:latest
```

Windows 3.12 可准备模型权重，Linux 依赖应在 Docker Desktop 的 Linux 容器或 WSL 内使用 Python 3.12 准备，不能把 Windows 的 wheelhouse 直接导入 Linux 容器。原生 Windows 下直接执行 `prepare_assets.py --download` 仍会提示平台不匹配，这是依赖目标平台校验，不是要求开发机降级。更新 Dockerfile 不会改变已经运行的旧镜像；须重建、导入并重新创建容器后才能切换。

脚本会构建完整 wheelhouse，并下载以下准备目录。`artifacts/` 用于联网下载和离线交付，生产挂载目录使用后文的 `./data/speech-models/`。下载行为只由 `--download` 显式触发：

- `artifacts/speech-models/paraformer`：SeACo Paraformer 中文句末识别，支持热词。
- `artifacts/speech-models/paraformer-streaming`：中文流式 Paraformer，保留每句独立缓存。
- `artifacts/speech-models/punctuation`：中文标点模型。
- `artifacts/speech-models/qwen-asr`：可选 Qwen3-ASR-1.7B。

`silero-vad` Python 包自带其 VAD 权重。工具会记录模型与 wheels 的 SHA-256 清单 `artifacts/speech-assets-manifest.json`；应将清单、镜像、模型目录、依赖许可证与构建日志一起交付。清单不是数字签名，跨安全域传输仍须按组织的可信介质和签名流程验收。

模型镜像完成后，可在对应 Python 环境运行 `python scripts/verify_speech_runtime.py` 检查真实 VAD 的静音与白噪声基础探针；该探针不代替中文精度评测。

依赖准备默认固定 `torch==2.8.0+cpu` 和 `torchaudio==2.8.0+cpu`，不会将 CUDA 依赖当作 CPU 环境的必要组件。主镜像安装时使用 CPU 约束并检查 `torch.version.cuda is None`。如联网准备机到 PyTorch 官方源不可达，可先通过组织允许的联网通道下载目标 Linux/Python 3.12 的官方 CPU wheel，核验上游摘要后放入 wheelhouse，脚本会优先复用这些本地包，不能关闭 TLS 校验。

如果特定依赖无法构建 wheel，应在准备机解决编译依赖后重试，不能改成生产启动时从公网安装。只有选择可选独立 GPU 语音服务器时，才需验证驱动、容器运行时并用 `--device cu126` 或 `--device cu128` 重新准备其专用依赖；该 CUDA wheelhouse 不用于标准 CPU 主镜像。

主镜像的构建上下文仅额外放行 `artifacts/speech-wheelhouse/`，模型、密钥与业务数据保持排除；三个权重仍通过只读目录挂载，不写入镜像。正式交付时用 `--build-arg PYTHON_IMAGE=<已验收镜像地址@sha256:摘要>` 固定 Python 基础镜像并保留最终镜像摘要。可选独立网关继续使用 `docker/speech-service/Dockerfile`，其 Python 参数名为 `SPEECH_PYTHON_IMAGE`。

## 内网导入

1. 将镜像、完整资源目录、摘要清单与脚本导入语音服务器，核验组织交付签名及文件 SHA-256。
2. 执行 `python docker/speech-service/prepare_assets.py --verify`。该命令只读取本地文件，不下载任何内容。
3. 执行 `docker load -i pivot-image.tar`。不要在生产运行 `docker build` 拉取基础镜像。
4. 按下面目录放置三个模型，在 `.env` 选择 `embedded`，重新创建 Pivot 容器。内置进程的临时密钥由应用自动生成，无需管理员维护。

### 生产目录与模型挂载

沿用主服务 `./data`、`./uploads`、`./downloads`、`./logs` 的相对目录方式，不固定宿主机的部署根目录。默认只使用主 Compose；在另一台语音服务器选择独立部署时也采用相同的相对布局：

```text
<部署目录>/
├── docker-compose.yml              # 默认只启动这一个主容器
├── .env
├── data/
│   ├── speech-models/
│   │   ├── paraformer/
│   │   ├── paraformer-streaming/
│   │   └── punctuation/
│   └── speech-models-manifest.json  # 模型下载校验清单（有则随包保留）
├── uploads/
├── downloads/
└── logs/
```

主服务 `docker-compose.yml` 已配置：

```yaml
volumes:
  - ./data/speech-models:/models:ro
```

将 Windows 开发机 `E:\pivot\artifacts\speech-models` 下三个完整目录复制到生产部署目录的 `data/speech-models/`，保留权重、词表和配置文件。如果离线包已按准备目录导入并校验，可在部署目录执行：

```bash
mkdir -p ./data/speech-models
cp -a ./artifacts/speech-models/. ./data/speech-models/
```

下载时生成的 `artifacts/speech-models-manifest.json` 可一并复制到 `data/speech-models-manifest.json`；这是仅模型的清单，与前文包含 wheelhouse 的 `speech-assets-manifest.json` 范围不同。模型目录须允许容器用户 UID 1000 读取文件和进入子目录。主 Compose 将模型根目录设置为 `/models`，进程自动加载三个子目录，无需手动配置内部端点。

相对源路径按第一个 Compose 文件所在的项目目录解析，并非宿主机根目录 `/data`。不要在路径中再额外插入 `pivot/`；实际绝对路径是 `<部署目录>/data/speech-models/`。已按旧独立容器挂载部署的实例，应先复制完整模型并核验，更新主镜像与配置后重建主容器；确认内置模式可用后可停止原独立语音实例。

## 内置 CPU 模式的 .env

### 优先使用模型配置页面

部署新版服务后，以系统最高管理员账号进入 **设置 → 模型配置 → 基础模型与算法服务 → 语音识别服务 → 配置**。语音输入和实时语音共用这处全站配置，网页与 Windows 客户端不再分别维护端点。

- 选择“内置中文识别（CPU）”即可使用当前 Pivot 容器内的三个模型，可调整推理线程数、热词、句末等待、识别超时及请求并发。
- 选择“内网语音网关”填写其他服务器的完整转写地址、可选 WS/WSS 地址和密钥；选择音频转写兼容 API 或 Qwen 音频接口时，同时填写服务实际部署的模型名。
- “测试连接”验证当前表单，不保存配置。网关测试检查鉴权、模型健康及流式能力；兼容 API 使用短静音 WAV 检查协议，不代替真实中文识别验收。
- “保存并应用”加密持久化到现有 `app_settings`，无需新增表或执行数据库迁移。保存成功后，主进程会停止旧语音连接和在途转写，按新模式预热或释放内置模型，不需要重启主应用。
- 密钥仅用于服务端调用，页面不回显原值。空白保留原密钥，“清除原密钥”明确删除；更换端点或接口协议时，必须填写新密钥或明确清除，避免将旧凭据交给新服务。
- 页面保存的配置优先于 `.env`。`.env` 用于初次部署和未配置页面时的默认值；已由页面接管后，应在页面更新。模型目录、Python 可执行文件和工作进程入口继续由部署文件控制，不提供浏览器任意修改。

普通用户可查看语音识别方式与启用状态，只有系统最高管理员能编辑或发起自定义连接测试。地址固定、内外网限制、禁止重定向、账号验证及单次流式票据仍由服务端执行。默认拒绝外部服务；管理员显式启用外部 API 后，浏览器录音流程会提示外发。

### 初次部署的环境默认值

```dotenv
PIVOT_SERVER_VOICE_ENABLED=true
PIVOT_VOICE_PROVIDER=embedded
PIVOT_EMBEDDED_VOICE_CPU_THREADS=4
PIVOT_EMBEDDED_VOICE_STARTUP_MS=180000
PIVOT_VOICE_ALLOW_EXTERNAL=false
```

```bash
docker compose up -d --no-build --force-recreate pivot
```

标准 Compose 已设置容器内模型路径与 Python 解释器，无需填写 `PIVOT_VOICE_ENDPOINT`、`PIVOT_VOICE_STREAM_ENDPOINT`、`PIVOT_VOICE_API_KEY`。这三个字段在 `embedded` 模式下不会覆盖内部随机连接信息。修改 `.env` 后须重新创建容器，单纯 `docker restart` 不会重新注入环境变量。

主镜像和主 Compose 的部署默认值为 `embedded`；通用配置注册表与 `.env.example` 保留 `local` 供旧源码/桌面环境兼容。复制通用模板后应将其中显式的 `PIVOT_VOICE_PROVIDER=local` 改为 `embedded`，不能期待镜像默认值覆盖 `.env` 的明确配置。

内置进程与 Pivot 一同启动，模型加载期间语音能力显示“正在加载”，用户可稍后重试；不因此退回系统识别。关闭 `PIVOT_SERVER_VOICE_ENABLED` 或切换为远程 API 时不启动内置模型；配置变更通过重新创建应用容器生效。

## 可选：其他内网服务器提供统一语音 API

如需将模型移至独立语音服务器，可在该服务器导入可选 `pivot-speech:1` 镜像，使用 `docker-compose.speech.yml`。其 `.env` 设置至少 24 字符的随机 `PIVOT_VOICE_API_KEY` 和该服务器的 `PIVOT_SPEECH_BIND_IP`，通过防火墙只允许 Pivot 访问发布端口。默认独立 Compose 使用 CPU，GPU 叠加配置仅在确认可用时启用；网络网桥本身不是外发防火墙。

优先在模型配置页选择网关并填写连接信息；首次部署尚未使用页面时，也可将 Pivot 主应用的 `.env` 改为：

```dotenv
PIVOT_SERVER_VOICE_ENABLED=true
PIVOT_VOICE_PROVIDER=gateway
PIVOT_VOICE_ENDPOINT=http://<语音服务器内网IP>:8000/transcribe
PIVOT_VOICE_STREAM_ENDPOINT=ws://<语音服务器内网IP>:8000/stream
PIVOT_VOICE_API_KEY=<与语音服务器相同的随机密钥>
PIVOT_VOICE_ALLOW_EXTERNAL=false
PIVOT_VOICE_HOTWORDS=智枢,未成年人,中华人民共和国刑法
PIVOT_VOICE_MAX_CONCURRENT=2
PIVOT_VOICE_TIMEOUT_MS=30000
PIVOT_VOICE_END_SILENCE_MS=1000
PIVOT_VOICE_MIN_CONFIDENCE=0.65
```

重新创建 Pivot 并刷新页面后生效。该模式不会启动内置模型。健康检查会确认 gateway 模型是否已加载，以及是否支持双遍流式；未加载或地址策略失败时显示不可用。页面不会获得模型地址、服务密钥和业务热词配置。

双遍流式地址须与句级转写地址使用相同主机和端口，且 HTTP/WS 或 HTTPS/WSS 配对，防止两条通道的数据处理范围不一致。

识别模型没有置信度时返回 `null`，不会凭空生成分数。热词仅作为有限的识别参考，不允许使用聊天大模型擅自润色金额、人名或法规编号。

配置了 gateway 的网页和桌面都需要 HTTPS 或受信任本地地址来采集麦克风。通过普通内网 HTTP 访问的旧 Windows 客户端不能靠修改页面绕过 Chromium 录音限制；应部署受信任 HTTPS。保留 `local` 模式用于既有系统识别兼容，配置主服务后不静默切换到它。

## 反向代理与多实例

浏览器只连接当前 Pivot，不直接连接语音服务器。HTTP 登录态申请一个有效 15 秒的单次票据，票据在 WebSocket 首帧发送，不放入 URL；连接时和每句开始前重新验证账号。句末才允许最终文本进入实时对话。

```nginx
location = /api/chat/voice-stream {
    proxy_pass http://pivot_backend;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_read_timeout 1900s;
    proxy_buffering off;
}
```

按现有登录 IP 绑定规则登记可信代理。票据和每实例容量保存在对应 Pivot 进程内，多实例负载均衡必须保证票据申请与 WebSocket 升级落在同一实例；没有粘性会话时连接会拒绝，不能把票据校验关闭。独立语音服务的模型锁仍提供第二层推理容量保护。

## 兼容 API

可选择 `PIVOT_VOICE_PROVIDER=openai` 连接音频转写兼容接口（Multipart），或 `qwen` 连接带音频内容的 Chat Completions 接口；填写完整 endpoint、模型名和服务端密钥。两种方式当前为句级转写，不冒充双遍流式。

默认仅允许内网地址，禁止敏感地址、URL 凭据及重定向，固定请求解析到的地址。只有管理员显式设置 `PIVOT_VOICE_ALLOW_EXTERNAL=true` 后才允许公网 HTTPS 服务；界面会明确提示录音交给外部服务。不能将普通文本 Qwen3.6-35B endpoint 当作语音模型使用。

“不保存录音”描述 Pivot 与随附内网网关的处理方式；外部 API 的数据留存和训练使用由服务商协议决定，不能仅凭 Pivot 的本地不落盘行为替外部服务作保证。

## 现场验收

使用组织授权且可脱敏的录音，至少覆盖安静近讲、键盘、风扇、开会背景、旁人说话、扬声器朗读、口音、低音量、停顿、金额日期和业务专名。建议每类先准备 30 条短句；纯噪声和系统朗读单独计数。每条 WAV 最长 20 秒、16kHz 单声道 PCM16。

语料清单为 JSONL，音频路径相对于清单文件；不用把录音提交到仓库：

```json
{"id":"near-001","path":"audio/near-001.wav","reference":"请查询中华人民共和国刑法第十七条","category":"quiet","keywords":["中华人民共和国刑法","第十七条"],"hotwords":["中华人民共和国刑法"]}
{"id":"noise-001","path":"audio/noise-001.wav","reference":"","category":"keyboard","keywords":[]}
```

```bash
# SPEECH_EVAL_API_KEY 通过受控环境注入
python scripts/evaluate_speech_quality.py corpus/manifest.jsonl \
  --endpoint http://<语音服务器内网IP>:8000/transcribe --output corpus/report.json
```

报告按类别输出中文字符错误率、关键字命中率、纯噪声误识别次数和转写延迟 P95，不保存转写正文。该脚本评估句级识别；实时首字时延、句末时延、回声误触发与打断成功率需要在真实页面配合音频设备验收。

验收阈值由业务方在试点前冻结。安静、噪声和专名指标必须分开比较 Vosk、FunASR 与 Qwen 候选，不能用单一平均值掩盖关键数字错误。发布时先小范围试点，保留当前配置回滚；真实中文精度与 2080 Ti 并发容量未通过前，不宣称完成生产声学验收。
