# 知识库生产验收与恢复演练

本指南用于准备验收，不代表已经完成生产验证。测试应在业务方批准的时间、范围和隔离环境进行；黄金集、访问凭据和备份应按资料敏感级别保存，不提交到代码仓库。

## 1. 黄金集与质量基线

由业务人员按专题、文档类型、权限角色和问题类型编制标注集，覆盖长 PDF、扫描件、表格、无答案、冲突资料、撤权、跨用户、多轮指代和引用定位。标注应包含问题、期望资料 ID、预期答案要点、正确引用以及应拒答原因，双人复核并冻结版本。先在知识库质量评测中建立评测用例并运行，记录 Recall@K、MRR、引用准确率、答案覆盖率及拒答准确率；单独人工抽检聊天入口与原文定位。阈值由业务风险和历史基线共同决定，不能以测试样本通过率代替生产结论。

## 2. 受控检索负载测试

将仅用于测试的 JSON 数组置于仓库外：

```json
[{"query":"测试问题","collectionId":123,"expectedDocumentIds":[456]}]
```

`expectedDocumentIds` 为产品文档 ID，对应搜索返回的引用文档；未产生可验证引用时视为未命中。使用受限测试账号和单独的访问令牌设置 `KNOWLEDGE_BENCHMARK_BASE_URL`、`KNOWLEDGE_BENCHMARK_AUTHORIZATION`（完整 `Bearer ...`）、`KNOWLEDGE_BENCHMARK_CONFIRM=YES`，可设置 `KNOWLEDGE_BENCHMARK_CONCURRENCY`（1–16），然后运行：

```powershell
npm run benchmark:knowledge -- C:\安全位置\黄金集.json
```

工具最多执行 1000 条、默认并发 2，输出成功/失败、P50/P95/P99、文档命中率，以及有显式标注的 Recall@5、MRR、无答案和引用指标及各自样本数；不会输出问题或令牌。质量均值只使用成功请求，失败数单独报告。无标注时保持未评估，不能据空样本推断通过。

v0.7.87 支持为样本提供 `expectedCitationKeys`、`expectedNoAnswer` 和 `reviewers`，例如：

```json
[
  {"query":"有答案的测试问题","collectionId":123,"expectedDocumentIds":[456],"expectedCitationKeys":["kb:456:v789:b101"],"reviewers":["标注者甲","标注者乙"]},
  {"query":"没有答案的测试问题","collectionId":123,"expectedNoAnswer":true,"reviewers":["标注者甲","标注者乙"]}
]
```

示例 ID 和引用键需替换为受控测试资料中的实际值。`reviewers` 只记录提供的标注者信息，不能代替独立复核；无答案指标检查是否没有返回引用，不能证明拒答正文正确。引用指标按返回引用键与标注键对应计算，不代表事实支持率；事实支持标注缺失时 `factSupportRate` 保持未评估。先在测试环境做低并发基线，按批准的预算递增，出现异常立即停止。阈值需业务确认。

## 2.1 本地隔离链路回归

无需使用业务数据库，可在安装 PostgreSQL 的本机执行：

```powershell
node scripts/verify_tool_knowledge_chain.js --isolated-postgres --report output/tool-knowledge-chain/v0.7.87.json
```

Windows 默认寻找已安装的 PostgreSQL；其他安装位置可用 `--pg-bin` 指定 `bin` 目录。脚本建立仅监听本机随机端口的临时独立实例，运行单元、数据库、恢复/网络和浏览器四组，完成后停止并清理；已有独立测试库可继续用 `TEST_DATABASE_URL` 分组执行。报告保留 Node/平台、源码指纹和失败/跳过计数，验证期间源码变化会使检查失败。

该回归包含本地服务及测试桩，不等同于真实模型、OCR、Kroki、ONLYOFFICE 或目标内网验收。版本同步前的 248 项通过记录及剩余条件见[实施台账](../reports/工具与知识库链路剩余任务实施台账-20261104.md)和[v0.7.87 发布记录](../releases/v0.7.87-工具与知识库全链路加固.md)。

## 3. 备份与恢复核验

1. 由运维按既有备份流程分别备份数据库、受控知识库原文件和必需密钥，记录时间点及版本。数据库和文件必须来自一致的业务快照，否则计数与实际来源可能不同。
2. 在事先创建的独立演练数据库恢复备份；`scripts/restore-pg-backup.js` 使用 `--clean`，会删除目标库内的对象，必须核对目标为专用演练库。禁止把生产库作为目标。原文件恢复到隔离目录，不覆盖现有生产目录。
3. 设置 `KNOWLEDGE_RESTORE_SOURCE_URL`、`KNOWLEDGE_RESTORE_TARGET_URL` 和 `KNOWLEDGE_RESTORE_CHECK_CONFIRM=YES`，运行 `npm run verify:knowledge-restore`。工具只读对比关键表计数和孤儿分块，拒绝源、目标为同一数据库。
4. 在恢复环境抽检用户权限、文件哈希、PDF 页码、索引检索、引用版本、队列恢复和来源撤权；记录恢复耗时、问题和人工签字。源库持续写入时，计数差异并不必然代表备份损坏，应使用同一快照或停写窗口复核。

本仓库没有生产语料、目标凭据、独立恢复库和业务标注，因此这些步骤必须在对应环境执行并保存真实报告。
