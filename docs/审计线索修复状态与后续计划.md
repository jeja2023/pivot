当前仅完成了第一批高风险问题和基础治理补强，不能将 `.tmp/审计结论.md` 中的 140 条线索标记为全部修复。

## 二、已完成或基本完成

### 1. 数据库 MCP 与出站安全

- 加固 SQL 只读治理，拦截 `SELECT INTO`、`OUTFILE`、`DUMPFILE`、文件读取函数、序列修改函数、锁语句和睡眠/进程控制函数。
- 对用户自带的 `LIMIT` 进行夹取，避免绕过最大返回行数限制。
- PostgreSQL 连接增加默认只读事务设置；MySQL 增加只读事务设置。
- 统一校验 IPv6 地址数值形式，覆盖压缩、全展开、loopback、未指定地址、IPv4 映射地址、ULA 和 link-local 地址。
- 拒绝 Unix socket 路径、带端口的 host、方括号 IPv6 和包含空白的数据库主机输入。
- 共享数据库连接必须配置明确的表白名单。
- 数据分析数据库导入路径改为复用统一 MCP 工具治理、能力校验和调用审计。

### 2. 权限治理

- 新增 `requireCapability()` 中间件，使权限能力矩阵可以参与服务端鉴权。
- 收紧全局记忆参数、隐身模式、审计日志、合规审计包、用户数据、统计报表和观测设置等接口的 MANAGER 访问权限。

### 3. Agent DAG 可靠性

- 移除 DAG 路径中硬编码的 `approvalGranted: true`。
- DAG 恢复时传递节点审批键和输入摘要。
- 增加 `AGENT_RECOVERY_REQUIRES_APPROVAL` 的 DAG 处理路径。
- 恢复停滞任务时检查全部 pending 检查点，避免幂等兄弟节点掩盖非幂等节点。
- 对非幂等副作用节点禁止自动重试。

### 4. PostgreSQL 与工程门禁

- 恢复 27 条关键业务索引，覆盖消息、附件、文档处理、知识库和知识图谱热点路径。
- 新增 PostgreSQL 迁移 `upPg` 覆盖检查。
- 新增关键索引基线检查。
- 新增跟踪文件秘密扫描。
- 移除多个脚本中的 PostgreSQL 默认硬编码凭据。

### 5. 桌面客户端与发布

- 安装包重新携带不含源码明文 secret 的远程启动配置。
- 默认远程地址为生产局域网服务，自动更新使用同站 `/downloads/`。
- 自动更新来源限制在配置的 Origin 白名单内。
- 桌面发布流程在构建阶段从环境变量或 `.env` 临时注入 stealthSecret，打包完成后恢复仓库配置。
- 新用户安装后可以直接连接启用隐身模式的服务端。
- 已生成 v0.1.99 Windows 安装包、blockmap、`latest.yml` 和通用下载入口。
- 清理了 8 个 ESLint warning，当前 ESLint 为 0 errors、0 warnings。

## 三、仍属于部分修复

- 数据库 MCP 的 SQL 治理仍主要依赖语句规则，不是完整 SQL 解析；SQL Server 尚无通用的引擎级只读事务保护。
- Agent DAG 的硬编码审批问题已修复，但 `operationKey` 仍包含 attempt，完整的行为级恢复测试还需要继续补充。
- PostgreSQL 关键索引已经写入代码和测试库，但尚未连接真实生产库核验 `pg_indexes`。
- 权限矩阵已经接入关键接口，但全服务端尚未统一改为能力中间件。
- PG 迁移覆盖门禁已经增加，但历史迁移基线机制仍需进一步结构化收口。
- Docker 中的 `agent.browser` 已在无 Chromium 时隐藏或拒绝，但 Docker 交付形态仍未真正内置 Chromium。
- stealthSecret 已从源码配置中移除，但按照当前发布要求，安装包仍会携带 secret；这属于按业务需求保留的可轮换风险，并非彻底消除风险。

## 七、发布注意事项

- 服务端不需要部署桌面客户端 `config.json`；桌面客户端安装包内部需要该配置。
- 新用户不需要手动准备 `config.json`。
- 如果服务端启用隐身模式且安装包内 secret 与服务端一致，用户无需手动填写。
- 如果管理员在全局参数页面修改 stealthSecret，现有客户端需要在“配置服务器”中输入新 secret；无需重新打包客户端，也无需重启系统。
- 如果希望未来新下载的安装包直接使用新 secret，则需要重新生成发布包；现有客户端不需要重新安装。
