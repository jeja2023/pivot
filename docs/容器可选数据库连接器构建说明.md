# 可选数据库连接器构建说明

Pivot 的 PostgreSQL 与 SQLite 是默认运行能力。数据库 MCP 的 MySQL、SQL Server 和 MongoDB 驱动为可选能力；标准 Docker 镜像不会携带它们的运行时依赖闭包。

如生产环境需要连接对应数据库，请在构建镜像时明确选择：

```bash
docker build --build-arg PIVOT_DB_CONNECTORS=mysql,mssql,mongodb -t pivot:full .
```

支持的值为 `mysql`、`mssql`、`mongodb`，可逗号组合。比如仅需 MySQL：

```bash
docker build --build-arg PIVOT_DB_CONNECTORS=mysql -t pivot:mysql .
```

## 桌面客户端

标准桌面包同样默认不携带 MySQL、SQL Server、MongoDB 的专用依赖闭包，SQLite 与 PostgreSQL 不受影响。需要数据库 MCP 连接器的桌面部署，可在打包时选择所需驱动：

```bash
# 仅保留 MySQL/MariaDB
$env:PIVOT_DESKTOP_DB_CONNECTORS = 'mysql'
npm run dist:win

# 需要三类可选数据库的完整桌面版
$env:PIVOT_DESKTOP_DB_CONNECTORS = 'mysql,mssql,mongodb'
npm run dist:win
```

Linux 构建时使用相同的 `PIVOT_DESKTOP_DB_CONNECTORS` 环境变量。该变量只作用于本次打包：打包脚本在结束时恢复仓库的 `package.json`，不会改变开发机依赖或之后的构建默认值。

若容器或桌面包未选择某驱动，工具库会给出需由管理员重新构建相应交付物的明确提示，而不会建议在运行中的只读环境内执行 `npm install`。
