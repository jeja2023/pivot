# 可选数据库连接器构建说明

Pivot 的 PostgreSQL 与 SQLite 是默认运行能力。数据库 MCP 的 MySQL、SQL Server 和 MongoDB 驱动为可选能力；标准 Docker 镜像不会携带它们的运行时依赖闭包。

这表示连接器是“构建时选择”，不是“运行时在线安装”。如果要让用户在工具库中自行填写任意 MySQL 连接，交付的服务端镜像必须至少使用 `PIVOT_DB_CONNECTORS=mysql` 构建；如果不确定用户会使用哪一种数据库，直接构建完整连接器版本即可。

如生产环境需要连接对应数据库，请在构建镜像时明确选择：

```bash
docker build --build-arg PIVOT_DB_CONNECTORS=mysql,mssql,mongodb -t pivot:full .
```

支持的值为 `mysql`、`mssql`、`mongodb`，可逗号组合。比如仅需 MySQL：

```bash
docker build --build-arg PIVOT_DB_CONNECTORS=mysql -t pivot:mysql .
```

## 桌面客户端

桌面包默认保留 MySQL、SQL Server、MongoDB 三类驱动，以兼容已有桌面数据库 MCP 配置；只有发布方显式设置 `PIVOT_DESKTOP_DB_CONNECTORS` 时才裁剪依赖闭包。`local` 和 `remote` 两种桌面档位都遵守这一规则。

如果需要缩小远程安装包，再按发布内容选择驱动；只选择 `mysql` 的安装包只能连接 MySQL/MariaDB：

```bash
# 仅保留 MySQL/MariaDB
$env:PIVOT_DESKTOP_DB_CONNECTORS = 'mysql'
npm run dist:win

# 远程桌面版需要三类可选数据库时
$env:PIVOT_DESKTOP_DB_CONNECTORS = 'mysql,mssql,mongodb'
npm run dist:win
```

Linux 构建时使用相同的 `PIVOT_DESKTOP_DB_CONNECTORS` 环境变量。该变量只作用于本次打包：打包脚本在结束时恢复仓库的 `package.json`，不会改变开发机依赖或之后的构建默认值。

### 用户终端数据库的边界

当前“远程客户端授权本机资源”协议中的 `local_database` 仍是本机 SQLite 文件授权；它不是把用户终端上的 MySQL、SQL Server、MongoDB 或 PostgreSQL 端口代理给服务端。因此，不能仅靠把驱动放进安装包，就宣称远程客户端已经支持直连用户终端数据库。

如果产品要求远程客户端直接访问用户终端数据库，还需要单独实现并审计本机数据库连接配置、凭据保护、授权范围和请求转发协议；在该功能完成前，应使用本机模式或把数据库部署到服务端可达网络。

若容器或桌面包未选择某驱动，工具库会给出需由管理员重新构建相应交付物的明确提示，而不会建议在运行中的只读环境内执行 `npm install`。
