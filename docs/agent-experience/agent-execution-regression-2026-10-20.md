## 重复任务卡片

截图中的三个相同任务卡片涉及后端续跑链和前端恢复展示两个层面。本次实现了以下修复：

- 聊天任务等待补充时恢复同一运行，不创建新子任务或再次预留父任务余额。
- 旧版本已有续跑链只展示最新任务；点击旧任务的继续按钮会定位到已有续跑任务。
- 同一运行的并发恢复请求复用现有消息节点和轮询。
- 会话选择序号与轮询实例共同判断响应是否仍有效，切走再切回时忽略旧响应。
- 任务删除或访问权限撤销后停止轮询，暂时查询失败时使用退避重试。
- 等待补充时展示已生成答案及具体原因，停止后台轮询；验收期间显示正在核验。

浏览器回归中，接口重复返回三条相同任务记录，并发触发三次恢复，最终始终只有一张任务卡片。点击继续后仍复用该卡片，累计输入与输出用量可见。

## 执行流程修复

| 问题 | 修复 | 回归证据 |
| --- | --- | --- |
| 预检索资料未参与任务验收 | 把本轮真实知识库快照作为验收观察传入规则和语义核验 | `agent-verification`、`agent-verification-persistence` |
| 流式检查点恢复遗漏既有工具结果和已应用指令 | 复用统一观察消息结构注入恢复上下文 | `agent-provider-sse-harness` |
| 暂停或租约失效被误判成原生工具故障 | 传播中断信号，阻止 JSON 兜底重新规划 | `agent-provider-sse-harness` |
| 暂停与结果验收并发写状态 | 暂停采用状态条件更新，验收前后检查中断；完成与提交边界保持有效 | `agent-runtime-pause`、`agent-execution-edge-cases` |
| 父任务停止时漏掉等待输入和验收中的子任务 | 补齐子任务状态范围 | `agent-runtime-pause` |
| 最终答案验收或落库失败引发另一轮规划 | 收尾故障上交运行错误处理，避免工具兼容性兜底重复生成 | `agent-provider-sse-harness` |
| 重试退避时间被运行字段白名单丢弃 | 允许持久化 `retry_after` | `agent-execution-edge-cases` |
| 已暂停、待审批或已结束后迟到异常重新排队 | 错误处理保留当前控制状态 | `agent-execution-edge-cases` |
| 重跑继承父任务已回写的消息和验收标记 | 新运行建立独立消息与任务事务关联 | `agent-resume-budget` |
| 预算恢复或超额异常导致内存额度判断失真 | 恢复累计 Token，用量记账后再抛出限额错误 | `agent-resume-budget`、`agent-auto-continuation` |
| 零额度、额度恰好用完仍允许下一次模型请求 | 在模型请求前阻断，并避免耗尽后追加模型总结 | `agent-execution-edge-cases`、`agent-provider-sse-harness` |
| 委派结构化修复混用原始与修复后的输出计费 | 分别记录两次调用的真实输出，修复失败也保留原始用量 | `agent-execution-edge-cases` |

纯知识问答按实际资料量使用较小预算，通常 32768 Token，最高 131072 Token，服从管理员更低限额；每个执行时间片最多 6 轮，不自动扩展续跑。复杂任务继续使用通用执行策略。

## 验证结果

- 149 个 Agent、聊天、工具、协作、桌面执行、工作流与安全相关测试文件，946 项通过，0 失败，0 跳过。
- 浏览器重复卡片与等待输入回归通过：`tests/e2e/chat-agent-waiting.spec.js`。
- 项目完整 `npm run check` 通过，改动文件 ESLint 检查通过。
- 测试使用隔离 PostgreSQL schema；流式协议、工具和界面场景使用受控服务或任务响应。

验证覆盖任务创建、队列与租约、模型调用、工具发现与执行、预算、审批、暂停取消、恢复续跑、协作、工作流、验收与结果回写。未对截图中的真实 Qwen 服务执行长时间压测，也未逐个连接生产外部工具服务；这些结果不能证明所有部署环境永不出现故障。

## 生效方式

代码修改已在工作区。运行中的服务需要加载更新代码并重启，浏览器刷新后使用新的任务卡片与恢复逻辑。旧任务记录保留，展示时过滤被后续运行替代的父任务；既有任务预算不会被自动扩张。
