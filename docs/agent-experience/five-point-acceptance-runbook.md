# 18 领域五分验收运行手册

本手册执行 [优化方案第 3.2 节](../design/Pivot对照Claude_Code架构优化方案_2026-10-17.md#32-逐领域-5-分强制验收标准与最终达标时间表) 和第 3.3 节。代码合并、单元测试或演示均不是 5 分认定。每个领域都必须在运行质量面板提交五类结构化证据，并由不同身份完成核验与委员会签署。

## 通用闸门

1. 每次候选认定前执行 `npm run test:agent:quality` 与 `npm run check`；保留 CI 运行 ID、产物 SHA-256 和受控报告链接。
2. 非功能与灰度证据必须满足服务端冻结的指标阈值、至少 30 样本；灰度至少 24 小时，P0/P1 均为零。
3. 先由系统管理员配置四名不同的委员会角色成员；四人分别使用本人登录态签署，提交人与签署人不得核验同一记录。
4. 没有生产/灰度证据、跨平台记录、回滚演练或委员会签署时，一律保持 4 分及以下，不创建发布日志、不升级版本。

## 逐领域执行清单

| 领域 | 必跑验证 | 必须附加的外部证据 | 不能认定为 5 分的情形 |
|---|---|---|---|
| 模型路由与降级 | `npm run test:agent:quality`；核对质量剖面与故障切换 Trace | 30 天模型质量/成本/失败升级趋势及回滚记录 | 样本不足、数据超过 30 天、切换扩大权限 |
| 工具按需发现 | 渐进发现、ACL 变更、TTL 与契约摘要回归 | 持续越权探针与缓存失效报告 | 发现缓存可复用旧授权或旧版本 |
| 工具并发与幂等 | 多进程租约、跨 Run 幂等与副作用冲突回归 | 容量压测与资源冲突 SLO | 存在重复副作用或无法解释的租约抢占 |
| 工具策略与审批 | 审批绑定、过期、撤销、并发审批回归 | 审计导出与审批撤销演练 | 审批可复用到其他工具、输入或资源 |
| 沙箱与本机执行 | `npm run preflight:capability-workers`；staging 执行 `npm run drill:capability-workers -- --confirm-staging` | Windows Docker、Linux Worker 两份签名镜像预置和逃逸探针报告 | Worker 未启用、镜像/签名缺失、隔离探针未在实机通过 |
| 长任务恢复 | 检查点、结果不确定、事务补偿、影子工作树归档/新目录恢复、凭据排除和重启恢复回归 | Windows/Linux 恢复/回滚故障演练与容量报告 | 副作用可自动重放、归档包含凭据类文件、归档摘要/恢复句柄缺失、恢复覆盖原工作区或无人工接管证据 |
| 多 Agent | Handoff `delivered→applied→acked`、Supervisor 重启与资源冲突回归 | 组织策略审计、容量/SLO 与灰度故障演练 | 未验收子任务可被汇合、消息重复应用 |
| DAG 编排 | 动态节点、循环拒绝、重放、补偿和跨版本恢复回归 | 有副作用 DAG 的生产演练 | 部分失败可绕过事务/补偿 |
| 生命周期扩展 | 签名包、前置 fail-closed、超时、审计与停用回归 | 灰度包导入、停用与故障演练记录 | Hook 可扩权、租户/授权 Hook 失败后仍继续 |
| 上下文治理 | 冻结压缩集、CAS 引用、保留率与遗漏项回归 | 成本/时延/质量 SLO、告警与生产回放 | 硬约束或阻塞项漏失、正文泄漏到指标 |
| 提示词与结构化输出 | 稳定段审批、原子切换、Schema 失败与缓存遥测回归 | Prompt 灰度、回滚和持续缓存观测报告 | 动态内容污染稳定段、Schema 失败被伪装为成功 |
| 长期记忆/知识 | 来源复核、撤销、两周期记忆效用与一致导出回归 | 两个结束周期各至少 30 个评估注入及撤销演练 | 有用率/冲突/过期/残留任一阈值不达标 |
| 技能生态 | 签名、路径、隔离验证、发布、熔断与回滚回归 | 供应链扫描和灰度故障演练 | 未验证草稿被自动发布、熔断无法回滚 |
| 浏览器自动化 | 会话租约、Observe/Act/Observe、上传下载边界与人工恢复回归 | Linux/Windows Chromium 崩溃、滚动升级、接管、回滚和视觉 E2E | Cookie/Storage 可读、写操作自动重放、P0/P1 非零 |
| 评测与发布 | `npm run test:agent:release-gates`；分层案例、双裁判和熔断回归 | 金标校准、灰度异常自动暂停/回滚演练 | CI 可绕过门禁、金标未实际核验 |
| 可观测性 | Trace 关联、SLO 指标和告警调度回归 | 告警路由、确认和演练记录 | 低样本被显示为通过、敏感字段未脱敏 |
| 代码语义/IDE | JS/TS/Python 导航、影子工作树、版本失效与工作区边界回归 | 跨 Windows/Linux 验收及调试协议记录 | 未经影子工作树直接修改、调试数据泄漏审计 |
| 语音/多模态 | 暂停/恢复/停止、barge-in、TTL 与会话隔离回归 | 目标设备 p95 中断延迟、多浏览器、无障碍和隐私演练 | 语音转写/音频越权持久化、控制跨会话生效 |

## 认定记录顺序

对任一领域，在运行质量面板依次提交并独立核验：`implementation_review`、`automated`、`nonfunctional`、`canary`。完成前四类后提交 `committee` 记录，四名预配置成员签署，再由第五名独立管理员核验。台账显示 `ready_for_committee_score` 仅表示证据齐备；评分、版本升级与发布日志仍须由架构委员会根据本手册的真实外部证据作出。
